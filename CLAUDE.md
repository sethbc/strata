# CLAUDE.md

This file gives Claude Code (claude.ai/code) guidance for working in this repository. It is an index: the rules every change needs, the engine command interface and how to run the checks. Each module's details are in its own notes file (see the module table): read that file before changing the module.

## Project Overview

Strata is an ambient granular soundscape generator for monome norns. It has seven synthesis voices (Resonator, FM, Folder, Sub, Pulse, Karplus, Ring), each with its own granular processor. Any voice's grain stage can read one of eight stereo sample buffers or the live input instead of its synth. A filter, delay and reverb, three global LFOs, MIDI input, scenes, an eight-page screen UI (MAIN, VOICE, SEQ, FX, LFO, BUFFER, SCENES, SETUP), grid and arc complete it. Version 3.0 added the buffers and live input, the filter and delay, grain envelopes and triggered grains, the LFOs, MIDI and the paged screen. Version 3.1 made everything playable from the norns alone: the VOICE, SEQ and SCENES pages, K1 held as ALT, lock, randomize undo, fine adjustment and center detents, arc rings on every page but SETUP, and grid pages per grid, with the script split into `lib/` modules. The current release is 3.1.0 (see CHANGELOG.md).

## Architecture

The project is written in two languages that must stay in sync:
1. **`strata.lua` and its `lib/*.lua` modules** (the norns script): UI, params, encoders/keys, grid, arc, MIDI and LFOs. They control the engine through `engine.*` commands.
2. **`lib/Engine_Strata.sc` and its `lib/engine/Strata*.sc` class extensions** (the SuperCollider engine): all synthesis and audio processing. It exposes commands with `this.addCommand()`. `lib/Engine_Strata.sc` holds only the class, every variable, `*new` and a generic `alloc` and `free`; all other code is in `lib/engine/` (`StrataUtil`, `StrataVoiceDefs`, `StrataGrainDefs`, `StrataVoices`, `StrataLifecycle`, `StrataBuffers`, `StrataFiles`, `StrataEffects`, `StrataPerformance`, `StrataRings`).
   - **Areas.** The engine is built from areas. An area is one method `strataArea<Name>` (its name is `<Name>` with a lowercase first letter) returning an Event: `order`, `allocState` (buses, buffers, state), `addDefs` (adds SynthDefs and returns the names whose controls `controlPairs` must know), `addCommands` (commands and polls), `start` (persistent nodes), `stop` (frees the area's nodes: synths, groups, recordings), `free` (frees its buses and buffers), `effectKeys` (persistent node keys `setSynth` sends to plainly), `grainDefs` (`{ arg source; ... } -> \defName` Associations, the first match wins in `grainDefFor`) and `grainParamHandlers` (`name: { arg voice, value; ... }`, true to skip `setGrainParam`'s store-and-send). Every key but `order` is optional. `alloc` runs `allocState`, then `addDefs`, then (after a sync) `addCommands`, then `start` across all areas in ascending `order`; `free` runs every area's `stop`, then every area's `free`, each pass in descending `order`, so every node is freed before any bus or buffer (the engine check asserts it). A node never goes in `free`, a bus or buffer never in `stop`. `strataAreas` (`StrataUtil.sc`) finds the methods by reflection and refuses two areas with one `order`. Orders: performance 10, voices 20, grains 30, buffers 40, files 50, effects 60, rings 70. An area keeps new state in `areaState[\<name>]`.
   - Engine files are named `Strata*.sc` (helper classes too: norns compiles every `.sc` under `~/dust`). Extension files add methods only, never variables. Renaming or deleting an engine file needs a norns restart note in the changelog fragment: an old copy left beside a new one would define the same methods twice.

```
Voice Synth → Voice Bus → Ring Writer → Voice Ring → strataGrainRing (voice filter) → Main Bus (dry) + Delay Send + Reverb Send → Filter ×3 → Delay → Reverb → Master (drift/limiter/saturation) → Output
                  ↓
              Mod Synth → Mod Bus → Other Voice Synths (cross-modulation, 3 slots per voice)

Buffer source:  Buffer pair (L/R) → strataGrainBuf → Main Bus (and mirrored to the Voice Bus → Mod Synth)
Input source:   SoundIn → strataInput → Input Bus → Ring Writer → Input Ring (history) → strataGrainRing → Main Bus (and mirrored to the Voice Bus → Mod Synth)
```

### Lua modules and `S`

`strata.lua` holds only the entry points: the shared table `S`, one `include("lib/<path>")` per module in dependency order, `init`, `redraw`, `enc`, `key`, `cleanup`, and the start steps only the script can own (init's start-up clock, `STARTUP` and `cancel_startup_clock`, and E1's settings). Everything else is in `lib/`.
- **`S`** (`lib/state.lua`: `local S = include("lib/state")()`) is the table the script and its modules share. Each call builds a fresh one, so a script reload keeps nothing from the previous run. State that more than one module uses is a field of `S` under its plain name (`S.voices`, `S.scenes`, `S.ui_page`, `S.engine_senders`, ...); state only one module uses stays local to it. `S.constants` is `lib/constants.lua`, a plain table.
- **Includes**: only `strata.lua` calls `include`, once per module, always as `include("lib/<path>")` (never `"strata/lib/..."`: the install folder may have another name). norns' `include` is `dofile`, so a second include would make a second copy with separate state. A test checks all three.
- **A module** is a constructor, `return function(S) local M = {} ... return M end`, ending with exactly `  return M` and `end` (the locals probe relies on it). Its table is `S.lib.<name>`: `S.lib.scenes` for `lib/scenes.lua`, `S.lib.<dir>_<basename>` in a subfolder (`S.lib.ui_keys`, `S.lib.grid_layout_256`). A local function another module calls becomes a field of that table (`S.lib.ui_text.fit_text`). Functions that were global stay global, defined in their module (`MODULE_HOMES` in the tests says where). Aliasing constants at the top of a constructor (`local NUM_VOICES = S.constants.NUM_VOICES`) is fine.
- **Registries** (`S.registry`, filled as the modules load): `pages` (one record per screen page), `params` (init runs each record's `add`, in PARAMS menu order), `grid_layouts` (`{key, redraw}` per grid size), `start` (init runs each step by order after the params) and `cleanup`; and, for 3.2's features, `voice_params` (per-voice param records), `scene_fields` (global scene fields), `source_change` (hooks after a source change), `param_filters` (one value filter per voice param key), `lfo_destinations` (per-voice LFO destinations) and `fx_params` (params after the fx group's own). Each has a register function on `S` (`S.register_voice_params`, ...) that checks its argument and refuses a duplicate name. The readers read them at init (inside a `register_params` add or later), never at include time, so a registering module's include order never matters. "Working in parallel" below says how to add to each.
- **`S.performance`** (`{tier, buffer_seconds, max_grains, history_seconds, reason}`): the tier the engine runs, read from the engine's `performance_active.data` by `S.lib.performance.read_active` in the first params record (`"performance"`, before any param is added); a missing or invalid file gives a copy of `S.constants.STANDARD_PERFORMANCE`. Every tier-dependent spec reads it (`record_duration` goes to `S.performance.buffer_seconds`). The setting itself (`performance.data`) is SETUP's, never a param.
- Tests reach script state with `local_value(name)` and `find_upvalue(name)`: a field of `S`, then of `S.constants`, then an upvalue of a global function.

### Lua ↔ SuperCollider Communication

**IMPORTANT**: this table is the engine command interface. The tests require exactly one row per engine `addCommand`, with the same signature and argument count. Keep the row format `` | `engine.<name>(<args>)` | `"<sig>"` | purpose | `` and update the table in the same commit as the engine. No `engine.<name>(` mentioned in this file, README.md, `docs/status.md` or `docs/notes/` may name a command the engine no longer has. Behavior details are in `docs/notes/engine.md`.

| Lua Command | SC Signature | Purpose |
|-------------|--------------|---------|
| `engine.voiceOn(voice, freq, amp, pan, grainSize, grainDensity, pitchShift)` | `"iffffff"` | Start a voice (resets `bend` to 1). Never stacks: synths still running or releasing are re-gated |
| `engine.voiceOff(voice)` | `"i"` | Stop a voice (release envelope) |
| `engine.retrigger(voice, velocity)` | `"if"` | Accent a running voice at velocity 0-1 (Karplus re-plucks; one grain in triggered mode). Creates no nodes |
| `engine.setVoiceParam(voice, param, value)` | `"isf"` | Set a synthesis param, or `bend` (MIDI pitchbend ratio) |
| `engine.setGrainParam(voice, param, value)` | `"isf"` | Set a grain param (`envShape` index, `grainMode` 0 continuous / 1 triggered, `bufPos`, `freeze` 0/1 and `freezeMode` 0 hold / 1 spectral, handled by the freeze area, ...) |
| `engine.setMasterDrift(amount)` | `"f"` | Global tape drift |
| `engine.setReverb(mix, size, damp)` | `"fff"` | Reverb mix 0-1 (broadcast on `fxMixBus`: 3.0's crossfade at reverb sends of 1), size, damping. `FreeVerb2` on standard, the FDN on high. Kept while bypassed (the mix stays 0 until lifted) |
| `engine.setFilter(freq, res, type, mix)` | `"ffif"` | Master filter, on all three of its instances (dry, delay send, reverb send): 20-20000 Hz, res 0-1, type 0 LP / 1 HP / 2 BP (20 ms crossfade), mix 0 = bypass |
| `engine.setDelay(time, feedback, mix)` | `"fff"` | Master delay: 0.01-2 s, feedback 0-0.95, mix 0-1 (broadcast on `fxMixBus`: 3.0's crossfade at delay sends of 1; 0 = dry, the node keeps running). Kept while bypassed (the mix stays 0 until lifted) |
| `engine.setBypass(effect, bypassed)` | `"ii"` | Effect 0 delay / 1 reverb (others ignored), bypassed 0 or 1: broadcasts the mix as 0, frees the node after the 0.05 s lag plus a block, and re-creates it in its place from the kept controls when lifted (a lift inside the wait cancels the free). Only this frees an effect |
| `engine.setModSource(voice, slot, sourceVoice)` | `"iii"` | Crossmod source for slot 1-3 (-1 = none → `silentBus`, 0-6 = voice). The three crossmod commands ignore any other slot |
| `engine.setModAmpAmt(voice, slot, amount)` | `"iif"` | Crossmod amplitude depth (-2 to 2) |
| `engine.setModFreqAmt(voice, slot, amount)` | `"iif"` | Crossmod frequency depth (-2 to 2) |
| `engine.setModSpeed(voice, speed)` | `"if"` | Mod signal LFO speed (0.1-50), kept per voice for restarted mod synths |
| `engine.setGrainSource(voice, source)` | `"ii"` | 0 = synth, 1-8 = buffer slot, 9 = input. A running voice's grain synth is replaced (never stacked); a stopped voice's choice is recorded. Same source = no-op |
| `engine.loadBuffer(slot, path)` | `"is"` | Read a file into slot 0-7 (mono fills both sides): at most `bufferSeconds` (16 s standard, up to 300 s high) at the server rate (a 96 kHz file keeps half as many seconds on a 48 kHz server). Voices reading the slot fade first. A file longer than 16 s at the server rate is checked in a routine that yields between chunks: it takes effect only after the check, and is dropped silently if a record, clear or later load that took effect arrived meanwhile. A missing, unreadable, empty or damaged file (checked by decoding it) leaves the slot unchanged but cancels a recording in it; a server read that fails anyway (the file vanished) leaves it empty. Both are reported by the `bufferLoadFailed` poll |
| `engine.recordBuffer(slot, seconds, level)` | `"iff"` | Record input × level into slot 0-7, at most `bufferSeconds` (16 s standard, up to 300 s high). On completion writes the scratch take `buf<n>.wav` |
| `engine.clearBuffer(slot)` | `"i"` | Zero slot 0-7 (cancels a recording) |
| `engine.stopRecord(slot)` | `"i"` | End a recording early and keep what was captured (as a completed take). No-op if the slot is not recording |
| `engine.saveBuffer(slot, path)` | `"is"` | Write the slot's valid region as a stereo 16-bit WAV (creates the directory). Samples beyond ±1 clip symmetrically. How the write ended is reported by the `bufferSaveResult` poll |
| `engine.setScale(root, mask)` | `"ii"` | The scale every quantized grain lands on: root 0-11 (0 = C), mask a 12-bit pitch-class set from the root (bit k = k semitones above it; 4095 = chromatic, the default). A root outside 0-11 or a mask outside 1-4095 is ignored |

**Poll `bufferState`** (engine → Lua): matron's polls carry one float, so each message carries **one** slot as `slot_index * 1000 + seconds` (`BUFFER_STATE_STRIDE` = 1000, 0-based slot, seconds ≤ `bufferSeconds`, at most 300; the largest value, 7 × 1000 + 300, keeps 0.01 s in a 32-bit float). It sends one slot every 0.25 s, in turn, so a full cycle of the eight slots takes 2 s, and every change is also sent at once. A slot that is recording reads 0 s.

**Poll `bufferLoadFailed`** (engine → Lua, not periodic): one message per failed load (a missing, unreadable, unsupported, empty or damaged file, at once; a server read that fails, after the fade and the read), whether or not the slot held audio, as `(load_number * 2 + emptied) * 8 + slot_index` (`NUM_BUFFERS` = 8, 0-based slot; `load_number` counts that slot's `loadBuffer` commands from 1, in the engine and in `load_buffer` alike; `emptied` = 1 when the failed server read left the slot zeroed). Lua's `buffer_load_failed` undoes exactly that load (its previous name, path and file param come back, or the slot shows empty) and never a later load, clear or recording, in whatever order the reports arrive.

**Poll `bufferSaveResult`** (engine → Lua, not periodic): one message per save whose write ends, written or failed (an empty slot, at once; a folder that cannot be made, a short write or a failed rename, when the write ends), as `(save_number * 2 + failed) * 8 + slot_index` (`NUM_BUFFERS` = 8, 0-based slot; `save_number` counts that slot's `saveBuffer` commands from 1, in the engine and in `save_buffer` alike; `failed` = 1 when nothing was written, so a file already at the path stays). A write abandoned for a newer write to the same path reports nothing. Lua's `buffer_save_result` prints the outcome and flashes `saved buf <n>` or `buf <n> save failed` on BUFFER only for the slot's newest save, so a late report never speaks for a newer one, in whatever order the reports arrive.

**Index conversion**: voices are 0-indexed in SC and 1-indexed in Lua, so always pass `voice_idx - 1`. Mod sources go through `engine_mod_source()` (Lua 0 = none / 1-7 → SC -1 / 0-6).

**The `voices` table is the only source of values.** The engine holds no per-voice defaults. `toggle_voice` calls `engine.voiceOn` and then `sync_voice_to_engine`, which sends `setGrainSource` first, then every synth, grain and crossmod value. Param actions reach the engine only while a voice is active. The `v<i>_source` action is the exception: it also reaches stopped voices.

### Invariants that are easy to break

The engine's (details in the area notes under docs/notes/engine/, listed above):
- **Pattern steps and MIDI notes never create nodes.** They call `retrigger`. Velocity only scales the accent envelope's `levelScale` (sampled at trigger time), never a running signal. The engine check asserts that in every voice and grain SynthDef `velocity` feeds only `EnvGen` `levelScale` inputs; the one allowance is `\strataKarplus`, where it may multiply a `T2A` of the `t_trig` control (a single-sample pluck impulse), and that product may reach only the pluck excitation (a `Decay` input, the `Pluck` trigger). Bent copies compiled in the check must fail it.
- **Replace, never stack.** A source switch replaces the grain synth. Earlier fading synths are cut with `cutSynth` (the `kill` fade), never a second `release` (EnvGen ignores it). New grain synths are placed with `startPlacedGrainSynth`, never relative to a releasing synth.
- **`openedGate(gate)`** wraps every ASR gate, so a synth gated off in its first block still starts and frees. Never use `gate.max(...)`: it breaks forced releases.
- **Silent bus**: unrouted mod slots read `silentBus`, never control bus 0 (norns allocates the input follower there).
- **Limiter before the tanh saturator** in `\strataMaster`. The engine check asserts the order.
- **One grain path.** Every grain synth is a `GrainBuf` pair (`\strataGrainRing` for the synth and input sources, `\strataGrainBuf` for slots, both built by `grainBody`), and pitch is the grain rate. No `PitchShift` or `DelayC` (or any delay line) in a grain SynthDef; the engine check fails on one.
- **Buffer and input sources have no voice synth.** Their grain synth mirrors to `granBuses[i]` (`mirrorLevel` 1) so crossmod keeps working. The synth-source grain synth must keep `mirrorLevel` 0 (its mod synth already follows the voice synth on that bus, so a mirror would count it twice), `pan` 0 (the voice synth already pans) and `rateLevel` 0 (the voice synth already bends and frequency-crossmods); buffer and input grain synths take the voice's `pan` (`panBalance`), bend and crossmod.
- **Ring writers** (`\strataRingWrite`, one per voice reading `granBuses[i]` and one reading `inputBus`) run at the tail of `voiceGroup`, after the voice, input and record synths, so a voice writer records only its voice synth (mirroring grain synths write the bus later, in `processGroup`). They are persistent and their keys are `effectKeys` (plain messages); their input goes through `zeroBadValues`. A ring grain reads behind the write head (margin + history + spread + max(r − 1, 0) × dur, rates clipped to ±4, grains at most 0.5 s), so it never overtakes the head and never reads past the ring.
- **`ringReaders`** maps every `\strataGrainRing` to its voice until it frees. Rings only ever append; any other write into a voice ring (3.2's freeze copy) fades the voice's ring readers first (`ringLevel 0`, `bufferFadeWait`) and runs only if `ringChanges[voice]` is unchanged (a source switch bumps it), as `slotChanges` guards the slots.
- **Freeze** (`lib/engine/StrataFreeze.sc`) changes a voice's ring writer only with `run` or `Synth.replace`, so each voice keeps one writer and `synths` names it; `\strataRingWriteSpectral` exists on the high tier only (standard, and buffer voices, always hold); history is 0 inside a frozen input copy; a source switch unfreezes first (`replaceGrainSynth`).
- **No `LocalBuf` in any engine SynthDef**: building one corrupts sclang 3.13's garbage collector (norns' version) and sclang aborts later. Pass server buffers as controls (the spectral writer's `\spectralBuffers`). A structure test enforces it.
- **Every SoundFile `readData` reads into a fresh array** (`freshReadArray`), never a reused one: on sclang 3.13 reuse also aborts sclang later (#131). A structure test enforces it.
- **Buffer memory**: 8 × 2 mono slot buffers of `bufferSeconds`, which the performance area sets first at alloc: 16 s on standard (≈ 49 MB); on high the setting's 16/60/120/300 s, stepped down until the slots and rings leave 1 GB of `MemAvailable` (300 s ≈ 922 MB). Besides them, 7 × 2 voice rings of 4 s (10.8 MB) and an input ring pair of `historySeconds` + 5 s (8.1 MB standard, 25 MB high). Never allocate longer ones. Bufnums never change. The engine runs high only if it wrote `performance_active.data` (through a `.part`, before `alloc` returns); otherwise standard, and Lua, finding no file, runs standard too.
- **Real-time memory**: norns' scsynth pool is 8192 KB. Every `GrainBuf` uses `maxGrains` (128); never size a delay line or table from a control. A source switch frees at once any synth of that voice still in its kill fade (`freeCuttingSynths`), and so does a `voiceOn` that meets releasing synths built for another source (`gateVoice` hands them to `fadingSynths`, never leaves them releasing beside the new ones), so a voice never holds more than its live synths, one fading and one cutting set, however fast switches, stops and starts arrive. A scene recall stops the voices it stops before setting their sources. The worst case (21 grain synths and 7 voice synths, the cut ones still in their fade) uses about 3.3 MB (each grain synth 69-75 KB with 2b's draws and its voice filter and sends, under the check's 80 KB limit; 6.9 MB before 3.2; on high, with spectral freeze on every voice and the FDN reverb, about 4.24-4.26 MB stays free, about 4.13-4.15 MB counting the spectral writers' late allocations), and the engine check requires 3 MB left on the standard tier (twelve 256 KB probes; sixteen, 4 MB, on high), started inside the kill fade, spaced, in a burst and for fast A -> B -> A -> C recalls, sized for 3.5's note streams (see `docs/notes/engine/memory.md`).
- **`slotChanges[i]`** guards late replies (load completion, `stopRecord` frame count) and the fade wait: a clear or load sent later always wins. A long file's load still in its check is dropped once `loadsSuperseded(i)` reaches its number (`slotChanged` raises it). A `bufferLoadFailed` report names its load's number, so it too never undoes a later load, clear or recording; a `bufferSaveResult` report names its save's number, so it never speaks for a later save.
- **Chunk loops in a routine** (a long file's check, a save's interleave) wait through `yieldToCommands`, never a plain `wait`: a routine that falls behind its clock never releases sclang's lock, so matron's commands would wait until it ends.
- **Fade before zeroing**: load, record and clear set the slot's frames to 0 first (`hasAudio` fades the voices) and zero or overwrite its buffers through `afterSlotFade` (`bufferFadeWait`, 60 ms, when a grain synth reads the slot). Never zero a slot directly. That covers every `\strataGrainBuf` until it frees, releasing and fading ones too (`grainSlots`, `slotGrainSynths`): those only ever get `bufFrames 0`. `bufRateScale` is sent only with a valid length (`slotLengthPairs`), never to grains fading out.
- **Messages to synths that can end on their own** (releasing, fading or cutting synths; a voice's live synths in `setSynth` with a voice, grain or mod key, `releaseVoice` and switches; record synths) go through `sendToSynth` (a bundle with `/error -1`), never `synth.set`/`release`/`free`/`moveBefore` directly: the synth may have freed a moment ago, and the server's `FAILURE ... Node not found` line fails the engine check. The effects chain's synths (`effectKeys`: the three master filters `\filter`, `\filterDelay`, `\filterReverb`, then delay, reverb, master) never end on their own, so `setSynth` sends to them plainly: a failure there is a real bug and must stay reported. The engine frees and re-creates the delay and the reverb itself (bypass), so they stay `effectKeys`; `setSynth` skips a missing key.
- **Bypass is explicit.** Only `setBypass` (Lua's `delay_bypass`/`reverb_bypass`, never a scene field) frees the delay or reverb node: it broadcasts the mix as 0 on `fxMixBus`, waits the 0.05 s lag plus a block, then frees it; a lift re-creates it in its place (`\addAfter` `\filterReverb` for the delay, `\addBefore` the master for the reverb, so the order filter ×3 → delay → reverb → master holds) from the kept controls, and a lift inside the wait cancels the free. A mix at 0 (LFO, scene fade, PARAMS, CC) only silences and never frees or creates a node. The master filters are never freed.
- **Sends reproduce 3.0's chain**: `voiceOutput` writes dry `(1 − s_d·m_d)(1 − s_r·m_r)`, delay send `s_d`, reverb send `s_r·(1 − s_d·m_d)`; the delay returns `m_d·D`, the reverb `m_r·R` (reading its send plus the delay's return), and the master sums dry + (1 − m_r)·delay return + reverb return. Every reader of a mix lags it 0.05 s (3.0 lagged only its delay mix: a moving reverb mix glides where 3.0's stepped, so only constant mixes and a moving delay mix match exactly), and the bus (`fxMixBus`) and the nodes' own mix controls are set in one bundle so they move in the same block. A grain synth gets its engine's send and mix buses through `grainControls` (`mixBusControls`), never only from its SynthDef defaults.
- **NaN guards**: the three `\strataFilter`s (before the effects, one on each mix bus) and `\strataMod` (input and output, so a voice that blows up never spreads through crossmod) replace bad values with `zeroBadValues`.
- **File writes** go to a `<path>.<instanceTag>-<generation>.part` file and are renamed into place. Never open the final path for writing. `deleteStaleParts` deletes only `.part` files and `writeSlot`'s temporary float files older than `stalePartAge`.
- **`\strataFilter`**: never compare a UGen with `==` (that is object identity); use `BinaryOpUGen('==', ...)`.

The Lua side's, across modules (each module's own list opens its notes file):
- **Param → engine** goes through `send_param_to_engine(id, value)` and an `S.engine_senders[id]` entry (this adds the LFO offsets). Never call `engine.*` from a control param's action directly. A command that carries several params builds the others from `engine_param_value(id)`, so an LFO on one never undoes an LFO on another. LFOs modulate around the stored value and never `params:set` their destination.
- **Scenes**: a new captured field needs `validate_scene` coverage and a migration default (`SCENE_GLOBAL_PARAMS.default`, `VOICE_SCENE_DEFAULTS` or `SCENE_BLOCK_DEFAULTS`, or a registered record's `scene_defaults` or field `default`, which the registries cover). Discrete keys (`DISCRETE_GRAIN_KEYS`, source, mod sources, a record's `discrete` keys, a field with `discrete`) switch at the end of a transition, never crossfade; discrete extras after the source. A recall sends one full sync per running voice whose source changed, after its params (`S.scene_recall_in_progress`).
- **Source tests**: use `voice_uses_synth(i)` / `voice_uses_buffer(i)`. Never use `not voice_uses_synth` (that includes input).
- **Grid, arc and MIDI handlers live on the vport only** (`grid.connect(port)`, `arc.connect`, `midi.connect`). Never store or attach to the raw device passed to `grid.add`.
- **Arc rings** sweep their range in `UI_PAGES.ARC_TICKS_PER_SWEEP` (512) ticks through `arc_sweep_param` and are drawn through `arc_ring_fill` from `param_fraction`, or `arc_ring_fill_bipolar` for a range through 0 (`arc_ring_fill_param` picks); never a bare `segment` or a hardcoded range. The exceptions, whole-step rings, carry their spare ticks through `arc_whole_steps(key, ...)` and then step a param through `delta_with_detent` or move a cursor (SEQ, SCENES); a page change forgets the carried ticks, and so does a change of what they were turned on (LFO, row, step). Strata follows one arc. The exceptions and details are in `docs/notes/lua/arc-core.md` and `docs/notes/lua/arc-pages.md`.
- **Lock** is what the user sees (`[L]`, the `K3:lock`/`K3:unlock` hints, the grid's lock keys, `toggle_lock`); the state and the scene field keep the name `frozen` (`S.frozen`), so scene files load unchanged. "Freeze" is the audio freeze of 3.2 (`lib/freeze.lua`, `[F]`, `S.lib.freeze.toggle`/`is_frozen`): no user doc or README sentence says freeze together with lock, `[L]`, params or values unless it contrasts them ("unlike"), and no Lua code names the lock with freeze (tests check both). A locked voice is left alone by randomize, drift and mutation (`randomize_voice` returns before storing anything), and can still be edited.
- **Randomize undo** (`lib/mutation.lua`, one level, `UNDO_SECONDS`): every param `randomize_voice` sets calls `note_param_edit(param_id)` from its action (`lib/params_setup.lua`), so a manual edit ends the undo instead of being overwritten by it. Every scene recall, a new randomize and a mutation of the undo's voice also end it; the drift's and the undo's own writes never do.
- **LFO offset**: it survives on/off only through `lib/lfos.lua`'s wrapper of the `lfo_<n>` action (#103), so anything that turns an LFO on or off (a page, a scene, cleanup) uses a plain `params:set("lfo_<n>", ...)`. A new LFO destination is a control param whose label fits the LFO page's right column (49 px).
- **Selected voice**: after init, `S.selected_voice` changes only through `S.lib.ui_keys.select_voice_by`, which moves an omni MIDI pitchbend with the selection (`docs/notes/lua/midi.md`). Only a page's `layout_states` and test setups set it directly.
- **Effect bypass**: `S.fx_last_mix[effect]` is recorded by each mix param's action whenever the mix goes above 0, however it was set, never by the FX page alone.

## Working in parallel

Several pull requests are built at once, often by agents. The rule: a feature lives in files that only that feature's work edits, apart from one-line registrations.
- **One worktree per pull request.** Branch from an up-to-date `main` in a worktree of its own; never share a checkout between two pieces of work. Engine checks in different worktrees can run at once on different `$STRATA_SC_PORT` ports (Development & Testing).
- **Own scratch folder, own worktree, nothing else.** Workers in one session share its scratchpad, so each works only in `scratchpad/<worker>/` (the name its dispatch gives) and its own worktree. It never writes to, renames or deletes anything outside those, including another worker's folder, worktree, logs or containers, even when the names look like its own. It removes only a worktree it created, with `git worktree remove`. Generic names (`v0`, `run1`) go inside the worker's folder, never at the top of the scratchpad.
- **The controller's ledger** (the record of dispatches, rulings and progress when a session runs packages through agents) is `.superpowers/sdd/<plan>/progress.md` in the main checkout `/home/sethbc/src/strata`, untracked (`.superpowers/` is in `.git/info/exclude`). Never inside a worktree: run the controller from the main checkout, and read the ledger's tail first when resuming.
- **Leftover worktrees and folders** of a worker that has finished (reported, or stopped) are cleaned up by the controller that dispatched it or by the maintainer, never by another worker: first check that the worktree has nothing uncommitted or unpushed (`git -C <worktree> status --short`, `git log @{u}..`), then `git worktree remove <path>` (and `git worktree prune`). A worktree whose branch is merged or abandoned goes; one with work not yet pushed is pushed or reported first, not removed.
- **Edit only the files your package owns.** A release's design lists its work packages and the files each owns (for 3.1, §9 of `docs/design/3.1-design.md`). Besides those, a package edits only registration lines (below), and its own notes file, unit test file and `docs/user/` page. Need a change in a file another package owns? Ask for it, or make it a separate pull request.
- **Where things live**: a module's table is `S.lib.<name>` (top-level `lib/` files) or `S.lib.<dir>_<basename>` (subfolders); shared state is on `S` under its plain name; the registries are `S.registry.pages`, `S.registry.params`, `S.registry.start`, `S.registry.cleanup`, `S.registry.grid_layouts`, and `voice_params`, `scene_fields`, `source_change`, `param_filters`, `lfo_destinations` and `fx_params` (`lib/state.lua`).
- **Registering a page**: a new `lib/pages/<name>.lua` creates its record at `S.registry.pages[UI_PAGES.index.<NAME>]` and sets every field but the four arc fields. Add the name to `UI_PAGES` in `lib/constants.lua` (one line; `NUM_UI_PAGES` is `#UI_PAGES` and `UI_PAGES.index` follows) and its `include` to `strata.lua` among the page includes (one line). Its rings, if any, go in a `lib/arc/<name>.lua`, included after every page file, that sets only `arc_delta`, `arc_redraw`, `arc_alt_delta` and `arc_alt_redraw` on the record. So a page package and the arc package never edit the same file. Every page in `UI_PAGES` already has both files. A page's own files are its `lib/pages/<name>.lua`, `docs/user/pages/<name>.md`, `docs/notes/lua/pages/<name>.md` and `test/unit/pages_<name>_test.lua`; the arc's page rings are `lib/arc/<name>.lua`, `docs/notes/lua/arc-pages.md` and `test/unit/arc_pages_test.lua`; a grid layout's are `lib/grid/layout_<size>.lua`, `docs/user/grid/<size>.md`, `docs/notes/lua/grid/layout_<size>.md` and `test/unit/grid_layout_<size>_test.lua`. A page adds layout-test states only through its record's `layout_states`.
- **Registering a param group**: one `register_params(name, add)` call in `lib/params_setup.lua`, at its place in the PARAMS menu (the registration order is the menu order). Keep the group's body in the owning module where you can, and call it from `add` (as the "lfos" record calls `add_lfo_params`).
- **Registering per-voice params** (3.2's freeze, variation, loops, history, voice filter and sends): one `S.register_voice_params(record)` call in the owning module's constructor; nothing central lists the params. The record is `{name, count, add = fn(voice_idx), add_first = fn(voice_idx), grain_keys, sync, scene_defaults, discrete, voice_rows = {section, rows, when, before}, layout_states, fader = false}` (`docs/notes/lua/params.md`). `add` adds exactly `count` params, each with `S.lib.params_setup.add_voice_extra(voice_idx, record, key, param)` (id `v<i>_<key>`, value in `S.voices[i].extras[key]`); they follow the voice's cross-modulation params under a `voice <i> extras` separator, except the optional `add_first`'s, which come ahead of the voice's synthesis params: norns reads a PSET in param order, so a param that a built-in param's filter reads must load first (variation's `quantize` before `freq`, #125). Its grain keys reach the engine through their senders and the voice sync, its scene keys are captured, crossfaded (or, `discrete`, set at the end after the source), validated and migrated, its rows join the VOICE page (a binary param is a `"binary"` row) and its `layout_states` VOICE's. Registered params never reach randomize, mutations or the 256 fader pages.
- **Registering the other shared spots**: `S.register_scene_field({id, default, discrete})` (a global scene field, read after `SCENE_GLOBAL_PARAMS`), `S.register_source_change(fn(voice_idx, source))` (runs after each `v<i>_source` action, never during a scene recall), `S.register_param_filter(key, fn(voice_idx, value, previous) -> value)` (one per key; every `v<i>_<key>` action applies it before storing), `S.register_lfo_destination(label, suffix)` (`v<i> <label>`, after every built-in destination, by registration then voice, so stored indices keep their meaning) and `S.register_fx_params({name, count, add})` (the fx group grows by `count`; its params follow the 11). Each is one line in the owning module.
- **Registering a start step**: `S.register_start(S.constants.START_ORDER.<step>, fn)` in the module that owns the resource, next to its cleanup step, and one line in `START_ORDER` (`lib/constants.lua`) at a free order at its place in the sequence (spaced by 10; two steps never share one). init runs the steps after the params are added, so a step can read them. `init` itself is never edited. Add the step's effects to `start_steps()` in `test/unit/structure_test.lua`.
- **Registering a cleanup step**: `S.register_cleanup(S.constants.CLEANUP_ORDER.<step>, fn)` in the module that starts the resource, and one line in `CLEANUP_ORDER` (`lib/constants.lua`) at a free order at its place in the sequence (orders are spaced by 10; two steps never share one). `cleanup()` itself is never edited.
- **Registering a grid layout**: a `lib/grid/layout_<name>.lua` sets `S.registry.grid_layouts["<name>"] = {key = ..., redraw = ...}`, plus one `include` line in `strata.lua` and the size match in `grid_layout()` (`lib/grid/core.lua`).
- **Registering an engine area**: a new `lib/engine/Strata<Name>.sc` (`+ Engine_Strata { ... }`) with one `strataArea<Name>` method at a free `order` (above 70 from 3.2: scale 80, variation 90, loop 100, freeze 110, mix 120), its state in `areaState[\<name>]`, never a new variable. `lib/Engine_Strata.sc` is never edited. A value a later package changes is a method in the area file that owns it (`bufferStateStride`, `standardBufferSeconds`, `ringSeconds`, `ringGuardSeconds`).
- **On a conflict in a registration line** (an include, a `UI_PAGES` entry, a `START_ORDER` or `CLEANUP_ORDER` entry, a `register_params` call, a module table row in this file): keep both lines, in the order the sequence needs, and rerun the checks. Two `START_ORDER` or `CLEANUP_ORDER` entries on the same number: give the later one a free number.
- **Shared files** (CHANGELOG.md, `docs/status.md`, this file, README.md): edit them only where your package needs to. A feature pull request never edits CHANGELOG.md.
- **Changelog**: every pull request adds a changelog fragment `changes/<branch-name>.md`; see `changes/README.md`. The release pull request merges the fragments into CHANGELOG.md.

## Code Style Guidelines

**Named constants, never magic numbers.** They live in `lib/constants.lua` (`S.constants`, aliased as locals at the top of each module that uses them): `NUM_VOICES` (7), `NUM_SCENES` (8), `PATTERN_LENGTH` (16), `SCENE_DATA_VERSION` (3), `NUM_MOD_SLOTS` (3), `NUM_UI_PAGES` (8, `#UI_PAGES`), `MAX_STEP_LEVEL` (15), `NUM_BUFFERS` (8), `STANDARD_BUFFER_SECONDS` (16), `STANDARD_PERFORMANCE`, `BUFFER_DATA_VERSION` (1), `NUM_LFOS` (3). The engine mirrors them as `numVoices`, `numBuffers`, `standardBufferSeconds` and `numModSlots`. The slot length is a tier value, not a constant: read `S.performance.buffer_seconds`. Never hardcode 7, 8 or 16 in voice, scene, pattern or buffer code (bare numbers in grid code are coordinates and LED levels).

**Lua's 200-local limit applies to each function, checked by a test**: the locals probe measures the free locals at the end of each file's main chunk and of each module's constructor function, and fails when any has fewer than 30 (`strata.lua`'s main chunk uses 5). Group a feature's constants in one table (as `LFO_PAGE`, `GRID_LAYOUT`, `BUFFER_PAGE`, `FX_PAGE`, `BUFFER_SETTLE` do) rather than adding many `local`s, and split a module that runs short.

**Descriptive names**: `selected_voice`, not `sv`; `master_density`, not `md`.

**Bounds-check every index** (voice 1..`NUM_VOICES`, scene, step, slot, grid coordinates) before indexing, so tables never grow by accident. **Clean up** every metro, clock, poll and device handler on exit: the module that owns it registers a step with `S.register_cleanup` at its place in `S.constants.CLEANUP_ORDER` (never code in `cleanup()` itself; the sequence is in `docs/notes/lua/state-and-voices.md`). Cancel an existing clock before starting its replacement.

**No unguarded recursive deletes**, in code or in the shell commands you run. Lua tests delete only through `h.remove_tree` (inside `h.data_root`); the engine check and `test/run_engine_check.sh` delete only folders matching their own templates, and a structure test fails on any other `rm -r`. In your own commands, quote the path, fail on an empty variable and pass it after `--` (`rm -rf -- "${dir:?}"`), spell out an absolute prefix rather than a bare `$var/...`, and remove a worktree with `git worktree remove`, never `rm`.

**Keep docs current in the same change**: the `docs/user/` page for the area (user-facing behavior; README.md only for the overview, quick start and index), the module's notes file (implementation details, and its "Must not break" list), this file (rules, the command table, the module table) and `docs/status.md`.

### CRITICAL: keep Lua and the engine in sync

- A new or changed `addCommand` needs: matching `engine.*` calls (same count and types; SC type codes i/f/s), the table row above, and the engine stub picks it up from the SC source.
- A new SynthDef argument the user controls needs: the `voices` table default, the voice's `param_order`, `add_voice_params()`, `get_param_spec()`, a sender in `S.engine_senders`, and the exact case-sensitive name. Grain params go through `setGrainParam` and `GRAIN_PARAM_IDS`.
- Lua defaults are what the engine plays (`sync_voice_to_engine` sends them). SynthDef defaults for the filter and delay must equal the Lua param defaults, because the script never bangs its params.
- New voice-level controls that a buffer or input grain synth also needs belong in `voiceControls` / `grainControls` and `controlNameSets` (see Audio Sources in `docs/notes/engine/grains.md`).

### IMPORTANT: update the UI with every feature (128×64 screen)

Details: `docs/notes/lua/ui-core.md`, and each page's `docs/notes/lua/pages/<page>.md`.
- Pages: `UI_PAGES = {"MAIN", "VOICE", "SEQ", "FX", "LFO", "BUFFER", "SCENES", "SETUP"}` (`UI_PAGES.index[name]` gives the index; `UI_PAGES.MAIN_PAGE` is 1). Each page file (`lib/pages/main.lua`, ...) creates one record at `S.registry.pages[UI_PAGES.index.<PAGE>]`, which `enc`, `key` and `redraw` in `strata.lua` dispatch through. Required fields: `name`, `draw()` (the page body only), `hints(alt_held)` (the hint row's text), `enc(n, d)`, `key(n)`; optional: `alt_enc`, `alt_key`, `key_release`, `alt_key_release`, `enter`, `leave` (run by `set_ui_page` on a page change), `arc_button`, `header_status`, `layout_states`. Its rings' file (`lib/arc/main.lua`, ...) sets only the arc fields (`arc_delta`, `arc_redraw`, `arc_alt_delta`, `arc_alt_redraw`), which `arc_delta`/`arc_redraw` in `lib/arc/core.lua` dispatch through (a page without them, SETUP, ignores turns and leaves the rings off); the page file never sets them. `docs/notes/lua/ui-core.md` describes each field. `arc_key` calls the shown record's `arc_button` on every page that has one. Find a page by index (`UI_PAGES.index.<PAGE>`, `S.ui_page`), never by its title string. Change pages only through `S.lib.ui_keys.set_ui_page` (it runs `leave`/`enter` and forgets carried arc ticks), never by setting `S.ui_page`. Change a page's draw or hints function (`redraw_main`, ...), never `redraw()`.
- **ALT** is K1 held (`S.alt_held`, set through `S.lib.ui_alt.set`; `lib/ui/alt.lua`). Every ALT+K2/ALT+K3 action goes through `alt_action(page, n)` (global), which runs the record's `alt_key(n)`, so the long-press fallback (`S.lib.ui_alt.long_press`, `LONG_PRESS_SECONDS` 0.6; a hook, no timer calls it yet) can trigger the same actions; never call `alt_key` directly. A key release acts only on the page where the key went down (`S.key_press_page`). A key that went down with ALT is an ALT press (`S.key_press_alt`): its release goes to `alt_key_release`, never `key_release`, even if K1 came up first, and it never reaches `key`. With ALT held, E2/E3 go to `alt_enc(n, d)` first and on to `enc` unless it returns true; E1 ignores ALT. `forget_held_keys` clears ALT and the ALT presses.
- **Encoder and ring changes**: never call `params:delta` from an encoder or a ring. A page's `enc` calls `enc_param_delta(n, id, d)` for every param edit; rings call `arc_sweep_param` or `delta_with_detent(id, d, opts)` (`lib/ui/detent.lua`). The one exception is a binary VOICE row (a registered param): VOICE's E3 and its arc ring set it with `params:set` (1 for a turn or whole step up, 0 for one down), since a toggle's delta flips it either way. Fine adjustment is ALT+E3 only (a control param moves `quantum / FINE_DIVISOR` of raw per detent), never ALT+E2 or the arc. Center detents: a range through 0 lands on exactly 0 when a change reaches or crosses it, whatever the delta, and holds there for `DETENT.encoder_detents` (3) detents or `DETENT.arc_ticks` (24) ticks, but only within `DETENT.hold_seconds` (1 s) of reaching 0, so an old hold never swallows a later turn.
- **Redraws**: when state the screen or arc shows changes, call `request_redraw()`; never call `redraw()` or `arc_redraw()` from script code. The frame clock draws whatever is dirty at `UI_PAGES.FRAMES_PER_SECOND` (15), and every param action already requests one. A page that animates (LFO, SEQ while playing) is marked dirty by `draw_frame`, screen only; a page's `draw()` never calls `request_redraw()`, which would redraw a connected arc at 15 fps. Grid redraws stay direct (`grid_redraw()`).
- Every page has the header at y=8 (`draw_header()`, positions in `S.constants.HEADER`; no `dens:`: title at x 0, eight 2×2 page dots from x 40, `[M]` at 76, the play mark at 90, `REC` at 96, scene `S1`-`S8` right-aligned at 127; a record's `header_status()` text at 79 replaces `[M]`, the play mark and `REC`) and the hint row at y=62 (`redraw()` draws it with `draw_hints(S.lib.ui_flash.text("hints") or record.hints(S.alt_held))`; a page never calls `draw_hints`). Transient messages go through `S.lib.ui_flash` (`lib/ui/flash.lua`): `header_flash(text)` replaces the dots and indicators for 1.5 s, `S.lib.ui_flash.start("hints", text, seconds, page)` the hint row, only while that page (a `UI_PAGES` index) is up (`buffer_page_flash` passes BUFFER's), so a prompt never shows over another page's keys. Never give a page its own flash clock. On MAIN the voice list (x 0-60, `UI.ScrollingList`, 4 visible rows) sits left of the divider at x=62 and the selected voice's details at x 65-127. Status indicators use `[BRACKETS]`; levels are 15 bright, 4 dim, 1-2 subtle.
- **Page cursors that other modules move**: the VOICE cursor (`S.cursors.voice`) and its anchor are `lib/ui/cursors.lua`'s: it is read outside a redraw through `S.lib.ui_cursors.sync("voice")` and set through `S.lib.ui_cursors.place("voice", index)` or `move("voice", d)` (the VOICE page's `sync_cursor()` and `place_cursor(index)` are the same calls), never `clamp_all()` alone or a bare assignment (either loses the anchored param when the source changes A → B → A). Every E2 or ring move of the SCENES cursor goes through `S.lib.pages_scenes.move_cursor(slot)`, which disarms a pending overwrite. A ring never reaches into a page's state (`S.scenes_page`, ...) itself. Row pages move their cursors through `S.lib.ui_field_list` (`move`, `clamp`), which skips section labels.
- A new voice type needs a `MAIN_PARAMS` entry (E3, the MAIN display and arc ring 2 follow; `list_name` is its voice-list name, at most 5 characters) and `get_param_spec()` specs.
- The layout tests check every page for overlapping strings, text off-screen, the hint row and the list's bottom edge, and that no MAIN string crosses the divider (width estimate: `stubs.text_width`). `test/unit/ui_layout_test.lua` draws every page record with every voice, source (synth, buf 1, input), ALT state and flash, then each record's `layout_states`. Keep them passing. They see only strings on one baseline and text off-screen, not strings crowding on nearby baselines or text over a rect or line: look at the page renders after a layout change.
- Before finishing, check that new values are visible with units, hints match the keys, all 7 voices fit, and nothing leaves 128×64.

### CRITICAL: keep grid and arc in step with the code

Details: `docs/notes/lua/grid-core.md`, each layout's `docs/notes/lua/grid/layout_<size>.md`, `docs/notes/lua/sequencer.md`, `docs/notes/lua/arc-core.md` and `docs/notes/lua/arc-pages.md`.
- Grid layouts: `grid_key_256/128h/128v/64()` and `grid_redraw_*()`, one file per layout (`lib/grid/layout_256.lua`, ...), each registering `{key, redraw}` in `S.registry.grid_layouts`; `grid_key` and `grid_redraw` (`lib/grid/core.lua`) dispatch through it by the name `grid_layout()` picks from the exact `cols`/`rows`. The 256's faders are in `lib/grid/faders.lua`. Patterns are `S.patterns[voice][step]` (`lib/sequencer.lua`). Anything the grid shows must call `grid_redraw()` when it changes, wherever it changes (cheap without a grid).
- Grid keys and pages are per port: a layout's `key(port, x, y, z)` gets presses and releases (it returns on `z == 0` unless it handles releases) and `redraw(port, grid_device)` draws one grid. Read and set a grid's page with `S.lib.grid_core.page(port)`/`set_page`, and test "does any grid show page n" with `any_page(n)`; there is no global grid page. Pattern keys go through `step_key` (the step-level gesture), scene save keys through `scene_save_key` (a 0.5 s hold, `GRID_HOLD`). Held keys are per port (`S.grid_held[port][x][y]` = press time): a key's release clears it, and `grid.remove`, `grid.add` and cleanup forget the port's held keys. A delayed key action uses `on_hold`, never its own clock: a new press or the release of the key, `grid.remove` and cleanup cancel its hold clock, so no hold fires for a released key, a removed grid or after exit. Other per-grid state (the 256's clipboard, the 8×8's half) lives in `S.lib.grid_core.port_state(port)`, never in a layout local or on `S`, so each grid has its own and unplugging forgets it. Pattern edits from any page, ring or layout stay within bounds (voice, step, level 0..`MAX_STEP_LEVEL`) and call `grid_redraw()`.
- New params in `param_order` appear on the 256 fader page automatically (`fader_param_ids`, `set_param_from_column`, which follows the controlspec warp). The 16×8 and 8×16 fader pages use the same list through `lib/grid/faders.lua` (`set_fader_param`, four per page), so `S.param_page` means the same page on every grid. Review whether a feature needs grid buttons or LED feedback on every layout.
- Arc: review whether new params belong on a page's rings (`lib/arc/main.lua`, ...: `arc_*_delta`/`arc_*_redraw`, `ARC_FX_RINGS`, `ARC_BUFFER_RINGS`). Ring feedback must use the same ranges as the param specs: every ring is drawn through `arc_ring_fill` from `param_fraction`, or `arc_ring_fill_bipolar` for a range through 0 (`arc_ring_fill_param` picks). The page rings are set only in `lib/arc/<page>.lua`, and a ring that shows a cursor or a step level draws the fraction `docs/notes/lua/arc-pages.md` names.
- Everything must degrade gracefully when no grid, arc or MIDI device is connected. Update `docs/user/grid.md` or the layout's `docs/user/grid/<size>.md`, `docs/user/arc.md` and the matching notes file with new patterns.
