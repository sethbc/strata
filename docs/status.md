## Running the checks

- **Lua:** `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua`, from the repo root. They need only Lua 5.3 (norns' version) and LuaJIT.
- **Engine:** `test/run_engine_check.sh [path/to/norns]` compiles the engine against a norns checkout's `sc/core` and runs `test/engine_check.scd` on a silent local scsynth with norns' 8192 KB real-time pool.
  - It needs SuperCollider and a norns checkout (`git clone https://github.com/monome/norns ~/src/norns`, or set `$NORNS_DIR`; CI uses commit `227aa0442181e3eab3fc189ee6b5342648ce7300`).
  - It uses `$SCLANG` if set, else `sclang` on `PATH`, else the macOS app.
  - It stops after `$ENGINE_CHECK_TIMEOUT` seconds (1800 by default, which a full run of about 17 minutes on 3.14.1 or 3.13 (about 1030 s of areas at 3.4.0) fits with about 12 minutes to spare; CI passes `ENGINE_CHECK_TIMEOUT=570` to keep each shard below its 600 s limit; the check's own deadline is 30 s less) and at once on a compile error. Stopping sclang also stops its scsynth (descendants found with POSIX `ps`, so neither `pgrep` nor `timeout` is needed), a scsynth that outlives a crashed sclang is stopped through the PID the check writes to its work dir (#152), and a signal to the script (Ctrl-C, a caller's limit) stops sclang, its scsynth and the work folder and exits 130 (#331).
  - Each run boots scsynth on the UDP port in `$STRATA_SC_PORT` (57110 by default). Runs on different ports can overlap, for example one per worktree (`STRATA_SC_PORT=57141 test/run_engine_check.sh`); avoid 57120 and the few ports above it, which sclang takes for itself when several run. Two runs on the same port collide, so on a shared machine give each its own port or wrap the runs in a lock, for example `flock /tmp/strata-engine-check.lock test/run_engine_check.sh`.
- **Soak** (on demand, not in CI or a full run): `STRATA_ENGINE_CHECK_AREAS=soak test/run_engine_check.sh` runs rounds of a 60 s load, save and every-frame check of the saved file on a high engine of its own, to stress sclang's allocation as a long session would (#131). `STRATA_SOAK_ROUNDS` (40) and `STRATA_SOAK_SECONDS` (60; 120 or 300) size it; give a long soak a longer `ENGINE_CHECK_TIMEOUT` (the check's own deadline follows, 30 s under it). Run it with SuperCollider 3.13, norns' version, to be meaningful.
- **Engine check on SuperCollider 3.13:** `test/run_engine_check_313.sh [-n runs] [-j parallel] [-o log_dir] [-1] [-l] [-c] [path/to/norns]` runs the check in Docker on CI's SuperCollider (norns' 3.13). A full run is CI's shards (read from `.github/workflows/test.yml` at each start), each in a container, and so a fresh sclang, of its own, and passes only when every shard passed (#581); `-1` runs every area in one sclang, as before, `STRATA_ENGINE_CHECK_AREAS` runs those areas in one container per run, `-l` prints the shards and `-c` classifies a log folder again. `-j` containers run at once, each on its own network; it builds its image (`test/docker/sc313/Dockerfile`) on first use and reports how many runs passed, failed or crashed (#131). Details in `docs/notes/lua/test-harness/engine-check-runner.md`.
- **Page renders** (on demand, not in CI): `lua test/render_pages.lua <dir>` then `python3 test/render_pages.py <dir> --font ~/src/norns/resources/norns.ttf` (needs Pillow) draws every page state as a PNG. The layout tests catch overlaps on one baseline and text off-screen; the renders are the check for text over a line or box and for strings crowding on nearby baselines.
- **Engine check on Linux:** install `supercollider-language`, `supercollider-server` and `jackd2`. scsynth needs a JACK server, and a dummy driver needs no sound card. Start one in the background, then run the check headless:

  ```sh
  nohup jackd --no-realtime -d dummy -r 48000 -p 1024 >/tmp/jackd.log 2>&1 &
  SCLANG=/usr/bin/sclang QT_QPA_PLATFORM=offscreen test/run_engine_check.sh ~/src/norns
  ```

  If scsynth does not boot, check that JACK is running (`jack_lsp` fails when it is not) and start `jackd` again. Run JACK at 48 kHz, like norns. The check fails at once, within seconds, with `scsynth did not boot` when the server cannot start, and with `port <n> already has a server` when another run holds the port (#471, #472).

## What 3.4 changed

CHANGELOG.md has every change. In short:
- **Sound:** 3.3's by default (every new setting starts off or neutral, and with every offset at 0 the grain synths and the stage play 3.3's within 1e-6), apart from LFOs on a voice's grain pitch, position and size, which run in the engine (smooth, same depth), and an LFO on the voice filter's cutoff, which runs there too and moves in octaves where 3.3 moved it in hertz (#613).
- **Modulation:** six LFOs (eight shapes, LFO-to-LFO rate and depth), the five fast destinations run in the engine at up to 50 Hz and the rest in Lua at up to 10 Hz, updating at 48 Hz; sixteen macros in four banks; a morph between two scenes or four (the XY morph); scatter; four gesture recorders; a sixteen-routing matrix from LFOs, macros, recorders and the input level; every modulation writer sharing one send budget (150 messages per 100 ms).
- **Sequencing:** a clock per voice (length, division, swing), probability, ratchets, step locks, notes, bookmark jumps and gates per step, Euclidean fill, pattern chaining, transport following (`seq_follow_transport`), quantized actions; SEQ's edit view and the grids' step editor; grid step keys toggle on release.
- **Scenes and voices:** sixteen named scenes in two banks (format 6), mute and solo per voice.
- **UI:** nine pages (MOD sixth), the LFO page's three-LFO window, MAIN's `~`, learn across page changes with a header notice, the 16×16's XY pad, macro, recorder, mute and morph keys on the grids.
- **Data:** `macros.data`, `matrix.data` and `gestures.data` (live, and beside each PSET), read and written through `lib/data_files.lua`; a 3.3 PSET loads every new setting at its default and its LFOs imported, and 3.3's MIDI maps on LFO params are moved or removed at start.
- **Code:** the modulation area (`lib/engine/StrataModulation.sc`, five commands; one norns restart), the stage's step gate and mute, the stage's check limit 42 KB (to confirm, `docs/decisions.md`); the registries, base overrides, extra offsets and send budget of `lib/engine_sync.lua`; eleven new Lua modules.
- **Tests:** 1703 Lua tests at 3.4.0 (1253 at 3.3.2); the engine check's modulation area; CI's Lua suites in parallel.

- **Limits to keep in mind:**
  - Lua's 200-local limit applies to each function: the locals probe in `test/run.lua` measures the free locals at the end of each file's main chunk and of each module's constructor function, and requires 30 in each (`strata.lua`'s main chunk uses 5). Group new constants into tables, and split a module that runs short.
  - An LFO that runs in Lua plays at most 10 Hz (`LFO.lua_max_hz`) and sends at most 12 values a 48 Hz step with the matrix's (576 a second); one on a fast destination runs in the engine, up to 50 Hz. A modulation writer's sends share 150 messages per 100 ms (`ENGINE_BUDGET`), a number the hardware soak (#6) is to confirm.
  - scsynth's real-time pool on norns is 8192 KB. With six engine LFOs and scatter running on every voice and destination, 3.4.0's worst cases leave 4.79-4.99 MB free on standard and, with spectral freeze on every voice and the FDN reverb, 4.12 MB on high at the tightest, synth -> buffer -> synth (536 KB above the 3.5 MB floor, about 424 KB counting the spectral writers' late allocations), and 4.88 MB at the all-buffer one, as CI's memory shard measures them; `\strataGrainBuf` is 69.1 KB of its 88 KB limit and each mix stage 40.9 KB of 42 (`docs/notes/engine/memory.md`). A new UGen with a delay line or table in the voice or grain SynthDefs, or a node per voice, needs that budget re-measured.
  - The largest scenes file 3.4 can write (sixteen scenes of full macros, routings and step attributes) is 7394 tables, under a quarter of the data file reader's cap of 32768 (`lib/data_files.lua`); a later block with tables per step (3.5's chords) re-measures it, since a file over the cap is refused whole.
  - sclang's garbage collector fails under millions of small allocations (#131, closed as a platform limit of norns' SuperCollider 3.13; seen once on 3.14.1 too while 3.4 was built). The rules that work around it are in AGENTS.md and `docs/notes/engine/files.md`, the device check is #6 section 6, and the 3.4 command rates' soak is #6's too.
