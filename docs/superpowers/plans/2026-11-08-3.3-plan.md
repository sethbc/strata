# Strata 3.3: Buffers as Instruments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the eight buffer slots playable: overdub and loop recording that stay playable while they record, a choice of record source (input, pre-master, post-master, one voice), arming by level, takes on the clock and in beats; random files, filling empty slots, a start point for long files and saving a loop region; a 64-point waveform per slot with playheads; position rows on every grid, arc scrubbing with friction, and four bookmarks per voice behind the interface 3.4 consumes.

**Architecture:** Wave 0 fixes every interface with no behavior change. 0a is the engine surface: the three changed signatures, the `recordState` poll, three new areas with neutral hooks, the record head and voice tap buses, the peak buffers, and the memory check re-measured on the merged 3.2 with the new floors. 0b is the Lua scaffolding: the grain-restart and ALT-release hooks, the constants, scene version 4, animating pages, a fifth grid page, and neutral `files`, `waveforms`, `playheads`, `positions` and `bookmarks` modules. Wave 1 fills the hooks in six parallel packages (three engine, three Lua), each owning its engine file or Lua module, its check area, tests and docs. Wave 2 builds the controls (the BUFFER page and header, the BUFFER arc rings, four grid layouts). Wave 3 releases.

**Tech Stack:** SuperCollider 3.13.0 (norns and CI) and 3.14.1 (local), class extensions `+ Engine_Strata { }`, core UGens only (`Phasor`, `BufRd`, `BufWr`, `Amplitude`, `DelayN`, `Sweep`, `SendReply`, `GrainBuf`); sclang `SoundFile` (`seek`, `readData` into fresh arrays), `Buffer.write` with `startFrame`/`numFrames`, `/b_getn`, `/b_setn`, `unixCmd`, timed bundles (`makeBundle`); Lua 5.3 and LuaJIT for the tests against `test/norns_stubs.lua`; the engine check through `test/run_engine_check.sh` on `$STRATA_SC_PORT`, and in the Docker image `strata-sc313` for 3.13.

**Spec:** `docs/design/3.3-design.md` (approved 2026-11-08: every question decided as recommended, and the memory rule of Question 1: high 3.5 MB, standard 3 MB, 88 KB per synth, eight recordings leaving 3 MB on both tiers). It binds over `docs/design/3.1-3.6-roadmap.md` for 3.3. Read the design sections a task names before starting it. `docs/design/3.4-design.md` (approved) consumes exactly `S.lib.bookmarks.recall(v, n)`, `S.lib.bookmarks.is_set(v, n)`, `SCENE_DATA_VERSION` 4 (3.4 takes it to 5) and engine areas 130-150 (3.4's modulation area is 160).

## Global Constraints

- Everything in CLAUDE.md applies: replace-never-stack, `cutSynth`, `openedGate`, `sendToSynth`, fade-before-zeroing and `slotChanges`, `afterSlotFade`, the file-write invariant (`.part`, `instanceTag`, generation, `mv -f`), the mirror rules and `silentBus`, the velocity invariant, the command table, Lua as the only source of values, `send_param_to_engine`, the scene rules, the registries, `request_redraw()`, the layout tests, bounds checks, cleanup steps.
- **No package edits `lib/Engine_Strata.sc`** (not even 0a: the record variables `recordSynths`, `recordFrameBuses` and `stopReplies` stay there; only their allocation moves). Engine files are named `Strata*.sc`; extension files add methods only, never variables; new state lives in `areaState[\record]`, `areaState[\waveform]`, `areaState[\positions]`. A new engine file needs the norns restart note in its changelog fragment.
- **No new command.** Exactly these signatures: `loadBuffer(slot, path, start)` `"isf"`; `recordBuffer(slot, seconds, level, feedback, source, threshold, loop, delay)` `"ifffifif"`; `saveBuffer(slot, path, start, length)` `"isff"`; `stopRecord(slot)` `"i"` extended to armed recordings. One new poll, `recordState`, not periodic: `((record_number * 4) + state) * numBuffers + slot_index` (state 0 armed, 1 recording, 2 ended and kept, 3 canceled). New grain controls on both grain SynthDefs: `recHeadBus`, `scrubRate=0`, `scanHold=0`, `t_scanReset=0`, `tapOut`; `setGrainParam` names `t_scanReset` (sent, never stored), `scrubRate`, `scanHold`.
- **Engine constants** (methods in the owning area file): `waveformPoints { ^64 }` (Lua `WAVEFORM_POINTS` 64); `recordFadeSeconds` 0.005; `recordPrerollSeconds` 0.01 (a fixed `DelayN`); `recordGuardFrames` (5 ms plus one block, at the server rate); `recordPrepMargin` 0.15 s; `peakRefreshSeconds` 0.5; `bufferFadeWait` stays 0.06 s. **Lua constants** (`lib/constants.lua`, 0b): `NUM_BOOKMARKS` 4; `RECORD_SOURCES` `{"input", "pre-master", "post-master", "voice 1" .. "voice 7"}` built from `NUM_VOICES`; `RECORD_SYNC = {beats_per_bar = 4, lead_seconds = 0.25}`; `FILES = {restart_seconds = 0.3}`; `WAVEFORMS = {refresh_seconds = 0.5}`; `PLAYHEADS = {update_hz = 15}`; `SCRUB = {release_seconds = 0.08, window_seconds = 0.1, max_glide_seconds = 4, stop_rate = 0.001}` (1f may retune `SCRUB` by hand); `NORNS_SAMPLE_RATE` 48000; `SCENE_DATA_VERSION` 4; `BUFFER_DATA_VERSION` 2 (1e).
- **Area orders:** record 130, waveform 140, positions 150. 160 is 3.4's modulation; later areas take free numbers above 160.
- **Real-time memory floors** (Question 1, decided; one rule for 3.3 and 3.4): at the **mixed** worst case (3.2's: every voice a live ring grain synth, an input grain synth in its 2 s release, a buffer grain synth in its 50 ms cut) and the **all-buffer** worst case (21 `\strataGrainBuf`: every voice switched among three slots), each with one recording running (a pre-master loop recording into a slot a voice reads, so the head guard runs): at least 3 MB free on standard (twelve 256 KB probes) and 3.5 MB (3584 KB, fourteen probes) on high (spectral freeze on every voice, FDN reverb). The mixed worst case with all eight slots recording: 3 MB (twelve probes) on both tiers. Every grain SynthDef under 88 KB of the pool. Never size a delay line or table from a control.
- **sclang 3.13's garbage collector (#131).** Heavy sclang allocation crashes sclang on norns (an `int32` scan counter in 3.13's `GC.h` overflows). So: no per-sample sclang loops in engine code or check code (no `FloatArray.fill(n, { ... })`, `collect`, `do` or `abs` over audio-length arrays); build arrays with primitives (`FloatArray.newClear`, `fill` with a value, `maxItem`, `minItem`); every `SoundFile` `readData` into a fresh array (`freshReadArray`); no `LocalBuf` in any SynthDef (pass server buffers as controls); no `copyRange` slices in the peak scan. Test sound files are built with the merged primitive builders (Step 0 names them; `h.writeTestFile` until then only for short files).
- **3.2's sound by default.** Feedback 0, loop off, threshold off, sync off, source input, friction 100%, load start 0, bookmarks 0/0.25/0.5/0.75 (inert until recalled). The only audible changes: the 5 ms record fades on replace takes (Question 10), and a voice restarted during its release starts its scan from `buf_pos` (Question 24). Old scenes, PSETs and `buffers.data` load unchanged.
- **Scenes:** `SCENE_DATA_VERSION` 4; the four bookmark keys per voice are registered continuous keys (they crossfade; Question 2) with migration defaults 0, 0.25, 0.5, 0.75 and `validate_scene` numbers in 0-1. Record settings and `scrub_friction` are PSET-only. `scrubRate`, `scanHold`, playheads and peaks files are never stored. Registered params never reach randomize, mutation or the 256 fader pages (`fader = false`).
- **Transient engine state.** `scrubRate`, `scanHold` and `t_scanReset` are the one exception to "the `voices` table is the only source of values": not params; `lib/positions.lua`'s record `sync` sends `scrubRate 0` and `scanHold 0` with every voice sync.
- **Grids:** no key changes its action on a layout that already has it (Anti-goals); 3.3 adds a page or view per layout and an armed level on the existing record keys.
- **Changelog:** each package adds `changes/3.3-<package>.md` (`### Added` / `### Changed` / `### Fixed`, a bullet under each heading used). A feature package never edits CHANGELOG.md. `docs/status.md` changes in Wave 3, except that a pull request closing an open item removes that item's line (`changes/README.md`).
- **US English** in code, comments and docs (the spelling test covers `lib/engine/` and `test/engine_check/`). Docs never name the maintainer.
- **Isolation.** Each task's dispatch names a scratch folder `scratchpad/<task>/` (for example `scratchpad/3.3-1a/`); a worker writes only there and in its own worktree, never to another worker's folder, worktree, logs or containers. Deletes are `rm -rf -- "${dir:?}"` on a path inside the worker's own folder, spelled out; worktrees go only with `git worktree remove`.
- **Every finding is fixed, never deferred.** A review's findings are fixed in the same pull request; a problem found outside the package's scope gets its own GitHub issue and pull request at once, never a "later" note.
- **After every task:** `lua test/run.lua`, `luajit test/run.lua`, `lua test/sync_check.lua` pass. A task that touches engine code or a check area also passes the full engine check on 3.14.1 (`STRATA_SC_PORT=<its port> test/run_engine_check.sh`) and **four full runs on 3.13** in Docker (below). ## Review Focus

1. **The seam at the record head.** A grain that starts in the guard zone of a moving head must move just behind it, for forward and reverse rates, modulo D in loop mode, and never leave the valid region; a start past D is never moved; head bus -1 makes the guard a no-op. Test in 1a (`"record: no grain reads across the head at rates -4, -1, 0.5, 1 and 4 with 0.5 s grains"`, `"record: the head guard is a no-op with the head bus at -1"`).
2. **A slot never shrinks, and is zeroed only through `afterSlotFade`.** A playable recording on a slot with audio zeroes nothing and sets the length to `max(V, D)` only at its start (arming); a canceled armed recording changes nothing; a playable recording into an empty slot zeroes it after the fade first. Tests in 1a (`"record: a playable recording keeps the slot playing and sets its length to max(V, D) at its start"`, `"record: a canceled armed recording leaves the slot as it was"`).
3. **Late steps and stale reports.** Every delayed step of a recording (a synced take's preparation, the zeroing, the start, the length update, the stop's frame count read in `onFree`) runs only if `slotChanges` is unchanged; `recordState` reports carry the record number, and Lua acts only on its newest recording's, in any order. Tests in 1a (`"record: rapid record, load, clear and stop leave at most one record synth and drop every late step"`, `"record: a load sent during a synced take's wait drops its preparation"`) and 1d (`"a stale recordState report never acts on a newer recording"`).
4. **Allocation in the peak scan (#131).** The scan rides on `fileDecodes`' chunks with two primitives per chunk (`maxItem`, `minItem`), bin-aligned chunks, one 64-value `FloatArray` per load; no `abs`, `copyRange`, `collect` or per-bin arrays. Tests in 1b (`"waveform: a 300 s load and a 300 s save back to back, three times, without an sclang abort"`, run on 3.13) and a source scan in `test/unit/structure_test.lua` (`"the peak scan allocates nothing per sample"`).
5. **Transient scan state never leaks.** `t_scanReset` is never stored (a replacement grain synth never starts with a stale trigger); a started or switched voice never inherits a glide or a hold. Tests in 1c (`"positions: t_scanReset restarts the phase and is not stored"`) and 1f (`"a voice sync sends scrubRate 0 and scanHold 0"`).
6. **Playheads agree with the engine.** The engine restarts the scan at every grain start, including a re-gate (`gateVoice`); Lua resets its estimate on the same events (`S.register_grain_restart`, jumps). Tests in 1c (`"lifecycle: a re-gated buffer voice restarts its scan"`) and 1f (`"the playhead resets on voiceOn, a source switch and a jump"`).
7. **The 3.4 interface, exactly.** `S.lib.bookmarks.recall(v, n)` and `S.lib.bookmarks.is_set(v, n)` with the behavior §5.4 pins, creating no node. Test in 1f (`bookmarks_test.lua`).

## How to read the tests

**Lua.** Tests live in `test/unit/<module>_test.lua`, each `return function(h) ... end`. ## Self-review notes (design ambiguities and how this plan resolves them)

- **`saveBuffer` lives in the files area now.** #139 (merged after the design) moved `saveBuffer` and its `bufferSaveResult` poll into `StrataFiles.sc`, so 0a owns `StrataFiles.sc` in Wave 0 for the signature (design §13 names only `StrataBuffers.sc`), and 1b in Wave 1. A trim region under one frame reports `failed` on `bufferSaveResult` as well as posting why, so BUFFER's save flash stays truthful.
- **`buffers[slot]` is `S.buffers[slot]`** (the design writes `buffers[slot].start` and `.records_sent`).
- **Neutral Lua modules instead of guarded calls.** Design §13 has 1d and 1f call `S.lib.waveforms` "guarded until 1e lands". This plan has 0b create the five modules with neutral functions, as 3.2's Wave 1 created neutral engine hooks, so Wave 1 packages call each other's names without guards and their tests run against the neutral versions. 0a's `S.lib.record.state` is a minimal real accessor, so 1f needs no guard either.
- **K1's release.** Question 19 says the scan hold ends when K1 comes up, but no page hook sees that. 0b adds `S.register_alt_release`, run from `S.lib.ui_alt.set(false)` and `forget_held_keys`; 2b registers the hook.
- **The peak hooks.** The design names `writeSlotPeaks` and `slotPeakBuffer`. 1a must also read the record synth's bins and 1b clear the peaks, so 0a adds `readSlotPeaks(index, usedBins, action)` and `clearSlotPeaks(index)`: 1a calls them, 1b fills them, and neither edits the other's file. 1a runs the 0.5 s refresh of a playable recording (it knows when one runs).
- **Constants in one place.** 0b adds every 3.3 constant table to `lib/constants.lua`, so Wave 1 edits only its start and cleanup lines there (and 1e's `BUFFER_DATA_VERSION`, 1f's `SCRUB` values). `START_ORDER`'s test counts one order per registered step, so each Wave 1 package adds its own order with its step; the numbers are fixed here so they never collide.
- **The rate check needs the server rate in Lua.** Question 3's flash compares the slot's rate with the server's; 0b adds `NORNS_SAMPLE_RATE` (48000) and 1e records each loaded file's rate (`audio.file_info`).
- **Shared files.** `test/norns_stubs.lua` (0a's argument checks, 0b's `audio` stub), `lib/constants.lua`, CLAUDE.md and `test/unit/structure_test.lua` are edited by several packages, each in its own lines, as listed under "Registration lines and shared files". `docs/user/sources-and-buffers.md` is split by section between 1d and 1e, as the design says.
- **Memory in steps.** 0a lands the new floors and the all-buffer case first, with 3.2's record synth for the eight-recordings case; 1a replaces those with one recording per source kind and adds the one-recording worst cases; 1a and 1c both grow `\strataGrainBuf`, so the second to merge posts the combined figures (as 3.2's 1a/1b did).
- **CI shards.** 0a gives `record` and `waveform` a shard each (their Wave 1 checks are long, and the 300 s soak runs in `waveform`), so no Wave 1 package edits `test.yml`; Wave 3 rebalances.
- **Structure checks.** `test/engine_check/structure.scd` is 0a's in Wave 0 and nobody's in Wave 1; each area's structural checks go in its own area file.
- **The 3.4 wraps.** 3.4's 1f wraps 3.3's jumps and recalls with one line each in `lib/positions.lua` and `lib/pages/buffer.lua`, so every user jump and recall enters through `jump` or `recall_bookmark` (the grid through `grid_key`/`strip_key`, BUFFER's `bm` through `recall_bookmark`).
- **3.4's figures.** 3.4's design budgets 3.3 at about 30 KB; 3.3's own design estimates about 68 KB (mixed) and 187 KB (all-buffer). The floors were decided with 3.3's figures, so nothing here changes; Wave 3 posts the measured figures for 3.4's plan.
