# 3.9's First Part: The State Machines Made Explicit, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, as `docs/workflow.md` runs it (parallel packages, one worktree and branch each, batch landings). Steps use checkbox (`- [ ]`) syntax for tracking. **Not started:** no task of this plan is built until the maintainer says so.

**Goal:** Make every state machine Strata keeps without naming explicit (one name and one reader, a table a test runs, a seeded walk, a state shown where it changes what a key does) and close the 86 issues the search filed, #864-#949, but #939.

**Architecture:** Fifty-five packages in seven waves, ordered by which files they own. Wave 0 adds three test helpers, one clock helper and the notes' Machines convention. Wave 1 fixes the defects, each from a failing test. Wave 2 writes the transition tables, their tests and the missing invariants, changing no behavior. Wave 3 adds the seeded walks. Wave 4 gives derived states one accessor each. Wave 5 shows the states a player needs to see. Wave 6 holds four follow-ons and the docs pass. Nothing is released: the fragments ride to 3.9.0.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua`; SuperCollider 3.14.1 locally and 3.13 in Docker for the engine check (packages 1m, 1n, 1o, 2j, 3e, 4e); norns' `params`, `clock`, `midi`, `grid` and `arc`.

**Spec:** `docs/design/3.9-state-machines-design.md` (written 2026-11-21, awaiting approval). Its facts are the eleven files under docs/design/3.9-state-machines-facts/: one per audited area (`lua-scenes.md`, `lua-ui.md`, `lua-buffers.md`, `lua-voices.md`, `lua-sequencer.md`, `lua-modulation.md`, `lua-grid-arc.md`, `lua-io.md`, `engine-voices.md`, `engine-buffers-fx.md`) and `probes.md`, the audits' probe tests. A task names the fact file and section it argues from; that section's sites (file and line), its state lists and its event tables bind as part of the task, except where "The design against the merged code" below rules otherwise. Line numbers in the fact files and in the issues are `main`'s at a1c8e8b4 (3.8.0). Each issue's body is part of its task.

## Global Constraints

- Everything in `AGENTS.md` applies: named constants, `send_param_to_engine`, the registries, `request_redraw()`, bounds checks, the data files rule, the locals probe (30 free locals per main chunk and constructor), a module's constructor shape, engine calls only as `engine.<name>(...)`.
- **No stored state is added for a state that can be derived.** An accessor reads the fields that exist. A package that finds it needs a second record of a fact stops and reports NEEDS_CONTEXT.
- **The default sound does not move, and no param's id, default or spec changes.** The one re-base of an exact-message test this plan allows is 4c's (#925): it names every line it moves in its report.
- **No file format changes.** `SCENE_DATA_VERSION` stays 10; `buffers.data`, `samples.data` and every side file keep their versions (4g moves two files onto another writer and writes the same bytes).
- **No engine command, SynthDef argument or node is added,** and `lib/Engine_Strata.sc` is not edited: an engine package adds methods and keys of `areaState` only, and a method that keeps a closure and is called from a function goes through `areaCall` and into `AREA_CALL_METHODS`.
- **Every name the tests reach stays** (`local_value`, `find_upvalue`): a new accessor reads the old field and does not replace it.
- **A transition table is enforced in tests, never on the device.**
- **`AGENTS.md` has 77 words left.** No package adds a rule there. A package rewrites only a line its task names, no longer than it was; 6e checks the file whole.
- **The engine check has 32 s of room** (1768 s of 1800 s). The shares: 1m 2 s, 1n 4 s, 1o 6 s, 2j 0 s, 3e 10 s, 4e 2 s. Each engine package measures its areas before and after, rewrites its areas' times in `.github/workflows/test.yml` and `docs/checks.md`, and reports NEEDS_CONTEXT before landing if it cannot stay inside its share.

- **A fault found on the way gets its own issue** (`docs/workflow.md`, Findings). A table lands with the faulty cell as a `known` row and a walk with a named allowance; the fix is a package of the next batch.

## Review Focus

The five conditions the design implies that are most likely to bite a player; each has its test in the task named.

1. **A clock is stopped at the instant it wakes, in every module moved onto the helper.** No error line is printed and the clock's body does not run once more. Test in 0b ("a stop inside the margin retires: no clock error at the wake and the body does not run again") and in each adopting task ("stopped as its wake is posted").
2. **A key is held across every way its release can be lost:** the menu, a page change, a covering owner, a grid unplugged, the 64's chooser. Nothing stays held, no hint names a key that is up, nothing animates. Tests in 1b, 1c, and the end checks of 3a and 3b.
3. **A scene fades while the player edits by hand and moves the morph.** The loop pair stays legal, the morph's sets keep the filter on, and no scene's set is taken for a hand edit. Test in 1d ("a morph move during a fade keeps the loop pair's filter on").
4. **A device leaves and comes back while notes sound, a zone is due and a remote claims its port.** Every device gets as many offs as ons and a held port gets nothing. Test in 3d.
5. **A 3.8.0 PSET and its scenes are loaded after this work.** Nothing reads differently and the default start sends what 3.8.0 sends, but for 4c's named lines. Test in 6e ("a 3.8.0 start's messages, but for #925's").

8. **Every data file is read through `S.lib.data_files.read`,** so #895's list of problems is kept there and no reader changes.
9. **`handle.id` is not known inside a clock's function before its first wait** (`clock.run` resumes the coroutine before it returns). A module keeps the handle.

## How to read the tests

**All three checks** means `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua`, from the worktree root, each exiting 0.

**Test lists.** A task names its tests and the values that decide them. The issue's body and the fact file's section give the sites and the sequence that shows the fault; where they differ from this plan, this plan rules. A probe in `probes.md` prints where a test asserts: a fix's failing test asserts the wrong value the probe shows, then the fix makes the test's expected value the right one. A test re-based or deleted is named in the report with its reason.

**An issue marked † was read in the code and not run.** Its task's first step writes the test that would show it. If the test passes on the unchanged code, the worker stops, reports the test and its result, and the controller closes the issue without a change or rules otherwise.

**Shared test files and lists:** a package edits only the tests of its own behavior, and only its own lines of the two shrinking lists (`BARE_CANCEL_FILES` in `structure_test.lua`, `UNTABLED_INVARIANTS` in `docs_test.lua`); the landing keeps every package's lines.

## Branches, ports, fragments

A package's branch is `<kind>/sm-<id>-<slug>` and its fragment `changes/sm-<id>-<slug>.md`, with the slug its task's heading gives in brackets; the kind is `fix` for a task that closes a defect, `test` for a table or a walk, `feat` for an accessor or a shown state, `docs` for 0c, 2i and 6e. The engine packages' scsynth ports: 1m 57810, 1n 57820, 1o 57830, 2j 57840, 3e 57850, 4e 57860.

**Landing.** Workers push their branches and open no pull request. The controller lands reviewed packages in batches, one pull request a batch: wave 0 in the order 0a, 0c, 0b; wave 1's Lua packages as one batch and its engine packages (1m, then 1n on it, and 1o) as another; then one batch a wave, wave 6 in the order 6a, 6b, 6c, 6d, 6e. A wave starts from `main` with the batch before it on.

**Step 0 for every package:** check each name in its Consumes line, and each site its fact section names, against the merged code. Where a merged name or line differs, use the code's and say so in the report; where a consumed interface is missing, report NEEDS_CONTEXT.

**The engine check** is in `docs/checks.md`: a package's own areas with its `STRATA_SC_PORT` and `STRATA_ENGINE_CHECK_AREAS` while it works, every area and then `test/run_engine_check_313.sh` before it pushes.

**The skills lines.** A fix: `superpowers:systematic-debugging` (first), `superpowers:test-driven-development`, `superpowers:receiving-code-review` (if resumed with findings), `superpowers:verification-before-completion` (before the report's status). A task that only adds tests or an accessor: the same without the first.

**The last step of every task,** not repeated below: run all three checks (and the engine check where the task says); update the task's notes file, its Machines entry and its user page; add the fragment; commit with the task's message.
