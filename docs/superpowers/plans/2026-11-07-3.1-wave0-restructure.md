# Strata 3.1 Wave 0: Restructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split `strata.lua` into modules with registries, and split the tests, notes and process files, so later 3.1 work can run as parallel packages. No behavior change.

**Architecture:** `strata.lua` keeps the norns entry points and includes each `lib/` module exactly once, passing a shared table `S` (state, registries, module tables). Modules are moved one at a time, each move verified by the full suite, a golden-master behavior log and a static global-reference check. Then the test suite, the Lua notes and the changelog process are split per module.

**Tech Stack:** Lua 5.3 (norns) and LuaJIT for tests, `luac` 5.3 for static checks, the existing norns stubs in `test/norns_stubs.lua`.

**Spec:** `docs/design/3.1-design.md` §0, §1 and §9 (Wave 0). Read §0 and §1 before starting.

## Global Constraints

- No behavior change anywhere in Wave 0: every engine call, param, screen string, grid LED and arc LED stays identical (the golden master in Task 2 enforces this).
- Only `strata.lua` calls `include`, and it includes each module exactly once, as `include("lib/<path>")` (never `"strata/lib/..."`).
- A module file is either a plain table (`lib/constants.lua`) or a constructor: `return function(S) local M = {} ... return M end`, ending with exactly `  return M\nend` (the locals probe relies on it).
- Script-level state used by more than one module becomes a field of `S` (`x` → `S.x` at every use). State used by one module stays local to it. A local function used by several modules becomes a field of its module table (`S.ui.fit_text`). Functions that are global today stay global, defined in their module.
- Every name the tests reach with `local_value`/`find_upvalue` (49 names: `grep -o 'local_value("[a-zA-Z_]*")\|find_upvalue("[a-zA-Z_]*")' test/run.lua`) must end up as a field of `S` or `S.constants`, under the same name, so the tests keep working unchanged. That includes local functions the tests call (`finish_buffer_take`) and tables such as `LFO_DESTINATIONS`, `SCENE_TRANSITION`, `FX_PAGE` and `BUFFER_PAGE`.
- `lib/state.lua` is the one constructor that takes no argument (`include("lib/state")()` returns `S`).
- Modules may alias constants at the top of their constructor (`local NUM_VOICES = S.constants.NUM_VOICES`) so moved code stays verbatim.
- Every Lua file keeps at least 30 free locals in each function the probe measures (Task 2), except `strata.lua` until Task 16.
- All checks pass after every task: `lua test/run.lua`, `luajit test/run.lua`, `lua test/sync_check.lua`.
- US English in code, comments and docs. Docs never refer to the maintainer by name.
- Everything in CLAUDE.md still applies (invariants, `request_redraw()`, vport-only handlers, `send_param_to_engine`).

## Review Focus

1. **A bare reference left after a move** (`selected_voice` instead of `S.selected_voice`) in a path no test runs (an error branch, cleanup, hot-plug) becomes a nil global on the device. Task 2's static global-reference check fails on any global read that nothing defines.
2. **A module included twice** (norns' `include` is `dofile`) gives two copies with separate state. Task 1's test asserts exactly one `include` per module path, all in `strata.lua`.
3. **The install folder isn't named `strata`** (for example `strata-main` from a GitHub zip). Task 1's test asserts every include path starts with `lib/`.
4. **A script reload on norns** re-runs `strata.lua`: any state kept outside `S` (module upvalues outside the constructor, `package.loaded`) would survive into the new run. Task 1's test loads the script twice and asserts the two `S` tables share no state tables.
5. **Cleanup order drifting** when `cleanup()` becomes a registry (scenes saved after LFOs restore their values, MIDI detached after voices stop, ...). The golden master records cleanup's engine calls and file writes in order.
