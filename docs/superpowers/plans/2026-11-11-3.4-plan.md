# Strata 3.4: Modulation and Sequencing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Strata's sound move on its own and its sequencer deep enough to carry a piece: six LFOs of Strata's own, engine-side fast modulation of five destinations per voice, scatter, 16 macros, scene morph, four gesture recorders, a 16-routing modulation matrix, a step sequencer with per-voice length, division and swing, gates, probability, ratchets, locks, notes, Euclidean fill and chaining, a mute and a solo per voice, the input level as a modulation source, 16 named scenes in two banks, and a MOD page, all defaulting to 3.3's sound.

**Architecture:** Wave 0 changes no behavior and fixes every interface: 0a adds the Lua registries, the base override, extra offsets and the deferrable send budget, the modal screen owner, the PSET hooks and the menu records; 0b rewrites scene recall on `scene_entries`/`apply_entries` with scene blocks and migrations; 0c adds the engine's `modulation` area (order 160) with its buses, addressing methods and five commands as checked stubs. Wave 1 fills them in ten packages (the engine's fast modulation, the LFOs, the scenes' banks and names, the sequencer, gestures and quantized actions, morph, the input level, mute and solo, then macros and scatter, then the matrix), each owning its module, tests and notes. Wave 2 builds the surfaces (the MOD page, the SEQ page and step editor, the grids). Wave 3 adds the XY morph and releases.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua`; norns' `lib/pattern_time`, `lib/er` and `lib/textentry` (new stubs); SuperCollider 3.13.0 (norns and CI) and 3.14.1 (local), class extensions `+ Engine_Strata { }`, control-rate core UGens only (`In.kr`, `Out.kr`, `Phasor.kr`, `LFDNoise3.kr`, `Lag.kr`, `Latch.kr`, `Demand.kr`, `EnvGen.kr`); the engine check through `test/run_engine_check.sh` on `$STRATA_SC_PORT` and `test/run_engine_check_313.sh` in Docker.

**Spec:** `docs/design/3.4-design.md` (approved 2026-11-08; every question decided; amended through 2026-11-11). It binds over `docs/design/3.1-3.6-roadmap.md` for 3.4. Read the design sections a task names before starting it. The design was written before 3.3 landed: where it and the merged code differ, "The design against the merged code" below rules, and a task's text already follows those rulings.

## Global Constraints

- Everything in AGENTS.md applies: Lua as the only source of values, `send_param_to_engine` and `S.engine_senders`, LFOs never `params:set` their destination, replace-never-stack, `sendToSynth`, `openedGate`, the velocity invariant (steps and notes never create nodes), no `LocalBuf`, the command table, the registries (read at init, never at include time), `request_redraw()`, arc rings through `arc_sweep_param` and `param_fraction`, grid handlers on the vport only, bounds checks, a cleanup step for every clock, metro and handler, the locals probe (30 free locals per main chunk and constructor), the data files rule (`S.lib.data_files.write` and `read` only, never `tab.save` or `tab.load`).
- **No package edits `lib/Engine_Strata.sc`, `init` or `cleanup()`.** Engine files are named `Strata*.sc`; extension files add methods only, never variables; the new area's state lives in `areaState[\modulation]`. The new engine file needs the norns restart note in 0c's changelog fragment.
- **Five new commands, exactly:** `setFastLfo(lfo, voice, destination, shape, rate, depth, offset)` `"iiiifff"`; `stopFastLfo(lfo)` `"i"`; `syncFastLfo(lfo, phase)` `"if"`; `setScatter(depth, rate, destinations, voices)` `"ffii"`; `setFastOffset(voice, noteSlot, destination, offset)` `"iiif"`. No other command, poll or signature changes.
- **Constants** (`lib/constants.lua`; each a field of the returned table, never a new local): `NUM_LFOS` 6, `NUM_SCENES` 16, `SCENE_BANK_SIZE` 8, `SCENE_NAME_MAX` 12, `SCENE_DATA_VERSION` 6, `NUM_MACROS` 16, `MACRO_BANK_SIZE` 4, `MACRO_TARGETS` 8, `MATRIX_SLOTS` 16, `NUM_GESTURES` 4, `NUM_FAST_DESTINATIONS` 5, `FAST_MOD_NOTE_SLOTS` 1, `NUM_UI_PAGES` 9, `GRID_HOLD.step_edit_seconds` 0.3, `ENGINE_BUDGET = {messages_per_window = 150, window_seconds = 0.1}`, `HEADER.dots_x` 36. The engine mirrors `numFastDestinations` 5 and `fastModNoteSlots` 1. A module's own tunables live in its one table (`LFO`, `MACROS`, `MORPH`, `SCATTER`, `GESTURES`, `QUANTIZE`, `SEQ`, `MATRIX`, `MOD_PAGE`, `ARC_MOD`), with the design's values: `LFO.step_hz` 48, `LFO.sends_per_step` 12, `LFO.lua_max_hz` 10, `LFO.engine_max_hz` 50, `LFO.send_threshold` 1/1000, `LFO.engine_rate_threshold` 0.005; `MACROS.apply_hz` 30, `MACROS.learn_seconds` 10; `MORPH.apply_hz` 10, `MORPH.hysteresis` 0.02, `MORPH.max_values_per_apply` 120; `GESTURES.max_events` 1024; `SEQ.max_step_notes` 8, `SEQ.min_ratchet_seconds` 0.02.
- **Fast destinations:** 0 pitch (`grain_pitch`, half range 1.875, clip 0.25-4), 1 position (`buf_pos`, 0.5, clip 0-1, `\strataGrainBuf` only), 2 size (`grain_size`, 0.245, clip 0.01-0.5), 3 cutoff (the stage's `filterFreq × 31.62 ^ m`, clip 20-20000), 4 amp (the stage's level, `(1 + m)` inside `voiceLevel`). Every bus channel comes from `fastModChannel(voice, noteSlot, destination)`; buses hold offsets only, and Lua owns every base value.
- **Real-time memory floors:** 3 MB free on standard and 3.5 MB (3584 KB) on high at the mixed worst case, synth → buffer → synth and the all-buffer worst case, 3 MB on both tiers with eight recordings, every grain SynthDef under 88 KB, `\strataVoiceMix` under 40 KB, all with six engine LFOs and scatter running. 3.4's estimate is about 111 KB (design §3.6's 97 plus §8.12's 14 for the gates, which take a stage to about 38.75 KB of its 40); 1a measures first and reports before building on.
- **Message bounds:** Lua's LFOs and the matrix together send at most 12 messages per 48 Hz step (576 a second); a macro applies at most 30 times a second; morph applies at most 10 times a second and 120 values per apply; every deferrable sender (Lua LFOs, the matrix, morph, gesture playback, every macro apply) writes inside `S.lib.engine_sync.deferrable(fn)` and shares 150 sends per 100 ms window. Hand edits, steps, notes, locks and recalls are never deferred.
- **3.3's sound by default.** LFOs 4-6 off, no macro targets, no routings, scatter off, recorders empty, every voice at 16 steps of 1/16, every step at 100 % with one hit and no locks or notes, every voice's gate, mute and solo off and its swing at 50, names empty, quantize off. A 3.3 scene recalls the same voices, values and patterns; a 3.3 PSET's LFO settings are imported. The audible changes, for the release notes: LFOs on pitch, position and size run in the engine (smoother, same depth); grid step keys toggle on release.
- **Scenes:** `SCENE_DATA_VERSION` 6 (1c sets it). Every migration is registered with `before_version = 6` and is idempotent (it converts only fields it finds in the old form and fills only what is missing), so Wave 1's packages can land in any order while the constant is still 5. A new captured field needs `validate_scene` coverage and a migration default.
- **Feedback loops are impossible by construction:** an LFO's rate and depth inputs read lower-numbered LFOs only; a macro never targets a macro or a morph param; matrix destinations exclude macros, LFO params and matrix depths; an LFO on a macro skips the macro's LFO-param and matrix-depth targets.
- **State invariants:** every new module that keeps a clock, a metro or paired state registers one with `S.register_invariant` (its task names it); the harness checks them after every unit test.
- **Changelog:** each package adds `changes/3.4-<package>.md`; a feature package never edits CHANGELOG.md. `docs/status.md` changes in Wave 3 only.
- **US English** everywhere (a test enforces it); docs, commits and pull requests never name the maintainer.
- **Isolation:** each task's dispatch names a scratch folder `scratchpad/3.4-<task>/`; a worker writes only there and in its own worktree. Deletes are `rm -rf -- "${dir:?}"` on a path inside the worker's own folder; worktrees go only with `git worktree remove`.
- **Every finding is fixed, never deferred:** a review's findings are fixed in the package; a problem outside the package gets its own GitHub issue and fix.
- **After every task:** `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua` pass. A task that touches engine code or a check area also passes the full engine check on 3.14.1 and four full runs on 3.13 (`test/run_engine_check_313.sh -n 4 -j 4`), reporting #131's rate, each grain def's KB against 88 and the stage's against 40.

## Review Focus

The inputs the design implies but none of its tests exercise, most likely to bite a player first. Each line's test is in the task that owns the code.

1. **A tempo change under a clocked engine-run LFO.** The engine LFO runs at a rate in Hz that Lua derived from the tempo; when the tempo moves (the param, Link, MIDI clock), the rate must follow within one Lua step, or the LFO runs at the old tempo and snaps at each bar's resync. Test in 1b (`"a tempo change resends a clocked engine LFO's rate"`).
2. **A step lock or note whose voice never plays another step.** A lock ends at the voice's next played step; if the patterns stop, the pattern is cleared, replaced by a recall or a chain link, or the voice's length is shortened past its only locked step, no such step comes and the voice would keep the locked value. Every one of those ends the voice's overrides at once. Test in 1d (`"a lock ends when the patterns stop, the pattern is replaced or cleared"`).
3. **A deferred send that outlives its voice's sync.** A morph or macro value waiting for the next window is older than the values a voice start, a source switch or a recall's sync sends directly; sent afterward it would leave the engine on a value Lua no longer holds. A sync drops the voice's pending values. Test in 0a (`"a voice sync or start drops the voice's pending deferred sends"`).
4. **A held grid step whose release never comes.** The step editor is open on a held key when its grid is unplugged, its port changes page or the pattern is replaced: the editor closes, nothing toggles and no later key takes the stale one as held. Test in 2c (`"the step editor closes when its grid goes away, changes page or the pattern is replaced"`).
5. **A PSET whose side file is missing, unreadable or names things this build lacks.** A 3.3 PSET has no `.macros.data`, `.matrix.data` or `.gestures.data`; a hand-copied PSET can lose one; a later release can name a param this one lacks. The PSET always loads: a missing file loads empty targets, routings and recorders (the PSET held none), an unreadable one is set aside with a console line, an unknown id is kept verbatim and does nothing. Tests in 1e, 1f and 1h (`"a PSET without a side file loads empty"`, `"an unreadable side file is set aside and the PSET still loads"`, and for 1f `"a gesture event naming an unknown param is kept and skipped"`).

## The design against the merged code

The design cites `main` at b79902e, before 3.3. These are the differences found on `main` at 3.3.2 and how this plan resolves each. A worker that finds another reports NEEDS_CONTEXT.

1. **Scene format 6, not 5.** 3.3 took `SCENE_DATA_VERSION` to 5 (#314), so 3.4's is 6: every "version 5" and `before_version` 5 in the design reads 6, and §13's "a version-4 file loads 16 empty routings" reads "a version-5 file".
2. **Data files.** `macros.data`, `matrix.data`, `gestures.data` and the three per-PSET side files are written with `S.lib.data_files.write` and read with `S.lib.data_files.read` (an unreadable one through `S.lib.data_files.set_aside`), never `tab.save` or `tab.load` (a structure test forbids both).
3. **Transport following shipped in 3.3 (#530),** without a param and from an external clock source only (`lib/sequencer.lua`, start step `pattern_transport` 160; the handlers are restored in the `pattern_clock` cleanup step). 1d keeps both steps and #530's rule (on the internal clock, PARAMETERS > CLOCK > reset neither starts nor stops the patterns; `docs/decisions.md`, 3.3), and adds what §8.11 adds to it: the `seq_follow_transport` param (default on), SETUP's row, the restart of every voice at step 1 and of a running chain. The design's `START_ORDER.transport` 135 and `CLEANUP_ORDER.transport` 15 are not added. The clock stub already has `clock.transport`; 1d adds only the helpers `context.clock.transport_start()` and `transport_stop()` to the stub's clock section, so there is no `test/stub_transport.lua`.
4. **Page randomize shipped in 3.3.2 (#557).** ALT+K2 on a page of parameters goes through `S.lib.ui_alt.k2_down` and `k2_up(record)`, the record's `randomize_section()` and `alt_hold()`. This plan settles what #557 left to it:
   - LFO (1b): a quick press randomizes the selected LFO's shape, its rate (free) or division (clocked), and its phase; destination, mode, depth, offset, on/off and the four mod params are kept. The held press resets the strip's field, as now.
   - MOD (2a): the scatter section draws `scatter_depth` (whole percent, 0-30) and `scatter_rate` (even in octaves, 0.02-0.5 Hz); the matrix section draws the depth of every complete routing (whole percent, −50..50); the macros, morph, gestures and lfos sections return no spec (a macro apply writes up to eight params the undo would not hold). Sub-views follow their section.
   - SEQ (2b): a quick press randomizes the pattern in both views, levels only; the held press opens the edit view from the pattern view and resets the row in the edit view.
   - `S.lib.ui_alt.k2_hint` names a held press `K2:reset` or `K2:cancel` only. 0a adds an optional record field `alt_hold_hint` (a string, or a function returning one) that replaces `K2:reset`, for SEQ's `K2:edit` and MOD's `K2:clear`.
5. **Registries close at init (#384).** `scene_blocks`, `scene_migrations` and `pset_hooks` are read once at init, so they join `INIT_READ` and refuse a late registration; `param_touch`, `lock_change`, `step_outputs` and `mod_sources` are read at each use and stay open. Every record's fields are checked with `require_known_fields`.
6. **Silent macro sets are a scene field's own setter,** not an `apply_entries` option: `S.register_scene_field` gains an optional `set = fn(value)`, which a recall, a transition step and `apply_entries` call in place of `params:set`. Macros register `set = function(v) S.lib.macros.set_silently(m, v) end`.
7. **Registered continuous scene fields are range-checked:** `validate_scene` rejects a registered continuous field outside its control param's range (today only discrete registered fields are checked), which covers §9.2's rules for the macro values, matrix depths and scatter's depth and rate without per-module code.
8. **`v<i> amp` is registered from `lib/voice_mix.lua`,** one entry after `rsend` in `VOICE_MIX.lfo` (1b's registration line). `lib/lfos.lua` is included before `lib/history.lua` and `lib/voice_mix.lua`, so a registration in its constructor would come first and move the 28 saved indices of 3.2's destinations. The list is: 68 built-in, `v<i> hist` 69-75, `vfilt` 76-82, `dsend` 83-89, `rsend` 90-96, `amp` 97-103, `macro 1`-`macro 16` 104-119.
9. **Global LFO destinations share the `lfo_destinations` registry** as `{label, param_id, global = true}` records, in registration order with the per-voice ones. 0b teaches the merged `lib/lfos.lua` to read one (a single destination), so 1e can land before 1b.
10. **The PSET read hook exists** (`params.action_read` = `S.lib.params_setup.migrate_read_pset`, installed by the `master` record). 0a's installer keeps it first and runs the registered hooks after it; `action_write` and `action_delete` are new. The stub's `params:write` and `params:read` pass no PSET number and it has no `params:delete`: 0a brings the stub to norns' `lua/core/paramset.lua` (`action_write(filename, name, number)`, `action_read(filename, silent, number)`, `action_delete(filename, name, number)`).
11. **`strata_seq` is one group filled by two packages.** `S.lib.sequencer.add_params()` (1d) adds the group with `6 + S.lib.quantize.PARAM_COUNT` params and calls `S.lib.quantize.add_params()` for the fifth; 0a's `lib/quantize.lua` has `PARAM_COUNT` 0 and adds nothing, and 1f sets 1 and adds `quantize_actions`. Either lands first.
12. **Quantized call sites.** `S.lib.positions.jump` and `recall_bookmark` are also what a step's bookmark lock reaches (`S.lib.bookmarks.recall`), which must never wait for a bar. So 1f wraps the user-action call sites (BUFFER's keys and the grid's `grid_key` and `strip_key` branches), never the two functions themselves; 1c wraps the scene recalls and 1d the pattern start, in their own files. Freeze is quantized where a key toggles it: only the grids call `S.lib.freeze.toggle` today, so 1f adds `toggle_quantized` and 2c points the grids' freeze keys at it; VOICE's freeze row and a mapped CC set the param and act at once, as every param edit does.
13. **A transport start is detected by the LFOs themselves:** `lib/lfos.lua` resyncs every clocked engine LFO at once when `clock.get_beats()` is lower than at its last step, so 1b and 1d share no call.
14. **Cleanup reaches no engine (#461):** norns frees the engine before `cleanup()`. The new cleanup steps cancel clocks and metros and save files; no test asserts an engine send from one.
15. **MAIN's status row is full.** `OFF [L] [T] [F]` ends at x 127 on the merged page, so §10's `~` goes after the voice's name on y 18 (the name's width is cut by the mark's), not after `[F]`.
16. **Arc sweeps are 1024 ticks (#552)** and the LFO depth rings step whole percents through `arc_whole_steps` with `ARC_LFO.ticks_per_percent`: where the design says "as now", the merged ring code is meant.
17. **User docs.** `docs/user/modulation.md` exists (crossmod, mutations, LFOs): 1b rewrites its LFO section, 2a adds the macros, morph, scatter, gestures and matrix sections. `docs/user/sequencer.md` does not exist: 1d creates it and adds its README index line.
18. **The XY morph (design §5.5) is built in 3.4, as package 3a** (decided 2026-11-11). The design's 6×6 pad on the 256's page 3 no longer fits (row 16 is the lock row on every page since #442), so §5.5 was amended the same day: a 5×5 pad on rows 11-15 × columns 12-16, the existing `morph` as the first axis and a new `morph_y` as the second, so the two-scene morph is unchanged at y = 0.
19. **Outside the design:** `docs/decisions.md` (3.3) says 3.4 numbers the `bufferState` reports per load, to close the two-quick-loads blink. No 3.4 package owns it; it is #578 and is not part of this plan.
20. **Four amendments of 2026-11-11 are in this plan** (design Questions 41-44, each decided as recommended that day): step gates (§8.12), swing (§8.13), mute and solo (§8.14) and the input level as a modulation source (§10.3). Gates, swing and mute are bullets marked **(gates)**, **(swing)** and **(mute)** in 0c, 1a, 1d, 2b and 2c; mute and solo and the input level are also the two small packages 1j and 1i.
21. **The scene name entry has no modal owner.** norns' `textentry` takes the global `key`, `enc` and `redraw` itself and cancels on a K2 release, so the entry opens on ALT+K2's release, as BUFFER opens the file selector (task 1c); the design's modal owner for it (§9.3) is dropped, and the step editor is the modal owner's one user.
22. **A step note's reference pitch.** Design §8.4 counts degrees from the voice's pitch in the global scale. A buffer or input voice has no frequency, so its pitch is the note MIDI plays at that rate (`rate_root_note` at rate 1), and the scale's root applies to every source (task 1d).

## How to read the tests

**All three checks** means `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua`, from the worktree root, each exiting 0.

**Test shorthand.** A Lua test block gives each test's name and its assertions in comments; the implementer writes the setup and the `h.` calls. `a -> b` and `a == b` are `assert_equal(a, b)` (a number marked `(near tol)` is `assert_near`); `f() -> g(1)` means calling `f` sends `g(1)` (`context.calls_named`); `;` starts the next case on the same setup. Every number in a comment is an exact value of the design or of a stub's arithmetic. Compare numbers with `assert_equal` or `assert_near`, never through string formatting (Lua 5.3 and LuaJIT print floats differently). A test given by its name alone pins a behavior that the design section its task cites states with its values: the implementer takes the values from there and writes at least one assertion per clause of the name.

**Lua.** Tests live in `test/unit/<module>_test.lua`, each `return function(h) ... end`, with `test`, `assert_equal`, `assert_true`, `assert_near`, `load_strata`, `local_value`, `show_page`, `tap`, `hint_text`, `screen_shows`, `assert_screen_layout` from `h`; `S` is `local_value("S")`. The stub entry points are `context.engine_calls`, `context.calls_named(name)`, `context.polls.fire`, `context.grid.press(port, x, y, z)`, `context.arc.turn(port, ring, d)`, `context.set_time(t)` and `context.clock.run_for(s)` (`docs/notes/lua/test-harness/stubs.md`, `clock.md`). The stub clock starts at 120 BPM, so a beat is 0.5 s. Run one file with `lua test/run.lua <filter>`.

**Engine check.** Each area is `test/engine_check/<area>.scd`, returning `{ arg h; ... }`; `h.check(condition, "area: message")` counts a failure, and the assertion messages below are the check names. Audio comparisons run on the server (a check synth writes `Peak` of the difference to a control bus, read with one `/c_get`), never in sclang (#131). Control buses are read with `Bus.get`. Run one area with `STRATA_ENGINE_CHECK_AREAS=modulation STRATA_SC_PORT=<port> test/run_engine_check.sh`, and the 3.13 runs with `test/run_engine_check_313.sh -n 4 -j 4 -o "${TASK_SCRATCH:?}/sc313"`.
