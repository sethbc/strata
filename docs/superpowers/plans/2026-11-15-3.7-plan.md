# Strata 3.7: Rhythm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, as `docs/workflow.md` runs it (parallel packages, one worktree and branch each, batch landings). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make rhythmic material playable: a buffer cut into up to 64 slices that steps, grid keys and MIDI notes play; scan modes and a scan as a speed; a tempo, a key and a normalize gain that follow each file, with voices that stay on the beat by stretch or repitch; trig conditions with fill, pattern directions and a chance for the next scene; a delay on the beat with ping-pong; an envelope per voice and four random sequences as modulation sources. Every new piece is off at its default, so a 3.6 scene sounds as it did.

**Architecture:** Wave 0 prepares the ground: the conversions of old file formats deleted (0d, first), the LFO destination list rebuilt by voice (0e), room in `AGENTS.md` and the wrong doc lines (0a), the Lua seams (one door for a hit, a factor on an engine value, settings rows for a modulation source, a picker, the shared divisions and the scene version; 0b) and the engine's `voiceHit` area hook (0c). Wave 1 builds the engine side and the Lua that needs none of it, side by side: the grain reader (scan modes, the speed unit, a region per note, the follow rate, the scan sync, the slot gain; 1a), the onsets area (1b), envelope nodes (1c), the delay (1d), conditions, directions, fill and the chain's chance (1e), the scene sequencer's chance (1f) and random sequences (1g). Wave 2 is Lua on the new engine: a file's settings (2d, first), slices (2b), scan and follow (2a), the slice editor (2c), the grids' slice rows (2e) and envelopes (2f). Wave 3 is the whole-system test, the docs pass and the release.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua`; SuperCollider 3.14.1 locally and 3.13 in Docker (norns' and CI's version) for the engine check, with no sc3-plugins; norns' `clock`, `params`, `midi`, `grid`, `arc` and `poll`.

**Spec:** `docs/design/3.7-design.md` (approved 2026-11-15, nineteen decisions; amended 2026-11-16 with five more, 20 to 24, from a review of what compatibility had cost: `docs/design/3.7-facts/revisit.md`). It binds over `ROADMAP.md` for 3.7. Its facts are the three files under docs/design/3.7-facts/ (`engine.md`, `buffers.md`, `lua.md`). Read the design sections a task names before starting it. Where the design and the merged code differ, "The design against the merged code" below rules, and a task's text already follows those rulings.

## Global Constraints

- Everything in `AGENTS.md` applies: named constants, `send_param_to_engine`, the registries, `request_redraw()`, bounds checks, a cleanup step for every clock and handler, the data files rule (`S.lib.data_files.write` and `read` only), the locals probe (30 free locals per main chunk and constructor), a module's constructor shape, one `include` per module from `strata.lua`, replace never stack, `openedGate`, `sendToSynth`, `areaCall` for every kept closure, no `LocalBuf`, fresh read arrays, no sclang function per sample.
- **A new feature is off at its default.** `scan_mode` wrap, `follow` off, `slices` off, `seq_direction` forward, `seq_misstep` 0, the three chances 100, 0, 0 (both sets), `delay_sync` off, `delay_pingpong` 0, a file with no settings. A fresh Strata sends nothing new but the values every voice sync carries (`scanMode` 0, `followRate` 1, `rootNote` 60, the own region's clear) and `setDelay`'s fourth value, 0. This is a regression net for the builders, not a promise to keep 3.6's sound: where this plan changes a default or a unit on purpose (the scan is a speed, ruling 29), the tests say the new behavior. Each package's tests assert its own features are off; 3a asserts it for all at once.
- **The engine's comparisons with earlier releases are regression nets.** The positions check against 3.2's scan, the loops check against 3.1's starts, the modulation and mix checks against 3.3 and 3.2, the effects check against 3.0's chain: each proves a refactor changed nothing it did not mean to. A package that changes a compared behavior on purpose (1a's scan as a speed) re-bases that check in the same commit and names it in its report; no other comparison is loosened or removed. The checks that hold a verbatim older reader (the runner's 3.2 copies, `test/engine_check/structure.scd:399-431`) guard the reader; the 3.3 and 3.2 split copies call the live reader and guard the hooks around it.
- **The mix stage takes nothing.** No package adds a UGen or a control to `\strataVoiceMix` (it has 0.71 KB under its 42 KB check).
- **Memory is measured before it is spent.** 1a runs the memory area before and after its change and records each def's size and every worst case in `docs/notes/engine/memory.md`; 1c does the same with sixteen envelope nodes in every worst case. The floors stand: 3 MB on standard and 3.5 MB on high at the eight worst cases, 1280 KB with the note pool full, `\strataGrainBuf` under 88 KB. If one fails, design §1's order of cuts applies and the worker reports before cutting.

- **No new page, and nothing in the mix stage, `init` or `cleanup()`.** Start and cleanup steps register at their orders (Branches, ports, fragments). `lib/Engine_Strata.sc` is never edited.
- **One door each.** Only `S.lib.engine_sync.retrigger` calls `engine.retrigger`. Only `S.lib.notes` calls `engine.noteRegion`. Only `S.lib.slices` plays a slice (`play`). Only `S.lib.samples` reads or writes `samples.data` and a slot's settings. Only `S.lib.envelopes` calls `engine.setFastEnv` and `engine.stopFastEnv`. Only `S.lib.scan` calls `engine.syncScan`.
- **Hooks never send and never yield.** A `voice_hit` hook, an `on_bind` listener and a peaks-read listener run through `S.lib.ui_frame.contained_call`.
- **Transient state is never stored.** A note's region, the follow rate, a slice bank, held fill and the candidates of a transients pass are never params, scene fields or PSET values. `seq_fill` is never saved on.
- **Storage.** `SCENE_DATA_VERSION` is 8 from 0b on, raised once; each package adds its fields under it with a default that leaves its feature off. `buffers.data` goes to version 3 (2d) and still loads version 2; the floors are 0d's (ruling 30). `samples.data` is new (2d). A file a build cannot read is set aside, never overwritten.
- **Layouts, menus and storage may change** where this plan says so (design decision 18): the 128h's row 8, column 4 becomes fill; K3 on BUFFER's `slices` row opens the editor; a slice row's strip keys pick banks; SCENES' fields become a scrolling list. Each such change is named in its package's user page.
- **`AGENTS.md` has 8,000 words.** 0a leaves at least 500 free. A package adds only the rows and lines its task names; if the word test fails, it shortens its own additions and reports it.
- **Changelog:** each package adds `changes/3.7-<package>.md`; a feature package never edits CHANGELOG.md. `docs/status.md` changes in Wave 3 only, except where a package closes an open item.
- **US English** everywhere (a test enforces it); docs, commits and pull requests never name the maintainer.
- **Isolation:** each task's dispatch names a scratch folder `scratchpad/3.7-<task>/`; a worker writes only there and in its own worktree. Deletes are `rm -rf -- "${dir:?}"` on a path inside the worker's own folder; worktrees go only with `git worktree remove`.
- **Every finding is fixed, never deferred:** a review's findings are fixed in the package; a problem outside the package gets its own GitHub issue and fix.
- **After every task:** `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua` pass. An engine package also runs its own areas while it works and every area before it pushes, on SuperCollider 3.14.1 and on 3.13, and reports #131's rate on 3.13 (`docs/workflow.md`, Worker rules).
- **Unverified on devices until 4.0** (#6). Nothing here is tried on a norns; 3b writes the device checks into #6.

## Review Focus

The inputs the design implies and no single package's happy path exercises, most likely to bite a player first. Each line's test is in the task that owns the code.

1. **Audio that changed under its settings.** A slot loaded, cleared or recorded over while its slices sound; a step that names slice 40 on a file with 12; a scene recalled over another file; a tier that shortens the slot so markers lie past its end; an onsets file for another slot, another length, or garbage. Nothing reads outside the valid region, a missing slice plays nothing (a step: as a plain step), and stale candidates never become markers. Tests in 1a (`"no grain of a region reads outside it or the valid region, in each scan mode, forward and reverse"`), 2b (`"a slice that does not exist plays nothing"`, `"an onsets file that does not match the slot is ignored"`, `"a bind clears the own region of every voice reading the slot"`).
2. **A note that never ends.** One-shot slices under held keys and under latch; overlap past the note cap and the pool; a scan of 0; a tempo change in the middle of a slice; a voice stopped, a source switched or a slot cleared while slices sound. After each, no extra slot is left holding a played-out note, and every note that was started is released or cut once. Tests in 2b (`"a played-out one-shot note is released within two steps of its slice's end"`, `"every way a slice note ends frees its slot"`), 3a.
3. **Tempo at its edges.** A file with no tempo under `follow`; the clock at 20 and at 300 BPM against a file at 120 (the rate clamps at 0.25 and 4); a tempo change mid-loop; a beat that jumps (a transport start); a division of one bar at 30 BPM under sync (halved twice). The scan and the delay stay finite and on the beat, and nothing is sent more often than the budget allows. Tests in 2a (`"follow with no tempo is a ratio of 1"`, `"repitch scales both, and clamps the rate at 0.25 and 4"`, `"a tempo move under 0.5% sends nothing, and a larger one sends within a step"`), 1d (`"a division that does not fit is halved until it does"`).
4. **Chance under late wakes and restarts.** Skipped ticks with a random direction, a misstep and conditions (the draws and the pass count move exactly as if the steps had played); a division reset and a single voice's restart; voice 1's neighbor; fill held when its grid leaves or its page changes, so the release never comes. Tests in 1e (`"skipped ticks advance the order and the pass count and test nothing"`, `"fill ends when its grid is removed or shows another page"`, `"first, pre and nei read the pass and the last outcomes"`, which holds voice 1's neighbor to voice 7).
5. **Old data, and new data in an old build's shape.** A 3.6 scenes file, a 3.6 PSET and a version 2 `buffers.data` load with their values as saved (a non-zero scan now a speed); a file below the floors is set aside whole; an unreadable `samples.data` is set aside and the slots still load; a scene with an unknown condition string is refused whole, as an unknown step key is today. Tests in 0b (`"a version 7 scenes file migrates to 8 with nothing changed"`), 2d (`"a version 2 buffers.data loads with no settings"`, `"an unreadable samples.data is set aside and the slots still load"`), 1e (`"a scene with a condition outside the 78 is refused"`).

## The design against the merged code

The design cites `main` at 334429aa; `main` is 78ba8510 now (the design's own three commits; no file under lib/ or test/ moved). Three more fact files, gathered for this plan, hold the merged code's exact names and lines for each package, and a task's **Where** line names the section to read: `docs/design/3.7-facts/plan-seams.md` (0a, 0b, 1e, 1f, 1g), `docs/design/3.7-facts/plan-engine.md` (0c, 1a to 1d) and `docs/design/3.7-facts/plan-lua.md` (1d's Lua half, 2a to 2f). These rulings fix what a planner would otherwise guess; each says what it costs if wrong.

1. **The own note's region is two grain params; `noteRegion` is for extra slots.** Two tests pin that only `setGrainParam` precedes `voiceOn` at a start (`test/unit/engine_sync_test.lua:81-110`, `test/unit/structure_test.lua:796-852`), and a start must carry the region so the first grain plays the slice (#632). So `regionStart` and `regionLength` are grain controls kept in `grainControls[voice]`, as the loop's are, and per-note controls, so a voice-wide send skips extra notes. Lua sets the own note's with `setGrainParam(voice, "regionStart", s)` and then `"regionLength"`, whose handler also restarts the own grain synth's scan. `engine.noteRegion(voice, slot, start, length)` takes slot 1-7 only. Design §3.4 gave it slot 0 too. If wrong: one more branch in a command.
2. **No `delayMaxSeconds` method.** The Lua stub reads the delay time's limit only from the literal `time.lag(0.1).clip(0.01, 2)` and reads `name { ^N }` methods as integers (plan-engine.md §0, 1). 0c adds no delay seam; 1d changes the two literals to 2.7, and a docs test compares Lua's `DELAY.max_seconds` with the stub's limit. Design §0.7's second item is dropped.
3. **`setDelay`'s fourth value touches 23 calls in the engine check** (effects 18, mix 3, record 2), the structure check's `"fff"` and five Lua test files (plan-engine.md §5; plan-lua.md §7). 1d owns them all; in `test/engine_check/mix.scd` and `record.scd` they are its shared lines, and the Wave 1 batch takes 1a before 1d.
4. **`pingPong` rides `setDelay`'s one `setSynth`**, with a numeric default in the def's arg list, and `delay_pingpong` is in the `strata_fx` group (through `S.register_fx_params`): a docs test requires every argument of an FX command to set a control there (`test/unit/docs_test.lua:453-485`).
5. **A new engine area is listed in six places** (plan-engine.md §0, 3): the structure test's `ENGINE_AREAS`, `areaOrder` (the soak stays last), the docs test's `ENGINE_CHECK_AREA_ORDER`, `docs/notes/engine/structure.md`'s `areaOrder` sentence, CI's shard matrix and `AGENTS.md`'s list of engine notes. 1b puts `onsets` in the `record,waveform` shard and 1c puts `envelopes` in `modulation,freeze`. Neither adds a time to the workflow's comment: its sum is the "about N minutes" five files quote, and the release moves those once.
6. **Where the reader's new inputs go is the builder's choice.** `slotGrainReader` has fifteen positional arguments and three check-only callers pass exactly fifteen (the 3.3 and 3.2 split copies and the loops check). 1a either adds one trailing argument with a neutral default, leaving those calls alone, or changes the calls: the comparisons are nets, not promises (Global Constraints).
7. **`voiceOn` has no stopped-voice branch.** 0c reads `this.voiceRunning(voice)` before the bundle and calls `voiceHit(voice, \start)` only when it was false (plan-engine.md §1).
8. **An envelope def's name must not begin with `strataFastLfo`**: the memory check counts LFO nodes by that prefix and requires six. The def is `\strataEnvelope`, and the check's count of `fastModGroup`'s nodes gains a figure for it.
9. **Fill's mark is on SEQ, not in the header.** `[F]` already means audio freeze on MAIN and a test refuses it in any other Lua file; the header has no free ten pixels and a test pins every position in it (plan-seams.md, Surprises 1 and 2). Fill shows on SEQ's two views and on the grids' fill keys. Design §5.2's and §9's header mark is dropped. If wrong: a header layout change later.
10. **Fill has holders.** It is on while `seq_fill` is 1 (the latch: SEQ's row, the action, a controller's mapping of the param) or while any key holds it (`S.lib.conditions.hold_fill`). The `fill` action in `lib/io/actions.lua` toggles the latch: crow's triggers act on a rising edge only, so they cannot hold. A held fill from a controller is norns' own mapping of the param. A key's release ends its own hold and nothing else: the latch stays until it is toggled. Design §5.2 said controllers hold it through the action, and that a release ends fill whatever latched it.
11. **`seq_fill` is `set_save(false)`**, and a PSET load leaves such a param as it is (plan-seams.md §1e (7)). Accepted: fill is off at a script start and survives a PSET load.
12. **The hit's door.** `S.lib.engine_sync.retrigger(voice, velocity, source)` replaces the three `engine.retrigger` calls. `M.start_voice(voice_idx, options)` and the global `toggle_voice(voice_idx, options)` take `options.retrigger_follows`; a start tells the `voice_hit` hooks unless it is set. It is set where a retrigger always follows (`lib/notes.lua:362`) and at `lib/sequencer.lua:638` for a gated voice. `start_extra` tells the hooks unless the note's owner is the sequencer's (plan-seams.md §0b (1)).
13. **The factor is read at a start and a sync too.** It goes in `with_lfo_offsets` after the clamp and on its early return, and its table joins `start_value` and `resend_modulated_voice_params`, which today look only at base overrides and extra offsets (plan-seams.md §0b (3)). `engine_param_value("v<i>_buf_scan")` then carries the factor, which is what the playhead should read.
14. **MOD's settings view is a view beside targets and routing**, and eight branches on the view learn it, with one in `lib/arc/mod.lua`, which 0b owns for that branch (plan-seams.md §0b (4)).
15. **FX: E3 turns `sync` on and off; K3 stays the delay's bypass.** FX's K3 toggles the bypass on every delay row today. Design §6 gave K3 on the `sync` row to sync.
16. **`lib/files.lua` has no save.** The saves and their result are in `lib/buffers.lua` (`save_buffer`, `buffer_save_result`), where 2d's copy of a whole take's settings goes. `lib/files.lua` leaves 2d's list.
17. **A grid's slice notes get their own owner.** `S.lib.notes.play` takes only `midi` and `seq`; 2b adds `grid`, with the key `port * 100 + slice`. `region` joins `valid_note`, `played` and the slot record, which copy only known fields.
18. **The root note's constants stay.** `rate_root_note` has four uses (the fourth is `own_pitch`, `lib/notes.lua:315-320`), and a docs test holds the engine's 60 equal to both Lua copies. `S.lib.samples.rate_root(voice)` returns the key, or that constant.
19. **The peaks reader tells of every read.** It drops `frames` and `rate` after checking them and returns early when the values did not change; 2d makes it keep the two and call its listeners before that return, since a reload of the same file resets the engine's gain.
20. **BUFFER's `slices` row is its twelfth and last field**, so the two field indices a layout state sets (3 and 10) hold; the test that pins eleven changes.
21. **Random sequences are stored as the gesture recorders are**: `S.lib.side_files` needs a live file, so `sequences.data` is a data file with a PSET side file beside the scene block. `AGENTS.md`'s list of data files gains it and `samples.data`.
22. **The sequences' hook runs before the matrix's.** Step hooks run in registration order, so `lib/random_sequences.lua` is included before `lib/matrix.lua`.
23. **`SCENES_FIELDS` is 1f's** (a line of `lib/constants.lua`), with `lib/arc/scenes.lua`, which reads its count.
24. **A module's `AGENTS.md` row lands with its file**: the path check refuses a row whose file does not exist. Each package adds its own row. 0b edits the quoted `SCENE_DATA_VERSION` (8) and 2d `BUFFER_DATA_VERSION` (3).
25. **Pending commands.** `test/sync_check.lua`'s `PENDING_COMMANDS` gains `noteRegion`, `syncScan` and `setSlotGain` (1a), `analyzeBuffer` (1b), `setFastEnv` and `stopFastEnv` (1c). The Wave 2 package that first calls one removes its line: 2b `noteRegion` and `analyzeBuffer`, 2a `syncScan`, 2d `setSlotGain`, 2f the two.
26. **A hit's hold** is `(grainControls[voice][\seqGate] ? 0) * (grainControls[voice][\gateSeconds] ? 0.1)`: both are nil until Lua sends them.
27. **`samples.data` has no SETUP row.** Unreadable, it is set aside and printed, as `io.data` is; SETUP's data rows cover the scenes and buffers files only.
28. **A modal owner reads `S.alt_held` itself** (K2, K3, E2 and E3 reach it with ALT unsplit), as SEQ's step editor does. The slice editor's ALT forms are its own branches.
29. **The scan is a speed** (design decision 20, 2026-11-16). `buf_scan` is a speed where 1 is the audio's own rate, for every buffer voice; no `scan_unit`, no `scanUnit` control. A non-zero scan in an old scene plays at another speed. Its range stays -2 to 2. A frozen ring's scan is untouched.
30. **Old formats go first** (decision 21). Task 0d deletes every conversion keyed on an old version before any other package starts. The floors: scenes format 7 (3.5's) and `buffers.data` version 2 (3.3's); an older file is set aside, as an unknown version is. From the floor up, a file loads with its missing fields filled from defaults. So 0b's version 8 needs no migration and keeps no `.v7` copy, and 2d's version 3 loads version 2 with no `.v2` copy.
31. **BUFFER's keys come in line** (decision 22; 2c): a quick ALT+K2 loads a random file and held it fills every empty slot; clear is K2 held; a quick K2 still opens the file selector; ALT+K3 is unchanged.
32. **A pattern's slices overlap on an overlap voice** (decision 23; 2b): there a step's slice plays in a note slot of its own and rings to its end; on a voice set to `one`, or off, it is the own note's and replaces.
33. **LFO destinations are listed by voice and stored by key** (decision 24). Task 0e, in Wave 0, so the matrix's and the envelopes' packages build on the new list.
34. **The 256's delay fader picks the division while the delay is synced** (1d), as FX's `time` row and arc ring 3 do. It is 1d's shared line in `lib/grid/layout_256.lua`, which 1e also edits (row 8).
35. **No 3.7 param joins a page's randomize, a mutation or the 256's fader pages.** Design §9 said each page's randomize takes in its new rows; none of 3.7's rows is a value worth a random draw (modes, options, chances, a file's settings). The 256's faders for newer params are a later package (`ROADMAP.md`).
36. **A repeat is the picker's move, never two equal slots.** `S.lib.chance.pick` returns the move; only `"repeat"` recalls or links nothing. With one populated slot at 100, 0, 0 the move is `"next"` and the slot is recalled again, as 3.6 does.
37. **Wave 1's memory is measured where its packages meet.** 1a and 1c each measure on their own branch; before the Wave 1 batch's pull request the controller runs the memory area on the landing branch on both SuperCollider versions and writes the final figures in `docs/notes/engine/memory.md`. A floor that fails there is handled by design §1's order of cuts.

## How to read the tests

**All three checks** means `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua`, from the worktree root, each exiting 0.

**Test shorthand.** A test block gives each test's name and its assertions in comments; the implementer writes the setup and the `h.` calls. `a -> b` and `a == b` are `assert_equal(a, b)` (a number marked `(near tol)` is `assert_near`); `f() -> "line"` means calling `f` makes the stub record `line`; `;` starts the next case on the same setup. Every number and every quoted line in a comment is an exact value of the design, of a fact file or of a ruling above.

**Lua.** Tests live in `test/unit/<module>_test.lua`, each `return function(h) ... end`. The harness (how a test reads the engine's calls, advances the 48 Hz clock and the beat, sends MIDI, presses and releases a grid key, shows a page, reads the screen and plugs a double before init) is in plan-lua.md §8, with one short existing test of each kind.

**The engine check.** An area file returns `{ arg h; ... }`. A check line's first words are its area and a colon, as every name below is written. Equality with an earlier release is measured as plan-engine.md §2 says (two synths in one bundle, `\strataCheckBusDiff`, a difference under the check's own tolerance with a level above 0.01). `h.controlFeedsAUGen(defName, controlName)` shows a control reaches a UGen.

**Doubles.** A package that consumes a module of its own wave gives its tests a double at the module's place in `S.lib`, with exactly the functions its Interfaces block names, through `load_strata({before_init = ...})`. The test stays valid once the real module lands.
