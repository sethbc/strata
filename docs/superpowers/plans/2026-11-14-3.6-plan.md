# Strata 3.6: Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, as `docs/workflow.md` runs it (parallel packages, one worktree and branch each, batch landings). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect Strata to the rest of a rig: a voice's steps and played notes also play Just Friends, W/, a TELEXo, an ER-301, an nb voice or a MIDI synth; crow's jacks carry modulation out and control voltages in; an E16, a fader box, a grid or arc in iii mode, a Launchpad and TouchOSC become control surfaces; a Teletype drives scenes and voices; a tape loop runs on softcut; all on a tenth page, IO, and all off by default.

**Architecture:** Wave 0 changes no behavior: the hooks the merged modules lack (0a), one owner for every MIDI port (0b), the IO page's shell and the rig settings (0c), five test stubs (0d), the facts documents can still settle (0e) and the actions three later modules share (0f). Wave 1 builds the foundations side by side: the targets core (1a), crow (1b), the controllers (1c), remote grids and arcs (1d), OSC (1e) and the tape (1f). Wave 2 plugs into them: MIDI out (2a), the ii bus and Teletype (2b), the four ii devices (2c to 2e) and nb (2f). Every module is Lua under `lib/io/`, registers itself (a target, a section of IO, a modulation source, an ii device) and does nothing until its setting is turned on. The engine is not touched.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua` and five new stubs (crow, OSC, softcut, nb, iii); norns' `midi`, `crow`, `osc`, `softcut` and `clock`; crow's ii descriptors as text; iii's device Lua (1.1.0 or later); OXI's E16 scripting; a TouchOSC `.tosc` generator. SuperCollider only as the release's regression gate.

**Spec:** `docs/design/3.6-design.md` (approved 2026-11-14, twenty-one decisions made). It binds over `ROADMAP.md` for 3.6. Its facts are the four files under docs/design/3.6-facts/ (`crow-ii.md`, `controllers.md`, `iii-osc-nb-softcut.md`, `code.md`), and 0e adds a fifth, `checks.md`. Read the design sections a task names before starting it. Where the design and the merged code differ, "The design against the merged code" below rules, and a task's text already follows those rulings.

## Global Constraints

- Everything in AGENTS.md applies: named constants, `send_param_to_engine`, the registries, `request_redraw()`, bounds checks, a cleanup step for every clock and handler, handlers on vports only, the data files rule (`S.lib.data_files.write` and `read` only), the locals probe (30 free locals per main chunk and constructor), a module's constructor shape, one `include` per module from `strata.lua`.
- **No engine change.** No package edits anything under lib/engine/, `lib/Engine_Strata.sc`, `test/engine_check.scd` or test/engine_check/, and none adds an `engine.<name>(` call of a new name. The engine check runs at the release only, as a regression gate.
- **No package edits `init` or `cleanup()`.** Start and cleanup steps register at their orders (Branches, ports, fragments).
- **Nothing by default.** Every route, input, output, slot, controller and the tape default to off. A fresh Strata, or a 3.5 PSET, sends no MIDI, crow, ii, OSC or softcut message and plays as 3.5 does. Each module's test asserts it for its own stub with defaults; 3a asserts it for all of them at once.
- **IO sections.** A module that registers a section gives it `layout_states` for each look it has: without its device, with it, and each detail list open. The layout tests and the renders then cover every one, and 3b reads them.
- **Params:** every 3.6 param is PSET-only, in one of five groups (`strata_out_midi`, `strata_crow`, `strata_out_ii`, `strata_out_nb`, `strata_tape`), added by plain `params:add` calls in its module's `add_params()`. None is a scene field, an LFO destination or a fader-page param, and none reaches a randomize or a mutation. `SCENE_DATA_VERSION` stays 7 and `PSET_FORMAT` stays 2. A group's count equals the params that follow it.
- **Rig settings** (`io.data`) are never params, scene fields or PSET data, and only a row of the IO page changes one. A PSET load, a scene recall, a controller, OSC and a Teletype call cannot.
- **One door per device.** Every MIDI listener, hot-plug handler and output goes through `S.lib.io_ports`. Every line to crow goes through `S.lib.io_crow.send_now` or `send_value`, as text (`crow.send(line)`): no function is ever assigned through the `crow` proxy. Every ii message goes through `S.lib.io_ii.send` or `send_direct`, which send nothing unless `S.lib.io_ii.leads()`. Every target note goes through `S.lib.io_targets`.
- **The bounds of design §1**, each a field of its module's one tunables table:

  | Constant | Value |
  |---|---|
  | `CROW.lines_per_window`, `CROW.window_seconds` | 32, 0.1 |
  | `CROW.stream_seconds` | 0.02 |
  | `II.sends_per_step`, `II.queue_max`, `II.cleanup_sends` | 4, 48, 14 |
  | `MIDI_OUT.express_per_step`, `MIDI_OUT.cc_per_step`, `MIDI_OUT.slots` | 24, 8, 8 |
  | `REMOTE.leds_per_tick`, `REMOTE.draw_hz`, `REMOTE.version` | 96, 30, 1 |
  | `OSC.sends_per_tick`, `OSC.feedback_hz`, `OSC.echo_seconds` | 32, 15, 0.25 |
  | `CONTROLLERS.echo_per_tick`, `CONTROLLERS.echo_hz`, `CONTROLLERS.pickup_window` | 16, 15, 2 / 127 |

  A step is one 48 Hz step of `S.lfo_clock`, reached through `S.lib.lfos.on_step`. Notes, gates, triggers and ii messages are never held back by crow's window; followed values are.
- **Hooks and targets never yield** and never call `S.lib.notes.play`. Every hook, listener, target call and section function a module runs for another runs through `S.lib.ui_frame.contained_call`.
- **Documents only.** No device is used. A device module's first failing tests pin the text or bytes its document gives, and each such test's comment cites the fact file's section. Every user page for a device names the document it was built from, its version, and says "unverified on the device until the 4.0 hardware check".
- **No third-party code** under lib/. Strata loads no nb, midigrid or TouchOSC file.
- **AGENTS.md has 8,000 words and this plan's pull request leaves about 7,750 used.** A package adds only the rows and lines its task names; if the word-limit test fails, it shortens its own additions and reports it.
- **Changelog:** each package adds `changes/3.6-<package>.md`; a feature package never edits CHANGELOG.md. `docs/status.md` changes in Wave 3 only, except where a package closes an open item.
- **US English** everywhere (a test enforces it); docs, commits and pull requests never name the maintainer.
- **Isolation:** each task's dispatch names a scratch folder `scratchpad/3.6-<task>/`; a worker writes only there and in its own worktree. Deletes are `rm -rf -- "${dir:?}"` on a path inside the worker's own folder; worktrees go only with `git worktree remove`.
- **Every finding is fixed, never deferred:** a review's findings are fixed in the package; a problem outside the package gets its own GitHub issue and fix.
- **After every task:** `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua` pass.

## Review Focus

The inputs the design implies and no single module's happy path exercises, most likely to bite a player first. Each line's test is in the task that owns the code.

1. **A note with no end.** A route changed while notes sound, a voice stopped under held keys, a latched chord replaced, the patterns stopped mid-gate, a voice muted mid-note, a PSET loaded while playing, cleanup: after each, every target has had as many offs as ons. Test in 1a (`"every way a note ends sends its off to the targets it started on"`), again per device in 2a, 2e and 2f, and for everything at once in 3a.
2. **A device that is not there, or leaves mid-note.** Every module with its device absent sends nothing and raises nothing; a MIDI output that returns gets all notes off on each channel it had notes on; crow returning gets every current setting's line again and nothing else. Tests in 2a (`"a MIDI output that returns gets all notes off on the channels it had notes on"`), 1b (`"a reconnect sends exactly the current settings' lines"`), 2b (`"with no crow nothing is queued or sent"`).
3. **A loop.** A played note sent back to the port it came from; a program change in that recalls a scene whose program change goes out on the same port; OSC feedback answering the message that caused it; a controller's echo read back as a turn. Tests in 2a (`"a played note is not sent to the port it arrived on"`, `"a scene recall sends its program change, and a program change in is not echoed on its own port"`), 1e (`"a value that just arrived is not sent back"`), 1c (`"the echo of a macro is never read as a turn"`).
4. **A flood.** Sixteen MPE notes all moving, a chord of eight to four ii devices at 300 BPM with ratchets, six LFOs on crow's outputs, a full redraw to a remote grid every frame: each bound holds as stated, the newest values win, nothing is starved, and a note is delayed only by the ii rate. Tests in 2a (`"MPE expression sends at most 24 a step, newest values, no note starved"`), 2b (`"the queue sends 4 a step in order and drops the newest past 48"`), 1b (`"followed values wait for the window and notes never do"`), 1d (`"a full redraw lands within four ticks at 96 a tick"`).
5. **A wrong setup.** A CC on the controller's channel outside its sixteen; a fader box sending 7 bits with `faders_hires` on; a remote hello with another version or a size that is no layout; a Teletype call out of range; a rig file from a later version. Tests in 1c (`"a CC outside the sixteen is ignored"`, `"hires uses the low byte once one has come, and a 7-bit box still reaches both ends"`), 1d (`"a hello of another version or size attaches nothing"`), 2b (`"a Teletype call out of range does nothing but print one line"`), 0c (`"an unreadable or wrong-version io.data is set aside"`).

The design's other two (the bus under `off` and `teletype`; crow's reset run twice) are 2b's and 1b's own tests.

## How to read the tests

**All three checks** means `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua`, from the worktree root, each exiting 0.

**Test shorthand.** A Lua test block gives each test's name and its assertions in comments; the implementer writes the setup and the `h.` calls. `a -> b` and `a == b` are `assert_equal(a, b)` (a number marked `(near tol)` is `assert_near`); `f() -> "line"` means calling `f` makes the stub record `line`; `;` starts the next case on the same setup. Every number and every quoted line in a comment is an exact value of the design, of a fact file or of a ruling above.

**Lua.** Tests live in `test/unit/<module>_test.lua`, each `return function(h) ... end`, with `test`, `assert_equal`, `assert_true`, `assert_near`, `load_strata`, `local_value`, `show_page`, `tap`, `hint_text`, `screen_shows`, `assert_screen_layout` from `h`; `S` is `local_value("S")`. MIDI goes in through `context.midi.plug`, `context.midi.send` and comes out in a plugged device's `sent` (`test/stub_midi.lua`). A step of the LFO clock is the harness's clock advance of 1 / 48 s, as `test/unit/notes_test.lua` does today.

**The stubs 0d adds**, by the names later tasks use:

| Stub | Reached as | Records |
|---|---|---|
| crow | `context.crow.plug()`, `unplug()`, `fire(event, ...)`, `clear()` | `context.crow.sent` (each line, in order, only while plugged), `function_assignments`, `resets` |
| OSC | `context.osc.receive(path, args, from)` | `context.osc.sent` (each `{to = {host, port}, path, args}`) |
| softcut | `_G.softcut`, `audio.level_eng_cut`, `audio.level_adc_cut`, `audio.level_tape_cut`, `audio.level_cut`, `context.softcut.fire(name, ...)` | `context.softcut.calls` (each `{name, ...}`), `context.softcut.value(name, ...)`, `context.audio.levels` |
| nb | `context.nb.add_player(name, methods, inherited)`: a plain table with exactly the methods named (default `note_on`, `note_off`, `add_params`) as its own fields, and `inherited` ones only through a metatable, as another nb host leaves them; it can be added in `load_strata({before_load = ...})` | the player's `calls` (each `{name, ...}`) |
| iii | `require("stub_iii")({kind, cols, rows, version})` (`version` is iii's, default `"v1.1.2"`; below 1.1.0 the environment has no `device_version`), `device.fire_metro(id)` | the device's `sent`, `leds`, `refreshes` |

**Doubles.** A package that consumes a module of its own wave (2c to 2e use 2b's) gives its tests a double at the module's place in `S.lib`, with exactly the functions its Interfaces block names. A double that init must see goes in through `load_strata({before_init = ...})` (`test/helpers.lua:142`): 2c to 2e's is `S.lib.io_ii = {leads, send, send_off, send_direct, add_params}`, the first four recording their calls, and `add_params` doing what 2b's does (one group `strata_out_ii` of the registered devices' summed `param_count`, then each device's `add_params()`), since without it a device's params are never added on its own branch. The test stays valid once the real module lands, since it replaces it.
