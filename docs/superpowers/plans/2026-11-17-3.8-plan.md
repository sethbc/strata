# Strata 3.8 (sound) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, as `docs/workflow.md` runs it (parallel packages, one worktree and branch each, batch landings). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Strata 3.8: a voice chooses its synth type from twelve (five new) and a scene carries the choice; the grain gains a continuous window, probability, an arpeggiator and constant overlap; a voice grains another voice's output or one input channel; any Scala tuning plays, with a scale editor; the sends become plain sends, the delay freezes and clears, shimmer sits in the delay and the reverb, the high tier's reverb freezes; a voice's sound is saved, loaded and copied; the four grid layouts become one model of panes; and the code that lists and loads factory sets exists.

**Architecture:** Twenty-nine packages in five waves, ordered by which files they own. Wave 0 makes room and budget: `AGENTS.md` trimmed, the comparisons with 3.7.0 taught to take named differences, the delay's line moved from the real-time pool to a buffer (about 1 MB back at every worst case), Karplus trimmed, a type per voice in the engine and in Lua with scene format 10, the pane engine for the grids, and the fix of #772. Waves 1 to 4 build each feature as a new module or engine file beside the code it joins, so packages of a wave share only registration lines. Every engine package measures what it adds against the memory area's floors before anything is built on it.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua`; SuperCollider 3.14.1 locally and 3.13 in Docker for the engine check; norns' `params`, `clock`, `midi`, `grid` and `arc`.

**Spec:** `docs/design/3.8-design.md` (approved 2026-11-17). Its facts are under docs/design/3.8-facts/: seven behind the design (`engine-voices.md`, `engine-effects.md`, `engine-grain.md`, `lua-types.md`, `lua-presets.md`, `lua-grids.md`, `lua-tuning.md`; their line numbers are older than the groundwork) and seven behind this plan, one per group of packages (`plan-budget.md`, `plan-types.md`, `plan-effects.md`, `plan-grain-sources.md`, `plan-tuning.md`, `plan-presets-factory.md`, `plan-grids.md`; line numbers are `main`'s at 2edbfa96, and earlier packages move them). A task names the plan fact file section it argues from; that section's site lists (file and line of every edit), its exact names and its test lists bind as part of the task, except where "The design against the merged code" below or the task itself rules otherwise. `docs/decisions/3.8.md` holds the groundwork's decisions this release builds on.

## Global Constraints

- Everything in `AGENTS.md` applies: Lua and the engine in sync, the command table (one row per `addCommand`, the same signature), named constants, `send_param_to_engine`, the registries, `request_redraw()`, bounds checks, the data files rule, the locals probe (30 free locals per main chunk and constructor), a module's constructor shape, engine calls only as `engine.<name>(...)`, engine extension files that add methods only.
- **The real-time pool is 8192 KB and the floors do not move**: every worst case of the memory area leaves at least 3072 KB on standard and 3584 KB on high with the note pool empty, and 1280 KB with it full, with every voice on the costliest type. One limit of 52 KB holds every voice def; a grain def's limit is what 1c measures plus 2 KB and no more than 97 KB; the mix stage stays under 42 KB. An engine package reports each pool size it adds, on 3.14.1 and on 3.13. If a floor fails, the order of cuts is the design's (§1): the additive voice's partials, the arpeggiator's fold, the reverb's shimmer; nothing is cut before the estimate that was wrong is found.
- **The engine uses SuperCollider's core UGens only**, one audio-rate `LocalIn` a SynthDef, no `LocalBuf`, no delay line or table sized from a control, no per-sample sclang loop, kept closures through `areaCall`, messages to synths that can end on their own through `sendToSynth`.
- **A new feature is off at its default.** A default start sends the engine what 3.7.0 sends but for the differences a package names in the fixture allowances (ruling 9): `setVoiceType` per voice, the reverb's level, the plain stage's controls, the grain controls that replace `envShape`, and what each later package lists. The fixtures stay 3.7.0's; a package that moves a comparison on purpose adds its named difference in the same commit and says so in its report.
- **Every param 3.7.0 has keeps its id, spec, default and place**, but for the named differences: `v<i>_grain_env` goes; `delay_time`'s maximum is 5.4 s; `reverb_mix`'s default is 0.43 and it and `delay_mix` are labeled `level`; `scale` gains `custom` at its end.
- **Scene format 10, raised once, by 0d** (`SCENE_DATA_VERSION` and `SCENE_FORMAT_FLOOR`); later packages add keys under it and never raise it. No conversion of an old file: a file below its floor is set aside whole. A test builds a scene from a capture, never from a literal of an older shape.
- **Data files** are written only through `S.lib.data_files.write` and read only through `S.lib.data_files.read`; `voices.data` and `factory.data` join the ten; a version is compared only with a constant named `_DATA_VERSION` or `_FLOOR`.
- **`AGENTS.md` has 7,744 of its 8,000 words** until 0a lands and at least 800 free after it. A package adds or rewrites only the lines its task names and reports `wc -w AGENTS.md`. A new module needs no row (ruling 7).
- **`init`, `cleanup()`, `redraw()` and `lib/Engine_Strata.sc` are never edited.**
- **Changelog:** each package adds `changes/<its fragment>` (the table below); no package edits CHANGELOG.md. A new or renamed engine file needs the norns restart note in its fragment.
- **`docs/status.md` is the landing's.** A package names the edit it needs in its report.
- **Unverified on devices until 4.0** (#6): each package lists, in its report, the device checks its work adds to #6.
- US English everywhere; the maintainer is never named.

## Review Focus

The five conditions the design implies and no task's first tests exercised; each has its test in the task named.

1. **A PSET saved by 3.7 is loaded after the update,** over a session that has moved on (a voice on another type, another tuning). A reasonable player expects it to load with no error line and to sound as it did but for the sends' balance: each voice its old type, its `v<i>_grain_env` lines naming no param, the reverb's 0.3 read as a level, twelve equal steps and a quantized voice on its saved note. Test in 0d ("a 3.7 PSET loads with no error line and each voice its old type"), with 1a, 1c and 1e each adding their lines to it.
2. **A scene recall changes the type of a voice that is frozen, holds a chord, or reads a buffer.** Nothing raises; the frozen voice stays frozen on the old type's sound; the chord's notes play on the new type; the buffer voice only records the type. Test in 0d.
3. **The delay is frozen and then the tempo moves, sync is switched, the delay is bypassed or a PSET is loaded.** The loop keeps its length until released; a bypass ends the freeze and the lift starts empty and unfrozen; a PSET load leaves the freeze as it is (ruling 61). Test in 1b.
4. **A grid is unplugged and plugged again, turned, or joined by a second grid of another size, while a pane shows a second side and a key is held.** No key stays held, no page of a missing pane is drawn, each port keeps its own panes. Test in 0e with probe pages, and with page 5's own keys in 1m.
5. **A factory set's load is interrupted mid-copy** (the script stopped, the card full), a first run's included. The next load finishes it, and a first run cut short runs again at the next start: a `.part` is never taken for a sample, no param or player file was touched, and a set is marked loaded only after a whole load (ruling 51). Test in 4d.

**1e, tuning**
37. **The quantize is the nearest allowed tone, a tie going down**, as Lua's snap already is. With a scale on, about a sixth of pitches land a tone away from where 3.7's two-step rule put them; the default, chromatic, is unchanged but at exact half-semitones. A sound change, recorded.
38. **The table is 4096 frames from note -100** (`tuningTableFrames`, `tuningTableLow`; buffer voices reach -84 to 211), built with `Signal` primitives and sent as one `/b_setn` Array.
39. **`custom` is tested for by name** in the mask and the chord code (at the list's end it would read as off).
40. **The chord set**: with a scale on in a twelve-note tuning, degrees 1, 3, 5 and 7 of the scale; otherwise the tuning's tones nearest 0, 4, 7 and 11 semitones. **A degree with the scale off is one tone of the tuning** (a semitone in twelve equal, as a test pins).
41. **A quantized `freq` turns by tones scaled to the tuning** (`min(1, mean step / 0.797 semitone)` of shadow travel a tone), so twelve equal and every built-in scale turn as today.
42. **No send at a default start** (the engine's start table is twelve equal; #460's rule). The tuning is sent when its params' actions run. `START_ORDER.tuning` is 55 for the module's own start.
43. **The parser refuses a period outside 100 to 4800 cents**, a file over 128 tones, and tones that do not ascend. A 128-tone tuning is a 1.26 KB param line.
44. **The SETUP rows are appended after `transport`**: `scale & tuning` (1e), then `factory sets` (4d).

46. **The undo of a load restores the capture's type and values with the voice's present `active` and `source`**, and `undo_for` matches any VOICE section of the voice for a held load.
47. **3b also edits `lib/ui/cursors.lua`** (a row with no param) and keeps the `preset` row out of the arc's rings.

It has two fields: `pending` (the key of a first-run set whose load has started and not finished) and `loaded` (each set loaded whole, by version). A first run writes `pending` before the copy; a whole load writes `loaded` and clears `pending`; a start that finds `pending` runs that load again; a player whose scenes file was found at the start gets `loaded = {}` and no load.

## How to read the tests

**All three checks** means `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua`, from the worktree root, each exiting 0.

**Test lists.** A task names its tests and the values that decide them. The plan fact file's section for the package gives each test's setup and the existing tests to re-base, by file and line. Write every test named there or here; where the two differ, this plan rules. A test re-based or deleted is named in the report with its reason.

**Shared test files and registration lines** (ruling 4): a package edits only the tests and lines of its own behavior there; the landing keeps both sides.
