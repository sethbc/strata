# Before 3.8: Groundwork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, as `docs/workflow.md` runs it (parallel packages, one worktree and branch each, batch landings). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settle the seams 3.8 builds on (one value table per voice with one registration path, an LFO's destination as a home routing of the matrix, one stepper under the chain and the scene sequencer, scenes that travel with the PSET), make the three roadmap revisions (`frozen` renamed `locked`, fader pages for newer params, MIDI note off as latch or release) and fix #738-#744 and #747-#754.

**Architecture:** Thirteen packages in six waves, ordered by which files they own. Wave 0 renames the lock and opens scene format 9. Wave 1 replaces a voice's four value tables with one and reshapes the scene, beside four fix packages that share no file with it. Wave 2 turns the built-in per-voice params into registration records (the faders read them), moves each LFO's destination into the matrix as slot 16 + n, and cuts MIDI note off to two modes. Wave 3 puts one stepper under the chain and the scene sequencer and fixes the sequencer's findings. Wave 4 makes scenes a PSET's fifth side file. Wave 5 is the docs pass. Nothing is released: the fragments ride to 3.8.0.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua`; SuperCollider 3.14.1 locally and 3.13 in Docker for the engine check (package 1e only); norns' `params`, `clock`, `midi` and `grid`.

**Spec:** `docs/design/3.8-groundwork-design.md` (approved 2026-11-16). Its facts are the nine files under docs/design/3.8-groundwork-facts/: three behind the design's decisions (`lfo-routing.md`, `chains.md`, `data-files-extras.md`) and six behind this plan, one per group of packages (`plan-0a-locked.md`, `plan-1a-values.md`, `plan-1b-1e-fixes.md`, `plan-2a-records.md`, `plan-2b-lfo-home.md`, `plan-3a-4a-scenes.md`). A task names the fact file it argues from; that file's site lists (file and line of every edit), its exact names and its test lists bind as part of the task, except where "The design against the merged code" below rules otherwise. Line numbers in the fact files are `main`'s at 3bb75daa; earlier packages move them. The fact files call package 2c "3b".

## The design against the merged code

The fact pass found these. Each is a ruling of this plan; 5a records them in `docs/decisions/3.8.md` with what each costs if wrong, and the design is amended to match.

**The lock and the format (0a)**
1. **The lock's own uses are 32 lines in 9 files under `lib/`,** about 100 test lines in 14 files and 27 doc sites. The design's larger counts included the audio freeze. No function, hook or param is renamed: only `S.frozen`, a scene's `data.frozen` and test locals.
2. **The format 9 fixture is 4a's,** the last package to change the file. No 3.7 fixture exists: a test that needs a format 8 file relabels the 3.6 fixture's version or writes a capture as 8.
3. **A scenes file below the floor reads as older, not unreadable.** `S.scene_file.problem` gains the value `"older"`; SETUP's row and the start's flash say `older` where they say `unreadable` for a damaged file; the console line names the file's format and the one this build reads. The line for a file newer than the build stops saying "expected 9 to 9".

**The value table (1a)**
4. **A voice's keys are applied built-in keys first, sorted, then registered keys, sorted.** One fully sorted order would set `freeze` before `freq`, and a recalled freeze on a running synth voice would take its reference from the old note. The design's "in sorted order" is amended.
5. **The seam for 2a is two functions in `lib/params_setup.lua`:** `voice_engine_parts(voice_idx)` (the start and sync sends) and `voice_scene_keys(voice_idx)` (the scene keys). After 1a neither `lib/engine_sync.lua` nor `lib/scenes.lua` reads `S.registry.voice_params`.
6. **A recall is built from `S.lib.scenes.voice_entries`, not from seven `apply_voice` calls,** which would run the scene-applied hooks eight times. `apply_voice` applies at once; what it does during a running fade is 3.8's.
7. **`GRAIN_PARAM_IDS` and `S.VOICE_SCENE_DEFAULTS` go in 1a; `DISCRETE_GRAIN_KEYS` is rekeyed in 1a and goes, with `BUFFER_MUTATION_KEYS`, in 2a.**
8. **A synth-key test is `S.lib.voices.is_synth_key(voice_idx, key)`,** never `values[key] ~= nil` (VOICE's randomize on a buffer voice would draw option rows).
9. **The synth params go out in sorted key order,** at a start and a sync, where they went in `pairs` order. MAIN's randomize and the mutations draw them in `param_order`.

**The records and the faders (2a)**
10. **No `action` field.** A param filter and the param's own action already cover every built-in. The new record fields are `voice_keys`, `send_order`, `separator`, `fader` groups (each with an optional `rank`), `main_randomize` and `mutate`, and `count` may be a function of the voice.
11. **The three built-in records register in `lib/voices.lua`,** the first module that can, so they are the first three records.
12. **The new faders keep the design's order** (the maintainer, 2026-11-16, over this plan's first call of registration order): the voice filter's cutoff, resonance and mix; the delay and reverb sends; the loop's start and length; the pitch, size and pan jitters; attack and release. Registration order cannot give it (loops and variation register before voice_mix), so a fader group carries an optional `rank` and `fader_param_ids` sorts the groups by it, stably. The loop's faders show on buffer voices only, as VOICE's rows do, so a voice has 7 or 8 fader pages; the design's "7 to 9" is amended.
13. **`fader = false` stays allowed** (eight records keep it).
14. **`grain_env`, `grain_mode` and `mod_source_<n>` send through `send_param_to_engine`,** so those sends are counted by the send budget and deferrable. The messages are the same.
15. **`turn_on_own_delta` is called by the synth record's `add` only.**

**LFO home routings (2b)**
16. **A home on `v<i>_main` that resolves to a fast param goes out as `setFastOffset`,** the matrix's rule, as an R routing to it does today. Until now the LFO sent it from Lua as `setGrainParam`.
17. **A restore after an LFO goes off, to depth 0 or to another destination arrives at the matrix's next step,** through the round robin, where it was sent at once. A macro's restore stays immediate.
18. **A voice start and sync carry a Lua home's offset at once.** The #644 and #50 tests are re-based.
19. **A destination this build lacks shows `none` on the LFO page** and is kept until the row is turned.
20. **A 3.7 MIDI map of `strata_lfo<n>_dest` is left to the player:** the fragment and `docs/user/modulation.md` say to remove the mapping.
21. **`with_lfo_offsets` keeps its name.** The homes are slots 17 to 22 with no new constant in `lib/constants.lua`.

**The fixes**
22. **#750:** every owed note keeps its number, so an arriving device gets each owed note's own off and no CC 123 is ever sent; `MIDI_OUT.all_notes_off_cc` goes. The design's "CC 123 only for the rest" has no rest.
23. **#748:** a record that names no device owes nothing: it is set aside with a nil key, at a settle and at a departure.
24. **#747-#750 are one worker's four commits, in the order #748, #749, #750, #747.**
25. **#751:** the handlers wait `math.ceil(sent / II.sends_per_step)` steps of the 48 Hz hook; another leader change cancels the wait.
26. **#752:** the fix is `ready` no longer emptying the active set before its sync, in `lib/io/txo.lua` alone. The design's "rebuilt when crow leaves" is amended.
27. **#738 and #754 arise only from a scene table written outside `lib/scenes.lua`** (a disk load sets the whole file aside when one scene is invalid). The validity cache is a local keyed by slot and holding the data table it checked; a table it has not seen is checked once.
28. **#743 takes the fits rule:** a shorter length applies at once while the leg can still turn at it, else at the leg's turn, as reverse does.
29. **A cleared playing scene on the chain goes on to the next saved one with no draw,** as the scene sequencer does. "Keeps the playing scene" is the pick's own answer for a list of one: applied again at 100, 0, 0, held on a repeat.
30. **The chances' label is `random` on both pages;** `lib/pages/scenes.lua` joins 3a.

**Scenes with the PSET (4a)**
