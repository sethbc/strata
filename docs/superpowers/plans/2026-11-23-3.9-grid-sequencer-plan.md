# 3.9: The Grid's Sequencer, Reworked: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, as `docs/workflow.md` runs it (parallel packages where their files allow, one worktree and branch each, batch landings). Steps use checkbox (`- [ ]`) syntax for tracking. **Not started:** no task of this plan is built until the seven waves of `docs/superpowers/plans/2026-11-21-3.9-state-machines-plan.md` have landed.

**Goal:** A pattern entered on the grid changes what is heard, at once and by a lot, and can be shaped and played from the grid alone: a step mode a voice (accent, pulse, move), lanes with their own lengths, a lane side and a step view on the grid, and a loop, a roll and four variations a voice to perform with.

**Architecture:** Fifteen packages in six waves, each wave landing whole. The existing sequencer stays: its per-step settings become lanes (`lib/lanes.lua`), read at the step that plays until a lane is given its own length. Pulse is the engine's existing gate driven by one derived rule, with one new stage control for a floor; move is the base override the step locks use, made to last. Variations (`lib/variations.lua`) and the loop and roll (`lib/perform.lua`) are new modules beside the sequencer; the grid gains a second side on its patterns and voices pages.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua`; SuperCollider 3.14.1 locally and 3.13 in Docker for the engine check (package 1a only); norns' `params`, `clock` and `grid`.

**Spec:** `docs/design/3.9-grid-sequencer-design.md` (approved 2026-11-23). Its facts are the four files under docs/design/3.9-grid-sequencer-facts/ (`sequencer-core.md`, `grid.md`, `engine-sound.md`, `around.md`), gathered from wave 2's landing branch of the state machines work; a task names the fact file and section it argues from. Line numbers there are that branch's: find each site by its text.

## Global Constraints

- Everything in `AGENTS.md` applies: named constants, `send_param_to_engine`, the registries, `request_redraw()` and `grid_redraw()`, bounds checks, the data files rule, the locals probe (30 free locals per main chunk and constructor), a module's constructor shape, engine calls only as `engine.<name>(...)`.
- **Every scene and PSET saved before this work loads and plays as it did.** No stored value changes meaning: `SCENE_DATA_VERSION` and its floor stay 10, no code is keyed on a file's version, and new data is a scene block with a default.
- **A script with no steps sounds as 3.8.0's.** A default start still sends `seqGate 0` for every voice. The start fixture is re-based once, by 1a, for its ten `gateFloor 0` lines and nothing else.
- **With no lane length set, a pattern plays exactly as it does today.** The tests that pin today's playing stay green untouched: "a 3.6 pattern plays the same steps as before", the draw order, the node counts, the `position and pass` table. A test re-based or deleted is named in the report with its reason.
- **No stored state for a state that can be derived.** The gate rule, a lane's following and a letter's waiting are functions of what exists. A package that finds it needs a second record of a fact stops and reports NEEDS_CONTEXT.
- **No engine command, SynthDef argument beyond `gateFloor`, node, delay line or table is added.** The stage stays under its 42 KB limit; `lib/Engine_Strata.sc` is not edited.
- **The grid's shape holds:** seven pages, at most two sides a page, sixteen strip keys, pane coordinates only, state in `pane.state()` or the port's state, one repaint a beat while the patterns play.
- **Every new machine gets its Machines entry and a transition table** a test runs (`h.transition_table` with `notes`), with an invariant where the design names one, in the package that builds it. An `impossible` reason is true of the code.
- **`init`, `cleanup()` and `redraw()` are never edited.** A clock runs through `S.lib.clocks`.
- **`AGENTS.md` has 76 words left** under its 8,000. Only 6c edits it, rewording one line within its words; a module in a subfolder adds its row as short as it can be.
- **Notes files stay under 9,000 words.** `docs/notes/lua/sequencer.md` takes no new section: each new module has its own notes file, and the sequencer's new topics go under docs/notes/lua/sequencer/.
- **Changelog:** each package adds `changes/gs-<id>-<slug>.md`; no package edits CHANGELOG.md.
- **A fault found on the way gets its own issue**; a table lands with the faulty cell as a `known` row.

## Review Focus

The five conditions the design implies that are most likely to bite a player; each has its test in the task named.

1. **A scene saved in 3.8.0 is recalled after this work, and a chain runs through 3.8.0's scenes.** Every voice plays in the mode it was saved in and every step sends what it sent. Test in 2b ("a format 10 scene plays the steps it played in 3.8.0", from `test/fixtures/format-10-files.lua`).
2. **A voice is left on a value.** Its steps are turned off one by one while it plays, the patterns are stopped, its target is changed, a letter is switched. The param is back at its own value each time. Test in 2a (the `held values` table walks every end).
3. **A pulse voice is silent and nothing says why.** Its only steps lie past its length; its mode is changed while the gate is closed; the patterns stop inside a gate's release. What the engine was last sent equals the rule after each. Test in 1b (the `step gate` table and its invariant).
4. **A key is held across a side change, the step view opening, a variation switch, an unplug.** Nothing stays held, a loop without its latch never outlives its key, the step view never outlives its key. Tests in 3c, 5a, and the walks of 6b.
5. **Things fall on the same bar.** A waiting letter, an order's next entry, a chain link and a recall arrive together, with the step editor open and a roll held. One pattern is left playing, the letter shown is the one that plays, and the roll ends with its key. Test in 4b ("a chain link wins over a waiting letter on the same bar") and 5b.
