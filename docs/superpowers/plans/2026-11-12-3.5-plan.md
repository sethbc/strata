# Strata 3.5: Polyphony and MPE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make each of Strata's seven voices playable as an instrument: up to eight notes on a voice from a pool of extra notes the voices share, MPE with per-note bend, pressure and slide from a LinnStrument, an Osmose or an Exquis, an expression mapping per voice, and sequencer chords, all defaulting to 3.4's sound.

**Architecture:** Wave 0 changes no behavior: 0a adds the Lua registries, the budget's direct-send count and the note module's skeleton; 0b adds the engine's `notes` area (order 170) with four commands as checked stubs and measures every voice SynthDef, which fixes the pool's maximum; 0c fixes the five findings of the design's fact gathering. Wave 1 builds the three foundations side by side: the per-note controls in the SynthDefs (1a), the allocator in Lua (1b) and the MPE parser (1c). Wave 2 builds the engine's note lifecycle (2a) and, against the engine stub, the players and pages (2b to 2g). Lua owns every value and decides what is stolen; the engine never stacks in a slot and holds the pool's bounds itself. The fast-modulation bus stays as 3.4 built it.

**Tech Stack:** Lua 5.3 and LuaJIT against `test/norns_stubs.lua`; norns' `midi.to_msg`, `musicutil` and `lib/ui`; SuperCollider 3.13.0 (norns and CI) and 3.14.1 (local), class extensions `+ Engine_Strata { }`, core UGens only; the engine check through `test/run_engine_check.sh` on `$STRATA_SC_PORT` and `test/run_engine_check_313.sh` in Docker.

**Spec:** `docs/design/3.5-design.md` (approved 2026-11-12, every question decided). It binds over `ROADMAP.md` for 3.5. Read the design sections a task names before starting it. Where it and the merged code differ, "The design against the merged code" below rules, and a task's text already follows those rulings.

## Global Constraints

- Everything in AGENTS.md applies: Lua as the only source of values, `send_param_to_engine` and `S.engine_senders`, replace-never-stack, `sendToSynth` for every synth that can end on its own, `openedGate`, `startPlacedGrainSynth`, one persistent stage per voice, no `LocalBuf`, the command table, the registries, `request_redraw()`, bounds checks, a cleanup step for every clock and handler, the locals probe (30 free locals per main chunk and constructor), the data files rule (`S.lib.data_files.write` and `read` only).
- **No package edits `lib/Engine_Strata.sc`, `init` or `cleanup()`.** Extension files add methods only, never variables; the new area's state lives in `areaState[\notes]`. The new engine file needs the norns restart note in 0b's changelog fragment.
- **Four new commands, exactly:** `noteOn(voice, slot, note, freq, rate, velocity)` `"iiffff"`; `noteOff(voice, slot, cut)` `"iii"`; `noteExpression(voice, slot, bend, amp, position, size, main)` `"iifffff"`; `setNotePool(size)` `"i"`. No other command, poll or signature changes. Engine slots are 0-7: 0 the voice's own note, 1-7 the extra ones. Lua's are 1-8 and it passes `slot - 1`.
- **Clips and ranges:** `note` 0-127, `freq` 8-20000, `rate` 0.25-4, `velocity` 0-1, `cut` 0 or 1, `bend` 0.0625-16, `amp` 0-2, `position`, `size` and `main` -1..1, `size` (the pool) 0-`notePoolMax`. An out-of-range index or a non-finite value is ignored with one console line (`strata: <command> ignored: <why>`), as 3.4's five commands do.
- **Constants** (`lib/constants.lua`; each a field of the returned table, never a new local): `NOTE_SLOTS` 8, `NOTE_POOL = {max = 16, standard = 4, high = 8}`. The engine mirrors `noteSlots` 8 and `notePoolMax` 16, and holds `noteLag` 0.02. `FAST_MOD_NOTE_SLOTS` stays 1 and nothing in `lib/engine/StrataModulation.sc` changes but the two hooks 1a names. A module's own tunables live in its one table (`NOTES`, `MPE`, `EXPRESSION`, `ZONES_EDITOR`).
- **The pool's maximum follows 0b's measurement.** If the arithmetic of design §1, redone from the measured voice SynthDef sizes, leaves less than 1280 KB on high with the pool full, the controller sets `NOTE_POOL.max` and `notePoolMax` to 12 in one commit before Wave 1 starts, and every later "16" in this plan reads 12.
- **Real-time memory floors:** 3.4's stay with the pool empty (3 MB on standard and 3.5 MB on high at every existing case, 3 MB with eight recordings, each grain SynthDef under 88 KB, each stage under 42 KB). With the pool full, 1280 KB (five 256 KB probes) on both tiers.
- **Bounds the engine holds whatever Lua sends:** no slot has two live synths; live and releasing extra notes never exceed the pool; cutting note synths never exceed one per slot, nor the pool in all.
- **Message bounds:** at most 16 `noteExpression` per 48 Hz step (`NOTES.sends_per_step`), a note's newest values once; a note's first expression goes at once, before its `noteOn`. Note sends are counted in the engine budget's window through `count_sends` and never deferred.
- **3.4's sound by default.** A voice whose `note_cap` is 1, or a pool of 0, plays every note as 3.4 does, message for message. With every per-note control at its default each SynthDef plays 3.4's values within 1e-6. Expression mappings change nothing until a controller sends pressure or slide. A 3.4 scene recalls the same sound; a 3.4 PSET loads with every new param at its default and `PSET_FORMAT` stays 2.
- **Scenes:** `SCENE_DATA_VERSION` 7 (2c sets it). Every migration is registered with `before_version = 7` and is idempotent, so Wave 2's packages land in any order. Extra notes, the pool, the freeze reference and expression values are never in a scene or a PSET.

## Review Focus

The inputs the design implies but none of its tests exercise, most likely to bite a player first. Each line's test is in the task that owns the code.

1. **A note off that never comes.** The controller is unplugged, the port or the channel mode changes, a zone's member count changes, or a panic arrives while chords are held or latched: every held MIDI note is released and its pool slot freed, so the pool never fills with notes no key can end. Test in 2b (`"a port change, an unplug, a mode change and a panic release every MIDI note and empty the pool's count"`).
2. **A voice stopped under its notes.** The norns, a grid, a scene recall or a pattern stops a voice whose keys are still down: Lua forgets the voice's notes, the later note offs do nothing, and a new key starts the voice again on slot 1. Test in 1b (`"a voice stopped by anything forgets its notes"`) and 2b (`"note offs for a stopped voice's forgotten notes send nothing"`).
3. **Lua and the engine disagreeing about a slot.** A note's start fails for want of memory, or the engine trimmed a tail: `noteOn` on a slot the engine holds empty starts it, `noteOff` on an empty slot does nothing, and neither posts an error, so the two sides heal at the next note. Test in 2a (`"notes: noteOn on a slot whose start failed starts it, and noteOff on an empty slot is silent"`).
4. **A flood of expression.** Sixteen notes each sending bend, pressure and slide a thousand times a second: at most 16 sends a step, every note served within two steps, each with its newest values, and a note that ended meanwhile sends nothing. Test in 1b (`"the flush sends at most 16 a step, newest values, no note starved, none for an ended note"`).
5. **An MPE controller that is not set up as Strata is.** Notes on a channel outside both zones, a data entry (CC6) with no RPN selected or another RPN selected, a CC87 never followed by pressure or CC74, a member count that shrinks under held notes: nothing is misread, and the notes outside the zone are ignored. Test in 1c (`"a data entry changes a setting only under RPN 0 or 6"`, `"a note outside both zones has no target"`, `"a stale CC87 never reaches a later message on another channel"`).

## The design against the merged code

The design cites `main` at de555c09. These rulings fix what a planner would otherwise guess.

1. **Where a voice stops.** The script sends `engine.voiceOff` in three places, all in `lib/engine_sync.lua` (`:500` `toggle_voice`, `:655` a start that failed, `:672` the stop of every voice). 0a's voice-stop registry runs after each.
2. **The freeze param's action.** `v<i>_freeze` is added in `lib/freeze.lua`'s record (`add_voice_extra`, a `binary` param whose own action is `function() grid_redraw() end`). 0a's one line goes in that action, which runs after the value is stored and sent, so the hooks run with the engine already frozen or unfrozen.
3. **The LFO clock's hook exists:** `S.lib.lfos.on_step(fn)` (`lib/lfos.lua:373`). Hooks run in registration order after the LFOs; the note flush and the expression module's voice-wide step are two hooks, the note flush registered second (its module is included first, so 1b registers it from its start step, not at include time, to run after 2c's).
4. **The park must start open.** Design §3.2's second envelope is 1 from a synth's first sample while `noteGate` is 1 (for example `Env([1, 1, 0], [attackTime, releaseTime], releaseNode: 1)`), or every note would start through two attacks and no def would play 3.4's values. The 1e-6 checks hold it.
5. **`voiceLevel` is the stage's too** (`lib/engine/StrataMix.sc:54-56`) and is not edited: a voice def passes `amp * noteAmp.lag(noteLag)` as its `amp`.
6. **Voice freq range.** `v<i>_freq` is 20-2000 Hz (`lib/params_setup.lua:1189`); `note_values` clamps to the voice's `param_range`, and the engine's wider clip (8-20000) only bounds a bad value.
7. **The expression controls' ranges** come from `VOICE_PARAM_SPECS` (`lib/params_setup.lua:1188-1210`): `rq` 0.01-1, `index` 0-10, `fold` 0.1-5, `drift` 0.001-0.1, `width` 0.05-0.95, `decay` 0.5-10, `ratio` 0.5-8.
8. **`midi_note_off` stops any voice.** Today's `voice off` stops a voice at its last released note whoever started it (`lib/midi_in.lua:229-234`); release mode keeps that.
9. **The MIDI option lists live in `lib/midi_in.lua`** (`M.MIDI.channel_mode_options`, `:20-21`), so 2b extends them, not 1c; until 2b lands the MPE modes cannot be chosen and 1c's `active()` is false.
10. **SETUP's tests pin field positions** (`test/unit/pages_setup_test.lua:17-42`, the layout states' `enc(2, 7)` and `enc(2, 9)`). 2f inserts three rows after `channels` and moves every pinned index by 3.
11. **The engine stub needs each literal it checks against.** `engine_spec_from_source` (`test/norns_stubs.lua:419-420`) reads `name { ^N }` methods; 0b adds `noteSlots` and `notePoolMax` there and to `engine_spec_problems`.
12. **The page render script fails on this machine's Pillow** (#665). 0c fixes it in Wave 0, so every UI package can look at its renders.
13. **`docs/notes/lua/pages/main.md:5`** gives the widest list entry as 59 px; it is 49 (#666). 0c corrects it, and 2f's count relies on the 11 px.

## How to read the tests

**All three checks** means `lua test/run.lua`, `luajit test/run.lua` and `lua test/sync_check.lua`, from the worktree root, each exiting 0.

**Test shorthand.** A Lua test block gives each test's name and its assertions in comments; the implementer writes the setup and the `h.` calls. `a -> b` and `a == b` are `assert_equal(a, b)` (a number marked `(near tol)` is `assert_near`); `f() -> g(1)` means calling `f` sends `g(1)` (`context.calls_named`); `;` starts the next case on the same setup. Engine calls are written with the engine's 0-indexed voice and slot. Every number in a comment is an exact value of the design or of a stub's arithmetic.

**Lua.** Tests live in `test/unit/<module>_test.lua`, each `return function(h) ... end`, with `test`, `assert_equal`, `assert_true`, `assert_near`, `load_strata`, `local_value`, `show_page`, `tap`, `hint_text`, `screen_shows`, `assert_screen_layout` from `h`; `S` is `local_value("S")`. MIDI goes in through `context.midi.plug` and the vport's `event`, as `test/unit/midi_in_test.lua` does today.

**Engine check.** Each area is `test/engine_check/<area>.scd`, returning `{ arg h; ... }`; `h.check(condition, "area: message")` counts a failure, and the assertion messages below are the check names. Audio comparisons run on the server (a check synth writes `Peak` of the difference to a control bus), never in sclang (#131). Run one area with `STRATA_ENGINE_CHECK_AREAS=notes STRATA_SC_PORT=<port> test/run_engine_check.sh`.
