# BUFFER

Where the eight sample buffers are recorded, filled, cleared and saved, where a buffer's waveform and the voices playing it show, and where the selected voice's source is chosen, so it all works without a grid. Back to [Screen Controls](../controls.md).

**Left column.** Eleven fields, four at a time (the list scrolls as the field cursor moves; a brighter mark on the dividing line shows where you are). A small `>` marks the field E3 edits:
- `v1`...`v7`: the selected voice (picked on MAIN) and its source: `synth`, `buf 1` ... `buf 8` or `input`.
- `rec`: what a recording takes: the input (`in`), the master before its effects (`pre`) or after them (`post`, Strata's own output only), or one voice (`v1`-`v7`).
- `dur`: the record duration, up to the buffer length (16 s, or up to 300 s on the high tier). With sync on it becomes `len`, the length in beats (`16b`); when that many beats would not fit in a buffer at the current tempo it shows how many do, with `max` (`8b max`; `<1b max` when not even one beat fits).
- `lvl`: the record level.
- `fb`: the record feedback: 0% replaces what the buffer held; above 0 the buffer keeps playing while it records, and each pass keeps the old audio at that level (an overdub).
- `loop`: `on` records over and over the first `dur` seconds until you stop it.
- `thr`: `off`, or a level (`-24dB`) the source must reach before the recording starts (it keeps the 10 ms before).
- `sync`: `off`, or start on the next `beat` or `bar` of the clock.
- `bm`: the selected voice's bookmark and its position (`2 0.25`). E3 steps through bookmarks 1-4 and jumps the voice to each one it lands on. Dim when the voice is not playing a buffer.
- `start`: for a file longer than a buffer, how far into the file the buffer starts; `-` when the file fits. It shows hundredths below 10 s (`9.05s`), tenths from 10 s (`12.1s`), whole seconds from 100 s (`123s`), minutes and seconds from 1000 s (`20:34`), then whole minutes (`123m`) and hours (`17h`) for very long files. ALT+E3 moves it by the last digit shown, E3 by that or a tenth of a second, whichever is more; the file reloads from there a moment after you stop turning.
- `fric`: the arc scrub's friction: 100% stops where you let go; lower lets a fling glide on and slow down.

Settings beside the fields are also in PARAMETERS > record and > positions. Below the fields, `in` is a meter of the live input: eight segments, about 6 dB each from -48 dB, showing the louder of the two channels; the highest segment reached stays lit for 1 s. The meter runs only while this page shows.

**Right column.** At the top, the waveform of the buffer under the cursor: brighter inside the selected voice's loop when that voice plays this buffer, a flat dim line when the buffer is empty. Over it, a line for each running voice playing the buffer at the place its grains start (the selected voice's brightest), with a short line under the waveform for the width its grains spread over; while the buffer records without emptying, a dotted line shows where the recording writes. Under the waveform, small ticks mark the selected voice's four bookmarks (the last one recalled brighter).

Below, the eight buffers, three at a time (the list scrolls as the cursor moves; a thin bar at the right edge shows where you are). Each row shows the buffer's number, its name (the file name, shortened, or `take <n>` for a recording; `-` when the buffer is empty) and its length: in seconds below a minute (`16.5s`), in minutes and seconds from a minute on (`1:05`, up to `5:00` on the high tier). While it records, the length gives way to the recording's state: `ARM` while it waits for a beat, a bar or a level, `REC` for a take that replaces the buffer, `DUB` for an overdub, `LOOP` for a loop recording. An empty buffer shows no length. The row under the cursor is bright and also lists the voices playing that buffer (`v2 v6`; `+` when more do than fit). Buffers holding audio are mid, empty ones dim.

A take shows `REC` until the engine reports what it captured (a moment after the recording ends): then it becomes `take <n>`, or `-` if nothing was captured (a stop right after the start; a take or file the engine reports late, such as a slow read at start, is still picked up, unless the buffer was cleared, loaded or recorded into meanwhile). A loaded file shows its name at once. On the high tier a file longer than 16 s is checked first, which can take a few seconds on the norns: meanwhile the buffer keeps playing what it held, its row shows the new name with `...` for the length, and the new length shows once the file is in (if the engine never reports it, the row goes back to what the buffer held after 30 s). If the file cannot be loaded (missing, unreadable, an unsupported format, empty, or damaged so that it stops decoding part way), the buffer goes back to what it held before (the earlier file and its audio, or empty; if the file disappears in the moment between the checks and the read, as when a drive is unplugged, the buffer is left empty), the hint row shows `buf <n> load failed` for 1.5 s, and the file is not reloaded at the next start.

K2, ALT+K2 and ALT+K3 act when released: let go within half a second for the first action, hold them half a second or more for the second.

- **E2** - Move the cursor to a buffer (1-8). It stays there when you change pages
- **ALT+E2** - Move the field cursor
- **E3** - Change the field under the field cursor (ALT+E3 in finer steps)
- **K3** - Record into the buffer under the cursor with the record settings, whether or not a voice plays it; press again to stop early and keep what was captured, or, while it waits to start (`ARM`), to cancel it. A take (feedback 0, loop off) silences the voices playing that buffer until it is done; an overdub or loop recording keeps them playing. The arc's button does the same
- **K2** - Load a sound file into the buffer under the cursor: released quickly it opens the file browser at `~/dust/audio`; held, it loads a random sound file from the folder of the buffer's file (else the folder you last chose a file from, else `~/dust/audio`) and the hint row shows `buf <n>: <name>` (`no files in <folder>` when the folder holds no sound file, `cannot open <folder>` when it cannot be opened)
- **ALT+K2** - Released quickly, clear the buffer under the cursor; held, fill every empty buffer with a different random file from the folder of the buffer under the cursor (`filled <k> slots`, or `no files in <folder>` / `cannot open <folder>` as for K2). It never opens the file browser, even if K1 is let go before K2
- **ALT+K3** - Released quickly, save the buffer under the cursor to `~/dust/audio/strata/<date-time>-buf<n>.wav`; held, save only the selected voice's loop region of it to `<date-time>-buf<n>-loop.wav` (trim; the buffer is left as it is). For 1.5 s the hint row shows `saving buf <n>` (`saving buf <n> loop`), then, once the file is written, `saved buf <n>` (`saved buf <n> loop`), or `buf <n> save failed` when it could not be written (a full card, a folder that cannot be made: a file already there is kept). It shows `buf <n> busy` while the buffer is recording or waiting for its take, or `buf <n> empty` when the buffer holds no audio; nothing is saved in those two cases
- While K2, ALT+K2 or ALT+K3 is held, the hint row names what letting go will do, and changes after half a second: `K2 up: load` then `K2 up: random`; `K2 up: clear` then `K2 up: fill`; `K3 up: save` then `K3 up: save loop`
- Otherwise the hint row reads `K2:ld/rnd K3:rec` (`K3:stop` while the buffer under the cursor records or waits to, `K3:...` while a take that has ended waits for the engine; K3 does nothing then). With K1 (ALT) held it reads `K2:clr/fill K3:sv/trim`

The arc's rings on this page are described in [Arc](../arc.md). Buffers, recording, saving and restoring are described in [Audio Sources and Buffers](../sources-and-buffers.md).
