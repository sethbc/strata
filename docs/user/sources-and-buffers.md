# Audio Sources and Buffers

Granulating a sample buffer or the live input instead of a voice's synth, and how buffers are saved and restored. Back to the [README](../../README.md).

Every voice can grain something other than its own synth. Its **source** (the BUFFER screen page, grid page 4, or PARAMETERS > the voice's granular section) is its synth (the default), one of eight sample buffers (`buf 1` to `buf 8`), or the live stereo input:
- **Buffers** hold up to 16 seconds of stereo audio each, or up to 300 on the high tier ([Performance tiers](technical.md#performance-tiers)), at the norns sample rate of 48 kHz: a file at a higher rate keeps fewer seconds (8 of 16 for a 96 kHz file). Load a sound file, record the input, clear or save a buffer from the BUFFER screen page, grid page 4 (record and clear) or the PARAMETERS **buffers** group. The BUFFER page's input meter shows the level going in before you record
- **Buffer position** (0-1 of the buffer's recorded or loaded length), **buffer rate** (0.25x-4x playback speed) and **buffer scan** (moves the position through the buffer, in buffer lengths per second, backwards when negative; 0 = static) shape a buffer-sourced voice. Grain size, density, pitch, spread, envelope and mode work as for synth voices
- **Loop start** (0-1) and **loop length** (0.001-1), fractions of the buffer's recorded or loaded length, set the part of the buffer a voice plays: its grains start inside the loop, and buffer position, scan and spread move through the loop instead of the whole buffer, wrapping at its end (so scan 1 crosses the loop once a second). The default, start 0 and length 1, is the whole buffer, as before 3.2. A grain is never cut short: it may play on past the loop's end, but never past the end of the recording, so a loop at the very end or shorter than a grain starts its grains as late as they still fit. Loop start stops at 0.999, and the length at what is left after the start (moving the start later shortens a length that no longer fits; moving it back does not lengthen it again). Both are on the VOICE page, at the end of a buffer voice's first section (after position, rate and scan), and in PARAMETERS under the voice's extras. Scenes store them and fade them (a scene file edited by hand with a length longer than its start leaves room for is shortened to fit when it loads); randomize, mutations and the grid's fader page leave them alone
- While a voice's source is a buffer, E3, arc ring 2 and the MAIN screen show its buffer position (`pos`), the grid fader page shows its buffer position, rate, scan, level and pan instead of the synthesis parameters (when a grain is as long as the sample at its rate, every grain plays the whole sample, so position and scan do nothing), ALT+K2 (randomize) changes the buffer parameters (and grain size and pitch) instead of the synthesis parameters, mutations change the buffer parameters, and the position drifts subtly around the value you set
- Cross-modulation works for every source: buffer- and input-sourced voices take amplitude modulation, and frequency modulation moves their grains' pitch (it is each grain's playback rate), as pitchbend does
- While a voice's source is the input, its synthesis parameters (except level and pan) do nothing, and of its buffer parameters only buffer scan does anything, and only while the voice is frozen: it moves the grains through the frozen 4 seconds, as for a synth voice ([Freeze](pages/voice.md#freeze)). So E3, arc ring 2 and the MAIN screen show its grain size (`size`), the grid fader page starts with the grain parameters (then level and pan), and ALT+K2, mutations and the drift change only the grain parameters
- The source itself is never randomized or mutated, and lock keeps the buffer parameters still
- Several voices can read the same buffer, and any voice can be switched back to its synth at any time

## Recording

Record the live input, the master or a single voice into a buffer ([Record group](params.md#record-group)). With feedback 0 and loop off, a recording is a **take**: it replaces the buffer, which is silent until the take ends. With feedback above 0 or loop on it is a **playable recording**: the buffer keeps playing while it records, its length becomes the longer of its own and the recording's, and each frame keeps the old audio times the feedback; when it ends, the buffer is `take <n>`. A recording into a buffer loaded from a file at another sample rate is a take (the buffer page says `replaced (rate)`). A recording that waits for a beat, a bar or a level shows `ARM` until it starts. Post-master is Strata's own output after its effects; norns' monitor, softcut and TAPE are mixed outside SuperCollider and are not recorded.

## Saving and restoring buffers

Strata writes audio to disk only when a recording finishes and when you save a buffer (besides the small waveform files, under Files below):
- **Scratch take** - Every finished (or early-stopped) recording is written to `~/dust/audio/strata/scratch/buf<n>.wav`, replacing that buffer's previous take. It exists so the take survives a restart; save the buffer to keep it. When the take cannot be written (a full card, a folder that cannot be made) the BUFFER page shows `buf <n> take not saved` for 1.5 s and the console names the file: the take still plays until the script ends, and ALT+K3 can still save it elsewhere, but it is not restored at the next start (the buffer starts empty, never with an older take under this one's name)
- **Save** - The buffer's save trigger (PARAMETERS > buffers, or ALT+K3 on the BUFFER page) writes a new timestamped file, `~/dust/audio/strata/<date-time>-buf<n>.wav`, which appears in the file browser for loading later. Nothing is overwritten: a second save of the buffer within the same second, or a name a file already has (after the clock was set back), gets a counter, `<date-time>-buf<n>-2.wav`, `-3`, and so on. The console says `saved to <path>` only once the file is written, and `cannot save <path>` when it could not be (the BUFFER page shows the same)
- **Restore on start** - Whenever a buffer's file or start point changes, Strata remembers, for each buffer, the file loaded into it or its scratch take (in `~/dust/data/strata/buffers.data`, a list of paths, not audio). On the next start each remembered file that still exists is loaded again, so scenes that use buffers are not silent after a reboot. A file that is not found (deleted, moved, or on a drive that is not mounted) is skipped and the console names it, but its path is kept for the next start, so the sample comes back once the file is there again; clearing, loading or recording into that buffer forgets it. The SETUP page shows how many buffers were restored (those the engine reports holding audio) and how many remembered files are missing
- A damaged or incompatible `buffers.data` loads nothing, is reported in the console and on SETUP, and is moved to the first free of `buffers.data.bak`, `.bak.2` ... `.bak.9`, so it is not overwritten and an earlier copy is never replaced

## Files

Beyond picking a file by name, a buffer can be filled from a folder, and a file longer than a buffer can be started anywhere:
- **Random file** - Loads a random sound file (`.wav`, `.aif`, `.aiff`, `.flac` or `.ogg`) into a buffer from a folder, never the file it already holds when the folder has another. The folder is the one the buffer's current file is in, else the one you last chose a file from, else `~/dust/audio`; subfolders are not searched. The BUFFER page flashes `buf <n>: <name>`, or `no files in <folder>` when there is nothing to load
- **Fill the empty buffers** - Gives every buffer that is empty (not loaded, recording or armed to record) a different random file from the folder of the buffer under the cursor (never one another buffer already holds), until the files run out; the rest stay empty. The BUFFER page flashes `filled <k> slots` (`filled 1 slot` for one)
- **Start point** - A file longer than a buffer (16 seconds, or up to 300 on the high tier) loads from its beginning. The buffer remembers a start point in seconds, so a long file can be loaded from any later place that still leaves a full buffer of audio. A file above 48 kHz fills a buffer with fewer of its own seconds (8 of 16 for a 96 kHz file), so its start reaches that much further: a 96 kHz file of 12 s has a start point, up to 4 s. Moving the start point reloads the file 0.3 seconds after you stop moving it, so turning through a long file loads once. A new file, a recording or a clear sets the start back to 0, and a start point cannot be moved while the buffer records. The start point is remembered with the file in `buffers.data`, so it comes back on the next start (files remembered by 3.2 load from 0)
- **Save the loop region** - Saves only the loop region of the voice reading the buffer (the selected voice's if it reads this buffer, else the lowest-numbered voice that does, else the whole buffer) to `~/dust/audio/strata/<date-time>-buf<n>-loop.wav` (`-loop-2.wav` and so on for a second save within the same second). The buffer itself is left as it is, and the BUFFER page flashes `saved buf <n> loop` when the file is written
- **Waveform** - The engine keeps a 64-point overview of each buffer's audio, and the BUFFER page and the grid read it to draw the waveform. It is a small text file per buffer, `buf1.peaks` to `buf8.peaks` in `~/dust/data/strata/`, written at each load and take, and while a buffer records without emptying (an overdub or a loop recording) at most every 2 s, only when the overview has changed (a loop recording silence, or one whose waveform has stopped changing, writes nothing more until it ends). So during an overdub or loop recording the waveform updates every 2 s, and is complete again when the recording ends. A recording that makes the buffer longer shows the old audio where it is in the new length and nothing after it. While a file loads, the buffer shows no waveform until the new file's is ready (on the high tier, through a long file's check too); a load that fails brings the old one back with the old file. The files are safe to delete: each is written again at its buffer's next load or recording
