# Audio Sources and Buffers

Granulating a sample buffer or the live input instead of a voice's synth, and how buffers are saved and restored. Back to the [README](../../README.md).

Every voice can grain something other than its own synth. Its **source** (the BUFFER screen page, grid page 4, or PARAMETERS > the voice's granular section) is its synth (the default), one of eight sample buffers (`buf 1` to `buf 8`), or the live stereo input:
- **Buffers** hold up to 16 seconds of stereo audio each, or up to 300 on the high tier ([Performance tiers](technical.md#performance-tiers)), at the norns sample rate of 48 kHz: a file at a higher rate keeps fewer seconds (8 of 16 for a 96 kHz file). Load a sound file, record the input, clear or save a buffer from the BUFFER screen page, grid page 4 (record and clear) or the PARAMETERS **buffers** group. The BUFFER page's input meter shows the level going in before you record
- **Buffer position** (0-1 of the buffer's recorded or loaded length), **buffer rate** (0.25x-4x playback speed) and **buffer scan** (moves the position through the buffer, in buffer lengths per second, backwards when negative; 0 = static) shape a buffer-sourced voice. Grain size, density, pitch, spread, envelope and mode work as for synth voices
- **Loop start** (0-1) and **loop length** (0.001-1), fractions of the buffer's recorded or loaded length, set the part of the buffer a voice plays: its grains start inside the loop, and buffer position, scan and spread move through the loop instead of the whole buffer, wrapping at its end (so scan 1 crosses the loop once a second). The default, start 0 and length 1, is the whole buffer, as before 3.2. A grain is never cut short: it may play on past the loop's end, but never past the end of the recording, so a loop at the very end or shorter than a grain starts its grains as late as they still fit. Loop start stops at 0.999, and the length at what is left after the start (moving the start later shortens a length that no longer fits; moving it back does not lengthen it again). Both are on the VOICE page, at the end of a buffer voice's first section (after position, rate and scan), and in PARAMETERS under the voice's extras. Scenes store them and fade them; randomize, mutations and the grid's fader page leave them alone
- While a voice's source is a buffer, E3, arc ring 2 and the MAIN screen show its buffer position (`pos`), the grid fader page shows its buffer position, rate, scan, level and pan instead of the synthesis parameters (when a grain is as long as the sample at its rate, every grain plays the whole sample, so position and scan do nothing), ALT+K2 (randomize) changes the buffer parameters (and grain size and pitch) instead of the synthesis parameters, mutations change the buffer parameters, and the position drifts subtly around the value you set
- Cross-modulation works for every source: a buffer-sourced voice takes amplitude and rate (frequency) modulation; an input-sourced voice takes amplitude modulation only (frequency modulation means nothing for live input and is ignored)
- While a voice's source is the input, neither its buffer parameters nor its synthesis parameters (except level and pan) do anything, so E3, arc ring 2 and the MAIN screen show its grain size (`size`), the grid fader page starts with the grain parameters (then level and pan), and ALT+K2, mutations and the drift change only the grain parameters
- The source itself is never randomized or mutated, and lock keeps the buffer parameters still
- Several voices can read the same buffer, and any voice can be switched back to its synth at any time

## Saving and restoring buffers

Strata writes audio to disk only when a recording finishes and when you save a buffer:
- **Scratch take** - Every finished (or early-stopped) recording is written to `~/dust/audio/strata/scratch/buf<n>.wav`, replacing that buffer's previous take. It exists so the take survives a restart; save the buffer to keep it
- **Save** - The buffer's save trigger (PARAMETERS > buffers, or ALT+K3 on the BUFFER page) writes a new timestamped file, `~/dust/audio/strata/<date-time>-buf<n>.wav`, which appears in the file browser for loading later. Nothing is overwritten. The console says `saved to <path>` only once the file is written, and `cannot save <path>` when it could not be (the BUFFER page shows the same)
- **Restore on start** - When the script exits it remembers, for each buffer, the file loaded into it or its scratch take (in `~/dust/data/strata/buffers.data`, a list of paths, not audio). On the next start each remembered file that still exists is loaded again, so scenes that use buffers are not silent after a reboot. A file that is not found (deleted, moved, or on a drive that is not mounted) is skipped and the console names it, but its path is kept for the next start, so the sample comes back once the file is there again; clearing, loading or recording into that buffer forgets it. The SETUP page shows how many buffers were restored (those the engine reports holding audio) and how many remembered files are missing
- A damaged or incompatible `buffers.data` loads nothing, is reported in the console and is moved to `buffers.data.bak` so the save on exit does not overwrite it
