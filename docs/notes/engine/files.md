## Must not break

- **Every `readData` reads into a fresh array** (`freshReadArray`), never one an earlier read filled: reusing a `FloatArray` across reads makes sclang 3.13 (norns' version) abort a while later in its garbage collector (#131). This covers `fileDecodes` (each decode chunk) and `interleaveFiles` (each left and right chunk). A structure test checks every `readData` in the engine.
- **No sclang function per sample** in the engine's sample paths (the interleave, the decode check): sclang's collector fails under millions of small allocations (below, sclang's garbage collector under heavy allocation). This is a platform limit (#131): norns' 3.13 overflows the collector's int32 scan count, and 3.14.1 has crashed the same way too. No `do`, `collect`, `fill` or function call per sample or frame: build and convert sample arrays with C primitives (Signal arithmetic and `clip`, `at` with an index Array, which returns an Array, `putEach` with Array keys and values, never a FloatArray or Signal there, which it misreads, `copySeries`, the `(a, b .. c)` series). `interleaveChunk` clips and interleaves with C primitives only; a structure test checks it, `interleaveKeys`, `fileDecodes` and the interleave's chunk loop (in `lib/engine/StrataFiles.sc`). Saved files stay byte for byte what the old per-frame loop wrote.
- **No List or Array that grows without bound in code that runs while a long save or load allocates** (an OSC responder, a polling loop, a chunk loop). A List grown past 128 entries inside the check's `/poll/value` responder during the 300 s soak corrupted sclang 3.13's collector every time (a failed count assertion) (below); make such a List with room for all it will hold (`List.new(n)`), as the runner's `pollListCapacity` does, or bound it. The engine keeps none today: its per-slot and per-voice tables are fixed-size, and its sets hold only live synths.
- **File writes** go to a private sibling `.part` and are renamed into place. A WAV includes a per-engine random nonce in its token. Never open the final path for writing. The newest write to a path wins, and two writes never mix.
- `deleteStaleParts` deletes only `.part` files and `writeSlot`'s temporary float files older than `stalePartAge`, and only in absolute directories below the root (`stalePartDirs`: `scratchDir`, its parent and the settings folder the performance area used). The mover's FIFO (`strata-peaks-mover.<instanceTag>.part`) and its acknowledgment and failure files (`<path>.<instanceTag>-<generation>.ack.part` and `.fail.part`, `docs/notes/engine/waveform.md`) are named to match, so ones a crash left go too; the FIFO's name never stays once the mover runs.
- A write clips samples beyond ±1 symmetrically to ±`int16Peak`, never wraps.
- **A save or scratch take gives its part to the FIFO mover on the healthy path** (#217). Before replacing an overdue writer, remove its unique same-directory source or establish that its rename already consumed it. A failed inspection or removal refuses the replacement. Engine free retires preparations and handed-off writers. A successor recovers a remaining writer from its receipt (#1069, File writes below).
- Peaks files use the same receipt, token serial, source revocation, mover and bounded fallback capacity as WAVs. `publishAnalysisPart` writes its unique sibling part synchronously and delivers its result to the owner. A successful sidecar claim also cancels an older WAV preparation for the same canonical path before that preparation can publish. Revoking a live, unconsumed analysis part runs its supersession callback. Free suppresses retired callbacks.
- `pathRenames` also orders the onsets pass's renames of `buf<n>.onsets` (`writeOnsetsFile`, keyed by the pass's count, #963, `docs/notes/engine/onsets.md`); it holds only renames under way, whoever started them.
- A write whose temporary files hold fewer frames than the slot's valid length, or whose output reads back short (a full disk), fails: nothing is renamed, the file already at the path stays, the `.part` is deleted and `strata: cannot write <path> (...)` is posted.
- Every completed write sends one initial `bufferSaveResult` report, written only once the file is in place (after the rename), failed otherwise; a superseded tagged request reports failure once, and legacy saves and scratch takes abandon silently. Lua confirms a tagged save only from its own terminal receipt (#127, #1091).
- Every scratch take whose write ends unwritten is reported exactly once on `takeWriteFailed` (`record_number * numBuffers + slot index`, #312), when the write ends: never held up for the write, `ended` comes first. A written take reports nothing, so Lua keeps the scratch path only for a take whose file is in place or still being written.
- A write's routine runs inside `try`: an sclang error in it is posted as `strata: cannot write <path> (<error class>)` (never with the word the engine check fails on), closes every sound file the interleave opened (each close in its own `try`), deletes its temporary and `.part` files and, if it is still the newest write, removes its `writeGenerations` entry and reports failed. A folder at the path fails the write before the rename (`mv -f` would move the file into it).
- The engine check never writes into `~/dust`: it points `scratchDir` at a temporary directory.
- A chunk loop in a routine (the interleave, a long file's decode check) waits through `yieldToCommands`, never a plain `wait`: a routine whose chunks outlast its waits falls behind its logical time, and SystemClock then runs it again at once without releasing sclang's lock, so every OSC message (matron's commands) waits until the loop ends.

## File writes

`writeSlot(index, path, done)` (scratch takes and `saveBuffer`) has the server write each mono buffer's valid frames to a temporary float file, then sclang interleaves them in 8192-frame chunks (`interleaveChunk`, C primitives only: below; yielding `writeChunkWait`, 1 ms, between chunks through `yieldToCommands`) into a stereo 16-bit WAV at the content's rate and deletes the temporaries; it creates no synth nodes. The buffers are float and `record_level` goes to 2, so a take can hold samples beyond ±1: the interleave clips every sample to ±`int16Peak` (32767 / 32768), so the file is clipped deliberately and symmetrically (+32767 / -32767) whatever libsndfile's own float-to-int conversion does (without its clipping mode it wraps; with it, it clips to +32767 / -32768).

Each WAV preparation gets a generation in `writeGenerations[path]`. A superseded routine stops after its next yield, closes its files and deletes its private temporaries. The part sits beside its destination. Its name includes the instance, generation and 128 bits from `/dev/urandom` at engine allocation. Both OS carriers receive that same source pathname. On Linux both use `mv -fT`, so a destination that became a directory fails the rename. Directory aliases share a canonical parent. Before creating directories, the writer walks existing links and parent components so a missing directory cannot hide a private pathname. A public save refuses the private receipt directory, generated part and marker names, FIFO names and the engine’s temporary float filenames in the system temp directory before it can write them.

Once the bytes are ready, the candidate gives the incumbent twice `peaksMoverTimeout` to finish normally. At expiry, or when a fresh engine finds an old receipt, `retireWavPublication` reads the token from `.strata-wav-writers/<filename>` in the destination directory. A successful POSIX `unlink` of the old source revokes both OS carriers. If the rename won the race, the source is already absent and the completed live write reports once before its successor. The carrier preserves the source on a failed rename until the language decides its result. A malformed receipt, a file inspection error, or a source still present after removal blocks the replacement. Stale cleanup keeps the exact token named by a readable receipt. An inaccessible or malformed receipt preserves the candidate for later inspection. Only after retirement does the candidate create its own receipt with exclusive creation, verify its contents and hand the part to the mover. A late callback can finish only its own publication record. The receipt goes after completion and its directory goes when empty.

A single sclang admits up to 16 WAV preparations, 16 WAV entries waiting for their FIFO acknowledgment across all engines (four per mover), and 16 fallback children. The counters include superseded routines and children until they actually end. A synchronous exception in the second buffer send still drains the first accepted server write and removes its temporary. An excess preparation or a write needing an unavailable fallback with no live FIFO carrier reports failure and preserves the file. An already queued rename can still complete through the mover. Each destination has one current preparation and one handed-off publication. The limits bound the temporaries of canceled preparations until their next yield. Engine free cancels outstanding preparation, retires each publication and suppresses callbacks into the retired engine. If removal fails or sclang exits abruptly, a receipt keeps the old source discoverable for the next save. This ordering assumes one active norns sclang owner. Power-loss persistence is outside the guarantee.

`alloc` calls `deleteStaleParts`, which deletes the `*.part` files a crash left in `scratchDir` (scratch takes) and in its parent (`saveBuffer`'s `<date>-buf<n>.wav.<tag>-<gen>.part` in `_path.audio/strata/`, visible in the file browser), and `writeSlot`'s temporary float files (`strata-buf*-*.wav`) in `Platform.defaultTempDir`; nothing else, and only unclaimed files last modified more than `stalePartAge` (60 s) ago (`File.mtime` against `Date.getDate.rawSeconds`). `File.mtime` throws for a file deleted since the glob, so it is wrapped in `try`: such a file is skipped silently, while one that is still there (or whose existence cannot be read either: a directory without search permission makes `File.exists` throw too) is left and posted (`strata: cannot read when <path> was last written`); `deleteStaleParts` returns those paths. A temporary float file is written just before its interleave opens it, and deleting an open file does not stop it being read, so the age check also keeps a running write's files: after a script reload in the same sclang session the previous instance's write routine may still be interleaving, and a running write touches its `.part` with every chunk. `stalePartDirs` picks the directories: `scratchDir` (with `~` expanded, trailing slash dropped), its `dirname` and the settings folder the performance area used at alloc (`allocSettingsDirectory`: `settingsDir`, or `~/dust/data/strata/`, where a crash can leave `performance_active.data.<tag>-<gen>.part` or Lua's `performance.data.part`), each listed once, keeping only absolute paths below the root, so an empty, relative (`"."`, `"scratch/"`, whose `dirname` is `"."`) or root `scratchDir` never globs the working directory or `/` (never `standardizePath` it: that turns `"."` into the working directory). `test/run_engine_check.sh` starts sclang in its temp dir, so the check's working-directory marker never lands in the caller's directory. Never open the final path directly for writing: `SoundFile.openWrite` truncates it, and libsndfile rewrites the header on `close`. The engine check sets `writeChunkWait` to 0.02 s so the overlap is certain.

**Scratch directory**: `scratchDir` (engine variable, settable) defaults to `Platform.userHomeDir +/+ "dust/audio/strata/scratch/"`, which equals Lua's `_path.audio .. "strata/scratch/"` on norns; it is created on demand before writing. `test/engine_check.scd` points it at a temporary directory so the check never writes into `~/dust`.

**Yielding to commands.** `yieldToCommands(wait)` waits `wait.max((Main.elapsedTime - thisThread.seconds) + commandGap)`: `wait` from the routine's logical time when it is on time (as a plain wait would), and otherwise until `commandGap` (0.2 ms) of real time from now. Measured with sclang 3.14: a `SystemClock` routine doing 20 ms of work per chunk with a plain `0.001.wait` let no OSC message in for its whole 2 s (the scheduler's batch reruns a task due in the past without releasing the language lock), while the same loop waking in the real future let every message in within one chunk. The interleave's old plain `writeChunkWait.wait` had that fault whenever a chunk took more than 1 ms (any long save on a Pi). The engine check sets `writeChunkWait` to 0.1 ms during a 60 s save and requires a message sent meanwhile to be handled before the save ends.

**Short writes.** `interleaveFiles(sourcePaths, path, sampleRate, keepGoing, frames)` compares each temporary file's `numFrames` with the slot's `frames` before opening the output (the server's `/b_write` stops short when the disk fills; a 300 s save needs about 115 MB of temporaries) and reads the finished `.part` back for its frame count. Either shortfall returns false, so `writeSlot` deletes the `.part` and keeps the old file, and posts `strata: cannot write <path> (a temporary file holds n of m frames: is the disk full?)` or `(n of m frames written: ...)`, as any failed write posts `cannot write`. A failed save is reported to Lua (below). The engine check simulates a short temporary file by giving a slot more valid frames than its buffers hold (`/b_write` clips to the buffer's end).

**Long saves** (high tier). The interleave is the same `interleaveChunk`. The temporary float files are one mono file per channel: for 300 s, 300 x 48000 x 4 bytes = 57.6 MB each, 115 MB per save, in `Platform.defaultTempDir`. Measured on a desktop (sclang 3.14): a 60 s save takes about 0.4 s, a 300 s save about 1.9 s (1758 chunks; with `writeChunkWait` 1 ms most of that is waiting, since each chunk takes under 1 ms there), a 300 s load about 0.4-0.65 s. The 300 s save time on a Pi 4 is on the 3.2 hardware list: above 10 s, the follow-up is to write the temporaries as `int16` (half the data) or to use `sox -M` when it is on the path, keeping this loop as the fallback, under the same `.part` and generation rules.

### Measuring save latency on norns (#1276)

Use one physical standard-tier and one physical high-tier norns. Record the board, active tier and buffer duration from SETUP, firmware, Strata revision, audio storage and JACK period. Use the same 48 kHz stereo 16-bit PCM source in slots 1–4, 16 seconds on standard and 60 seconds on high. Keep the same playing scene, active voices, sequencer and modulation throughout each board’s comparison. Stay on a script page because the norns home statistics screen consumes matron’s JACK xrun counter. Let earlier loads and writes finish. A four-writer trial creates about 12.3 MB on standard or 46.1 MB on high. Copy or remove the trial outputs between runs as needed.

1. In Maiden’s SuperCollider REPL install the localhost echo responder. Read back the engine’s wait after setting each trial condition.

   ```supercollider
   OSCdef(\strataSaveBench, { |msg, time, addr| if (addr.ip == "127.0.0.1") { NetAddr("127.0.0.1", 10111).sendMsg('/strata/check/save/pong', msg[1], msg[2]) } }, '/strata/check/save/ping');
   Crone.engine.writeChunkWait = 0.001; Crone.engine.writeChunkWait.postln;
   ```

2. In Maiden’s matron REPL load the measurement helper and run one batch. It invokes the regular Lua save command on slots 1 through the requested writer count and sends a localhost OSC probe about every 10 ms while receipts are pending. Wait for the output rows before starting another batch.

   ```lua
   save_trial = dofile(_path.code .. "strata/test/hardware/save_latency.lua")
   save_trial(1)
   ```

3. Measure writer counts 1, 2, 3 and 4 at both waits. Set `Crone.engine.writeChunkWait = 0` in Maiden SC to try the existing 0.2 ms real-time floor. Alternate baseline and candidate order across repeats; collect at least five matched pairs per count. Keep the printed tier, count, actual wait, per-slot receipt delays, observed maximum clock gap, OSC replies/losses and p99/max RTT, xrun count, paths and frame counts. Each receipt delay is an upper bound from immediately before sending to the next observation of Lua having consumed the receipt. The printed maximum observation gap bounds this polling uncertainty. For PCM validation, run this on the saved WAVs from each matched pair on a workstation. Their hashes must agree.

   ```sh
   python3 - baseline.wav candidate.wav <<'PYTHON'
   import hashlib, sys, wave
   for path in sys.argv[1:]:
       digest = hashlib.sha256()
       with wave.open(path, 'rb') as wav:
           for block in iter(lambda: wav.readframes(8192), b''):
               digest.update(block)
       print(digest.hexdigest(), path)
   PYTHON
   ```

   Pool the printed RTT samples across repeats of each board/count/wait until there are at least 100 replies for p99. Keep trials with lost probes, failed saves, or timeouts in the results.
4. Restore `Crone.engine.writeChunkWait = 0.001`, free the echo with `OSCdef(\strataSaveBench).free`, and release `save_trial` in matron. The shipped default remains 1 ms. Consider shortening it only if both physical tiers consistently complete the saves sooner under the same load, every paired output matches, and the candidate introduces neither underruns nor worse OSC tails or losses beyond baseline variation. Retain the per-chunk cancellation check and real-time yield floor. Desktop interleave timing alone does not meet this check.

**The region** (3.3): `saveBuffer` takes `"isff"`, `saveSlot(index, path, start = 0, length = 1)` and `writeSlot(index, path, done, start = 0, length = 1)` carry `start` and `length` (fractions of the valid region V). The write takes frames `[start × V, (start + length) × V)`, each end rounded to a frame and clipped to V, through `Buffer.write`'s `startFrame` and `numFrames`, under the same `.part`, generation and short-write rules (`interleaveFiles`' `frames` is the region's length). A region of less than one frame writes nothing, posts why and calls `done` with false, so `saveSlot` reports `failed` on `bufferSaveResult`. A scratch take always writes the whole slot.

**Save results** (`bufferSaveResult`, #127). The files area owns `saveBuffer` (`addFileCommands`) and its poll. `saveSlot(index, path)` ignores a slot out of range, counts the slot's saves in `bufferSaves` (`areaState[\files][\saves]`, from 1 at alloc, including direct and Lua-tagged saves) and calls `writeSlot` with a `done` function. `writeSlot` calls `done.value(written)` exactly once when a write ends (through `finish`, guarded by a `reported` flag): false at once for an empty slot (`frames < 1`); in the write's routine, only while it is still the newest write for its path (`current`), true once the `mv -f` succeeded (the carrier acknowledgment, or an old source already installed when its successor retires it) and false when the interleave failed (a folder that cannot be made, a short temporary file or output), a folder is at the path (`PathName(path).isFolder`: `mv -f` would move the file into it and succeed) or the rename failed (the mover's failure file, or the fallback's exit code). The routine's body is wrapped in `try`: an sclang error anywhere in it (a read, a delete, the interleave) is posted as `strata: cannot write <path> (<error class>)`, closes every sound file the interleave had opened (`interleaveFiles` adds the sources, the output and the read-back file to the routine's `openFiles` list; each close that is still needed runs in its own `try`, so a close that fails never skips the report), deletes the temporary float files and the `.part`, and, only if the write is still the newest for its path, removes its `writeGenerations` entry and reports failed, so a save never waits forever for its report. The engine check injects such an error through `interleaveFaultHook` (`areaState[\files][\interleaveFaultHook]`, nil on norns), which `interleaveFiles` calls with the path, a stage and `openFiles`: `\start` before it opens any file, `\open` once the temporary files and the output are open. The check throws at each stage and asserts one failed report, no entry or file left, and every opened sound file closed. When a newer writer supersedes a preparation, its tagged predecessor calls `done(false)`. At handoff the publication record carries the same failure callback, so revoking its rename source also settles its request. A source already consumed by its rename still counts as written. An abandoned legacy save or scratch take remains silent. Lua chooses distinct save names (#522), but a direct engine caller can select the same destination as a tagged save (#1243). A scratch take passes a `done` too (#312, the record area's `endTake`): a write that ends unwritten (a folder that cannot be made, a short write, a failed rename) is reported on the record area's `takeWriteFailed` poll with the take's record number (`docs/notes/engine/record.md`); a written one reports nothing, nor does one a newer take of the slot abandoned. The report is one float, `bufferSaveResultValue(i, save, failed)` = `(save * 2 + failed) * numBuffers + i`, the layout of `bufferLoadFailed` (one float per message, since matron's `/poll/value` is typed `"if"`), exact for the first 2^20 saves of a slot. The poll is not periodic (`addPoll(\bufferSaveResult, func, false)`, sent only through `bufferSaveResultPoll.update`; its function returns the last value, 0.0 before any report, which names save 0, never sent). Why a result rather than only failures: a failure-only report cannot tell Lua when a save has succeeded, so its flash would have to claim success before the write ends (a long save on a Pi takes seconds) and correct itself later, or never confirm. With the result, Lua shows `saving buf <n>` at once and `saved buf <n>` or `buf <n> save failed` from the report (see `docs/notes/lua/buffers.md`). A save of a slot that a later load, clear or recording changed still reports its own file: the server's `/b_write` was queued before the change. The engine check asserts each case: written, the newer of two writes to one path (either order), a folder that cannot be made, an empty slot, a short write, an error thrown inside the write (one failed report, no entry or file left), a save onto a non-empty folder (one failed report, the folder unchanged), an out-of-range slot (nothing counted or reported) and a 60 s save on a high engine of its own (whose report arrives through the registry's `bufferSaveResult` poll, `h.engine`'s, which `addPoll` hands the second engine: it reaches the check only while the registry holds `h.engine`'s running poll, which the runner checks after every area, #652). For the mover (#217): ten saves whose rename gap (a 1 ms `SystemClock` task's gap in which the saved file appears) stays under 3 ms (before: every one over, median 3.49 ms; after: median 1.0 ms; a measurement more than a guard, since a fork on a faster machine with a smaller sclang costs 2.2-2.7 ms and the gap depends on scheduling under load: the stopped-mover save is the regression guard), and, on an engine of its own, a save through the mover, one while the mover is stopped (renamed by subprocess after `peaksMoverTimeout`, reported once, also after the mover catches up), one after it is killed (by subprocess at once, reported once), and an older save's rename held in a stopped mover with its backlog filled, so a newer save to the same path cannot use it: the newer file stays and each reports once; a write superseded while it waits for an older rename to the path stops at once (its `.part` gone within 0.1 s, no report) and the newest file lands; and a rename that cannot start (an unreadable mover count) reports failed once, deletes the `.part` and leaves no rename marked under way.

**Session receipts (#1091).** `bindSaveResults(token)` opens the private file Lua created with `mktemp` in `/dev/shm` on norns. Hosts without that directory use `/tmp` for off-device checks. The token has exactly 24 alphanumeric characters. SC checks the regular file, its header and its length before writing. At eight slots the inode holds 300 bytes: the 40-byte header, a four-byte ready marker and four eight-byte cells per slot. Lua unlinks its name once the ready marker is visible. Each side keeps one handle until teardown. A process interrupted before the bind can leave its private name in the temporary directory until reboot. The file contains no sample settings or WAV paths.

Lua uses `saveBufferRequest(slot, path, start, length, number, token)` so the actual write carries its full request number and session token together. A stale token or a duplicate still in its ring sends nothing. Legacy `saveBuffer` calls still own a physical write and numbered poll, but cannot publish a Lua receipt. A direct write interleaved with a Lua save, or a dropped Lua command followed by another save, therefore cannot confirm the wrong metadata. Admission installs the full Lua number, pending state and physical write number in the session's four-entry-per-slot ring. Completion updates only that same numbered cell. The engine flushes two matching big-endian copies of `number * 2 + failed` in the inode before sending the existing poll. Lua rejects a short or inconsistent read. `requestSaveResult(slot, number)` republishes an exact retained terminal to repair a missed notification or incomplete receipt write. Unknown, overwritten and pending numbers send nothing. A caller that sends tagged requests beyond Lua’s admission window still receives a legacy poll when the late write completes, while the newer cell remains intact. Free retires publication and closes the handle. Neither a prior session's still-open inode nor an old poll proves a current save finished.

## A write's states

A `writeSlot` (a save or a scratch take) is in one of these, read from its routine's own flags (`reported`, `handedOff`, `newest`) and the area's two records of the path (`writeGenerations[path]`, the newest write's generation; `pathRenames[path]`, the handed-off WAV publication and its completion action), never kept as a name: refused (at the command), the server's writes (the two `/b_write`s to temporary float files and a `sync`), interleaving (chunks into the `.part`, yielding), waiting for an older rename to the path, handed off (its rename owns the `.part` and reports), and ended: reported written, reported failed, or abandoned (a newer write to the path superseded it; a tagged caller gets a failure receipt). The rename itself is the waveform area's (`docs/notes/engine/waveform.md`, A rename's states).

| State | Event | Next | Effect |
|---|---|---|---|
| (the command) | an empty slot, a region under one frame or a full preparation budget | ended, failed | `done(false)` at once, nothing written |
| (the command) | a slot with frames | the server's writes | a new generation is the path's newest (`writeGenerations`); the two `/b_write`s |
| the server's writes | the `sync`, still the newest | interleaving | the temporary files read in chunks into the `.part` |
| the server's writes, interleaving | a newer write to the path | abandoned | stops at its next chunk (`current`), deletes its temporary files and its `.part`, reports failure for a tagged request |
| interleaving | a short temporary file or output (a full disk) | ended, failed | `cannot write`, the `.part` deleted, the generation forgotten, `done(false)` |
| interleaving | done, an older rename to the path under way | waiting for it | yields every `peaksMoverPollStep`, at most twice `peaksMoverTimeout` |
| interleaving, waiting | ready, previous publication finished or revoked | handed off | record the token and completion action, then call `renameIntoPlace` |
| interleaving, waiting | previous publication cannot safely be retired | ended, failed | discard the candidate and preserve the destination |
| handed off | successor or engine free removes its source | abandoned | release the publication receipt; a successor reports the tagged predecessor failed; free suppresses callbacks |
| handed off | successor finds its source already installed | ended, written | finish a live writer once and release its receipt |
| any | engine free | retired | invalidate preparation, revoke outstanding sources and suppress retired callbacks |
| waiting | a newer write to the path | abandoned | stops waiting at once, deletes its `.part`, reports failure for a tagged request |
| interleaving, waiting | a folder at the path | ended, failed | `cannot write ... (a folder is in the way)`, the `.part` deleted, `done(false)` |
| handed off | the rename ends | ended, written or failed | `pathRenames[path]` cleared if it is this generation's; `done(moved)`, once |
| any before handed off | an sclang error in the routine | ended, failed (abandoned if a newer write has the path) | every opened sound file closed, the temporary files and the `.part` deleted, `done(false)` for the newest or for a tagged request |
| handed off | an sclang error after the hand-off | handed off | nothing more: the rename reports |

**What drives its rows** (`test/engine_check/files.scd`): the refusals, `"saving an empty slot writes nothing"` and `"files: a region under one frame writes nothing and reports failed ..."`; a write through to its end, `"a save that writes its file is reported once, written, with its slot and save number ..."` and `"files: a save through the mover lands and reports once ..."`; abandoned while it interleaves, `"an older write to the same path abandons: the file is the second write ..."` and `"of two writes to one path only the newer is reported, written; the abandoned one reports nothing ..."`; a short write, `"files: a save whose temporary file is short is reported failed ..."` and `"files: a save whose temporary file is short keeps the old file and leaves no .part ..."`; waiting for an older rename, `"files: renames to one path land in write order, the newer save's file stays ..."`, and abandoned while waiting, `"files: a write superseded while it waits for an older rename stops at once and reports nothing ..."`; a folder at the path, `"files: a save onto a folder is reported failed ..."`; a folder that cannot be made, `"a save whose folder cannot be made is reported failed ..."`; the rename's end, the mover's and the fallback's checks (`"files: a save while the mover is stopped renames by subprocess after its timeout ..."`, `"files: a save after the mover is killed renames by subprocess at once and reports once ..."`); an error before the hand-off, `"files: a save whose routine throws (%) is reported failed, once ..."` with its two following checks (files closed, nothing left), and `"files: a rename that cannot start reports failed once and leaves nothing ..."` (`renameIntoPlace` throwing as the hand-off begins: a mover whose `pending` is nil). The registered-save barrier cases hold both OS carriers through that limit, inspect every sample after their release, and cover a blocked revocation, a delayed acknowledgment, saturated fallbacks and engine free/reallocation.

A save reports on `bufferSaveResult` from `done` (Save results, above), a scratch take on `takeWriteFailed` when it ends unwritten (`docs/notes/engine/record.md`). A rename still waiting when the engine is freed never reports (its one known limit: `docs/notes/engine/waveform.md`, The mover).

## sclang's garbage collector under heavy allocation (#131, a platform limit)

norns ships SuperCollider 3.13.0. Its sclang collector keeps its scan credit in an `int32 mNumToScan` (`lang/LangSource/GC.h`), raised by every allocation (`1 << sizeclass`: a 64 KB Signal adds 4096, a frame a few); a frame of a function that needs no heap context is allocated without a collection, so millions of small calls in a row run the count up until it overflows and corrupts the collector: a failed count assertion, a segfault or a hang, some time later, wherever the collector next runs. 3.14 made the count `int64` (upstream PR 6261, whose reproducer segfaults 3.13 in 3 of 3 runs and passes 3.14.1), but 3.14.1 is not immune: a full engine check on it has also ended in the same count assertion (once, in the performance area; a rerun passed), so at least one more collector bug is involved (3.14.1 still has upstream issue 7711's frame use-after-free). Strata never asks other projects for changes: this is a fixed platform constraint on every version it runs on, and Strata keeps its allocation low instead, which lowers the risk on both.

- **Engine code** runs no sclang function per sample. `interleaveChunk` clips each chunk with the Signal `clip` primitive, turns it into an Array of Floats with `at` and an index Array (`interleaveKeys`, built once per write by the `(a, b .. c)` series primitive) and places it with `putEach` (keys and values both Arrays: the primitive reads both as slots, so a FloatArray or Signal there is misread). `freshReadArray` makes a Signal, so a chunk read from a file can be clipped directly. The saved bytes are those of the old per-frame loop (`left.size.do({ arg frame; ... })`, one sclang frame per sample): a 60 s stereo comparison of random samples up to ±1.6, with ±1, ±`int16Peak` and 0 in them, wrote identical files. Measured with sclang 3.14 on a desktop: that 60 s interleave fell from 2.88 M allocations (`gcInfo`'s `nalloc`) and 0.31 s to 2.5 k and 0.06 s; the engine check's 60 s save from about 0.5 s to 0.23 s, the 16 s write stays at 0.15 s (the server's `/b_write` dominates).
- **The check's constant files** (#207): `h.writeConstantFrames` builds one full chunk (65536 frames) before its loop and writes it again and again; only a shorter last chunk is built apart. It used to build every chunk afresh (`repeating`: an index Array of 131072 slots, which the collector must scan, and a Signal), 220 of each for the waveform area's 300 s file, and sclang 3.13 then failed in the first 300 s save that followed: signal 11, a hang, or the collector's failed count assertion with a `PrimitiveFailedError` in the save's routine, which fails the check `a 300 s load and a 300 s save back to back` instead of crashing. In Docker, the waveform area alone (CI's shard) failed 14 of 224 runs (16 at once, or 8 beside 8 others), every one in or just before the first round's save, and 0 of 16 with 8 at once; with the chunk built once, 2 of 352 (both a failed count assertion in the second round's load, a later point: a rarer failure this change does not explain: #211, below, which about 1 run in 10 to 16 showed by 3.4.0 and 3.5 fixed). Why those allocations break the save is not shown: the failure is the collector's, some time after the allocations, as in #131. Writing one array again and again is allowed: #131's rule forbids only a `readData` into an array an earlier read filled, and `writeData` never changes its array. A structure test (`test/unit/structure_test.lua`) checks that each of its loops holds only a `writeData` of a chunk built before it and the count of frames left. A long file of any other content is written a second at a time and, when every second is the same, from one second built once (`h.writePeriodicSeconds`).
- **The engine check** builds its test sound with primitives too (`h.repeating`, `h.stereoOf`, `h.periodic`, `h.rampSignal`, `h.noise`; `docs/notes/engine/structure.md`) and compares a long saved file with the file it was loaded from in every sample, a chunk at a time into fresh Signals (`h.sameFrames`, where it used to read 23 MB into one array and look at spots). A first version that built the expected chunk from index Arrays (65536 slots each, which the collector must scan) crashed a 300 s soak on 3.13 by the eighth round; comparing raw Signals passes. Before, its file builders made about 15 M function calls (`FloatArray.fill(n, { ... })`), and the files and buffers areas allocated about 35 M and 30 M objects, against under 5 M for any other area; now 1.2 M and 1.5 M, and the whole check about 17 M instead of 81 M (sclang 3.14, `gcInfo`'s `nalloc` around each area).
- **Measured on 3.13** (16 full checks in parallel, Ubuntu 24.04's 3.13.0 in a container): before, 10 of 16 completed, and 6 crashed (core dumps, hangs until the timeout, failed count assertions), five at the end of the files area or early in effects, one in buffers' long-file checks; after, 32 of 32 completed with no crash (two failed one load-sensitive reverb measurement, the FDN's RT60 against FreeVerb2's, which a baseline run came within 1% of failing). On 3.14.1 (8 full checks in parallel): 6 of 8 before (two failed count assertions just after the files area), 8 of 8 after.
- **CI** runs the check in shards (the `engine-shard` matrix in `.github/workflows/test.yml`), each in its own sclang, so no sclang's allocation adds up over the whole check; freeze and memory, the heaviest high-tier areas, are in different shards. The local 3.13 runner's full run is the same shards (#581).
- **The soak** (`STRATA_ENGINE_CHECK_AREAS=soak test/run_engine_check.sh`, `test/engine_check/soak.scd`, never in CI or a full run) repeats a long session's long-file work on a high engine: each round loads a 60 s file into the next slot (the decode check and the server's read), saves it (the interleave), checks the saved file in every frame and clears the slot. `STRATA_SOAK_ROUNDS` (40) and `STRATA_SOAK_SECONDS` (60, 120 or 300) size it, and `STRATA_SOAK_CHECK=length` checks only the saved file's length (the engine's allocation without the check's reads); a longer soak needs a longer `ENGINE_CHECK_TIMEOUT`. Run it on 3.13 to be meaningful: 40 rounds of 60 s pass on 3.14 in about 25 s, of 300 s on 3.13 in about 95 s.
- **What crashed the 300 s soak near its tenth round** (`STRATA_SOAK_SECONDS=300`, `STRATA_SOAK_CHECK=length`, on 3.13, three to six containers at once): the runner's poll lists, not the engine. Every failing run ended in a failed count assertion in the ninth or tenth round whatever the interleave (the old per-frame loop 0 of 3, `interleaveChunk` 2 of 6, an inlined `while` loop 2 of 3), loads alone passed 5 of 5, and the heap stayed flat (about 53 k objects and 6.8 MB every round; no counter near a limit). The round was set by time: the check keeps every `/poll/value` message (about 5 a second), and the failures came as the List passed 128 entries, when its Array is reallocated as a big object (size class 8, above the collector's pooled classes), inside the responder while a save allocated; the every-frame check, whose rounds are slower and spend a second reading files between saves, passed 6 of 6 before the fix, probably because it passed that mark outside a save; after it, 5 of 6 (one failed count assertion in round 3, which the poll Lists do not explain: still open). With the poll Lists made with room for 16384 entries (`pollListCapacity`), 6 of 6 passed at 20 rounds and 6 of 6 at 40, against 2 of 6 for the same code growing them. Also fixed on the way: `h.pollValues` and the waits read one poll's values (`pollValueLists`) instead of scanning every message the run has received with a function per message, `h.pollValueNear` tests them with Signal arithmetic, and `h.writePeriodicSeconds` builds one second of a long test file at 48 kHz instead of every second. Users never ran into this: matron, not sclang, keeps norns' polls.
- **What the remaining early failures were** (the round-3 count assertion and a hang in round 1, each in one every-frame soak of a batch of 6 or 12 started at once on 3.13): sclang's collector, set off by the engine's own frames (#211, the next item), not by the long-file work. In the hangs the check's own deadline (a SystemClock task 30 s before the timeout) never fired, so the language itself stopped, not a wait for a late reply; the assertion came from inside a primitive in the save's routine (reported as `PrimitiveFailedError`). Both came within the first three rounds, after the run had built two engines (whose SynthDef builds allocate the most small objects of the run), and never later: 24 soaks of 120 rounds each (8 every-frame, 8 `length`, 8 every-frame with fewer temporary arrays, 2880 rounds of a 300 s load and save) all passed, and every completed round's saved file equaled its source in every sample. `test/run_engine_check.sh` now names such a stop (`no result within <n> s, and its own deadline never fired: sclang hung`).
- **What #211 was** (the waveform area's 300 s pairs failing about 1 run in 10 on 3.13 and 3.14.1, and #671's crash at the start of the modulation area in a full single-sclang run): not allocation, but a frame left pointing at freed memory. A method whose frame a kept closure holds (an area's `addDefs`, whose SynthDef functions SynthDescLib keeps) was called straight from a function, whose frame sclang frees as it returns; a few hundred flips after an engine build, when the collector's colors (which repeat every 256 flips) came round, a scan of that frame's `caller` slot revived dead objects and could move a free list's head onto the gray list (the objects still to scan). The long-file work only supplied the flips: about 600 per 300 s pair, so it came within a pair or two of the high engine's build, and never later, as the soak's rounds showed. The area hooks, `strataAreas` and every such call found by the instrumented builds or a read of the engine's deferred functions now go through `areaCall` (`docs/notes/engine/structure.md`, Must not break and Areas), and the failures stopped (0 in 96 waveform runs on 3.13 and 0 in 24 on 3.14.1, against 7 in 48 and 5 in 31 before, the same day). So the family, as far as measured, is three things: 3.13's `int32` scan count (#131, which the per-sample loops and the reused readData arrays drove), allocation inside the check's own responders (the poll Lists), and these frames, the part that also failed 3.14.1.

`fileDecodes` also makes a load's peaks: its reads are bin-aligned and each played chunk goes through `Signal`'s `peak` after selecting the first two channels of a multichannel file (`docs/notes/engine/waveform.md`). When loading, the same decoder writes the selected region as one or two float channels to the load’s private snapshot. It takes samples for the overview and for the server from the same chunks. A multichannel source is reduced to its first two channels with array primitives. Decoding a file before it loads (`fileDecodes`, `loadShortfallFrames`, the long-file check) is under Damaged files and failed reads and Long files in `docs/notes/engine/buffers.md`.
