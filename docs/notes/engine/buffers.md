## Must not break

- **`slotChanges[i]`** guards late replies (load completion, `stopRecord` frame count) and the fade wait: a clear or load sent later always wins. The count has two roles (#946): "anything changed the slot" and "the token of the operation that changed it last". A stop that keeps its take counts a change and re-keys the take (`take[\change]`, `stopRecordSlot`), so a step of that take is guarded by its own token, and an arming's peaks write asks a `current` function (`writeSlotPeaks`) rather than the count it read. A long file's load still in its check is dropped once `loadsSuperseded(i)` reaches its number (`slotChanged` raises it). A `bufferLoadFailed` report names its load's number, so it never undoes a later load, clear or recording, and says the slot emptied only while `slotChanges[i]` is the count its load took (#1035); a `bufferSaveResult` report names its save's number, so it never speaks for a later save.
- **Every `bufferState` report names the newest load of its slot that, with every load before it, has an outcome** (#578, #983): `bufferStateReport` encodes `bufferStateLoad(i)` modulo `bufferStateLoads` (7) with the slot index and seconds, whatever the report is of, the periodic repeat included (it re-encodes the announced seconds with the number of that moment, so the report after a rejected load names it). `bufferStateLoad(i)` is `bufferLoads[i]` but while a load is in its check (`areaState[\buffers][\checks][i]`, from its command to its outcome, and not superseded: `loadsSuperseded(i)`), then the load before the oldest such one: a repeat of the previous load's length never carries a checked load's number. Never a number stored with the seconds, and never one only a load's reports carry: Lua acts on a slot's report only when the number is its own count's, and a clear's or a recording's report must pass. One report is the exception: a rejected check that had canceled a recording re-reports the slot's length under its own load's number (`rejectLoad`, #1016, Polls below).
- Recording is the record area's (`lib/engine/StrataRecord.sc`, `docs/notes/engine/record.md`): `recordBuffer` and `stopRecord`, `recordSlot`, `stopRecordSlot` and `stopRecording` are there, rewritten for 3.3 (the record synth in the tap group, playable recordings, the state table). This file keeps only what a recording asks of a slot. `loadBuffer` takes `"isf"`: `loadSlot(index, path, start = 0)`, `start` in seconds at the file's own rate (Start points, below).
- **Fade before zeroing**: load, record and clear set the slot's frames to 0 first (`hasAudio` fades the voices) and zero or overwrite its buffers through `afterSlotFade` (`bufferFadeWait`, 60 ms, when a grain synth reads the slot). Never zero a slot directly. That covers every `\strataGrainBuf` until it frees, releasing and fading ones too (`grainSlots`, `slotGrainSynths`): those only ever get `bufFrames 0`. 3.5's extra buffer notes are in `grainSlots` too, so a load or clear fades them with the own note; `bufferChanged`'s live set (the grain synths that take a new length and rate) is each voice's own grain synth and its live extra grain notes (`noteSynths(voice, \grain)`), and a releasing note's tail only ever gets `bufFrames 0`. `bufRateScale` is sent only with a valid length (`slotLengthPairs`), never to grains fading out.
- A missing, unreadable, empty or damaged file leaves the slot as it was (and cancels a recording in it, which leaves the slot as the take left it: `docs/notes/engine/record.md`, The state table), and is reported by `bufferLoadFailed`, after the canceled take's report and the slot's length.
- **An empty slot is at the server's rate**: wherever `bufferFrames[i]` becomes 0 (a load taking effect, a clear, a replace take's preparation, a failed read) `bufferSampleRates[i]` becomes the server's, so a recording sent while a load is in flight is judged on the empty slot, never on the rate of the file the load replaces (#374). No step has another rate with 0 frames (#946): a load's last step, from its reads until its peaks file is in place, keeps the server's rate, passes the file's to the peaks write (`writeSlotPeaks`' `rate`: the file names it) and sets it with the frames in the write's action (`"buffers: a slot being loaded is at the server's rate until its length is reported"`); `recordSlot` still judges a slot of 0 frames empty whatever its rate, a second guard (`docs/notes/engine/record.md`). `slotLengthPairs` sends no rate with 0 frames, so the grains fading out are not retuned.
- A file longer than `standardBufferSeconds` (16 s) at the server rate is checked in a routine (`fileDecodes` yielding) and takes effect (`applyLoad`) only after the check. It is dropped silently, reporting nothing, once `loadsSuperseded(i)` reaches its load number: a record, clear or stop raises it to every load sent so far, a load that takes effect to its own number. The check asks after every chunk (`fileDecodes`' `keepGoing`, `load > loadsSuperseded(i)`), so a superseded check reads no further and closes the file at once (#375; `areaState[\files][\decodeChunks]` counts the chunks read, for the check: a load and a clear in one tick read 1 of a 60 s file's 192).
- **New audio never plays at an old gain** (3.7, design §4.4): a slot's gain (`setSlotGain(slot, gain)`, `"if"`: slot 0-7, gain clipped 0-16, kept in `areaState[\buffers][\gains]`, 1 at alloc) goes to every live reader of the slot at once (`setSlotGainValue`, through `slotLiveReaders`: the own grain synths and live grain notes reading it, as `bufferChanged`'s live set) and to every reader started or re-gated later (`slotLengthPairs` carries `slotGain` with the head bus). The engine sets it to 1 itself, with the same send, wherever the slot's audio is replaced or recorded into: `applyLoad`'s reset and `clearSlot`'s (before their `bufferChanged`) and every recording's preparation (`prepareTake`, `docs/notes/engine/record.md`); a load that cannot be used (`rejectLoad`) leaves it. Lua owns the value and sends the file's gain once it has read the slot's new peaks. 3.5's command rules: a bad slot or a non-finite gain is ignored with one line, and what it took is `areaState[\buffers][\received][\setSlotGain]` (`"buffers: setSlotGain reaches a live reader and the reader a later start makes"`, `"buffers: a load and a clear set the slot's gain to 1"`).
- **A slot that holds frames reports at least 0.01 s** (`bufferStateSeconds`, #456): a slot under 240 frames at 48 kHz (a single cycle) would round to 0.00, which Lua takes as empty everywhere (not loaded, nothing to save, no waveform) while the engine plays it. Only an empty slot reports 0. A later load that fails never drops it (Lua then puts that load's name back). Its command cancels a recording in the slot at once, whatever the check finds.
- Bufnums never change: loads read into the existing buffers.
- A load's check and its read begin at one frame (`startFrame`): the check seeks there (`SoundFile.seek`), so a damaged region before the start never matters and the peaks the check makes describe what the slot holds.
- `applyLoad` reports the length only after the peaks file is in place (`writeSlotPeaks`, `docs/notes/engine/waveform.md`), and sets `bufferFrames` and `bufferSampleRates` in that same step, so a slot never reads as loaded with its peaks file still missing.
- **A long load's check always ends** (#885): its routine runs the check (`fileDecodes`) inside a `try`, as a save's and an onset pass's routines do; an sclang error there closes the file and, unless the load was superseded meanwhile, rejects it (`rejectLoad`: its `bufferLoadFailed` names the load's number, the slot as it was), so Lua's slot never waits on a load that can no longer end (`loadCheckFaultHook`, nil on norns, lets the engine check throw inside it: `"buffers: an error in a long load's check reports bufferLoadFailed with the load's number"`).

## Polls

**Poll `bufferState`** (engine → Lua): each slot's valid seconds. matron's `/poll/value` handler is typed `"if"` (one float) and its data-blob polls are broken (`w_handle_poll_data` writes every byte to index 1), so a string or table cannot reach Lua: every message carries **one** slot and the load it was sent after (#578), as `bufferStateReport(index, seconds)` = `(load * (numBuffers + 1) + index) * bufferStateStride + seconds`: `load` is `bufferStateLoad(index)` (the slot's `loadBuffer` commands so far, counted from 1, as Lua's `load_buffer` counts them in `loads_sent`, but while a long load is in its check the load before the oldest such check not yet superseded, #983: below) modulo `bufferStateLoads` (7), and 0 for the slots' length (`bufferStateStride = 1000`; seconds ≤ `bufferSeconds`, at most 300, rounded to 0.01, and at least 0.01 for a slot that holds any frames: `bufferStateSeconds`). The cells `load * 9 + index` run to 6 × 9 + 7 = 61, so the largest value is 61300: below 2^16, where a 32-bit float holds it to 2^-8 s (within 0.002 s) and every thousand exactly, so the hundredth comes back by rounding. 7 is the most load numbers whose largest value stays below 2^16 (8 would reach 70300, where a float's step is 2^-7 s). Decode in Lua with `cell = math.floor(value / 1000)`, `slot = cell % 9` (0-based, so Lua slot `slot + 1`), `load = math.floor(cell / 9)` and `seconds = math.floor((value - cell * 1000) * 100 + 0.5) / 100`. The number is the slot's newest load whose outcome the engine has reached, with every load before it, when the report is sent, whatever change it reports: a load's 0 s and its length, a clear, a recording's preparation, length or stop, a cancel's length, and the periodic repeat, which encodes the announced seconds with the number of its own moment (so after a load the engine rejected, which Lua counted too, the next periodic report names that load and settles the state Lua put back). A load in its check (a long file on the high tier, `areaState[\buffers][\checks]`) has no outcome yet: from its command until it takes effect, is rejected or is superseded, every report names the load before the oldest such check not yet superseded (`loadsSuperseded`; with one check, the load before it, #983), the periodic repeat of the old audio, the length its own command's cancel of a recording leaves, and the reports of a take that completes meanwhile (#890) included; a short load rejected meanwhile is not named either. So a report under a checked load's number comes after its outcome: its own 0 s when it took effect (`applyLoad` always reports 0 s first), and any other length only once it was rejected; a rejected check that had canceled a recording reports the slot's length under its own number just before its `bufferLoadFailed` (`rejectLoad`, `bufferStateReport`'s `named`), as a short load's cancel does, so Lua undoes the load from the length the cancel left; its own number, never `bufferStateLoad`'s, which would name a later load rejected during the check, so Lua would take the old audio for the end of the check that load's failure gave back (#1016: Lua keeps that report's seconds only). Lua ends a check only at its own 0 s, or, for a check a later load's failure gave back, at any report of that later load's number (`docs/notes/lua/buffers.md`). The buffers area's check "a periodic report during a long load's check names the load before it" reads the values the periodic poll sends for the slot (`announcedBufferState`) at the command and in the check, and "a long load's cancel of a recording reports under the load before it" and "a rejected check that canceled a recording reports its length under its own number when a later load was rejected first" (#1016) the reports in the order they arrived. A report sent before the engine had a load names an older number; one sent after it, whatever its change, names it: Lua sends a clear or a recording after the loads before it, and the engine handles commands in order. More than 7 loads of one slot in flight at once wrap the number: a report sent before the newest of them can then name it, and Lua acts on it as on every report in 3.3 (the slot and the seconds never depend on the number). The poll is periodic: every 0.25 s it sends the next slot in turn (`bufferStateCursor`), then the slots' length as slot index `numBuffers` (`bufferLengthValue`: `numBuffers * 1000 + bufferSeconds`, load number 0), so each slot is reported every 2.25 s ((`numBuffers` + 1) × 0.25 s); every change (load, record start, completion and early stop, clear) is also sent immediately via `bufferStatePoll.update`. A slot's periodic value is the seconds `bufferChanged` last sent (`announcedBufferState`, kept in `areaState[\buffers][\announced]`) with the slot's load number now, never `bufferFrames` read at the poll's moment: a playable recording's arming sets `bufferFrames` before its peaks file of that length is written and calls `bufferChanged` after, so the periodic poll never announces a length whose peaks file is not in place. Every change of `bufferFrames` or a slot's rate goes through `bufferChanged` (at once, or as a peaks write's action), with one exception: an arming whose peaks write a later `recordBuffer` cancels (the write's action runs only while `slotChanges` is unchanged) announces nothing, so the periodic poll repeats the slot's old length until its next load, clear or replace take. Lua never sends that sequence: it stops a recording before it starts another in the slot. A slot recording a replace take reads 0 s from the take's preparation until it ends, then the take's length; a playable recording keeps its slot's length and, at its arming, reads the longer of that and the record length (`docs/notes/engine/record.md`). Lua: `init` calls `poll.set("bufferState", buffer_state_changed)` and starts it (it prints a message if the poll is missing); `buffer_state_changed` decodes the value with `BUFFER_STATE_STRIDE` (1000) and `BUFFER_STATE_LOADS` (7) into `buffers[slot].seconds`, hands slot index `NUM_BUFFERS` (the slot length) with load number 0 to `S.lib.performance.engine_slot_seconds`, ignores other slots outside 1..`NUM_BUFFERS` and every report whose load number is not the slot's `loads_sent` modulo 7 (sent before the engine had the slot's newest load: it tells what that load replaces), and settles a take or load waiting for the engine, or adopts a late take or load (see the buffers table under Audio Sources); `cleanup` stops it.

**Poll `bufferLoadFailed`** (engine → Lua, not periodic: `addPoll(\bufferLoadFailed, func, false)`, sent only through `bufferLoadFailedPoll.update`): one message per failed load, whether or not the slot held audio. `rejectLoad` sends it at once for a missing, unreadable, unsupported, empty or damaged file, which leaves the slot as it was. `loadSlot`'s read sends it after the fade and the read when the server's `/b_readChannel` fails, which leaves the slot empty (below). `bufferState` cannot carry this: over audio the slot keeps its old length, so its reports look like a good load's, and its layout has room only for the load number modulo 7 (#578). A second poll keeps both encodings plain. The value is one float, `bufferLoadFailedValue(i, load, emptied)` = `(load * 2 + emptied) * numBuffers + i`: `load` is the failed load's number, from `bufferLoads[i]`, which counts the slot's `loadBuffer` commands from 1 (in `loadSlot`, after the slot check); `emptied` is 1 when the failed server read left the slot zeroed and nothing called `slotChanged` since (`slotChanges[i]` unchanged: no later load took effect, no clear, recording or stop, no load canceled a recording), and 0 when the slot is as it was or such a change decides it: Lua undoes a load it no longer tracks only on a 1 (#1035; #1040's cases, closed by 3.9's package 6o: `docs/notes/lua/buffers.md`). Lua's `load_buffer` counts the same commands in `buffers[slot].loads_sent`. Both start at 0 when the script starts, because norns builds a new engine for every script load. It is exact for the first 2^20 loads of a slot (float32 integers). For a load that canceled a recording it is sent after that recording's `canceled` report and the slot's `bufferState` (the slot as the take left it). A failed read is reported after the fade wait and the read, so it can arrive after a later load's immediate rejection: reports are not in load order, and Lua does not assume they are. Its poll function returns the last value (0.0 before any failure, which names load 0, never sent), so a value request only repeats a report, and Lua ignores repeats. Lua: `init` sets `buffer_load_failed` as its callback and starts it (`buffer_polls.load_failed`; it prints a message if the poll is missing), and `cleanup` stops it.

## The polls' encodings

Each of the six polls (engine → Lua) carries one float per message, with a 0-based slot `index` (Lua's slot is `index + 1`; `freezeEnded`'s is a voice, Lua's `voice + 1`) and, where it names one, the slot's count of one command, counted from 1 in the engine and in Lua alike: `load` is `bufferLoads` (Lua's `loads_sent`), `save` is `bufferSaves` (`saves_sent`), `record` is `recordCounts` (`records_sent`).

| Poll | Sent | Value (engine function) | The rest |
|---|---|---|---|
| `bufferState` | one slot every 0.25 s in turn, then the slots' length; every change at once | `(load * (numBuffers + 1) + index) * bufferStateStride + seconds`, `load` the newest load that, with every one before it, has an outcome (`bufferStateLoad`: while a long load is in its check, the load before the oldest check not yet superseded, #983) modulo `bufferStateLoads` (7), but for `rejectLoad`'s re-report of a check that had canceled a recording, which names the rejected load's own number (`bufferStateReport`'s `named`, #1016); index `numBuffers` with load 0 is the slots' length (`bufferStateReport`, `bufferLengthValue`) | Polls, above; Lua: `docs/notes/lua/buffers.md`, and `docs/notes/lua/performance.md` for the length |
| `bufferLoadFailed` | once per failed load, not periodic | `(load * 2 + emptied) * numBuffers + index` (`bufferLoadFailedValue`; emptied 1: `applyLoad` zeroed the slot, its read failed, and nothing called `slotChanged` since, #1035) | Polls, above; Lua: Audio Sources: Lua side, below, and `docs/notes/lua/buffers.md` |
| `bufferSaveResult` | once per save whose write ends, not periodic | `(save * 2 + failed) * numBuffers + index` (`bufferSaveResultValue`) | `docs/notes/engine/files.md` (Save results); Lua: `docs/notes/lua/buffers.md` (Save results) |
| `recordState` | once per change of a recording's state, not periodic | `((record * 4) + state) * numBuffers + index`, state 0 armed, 1 recording, 2 ended and kept, 3 canceled (`recordStateValue`) | `docs/notes/engine/record.md` (recordState, The state table); Lua: `docs/notes/lua/record.md`, where a take whose "ended" or "canceled" never comes, a replace take's or a playable recording's, settles by its fallback (#904) |
| `takeWriteFailed` | once per kept take whose scratch write ends unwritten, not periodic | `record * numBuffers + index` (`takeWriteFailedValue`) | `docs/notes/engine/record.md` (takeWriteFailed); Lua: `docs/notes/lua/buffers.md` |
| `freezeEnded` (3.8, #858) | once per freeze the engine ended itself (a hold abandoned), not periodic | `ended * numVoices + voice`, `ended` the voice's count of them from 1 (`freezeEndedValue`) | `docs/notes/engine/freeze.md`; Lua: `docs/notes/lua/freeze.md` |

Decoding the last four: `index = value % numBuffers` and `rest = floor(value / numBuffers)`; `emptied` and `failed` are the lowest bit of `rest` and the number the rest of it (`floor(rest / 2)`), `recordState`'s state is `rest % 4` and its number `floor(rest / 4)`, and `takeWriteFailed`'s number is `rest`; `freezeEnded`'s voice is `value % numVoices` and its count `floor(value / numVoices)`. `bufferState`'s decoding is in Polls, above.

## Buffer slots

- **Buffer slots**: `numBuffers = 8` slots (mirrors Lua `NUM_BUFFERS`), each a pair of mono buffers `buffersL[i]`/`buffersR[i]` (GrainBuf reads mono buffers only) of `sampleRate * bufferSeconds` frames (`bufferSeconds` is set by the performance area first at alloc: 16 s on standard, 16/60/120/300 s on high; Lua reads it as `S.performance.buffer_seconds`, see [performance.md](performance.md)). Memory: 8 × 2 × 16 s × 48 kHz × 4 bytes ≈ 49 MB of scsynth memory on standard, up to 922 MB for 300 s on high. Never allocate longer buffers. `bufferFrames[i]` is the valid length (0 = empty); `bufferSampleRates[i]` the content's sample rate. bufnums never change: loads read into the existing buffers

**Buffer commands** (`loadSlot`, `recordSlot`, `clearSlot`, `writeSlot` in the engine): load opens the file with `SoundFile` (frames, channels, rate) and `readChannel`s at most `bufferSeconds` of it into the existing buffers, capped by the buffers' size (`bufferSeconds` at the **server** rate): a 96 kHz file keeps half of `bufferSeconds` (8 s of 16) on a 48 kHz server, a 44.1 kHz file the full length. **Damaged files and failed reads** were probed with scsynth 3.14:
- A WAV whose header claims more data than the file holds, and a truncated WAV, are not failures. libsndfile shortens `numFrames`, and sclang and the server both read the frames that are there.
- A corrupt or truncated FLAC keeps a sound header (48000 frames) but stops decoding early (12288 frames). The server's `/b_readChannel` then fills the rest with silence and reports nothing. So `loadSlot` decodes the frames it will read itself first (`fileDecodes`, a fresh chunk array per read, at most `loadCheckFrames` = 16384 frames each: 16 s of 48 kHz stereo takes about 2 ms for a WAV and 9 ms for a FLAC on a desktop, and the file is then in the page cache for the server). Up to `loadCheckAtOnceFrames` (`standardBufferSeconds` at the server rate, so every load on the standard tier) it decodes at once, in the command. A longer file (the high tier's slots) is decoded in a routine that yields after every chunk (`yieldToCommands`, at least `commandGap` of real time), so seconds of decoding on a Pi never hold up matron's commands; see Long files below. A file that decodes more than `loadShortfallFrames` (4096) frames short is rejected like an unreadable one. That tolerance is one default FLAC block (85 ms at 48 kHz) and more than an MP3's encoder delay and padding (under 2 × 1152 frames), so a header count that overshoots by a codec's padding still loads. The damaged FLAC (35712 frames short) is rejected. Damage inside a FLAC's last block slips through as at most 4096 frames of silence at the end. A format whose header count is only a rough estimate that overshoots by more is rejected: an MP3 without a Xing/LAME header, which needs libsndfile 1.1 or later and is therefore not readable on norns' libsndfile anyway. libFLAC 1.4 prints `Rewinding, seeking necessary` to stderr when it seeks in a damaged FLAC; sclang cannot silence it, it is harmless, and `run_engine_check.sh` does not count it as an error.
- A corrupt Ogg reads as 0 frames, so it is rejected as empty.
- The server's read itself fails (`/fail /b_readChannel <message> <bufnum>`) only when the file vanishes or becomes unreadable between those checks and the read, for example a drive unplugged during the fade wait. The read's `fork` watches for that `/fail` with an `OSCFunc` from the server's address that matches `/b_readChannel`, one of the slot's bufnums and the quoted path in the message (`File '<path>' could not be opened: ...`). Matching the bufnum alone would not do: two back-to-back loads into an unplayed slot both read at once, so a vanished file's `/fail` would also fail the next load's good read. A next load of the very same path cannot be told apart, but it reads a file that has just vanished. The `/fail` arrives before the `/synced` that ends the wait, and the `OSCFunc` is freed after it. The slot has already been zeroed, so it keeps 0 frames (its rate is reset to the server's, only if `slotChanges` is unchanged), and the load is reported whatever came after it (Lua relies on the report to keep its tracked loads right), emptied only if `slotChanges` is unchanged (#1035). A load that a later load, clear or recording superseded inside the fade wait never reads, so it reports nothing.

A missing, unreadable, empty or damaged file (`rejectLoad`) is logged, reported by the `bufferLoadFailed` poll (above) and leaves the slot unchanged (before anything is zeroed), except that it cancels a recording in progress or waiting to start in that slot, or one `stopRecord` ended whose frame count has not arrived yet (`stopReplies[i]` holds that stop's `slotChanges` count until the reply; the bad load's `slotChanged` drops the reply; every `slotChanged` empties `stopReplies[i]`, so once a good load, record or clear has followed the stop there is no take left to cancel and a bad load sent after it leaves that command alone) (`stopRecording`, `slotChanged`): Lua's `load_buffer` ends the recording state, so a take that completed anyway would be adopted under the bad file's name and path (and lost at the next restore). The slot is left as the canceled take left it: untouched when the take had not prepared it (a synced replace take still waiting for its preparation keeps its audio, as does a playable recording, which is freed at once with no stop fade), empty when it had (#311); `cancelSlotRecording` reports the slot's length right after "canceled", so Lua learns which. A good load sets the slot's frames to 0 (and its rate to the server's) at once, zeroes the pair and reads after the fade (below); the slot's `bufferFrames`/`bufferSampleRates`, the grain synths reading it and the poll get the new length only once the reads have completed (a `server.sync` after them in a `fork`). **Fade before zeroing**: `b_zero` and `b_readChannel` complete within about a millisecond, far inside `\strataGrainBuf`'s 50 ms `hasAudio` lag, so load, record and clear first set the slot's `bufferFrames` to 0 (`bufferChanged` sends it to every grain synth reading it, and the poll reports 0) and only then zero or overwrite the buffers, through `afterSlotFade(index, change, action)`: `bufferFadeWait` (0.06 s, settable; the engine check lengthens it) later when any grain synth reads the slot (`slotPlaying`), at once otherwise, so a recording into an unplayed slot starts without delay. The delayed action runs only if `slotChanges[index]` is still `change`, so a later load, record or clear inside the wait wins (the earlier command's zeroing, read or record start is dropped, the later one does its own). `free` bumps every slot's count, so nothing waiting runs on freed buffers (the engine check frees it with a clear, a load and a recording waiting). **Grain synths that are no longer a voice's** still read their slot: one releasing after `voiceOff` (2 s), fading after a source switch, or in its kill fade. `grainSlots` maps every `\strataGrainBuf` (set in `startGrainSynth`, removed in `onFree`) to the slot it reads, and `slotGrainSynths(index)` lists the playing ones; `slotPlaying` counts them all, so a slot change waits for their fade too, and `bufferChanged` sends them `bufFrames 0` only (never a new take's length, which their tail would replay, and never a rate). `voiceOn` re-gates a releasing one with the slot as it is then (`bufferSlotPairs`). **The rate follows the audio**: `bufferChanged` and `bufferSlotPairs` send `bufRateScale` only with a valid length (`slotLengthPairs`), so a clear or recording, which set the slot to the server rate, never retunes the grains still fading out (a 44.1 kHz file's grains started in the 50 ms fade played about 1.5 semitones sharp); a take's rate arrives with its length. **`slotChanges[i]`** counts the changes to slot i (load, record, clear, stop, through `slotChanged(i)`, which also raises `loadsSuperseded(i)`: Long files above); a reply that arrives later (the load's completion, `stopRecord`'s frame count) applies only if the count is what it was when the reply was requested, so a clear (or load, or new recording) sent before it wins. A recording (its preparation, the record synth, a stop that keeps it, and what a canceled take leaves the slot: untouched before a replace take's preparation and for a playable recording, empty after a replace take's preparation, each followed by the slot's length) is the record area's: `docs/notes/engine/record.md` (The recording path, The state table) and, for Lua, `docs/notes/lua/record.md`. Every change updates `bufferFrames`, the grain synths reading the slot (`bufFrames`, and `bufRateScale` when the slot holds audio) and the `bufferState` poll.

**Start points** (3.3). `loadSlot(index, path, start)` turns `start` (seconds at the file's rate) into `startFrame = (start × rate).floor`. A start inside the file reads from there to the file's end or `bufferSeconds` from it, whichever comes first. A start at or past the end (a stale `start` after the file was replaced by a shorter one) loads the last frames the slot holds, `numFrames - slotFrames` or the whole file when it fits, so the result is something a player can hear rather than an empty slot. `applyLoad` reads with `readChannel(path, startFrame, frames, ...)`.

**Long files** (high tier). `loadSlot` counts the load (`bufferLoads`), opens the file and works out its frames at the command, as for any file; a missing, unreadable or empty file is rejected at once. A file of more than `loadCheckAtOnceFrames` frames is then checked in a `fork` on `SystemClock`: its command first cancels a recording or an awaited `stopRecord` frame count in the slot (`slotRecording`, `cancelSlotRecording(i, load - 1)`, which supersedes only the loads before it, so the load itself can still apply), since Lua's `load_buffer` ends the recording whatever happens. The routine decodes with `fileDecodes(file, frames, true, peaks, keepGoing)`, `keepGoing` being `load > loadsSuperseded(i)`, asked after every chunk's yield: a check something superseded stops there (a 300 s FLAC on a Pi would otherwise decode for seconds, file open, after a clear or the engine's free, #375). It then closes the file and goes on only while `load > loadsSuperseded(i)`. `loadsSuperseded` lives in `areaState[\buffers][\loadsSuperseded]` (the newest load number per slot that can no longer take effect, 0 at alloc). `slotChanged(i, throughLoad)` raises it to `throughLoad`, or to `bufferLoads[i]` when none is given: a record, clear or stop (and `free`'s `stopBuffers`) supersede every load sent so far; `applyLoad` passes its own number, so a later load still in its check is not dropped by an earlier one that applies first. So, whatever order the checks end in, the newest load or other change wins: a clear, record or short load sent during the check wins (the checked load is dropped, a damaged file is never reported); of two long loads the later one wins (if its check ends first, the earlier one is dropped; if it ends last, it applies over the earlier one); a later load that is rejected leaves the checked load to apply, matching Lua, whose `buffer_load_failed` then puts that load's state back. A dropped check reports nothing, as a superseded load inside the fade wait already does. A check that passes calls `applyLoad` (stop the recording, `slotChanged(i, load)`, 0 frames, `afterSlotFade`, read, as for a short file); one that fails calls `rejectLoad`. While the check runs the slot keeps its old audio and reports its old length under the load before the oldest check not yet superseded (`bufferStateLoad`, #983: the load is in `areaState[\buffers][\checks][i]` from its command until its routine's outcome; Lua shows the new name at once with `...` for its length, and settles it only after its own 0 s: `checking_from`, `docs/notes/lua/buffers.md`). On a desktop the check of a 60 s WAV takes a few tens of ms; a 300 s WAV loads (check and read) in about 0.4-0.65 s. Freeing the engine during a check supersedes it (`stopBuffers`), so it touches no freed buffer.

File writes (`writeSlot`, `saveBuffer`, the scratch takes) and the `bufferSaveResult` poll are in `docs/notes/engine/files.md`.

## The slot's states

A slot is in one of seven states, none kept as a name: each is read from `bufferFrames[i]`, `bufferSampleRates[i]`, the pending steps (a `SystemClock.sched` of `afterSlotFade`, the reads' `fork`, a peaks write) and the long check's routine. A recording's own states are the record area's (`docs/notes/engine/record.md`, The phases and The state table), which every row below calls where a command cancels or ends one: a replace take empties its slot as a clear does, a playable recording leaves it alone (but zeroes an empty one after the fade).

- **empty**: 0 frames at the server's rate, zeroed (or about to be).
- **audio**: V frames at the content's rate R, reported.
- **checking**: a long file's check running (high tier only), the slot as it was (empty or audio), more than one at a time possible.
- **fading to a load**: 0 frames reported, a voice still reading the slot, the zeroing and the reads waiting for `bufferFadeWait`.
- **reading**: zeroed, the reads and the `sync` after them pending.
- **peaks pending**: read, 0 frames at the server's rate (#946), the peaks file being written; the file's rate and frames come with the write's action.
- **fading to a clear**: 0 frames reported, a voice still reading the slot, the zeroing waiting for `bufferFadeWait`.

| State | Event | Next | Effect |
|---|---|---|---|
| any | `loadBuffer` of a missing, unreadable or empty file, or a damaged short one | as it was | a recording not ending canceled (canceled, bufferState); bufferLoadFailed(n, 0) (`rejectLoad`) |
| any | `loadBuffer` of a good short file | fading to a load, or reading when no voice reads the slot | a recording canceled (an ending one reported ended); the older loads superseded; 0 frames, the server's rate, gain 1, bufferState 0 (`applyLoad`) |
| any | `loadBuffer` of a long file (its check passes or not) | checking | a recording not ending canceled, superseding only the loads before this one (`cancelSlotRecording(i, load - 1)`) |
| checking | the check passes, the load not superseded | fading to a load, or reading | as a good short file's load |
| checking | the check fails, or throws (#885), the load not superseded | as it was | bufferLoadFailed(n, 0) |
| checking | a newer load takes effect, a clear, a recording or a stop | that command's state | the check stops at its next chunk (`loadsSuperseded`) and reports nothing |
| fading to a load | the fade's end, the slot unchanged | reading | both buffers zeroed, both reads sent with a `/fail` watcher |
| reading | the sync, a read failed | empty, the slot unchanged; else the later command's state | unchanged: the server's rate and no peaks, bufferState 0, bufferLoadFailed(n, 1); changed: bufferLoadFailed(n, 0) only (#1035) |
| reading | the sync, the reads done, the slot unchanged | peaks pending | the load's peaks stored, the peaks file written with the file's rate |
| peaks pending | the write's action, the slot unchanged | audio | the file's rate and frames, bufferState V' (`writeSlotPeaks`, a failed write too) |
| fading to a load, reading, peaks pending | a load that takes effect, a clear or a recording | that command's state | the older load's steps dropped (`slotChanges`): it reports nothing, but for a read already sent that the server fails, which still reports bufferLoadFailed(n, 0) when it ends (the reading row, #1035) |
| any | `clearBuffer` | fading to a clear, or empty when no voice reads the slot | a recording canceled (an ending one reported ended); 0 frames, the server's rate, no peaks, gain 1, bufferState 0 |
| fading to a clear | the fade's end, the slot unchanged | empty | both buffers zeroed |
| any | `recordBuffer` | the record area's: a replace take as `clearBuffer` at its preparation, a playable recording as it was | the slot's change counted; record.md's state table |

**What drives its rows** (`test/engine_check/buffers.scd`, but for the recordings, which `record.scd` walks): a bad file, `"a missing or unreadable file leaves the slot unchanged"` and `"a % file loaded during a recording cancels it: no take, nothing written ..."`; a good short file, `"loadBuffer empties the slot (the voices reading it fade) until the file has been read"`, `"a slot no voice plays loads without the fade wait ..."` and `"buffers: a load and a clear set the slot's gain to 1 ..."`; a long file and its check, `"buffers: a long file's check lets commands in between its chunks ..."` (checking), `"buffers: a damaged long file is reported once its check ends ..."` and `"buffers: an error in a long load's check reports bufferLoadFailed with the load's number ..."` (the check fails), `"buffers: a long file's check superseded by a clear stops at its next chunk ..."`, `"buffers: a recording sent during a long file's check wins ..."`, `"buffers: a short load sent during a long file's check wins ..."` and `"buffers: of two long loads the later wins when its check ends first ..."` (superseded), `"buffers: a load rejected during a long file's check leaves that load to apply ..."`; the fade's end, `"loadBuffer fades the voice at once and reads the file only after the fade"`; a failed read, `"a file gone when the server reads it is reported by bufferLoadFailed"` and, emptied or not, `"a failed server read reports the slot emptied only while nothing has changed it since (#1035) ..."`; the reads done, `"loadBuffer sets the valid length from the file"`; the peaks write's action, `"buffers: a slot being loaded is at the server's rate until its length is reported ..."`; an older load's dropped steps, `"a load inside the fade wait wins over a vanished file's load ..."` and `"buffers: two quick loads report 0 s as load 1, then 0 s and 0.1 s as load 2, never load 1's 0.5 s ..."`; a clear and its fade, `"clearBuffer fades the voice at once and leaves the buffers until the fade is over"` and `"clearBuffer zeroes the slot"`; a recording, `record.scd`'s state table walk (rows 1 to 4, and 4 over a load taking effect). Every row has a check.

### The three counters

| Counter | Counts | Role |
|---|---|---|
| `slotChanges[i]` (`slotChanged`) | every change to the slot: a load that takes effect, a clear, a recording, a stop (`stopRecordSlot`: one that keeps its take re-keys it, `take[\change]`), a cancel by a bad or long load | two roles (#946): "something changed the slot", the guard every delayed step reads (`afterSlotFade`, a load's reads and peaks write, a recording's steps), and "the token of the last change", which a kept take's steps carry; an arming's peaks write asks a `current` function for that reason |
| `bufferLoads[i]` | the slot's `loadBuffer` commands, at the command, before any check (Lua's `loads_sent`) | the load's number: `bufferLoadFailed` names it, and every `bufferState` report names it modulo 7 (#578) once it and every load before it have an outcome (`bufferStateLoad`, with `areaState[\buffers][\checks]`, the loads whose check routine runs, #983) |
| `loadsSuperseded(i)` (`areaState[\buffers][\loadsSuperseded]`) | the newest load number that can no longer take effect, raised by `slotChanged` (to `bufferLoads[i]`, or to the load that takes effect) | a long load's check asks it after every chunk (`load > loadsSuperseded(i)`) and stops once superseded; a shadow of `slotChanges` in load numbers |

## Audio Sources: Lua side

**Lua side** (`lib/buffers.lua`, `lib/record.lua`; the behavior in detail is in `docs/notes/lua/buffers.md` and `docs/notes/lua/record.md`):
- **Per-voice source**: option `v<i>_source` over `SOURCE_OPTIONS = {"synth", "buf 1", ..., "buf 8", "input"}` (built from `NUM_BUFFERS`), default synth, held in `voices[i].source`. The action always sends `setGrainSource(i - 1, x - 1)`, then for a running voice `sync_voice_values_to_engine`, clamps the grid `param_page` and redraws the grid (the screen and arc follow on the next frame, as for every param action: `request_redraw`, see `docs/notes/lua/ui/redraws.md`). `voice_uses_synth(i)` (source 1), `voice_uses_buffer(i)` (sources 2-9; input is not a buffer) and `voice_source_label(i)` (the option name) are the helpers. The source params sit at the top of each voice's granular section with `v<i>_buf_pos`, `v<i>_buf_rate`, `v<i>_buf_scan`
- **Behavior rules (design §1, amended for the input source)**: for a buffer source (`voice_uses_buffer`): E3, arc ring 2 and MAIN's main parameter are `buf_pos` (label `pos`, through `main_param_entry`), the 256 grid's first faders are the buffer params then the level and pan (the grain record's first fader group, `voice_level_fader_keys`), `randomize_voice` sets `buf_pos` (0-1), `buf_rate` (0.5-2, `2 ^ (r * 2 - 1)`) and `buf_scan` (-0.5..0.5) plus grain size/pitch instead of synthesis params, `gentle_mutate` mutates the buffer params instead of synthesis params, and `drift_update` drifts `buf_pos` as well as grain pitch. For the input source both the synth and the buffer params are dead in the engine (except `amp` and `pan`, which every source applies), so the main param is `grain_size` (`INPUT_MAIN_PARAM`, label `size`, `%.2f s`), its faders start with the grain params (then `amp` and `pan`), and `randomize_voice`, `gentle_mutate` and `drift_update` touch only grain params. Test with `voice_uses_synth` / `voice_uses_buffer`, never `not voice_uses_synth` (that includes input). `source` is never randomized or mutated; freeze covers the buffer params. `voice_buffer_slot(i)` is the slot (1-8) a buffer-sourced voice reads, or nil
- **Buffers table**: `buffers[slot]` = `{name, loaded, recording, finishing, restoring, settled_empty, seconds, path, confirm_since, missing_path, loads_sent, pending_loads, saves_sent, pending_saves, records_sent, checking_from, checking_load, start, sent_start, sample_rate, file_seconds, kept_state, take_unsaved, awaiting_zero}` per slot (`awaiting_zero`: a load sent over audio, waiting for the 0 s the engine reports when the load takes effect, #401; `records_sent`: the slot's `recordBuffer` commands, `lib/record.lua`; `start`, `sent_start`, `sample_rate`, `file_seconds`: the file's start point and length, `docs/notes/lua/buffers.md`; `take_unsaved`: a take whose scratch file the engine could not write, `takeWriteFailed`, #312) (`kept_state`: what a canceled replace take had replaced, until the next length report, `docs/notes/lua/buffers.md`) (`checking_from`, `checking_load`: the length shown before a long file's load and that load's number, while the engine checks it, `docs/notes/lua/buffers.md`) (`name = "empty"` until something is loaded or recorded). `load_buffer(slot, path)` sends `loadBuffer`, shows the path in `buf<n>_file` without running its action (`set_buffer_file_param`: a silent `params:set`, which makes norns list the file's folder; a folder path is written to the param without that listing, and a folder the shell reads inside double quotes never enters it, `docs/notes/lua/buffers.md`, #480, #559) and sets `name` (the file name), `loaded` (optimistic, settled by the poll), `path`, `confirm_since = util.time()`, and clears `missing_path`; it ignores `""`, norns' `"-"` (no file chosen) and directory paths. norns' file param runs its action only when the path changes, so `record_buffer` (on start) and `clear_buffer` silently put `buf<n>_file` back at its starting folder `_path.audio` (which loads nothing and keeps the PARAMS browser in the audio folder): picking the same file again from PARAMS then loads it. The BUFFER page's file selector calls `load_buffer` directly, so it reloads even a file the param already shows, and a restored slot's param shows its path. `record_buffer(slot)` (`lib/record.lua`) sends the nine-argument `recordBuffer` from the record params (the ninth, `sent`, is `util.time() % 1000`, #565) and sets `recording`; only a replace take with no delay or threshold starts its timer at once (`buffer_record_clocks[slot]`, `record_duration`, then `finish_buffer_take(slot)`), an armed one at its "recording" report, and a playable recording ends with its "ended" report or, when none comes, with its fallback (#904: `BUFFER_SETTLE.fallback_seconds` after its length has run out, or after K3, it settles from the last known length, `docs/notes/lua/record.md`); called while the slot records, it sends `stopRecord` (and a replace take finishes at once). See `docs/notes/lua/record.md`. `finish_buffer_take` sets `finishing` and `confirm_since` (`recording` stays set, so the slot still shows `REC`; the BUFFER hint shows `K3:...`) and starts the slot's fallback clock in `buffer_record_clocks[slot]`: a press while `finishing` does nothing (no new take, no stop). **The poll settles takes and loads**: `buffer_state_changed` ignores a report that names an older load than the slot's newest (#578, Polls above) and otherwise stores the seconds and, for a slot with `confirm_since` set, on any report (repeated or not), calls `settle_buffer_slot(slot)` when the seconds are > 0 or when 0 arrives at least `BUFFER_SETTLE.confirm_seconds` (1 s) after `confirm_since` (the periodic poll can carry a value read before the engine finished: the Lua timer ends just before the engine's take completes). A load sent over audio (`awaiting_zero`, set by `load_buffer` when the slot reads audio, no long-file check is running and both polls exist) settles only after the engine's 0 s report for it: until then a report of audio is the old audio's, sent before the load reached the engine, and settles nothing; the 0 s clears `awaiting_zero`, and the next report of audio settles the load (#401). `settle_buffer_slot` (global) works from `buffers[slot].seconds`: with audio it calls `confirm_buffer_audio(slot, is_take)` (global): `loaded = true`, a take gets `name = "take <n>"` and `path` = the scratch take `_path.audio .. "strata/scratch/buf<n>.wav"` (a load keeps its name), and a slot with `restoring` set (a `load_buffers_from_disk` load), or one whose restore settled empty (`settled_empty = "restore"`), counts once in `buffers_restored`. Without audio a take leaves the slot empty (`name = "empty"`, `path = nil`; stopped in the engine's start-up window) and a load gets `loaded = false` (keeping its name); `settled_empty` records `"take"`, `"load"` or, for a load with `restoring` set, `"restore"`. Either way `recording`/`finishing` and `restoring` clear (the slot has settled; `"restore"` keeps the late count) and the fallback clock is canceled. **Late takes and loads**: under sclang load a take can complete more than 1 s after the Lua timer, and the engine reports a load only when its reads complete (16 sequential `readChannel`s for a full restore on a CM3), so a periodic 0 can settle the slot empty first; a later report with seconds > 0 for a slot with `settled_empty` set adopts it through `confirm_buffer_audio` (loaded, named, counted when restoring). Load, clear and a new recording clear `settled_empty`, so they always win. **Fallback**: if no report arrives at all (no `bufferState` poll), the fallback clock settles a still-finishing slot `BUFFER_SETTLE.fallback_seconds` (5 s) after the take ended, from the last known seconds, so K3 is never ignored for good; a playable recording whose "ended" or "canceled" never comes has one too (#904): it starts when the dub's length has run out (the slot's clock in the role `"take"` first) or at K3, and settles the slot as a take that ran (`take <n>`, loaded when its last known length is above 0, on no path when the take may be unsaved, `docs/notes/lua/record.md`); load, clear, a new recording, a settle and `cleanup` cancel it (it lives in `buffer_record_clocks`). **Failed loads**: `bufferState` alone cannot reveal a bad file loaded over audio (the engine keeps the old audio, so the report of its seconds settles the load as loaded), so the engine reports every rejected load on the `bufferLoadFailed` poll. `load_buffer` counts the slot's loads (`loads_sent`) and appends `{number, path, previous}` to `pending_loads` (every load being checked and at most `BUFFER_SETTLE.tracked_loads`, 4, others, the oldest dropped, #980). `previous` is `buffer_state_before_load(slot)`: the slot's `name`, `loaded`, `restoring`, `settled_empty`, `confirm_since`, `path`, `missing_path` and its `buf<n>_file` value. For a slot that is `recording` or `finishing` with a replace take, the engine cancels the recording when the load fails, so `previous` is the empty slot with `settled_empty = "take"` and the file param at `_path.audio`: a take that had already completed is still adopted from the next report. For a replace take still armed (also one K3 stopped whose "canceled" report has not arrived) it is `{after_cancel = true, kept = the take's previous}` instead, which `resolve_previous` turns into `kept` when the length the engine reported after "canceled" shows audio (the take had not prepared the slot) and into that empty slot when it reads 0 s (`docs/notes/lua/buffers.md`, States). `buffer_load_failed(value)` (global) decodes `slot = value % NUM_BUFFERS + 1`, then from `floor(value / NUM_BUFFERS)` the `emptied` bit (its lowest) and `load_number` (the rest); it ignores NaN, infinities, negative, fractional and out-of-range values. It then looks the number up in the slot's `pending_loads`. The state the failed load left is its `previous` (through `resolve_previous`), or, when `emptied`, an empty slot (`empty_buffer_state(false)`). Not found (a repeat, a load before the newest `tracked_loads`, or a clear or new recording since, both of which empty `pending_loads`): nothing happens, but in a restoring slot that tracks no load, which takes a failure of load 1 for the restore's own and empties (#980), in a slot that tracks no load and awaits a plain load's read, or shows it or a restore settled `unsettled`, which empties on an emptied failure (#1035, #1040), and for the load just before the oldest tracked one, sent over its state, whose emptied failure is spliced into that load's `previous` (#1040). Found and newest: the slot gets that state, including the file param (silently, `set_buffer_file_param`), so the bad path never reaches `buffers.data` and a failed restore is forgotten. Found but superseded by a load sent before the report arrived: the next tracked load inherits that state, so if it fails too the slot shows what the failed load left. Only the reported entry is removed: reports can arrive out of load order (a failed read is reported after the fade), and the splice gives the right result in either order. `buffers_restored` needs no undo: a restore loads into a slot that is empty at start, so no report of old audio counted it. Either way the console names the file and `buffer_page_flash("buf <n> load failed")` shows on the BUFFER page. `clear_buffer(slot)` sends `clearBuffer` and resets the slot (including `finishing`, `restoring`, `settled_empty`, `confirm_since`, `missing_path`; a new recording clears `restoring`, `settled_empty`, `confirm_since` and `missing_path` too, and a load all but `confirm_since`, which it sets). Load, clear and stop cancel the slot's timer (the engine cancels its recording, even for a file it cannot read, so a bad load during a recording settles as an empty slot through `bufferLoadFailed`, or, without that report, as a load that is not loaded; never as a take under the bad file's name). `save_buffer(slot)` does `util.make_dir(buffer_audio_dir)` and `saveBuffer(slot - 1, buffer_save_path(slot), 0, 1)` (`_path.audio .. "strata/<YYYYMMDD-HHMMSS>-buf<n>.wav"`, `-2`, `-3`, ... when the name is in use, #522), counts it (`saves_sent`, tracked with its path in `pending_saves`, at most `BUFFER_SETTLE.tracked_saves`, 4), prints `saving to <path>` and returns true; the `bufferSaveResult` report then settles it (`buffer_save_result`, `docs/notes/lua/buffers.md`). A slot the engine reports as empty (`seconds <= 0` from the poll) is not saved (`save_buffer` returns false): `loaded` is set optimistically by `load_buffer` until the poll settles it, and a replace take reads 0 s until it completes. `seconds` comes only from the poll. `scratch_take_path(slot)` is the take path; `load_buffer` names a scratch-take path `take <n>`, so a restored take keeps its name. Load, record (start, stop, timer end) and clear call `buffer_display_changed()` (`request_redraw()` + `grid_redraw()`: the BUFFER page and grid page 4 show the state; then `remember()`, which writes `buffers.data` when what it would hold changed, `docs/notes/lua/buffers.md`); `buffer_state_changed` requests a screen redraw, and the grid while a grid shows page 4 (`S.lib.grid_core.any_page(S.constants.GRID_PAGES.sources)`), only when a slot's seconds change or it settles (the periodic poll repeats values). All four check the slot (1..`NUM_BUFFERS`); `cleanup` cancels the timers and stops the poll
- **Buffer params**: group `strata_buffers` (size `2 + NUM_BUFFERS * 4`): `record_duration` (0.5 s to `S.performance.buffer_seconds`, default 8), `record_level` (0-2, default 1), then per slot `buf<n>_file` (`params:add_file`, starting folder `_path.audio`; action `load_buffer`), `buf<n>_record`, `buf<n>_clear`, `buf<n>_save` triggers
- **Scenes** capture `voices[i].source` and the three buffer params (keys of the voice's `values`), never buffer contents: a recalled scene plays whatever is in the slot now. `source` switches at the end of a smooth transition (its entry is discrete, so `scene_transition_targets` skips it); the buffer params crossfade. The fill gives a scene voice without them `source = 1` and the buffer params' defaults (`docs/notes/lua/scenes.md`); `validate_scene` requires `source` to be an integer 1..`#SOURCE_OPTIONS`
