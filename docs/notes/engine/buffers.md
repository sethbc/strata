## Must not break

- **`slotChanges[i]`** guards late replies (load completion, `stopRecord` frame count) and the fade wait: a clear or load sent later always wins. A `bufferLoadFailed` report names its load's number, so it never undoes a later load, clear or recording.
- **Fade before zeroing**: load, record and clear set the slot's frames to 0 first and zero or overwrite its buffers through `afterSlotFade`. Never zero a slot directly. That covers every `\strataGrainBuf` until it frees, releasing and fading ones too: those only ever get `bufFrames 0`. `bufRateScale` is sent only with a valid length (`slotLengthPairs`).
- A missing, unreadable, empty or damaged file leaves the slot as it was (and cancels a recording in it), and is reported by `bufferLoadFailed`.
- Bufnums never change: loads read into the existing buffers.

## Polls

**Poll `bufferState`** (engine → Lua): each slot's valid seconds. matron's `/poll/value` handler is typed `"if"` (one float) and its data-blob polls are broken (`w_handle_poll_data` writes every byte to index 1), so a string or table cannot reach Lua: every message carries **one** slot as `slot_index * 100 + seconds` (`bufferStateStride = 100`; seconds ≤ 16, rounded to 0.01). Decode in Lua with `slot = math.floor(value / 100)` (0-based, so Lua slot `slot + 1`) and `seconds = value - slot * 100`. The poll is periodic: every 0.25 s it sends the next slot in turn (`bufferStateCursor`), so each slot is reported every 2 s (`numBuffers` × 0.25 s); every change (load, record start, completion and early stop, clear) is also sent immediately via `bufferStatePoll.update`. A slot reads 0 s while it records and its length once the recording completes. Lua: `init` calls `poll.set("bufferState", buffer_state_changed)` and starts it (it prints a message if the poll is missing); `buffer_state_changed` decodes the value with `BUFFER_STATE_STRIDE` (100) into `buffers[slot].seconds`, ignores slots outside 1..`NUM_BUFFERS`, and settles a take or load waiting for the engine, or adopts a late take or load (see the buffers table under Audio Sources); `cleanup` stops it.

**Poll `bufferLoadFailed`** (engine → Lua, not periodic: `addPoll(\bufferLoadFailed, func, false)`, sent only through `bufferLoadFailedPoll.update`): one message per failed load, whether or not the slot held audio. `rejectLoad` sends it at once for a missing, unreadable, unsupported, empty or damaged file, which leaves the slot as it was. `loadSlot`'s read sends it after the fade and the read when the server's `/b_readChannel` fails, which leaves the slot empty (below). `bufferState` cannot carry this: over audio the slot keeps its old length, so its reports look like a good load's, and its `slot * 100 + seconds` layout has no room for a load identifier. A second poll keeps both encodings plain. The value is one float, `bufferLoadFailedValue(i, load, emptied)` = `(load * 2 + emptied) * numBuffers + i`: `load` is the failed load's number, from `bufferLoads[i]`, which counts the slot's `loadBuffer` commands from 1 (in `loadSlot`, after the slot check); `emptied` is 1 when the failed server read left the slot zeroed and 0 when the slot is as it was. Lua's `load_buffer` counts the same commands in `buffers[slot].loads_sent`. Both start at 0 when the script starts, because norns builds a new engine for every script load. It is exact for the first 2^20 loads of a slot (float32 integers). It is sent after `rejectLoad`'s own `bufferState` 0 for a canceled recording. A failed read is reported after the fade wait and the read, so it can arrive after a later load's immediate rejection: reports are not in load order, and Lua does not assume they are. Its poll function returns the last value (0.0 before any failure, which names load 0, never sent), so a value request only repeats a report, and Lua ignores repeats. Lua: `init` sets `buffer_load_failed` as its callback and starts it (`buffer_polls.load_failed`; it prints a message if the poll is missing), and `cleanup` stops it.

## Buffer slots

- **Buffer slots**: `numBuffers = 8` slots (mirrors Lua `NUM_BUFFERS`), each a pair of mono buffers `buffersL[i]`/`buffersR[i]` (GrainBuf reads mono buffers only) of `sampleRate * bufferSeconds` frames (`bufferSeconds = 16`, mirrors `BUFFER_SECONDS`). Memory: 8 × 2 × 16 s × 48 kHz × 4 bytes ≈ 49 MB of scsynth memory. Never allocate longer buffers. `bufferFrames[i]` is the valid length (0 = empty); `bufferSampleRates[i]` the content's sample rate. bufnums never change: loads read into the existing buffers

**Buffer commands** (`loadSlot`, `recordSlot`, `clearSlot`, `writeSlot` in the engine): load opens the file with `SoundFile` (frames, channels, rate) and `readChannel`s at most `bufferSeconds` of it into the existing buffers, capped by the buffers' size (`bufferSeconds` at the **server** rate): a 96 kHz file keeps 8 s on a 48 kHz server, a 44.1 kHz file the full 16 s. **Damaged files and failed reads** were probed with scsynth 3.14:
- A WAV whose header claims more data than the file holds, and a truncated WAV, are not failures. libsndfile shortens `numFrames`, and sclang and the server both read the frames that are there.
- A corrupt or truncated FLAC keeps a sound header (48000 frames) but stops decoding early (12288 frames). The server's `/b_readChannel` then fills the rest with silence and reports nothing. So `loadSlot` decodes the frames it will read itself first (`fileDecodes`, one reused chunk array of `loadCheckFrames` = 16384 frames, synchronously: 16 s of 48 kHz stereo takes about 2 ms for a WAV and 9 ms for a FLAC on a desktop, and the file is then in the page cache for the server). A file that decodes more than `loadShortfallFrames` (4096) frames short is rejected like an unreadable one. That tolerance is one default FLAC block (85 ms at 48 kHz) and more than an MP3's encoder delay and padding (under 2 × 1152 frames), so a header count that overshoots by a codec's padding still loads. The damaged FLAC (35712 frames short) is rejected. Damage inside a FLAC's last block slips through as at most 4096 frames of silence at the end. A format whose header count is only a rough estimate that overshoots by more is rejected: an MP3 without a Xing/LAME header, which needs libsndfile 1.1 or later and is therefore not readable on norns' libsndfile anyway. libFLAC 1.4 prints `Rewinding, seeking necessary` to stderr when it seeks in a damaged FLAC; sclang cannot silence it, it is harmless, and `run_engine_check.sh` does not count it as an error.
- A corrupt Ogg reads as 0 frames, so it is rejected as empty.
- The server's read itself fails (`/fail /b_readChannel <message> <bufnum>`) only when the file vanishes or becomes unreadable between those checks and the read, for example a drive unplugged during the fade wait. The read's `fork` watches for that `/fail` with an `OSCFunc` from the server's address that matches `/b_readChannel`, one of the slot's bufnums and the quoted path in the message (`File '<path>' could not be opened: ...`). Matching the bufnum alone would not do: two back-to-back loads into an unplayed slot both read at once, so a vanished file's `/fail` would also fail the next load's good read. A next load of the very same path cannot be told apart, but it reads a file that has just vanished. The `/fail` arrives before the `/synced` that ends the wait, and the `OSCFunc` is freed after it. The slot has already been zeroed, so it keeps 0 frames (its rate is reset to the server's, only if `slotChanges` is unchanged), and the load is reported as emptied whatever came after it (Lua relies on the report to keep its tracked loads right). A load that a later load, clear or recording superseded inside the fade wait never reads, so it reports nothing.

A missing, unreadable, empty or damaged file (`rejectLoad`) is logged, reported by the `bufferLoadFailed` poll (above) and leaves the slot unchanged (before anything is zeroed), except that it cancels a recording in progress or waiting to start in that slot, or one `stopRecord` ended whose frame count has not arrived yet (`stopReplies[i]` holds that stop's `slotChanges` count until the reply; the bad load's `slotChanged` drops the reply; every `slotChanged` empties `stopReplies[i]`, so once a good load, record or clear has followed the stop there is no take left to cancel and a bad load sent after it leaves that command alone) (`stopRecording`, `slotChanged`): Lua's `load_buffer` ends the recording state, so a take that completed anyway would be adopted under the bad file's name and path (and lost at the next restore). The slot then reads 0 frames, as for a recording a clear canceled. A good load sets the slot's frames to 0 at once, zeroes the pair and reads after the fade (below); the slot's `bufferFrames`/`bufferSampleRates`, the grain synths reading it and the poll get the new length only once the reads have completed (a `server.sync` after them in a `fork`). **Fade before zeroing**: `b_zero` and `b_readChannel` complete within about a millisecond, far inside `\strataGrainBuf`'s 50 ms `hasAudio` lag, so load, record and clear first set the slot's `bufferFrames` to 0 (`bufferChanged` sends it to every grain synth reading it, and the poll reports 0) and only then zero or overwrite the buffers, through `afterSlotFade(index, change, action)`: `bufferFadeWait` (0.06 s, settable; the engine check lengthens it) later when any grain synth reads the slot (`slotPlaying`), at once otherwise, so a recording into an unplayed slot starts without delay. The delayed action runs only if `slotChanges[index]` is still `change`, so a later load, record or clear inside the wait wins (the earlier command's zeroing, read or record start is dropped, the later one does its own). `free` bumps every slot's count, so nothing waiting runs on freed buffers (the engine check frees it with a clear, a load and a recording waiting). **Grain synths that are no longer a voice's** still read their slot: one releasing after `voiceOff` (2 s), fading after a source switch, or in its kill fade. `grainSlots` maps every `\strataGrainBuf` (set in `startGrainSynth`, removed in `onFree`) to the slot it reads, and `slotGrainSynths(index)` lists the playing ones; `slotPlaying` counts them all, so a slot change waits for their fade too, and `bufferChanged` sends them `bufFrames 0` only (never a new take's length, which their tail would replay, and never a rate). `voiceOn` re-gates a releasing one with the slot as it is then (`bufferSlotPairs`). **The rate follows the audio**: `bufferChanged` and `bufferSlotPairs` send `bufRateScale` only with a valid length (`slotLengthPairs`), so a clear or recording, which set the slot to the server rate, never retunes the grains still fading out (a 44.1 kHz file's grains started in the 50 ms fade played about 1.5 semitones sharp); a take's rate arrives with its length. **`slotChanges[i]`** counts the changes to slot i (load, record, clear, stop, through `slotChanged(i)`); a reply that arrives later (the load's completion, `stopRecord`'s frame count) applies only if the count is what it was when the reply was requested, so a clear (or load, or new recording) sent before it wins. Record sets the slot to 0 frames, zeroes the pair after the fade and, after a `server.sync` (so the zeroing never lands on the take), starts a `\strataRecord` synth (two `RecordBuf`s of `In.ar(inputBus, 2) * level`, `loop: 0`, plus a `Line` with `doneAction: 2` for the duration) right after `inputSynth`, unless the recording was canceled meanwhile (`recordSynths[i]` is the token; do not use a zero completion message: it cannot be canceled before the node exists). The slot reads 0 frames until the recording completes (`onFree`), then gets its frames and the take is written to `scratchDir +/+ "buf<n>.wav"`. A new record, load (even one whose file cannot be read) or clear on the slot cancels a recording in progress or pending (`stopRecording`), which writes nothing. `stopRecord` (`stopRecordSlot`) instead keeps the take: the record synth writes its frame count (`Sweep.kr(0, SampleRate.ir)`) to the slot's `recordFrameBuses[i]`; the engine frees the synth, reads that bus (`/c_get` is answered after the `/n_free`, and the bus keeps its last value), sets `bufferFrames[i]` to it and writes the scratch take (unless `slotChanges[i]` moved meanwhile: `stopRecord` then `clearBuffer` in one go leaves the slot empty and writes nothing). Read `isPlaying` before freeing (`Node.free` clears it). A recording still waiting for its zeroed buffers has captured nothing and is just canceled. Every change updates `bufferFrames`, the grain synths reading the slot (`bufFrames`, and `bufRateScale` when the slot holds audio) and the `bufferState` poll.

File writes (`writeSlot`, `saveBuffer`, the scratch takes) are in `docs/notes/engine/files.md`.

## Audio Sources: Lua side

**Lua side** (strata.lua):
- **Per-voice source**: option `v<i>_source` over `SOURCE_OPTIONS = {"synth", "buf 1", ..., "buf 8", "input"}` (built from `NUM_BUFFERS`), default synth, held in `voices[i].source`. The action always sends `setGrainSource(i - 1, x - 1)`, then for a running voice `sync_voice_values_to_engine`, clamps the grid `param_page` and redraws the grid (the screen and arc follow on the next frame, as for every param action: `request_redraw`, see Redraws in `lua.md`). `voice_uses_synth(i)` (source 1), `voice_uses_buffer(i)` (sources 2-9; input is not a buffer) and `voice_source_label(i)` (the option name) are the helpers. The source params sit at the top of each voice's granular section with `v<i>_buf_pos`, `v<i>_buf_rate`, `v<i>_buf_scan`
- **Behavior rules (design §1, amended for the input source)**: for a buffer source (`voice_uses_buffer`): E3, arc ring 2 and MAIN's main parameter are `buf_pos` (label `pos`, through `main_param_entry`), the 256 grid's first faders are `BUFFER_FADER_KEYS` then the level and pan (`voice_level_fader_keys`), `randomize_voice` sets `buf_pos` (0-1), `buf_rate` (0.5-2, `2 ^ (r * 2 - 1)`) and `buf_scan` (-0.5..0.5) plus grain size/pitch instead of synthesis params, `gentle_mutate` mutates the buffer params instead of synthesis params, and `drift_update` drifts `buf_pos` as well as grain pitch. For the input source both the synth and the buffer params are dead in the engine (except `amp` and `pan`, which every source applies), so the main param is `grain_size` (`INPUT_MAIN_PARAM`, label `size`, `%.2f s`), its faders start with the grain params (then `amp` and `pan`), and `randomize_voice`, `gentle_mutate` and `drift_update` touch only grain params. Test with `voice_uses_synth` / `voice_uses_buffer`, never `not voice_uses_synth` (that includes input). `source` is never randomized or mutated; freeze covers the buffer params. `voice_buffer_slot(i)` is the slot (1-8) a buffer-sourced voice reads, or nil
- **Buffers table**: `buffers[slot]` = `{name, loaded, recording, finishing, restoring, settled_empty, seconds, path, confirm_since, missing_path, loads_sent, pending_loads}` per slot (`name = "empty"` until something is loaded or recorded). `load_buffer(slot, path)` sends `loadBuffer`, shows the path in `buf<n>_file` without running its action (`set_buffer_file_param`, a silent `params:set`) and sets `name` (the file name), `loaded` (optimistic, settled by the poll), `path`, `confirm_since = util.time()`, and clears `missing_path`; it ignores `""`, norns' `"-"` (no file chosen) and directory paths. norns' file param runs its action only when the path changes, so `record_buffer` (on start) and `clear_buffer` silently put `buf<n>_file` back at its starting folder `_path.audio` (which loads nothing and keeps the PARAMS browser in the audio folder): picking the same file again from PARAMS then loads it. The BUFFER page's file selector calls `load_buffer` directly, so it reloads even a file the param already shows, and a restored slot's param shows its path. `record_buffer(slot)` sends `recordBuffer(slot - 1, record_duration, record_level)`, sets `recording` and starts a `clock.run` timer of `record_duration` (`buffer_record_clocks[slot]`) that ends it with `finish_buffer_take(slot)`; called while the slot records, it sends `stopRecord` and calls `finish_buffer_take` at once. `finish_buffer_take` sets `finishing` and `confirm_since` (`recording` stays set, so the slot still shows `REC`; the BUFFER hint shows `K3:...`) and starts the slot's fallback clock in `buffer_record_clocks[slot]`: a press while `finishing` does nothing (no new take, no stop). **The poll settles takes and loads**: `buffer_state_changed` stores the seconds and, for a slot with `confirm_since` set, on any report (repeated or not), calls `settle_buffer_slot(slot)` when the seconds are > 0 or when 0 arrives at least `BUFFER_SETTLE.confirm_seconds` (1 s) after `confirm_since` (the periodic poll can carry a value read before the engine finished: the Lua timer ends just before the engine's take completes). `settle_buffer_slot` (global) works from `buffers[slot].seconds`: with audio it calls `confirm_buffer_audio(slot, is_take)` (global): `loaded = true`, a take gets `name = "take <n>"` and `path` = the scratch take `_path.audio .. "strata/scratch/buf<n>.wav"` (a load keeps its name), and a slot with `restoring` set (a `load_buffers_from_disk` load) counts once in `buffers_restored` (`restoring` stays set until then). Without audio a take leaves the slot empty (`name = "empty"`, `path = nil`; stopped in the engine's start-up window) and a load gets `loaded = false` (keeping its name); `settled_empty` records `"take"` or `"load"`. Either way `recording`/`finishing` clear and the fallback clock is canceled. **Late takes and loads**: under sclang load a take can complete more than 1 s after the Lua timer, and the engine reports a load only when its reads complete (16 sequential `readChannel`s for a full restore on a CM3), so a periodic 0 can settle the slot empty first; a later report with seconds > 0 for a slot with `settled_empty` set adopts it through `confirm_buffer_audio` (loaded, named, counted when restoring). Load, clear and a new recording clear `settled_empty`, so they always win. **Fallback**: if no report arrives at all (no `bufferState` poll), the fallback clock settles a still-finishing slot `BUFFER_SETTLE.fallback_seconds` (5 s) after the take ended, from the last known seconds, so K3 is never ignored for good; load, clear, a new recording, a settle and `cleanup` cancel it (it lives in `buffer_record_clocks`). **Failed loads**: `bufferState` alone cannot reveal a bad file loaded over audio (the engine keeps the old audio, so the report of its seconds settles the load as loaded), so the engine reports every rejected load on the `bufferLoadFailed` poll. `load_buffer` counts the slot's loads (`loads_sent`) and appends `{number, path, previous}` to `pending_loads` (at most `BUFFER_SETTLE.tracked_loads`, 4, the oldest dropped). `previous` is `buffer_state_before_load(slot)`: the slot's `name`, `loaded`, `restoring`, `settled_empty`, `confirm_since`, `path`, `missing_path` and its `buf<n>_file` value. For a slot that is `recording` or `finishing`, the engine cancels the recording when the load fails, so `previous` is the empty slot with `settled_empty = "take"` and the file param at `_path.audio`: a take that had already completed is still adopted from the next report. `buffer_load_failed(value)` (global) decodes `slot = value % NUM_BUFFERS + 1`, then from `floor(value / NUM_BUFFERS)` the `emptied` bit (its lowest) and `load_number` (the rest); it ignores NaN, infinities, negative, fractional and out-of-range values. It then looks the number up in the slot's `pending_loads`. The state the failed load left is its `previous`, or, when `emptied`, an empty slot (`empty_buffer_state(false)`). Not found (a repeat, a load before the newest `tracked_loads`, or a clear or new recording since, both of which empty `pending_loads`): nothing happens. Found and newest: the slot gets that state, including the file param (silently, `set_buffer_file_param`), so the bad path never reaches `buffers.data` and a failed restore is forgotten. Found but superseded by a load sent before the report arrived: the next tracked load inherits that state, so if it fails too the slot shows what the failed load left. Only the reported entry is removed: reports can arrive out of load order (a failed read is reported after the fade), and the splice gives the right result in either order. `buffers_restored` needs no undo: a restore loads into a slot that is empty at start, so no report of old audio counted it. Either way the console names the file and `buffer_page_flash("buf <n> load failed")` shows on the BUFFER page. `clear_buffer(slot)` sends `clearBuffer` and resets the slot (including `finishing`, `restoring`, `settled_empty`, `confirm_since`, `missing_path`; a new recording clears `restoring`, `settled_empty`, `confirm_since` and `missing_path` too, and a load all but `confirm_since`, which it sets). Load, clear and stop cancel the slot's timer (the engine cancels its recording, even for a file it cannot read, so a bad load during a recording settles as an empty slot through `bufferLoadFailed`, or, without that report, as a load that is not loaded; never as a take under the bad file's name). `save_buffer(slot)` does `util.make_dir(buffer_audio_dir)` and `saveBuffer(slot - 1, buffer_save_path(slot))` (`_path.audio .. "strata/<YYYYMMDD-HHMMSS>-buf<n>.wav"`) and prints the path; a slot the engine reports as empty (`seconds <= 0` from the poll) is not saved: `loaded` is set optimistically by `load_buffer` until the poll settles it, and a recording reads 0 s until it completes. `seconds` comes only from the poll. `scratch_take_path(slot)` is the take path; `load_buffer` names a scratch-take path `take <n>`, so a restored take keeps its name. Load, record (start, stop, timer end) and clear call `buffer_display_changed()` (`request_redraw()` + `grid_redraw()`: the BUFFER page and grid page 4 show the state); `buffer_state_changed` requests a screen redraw, and the grid while a grid shows page 4 (`S.lib.grid_core.any_page(4)`), only when a slot's seconds change or it settles (the periodic poll repeats values). All four check the slot (1..`NUM_BUFFERS`); `cleanup` cancels the timers and stops the poll
- **Buffer params**: group `strata_buffers` (size `2 + NUM_BUFFERS * 4`): `record_duration` (0.5-`BUFFER_SECONDS` s, default 8), `record_level` (0-2, default 1), then per slot `buf<n>_file` (`params:add_file`, starting folder `_path.audio`; action `load_buffer`), `buf<n>_record`, `buf<n>_clear`, `buf<n>_save` triggers
- **Scenes** capture `voices[i].source` and the three buffer params (through `GRAIN_PARAM_IDS`), never buffer contents: a recalled scene plays whatever is in the slot now. `source` switches at the end of a smooth transition (it is not in `params`/`grain`, so `scene_transition_targets` skips it); the buffer params crossfade. `VOICE_SCENE_DEFAULTS` gives older scenes `source = 1` and the buffer params' defaults; `validate_scene` requires `source` to be an integer 1..`#SOURCE_OPTIONS`
