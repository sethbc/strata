## Must not break

- **Freeze acts through a synth voice's ring writer, an input or voice-source voice's copy ring, its grain synth's ring and the `freeze` control, never by stopping a grain synth.** A freeze and a `freezeMode` act, then return false, so `setGrainParam` also stores the control and sends it: `freeze` is what stops a slot's scan (`scanRate`) and moves a frozen ring's read point (`ringScanOffset`). An unfreeze (`freeze` 0) stores and sends the control itself (`unfreezeWithControl`), so it goes in one bundle with the rest of the unfreeze.
- **The copy family serves the input and the voice sources alike** (3.8, package 1d): `freezesByCopy(source)` (the input or a voice source) picks the copy; `frozenOnInput`, `readsInputCopy`, `copyInputToCopyRing`, `copyInputSpan` and `returnToInputRing` keep their names with the meaning "a ring another writer writes". A voice source's copy is of the read voice's output ring (`ringBuffersFor`, its head through `ringHeadFrame(bus)`, at history 0), and its spectral copy writer reads the read voice's tap in the tap group. `readsInputCopy` also asks that the voice still reads the source it froze. `spectralHoldsVoice` stays a synth-source voice's alone, so a voice source's freeze never makes a type switch wait.
- **An input freeze never touches the voice's own ring or its writer** (#494, #495), nor does a voice source's. Its copy goes into the voice's copy ring (`copyRingFor`, the rings area's), which only the voice's input grain synths are pointed at, and its spectral writer is a node of its own on the copy ring. The voice ring holds only what its writer records from the voice bus, so a synth-source grain synth, whose path carries no voice level, never plays input audio: not one a switch to the input leaves releasing, not a new one after a switch back to the synth, and not one a voice stopped while frozen on the input starts on its synth.
- **An unfreeze's re-point and the grain synth's `freeze` 0 land in one block.** `unfreezeWithControl` sends what `unfreezeVoice` sends (the readers set back to the input ring, a copy writer freed, a synth voice's writer resumed or replaced) and the kept control's `freeze` 0 in one `makeBundle`. `ringGrainReader` holds the freeze flag for the block (#535): a reader set back to the input ring a block before its `freeze` 0 starts that block's grains a further `grainMaxSeconds` back, on neither read point (the rings check shows it with the two split across blocks).
- **Fade before overwriting a copy ring.** The input copy is the one ring write that is not a writer's, and it goes into the voice's copy ring: that ring's readers (`copyRingReaders`) get `ringLevel 0` and the copy waits `bufferFadeWait` when any plays, at once otherwise. They are the voice's input grain synths reading the copy and those set back from it within `freezeLeaveSeconds` (a synth-source grain synth is never one), so a copy waits only for a refreeze soon after an unfreeze. Every step after a wait runs only while `ringChanges[voice]` is unchanged and no later copy started: an unfreeze, refreeze or source switch wins. The faded readers get `ringLevel 1` back once the copy is in, or abandoned, by the latest copy only.
- **A copy is in only if it ran inside its room** (#809). The server runs a `/b_gen copy` when its queue gets to it (behind a long `/b_read`, for example), while the source ring's writer goes on. So the copy reads the head again after its `server.sync` and lands only when `copyOnTime`: the head moved less than `copyRoomFrames` from the read point's (counted round the ring), and less than that time passed from the read's reply to `/synced`. Otherwise, or when the server never gave a head (`ringHeadFrame`'s 1 s), it is made again from a fresh read point, while the copy is current, up to `copyAttempts` (8; the check sets a smaller bound, `areaState[\freeze][\copyAttempts]`). After the second late copy one console line says so (`copyLateLineAttempt`, 2): an attempt with no head is counted apart, as no copy, never as a late one (#835), and the abandon's line (`copyAbandonReason`) names both counts ("the server gave no head in n attempts" when none was late); a copy that then lands freezes the voice on its own read point, a little later than the freeze was asked for, as `[F]` says. A late reply to a head read that timed out can answer the next read (`Bus.get` matches the reply by the bus alone): that read is then older than it seems, which only makes its copy count as later (its room is counted from the head it used), and the copy's own `server.sync` delivers every earlier reply first, so the read after a copy is never an old one. The hold is abandoned (`abandonCopy`: one console line, then `unfreezeWithControl(voice, 0)`, so the engine's freeze state and its grain synths' `freeze` read 0) only for a refused span or once the bound is spent. Each attempt, its re-read and the abandon are steps of the copy: each runs only while it is current, so a switch, an unfreeze, a second freeze or the area's `stop` during any attempt ends the loop with no abandon (the voice's stop does not: a stopped voice is still frozen, and its copy goes on). Each attempt reads the history once (`copyHistory`) and hands it to `copyInputSpan` and `copyOnTime`, so its room is counted at the history its copy used. Meanwhile nothing reads the copy ring: the readers a refreeze faded stay at `ringLevel 0` until a copy lands or the loop ends (silence from them), and a live grain synth that was no reader plays its live ring at `freeze` 1 (the frozen read offset on a moving head: the read voice, about half a second late) until the copy points it at the copy. An abandon is reported to Lua (#858): `abandonCopy` counts it (`\ended`) and updates the `freezeEnded` poll with `freezeEndedValue(voice, count)`, so Lua sets `v<i>_freeze` to 0 (MAIN's `[F]` clears) without sending an unfreeze back (`docs/notes/lua/freeze.md`); with eight attempts, an abandon needs a server queue held for seconds eight times over.
- **`copyInputSpan` refuses a source ring shorter than the copy ring** (#809), with one console line (`postFreezeLine`): its span would leave the copy's start unwritten. Every source ring is at least as long today (the input ring, the 4 s output rings).
- **One writer per ring.** A synth voice's spectral writer changes by `Synth.replace` of its ring writer (the old node freed in the same server step); `synths[ringWrite<i>]`, the writers' one record (#943), always names the running one, so the rings area's `stop` frees it. A copy ring has at most one writer, a spectral input freeze's (`synths[copyWrite<i>]`, `copyWriterKeys`), from the copy's landing to the unfreeze; the freeze area's `stop` frees any left. All writers are `effectKeys`: plain messages (`run`, `replace`), and a copy writer is freed quietly (`sendToSynth`: one whose `/s_new` found no room never started). A freeze changes a synth voice's ring writer only with `run` (hold) or `Synth.replace` (spectral), never otherwise.
- **A replaced writer goes on from the write head** (#801). A spectral freeze and its unfreeze replace a synth voice's writer (`replaceRingWriter`, `resume` 1), and the new writer starts one block after the old one's last report on the phase bus (`ringWritePhase`, [rings.md](rings.md)). It never resets a `Phasor` with a trigger on its first sample: SuperCollider 3.13's `Phasor` (norns') never sees one, and that started every replaced writer at frame 0 on norns, so a spectral freeze opened with about half a second of the ring's end, often silence. A copy writer is a new node (`resume` 0) and starts at its phase bus, the copy's end (0).
- **Spectral only on the high tier, and only for a ring.** `\strataRingWriteSpectral` is added only when `tier == \high`; `freezeModeFor` gives `\hold` on standard and for a buffer voice whatever `freezeMode` says.
- **No `LocalBuf`, in this def or any engine SynthDef.** Building a `LocalBuf` into a SynthDef corrupts sclang 3.13's garbage collector (norns runs 3.13), and sclang aborts a little later wherever the collector next runs: in CI the engine check died in the buffers, files or performance area. The spectral writer's FFT buffers are server buffers (`\spectralBuffers`, one pair per voice on the high tier, passed as `fftL`/`fftR`); a voice's pair serves one node at a time, its synth freeze's writer or its input freeze's copy writer, since an unfreeze frees the one before the other can start. `test/unit/structure_test.lua` fails on any `LocalBuf` in the engine source outside comments.
- **History is 0 inside a frozen input copy.** The freeze area wraps the grains area's `history` handler: while the voice is frozen on the input it keeps the value and sends nothing; the unfreeze sets the grain synth back to the input ring at that history.
- **A switch unfreezes.** `replaceGrainSynth` calls `unfreezeVoice` first; it puts the kept `freeze` control at 0, so the new grain synth starts unfrozen (Lua's `source_change` hook then sets `v<i>_freeze` 0 too).
- **What a ring grain synth reads is `grainReadPairs`' answer**: the start, the re-gate, `pointAtCopyRing` and the input channel's handler all send it, never pairs of their own (`grainControlPairs` ends with it). `returnToInputRing(voice, source)` alone keeps its own pairs, of the source the unfreeze was given (the input channel applied: `channelPair`): it sets back synths the voice may no longer own (a switch calls it with `grainSource` already changed).
- **`inputReaders` holds only playing synths**: `noteInputReader` adds a grain synth that reads the copy (at its start, its re-gate and `pointAtCopyRing`), and `watchVoiceSynth`'s `onFree` removes it (`forgetInputReader`), as it does `ringReaders`; a note synth's watcher (`watchNoteSynth`) removes it the same way.
- **An input freeze reaches the voice's extra notes** (3.5, `docs/notes/engine/notes.md`): `pointAtCopyRing` points the own grain synth and every live extra input note at the copy (`setGrainSynths`) and counts each among the readers, a note started while the voice is frozen reads the copy from its start (`grainControlPairs`), the copy's fade and `returnToInputRing` reach them through `inputReaders`, and the freeze control reaches them (the plain set and `unfreezeWithControl`, through `setGrainSynths`). A synth voice's freeze changes no note on its own: Lua cuts its extra notes, and its later notes are streams of the frozen ring (`\strataGrainRing`s of the voice ring at `noteRate`); its unfreeze (`unfreezeWithControl`, through the notes area's `notesUnfrozen`, in the same bundle) returns the own grain synth's `noteRate` to 1 and its park to open (the own voice synth's park followed the own note's all through the freeze, ruling 44, so a parked own note makes no sound), and cuts the ring-stream notes, restarting each live one as a voice synth, silent (ruling 45).
- **The kept `freeze` control is 1 while frozen and 0 after an unfreeze**: `freezeVoice` sets 1 where it sets `\frozen`, `unfreezeVoice` 0, so a mode change (unfreeze, then freeze) leaves 1 and a grain synth a start or re-gate builds is frozen too.
- **Real-time memory.** A spectral writer takes about 80 KB of the pool (two 2048-frame FFT chains; their FFT buffers are server buffers, outside the pool); a spectral input freeze runs it beside the voice's plain writer (a few KB more than 3.2's replacement did). The `memory` area's high run engages spectral freeze on every voice, and the floor it holds the pool to and what it leaves free are in [memory.md](memory.md).
- **Buffer memory.** The copy rings are ordinary RAM (`b_alloc`), allocated once by the rings area beside the voice rings: 7 × 2 × 4 s at the server rate, 10.8 MB at 48 kHz, on both tiers, counted in the high tier's step-down (`highMemoryBytes`, [performance.md](performance.md)). Their bufnums never change.

## The freeze area

`lib/engine/StrataFreeze.sc`, order 110; its `addCommands` hook adds the `freezeEnded` poll (#858; not periodic, one message per freeze the engine ended on its own, `docs/notes/engine/buffers.md`, The polls' encodings). `areaState[\freeze]`, per voice:

| Key | What |
|-----|------|
| `\frozen` | Boolean |
| `\mode` | `\hold` or `\spectral` while frozen, else nil |
| `\source` | the source it froze (a source changed while the voice was stopped is unfrozen and frozen again) |
| `\copied` | an input voice's copy is in its copy ring and its grain synth reads it |
| `\copies` | the number of the voice's latest input copy |
| `\faded` | the copy ring readers a pending copy set to `ringLevel 0` |
| `\inputReaders` | (one for all voices) input grain synths reading their voice's copy, or set back from it → `(voice, until)`: `until` nil while they read it, the time they stop counting once set back. `noteInputReader` adds one (a start, a re-gate, `pointAtCopyRing`); it is removed when it frees (`forgetInputReader`, from `onFree`) or, set back, after `until` (`copyRingReaders`) |
| (none: `pastStop`) | the engine's past-stop flag (`StrataUtil.sc`, 3.9, #942; before, the area kept its own `\stopped`), true from the start of `free`'s stop phase: a copy still waiting does nothing, no copy writer starts and no ring writer is replaced |
| `\ended` | per voice, the freezes the engine ended on its own (`abandonCopy`), counted from 1 as `freezeEnded` reports them (#858) |
| `\endedPoll` | (one for all voices) the `freezeEnded` poll (`addFreezePoll`, the area's `addCommands`) |
| `\copyAttempts` | (one for all voices) the engine check's bound on a copy's attempts (`copyAttempts_`); nil: `copyAttempts` is 8 |
| `\beforeCopy` | (one for all voices) the engine check's step before each copy's message, a function of the voice and the attempt (`beforeCopyHook_`); nil: nothing |
| `\postLine` | (one for all voices) the engine check's collector of the area's console lines (`postFreezeLine`); nil: each line is posted |
| `\spectralBuffers` | (high tier only, else empty) each voice's `[left, right]` FFT buffers of `spectralFrames`, for its spectral writer; the area's `free` frees them |

The spectral copy writers are `synths[copyWrite<i>]` (`copyWriterKeys`, the area's `effectKeys`). An input voice's is at the tail of `voiceGroup`; a voice source's (3.8) at the tail of the record area's tap group, which the record area's `stop` (order 130) frees before this area's `stop` (110) runs: there the group's free takes the copy writer, and `stopCopyWriters`' later free of it is quiet (`sendToSynth`). The copy rings themselves are the rings area's (`areaState[\rings][\copyL]`, `\copyR`, `\copyPhaseBuses`; `copyRingFor(voice)`, [rings.md](rings.md)).

Methods: `spectralFrames` (2048), `spectralDither` (0.00001), `freezeLeaveSeconds` (`grainMaxSeconds + ringReadMargin`), `scanRate(bufScan, freeze)`, `ringScanOffset(bufScan, freeze)`, `freezeVoice(voice)`, `unfreezeVoice(voice)`, `unfreezeWithControl(voice, value)`, `setFreezeMode(voice, value)`, `freezeModeFor(voice)`, `spectralHoldsVoice(voice)`, `freezesByCopy(source)`, `frozenOnInput(voice)`, `readsInputCopy(voice)`, `channelPair(voice, source, ring)`, `grainReadPairs(voice)`, `ringHeadFrame(bus)` (through `areaCall`, from the copy's fork), `beforeCopyHook` (the engine check's step before each copy's message, `areaState[\freeze][\beforeCopy]`, nil: nothing), `copyAttempts` (and `copyAttempts_`, the check's bound), `copyLateLineAttempt`, `copyAbandonReason(room, attempts, late, missing)`, `frozenReachSeconds`, `copyHistory(voice)`, `copyRoomFrames(sourceFrames, history)`, `copyOnTime(head, after, seconds, ringFrames, history)`, `abandonCopy(voice, why)` (through `areaCall`, from the copy's fork; it reports on `freezeEnded`), `addFreezePoll`, `freezeEndedPoll`, `freezeEndedValue(voice, count)` (`ended * numVoices + voice`; one expression on its own line, which the docs test evaluates to feed Lua's handler), `postFreezeLine(line)` (`areaState[\freeze][\postLine]`, the check's), `noteInputReader(voice, synth)`, `forgetInputReader(synth)`, `copyRingReaders(voice)`, `copyInputToCopyRing(voice)`, `holdCopyRing(voice)`, `pointAtCopyRing(voice)`, `copyWriterKeys`, `startCopyWriter(voice)`, `stopCopyWriter(voice)`, `stopCopyWriters`, `ringWriterFor(voice)` (and `pauseRingWriter`, `resumeRingWriter`, `replaceRingWriter`: a synth voice's only).

Both controls come through `setGrainParam`: `freeze` 0 (unfrozen) or 1 (frozen), `freezeMode` 0 (hold) or 1 (spectral).

## State by event

A voice's freeze, running or stopped (a freeze acts on a stopped voice too: its ring writer and its copy ring are persistent). The states, read from `areaState[\freeze]` and the nodes:
- **unfrozen**: `\frozen` false (`\mode` and `\source` nil, `\copied` false), the kept `freeze` 0.
- **hold on synth**: frozen with `\source` 0 and `\mode` `\hold`: the voice's ring writer paused.
- **spectral on synth**: `\source` 0, `\mode` `\spectral` (high tier): the ring writer replaced by `\strataRingWriteSpectral`. A type switch made meanwhile waits (`voiceTypeWaits`, derived: [types.md](types.md)).
- **hold on slot**: `\source` a slot (always `\hold`): the grain synths' `freeze` 1 stops the scan.
- **copy pending**: `\source` the input or a voice source, `\copied` false, the copy's routine current (the readers it faded at `ringLevel 0`), in hold or spectral.
- **copy held**: `\copied` true, `\mode` `\hold`: the voice's ring grain synths read the copy ring.
- **copy held, spectral**: `\copied` true, `\mode` `\spectral`, and the copy writer (`copyWrite<i>`) writing the source into the copy ring.
- **stale**: any of the frozen states on a `\source` that is no longer `grainSource[voice]`: the source was changed while the voice was stopped, which changes no freeze. A start ends it: Lua sends `freeze` before `voiceOn` (#325).

Four readers derive the kind of freeze from different fields (`frozenOnInput`: the frozen source; `spectralHoldsVoice`: the mode and the frozen source; `readsInputCopy`: both sources and `\copied`; the notes area's `frozenSynthVoice`: `grainSource` and `\frozen`, never the frozen source). They agree in every state but stale, where `frozenSynthVoice` takes a stale freeze of a voice now on its synth source for a synth freeze (#887, read in the code, unreachable from Lua's order).

No check walks every row of the table.

The copy's events (it lands, it is late, it is abandoned) happen only in copy pending: a copy whose freeze ended, or that a later copy replaced, runs none of its steps (`current`: `\copies` and `ringChanges[voice]` unchanged and the engine not past stop). The states the keys can hold and no event makes: `\copied` on a synth source or a slot; a copy writer with `\mode` `\hold`; a `\mode` with `\frozen` false; spectral on the standard tier (`freezeModeFor` gives hold there).

## What a ring grain synth reads

`grainReadPairs(voice)` is the one answer, as `\strataGrainRing` controls `[\bufL, bufnum, \bufR, bufnum, \phaseBus, index, \history, seconds]`:
- the synth source: the voice's ring at history 0 (history is for the input ring, so a voice that leaves the input never reads a wrapped ring);
- the input source: the input ring at the voice's kept history (`grainControls[voice][\history] ? 0`), or, when `readsInputCopy(voice)` (on the input, frozen on the input, the copy in: `\copied`), the voice's copy ring at history 0; either with the input channel applied (`channelPair`: 0 `[L, R]`, 1 `[L, L]`, 2 `[R, R]`);
- a voice source (3.8): the read voice's output ring at history 0, or its frozen copy at history 0;
- a buffer source: nothing (`[]`), so a `\strataGrainBuf` gets no new control.

`grainControlPairs` ends with it (after the kept controls, so it wins over the kept history), so `startGrainSynth` (a `voiceOn`, a switch, the late-gate restart in `onFree`) and `gateVoice`'s re-gate (one `setMsg`, through `sendToSynth`) send it; `pointAtCopyRing` sends it when the copy lands or a freeze is resent. Each of them then calls `noteInputReader`, which counts the synth in `\inputReaders` when it reads the copy, so `returnToInputRing` reaches it on unfreeze. A restart while the copy still waits for its fade reads the input ring at the voice's history; the copy, once in, points it at the copy ring.

## What each source holds

| Source | hold | spectral (high tier) |
|---|---|---|
| synth | the voice's writer is paused (`/n_run 0`); the phase bus keeps its last frame, so the grains read the frozen ring | the writer is replaced by `\strataRingWriteSpectral` reading the voice bus: the ring keeps receiving one held spectrum |
| input | the 4 s of the input ring ending at the voice's read point (the head minus `ringReadMargin + history`) are copied into its copy ring (one `/b_gen copy` per channel, two when the span wraps the input ring's end), oldest first from frame 0; the copy ring's phase bus is set to 0 (the copy's end) and the live grain synth gets the copy ring, its phase bus and history 0 with a `set`. The voice's own ring and writer go on as ever (its ring holds its voice bus: silence, as an input voice's stage writes its mirror later in the block) | the same copy, then a spectral writer of `inputBus` into the copy ring (`copyWrite<i>`), starting from the copy's end; the voice's own writer goes on writing its voice bus |
| voice source (3.8) | the 4 s of the read voice's output ring ending `ringReadMargin` behind its head copied into the voice's copy ring, as the input's (the span always wraps: the ring is as long as the copy) | the same copy, then a spectral writer of the read voice's tap (`copyWrite<i>`, at the tail of the tap group) into the copy ring |
| buffer | `scanRate` is `bufScan × (1 − freeze)`: the position holds while spread, pitch and the draws still move | not offered: holds |

- **Unfreeze** reverses each step. A paused writer resumes from its own phase (the grains may cross the seam between old and new audio once; for the reader's lookback they read the ring's newest audio from before the freeze, the tail an unfreeze under a parked own note leaves: accepted, `docs/notes/engine/notes.md`, rulings 48 and 49). A synth voice's spectral writer is replaced by a `\strataRingWrite` of the voice bus, which carries on from the phase bus (`resume` 1), and then a type switch that waited for the unfreeze is applied (`applyWaitingVoiceType`: `setVoiceType` under a spectral freeze only records the type, since the held spectrum takes its phases from the voice synth; `spectralHoldsVoice` says when, [types.md](types.md)). Every path that ends a spectral freeze runs `unfreezeVoice`, so each applies it: the freeze param's unfreeze in its own bundle (`unfreezeWithControl`), a `freezeMode` change while frozen before it freezes again in hold (one bundle with that freeze, #834), a freeze on another mode or source, and a source switch (`replaceGrainSynth`, `grainSource` already the new one, so nothing is started: the voice synth fades, and a return to the synth starts the type's def). An input voice's copy writer, if any, is freed and its grain synths are set back to the input ring at the voice's history; the copy stays in the copy ring, read by nothing but those grain synths' grains already playing, until the next copy overwrites it (after fading them). The freeze param's unfreeze sends all of it and the grain synth's `freeze` 0 in one bundle (`unfreezeWithControl`); a switch's unfreeze leaves the old grain synth's `freeze` as it was (it fades out).
- **The frozen read point** (`ringScanOffset`, added to a ring grain's lookback): 0 unfrozen. Frozen, a ring's head no longer moves, so a grain must start at least its own length behind it or it reads across the seam into the ring's oldest audio: `grainMaxSeconds` (0.5 s) more covers any grain (`max(r − 1, 0) × dur` is already in the lookback). Then `bufScan` moves the read point back through the ring, in ring lengths per second (a negative scan moves it forward), from where the freeze began, wrapping (a `Phasor` reset as `freeze` rises): moving back, the grains play about 3.5 s of continuous audio before the read point crosses the seam into the newest audio again, once per 4 s of travel. Frozen grains therefore play from about half a second before the freeze point. Spectral keeps the offset: a spectral writer's ring still moves, and 0.5 s back is real audio (the voice's, or the input copy's).
- **The spectral writer** has `\strataRingWrite`'s controls (`resume` among them) and phase (`ringWritePhase`); each channel goes through `FFT(fftL or fftR, …, 0.5)` (the voice's 2048-frame `\spectralBuffers`, which `replaceRingWriter` or `startCopyWriter` passes) → `PV_MagFreeze` → `IFFT`. It writes the input itself until the analysis has run two windows (the IFFT's latency; `PV_MagFreeze` then holds a real spectrum), then crossfades to the held spectrum over 10 ms, so the ring never gets a gap. Its input and output go through `zeroBadValues`. The analysis input gets a dither of about −100 dBFS (`spectralDither`, white noise): on exact digital silence `PV_MagFreeze` would otherwise hold zero phases and buzz at the hop rate; under real sound it is inaudible.
- **A mode change while frozen** (`freezeMode`) freezes again in the new mode: unfreeze, then freeze, in one bundle (#834), as `unfreezeWithControl` sends its unfreeze: from spectral to hold the writer's replace, the type switch that waited for the unfreeze and the new writer's `/n_run 0` land in one block, so the new writer never writes a block into the held ring.
- **A freeze while frozen** on the same source and mode changes nothing but points the live input grain synth at the copy again (a start sends `freeze` before its `voiceOn`, #325, and a voice sync sends it again after the source; a grain synth `voiceOn` starts or re-gates already reads the copy, `grainReadPairs`). A voice frozen on another source (it changed while the voice was stopped, so no switch unfroze it) is unfrozen first, by the `freeze` its start sends before `voiceOn`. Without that `freeze` (the engine check's starts with no freeze resent), the freeze state stays on the old source, and the grain synth `voiceOn` starts reads the new source and is no reader of the copy. A voice moved to its synth source while stopped reads its own live ring (an input freeze never pauses or replaces its writer), so it starts as any voice switched from the input does, from what its voice bus held, until a `freeze` unfreezes it: the gap 3.3's engine-state plan left closed itself with the copy ring (#494, #495).

## The input copy and the copy ring's readers

`copyInputToCopyRing` runs in a routine (`SystemClock`):
1. it counts the copy (`\copies`) and finds the copy ring's readers (`copyRingReaders`), giving each `ringLevel 0` (added to `\faded`);
2. with readers it waits `bufferFadeWait`;
3. it reads the source writer's frame from its phase bus, sends the copies into the copy ring, waits for them (`server.sync`) and reads the frame again;
4. if the copy ran inside its room (`copyOnTime`), `holdCopyRing`: the copy ring's phase bus to 0, the spectral copy writer for spectral (`startCopyWriter`), `\copied`, and the grain synth pointed at the copy (`pointAtCopyRing`); if not, step 3 again from a fresh read point while the copy is current, up to `copyAttempts` (one console line after the second late copy; an attempt whose head never came is no late copy), and `abandonCopy` once the bound is spent or a span is refused;
5. the latest copy gives the faded readers `ringLevel 1` back.

Steps 3 and 4 run only while the copy is current (`ringChanges` unchanged, no later copy and the engine not past stop, `pastStop`: a `free` inside the wait, #503, runs none of it).

**The room** (`copyRoomFrames(sourceFrames, history)`): audio the writer writes after the head's read enters the copy at copy frame `ringReadMargin` + history + a block (the phase bus holds the start of the block its writer has written) less the source ring's spare length (its frames less the copy's), and a frozen grain with no scan reads the copy's last `frozenReachSeconds` (`grainMaxSeconds` of the frozen read point, `ringReadMargin`, `ringSpreadSeconds`, and `ringMaxRate × grainMaxSeconds` for a grain at the fastest rate either way: 3.005 s) and a block (its reader's lag). So the room is the source ring's frames less the frozen reach, the read margin, the history and two blocks: 0.987 s of an output ring at 48 kHz, which has no spare length; 1.99 s of the input ring at its longest history (its spare `ringGuardSeconds` + 1 s), more at a shorter one. A copy inside it can still hold up to that much audio from after the read at its seam (copy frame `ringReadMargin` + a block on), which only a scan reaches ([outrings.md](outrings.md)). The second test, the time from the head read's reply to `/synced` (so a reply the queue holds back after the copy never counts against it), keeps a head that went a whole ring round from passing: each head read waits at most 1 s, and any ring's length less its room is at least `frozenReachSeconds`, more than the two reads' 2 s. The engine check makes a copy late through `beforeCopyHook` (a wait before the copy's message, with the writer going on): a hold of the server's queue from the check alone would also hold the head read's reply, which scsynth sends from the same queue.

`copyRingReaders(voice)`: the playing input grain synths in `\inputReaders` for the voice, those reading the copy and those set back from it until `freezeLeaveSeconds` after (their grains already playing still read the copy ring); it prunes freed ones and expired ones. A synth-source grain synth reads its voice's own ring and is never among them, so a switch from the synth to the input followed by a freeze (a scene recall's order) copies at once, and the synth-source grain synth the switch left releasing keeps its level and reads its own ring, which holds no input audio (3.2 faded it and then gave it the copy at full level, #494). A refreeze within `freezeLeaveSeconds` of an unfreeze finds the live synth among the readers: it fades (a short dip), the copy waits `bufferFadeWait`, and its level comes back with the copy.
