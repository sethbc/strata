## Must not break

- **Five commands, exactly**, with these signatures: `noteOn(voice, slot, note, freq, rate, velocity)` `"iiffff"`, `noteOff(voice, slot, cut)` `"iii"`, `noteExpression(voice, slot, bend, amp, position, size, main)` `"iifffff"`, `setNotePool(size)` `"i"` (design 3.5 §3.1), and 3.7's `noteRegion(voice, slot, start, length)` `"iiff"` (design 3.7 §3.4; slot 1-7 only, ruling 1: the own note's region is `setGrainParam`'s `regionStart` and `regionLength`, `docs/notes/engine/positions.md`). Slots are 0-indexed in the engine: 0 is the voice's own note, 1-7 its extra notes; Lua's are 1-8 and it passes `slot - 1`.
- **Each command checks before it acts**: its indices first (voice 0-6, slot 0..`noteSlots` - 1, `noteOff`'s `cut` 0 or 1, `setNotePool`'s size 0..`notePoolMax`), then that every continuous argument is finite, through the modulation area's `fastModIndicesValid` and `fastModValuesFinite`, as 3.4's five commands do. A bad one is ignored with one console line (`strata: noteOn ignored: voice 7 is not a whole number from 0 to 6`, posted by `postFastModIgnored`): nothing recorded, no state changed. Only then are the continuous arguments clipped (note -24 to 151, freq 8-20000, rate 0.25-4, velocity 0-1, bend 0.0625-16, amp 0-2, position, size and main -1..1), never ignored for being out of range.
- **The literals** `noteSlots { ^8 }` and `notePoolMax { ^16 }` equal Lua's `NOTE_SLOTS` and `NOTE_POOL.max` (a docs test compares them), and the Lua engine stub reads them as written (`name { ^N }`) for its index checks: keep them literal methods. `noteLag { ^0.02 }` is every per-note control's lag.
- **Extra notes live only in `areaState[\notes]`'s slots**, never in `synths`, `releasingSynths`, `fadingSynths` or `cuttingSynths`: `voiceRunning`, `gateVoice`, the switch's fading and cutting sets and every other own-synth rule are the voice's own synths' alone.
- **The engine holds the bounds whatever Lua sends**: a slot never holds two live synths (a `noteOn` on a releasing slot cuts its tail first); live and releasing extra notes never exceed the pool (before a new synth starts, the oldest releasing note anywhere is cut; with none releasing the note is refused with one line); cutting note synths never exceed one per slot (a slot's earlier cutting synth is freed at once) nor the pool in all (the oldest is freed at once).
- **A live slot with no synth is a broken invariant, never a send to nil** (#941): a slot's `state` and `synth` are two fields, and no command leaves one `\live` with no synth. `noteSynths` skips such a slot; `releaseNote` (a `noteOff`, a `voiceOff`'s `releaseNotes`) and `extraNoteOn` (before it keeps the note's values) leave it as it is, send nothing and make no hit, each with one `Strata invariant broken` line (`warnLiveWithoutSynth`), where both sent a message to nil and raised. The check sets a slot so by hand and sends both.
- **A note synth is watched as a note's** (`watchNoteSynth`): when it frees, its slot empties (or its cutting entry clears) and nothing restarts it, never `watchVoiceSynth`'s restart rule. Its start counts once the server confirms it (`watchStart`, `unconfirmedStarts`); one unconfirmed past `startConfirmWait` is forgotten at its slot's next command and before any start counts the pool (`forgetFailedNoteStarts`, `makeNoteRoom`), so a failed start frees its slot and its room. A note synth the engine frees itself leaves every list it was in at once (`endNoteSynth`).
- **Voice-wide sends reach a voice's notes through `setVoiceSynths` and `setGrainSynths`**: the own synth through `setSynth`, every live extra note of that kind through `sendToSynth`, without the per-note names (`perNoteVoiceControls`, `perNoteGrainControls`: a voice synth note's `freq`; a buffer note's `bufRate` and `scaleNote`; an input note's `pitchShift`; the note controls, `velocity` and `t_accent`; 3.7's region, `regionStart` and `regionLength`). 3.7's `scanMode` and `followRate` are voice-wide and reach every note. So the param that is a voice's own pitch moves its own note only. Every voice-wide site uses them: `setVoiceControl`, `setGrainParam`'s plain sets (the `freeze` control's included), the `history` and `t_scanReset` handlers, `retrigger`'s `t_trig`, `unfreezeWithControl`'s `freeze` 0 and `pointAtCopyRing` (the copy ring's read pairs, each note then counted among the copy ring's readers); `bufferChanged`'s live set, which takes a slot's new length and rate, is the own grain synth and the voice's live grain notes (`noteSynths(voice, \grain)`); `sendScaleNote` gives a buffer note its own `scaleNote` (`noteScaleNote`) and an input or ring-stream note the voice's.
- **The own note's state lives on the synth that sounds it** (`ownNoteKey`: the own voice synth on a synth voice, the own grain synth on a buffer or input voice and on a frozen synth voice, whose grain synth plays the frozen ring): slot 0's expression goes there, and every own synth the engine starts or re-gates takes it (`ownNotePairs`), every other own synth the neutral values (the synth-source grain synth, which grains the chord, keeps every note control at its default while the voice is unfrozen). `voiceOn` starts every voice unparked at the neutral expression (`resetOwnNote`).
- **The park follows the own voice synth through a freeze** (ruling 44, `ownNoteGateKeys`): on a synth voice the own voice synth's `noteGate` always follows slot 0's park, frozen or not (inaudible while frozen, so parking it costs nothing); while frozen a slot-0 command also reaches the own grain synth; the freeze itself parks nothing (its ring holds the chord), and the unfreeze returns the grain synth's `noteGate` to 1 and finds the voice synth where the park says. So an unfreeze under a parked own note makes no sound of it.
- **The tail at an unfreeze under an own note parked during the freeze is the ring's ordinary tail, accepted** (rulings 48, 49): the unfreeze resumes the ring writer from its paused phase, so for the reader's lookback the grains still read the ring's newest audio from before the freeze, the note's included, at most `ringReadMargin` + `posSpread` × `ringSpreadSeconds` + the grain size, at up to the level the voice played before the freeze (measured on the synth path with 0.1 s grains in seven runs of the check: the tail ends within 0.11 s at spread 0 and within 0.22 s at Pulse's default 0.35, against bounds of 0.105 and 0.28 s before the check's 0.1 s margin, and lasts about 0.3 s at spread 1; its peak reaches at most about 1.1 times the level playing: 0.177 against 0.157 at most). Never delay the own grain synth's `noteGate` there, silence the ring's stale region or skip it: the ring holds the voice's whole mix, the extra notes' too, so any of them would cut a held chord for the same span at every unfreeze.
- **A slot-0 `noteOn` fires no accent and no trigger on an unfrozen voice** (ruling 47, replacing ruling 15's accent): it only sets `noteGate` 1 where the park is. Lua always follows it with `retrigger`, which accents the voice, plucks Karplus and opens the stage's step gate, once. On a frozen synth voice it also sets the own grain synth's `noteRate` and fires that synth's `t_accent` at `velocity` (the only accent that stream has; velocity 0 gives none). Lua sends a slot-0 `noteOn` only to a running voice and never an extra note to a stopped one: one that arrives is ignored with one line.
- **An extra note's start opens the voice's step gate** (ruling 54, #683): `extraNoteOn`, once the slot's note sounds (a start or a re-strike, a player's or a step's), sends the stage `t_gate` (`openStepGate`), which starts the gate's envelope as `retrigger`'s `t_trig` does, with no accent on the stage, no pluck and no grain trigger; with the gate off it changes nothing heard. The engine's own restarts (`startNote` from `restartNotes` and `notesUnfrozen`) never send it.
- **Restarts are silent** (ruling 45): the held extra notes the engine restarts itself (a source switch's `restartNotes`, an unfreeze's `notesUnfrozen`) start with no `t_accent` and no `t_trig`, their `velocity` kept for later.
- **A restarted note plays its own pitch on the new source** (ruling 53, #682): a ring-stream note's kept `rate` is against Lua's freeze reference, which the engine never holds, so a note that leaves the stream (`leaveStream`, in `restartNotes` and `notesUnfrozen`) takes its rate from its kept `note`, `absoluteNoteRate(note, voice)`: `2 ^ ((note - root) / 12)`, clipped to 0.25-4, which is exactly Lua's `note_values` for a buffer or input voice (its rate depends on the note alone: no `buf_rate` or `grain_pitch` enters it, and quantize is the engine's per-grain step). The root is the voice's (3.7, design §4.3): `areaState[\notes][\rootNotes][voice]`, which the handler-only grain param `rootNote` sets (Lua sends it in every voice sync: the slot's key, or 60) and nothing else reads; `noteRateRootNote { ^60 }` is its value at alloc and equals Lua's `NOTES.rate_root_note` (a docs test).
- **A held note follows its voice's root** (3.9, #958): a `rootNote` that moves the voice's root (a source switch between roots, a key change of the slot it reads: Lua sends `rootNote` after the switch and no note) gives each live buffer or input extra note the rate of its kept `note` against the new root, `absoluteNoteRate`, set on its synth with its pitch pairs (`notePitchPairs`: a buffer note's `bufRate` and `scaleNote`, an input note's `pitchShift`) in one plain `sendToSynth` (`notesFollowRoot`): no node is created, cut or struck again. So a stream note that left a frozen voice for a keyed slot against the old root (`leaveStream` runs in the switch, before the `rootNote`) plays at the slot's root once it arrives. A voice synth note, a releasing note, a cutting synth, the own grain synth and a `rootNote` of the root the voice has are sent nothing; a stream note is left too, though Lua, which sends a synth voice's root as 60, never moves its root. A pitch outside 0-127 gets Lua's `note_values` rate too (#1002): `noteOn`'s `note` is the pitch, clipped only past -24 to 151 (every root, 0-127, widened by the rate's 24 semitones each way), where the rate is clipped as well; the engine check's `checkNoteRange` holds both derivations, this and `leaveStream`, to Lua's rates for pitches 132 and -5.
- **A note's region is kept with its slot** (3.7): `noteRegion` stores `[start, length]` (clipped 0-1) in the record (`[0, 0]` at an empty record and after `stopNotes`), every start of the slot's grain synth carries it (`noteRegionPairs`, last with the note's pairs, so it wins over the own region in `grainControlPairs`), and a live grain note gets it with `t_scanReset 1` in one message, while a releasing one is sent nothing (its tail stays where it was; the `noteOn` that follows cuts it, the final review's engine Minor 1); a voice synth note has no region. The engine never clears a region itself.
- **A live slot's `noteOn` restarts its scan on a one-shot voice only** (3.7, design §2.1): on a buffer voice whose `scanMode` is 2 (`oneShotVoice`, the positions area's), the live branch of `extraNoteOn` adds `t_scanReset 1` to the note's pitch and accent message; a new or restarted note's synth starts its scan at 0 anyway. Every other note keeps the rate Lua sent (but at a moved root, above); a voice synth note plays its kept `freq`.
- The area's state lives in `areaState[\notes]`; `StrataNotes.sc`, like every extension file, adds methods only, never a variable.

## The notes area (`StrataNotes.sc`, order 170)

The last area in `alloc`'s order and the first in `free`'s. It has `allocState`, `addCommands` and `stop`: its `stop` frees every note synth (quietly, `sendToSynth`) and puts every slot back as `alloc` left it, before the voices area's `stop` frees the voices' groups. It has no SynthDef, bus or buffer: a note's synth is a voice or grain SynthDef of its voice.

`areaState[\notes]`:
- `pool`: how many extra notes the pool holds, across every voice; 0 until Lua sends `setNotePool` (Lua sends its tier's default, `NOTE_POOL.standard` 4 or `NOTE_POOL.high` 8, or the player's setting from `notes.data`, at its start).
- `slots`: per voice an Array of `noteSlots` records (`emptyNoteRecord`). Slot 0, the own note: its kept `expression` (an Event of `bend`, `amp`, `position`, `size`, `main`), `parked`, and `rate` (a frozen synth voice's own grain synth's `noteRate`, 1 otherwise). Each extra slot: `state` (`\empty`, `\live` or `\releasing`), `synth` (live or releasing), `cutting` (its synth in the kill fade), `kind` (what its synth is: `\voice`, `\buffer`, `\input`, `\stream`), its last `noteOn`'s `note`, `freq`, `rate` and `velocity`, its kept `expression`, and `order` and `cutOrder` (when it started and when its cutting synth was cut).
- `order`: a counter; every start and every cut takes the next number, so the oldest note (or cutting synth) has the lowest.
- `received`: what each command last took (an IdentityDictionary, the command's name to its arguments, the continuous ones clipped), for the engine check, as the modulation area's `received`.
- `rootNotes` (3.7): per voice the note that plays rate 1 (`noteRateRootNote` at alloc; the `rootNote` grain param's handler, this area's `grainParamHandlers`, sets it and returns true, so it is never stored in `grainControls` or sent to a synth as itself (a moved root re-derives the held notes' rates, `notesFollowRoot`); a non-finite value is ignored with one line, `fastModValuesFinite`, and the kept root stays: `"notes: a non-finite rootNote is ignored with one line and the root note stays"`).

**`note` is kept** (ruling 46): each `noteOn` stores its `note` (-24 to 151 since 3.9's #1002: the pitch Lua played, clipped only where the rate clips too) in the slot's record. Its readers are `leaveStream` (ruling 53) and, since 3.9's #958, `notesFollowRoot`, both through `absoluteNoteRate`: a ring-stream note's rate is against the freeze reference, so a note leaving the stream takes its rate from its note, and a held buffer or input note takes its note's rate against a moved root. A buffer note's `scaleNote` comes from the voice's reference note and the note's rate (`noteScaleNote`); a tuning (3.8) needs nothing more here: Lua sends each note's tuned pitch, its freq and rate from it (`docs/notes/engine/tuning.md`).

The Lua engine stub refuses the same indices and, from the clips in the source (`note = msg[3].clip(0, 127)`, ...), the clipped ranges, so Lua sends neither (`docs/notes/test-harness/engine-stub-and-sync.md`).

### The lifecycle (design 3.5 §3.4)

**An extra note's synth** (`startNoteSynth`) is built by its voice's state (`noteKindFor`), from the voice's controls with the note's own last, so they win: its pitch (`notePitchPairs`), its accent at its velocity (`noteAccentPairs`), `noteGate` 1 (the park open) and its kept expression (`noteExpressionPairs`):
- **A synth voice's** (`\voice`): a voice synth of the voice's def at the head of `voiceGroup`, writing the voice's bus (`granBuses`), from `voiceControls` (as `startVoiceSynth`) with its own `freq`, `velocity`, `t_trig` 1 (its accent; a Karplus note's pluck) and `noteBend`, `noteAmp` and `noteMain`. The voice's one ring writer records the chord and its one grain synth grains it: the grain synth, ring writer and mod synth stay one each.
- **A buffer voice's** (`\buffer`): a `\strataGrainBuf` for the voice's slot at the head of its mix group (`startGrainSynth(voice, voiceMixGroup(voice), \addToHead, notePairs, watch)`, from `grainControlPairs`), playing the note's `rate` as its `bufRate`, with a `scaleNote` of its own (`noteScaleNote`: Lua's reference note plus the rate's semitones, as `scaleNoteFor` gives the own note's), its `velocity`, `t_accent` 1 and `noteBend`, `noteAmp`, `notePos` and `noteSize`. Its scan starts at the voice's position, as any grain start does; the playheads show the own note's.
- **An input voice's** (`\input`): a `\strataGrainRing` of the input ring, the same way, playing the note's `rate` as its `pitchShift` (an absolute rate) under the voice's one `scaleNote`.
- **A frozen synth voice's** (`\stream`, `frozenSynthVoice`: on its synth source with its ring held): a stream of the frozen sound, a `\strataGrainRing` reading the voice's ring through `grainReadPairs` (as its own grain synth does, the freeze on) at the head of `processGroup`, writing the synth path with `rateLevel` and `pan` 0 and its mod buses on the silent bus (`startGrainSynth`'s synth source), at `noteRate` the note's `rate` (the rate against the voice's freeze reference, Lua's); the voice's `pitchShift` and `scaleNote` stay voice-wide. A hold's and a spectral freeze's notes are the same: both read the voice ring.

Placement is never relative to another note's synth (a group never ends). `startGrainSynth` keeps a note's grain synth in `grainSlots` or `ringReaders` (and `inputReaders` while it reads a frozen input voice's copy) as it does the own one's, and `watchNoteSynth`'s `onFree` takes it out (`forgetGrainReader`).

**`noteOn` on an extra slot** (`extraNoteOn`; a stopped voice's is ignored with one line):
- **Live:** the pitch is set on its synth and its accent fired, in one message. No node.
- **Releasing:** the tail is cut (`cutNote`: it becomes the slot's cutting synth, an earlier cutting synth of the slot freed at once) and a new synth starts.
- **Empty:** a new synth starts.
- Before a new synth starts (`startNote`, `makeNoteRoom`), if live and releasing extra notes already number the pool, the oldest releasing one anywhere is cut; if none is releasing the note is refused with one line (`strata: noteOn ignored: the pool of 4 is full of live notes`): Lua never sends that, since its own count of held notes stays within the pool.

**`noteOff`**: `cut` 0 sends `gate 0` (`releaseNote`: the synth frees itself after its release; the slot is releasing until then, and its tail counts against the pool); `cut` 1 cuts it (`cutNote`: `kill` 1, the 50 ms kill fade). Both through `sendToSynth`.

**Cutting** (`cutNote`, `trimCuttingNotes`): a cut synth stays the slot's `cutting` until it frees; a later cut on the slot frees it at once, and when cutting note synths would pass the pool the oldest is freed at once, so they never exceed one per slot nor the pool in all (with a pool of 0, a cut frees at once).

**The own note (slot 0)**: its synths are the voice's own (`synths`). `ownNoteKey` names the one that sounds the own note: the own voice synth on a synth voice, the own grain synth on a buffer or input voice and on a frozen synth voice, whose grain synth plays the frozen ring (`ownNoteOnGrain`). On a frozen synth voice a slot-0 `noteOn` also sets the own grain synth's `noteRate` to its `rate`, parked or not (kept in slot 0's `rate`), and fires its `t_accent` at `velocity`. A slot-0 `noteOff` parks the own note (`noteGate` 0: the voice def's or grain def's second envelope, `notePark`, falls over the def's release; nothing frees), a slot-0 `noteOn` unparks it (`noteGate` 1, over the attack), each on the synths the park is on (`ownNoteGateKeys`: a synth voice's own voice synth, frozen or not, and the own grain synth where it sounds the own note), and a slot-0 `noteExpression` sets the sounding synth's note controls. Every own synth the engine starts (`startVoiceSynth`, `startGrainSynth` with no note pairs) or `gateVoice` re-gates takes `ownNotePairs`: slot 0's expression when it sounds the own note, the neutral values when not; the park on a voice synth always and on a grain synth when it sounds the own note.

### The own note's park

Where the own note sounds (`ownNoteKey`) by whether it is parked: three places a voice can be in, two park states. `voiceOn` puts every voice in the unparked column at the neutral expression (`resetOwnNote`); a freeze or unfreeze of a synth voice moves it between the first and the third row, a source switch to the second or back.

| The voice | Sounds on (`ownNoteKey`); the park on (`ownNoteGateKeys`) | Unparked (a slot-0 `noteOn`: `noteGate` 1) | Parked (a slot-0 `noteOff`: `noteGate` 0) |
|---|---|---|---|
| a synth voice, unfrozen | the own voice synth; the park on it alone | the voice synth plays at slot 0's expression (`noteBend`, `noteAmp`, `noteMain`); the grain synth, which grains the whole chord, keeps the neutral values | the voice synth falls over its release and stays (nothing frees); the grain synth grains what the voice bus still carries (the extra notes) |
| a buffer, input or voice-source voice | the own grain synth; the park on it alone (no voice synth) | the grain synth plays at slot 0's expression (`noteBend`, `noteAmp`, `notePos`, `noteSize`) | the grain synth falls over its release and stays |
| a synth voice, frozen (`frozenSynthVoice`) | the own grain synth, playing the frozen ring; the park on it and on the own voice synth (ruling 44) | the grain synth at `noteGate` 1, its `noteRate` slot 0's `rate` and its `t_accent` at `velocity` from each slot-0 `noteOn` (ruling 47); the voice synth at 1, inaudible (its ring is held) | parked during the freeze: both at 0, so the unfreeze (the grain synth back to `noteGate` 1 and the neutral values, `notesUnfrozen`) finds the voice synth parked and makes no sound of the note but the ring's tail (rulings 48, 49); parked before the freeze: the voice synth at 0 and the grain synth still at 1, since the freeze itself parks nothing (the ring holds what played) |

A slot-0 `noteExpression` sets the synth in the second column (a grain synth's controls on the buffer and frozen rows, the voice synth's on the first). Every own synth the engine starts or re-gates takes the row's values (`ownNotePairs`). What checks the rows: `test/engine_check/notes.scd`'s park checks ("notes: noteOff on slot 0 parks the own note: its synths stay, its level falls to 0; noteOn on slot 0 brings it back", on a synth, a buffer and an input voice; "notes: slot 0 of a frozen synth voice parks on its grain synth, and its voice synth with it (ruling 44 ...)") and the heard-path checks of a park during, well before and just before a freeze (rulings 48, 49). No check walks every cell.

| `rootNote` of another root (3.9, #958: `notesFollowRoot`) | a `\buffer` or `\input` note: its rate re-derived from its kept note (`absoluteNoteRate`) and set on its synth with its pitch pairs, no node, no accent or trigger; a `\voice` note: sent nothing; a `\stream` note: left by the code, unchecked (Lua sends a synth voice's root as 60, so no command of Lua's reaches it) | sent nothing | sent nothing | a buffer or input voice's own grain synth sent nothing (Lua's `bufRate` or `pitchShift` is its pitch) |
| a buffer load or clear of the voice's slot | faded with every grain synth reading the slot (`grainSlots`: `bufFrames` 0), then given the slot's new length and rate (`bufferChanged`'s live set: the own grain synth and every live extra grain note) | `bufFrames` 0 only | `bufFrames` 0 only | as a live note |
| a new note with the pool full of live and releasing notes (`makeNoteRoom`), or `setNotePool` below what is held | `setNotePool` only: the oldest live cut once no releasing one is left | the oldest anywhere cut first | the oldest freed past the pool (`trimCuttingNotes`) | — |
| the area's `stop` | freed (quietly, `endNoteSynth`); every slot as `alloc` left it, before the voices' groups go | freed | freed | reset to `alloc`'s |

So a slot holds a live and a cutting synth at most, through every row. What checks the rows: `test/engine_check/notes.scd` drives them by example ("notes: voiceOff releases every note and voiceOn after it re-gates only the own synths", "notes: a source switch under a chord cuts every extra note and restarts the held ones on the new source in one bundle", "notes: an unfreeze cuts the ring-stream notes, restarts the held ones as voice synths at their freq, and returns noteRate to 1, in the unfreeze's bundle", "notes: notes the engine restarts (a source switch, an unfreeze) start with no accent or trigger, their velocity kept", "notes: an input freeze points every note of the voice at the copy ring", "notes: a buffer load fades every note reading the slot", "notes: a held buffer or input note follows its voice's root, by a set on its own synth", the pool's cuts and `setNotePool`); `test/engine_check/types.scd` the type switch's rows ("types: a held chord's voice synth notes wait with the switch and move to the new def at the unfreeze", and a switch under three live notes and one releasing). The seeded run of 2000 commands over the seven voices (`checkPoolRandom`: "notes: in that run every extra slot has a state exactly while it has a synth, and each new synth the kind its voice was at its start") walks the rows of `voiceOff`, `voiceOn`, the running source switch (to the synth, two slots, the input and the voice sources), the running type switch, a synth voice's freeze and its unfreeze by `freeze` 0, an unfreeze inside a source switch, and the pool's cuts, together with `noteOn` and `noteOff`, and after every command checks every extra slot of every voice: a state exactly while it has a synth (`\live` or `\releasing` with one, `\empty` with none), and a synth new since the command before of the kind the voice was at its start, by its source and freeze (a slot's `\buffer`; the input's or a voice source's `\input`; a frozen synth voice's `\stream`; any other synth voice's `\voice`), of that kind's def (`\strataGrainBuf`, `\strataGrainRing`, the type's def); it must start notes of all four kinds and restart some. The source, freeze and type it judges by are the run's own record of its commands (every voice unfrozen at its start; a `freeze` sets it, a switch to another source ends it), never the engine's. It runs on the standard engine, so not the spectral rows; it yields every 25 commands, so the kill fades' `/n_end` come in too (a released note's own end, its slot emptied by `/n_end`, does not within the run). A buffer load or clear, an input freeze's copy and the area's `stop` are the examples' alone.

### Watching

A note synth is watched with a watcher of its own (`watchNoteSynth`), never `watchVoiceSynth`'s restart rule. `watchStart` (the lifecycle's, shared with `watchVoiceSynth`) registers it and keeps it in `unconfirmedStarts` until its `/n_go`. When it frees, its slot's entry clears (the slot empties, or its cutting entry clears) and it leaves `grainSlots`, `ringReaders` and `inputReaders`; nothing restarts it. A start the server never confirms (its `/s_new` failed: no room in the real-time pool) is forgotten as `forgetFailedStarts` does (#497), at the slot's next `noteOn` or `noteOff` past `startConfirmWait` (`forgetFailedNoteStarts`, `endFailedStart`): the slot is then empty, so a `noteOn` starts it and a `noteOff` does nothing, and neither sends the server anything it fails on. Lua and the engine heal at the next note. A failed start never holds room in the pool: `makeNoteRoom` forgets every note start unconfirmed past `startConfirmWait` before it counts, whatever slot it is in. A note synth the engine frees itself (a slot's earlier cutting synth, the pool's cap on cutting synths, the area's `stop`) goes through `endNoteSynth`: freed quietly and forgotten at once wherever it was registered (the NodeWatcher, `unconfirmedStarts`, its `onFree`), as its `/n_end` would have it, since one that never started sends none.

### Memory

The note pool is sized from what a note costs. A synth voice's extra note is a voice synth, a buffer or input voice's a grain synth; the memory area measures every voice SynthDef and `\strataMod` (`memory: \strataResonator takes <n> KB`, ...), every voice def under one 52 KB limit since 3.8. The costliest note is a buffer note (`\strataGrainBuf`, 82.6 KB since 3.7), and since 3.8 a voice-synth note is at most the costliest voice def (Karplus, 49.7 KB with its 4096-frame lines; 80.9 KB before 3.8, when it was the costliest note: #775), which every voice is cast to in the worst cases. A pool of sixteen buffer notes live and cutting is 16 × 2 × 82.6, about 2643 KB; sixteen Karplus notes live and cutting 16 × 2 × 49.7, about 1590 KB. The memory area measures a full pool itself, on both tiers, in three pool cases (the all-buffer worst case with every pool slot live and cutting; synth -> buffer -> synth with sixteen voice synth notes of the costliest def, live, beside sixteen cutting buffer notes; and the same with every note also cutting a voice synth of the costliest def, a type switch under a full held chord), each against 1280 KB. The figures, the sums and the cases are in `docs/notes/engine/memory.md` (the voice SynthDefs; the floors section; 3.8's section).
