## Must not break

- Every control param that reaches the engine has an action of the form `function(x) <store x>; send_param_to_engine(id, x) end`, and its engine call lives in `S.engine_senders[id]`. Never call `engine.*` from a control param's action. `test/unit/lfos_test.lua` (every control param with a sender sends its LFO-offset value) puts an offset on each in turn and checks that setting the param sends the sender's call with the offset value, and that a control param without a sender makes no engine call (#316).
- One path from a value to the engine: `send_engine_value` records `S.engine_param_values[id]` and runs the sender. The LFOs send through it too.
- Voice senders run only while the voice is active (`S.lib.engine_sync.add_voice_sender`, which `lib/params_setup.lua`'s `add_voice_sender` calls for every synthesis, grain, buffer and crossmod param and every registered grain key, gates the call on `S.voices[voice_idx].active` and, 3.8, on the record's `reaches`: a synth key the voice's type lacks sends nothing). The `v<i>_source` and `v<i>_type` actions are the exception: they also reach stopped voices.
- **The send budget counts only sends that reach the engine** (#642): a send of an id with no engine sender (#646: `v<i>_seq_gate_length`, the bookmarks, ...) or of a stopped voice's param whose installed sender is the gated one `add_voice_sender` made reaches no engine, so it is never counted and never waits, whether deferrable or not, and a waiting value whose voice has stopped since goes uncounted; its value is still recorded in `S.engine_param_values` (dropping the id's waiting value), as a delivered one is, so `expected_value` and the matrix's compare read what they read before and a start still forgets it. Every other sender counts as before (the mute, which reaches a stopped voice's stage, among them; a sender installed over a gated one later counts too), but the master density, which counts one message per running voice it reaches (0 with none running, and then it never waits, #645).
- A command that carries several params builds the others from `engine_param_value(id)` (what the engine has), so an LFO on one param never undoes an LFO on another.
- **The `voices` table is the only source of values**: the engine holds no per-voice defaults (`docs/notes/engine/voices.md`), so a start sends every value of the voice itself, as below.
- A start (`S.lib.engine_sync.start_voice`, which `toggle_voice` and a pattern step call) sends `setGrainSource`, `setVoiceType` and every grain value before `engine.voiceOn` (the eight grain params, then the registered voice params' grain keys and syncs, all `setGrainParam`), then `engine.voiceOn` with the grain size, density and pitch just sent, then the voice-level values (every synth param, the crossmod slots, `setModSpeed`, `bend`). The engine keeps a stopped voice's grain values and builds or re-gates its grain synth with them inside `voiceOn`'s bundle, so the first grain plays this start's values; sent after `voiceOn` they arrived late and the first grain played the last run's position, loop, envelope or mode (#325). Nothing but the type (3.8) and `setGrainParam` goes between the source and `voiceOn`: `voiceOn` resets the voice-level controls, so a voice-level value sent before it is lost (a test fails on it).
- **A start's first values carry the overrides and extra offsets** (#632): every grain value, registered grain key, `voiceOn` argument and synth param a start sends for a param that holds a base override or an extra offset is `with_lfo_offsets(id, stored)` (`start_value`; the stored value otherwise, as before 3.4), so a step that starts a stopped voice (its locks and note set first, `docs/notes/lua/sequencer.md`) plays its first grain with them, and no grain value follows `voiceOn` (a test fails on one). The resend at its end only records what the start already carried; crossmod amounts, which it does not carry, are sent there.
- A start is all or nothing (#382): a send that raises before `voiceOn` has started nothing, and once `voiceOn` is sent a grain-restart hook or a send that raises sends `engine.voiceOff` and raises the error again, so the engine and `voice.active` always agree. `voice.active` is set only once the whole start has gone out.
- **Every `engine.voiceOff` the script sends is followed by the voice-stop hooks** (3.5, `S.registry.voice_stop`, `fn(voice_idx)`), so the notes module forgets a stopped voice's notes whoever stopped it. There are three, all here: `toggle_voice`'s stop (after `voice.active` is false), a start that failed once its `voiceOn` went (before the error is raised again) and cleanup step 160 (per running voice). A new `voiceOff` runs them too. **A hook never breaks a stop**: each runs through `S.lib.ui_frame.contained_call` (`run_voice_stop_hooks`, as the LFO step hooks do), so one that raises prints `strata: voice stop hook failed: ` and its traceback once per distinct message per hook and is skipped; the next hook runs, `toggle_voice` still redraws, a failed start raises its own error, and cleanup still sends every other `voiceOff` and runs its later steps.
- **A sender that is not the engine's is marked** (#703, `S.lib.engine_sync.mark_not_engine(id)`; the tape's four, which call softcut): it is still called, with the offset value, by `deliver` (and records `S.engine_param_values`), but counts no engine message, never waits for the budget and takes no round-robin slot (`reaches_engine` is false for it). Call it where the sender is installed.
- **`count_sends(n)` counts and never defers** (3.5): it adds `n` messages, sent outside `send_engine_value` (the notes' commands), to the current window's count, entering a new window first when the old one has passed (its waiting values go then, as for any send); it sends nothing and never makes anything wait. So the deferrable sends make room for note expression, never the reverse.
- Voices are 0-indexed in the engine: always pass `voice_idx - 1`. Mod sources go through `engine_mod_source()` (Lua 0 = none / 1-7 → SC -1 / 0-6).
- Action sends always go out (no dedupe). Only the steps of the Lua-run LFOs and of the matrix (a value near `expected_value`, both since #647) skip sends (`docs/notes/lua/lfos.md`, `docs/notes/lua/matrix.md`).
- Every `engine.setVoiceType` goes through `S.lib.engine_sync.send_voice_type(voice_idx)` (3.8: a start's second send, right after the source, and every `v<i>_type` action), which sends the voice's current type's `index - 1` (`docs/notes/lua/types.md`). A start's `voiceOn` sends `pan` as 0 on a type without it (`S.lib.voices.is_synth_key(voice_idx, "pan")`, ruling 20).
- Every `engine.setGrainSource` goes through `S.lib.engine_sync.send_grain_source(voice_idx)` (a start's first send and the `v<i>_source` action), which remembers the source the engine has per voice. A running voice whose source changed runs the `S.registry.grain_restart` hooks; the same source again, or a stopped voice's change, runs none. A start runs them after `engine.voiceOn`, before the voice-level values and before it marks the voice running (`lib/midi_in.lua`'s hook relies on that).
- A start redraws nothing itself: `toggle_voice` updates the voice list and redraws the screen and the grid after it, and a pattern step does so once for every voice it starts (#527).
- **A base override is cleared only by a hand edit of its param** (3.4): the touch hook (`S.register_param_touch`, run by an encoder, arc or grid edit) clears it; the drift, morph, a macro, gesture playback, a mutation and a recall run the param's action, whose send stays under the override. Setting and clearing an override send at once.
- **Only a deferrable send waits** (3.4): a send waits for the budget only while `S.deferrable_write` is set (`S.lib.engine_sync.deferrable(fn)`, used by the Lua LFOs, the matrix, morph, gesture playback and every macro apply). Hand edits, steps, notes, locks, recalls and voice syncs are never deferred; a send that goes at once drops its id's waiting value, so an older value never follows a newer one.
- **The budget counts and defers `send_engine_value` only; a discrete switch is its exception** (#649, ruling 93): every engine command sent another way (a voice start or stop, a voice sync, and the actions of the option, binary and number params that call the engine themselves) is never counted and never deferred, inside `deferrable` too. So the uncounted part of the discrete switch a recall, a transition's end or a morph crossing applies (its voice starts and stops, source switches and the option actions that call the engine themselves) goes out whole, at once, in recall order, however full the window, and leaves the count where it was (a test pins it, with a crossing at a full window). Its counted discrete entries (mute and solo, the filter types, freeze, `quantize`'s grain key, `seq_gate`, scatter, the bypasses, an LFO's restore, the delay's held `setDelay` from its `scene_applied` hook: listed below) go through `send_engine_value` and wait only inside `deferrable` with the window full (a morph crossing's; a recall's never wait), as a morph's continuous values do. The contract, the commands and the measured sizes are below (The send budget, The exception).
- **A voice sync or start drops the voice's waiting values** (`forget_sent_voice_values`): they are older than what the sync sends.
- **A voice sync or start keeps the voice's overrides and extra offsets**: after a sync's own sends (which carry the stored values) it sends every param of the voice that holds a base override or an extra offset again, through `with_lfo_offsets`, at once and never deferred; a start's own sends carried them already (above), so it records them as sent and sends again only one a grain-restart hook changed meanwhile (and the crossmod amounts); with none set either sends exactly what it sent before 3.4.
- **`deferrable(fn)`'s `fn` never yields** (no `clock.sleep` or `clock.sync` inside it): `S.deferrable_write` would stay set across the wait, and a hand edit made meanwhile would be deferred. A caller that waits sleeps outside `deferrable` and wraps each burst of writes.
- **A base override is a finite number**: `set_base_override` raises, naming the param, for anything else (nil, a string, NaN, ±inf); a caller clears with `clear_base_override`.
- **One door for a hit** (3.7, plan ruling 12): `S.lib.engine_sync.retrigger` is the only caller of `engine.retrigger` (a test scans every Lua source for it), and every hit tells the `voice_hit` hooks exactly once: a retrigger, a played extra note's start (`extra_note_hit`, from `lib/notes.lua`'s `start_extra` unless the note is a step's chord's) and a start that took effect unless its caller says a retrigger follows (`options.retrigger_follows`: a note that starts a stopped voice, a gated voice's first step). So a start and its own retrigger count once, and a step is one hit however many notes its chord has. A stop, a start of a running voice and a start that raised tell nobody. Each hook runs contained (`contained_call`: `strata: voice hit hook failed: ` once per distinct message per hook), never sends and never yields.
- **A factor is applied last and read everywhere** (3.7, plan ruling 13): `with_lfo_offsets` multiplies by the param's engine factors after the clamp and on its early return, so every send of the param carries it and `engine_param_value(id)` is the factored value; `start_value` and `resend_modulated_voice_params` treat a param with a factor as modulated, so a start and a voice sync carry it too. A factor is a finite number above 0 (anything else raises); 1 or nil clears it; the stored param never changes.
- **A value waits only while `S.engine_budget_clock` runs, and the flush clock is never canceled while the script runs** (#654; the `engine budget` invariant: a value waiting has a clock, the clock is a live coroutine, every waiting id has a value). matron may have posted the clock's resume when a send empties the waiting list (another clock of its tick, delivered first), and norns' `clock.resume` raises on a canceled coroutine (`bad argument #1 to 'resume'`). So the clock runs on with nothing waiting to its next wake, the next window's start, and ends there. A value that waits meanwhile is that clock's, sent at that wake: never a second clock, never none while a value waits. Only cleanup step 127 cancels it (the script is ending). A waiting value's sender that raises never ends the flush clock (#637): each waiting value goes on its own, a failure prints `strata: engine send <id> failed: <error>` once per param, and the rest still go, so the clock ends only once nothing waits.

## Machines

### engine budget
- **State:** the local `budget` (`window`, the current window's index; `sent`, its count; `pending[id]` and `order`, the waiting values and the order their ids first waited; `failed`, the ids whose waiting value's sender raised) and `S.engine_budget_clock`, the flush clock; read with `M.budget_state()` and `M.expected_value(id)`. The states: `idle` (nothing waits, no clock), `waiting` (values wait, the clock runs) and `clock to its wake` (the clock runs on with nothing waiting, to the next window's start, where it ends: #654).
- **Invariant:** `engine budget`: a value waits only while the flush clock runs, the clock is a live coroutine, and every waiting id has a value.
- **Test:** `test/unit/engine_sync_test.lua`: "a deferrable send past the window's budget waits with its newest value", "a clock in the flush clock's tick that empties the waiting list leaves the flush clock to end at its wake (#654)", "a value that waits while the flush clock runs on idle goes at its wake, from the same clock (#654)", "count_sends enters direct sends in the budget's window".

No table yet: a value's path through the budget is the contract below (The send budget), and the modulation walk (3.9's package 3c) checks it against the engine calls.

## 3.7's seams

**One hit** (design §0.2): a *hit* is what an envelope or a positions reset restarts on.
- `S.lib.engine_sync.retrigger(voice, velocity, source, gate_seconds)` sends `engine.retrigger(voice - 1, velocity)` and tells the hooks `(voice, {velocity = velocity, source = source, slot = 1, gate_seconds = gate_seconds})`. `source` is `"step"`, `"note"` or `"action"` (anything else raises, naming it); `gate_seconds` is a gated voice's step's gate length (the value `send_gate_seconds` sends), else nil. A voice outside 1..`NUM_VOICES` is left alone. Its callers: `lib/notes.lua`'s `play_own` (`"note"`), the sequencer's `voices` output (`"step"`) and `S.lib.io_actions.retrigger` (`"action"`: crow, ii, OSC).
- `M.start_voice(voice_idx, options)` and the global `toggle_voice(voice_idx, options)` take `options.retrigger_follows`. A start that took effect tells the hooks `(voice, {velocity = 1, source = "start", slot = 1})` after its last send (the voice is marked running by then), unless the option is true. It is true at `play_own`'s start of a stopped voice (its retrigger always follows) and at a gated voice's first step (`voices_play`); every other start (by hand, a grid key, a scene, an action, the startup clock, an ungated voice's first step) is a hit of its own.
- `M.extra_note_hit(voice, slot, velocity)` tells the hooks with `source = "note"` and the extra slot (2 to `NOTE_SLOTS`; anything else is ignored). `start_extra` calls it unless the note's owner is the sequencer's (`NOTES.step_owner`, `"seq"`): the step's own retrigger or start is its one hit.
- The hooks (`S.registry.voice_hit`, `S.register_voice_hit({name, hit})`, read at each use) run in registration order, each with its own copy of `info`, through `S.lib.ui_frame.contained_call` (keyed by the hook's name).
- Lua's hits and the engine's `voiceHit` (package 0c) differ where the engine cannot know what Lua knows: a start followed by its own retrigger is one hit here and two in the engine (`\start`, then `\retrigger`); a step's chord's extra notes are hits in the engine only (`\note`); a start that `start_voice`'s `xpcall` rolls back is a `\start` in the engine and no hit here. The engine's side of the same list is in `docs/notes/engine/structure.md`.

**A factor on an engine value** (design §0.3; tempo follow's on `buf_scan`, 2a):
- `S.lib.engine_sync.set_engine_factor(key, param_id, factor)` keeps one factor per key and param; `engine_factor(param_id)` is the product of every key's (1 with none); `clear_engine_factor(key, param_id)` drops one key's (nothing is sent when it held none). A factor of 1 or nil clears the key's; anything but a finite number above 0 raises, naming the param.
- `with_lfo_offsets` multiplies its result by `engine_factor(id)`: after the clamp when an extra offset modulates the param, and on the early return when nothing does. So the engine can get a value past the param's range (a scan of 2 at a factor of 1.5 is 3), the stored value never moves, and `engine_param_value(id)` carries the factor (what `lib/playheads.lua` should read).
- Setting or clearing a factor resends the param at once, as a base override does (`send_base`). A start's `start_value` and a sync's `resend_modulated_voice_params` treat a param with a factor as modulated, as one with an override or an extra offset, so a start carries the factor before `voiceOn` and a sync ends with the factored value.

## Param → engine

Params that go this way: voice synthesis params, grain and buffer params, crossmod amounts and speed, master density, filter, delay, reverb, tape drift, and `filter_type`.

`send_param_to_engine(id, value)`:
- adds every offset on that param: `with_lfo_offsets(id, value)` = the base override or value, + Σ the extra offsets (the matrix's, which sums the LFOs' home routings with the R routings, and the macros' LFO extras), clamped once, times the param's factors; the value itself when nothing modulates it. The name is 3.4's and stays (ruling 21);
- passes the result to `send_engine_value(id, value)`, which records `S.engine_param_values[id] = value` and runs the sender.

So an edit, a mutation, a scene-fade step or the 10 Hz drift on a modulated param never sends the plain value under a running LFO. That mattered for `bufPos`, which has no lag in the engine: the stored position gave stray grains.

## 3.4's modulation hooks

Three additions, for step locks, LFOs on macros, the matrix and the deferrable writers (design §0.1). The sequencer's step locks and notes use the base override (`docs/notes/lua/sequencer.md`); with no lock or note set, the engine gets what it got in 3.3.

**The base override** (`S.lib.engine_sync.set_base_override(param_id, value)`, `clear_base_override(param_id)`, `engine_base_value(param_id)`):
- While an override is set, `with_lfo_offsets(param_id, value)` starts from it instead of `value`, so every send of the param (its action's, an LFO step's) carries the override plus the offsets. The stored value keeps changing underneath: a param action stores its value and its send is held under the override.
- Setting and clearing send at once, through `send_engine_value(id, with_lfo_offsets(id, params:get(id)))`; clearing a param with no override sends nothing. The value is a finite number (anything else raises, naming the param).
- A voice's sync (`sync_voice_values_to_engine`) ends by sending, in id order, every param of the voice that holds an override or an extra offset, with `with_lfo_offsets(id, params:get(id))`, at once whatever `S.deferrable_write` says: its own sends carry the stored values (as they carry no LFO offset), so without it the engine would lose a step lock or an extra until the param was next sent. A start (`S.lib.engine_sync.start_voice`) sends those values in its own messages, before `voiceOn` for the grains (`start_value`, #632), and ends, once the voice is marked running, by recording each as sent (`send_now(id, value, already_sent)`: counted, `S.engine_param_values` set, no engine call), or sending it when its value is no longer the one the start carried.
- `engine_base_value(id)` is the override, else `params:get(id)`.
- This module registers a touch hook (`S.register_param_touch`) that clears the touched param's override: an encoder, arc or grid edit ends it. The drift's writes (`set_drifted_param`), morph, macros, gesture playback, mutations and recalls are no touch, so none of them ends a step lock.

**Extra offsets** (`S.lib.engine_sync.set_extra_offset(source_key, param_id, offset)`, nil clears): offsets in the param's own units, one per source key (a mod source's key), summed in `with_lfo_offsets` and clamped once to the range (an LFO's home on a Lua param is the matrix's extra, since the groundwork before 3.8). A param with an extra counts as modulated (its value is clamped even when the extras sum to 0). It sends nothing: the source sends the param when it moves. Lua destinations only: a fast destination's extras join the engine's `setFastOffset` sum.

**The send budget** (Question 23): `send_engine_value` counts every send that reaches the engine in the current window, `math.floor(util.time() / ENGINE_BUDGET.window_seconds)` (0.1 s; the window index never goes back):
- What counts (#642): a send reaches the engine unless its id has no engine sender (#646) or its installed sender is the gated one `add_voice_sender` made and the voice is stopped (the question is asked before the send counts or waits, and again when a waiting value goes). One that reaches no engine goes at once, deferrable or not: its value is recorded in `S.engine_param_values`, the id's waiting value is dropped, and nothing is counted or called. So a stopped voice's sends (an LFO, a macro, the matrix, morph) never fill a window that a running voice's sends need, and none waits to be delivered into a voice started since (a start drops its voice's waiting values anyway, `forget_sent_voice_values`). The question is asked rather than a sender reporting whether it sent, because a send past the budget must be kept from waiting before its sender runs. Senders that are not a voice's (the effects, the mute and solo, scatter, the bypasses, the matrix's fast channels, the engine LFOs' keys) count one message a send, as before.
- The master density's messages (#645): its sender sends one `grainDensity` per running voice, so a send of it counts the running voices (`engine_messages`, the count the budget adds and checks; `reaches_engine` is that count above 0): seven running voices cost seven of the window, none costs nothing and never waits.
- A deferrable send whose messages the window has no room left for (its count plus the window's would pass `ENGINE_BUDGET.messages_per_window`, 150) is not sent: it is kept as its id's pending value (a newer one replaces it) and is not recorded in `S.engine_param_values` until it goes. For a one-message send that is the window having had 150, as before; a master density send of seven waits at 144, and a one-message send behind it in the same window still goes while there is room. An empty window takes any send (`window_has_room`), so one larger than a whole window goes at the next window's start, costs that window, and never blocks the flush: what waits behind it follows in the window after.
- The pending values go first in the next window, in the order their ids first waited (the flush stops at the first whose messages do not fit), from the first send of that window or from the flush clock (`S.engine_budget_clock`), which sleeps to the next window's start, starts when a value first waits and ends at its first wake that finds nothing waiting (it is never canceled while the script runs: #654, above). They count against that window; what the budget cannot take waits one more window. Each is delivered inside its own `xpcall` (`flush_pending`): a sender that raises is reported once per param and skipped, so neither the flush clock nor the send that opened the window carries its error.
- `S.lib.engine_sync.expected_value(id)` is the value the engine has or will have for the id: its waiting value when one waits, else `S.engine_param_values[id]` (nil when neither). A module that skips a send because the new value is near the last one compares with this, never with `S.engine_param_values[id]` alone (#591, the Lua-run LFOs).
- `S.lib.engine_sync.record_as_sent(id, value)` records the id as sent with the value and drops its waiting value, as a delivered send does, and sends and counts nothing: for an id another id's command carries (#965: the engine params' PSET hook records every param of a group a silent read changed, then sends the group's command once). It is the only way anything outside this module's sends writes `S.engine_param_values`.
- `S.lib.engine_sync.deferrable(fn)` runs `fn` with `S.deferrable_write` true and puts the flag back as it was, even if `fn` raises (the error is raised again, with its traceback). `fn` never yields: a writer that runs on a clock sleeps outside `deferrable` and wraps each step's writes.
- A send made outside `deferrable` always goes at once (and counts) and drops its id's pending value. `forget_sent_voice_values(voice_idx)` (a voice sync or start) drops the voice's pending values too, so a waiting value never lands after the sync's newer one.
- `S.lib.engine_sync.count_sends(n)` (3.5): `n`, a whole number of at least 0, joins the current window's count as a delivered send's messages do (a new window is entered first, sending its waiting values), for the messages a module sends itself and must not defer (the notes' `noteOn`, `noteOff`, `noteExpression`; design §6.4). It sends nothing and defers nothing: a count past the window's room makes the deferrable sends after it wait, never the counted ones. 0 changes nothing; anything else (a negative number, a fraction, NaN, ±inf, a non-number) raises.
- `budget_state()` returns `{sent = <this window's count>, pending = <ids waiting>}`, for tests.
- Cleanup step 127 cancels the clock and drops what waits: the one cancel of it, as the script ends (norns has freed the engine, #461).

**The budget's contract** (#649), exactly:
- **What it counts:** the engine messages of `send_engine_value`, the one path every `send_param_to_engine` takes (a param's action through its `S.engine_senders` entry, the Lua LFOs, the matrix, the macros' targets, morph's and gesture playback's continuous values, the drift) along with the keyed sends (the matrix's fast channels, the engine LFOs' `lfo<n> engine` and `lfo<n> sync`). Each counts its messages: one; one per running voice the master density reaches; none for a send that reaches no engine (a stopped voice's param, an id with no sender).
- **What it defers:** only such a send made inside `deferrable`, when the window has no room for its messages (an empty window takes any). Nothing made outside `deferrable` waits.
- **What it does not count at all, and never defers:** every engine command sent other than through `send_engine_value`, whoever sends it and whether or not `S.deferrable_write` is set, unless its sender enters it through `count_sends` (3.5's notes: counted, never deferred).

**The exception** (ruling 93): the discrete switches and the voice starts and stops that a recall, a transition's end and a morph crossing apply (`S.lib.scenes.apply_entries`, discrete entries; morph's through `{only = "discrete"}` inside its `deferrable`) run whole, in recall order: voices that stop first, sources before their params, discrete extras after their source, blocks, voices that start last, one sync per running voice whose source changed. What they send other than through `send_engine_value` (the voice starts and stops, the source switches and their syncs, the option, binary and number actions that call the engine themselves: the table below) goes at once and uncounted. The entries whose senders go through `send_engine_value` (listed at the end) are counted and, inside `deferrable` with the window full, wait like any deferrable send, so a crossing's counted part can land a window after its uncounted part. The design never defers a hand edit, a step, a note, a lock or a recall, and a crossing's switch is a recall's. Deferring part of it would break that order (a source after its params, a param into a voice not yet started). Counting a whole voice start against a window meant for continuous values would starve the very sends the budget protects. What bounds a morph's switches instead is their rate: a crossing's switch is applied at most once per `MORPH.crossing_seconds` (0.3 s, #653, ruling 94; `docs/notes/lua/morph.md` has the arithmetic). That uncounted load comes on top of the budget's counted 1500 messages a second, never inside it. With a morph swept across the crossing, the worst sustained load on sclang is the sum:

| Uncounted crossings | Messages a second | With the counted budget |
|---|---|---|
| Every crossing starting all seven voices, the way back stopping them | about 707 | about 2207 |
| A crossing of about 417 messages both ways (every running voice's source switched both ways) | about 1390 | about 2890 |

Leaving voice starts and source switches outside the count, as the design has it, was the maintainer's decision (2026-11-12).

What goes uncounted. Measured with real morph crossings, the numbers are engine messages:

| Uncounted | Engine messages |
|---|---|
| A voice start (`start_voice`) | 59 (a voice's whole set: `setGrainSource`, every grain value and registered grain key, `voiceOn`, the synth params, crossmod, `setModSpeed`, `bend`) |
| A voice stop (`voiceOff`) | 1 |
| A running voice's `v<i>_source` switch | 58 (`setGrainSource`, then `sync_voice_values_to_engine`'s 57) |
| A running voice's `v<i>_grain_mode`, `v<i>_grain_cloud` or `v<i>_mod_source_<k>` | 1 (`grainMode`, `overlapOn`, `setModSource`; the cloud's switch then resends the rate it now plays, one more) |
| A voice's `intervals` set (variation) | 9 (`interval1`-`8`, `intervalCount`) |
| The scale's `root` or `scale` | 1 `setScale` and one `scaleNote` per running voice |
| A voice's `quantize`'s `scaleNote` | 1 (its `quantize` grain key itself is counted) |
| An engine-run LFO's on, destination, shape, mode or division | 2 (`setFastLfo`, `syncFastLfo`; a stop, `stopFastLfo`) |
| A lock's `setScatter` (scatter's lock hook) | 1 |

A crossing between two scenes, all uncounted:

| What the two scenes differ in | Engine messages at once |
|---|---|
| Envelope and grain mode on seven running voices | 14 |
| The same, with each voice's mod source 1 | 21 |
| Envelope and grain mode on all seven voices, one of which starts while another, running, switches its source | 128 |
| All seven voices starting | 417 |

**Discrete entries that do go through `send_engine_value`, and so are counted** (and wait when deferred): the master `filter_type`; a voice's `filter_type`, `mute` and `solo`; `freeze` and `freeze_mode`; `quantize`'s grain key; `seq_gate`; `scatter` and its destination binaries; the effect bypasses. (A Lua-run LFO's restore when the scene turns it off is the matrix's next step since the groundwork before 3.8, a deferrable send of the round robin.)

Commands that carry several params:
- `engine_param_value(id)` is the last value sent, or `params:get(id)` before any.
- `send_filter_to_engine`, `send_delay_to_engine` and `send_reverb_to_engine` build `setFilter`/`setDelay`/`setReverb` from it.
- The grain density sender multiplies by `engine_param_value("master_density")`.
- The master density sender (`send_master_density_to_engine`) multiplies by each running voice's `engine_param_value("v<i>_grain_density")`.

Voice sync and start:
- The parts, as the engine takes them, come from `S.lib.params_setup.voice_engine_parts(voice_idx)` (`docs/notes/lua/params.md`); this file reads no `S.registry.voice_params` (a test checks). A part is `{name, kept, voice_level}`, in order `synth`, `grain`, `crossmod`, `bend`, then one per registered record. Its `kept` entries are `setGrainParam` messages, which the engine keeps for a stopped voice too: the grain part's eight (grainSize, grainDensity = the stored density × `engine_param_value("master_density")`, pitchShift, posSpread, grainMode, bufPos, bufRate, bufScan) and each record's `grain_keys` (in its `send_order`, else sorted by key: 3.8's `grain_controls`, `lib/grain.lua`, sends windowShape, windowSkew, grainProb, overlapOn, grainOverlap = the overlap × master density, and panSpread), then its `sync(voice_idx)`. Its `voice_level` entries are the controls `voiceOn` resets: the synth keys in sorted key order (3.7 sent them in `pairs` order, which differs between Lua and LuaJIT), the `NUM_MOD_SLOTS` slots' source and amounts and `setModSpeed`, and `bend` = `S.midi_state.bend[i]`.
- `send_part_entry` sends one entry: the voice's stored value of its `key`, carried at a start (`start_value`) unless the entry has `carry = false` (grainMode, overlapOn and crossmod), through its `value` conversion, as `setGrainParam`, `setVoiceParam` or the entry's `send`.
- `sync_voice_values_to_engine` (a running voice: a source switch, a scene recall) sends the voice's stored values: `forget_sent_voice_values(voice_idx)` first, then per part its `voice_level` and then its `kept` entries (the synth params, the grain params, crossmod and bend, and the registered voice params), then the modulated params again. It sends no source: the `v<i>_source` action has sent it, both for a switch and for a recall (which syncs a running voice whose source it changed, `docs/notes/lua/scenes.md`).
- `S.lib.engine_sync.start_voice` (a stopped voice) sends the same messages in the start's order: `forget_sent_voice_values`, `send_grain_source` (no hook: the voice is not running yet), `send_voice_type` (3.8), every part's `kept`, `voiceOn`, the grain-restart hooks, every part's `voice_level`; then it marks the voice running. Its values are the sync's, but a param holding a base override or an extra offset carries them (`start_value`, #632). `voiceOn`'s density is the voice's density (so carried) times the master density the engine has, as the grainDensity just sent (an LFO's home on the voice's density is the matrix's extra offset, so the start carries it: ruling 18). A record's `sync` goes before `voiceOn`, so it sends grain params only (`setGrainParam`).
- What a start leaves: for its first milliseconds a synth voice plays its SynthDef defaults for the synth params `voiceOn` does not carry, and a buffer or input voice's first grain has no crossmod and bend 1, until the voice-level values arrive. Those are neutral values, not another run's.

Adding a param that reaches the engine:
- give it a sender in `S.engine_senders` and call `send_param_to_engine` from its action (a per-voice param gets both from `add_voice_param`, through its record's `grain_keys` or `voice_keys`);
- the source, an option no LFO targets and no value, still calls the engine from its action (`send_grain_source`); the grain mode (and 3.8's cloud) and the mod sources send through `send_param_to_engine` since the groundwork before 3.8 (ruling 14: counted and deferrable, the same messages);
- a new SynthDef argument the user controls also needs its default, its place in `param_order` and its spec in its voice type's record (3.8, `lib/types/<key>.lua`, `docs/notes/lua/types.md`; the `synth` record adds and sends it, `get_param_spec()` reads the spec) and the control's exact, case-sensitive name; a grain param is a record's `grain_keys` entry, sent with `setGrainParam`.

## Who is writing

A param's action does not know who set the param; a few flags, each set around one writer's writes, tell it (3.9, #892). Each is set inside an `xpcall` and put back after an error too, so it never outlives its writes.

### Writers

| Writer | Flag | After its writes | What the actions do under it |
|---|---|---|---|
| hand: an encoder, arc ring, grid fader, PARAMS, a mapped CC, MIDI | none | | every action as written: an encoder, arc or grid edit runs the touch hooks (`S.register_param_touch`: it ends a base override, a recording gesture takes it); `note_param_edit` and `note_pattern_edit` end a held undo; the drift takes a `buf_pos` or `grain_pitch` as its new center; the loop length's filter clamps; a scale, root or tuning change snaps the quantized freqs; a `v<i>_source` action runs the source hooks and syncs a running voice; an FX fader redraws a grid that shows it; the screen is redrawn |
| a recall's apply (`apply_entries`: an instant recall, a fade's landing, morph's discrete entries, `apply_voice` in the undo of a voice preset's load, inside the undo's flag) | `S.scene_recall_in_progress`; `S.lib.scenes.setting()` is true | puts back what it found (#892) | the `v<i>_source` and `v<i>_type` actions leave the voice's sync to the end and the source hooks do not run; the `freq` filter and `quantize` do not snap; the loop length's filter stands down; an LFO's settings are only marked; the delay's send is held for the scene-applied hook; `euclid` does nothing; the sequencer's kept next scene is not drawn again; the FX faders do not redraw the grid; the scene-applied hooks run once it ends |
| a fade's step: its loop of sets and its through-zero switches (`lib/scenes.lua`) | `S.lib.scenes.setting()` (the local `fade_step_setting`); `S.scene_transition_active` says only that a fade runs | puts back what it found | the loop length's filter stands down, the quantized freqs are not re-snapped and the FX faders do not redraw the grid (the step redraws once); every other action is a hand edit's (the `freq` filter snaps each step's value; the discrete keys wait for the landing, an apply); morph reads `S.scene_transition_active` as a takeover |
| undo: a randomize's writes and `undo` (`write_as_undo`, `lib/mutation.lua`) | `undo_writing` (local) | puts back what it found | `note_param_edit` and `note_pattern_edit` do not end the undo |
| drift (`set_drifted_param`, `lib/mutation.lua`) | `S.drift_writing` | puts back what it found | `note_param_edit` does not end the undo; `buf_pos` and `grain_pitch` keep their centers (`S.buf_pos_base`, `S.grain_pitch_base`); the action asks for no screen redraw (`drift_update` asks for its own) |
| a gesture's playback (`lib/gestures.lua`, inside `deferrable`) | `S.gesture_playing` | puts back what it found | the touch hook records nothing; the sends wait for the budget (`S.deferrable_write`) |
| a read-only load: a factory set's files (`S.lib.side_files.read_only`, #847) | `reading_only` (`S.lib.side_files.reading_only()`) | puts back what it found | a file that fails to load is skipped, never set aside; the scenes' PSET hook takes the set's scenes with no PSET mark and writes the live file |

Morph, the macros and the LFOs have no writer flag of their own: they write inside `deferrable` (`S.deferrable_write`), which only the send budget and the LFOs read. A scene's sets and the drift's never come through the touch hooks, which only an encoder, arc or grid edit runs.

### The undo's and the drift's flags

The randomize undo's `undo_writing` (`write_as_undo`, `lib/mutation.lua`) and the drift's `S.drift_writing` (`set_drifted_param`) each put back the value they found when their write ends, even when it raises (the error is raised again, with its traceback), as `S.gesture_playing` and `side_files`' `reading_only` do (#892). A write nested in another (a randomize inside a randomize's draw, a drift write inside a drift write's action) therefore leaves the outer write's flag set until the outer write ends, and only the outermost write clears it. `docs/notes/lua/mutation.md` says what each flag keeps the param actions from doing.

## Mirrors of the engine

Lua keeps eleven records of what it sent the engine, each read to decide what to send next, and each reset by its own rule (#916). None reads back: a command the engine's guards ignore (`fastModIndicesValid`, `fastModValuesFinite`, `lib/engine/StrataModulation.sc`) posts one console line while Lua records it as sent, so the two differ until Lua's value next changes (3.9's modulation walk, package 3c, compares the modulation area's records with the engine calls). Each lives in its load's constructor or on that load's fresh `S`, so a script load resets every one.

| Mirror | Holds | Set by | Reset by |
|---|---|---|---|
| `S.engine_param_values[id]` (`lib/engine_sync.lua`) | the last value sent for a param id (with its offsets and factors), or recorded for a send that reached no engine (a stopped voice's, #642) | `deliver` (every `send_engine_value`), a start's `send_now(id, value, already_sent)`, `record_as_sent(id, value)` (the engine params' PSET hook after a silent read, #965; it drops the id's waiting value too) | a voice's sync and start forget the voice's `v<i>_` ids (`forget_sent_voice_values`); a load. `engine_param_value(id)` falls back to `params:get(id)` |
| `sent_sources[voice]` (`lib/engine_sync.lua`) | the source the engine last got (`setGrainSource`), to tell a running voice's source change from the same source again | `send_grain_source`, every `setGrainSource` | a load only (nil: the next send counts as a change) |
| `sent[voice][slot]` (`lib/notes.lua`) | the expression the engine keeps for a note slot, so a note's expression is sent only when it differs | `send_expression`, every `noteExpression` | slot 1's goes back to neutral at the voice's stop (`voiceOn` resets slot 0's); a load (every slot neutral) |
| `regions_sent[voice][slot]` (`lib/notes.lua`) | the region the engine keeps for an extra slot (`0, 0` for none) | `send_slot_region`, every `noteRegion` | a load (`0, 0`, the engine's alloc); kept across a voice's stop, release or cut, as the engine keeps it |
| `sent_mute[voice]` (`lib/voice_mix.lua`) | the `voiceMute` the voice's stage last got (nil: the engine's 0), so only a changed answer is sent | `send_changed_mutes`, the record's `sync` | a load only; every voice sync writes it again |
| `remembered[voice]` (`lib/arp.lua`) | the interval list the engine was last sent, so the LFO step sends a held chord's list only when it differs | `M.sent`, from every `send_intervals_now` (a start's and a sync's included) | a load only |
| `last_sent` and `last_others` (`lib/delay_sync.lua`) | the delay time the delay's sender last sent and the feedback, mix and ping-pong that send carried (`time_unheard`) | `M.sent`, from every `setDelay` | a load only (nil: no send yet, the engine plays `delay_time`'s default) |
| `engine_text` (`lib/tuning.lua`) | the text of the tuning the engine has; a silent read's hook sends the text it takes (#842, #965) | `M.send` (`setTuning` and its tones) | a load (the default tuning's text, which the engine allocs with) |
| `state[n].engine` (`lib/lfos.lua`) | an engine-run LFO's settings as last sent (`setFastLfo`), and that its node exists | `send_fast_lfo` | `reconcile_engine` once the LFO no longer plays in the engine (`stopFastLfo` sent); cleanup; a load |
| the envelope routes' records, `S.engine_param_values["env route <k>"]` (`lib/envelopes.lua`) | a route's settings as last sent (`setFastEnv`), or `false` once `stopFastEnv` went; read through `expected_value`, so a waiting one counts | the budget's `deliver` | a load only: a voice's sync forgets `v<i>_` ids, never these |
| the matrix's fast channels' records, `S.engine_param_values["matrix fast <voice> <destination>"]` (`lib/matrix.lua`) | the offset sum a fast channel last sent (`setFastOffset`), read through `expected_value` | the budget's `deliver` | a load only: the engine's offset node keeps its value across a voice's sync, stop and start |
