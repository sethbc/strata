## Must not break

- Every control param that reaches the engine has an action of the form `function(x) <store x>; send_param_to_engine(id, x) end`, and its engine call lives in `S.engine_senders[id]`. Never call `engine.*` from a control param's action. `test/unit/lfos_test.lua` (every control param with a sender sends its LFO-offset value) puts an offset on each in turn and checks that setting the param sends the sender's call with the offset value, and that a control param without a sender makes no engine call (#316).
- One path from a value to the engine: `send_engine_value` records `S.engine_param_values[id]` and runs the sender. The LFOs send through it too.
- Voice senders run only while the voice is active (`S.lib.engine_sync.add_voice_sender`, which `lib/params_setup.lua`'s `add_voice_sender` calls for every synthesis, grain, buffer and crossmod param and every registered grain key, gates the call on `S.voices[voice_idx].active`). The `v<i>_source` action is the one exception: it also reaches stopped voices.
- **The send budget counts only sends that reach the engine** (#642): a send of an id with no engine sender (#646: `v<i>_seq_gate_length`, the bookmarks, ...) or of a stopped voice's param whose installed sender is the gated one `add_voice_sender` made reaches no engine, so it is never counted and never waits, whether deferrable or not, and a waiting value whose voice has stopped since goes uncounted; its value is still recorded in `S.engine_param_values` (dropping the id's waiting value), as a delivered one is, so `expected_value` and the matrix's compare read what they read before and a start still forgets it. Every other sender counts as before (the mute, which reaches a stopped voice's stage, among them; a sender installed over a gated one later counts too), but the master density, which counts one message per running voice it reaches (0 with none running, and then it never waits, #645).
- A command that carries several params builds the others from `engine_param_value(id)` (what the engine has), so an LFO on one param never undoes an LFO on another.
- A start (`S.lib.engine_sync.start_voice`, which `toggle_voice` and a pattern step call) sends `setGrainSource` and every grain value first (the nine grain params, then the registered voice params' grain keys and syncs, all `setGrainParam`), then `engine.voiceOn` with the grain size, density and pitch just sent, then the voice-level values (every synth param, the crossmod slots, `setModSpeed`, `bend`). The engine keeps a stopped voice's grain values and builds or re-gates its grain synth with them inside `voiceOn`'s bundle, so the first grain plays this start's values; sent after `voiceOn` they arrived late and the first grain played the last run's position, loop, envelope or mode (#325). Nothing but `setGrainParam` goes between the source and `voiceOn`: `voiceOn` resets the voice-level controls, so a voice-level value sent before it is lost (a test fails on it).
- **A start's first values carry the overrides and extra offsets** (#632): every grain value, registered grain key, `voiceOn` argument and synth param a start sends for a param that holds a base override or an extra offset is `with_lfo_offsets(id, stored)` (`start_value`; the stored value otherwise, as before 3.4), so a step that starts a stopped voice (its locks and note set first, `docs/notes/lua/sequencer.md`) plays its first grain with them, and no grain value follows `voiceOn` (a test fails on one). The resend at its end only records what the start already carried; crossmod amounts, which it does not carry, are sent there.
- A start is all or nothing (#382): a send that raises before `voiceOn` has started nothing, and once `voiceOn` is sent a grain-restart hook or a send that raises sends `engine.voiceOff` and raises the error again, so the engine and `voice.active` always agree. `voice.active` is set only once the whole start has gone out.
- Voices are 0-indexed in the engine: always pass `voice_idx - 1`. Mod sources go through `engine_mod_source()` (Lua 0 = none / 1-7 → SC -1 / 0-6).
- Action sends always go out (no dedupe). Only the steps of the Lua-run LFOs and of the matrix (a value near `expected_value`, both since #647) skip sends (`docs/notes/lua/lfos.md`, `docs/notes/lua/matrix.md`).
- Every `engine.setGrainSource` goes through `S.lib.engine_sync.send_grain_source(voice_idx)` (a start's first send and the `v<i>_source` action), which remembers the source the engine has per voice. A running voice whose source changed runs the `S.registry.grain_restart` hooks; the same source again, or a stopped voice's change, runs none. A start runs them after `engine.voiceOn`, before the voice-level values and before it marks the voice running (`lib/midi_in.lua`'s hook relies on that).
- A start redraws nothing itself: `toggle_voice` updates the voice list and redraws the screen and the grid after it, and a pattern step does so once for every voice it starts (#527).
- **A base override is cleared only by a hand edit of its param** (3.4): the touch hook (`S.register_param_touch`, run by an encoder, arc or grid edit) clears it; the drift, morph, a macro, gesture playback, a mutation and a recall run the param's action, whose send stays under the override. Setting and clearing an override send at once.
- **Only a deferrable send waits** (3.4): a send waits for the budget only while `S.deferrable_write` is set (`S.lib.engine_sync.deferrable(fn)`, used by the Lua LFOs, the matrix, morph, gesture playback and every macro apply). Hand edits, steps, notes, locks, recalls and voice syncs are never deferred; a send that goes at once drops its id's waiting value, so an older value never follows a newer one.
- **The budget counts and defers `send_engine_value` only; a discrete switch is its exception** (#649, ruling 93): every engine command sent another way (a voice start or stop, a voice sync, and the actions of the option, binary and number params that call the engine themselves) is never counted and never deferred, inside `deferrable` too. So the discrete switch a recall, a transition's end or a morph crossing applies goes out whole, at once, in recall order, however full the window, and leaves the count where it was (a test pins it, with a crossing at a full window); its continuous values beside it still wait. The contract, the commands and the measured sizes are below (The send budget, The exception).
- **A voice sync or start drops the voice's waiting values** (`forget_sent_voice_values`): they are older than what the sync sends.
- **A voice sync or start keeps the voice's overrides and extra offsets**: after a sync's own sends (which carry the stored values) it sends every param of the voice that holds a base override or an extra offset again, through `with_lfo_offsets`, at once and never deferred; a start's own sends carried them already (above), so it records them as sent and sends again only one a grain-restart hook changed meanwhile (and the crossmod amounts); with none set either sends exactly what it sent before 3.4.
- **`deferrable(fn)`'s `fn` never yields** (no `clock.sleep` or `clock.sync` inside it): `S.deferrable_write` would stay set across the wait, and a hand edit made meanwhile would be deferred. A caller that waits sleeps outside `deferrable` and wraps each burst of writes.
- **A base override is a finite number**: `set_base_override` raises, naming the param, for anything else (nil, a string, NaN, ±inf); a caller clears with `clear_base_override`.
- **Values wait exactly while `S.engine_budget_clock` runs** (the `engine budget` invariant); cleanup step 127 cancels it. A waiting value's sender that raises never ends the flush clock (#637): each waiting value goes on its own, a failure prints `strata: engine send <id> failed: <error>` once per param, and the rest still go, so the clock ends only once nothing waits.

## Param → engine

Params that go this way: voice synthesis params, grain and buffer params, crossmod amounts and speed, master density, filter, delay, reverb, tape drift, and `filter_type`.

`send_param_to_engine(id, value)`:
- adds the offsets of every global LFO on that param: `with_lfo_offsets(id, value)` = value + Σ `S.lfo_scaled` × half the range, clamped; the value itself when no LFO is on it;
- passes the result to `send_engine_value(id, value)`, which records `S.engine_param_values[id] = value` and runs the sender.

So an edit, a mutation, a scene-fade step or the 10 Hz drift on a modulated param never sends the plain value under a running LFO. That mattered for `bufPos`, which has no lag in the engine: the stored position gave stray grains.

## 3.4's modulation hooks

Three additions, for step locks, LFOs on macros, the matrix and the deferrable writers (design §0.1). The sequencer's step locks and notes use the base override (`docs/notes/lua/sequencer.md`); with no lock or note set, the engine gets what it got in 3.3.

**The base override** (`S.lib.engine_sync.set_base_override(param_id, value)`, `clear_base_override(param_id)`, `engine_base_value(param_id)`):
- While an override is set, `with_lfo_offsets(param_id, value)` starts from it instead of `value`, so every send of the param (its action's, an LFO step's) carries the override plus the offsets. The stored value keeps changing underneath: a param action stores its value and its send is held under the override.
- Setting and clearing send at once, through `send_engine_value(id, with_lfo_offsets(id, params:get(id)))`; clearing a param with no override sends nothing. The value is a finite number (anything else raises, naming the param).
- A voice's sync (`sync_voice_values_to_engine`) ends by sending, in id order, every param of the voice that holds an override or an extra offset, with `with_lfo_offsets(id, params:get(id))`, at once whatever `S.deferrable_write` says: its own sends carry the stored values (as they carry no LFO offset), so without it the engine would lose a step lock or an extra until the param was next sent. A start (`S.lib.engine_sync.start_voice`) sends those values in its own messages, before `voiceOn` for the grains (`start_value`, #632), and ends, once the voice is marked running, by recording each as sent (`send_now(id, value, already_sent)`: counted, `S.engine_param_values` set, no engine call), or sending it when its value is no longer the one the start carried.
- `engine_base_value(id)` is the override, else `params:get(id)`.
- This module registers a touch hook (`S.register_param_touch`) that clears the touched param's override: an encoder, arc or grid edit ends it. The drift's writes (`set_drifted_param`), morph, macros, gesture playback, mutations and recalls are no touch, so none of them ends a step lock.

**Extra offsets** (`S.lib.engine_sync.set_extra_offset(source_key, param_id, offset)`, nil clears): offsets in the param's own units, one per source key (a mod source's key), summed in `with_lfo_offsets` with the LFOs' offsets (scaled × half the range) and clamped once to the range with them. A param with an extra counts as modulated (its value is clamped even when the extras sum to 0). It sends nothing: the source sends the param when it moves. Lua destinations only: a fast destination's extras join the engine's `setFastOffset` sum.

**The send budget** (Question 23): `send_engine_value` counts every send that reaches the engine in the current window, `math.floor(util.time() / ENGINE_BUDGET.window_seconds)` (0.1 s; the window index never goes back):
- What counts (#642): a send reaches the engine unless its id has no engine sender (#646) or its installed sender is the gated one `add_voice_sender` made and the voice is stopped (the question is asked before the send counts or waits, and again when a waiting value goes). One that reaches no engine goes at once, deferrable or not: its value is recorded in `S.engine_param_values`, the id's waiting value is dropped, and nothing is counted or called. So a stopped voice's sends (an LFO, a macro, the matrix, morph) never fill a window that a running voice's sends need, and none waits to be delivered into a voice started since (a start drops its voice's waiting values anyway, `forget_sent_voice_values`). The question is asked rather than a sender reporting whether it sent, because a send past the budget must be kept from waiting before its sender runs. Senders that are not a voice's (the effects, the mute and solo, scatter, the bypasses, the matrix's fast channels, the engine LFOs' keys) count one message a send, as before.
- The master density's messages (#645): its sender sends one `grainDensity` per running voice, so a send of it counts the running voices (`engine_messages`, the count the budget adds and checks; `reaches_engine` is that count above 0): seven running voices cost seven of the window, none costs nothing and never waits.
- A deferrable send whose messages the window has no room left for (its count plus the window's would pass `ENGINE_BUDGET.messages_per_window`, 150) is not sent: it is kept as its id's pending value (a newer one replaces it) and is not recorded in `S.engine_param_values` until it goes. For a one-message send that is the window having had 150, as before; a master density send of seven waits at 144, and a one-message send behind it in the same window still goes while there is room. An empty window takes any send (`window_has_room`), so one larger than a whole window goes at the next window's start, costs that window, and never blocks the flush: what waits behind it follows in the window after.
- The pending values go first in the next window, in the order their ids first waited (the flush stops at the first whose messages do not fit), from the first send of that window or from the flush clock (`S.engine_budget_clock`), which sleeps to the next window's start and runs only while something waits. They count against that window; what the budget cannot take waits one more window. Each is delivered inside its own `xpcall` (`flush_pending`): a sender that raises is reported once per param and skipped, so neither the flush clock nor the send that opened the window carries its error.
- `S.lib.engine_sync.expected_value(id)` is the value the engine has or will have for the id: its waiting value when one waits, else `S.engine_param_values[id]` (nil when neither). A module that skips a send because the new value is near the last one compares with this, never with `S.engine_param_values[id]` alone (#591: the Lua LFOs).
- `S.lib.engine_sync.deferrable(fn)` runs `fn` with `S.deferrable_write` true and puts the flag back as it was, even if `fn` raises (the error is raised again, with its traceback). `fn` never yields: a writer that runs on a clock sleeps outside `deferrable` and wraps each step's writes.
- A send made outside `deferrable` always goes at once (and counts) and drops its id's pending value. `forget_sent_voice_values(voice_idx)` (a voice sync or start) drops the voice's pending values too, so a waiting value never lands after the sync's newer one.
- `budget_state()` returns `{sent = <this window's count>, pending = <ids waiting>}`, for tests.
- Cleanup step 127 cancels the clock and drops what waits.

**The budget's contract** (#649), exactly:
- **What it counts:** the engine messages of `send_engine_value`, the one path every `send_param_to_engine` takes (a param's action through its `S.engine_senders` entry, the Lua LFOs, the matrix, the macros' targets, morph's and gesture playback's continuous values, the drift) along with the keyed sends (the matrix's fast channels, the engine LFOs' `lfo<n> engine` and `lfo<n> sync`). Each counts its messages: one; one per running voice the master density reaches; none for a send that reaches no engine (a stopped voice's param, an id with no sender).
- **What it defers:** only such a send made inside `deferrable`, when the window has no room for its messages (an empty window takes any). Nothing made outside `deferrable` waits.
- **What it does not count at all, and never defers:** every engine command sent other than through `send_engine_value`, whoever sends it and whether or not `S.deferrable_write` is set.

**The exception** (ruling 93): the discrete switches and the voice starts and stops that a recall, a transition's end and a morph crossing apply (`S.lib.scenes.apply_entries`, discrete entries; morph's through `{only = "discrete"}` inside its `deferrable`) go at once and uncounted, whole, in recall order: voices that stop first, sources before their params, discrete extras after their source, blocks, voices that start last, one sync per running voice whose source changed. The design never defers a hand edit, a step, a note, a lock or a recall, and a crossing's switch is a recall's. Deferring part of it would break that order (a source after its params, a param into a voice not yet started). Counting a whole voice start against a window meant for continuous values would starve the very sends the budget protects. What bounds a morph's switches instead is their rate: a crossing's switch is applied at most once per `MORPH.crossing_seconds` (0.3 s, #653, ruling 94; `docs/notes/lua/morph.md` has the arithmetic).

What goes uncounted. Measured with real morph crossings, the numbers are engine messages:

|---|---|
| A voice start (`start_voice`) | 59 (a voice's whole set: `setGrainSource`, every grain value and registered grain key, `voiceOn`, the synth params, crossmod, `setModSpeed`, `bend`) |
| A voice stop (`voiceOff`) | 1 |
| A running voice's `v<i>_source` switch | 58 (`setGrainSource`, then `sync_voice_values_to_engine`'s 57) |

|---|---|

| The same, with each voice's mod source 1 | 21 |

**Discrete entries that do go through `send_engine_value`, and so are counted** (and wait when deferred): the master `filter_type`; a voice's `filter_type`, `mute` and `solo`; `freeze` and `freeze_mode`; `quantize`'s grain key; `seq_gate`; `scatter` and its destination binaries; the effect bypasses; a Lua-run LFO's restore when the scene turns it off (its destination's send).

Commands that carry several params:
- `engine_param_value(id)` is the last value sent, or `params:get(id)` before any.
- `send_filter_to_engine`, `send_delay_to_engine` and `send_reverb_to_engine` build `setFilter`/`setDelay`/`setReverb` from it.
- The grain density sender multiplies by `engine_param_value("master_density")`.
- The master density sender (`send_master_density_to_engine`) multiplies by each running voice's `engine_param_value("v<i>_grain_density")`.

Voice sync and start:
- The parts, as the engine takes them: `send_grain_params` (grainSize, grainDensity = the stored density × `engine_param_value("master_density")`, pitchShift, posSpread, envShape, grainMode, bufPos, bufRate, bufScan) and `send_registered_voice_values` are `setGrainParam` messages, which the engine keeps for a stopped voice too; `send_synth_params` (every `voices[i].params` entry) and `send_crossmod_and_bend` (the `NUM_MOD_SLOTS` slots, `setModSpeed`, `bend` = `S.midi_state.bend[i]`) are voice-level controls, which `voiceOn` resets.
- `sync_voice_values_to_engine` (a running voice: a source switch, a scene recall) sends the voice's stored values: `forget_sent_voice_values(voice_idx)` first, so an LFO re-applies its offset on its next step, then the synth params, the grain params, crossmod and bend, and the registered voice params. It sends no source: the `v<i>_source` action has sent it, both for a switch and for a recall (which syncs a running voice whose source it changed, `docs/notes/lua/scenes.md`).
- `S.lib.engine_sync.start_voice` (a stopped voice) sends the same messages in the start's order: `forget_sent_voice_values`, `send_grain_source` (no hook: the voice is not running yet), the grain params, the registered voice params, `voiceOn`, the grain-restart hooks, the synth params, crossmod and bend; then it marks the voice running. Its values are the sync's, but a param holding a base override or an extra offset carries them (`start_value`, #632). `voiceOn`'s density is the voice's density (so carried) times the master density the engine has, as the grainDensity just sent (a Lua LFO on the voice's density re-applies its offset on its next step).
- The registered voice params (`send_registered_voice_values`): per `S.registry.voice_params` record, in registration order, each `grain_keys` entry (sorted by key) with the voice's `extras[key]`, then the record's `sync(voice_idx)` (`docs/notes/lua/params.md`). At a start they go before `voiceOn`, so a record's `sync` sends grain params only (`setGrainParam`).
- What a start leaves: for its first milliseconds a synth voice plays its SynthDef defaults for the synth params `voiceOn` does not carry, and a buffer or input voice's first grain has no crossmod and bend 1, until the voice-level values arrive. Those are neutral values, not another run's.

Adding a param that reaches the engine:
- give it a sender in `S.engine_senders` and call `send_param_to_engine` from its action;
- option and number params the LFOs cannot target (source, grain envelope/mode, mod sources) still call the engine from their action.
