## Must not break

- A default start sounds as 3.7.0's (3.8's plain sends, design §7.1): every `v<i>_dry`, `v<i>_delay_send` and `v<i>_reverb_send` defaults to 1, every `v<i>_filter_mix` to 0, `delay_to_reverb` to 1 and the bypass params to off; the reverb's level (`reverb_mix`, `lib/params_setup.lua`) starts at 0.43.
- `v<i>_dry` is the stage's dry level (grain key `dry`): a scene key (default 1) and in the record's fader group, never in its `randomize` (a draw near 0 would silence the voice's dry sound) and no LFO destination. The sends are taken before it, in the engine (`docs/notes/engine/mix.md`).
- The voice params reach the engine only through their registered grain keys (`setGrainParam`, while the voice runs) and the voice sync; never `engine.*` from an action. `filter_type` goes as its option minus 1 (`filterType` 0-2).
- `filter_type` is a discrete scene field (it switches at a transition's end); the other six crossfade. The cutoff and the two sends are LFO destinations (`v<i> vfilt`, `v<i> dsend`, `v<i> rsend`), each in its voice's group after history (3.7: the list is by voice, and an LFO keeps its destination by key).
- The bypass is explicit: only `delay_bypass` and `reverb_bypass` send `engine.setBypass`. A level of 0 (E3, PARAMS, an LFO, a scene fade, a MIDI CC) never sets a bypass, and a bypass never changes a level.
- A bypass ends its effect's freeze first (3.8, design §7.3): the action calls `S.lib.fx_hold.release(effect)` before it sends, so `setDelayFreeze(0)` goes out before `setBypass(0, 1)` (the reverb's `setReverbFreeze(0)` before `setBypass(1, 1)`, 3.9) and the lift starts unfrozen; `release` does nothing for an effect whose freeze is not offered (the reverb on the standard tier). `docs/notes/lua/fx-hold.md`
- PSETs store the bypass params (they are params); scenes never capture or recall them. MAIN's randomize and the mutations never touch any param of this module (no `main_randomize` or `mutate` group). The fader pages show the cutoff, resonance and mix, the dry level and both sends (`fader = {{keys = {"filter_freq", "filter_res", "filter_mix", "dry", "delay_send", "reverb_send"}, rank = 1}}`, right after 3.7's faders, the groundwork before 3.8, `dry` 3.8's); `filter_type` (an option), mute and solo get none. A quick ALT+K2 on VOICE's filter & sends section is the one exception (#557): the record's `randomize` draws `filter_type` (a uniform option), `filter_freq` (100-8000 Hz, even in octaves), `filter_res` (0-0.7, below self-oscillation) and `delay_send` and `reverb_send` (0-0.6 each); `filter_mix` is kept (0 would leave the filter out), and so are `dry` and the bypass params.

- **Mute and solo (3.4)**: a mute silences in the mix stage (`voiceMute`) and never stops a voice; scenes store `mute` (discrete, `fill_scene` default 0) and never `solo`. `S.lib.voice_mix.soloed(voice)` (soloed and not silenced) is what MAIN's list marks `s`. What the engine gets is `S.lib.voice_mix.silenced(voice)` (muted, or some voice is soloed and this one is not; false for any argument that is not a voice), sent by the record's `sync` (unconditionally, before `voiceOn`) and by the params' own senders, never through `grain_keys` (a grain key sends a stored value as it is). A change of any mute or solo sends to every voice whose answer changed, running or stopped (#640): the stage is one persistent node per voice (`docs/notes/engine/mix.md`), so a voice stopped while its release still sounds goes silent within the mute's 20 ms, and an unmute lets the rest of the release sound. This is the one exception, besides `v<i>_source`, to param actions reaching the engine only while a voice runs: `setGrainParam` `voiceMute` on a stopped voice only sets its stage and keeps the value (`setStageParam`), creating no node. Neither is in the record's `randomize`.
- **The silence hooks (3.6's 0a)**: whenever a mute or a solo param is set by anything (its action: a key, a scene recall, a PSET load), every `S.registry.silence_change` hook (`S.register_silence_change`) runs, contained (`strata: silence change hook <n> failed: ` once per message), with `(voice_idx, silenced)` for each voice, in voice order, whose `silenced(voice)` differs from the answer the module last told (`told_silenced`, false at start). That record is the hooks' own (plan ruling 16), never `sent_mute`, which a voice's sync also writes; so a start or stop tells nothing, and a set to the same value tells nothing. The targets end a silenced voice's notes from it.

## lib/voice_mix.lua (`S.lib.voice_mix`)

One registered voice-param record (`S.register_voice_params`, `docs/notes/lua/params.md`), `voice_mix` (count 9), per voice:

| Param | Kind | Range, default | Grain key |
|---|---|---|---|
| `v<i>_filter_type` | option | lowpass / highpass / bandpass, lowpass | `filterType` (option − 1) |
| `v<i>_filter_freq` | control | 20-20000 Hz exp, 5000 | `filterFreq` |
| `v<i>_filter_res` | control | 0-1, 0.5 | `filterRes` |
| `v<i>_filter_mix` | control | 0-1, 0 (the filter left out) | `filterMix` |
| `v<i>_dry` | control | 0-1, 1 (shown as a percent, `100 %`; 3.8) | `dry` |
| `v<i>_delay_send` | control | 0-1, 1 (shown as a percent, `100 %`) | `delaySend` |
| `v<i>_reverb_send` | control | 0-1, 1 (shown as a percent, `100 %`) | `reverbSend` |
| `v<i>_mute` | binary | 0 | none: `voiceMute` is the effective mute (`silenced`), sent by the record's `sync` and a sender of its own (to a stopped voice too) |
| `v<i>_solo` | binary | 0, in no scene | none (as `mute`) |

- Stored in `S.voices[i].values`; scene defaults are the param defaults, and `discrete = {filter_type = {1, 3}, mute = {0, 1}}` (`scene_defaults.mute` = 0; `solo` is in neither). VOICE shows `mute` and `solo` as binary rows after the sends.
- VOICE: the section `filter & sends`, after mix, on every source (`M.VOICE_MIX.section`). Its `layout_states` put each voice on each source (synth, buf 1, input) with the cursor on the section's first and last row, at bandpass and 20000 Hz.
- LFO destinations (`S.register_lfo_destination`): `vfilt` (`filter_freq`), `dsend` (`delay_send`), `rsend` (`reverb_send`), then 3.4's `amp` (the voice's `amp`, 97-103; `vfilt` and `amp` run in the engine, `docs/notes/lua/lfos.md`). `lib/history.lua` is included first, so `v<i> hist` comes before them.

The bypass params (`S.register_fx_params`, record `bypass`, count 2), at the end of the fx group (before lib/delay_sync.lua's record): `delay_bypass` and `reverb_bypass`, binary toggles, default 0 (`M.BYPASS`, in `M.BYPASS_ORDER`). Their senders (`S.engine_senders`, set in the record's `add`) call `engine.setBypass(0, v)` and `engine.setBypass(1, v)`; their actions go through `send_param_to_engine`. `M.bypassed(effect)` ("delay", "reverb") is true while the param is on; the FX page reads it (`docs/notes/lua/pages/fx.md`).

3.8's delay into the reverb (`S.register_fx_params`, record `sends`, count 1, after the bypass params; `M.DELAY_TO_REVERB`): `delay_to_reverb`, a control 0-1, default 1, shown in percent, named `delay to reverb`: how much of the delay's return the reverb takes. Its action calls `note_param_edit` and `send_param_to_engine`; its sender is the reverb's (`S.engine_senders.delay_to_reverb`, `lib/engine_sync.lua`: `setReverb`'s fourth value). A continuous scene global (`S.register_scene_field`, default 1) and a global LFO destination, `dly>rev`, after the built-in globals (so every per-voice destination's index is one more than 3.7's; destinations are stored by key).

The engine side (the voice filter and the plain sends in each voice's stage, the returns' levels, the bypass that frees and re-creates the node) is in `docs/notes/engine/mix.md` and `docs/notes/engine/effects.md`.
