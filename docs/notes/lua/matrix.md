## Must not break

- **The matrix adds offsets and never sets a destination param**: like the LFOs it modulates around the stored value (or a step lock's base override, `engine_base_value`), and no routing ever calls `params:set` on its destination. The only params it sets are its own: a depth (the 25 % rule of `edit_routing`, `clear`) and an on/off (`clear`).
- **One sum and one clamp per destination**: a Lua destination's routings sum into one extra offset, `S.lib.engine_sync.set_extra_offset("matrix", id, sum)` (the sum of `S.lib.lfos.offset_for(id, m)`), which `with_lfo_offsets` adds to the Lua-run LFOs' offsets and the macros' LFO extras and clamps once to the param's range: +100 % and −100 % cancel instead of clamping each other.
- **Fast destinations only through `setFastOffset`** (design §10.2, which binds over §13's test lines: ruling 62): the five fast params (`S.lib.lfos.fast_destination`: a voice's `grain_pitch`, `buf_pos`, `grain_size`, `filter_freq` and `amp`) never get a `setGrainParam` or a Lua offset from the matrix: their routings' sum and the macros' fast extras (`set_fast_extra`) go to the engine as `engine.setFastOffset(voice - 1, 0, destination, sum)`, the sum clamped to −2..2 half ranges in Lua (the engine clips to the same, but the stub accepts any finite offset), so one clip applies. The engine adds it to the engine LFOs and scatter on the bus.
- **Every fast send counts against the send budget** (ruling 65): each fast channel (voice, destination) is one deferrable id, its key `matrix fast <voice> <destination>` (no param id holds a space, and none starts `v<i>_`, so a voice sync's `forget_sent_voice_values` never touches it), whose engine sender (`S.engine_senders[key]`, registered at include time for the 35 channels) sends `setFastOffset`. The round robin's send is `S.lib.engine_sync.send_engine_value(key, sum)`, inside `deferrable`: counted in `ENGINE_BUDGET`'s 150 per 100 ms, past it waiting as the key's one pending value (the newest sum winning) and going out first in the next window. The value the engine last got is `S.engine_param_values[key]`. Never `engine.setFastOffset` straight from the step.
- **Destinations never include macros, LFO params or matrix depths** (nor the morph): `destination_ids()` is the LFO destination list without `none` and the global `macro <m>` entries, filtered again by `MATRIX.never`, so no source's value can depend on a routing. `edit_routing` and learn take only these ids; a macro may target a matrix depth (Question 38), and an LFO on a macro leaves that target alone (`lib/macros.lua`).
- **Every send goes through the LFOs' round robin** (`S.lib.lfos.mark_due`): at most `LFO.sends_per_step` (12) a step for the LFOs and the matrix together, each inside `deferrable`. A Lua destination's key is its param id, the LFOs' key for it too, so one send carries every layer. A fast destination's key is its channel's.
- **A Lua destination is resent when its value moved past `LFO.send_threshold` from what was last handed to the budget, while the engine still has what it had then, else from `S.engine_param_values[id]`** (what the engine last got, along its warp, unrounded), never from the matrix's own last sum: a value back at the delivered one while another waits in the budget is sent, so it replaces the waiting one; once the engine's value changed (the handed one delivered, a hand edit, a sync) the engine's is the reference, so what the engine has forgotten, the next step sends again (a voice sync and a start resend an offset param themselves, `resend_modulated_voice_params`). The handed value is the matrix's own send's (`lua_handed`); a send of the same key by an LFO or a macro is not seen, and is corrected at the step after it lands. A fast destination is resent when its clamped sum moved by `LFO.send_threshold` half ranges from the value last handed to the budget (only the matrix sends its channel's key, so it is what the engine has or will have; the engine's `S.engine_param_values[key]` before any); a voice start or sync resends no unmoved channel (the offset node is persistent and keeps its values, `docs/notes/engine/modulation.md`). **A destination whose sum returns to 0 is sent once more**: a Lua one gives its extra offset up and sends its base with the other layers' offsets, a fast one sends 0, whatever the size of its last offset, and also while a nonzero sum still waits in the budget (the value last handed to it, `fast_handed`), so a stale sum never lands after the routing stopped. A fast channel stays tracked until its sum, the engine's value and the handed value are all 0.
- **Each routing and each destination is contained** (#517): every routing's read (its source's value, its destination's resolution) and every destination's update runs in `S.lib.ui_frame.contained_call`, keyed by routing (`matrix routing <k>`) or param id (`matrix destination <id>`): one that raises is skipped at that step, printing `strata: <label> failed:` once per message, and every other routing and destination still plays at every step. A raising engine sender is the round robin's own containment (`LFO send`).
- **An idle step does nothing**: with no routing holding both parts, no offset held and no fast extra, the step returns before touching a table; otherwise its sums and id lists are reused tables, emptied each step, and its send functions and labels are made once per id.
- **A routing plays only while it is on, both its parts are set and known, and its depth is not 0**; a source whose value is not finite reads 0 (`S.lib.mod_sources.normalized`) and reaches nothing: no extra offset, no `setFastOffset`.
- **`set_routing` never applies the 25 % rule**: a recall, a transition's or morph's switch and a PSET load leave the depth as their own params set it. Only `edit_routing` (MOD's edits and learn) gives a routing it completes at depth 0 the depth `MATRIX.new_depth` (25 %).
- **A routing whose source or destination differs between two scenes ramps through 0**: the scene block's `through_zero` names its depth, which a transition fades A × (1 − 2f) to the midpoint and B × (2f − 1) after it, with the routing switched (`set_routing`) once at the midpoint; morph does the same at its crossing (0.52 from A, 0.48 from B). A routing that matches in both crossfades its depth; the on/off switches at a fade's end.
- **Unknown parts are kept verbatim**: a source key or destination id this build lacks (a later release's scene, PSET or live file) is kept, saved again as it was, reported with a console line at each file load and, for a scene, once a session per distinct key or id at the first block apply that holds it (a recall, a fade's end and morph's crossing apply it again and again, the scene sequencer's recalls too), and the routing does not play.
- **Files** go through `S.lib.data_files` only (`write`, `read`, `set_aside`): a missing side file loads no routings (a PSET from before 3.4), an unreadable or invalid one is set aside (`<file>.bak`, ...) with a console line and loads none, and the PSET still loads. The PSET hook's write always writes, an empty side file too, so a PSET saved over never keeps an older one.
- **A live file that could be neither read nor set aside is never written over** (scenes.data's rule): the start step marks the live file loaded only when it was read, missing or set aside; otherwise the routings are not saved in the session (no timed write, nothing at cleanup), with one console line (`... the routings will not be saved this session`).
- **Cleanup sends nothing** (#461; ruling 63, over §10.2's "sends every fast offset to 0"): its step cancels learn and forgets the matrix's offsets; norns has freed the engine by then.
- **Learn** waits exactly while its timeout clock runs (`S.matrix_learn_clock`, the `matrix learn` invariant), `MATRIX.learn_seconds` (10 s); `cancel_learn` ends both. Its end never cancels the clock once its resume may be posted (#626): within `MATRIX.learn_wake_margin` (0.1 s) of the wake the clock is retired (its token goes old, and at its wake it ends, touching nothing a newer learn armed; the cleanup step cancels a retired one still waiting), and only earlier is it canceled, so a burst of learns holds no clock slots.
- **Every flash fits the header's flash room** (`S.constants.HEADER.flash_width`, 74 px) whole: `not a destination` (74 px), the widest learned destination `R10 > v2 spread` (68 px).

## Owns

`lib/matrix.lua` (`S.lib.matrix`, 3.4, package 1h, design §10.2):
- `add_params()`: the group `strata_matrix` ("matrix", 2 × `MATRIX_SLOTS` = 32) with, per routing k (1-16), `matrix_<k>_depth` ("R<k> depth", control −100..100 %, step 1, default 0, shown `+40%`; its action calls `note_param_edit`, so MOD's randomize can undo it) and `matrix_<k>` ("R<k> on", binary toggle, default 1). `lib/params_setup.lua`'s menu record `matrix` calls it, after scatter.
- `S.matrix[k] = {source, dest}`: a source key of `S.registry.mod_sources` and a destination id of `destination_ids()`, each `""` for none.
- `routing(k)` (`{source, dest, depth, on}`, `on` a boolean; nil for no routing), `set_routing(k, source_key, dest_id)` (strings of at most `MATRIX.max_text`, 32, characters, unknown ones kept; returns whether it set the routing), `edit_routing(k, source_key, dest_id)` (each part `""`, known, or the part already held; returns whether it set the routing), `clear(k)` (no source or destination, depth 0, on), `destination_ids()`, `learn(k)`, `learning()` (the routing, or nil), `cancel_learn()`, `uses_source(key)`, `affects(voice)`, `offset(param_id)`, `set_fast_extra(source_key, param_id, m)`.
- `MATRIX`, the module's one table of tunables and names (`new_depth` 25, `fast_limit` 2, `note_slot` 0, `extra_key` `matrix`, `learn_seconds` 10, `learn_wake_margin` 0.1, `save_delay` 0.1, `max_text` 32, the files' version and suffixes, the `never` patterns).
- `S.matrix_learn_clock`, `S.matrix_save_clock`; the engine senders of the 35 fast channels (`matrix fast <voice> <destination>`); the LFO step hook (`S.lib.lfos.on_step`); the touch hook (learn); the scene fields `matrix_<k>_depth` (continuous) and `matrix_<k>` (discrete); the scene block `matrix`; the PSET hook `matrix`; the start step `matrix_load` (108), the cleanup steps `matrix_save` (36) and `matrix` (118); the invariant `matrix learn`.

Elsewhere: the MOD page and its rings (package 2a) draw and edit the routings through these functions; MAIN's `~` (2a) reads `affects(voice)`; the LFO page reads `uses_source("lfo<n>")` for its ` R` mark (`docs/notes/lua/pages/lfo.md`); `lib/macros.lua` calls `set_fast_extra` for an LFO on a macro's fast target.

## Destinations

`destination_ids()`, in this order, only ids whose params exist now (the list is rebuilt when params are added): every LFO destination (`S.LFO_DESTINATIONS`) but `none` and the global `macro <m>` entries, by param id, a voice's `main` as `v<i>_main`: the 67 built-in ones (11 globals, then per voice its main entry and seven grain and buffer params), then the registered ones (`hist`, `vfilt`, `dsend`, `rsend`, `amp` per voice), 102 in all. Any later `register_lfo_destination` becomes a matrix destination too. `v<i>_main` resolves through `main_param_id(i)` at each step, so it follows the voice's source: a synth voice's main param runs in Lua, a buffer voice's `buf_pos` on the fast path.

## The step

The matrix steps in the LFO clock, as a hook of `S.lib.lfos.on_step`, after the six LFOs, so a routing from an LFO reads that step's value, and after the macros' hook (it registers first: `lib/macros.lua` is included before `lib/matrix.lua`). Per playing routing, `m = depth / 100 × S.lib.mod_sources.normalized(source)` (−1..1 for a bipolar source, 0..1 for a unipolar one, design §10.2), summed by the param the destination resolves to:
- a Lua destination: the sum's `offset_for` becomes the extra offset `matrix` on the param, and a send of it is marked due when its value moved (above); a destination the matrix held whose sum is now 0 (no playing routing reaches it, or its routings cancel) gives the offset up and is marked due once;
- a fast destination: the sum plus every fast extra on it, clamped to −2..2, is what its next send carries (`offset(param_id)`), marked due under its channel's key when it moved from `S.engine_param_values[key]`; the round robin's send hands it to `send_engine_value(key, sum)` (counted, maybe waiting for the next window), whose sender calls `setFastOffset`; one whose sum returns to 0 is sent 0 once (or as long as the engine or the budget holds another value).

Each routing's read and each destination's update is contained (above); a raising one prints once and the rest of the step goes on. A step with nothing to do returns at once.

`set_fast_extra(source_key, param_id, m)` records the macros' extras (half ranges, by source key `macro<m>`, nil or a value that is not finite clearing it; a param that is no fast destination is ignored). The macros call it at once, never through the round robin (#636: the hand-over reaches no engine), so an extra joins the sum at the matrix's next step: the same step when the LFO step or the macros' hook (both before the matrix's) hands it over.

`uses_source(key)` and `affects(voice)` read the playing routings: a routing that is off, incomplete, at depth 0 or with an unknown part counts for neither. `offset(param_id)` is the matrix's current sum on a param: the extra offset on a Lua destination (in its units), the clamped sum on a fast one (half ranges); 0 when nothing reaches it.

## Learn

`learn(k)` (MOD's ALT+K3 on the routing view's `dest` row, package 2a) arms routing k's destination; the next param a hand touches (the `param_touch` registry: an encoder, an arc ring, a grid fader) that is a destination becomes it through `edit_routing` (the 25 % rule applies), and the header flashes `R<k> > <label>` (`R3 > v3 pitch`). A touched voice's main param that is no destination itself learns `v<i>_main`. Any other touched param (a macro, an LFO param, a matrix depth, an option) flashes `not a destination`, and learn waits on. `cancel_learn()` (MOD's K2 in its view, or its routing view showing another routing), a new `learn` or 10 s without a touch ends it; a page change does not (ruling 80: the touch is made on another page).

## Storage

- Scenes: the depths and on/offs are registered scene fields (depths continuous, range-checked by `validate_scene`; on/off discrete). The routings are the block `matrix` (`register_scene_block`, discrete: a fade applies it at its end; sparse, `[k] = {source, dest}` for routings with either part set, an empty table when none is; its `default` is `{}`, which a scene from before 3.4 gets, and the fields' defaults are depth 0 and on, so a format 5 scene recalls 16 empty routings; its `validate` refuses a key outside 1-16, or a routing that is no table of two strings of at most 32 characters; its `through_zero`, above). Its apply loads the routings, prints a console line for every unknown part not yet named in the session (`matrix: a scene: routing 3's source ... is unknown here`), saves the live file and asks for a redraw.
- PSETs: the depths and on/offs are params; the routings are `<path_base>.matrix.data` (`{version = 1, matrix = <sparse>}`), written, read and deleted by the PSET hook `matrix`. A silent read needs nothing more: the step reads the params at the next step.
- The live file data/strata/matrix.data (the same layout): loaded at the start step `matrix_load` (a missing file loads no routings), and, once that step has read it, found it missing or set it aside, written `MATRIX.save_delay` (0.1 s) after the routings change, one write per burst carrying the newest routings (`S.matrix_save_clock`), and at once at the cleanup step `matrix_save`, which cancels that clock first. A file that could be neither read nor set aside is never written over (above).
- 16 scenes of 16 full macros, 16 routings and every step's attributes (the sequencer's own `steps` block, every attribute set through `S.lib.sequencer.set_step_attr`, eight notes and a gate, saved through `S.lib.scenes.save`) keep scenes.data inside `lib/data_files.lua`'s `max_tables` (8192): 7394 tables, about 1.0 MB of its 4 MB. The test writes and reads one.
