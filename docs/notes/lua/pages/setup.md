## Must not break

- `grid.add`/`grid.remove`/`arc.add`/`arc.remove`/`midi.add`/`midi.remove` call `request_redraw()`, so SETUP's status lines stay current (drawn on the next frame).
- The MIDI device name is cut with `fit_text` to end by x 124 (the scroll marker owns x 127), so a long norns device name never leaves the screen.
- E3 edits a control or option field through `enc_param_delta` (ALT+E3 fine steps apply). `mutation_enabled` is a binary param with no range, so E3 sets it directly (right = on, left = off); never send it through `enc_param_delta`.
- K3 runs only a save/load field, by calling its record's `run` (a function that calls `save_scenes_to_disk` / `S.lib.scenes.request_load` as it runs), never a global looked up by name; on every other field it does nothing. Each says what it did on the hint row, through `M.flash` (a `hints` flash scoped to SETUP, #463), and `load scenes` goes through `request_load`, never `load_scenes_from_disk` itself, so it asks for a second K3 while a scene of this session is not on disk (#328). The cursor (`S.setup_cursor`) only ever rests on the fields; the status and note rows are `selectable = false`. The fields are looked up through the rows (`setup_rows()[S.setup_cursor]`), since the buffer length field comes and goes.
- The performance fields edit the setting through `S.lib.performance.set_setting` (saved at once to `performance.data`), never a param: no PSET or scene holds them. A change applies at the next start. When `set_setting` returns false (the write failed) the field keeps its old value and SETUP's hint row flashes `setting not saved` (`S.lib.ui_flash`, #236).
- The grid rotation fields (#323), one per grid port (`S.MAX_GRID_PORTS`, connected or not), sit after `load scenes` and before `performance`: their count never changes, so no row comes or goes above a field. E3 steps a field's port through `S.lib.grid_core.set_rotation` (0-`MAX_ROTATION`, clamped), never a param: no PSET or scene holds it; the core writes `grids.data` and turns the grid at once. When `set_rotation` returns false (the write failed) the field keeps its old value and the hint row flashes `setting not saved`, as the performance fields do.
- The performance fields' notes go on dim rows below them, indented 8 px: by norns' font advances `performance` and `high (next start)` need 127 px with the space between them, more than the 124 px row.
- The grid-size line exists only while a grid is connected.
- The data files' problem rows end the list, after `buffers:` (#301's design), never above a field (the cursor is a row index: a row appearing above it would move it to another field). Every row is reachable (#319): E2 on the last field scrolls the view over the rows below it (`S.lib.ui_field_list.move_scroll`, the page's `setup_view.tail`), and back before the cursor moves up. A test draws every row of `setup_rows()` at some E2 position for notes, grids and problems stacked up.
- While `setup_view.tail` is above 1 the cursor's own row has scrolled out of view, and the hint row still names that field's keys. That is acceptable: the tail exists only after E2 went on past the last field, E2 back shrinks it before the cursor moves (so the field returns to view with the first turns back), and the keys keep acting on the field.
- Rows are 7 px apart, six visible (y 18-53), so a descender (the `p` of `performance`) clears the next row's top pixel (#422); `assert_screen_layout` fails a string with a descender less than 7 px above another it overlaps.
- The hints name only keys that act (#419, #420): an action row offers `E2:field K3:save` (no E3), a value row `E2:field E3:value`; with ALT held no K3 (`E2:field`, plus `E3:fine` on the three mutation values).
- SETUP has no arc fields: its rings stay dark and ignore turns.

## Owns

- `lib/pages/setup.lua` (`S.lib.pages_setup`): the SETUP record, `redraw_setup`, `setup_key`, `setup_hints`, `setup_enc` (global), `S.setup_cursor`, `layout_states`; on the module, `SETUP_FIELDS`, `SETUP_PAGE` (the page's layout constants: row spacing, note indent, the rotation fields (`rotation_fields`, made at the first look) and their `rotation_degrees`, ..., exported for the tests) and `setup_rows()` (the rows as drawn now, for the tests).
- Its unit tests: `test/unit/pages_setup_test.lua`.

## The page

A `S.lib.ui_field_list` page of 13 or 14 fields, their note rows, up to four data file rows and 4 or 5 status rows, 6 rows visible at y 18-53 (7 px apart), with the scroll marker at x 127:
- Fields (each row starts with its field's `label`): `midi 1: <device>` (label `midi`, then the port, `midi_device`, and the device from `midi_device_name()`), `channels` (`midi_channel_mode`), `mutations` (on/off), `mutation rate` (`%.1f s`), `mutation prob`, `mutation amt` (`%.2f`), `save scenes`, `load scenes`, `grid 1 rotation` to `grid 4 rotation` (kind `"rotation"`: `S.lib.grid_core.rotation(port)` shown in degrees, 0, 90, 180 or 270), `performance` (auto, standard, high) and `buffer length` (16, 60, 120, 300 s; shown when the setting or the running tier is high).
- Note rows (level 4, at x 8), below both performance fields (so the view, which keeps one row above the cursor, shows `performance` above `buffer length` when the cursor is on the length): `(next start)` when a shown field differs from the setting this start used (`S.performance_start_setting`) and `may xrun` when the setting is high and `norns.platform` is 2 (CM3) or 3 (Pi 3), joined as `(next start), may xrun`; then `300 s -> 120 s (memory)` (`(meminfo)` when the engine could not read meminfo and took the shortest length, `S.lib.performance.step_down_cause()`) when the high tier runs a shorter length than the unchanged setting asks for. A further dim note row sits directly under the `running:` row when `S.lib.performance.running_note()` says why the running tier is not what the engine decided: `active file not written` or `old active file kept`.
- Data file rows (#463), one group per file with a problem (`S.scene_file`, `docs/notes/lua/scenes.md`; `S.buffer_file`, `docs/notes/lua/buffers.md`), scenes first, after the status rows (the last row of the list is `buffers:`, then these): a file that could not be read and was kept, `scenes unreadable, kept` (level 10) and the dim note `as scenes.data.bak.2` (the backup's file name); one still in place (every backup name taken), `scenes file unreadable` and the note `not saved over`; a write that failed, `scenes file not saved`. The same for `buffers`. The texts are `SETUP_PAGE.file_texts`.
- Status rows (level 10, sizes line level 4): `running: high, 60 s` or `running: standard` (`S.performance`), `grid: n connected`, the sizes (`16x16 16x8`, port order), `arc: connected|none`, `buffers: k restored` or `buffers: k ok, m missing`.
- E2 moves over the fields and, from the last one, scrolls over the status and data file rows, E3 edits (a performance field steps its choices, clamped at the ends), K3 calls the field's `run`.
- K3 on `save scenes` runs `save_scenes_to_disk()` and flashes `scenes saved` or `scenes not saved`; on `load scenes` it runs `S.lib.scenes.request_load()` and flashes `SETUP_PAGE.load_texts`' text for its answer: `scenes loaded`, `no scenes file`, `scenes unreadable`, or `K3 again: drop unsaved` for `SCENE_LOAD.confirm_seconds` (2 s) when a scene of this session is not on disk (a second K3 inside it loads). The other flashes last `HEADER.flash_seconds`.
- Hints: `E2:field E3:value` on a value field, `E2:field K3:save` or `E2:field K3:load` on an action field; with ALT held `E2:field` (`E2:field E3:fine` on the mutation rate, probability and amount).
- The saved-scene count is no longer on this page (the SCENES page shows its slots).
- `layout_states`: scrolled to each end, two grids and an arc, a 16x8 turned upright with the cursor on its rotation field, both data files unreadable and kept, a scenes write failed with an unreadable buffers file in place, the load prompt, a kept scenes file and a failed buffers write under the high setting's two notes, buffers missing, a long MIDI device name, and the performance fields: standard, the high setting on a CM3 while standard runs (both notes and the buffer length's `(next start)`), the memory step-down, and the active file not written.
