## Must not break

- `grid.add`/`grid.remove`/`arc.add`/`arc.remove`, MIDI's hot-plug handlers (`S.lib.io_ports.on_change`) and a MIDI port's claim or release (`S.lib.io_ports.claim`, `release`) call `request_redraw()`, so SETUP's status lines and `midi` row stay current (drawn on the next frame).
- The MIDI device name is cut with `fit_text` to end by x 124 (the scroll marker owns x 127), so a long norns device name never leaves the screen.
- E3 edits a control or option field through `enc_param_delta` (ALT+E3 fine steps apply). `mutation_enabled` and the `transport` row's `seq_follow_transport` (3.4; a field with a `binary` table of its two value names, `off` and `follow`) are binary params with no range, so E3 sets them directly (right = on, left = off) through `set_binary_param`, so a controller mapped to one follows (norns' `Binary:set` sends no MIDI-map CC, #538); never send them through `enc_param_delta`.
- K3 runs only an action field (save scenes, load scenes, 3.5's mpe & zones), by calling its record's `run` (a function that calls `save_scenes_to_disk` / `S.lib.scenes.request_load` / `S.lib.ui_zones.open` as it runs), never a global looked up by name; on every other field it does nothing. Each says what it did on the hint row, through `M.flash` (a `hints` flash scoped to SETUP, #463), and `load scenes` goes through `request_load`, never `load_scenes_from_disk` itself, so it asks for a second K3 while a scene of this session is not on disk (#328). The cursor (`S.setup_cursor`) only ever rests on the fields; the status and note rows are `selectable = false`. The fields are looked up through the rows (`setup_rows()[S.setup_cursor]`), since the buffer length field comes and goes.
- The performance fields edit the setting through `S.lib.performance.set_setting` (saved at once to `performance.data`), never a param: no PSET or scene holds them. A change applies at the next start. When `set_setting` returns false (the write failed) the field keeps its old value and SETUP's hint row flashes `setting not saved` (`S.lib.ui_flash`, #236).
- 3.5's three fields, `note off` (`midi_note_off`, shown by the param's own option names), `mpe & zones` and `note pool`, sit directly after `channels` in every channel mode, so no field moves when the mode changes (plan ruling 10); the tests' pinned field indices count them.
- The note pool is a device setting, never a param: E3 steps it through `S.lib.notes.set_pool` (one more or fewer, clamped to 0..`NOTE_POOL.max`; `notes.data` is written first and the engine told). When `set_pool` returns false (the write failed) the field keeps its old value and the hint row flashes `setting not saved`, as the performance fields do. On the standard tier a dim `may xrun` note row sits directly under it while the pool is above `NOTE_POOL.standard`: the pool changes only by E3 with the cursor on its own row, so the note comes and goes below the cursor and never moves the field the cursor is on.
- K3 on `scale & tuning` (3.8, ruling 44: an action row appended after `transport`, so no earlier field moves; 4d's `factory sets` follows it) opens the scale and tuning editor (`S.lib.ui_scale_editor.open()`, `docs/notes/lua/ui/scale-editor.md`); its layout states (`scale_editor_state`) sit beside the zones editor's. K3 on `factory sets` (3.8, 4d, after `scale & tuning`) opens the factory sets' list (`S.lib.factory.open_list()`, a modal owner, `docs/notes/lua/factory.md`); its five layout states (the row selected, then the list's four) write an index to the script's folder first where they need one (`factory_index`).
- K3 on `mpe & zones` opens the zones editor (`S.lib.ui_zones.open()`, a modal owner over the page, `docs/notes/lua/ui-core.md`, The zones editor); SETUP never draws it or handles its keys, and the cursor is on `mpe & zones` again when it closes.
- The grid rotation fields (#323), one per grid port (`S.MAX_GRID_PORTS`, connected or not), sit after `transport` and before `performance`: their count never changes, so no row comes or goes above a field. E3 steps a field's port through `S.lib.grid_core.set_rotation` (0-`MAX_ROTATION`, clamped), never a param: no PSET or scene holds it; the core writes `grids.data` and turns the grid at once. When `set_rotation` returns false (the write failed) the field keeps its old value and the hint row flashes `setting not saved`, as the performance fields do.
- The performance fields' notes go on dim rows below them, indented 8 px: by norns' font advances `performance` and `high (next start)` need 127 px with the space between them, more than the 124 px row.
- The grid-size line exists only while a grid is connected. A size with no layout says `no layout` beside it (#931), read from `S.lib.grid_core.layout_of(port)` at each draw, never kept by the page; the sizes wrap onto further rows so none leaves the screen.
- Every data file's problem has a row (#895): the scenes' and buffers' from `S.scene_file` and `S.buffer_file`, every other file's from `S.lib.data_files.problems()`, read at each draw (the page keeps no copy). The list never holds those two files (`S.lib.data_files` keeps no record of them), so the page filters nothing and neither has two rows. A file's name is cut to fit (`fit_text`).
- The data files' problem rows end the list, after `buffers:` (#301's design), never above a field (the cursor is a row index: a row appearing above it would move it to another field). Every row is reachable (#319): E2 on the last field scrolls the view over the rows below it (`S.lib.ui_field_list.move_scroll`, the page's `setup_view.tail`), and back before the cursor moves up. A test draws every row of `setup_rows()` at some E2 position for notes, grids and problems stacked up.
- While `setup_view.tail` is above 0 the view has scrolled past the cursor's field (which can be out of view), so E3 edits nothing: it sets `tail` to 0, scrolling the field back into view, and the hint row reads `E2:field E3:back` (`E2:field` with ALT held), never `E3:value` (a probe found one E3 there turning the hidden performance setting from auto to standard). The tail exists only after E2 went on past the last field; E2 back shrinks it before the cursor moves.
- Rows are 7 px apart, six visible (y 18-53), so a descender (the `p` of `performance`) clears the next row's top pixel (#422); `assert_screen_layout` fails a string with a descender less than 7 px above another it overlaps.
- The hints name only keys that act (#419, #420): an action row offers `E2:field K3:save` (no E3), a value row `E2:field E3:value`, a view scrolled past the field `E2:field E3:back`; with ALT held no K3 (`E2:field`, plus `E3:fine` on the three mutation values while the view is not scrolled past them).
- SETUP has no arc fields: its rings stay dark and ignore turns.

## Owns

- `lib/pages/setup.lua` (`S.lib.pages_setup`): the SETUP record, `redraw_setup`, `setup_key`, `setup_hints`, `setup_enc` (global), `S.setup_cursor`, `layout_states`; on the module, `SETUP_FIELDS`, `SETUP_PAGE` (the page's layout constants: row spacing, note indent, the rotation fields (`rotation_fields`, made at the first look) and their `rotation_degrees`, ..., exported for the tests) and `setup_rows()` (the rows as drawn now, for the tests).
- Its unit tests: `test/unit/pages_setup_test.lua` (the factory sets row and its list's K3 among them; the list's own tests are in `test/unit/factory_test.lua`).

## The page

A `S.lib.ui_field_list` page of 19 or 20 fields, their note rows, the data file rows (four at most for the scenes and buffers, up to two more for each other file with a problem) and 4 or more status rows, 6 rows visible at y 18-53 (7 px apart), with the scroll marker at x 127:
- Fields (each row starts with its field's `label`): `midi 1: <device>` (label `midi`, then the port, `midi_device`, and the device from `midi_device_name()`, or `(<owner>)` while another module claims the port, `S.lib.io_ports.owner`, 3.6), `channels` (`midi_channel_mode`), 3.5's `note off` (`midi_note_off`), `mpe & zones` (kind `"action"`, hint `edit`: K3 opens the zones editor) and `note pool` (kind `"pool"`: `S.lib.notes.pool()`, E3 `set_pool`), `mutations` (on/off), `mutation rate` (`%.1f s`), `mutation prob`, `mutation amt` (`%.2f`), `save scenes`, `load scenes`, `transport` (`seq_follow_transport`, 3.4: `follow` or `off`), 3.8's `scale & tuning` and `factory sets` (kind `"action"`, hint `open`: K3 opens the scale and tuning editor, or the factory sets' list), `grid 1 rotation` to `grid 4 rotation` (kind `"rotation"`: `S.lib.grid_core.rotation(port)` shown in degrees, 0, 90, 180 or 270), `performance` (auto, standard, high) and `buffer length` (16, 60, 120, 300 s; shown when the setting or the running tier is high).
- Note rows (level 4, at x 8): `may xrun` directly under `note pool` on the standard tier while the pool is above `NOTE_POOL.standard` (4) (`SETUP_PAGE.xrun_note`, the text the performance notes use too); below both performance fields (so the view, which keeps one row above the cursor, shows `performance` above `buffer length` when the cursor is on the length): `(next start)` when a shown field differs from the setting this start used (`S.performance_start_setting`) and `may xrun` when the setting is high and `norns.platform` is 2 (CM3) or 3 (Pi 3), joined as `(next start), may xrun`; then `300 s -> 120 s (memory)` (`(meminfo)` when the engine could not read meminfo and took the shortest length, `S.lib.performance.step_down_cause()`) when the high tier runs a shorter length than the unchanged setting asks for. A further dim note row sits directly under the `running:` row when `S.lib.performance.running_note()` says why the running tier is not what the engine decided: `active file not written` or `old active file kept`.
- Data file rows (#463), one group per file with a problem (`S.scene_file`, `docs/notes/lua/scenes.md`; `S.buffer_file`, `docs/notes/lua/buffers.md`), scenes first, after the status rows (the last row of the list is `buffers:`, then these): a file that could not be read and was kept, `scenes unreadable, kept` (level 10) and the dim note `as scenes.data.bak.2` (the backup's file name); one still in place (every backup name taken), `scenes file unreadable` and the note `not saved over`; a scenes file below the format floor (`problem` `"older"`, an older Strata's), `scenes older, kept` and its note, or `scenes file older` and `not saved over`; a write that failed, `scenes file not saved`. The same for `buffers`, which has no older. The texts are `SETUP_PAGE.file_texts`. Then (3.9, #895) a group for every other file `S.lib.data_files.problems()` lists, in its order (it never lists the scenes' or buffers' file): the file's name without `.data` (cut with `fit_text` to leave room for the rest, any space at the cut dropped) then ` unreadable, kept` (it did not parse) or ` damaged, kept` (it parsed and its reader set it aside: refused whole, or `voices.data`'s damaged presets kept while its good ones loaded; `file_texts.damaged_kept`) and the note `as <backup's name>`, ` file unreadable` or ` file damaged` and the note `left in place` (`file_texts.left_note`: whether a later change writes over it is the file's own rule, `docs/notes/lua/data-files.md`, Each file's states), or ` file not saved`. The page reads the list at each draw and keeps no copy.
- Status rows (level 10, sizes line level 4): `running: high, 60 s` or `running: standard` (`S.performance`), `grid: n connected`, the sizes (`16x16 16x8`, port order; a size with no layout, `S.lib.grid_core.layout_of(port)` nil, is followed by `no layout`, `SETUP_PAGE.no_layout`, 3.9, #931; as many sizes on a row as end by x 124, the rest on further level 4 rows), `arc: connected|none`, `buffers: k restored` or `buffers: k ok, m missing`.
- E2 moves over the fields and, from the last one, scrolls over the status and data file rows, E3 edits (a performance field steps its choices, clamped at the ends; while the view is scrolled past the field it only scrolls back), K3 calls the field's `run`.
- K3 on `save scenes` runs `save_scenes_to_disk()` and flashes `scenes saved` or `scenes not saved`; on `load scenes` it runs `S.lib.scenes.request_load()` and flashes `SETUP_PAGE.load_texts`' text for its answer: `scenes loaded`, `no scenes file`, `scenes unreadable`, `scenes older`, or `K3 again: drop unsaved` for `SCENE_LOAD.confirm_seconds` (2 s) when a scene of this session is not on disk (a second K3 inside it loads). The other flashes last `HEADER.flash_seconds`.
- Hints: `E2:field E3:value` on a value field (the note pool included), `E2:field K3:save`, `E2:field K3:load`, `E2:field K3:edit` or `E2:field K3:open` on an action field, `E2:field E3:back` while the view is scrolled past the field; with ALT held `E2:field` (`E2:field E3:fine` on the mutation rate, probability and amount).
- The saved-scene count is no longer on this page (the SCENES page shows its slots).
- `layout_states`: scrolled to each end, two grids and an arc, a 16x8 turned upright with the cursor on its rotation field, both data files unreadable and kept, a scenes file older and kept, a scenes write failed with an unreadable buffers file in place, the load prompt, a kept scenes file and a failed buffers write under the high setting's two notes, 3.9's other data files' problems (a damaged `gestures.data` kept, a PSET side file with a long name in place, a failed `matrix.data` write, a `voices.data` that parsed and was set aside (`damaged`), made through the reader, the set-aside and the writer) and four grids, two with no layout (`10x10 no layout 16x16`, `12x6 no layout 8x8`), buffers missing, a long MIDI device name, and the performance fields: standard, the high setting on a CM3 while standard runs (both notes and the buffer length's `(next start)`), the memory step-down, and the active file not written; 3.5's note pool at its maximum on standard (`may xrun` under it) and the zones editor: opened, the cursor on v7's high with every row at its widest (every zone `upper`, every range `C#-2`, the bend range `96 st`), and a learn waiting for v7's low and for its high (the MIDI module's note tap a do-nothing stand-in); 3.8's scale and tuning editor (`docs/notes/lua/ui/scale-editor.md`) and the factory sets' row selected and its list: `none` (no index), a twelve-character name (`MMMMMMMMMMMM`, the widest) at `v12`, the armed prompt (`K3 again: drop unsaved`) and a set loading with a second K3 refused (`loading`).
