## Must not break

- While `S.BUFFER_PAGE.file_selector_open` is set, `redraw()` draws the file selector (`fileselect.redraw()`), never the page, so no frame-clock redraw draws over the file list.
- `buffer_key_release` calls `forget_held_keys()` just before `fileselect.enter`: the selector takes the keys, so a key held then would never be released to the script.
- K2, ALT+K2 and ALT+K3 act on release, by how long they were held: the dispatcher's press time (`S.lib.ui_keys.held_seconds(n)`, #866; the page keeps no mark of its own), compared with `S.BUFFER_PAGE.hold_seconds` (`ALT_HOLD_SECONDS`, 0.5 s, the other pages' hold). No clock. ALT+K2 and ALT+K3 are the one exception to acting through `alt_action` at the press (design 3.3 §8.1, Question 20): the record has no `alt_key` (#959), so the press does nothing (`key()` still marks it an ALT press), and `alt_key_release` acts.
- An ALT press releases through `alt_key_release`, never `key_release`, so ALT+K2 never opens the file selector or clears the slot, even when K1 comes up first (K1 down, K2 down, K1 up, K2 up). BUFFER never reads `S.key_press_page[2]` to change what K3 does: the K2+K3 save gesture is gone (ALT+K3 saves), and a K2 pressed with ALT is still in `S.key_press_page`.
- K3 on the `slices` field (the twelfth and last, so the field indices the layout states set, 3 and 10, hold: plan ruling 20) opens the slice editor (`S.lib.ui_slice_editor.open(cursor slot)`, `docs/notes/lua/ui/slice-editor.md`) and records nothing; a slot with no audio flashes `buf <n> empty`, and its hint names no K3 there (`K2:ld/clr`: the final review's Lua B, Minor 3). On every other field K3 records. The arc button records on every field.
- BUFFER's keys follow the other pages (3.7, plan ruling 31): a quick ALT+K2 is the random draw (`S.lib.files.random_into`), held it fills the empty slots; K2 held clears the slot (`clear_buffer`, no flash); a quick K2 opens the file selector; ALT+K3 as before.
- The slices field and the waveform's slice marks read only `S.lib.ui_slice_editor.slot_text` and `starts`, never the slices or the file's settings themselves.
- Every key and the arc button act on the slot cursor (`S.buffer_page.slot`), never on the selected voice's buffer: K3 records into it whether or not a voice reads it.
- BUFFER's progress and results go through `buffer_page_flash` (the shared "hints" flash, owned by BUFFER), never a clock of the page's own; they show only while BUFFER is up. `draw_hints` cuts a long one to the screen. A refusal or a failure of a load, a save or a recording goes through `header_flash` instead, which shows on every page (#878): `buf <n> load failed` (`buffer_load_failed`), `take <n> unsaved` (the `takeWriteFailed` poll), `buf <n> save failed` (`buffer_save_result`, which also ends the hint row's `saving` flash it answers), `buf <n> busy` and `buf <n> empty` (a save refused, `save_cursor_slot`), `buf <n> loading` (an overdub refused, `record_buffer`) and `buf <n> replaced` (an overdub or loop recording the slot's file's rate turns into a replace take, `record_buffer`: the overdub is refused and the slot empties, #1027). Each fits the header's flash room (74 px) whole (`buf 8 replaced` is 62 px; `buf 8 replaced (rate)`, 90 px, would not). The slice editor's `buf <n> empty` and the check's `still checking K2:ld/clr` (it names BUFFER's keys) stay the page's.
- A save (either kind) while the slot is `recording` or `finishing` saves nothing (`buf <n> busy`); the check is in `save_buffer` and `save_buffer_loop`, which `save_cursor_slot` flashes from.
- A save never shows `saved buf <n>` before the engine's `bufferSaveResult` report says the file is written (#127): ALT+K3 shows `saving buf <n>` (`saving buf <n> loop`), and `buffer_save_result` the result. The slot's row shows `saving` while `S.lib.buffers.saving(slot)` (a tracked save awaits its report; false without the poll), past the flash's 1.5 s, until that report (#905): `send_save` and `buffer_save_result` ask for the redraws. It rests on the engine's one report per save, as `saved` does (`docs/notes/engine/files.md`, Save results), so it has no timeout: a report lost on the way would leave `saving` until four newer saves of the slot roll it out of the tracked saves (`BUFFER_SETTLE.tracked_saves`). A save's failure ends the hint row's flash only while it is that save's own `saving buf <n>[ loop]` (`S.lib.buffers.saving_flash_text`), never a flash raised since.
- `fileselect` is required (`require "fileselect"`), never read as a global.
- The input meter reads `S.lib.input_level.levels()` and never names the polls (`amp_in_l`, `amp_in_r`): `lib/input_level.lua` runs them from the start step to cleanup on every page (`docs/notes/lua/input-level.md`), and the meter registers a listener with `on_level` that acts only while BUFFER shows (`S.ui_page`). The record's `enter` calls `S.lib.input_level.refresh()`, which looks both polls up again with `poll.set` and starts them: never kept from load time alone, because norns replaces its poll objects when it re-registers the polls (#438; the module's `refresh` is where it is done). `enter` also clears the held peak. A visit shows the last polled level, at most one poll (1/30 s) old, with no held peak (before 3.4 a visit started silent, and the polls ran at 20 Hz). A norns without the polls leaves the meter dark.
- A poll value asks for a redraw only when the drawn level or held peak changes, and of the screen alone (`S.lib.ui_frame.request_screen_redraw()`: no arc ring shows the meter, so it never repaints a connected arc, #434), and none while the file selector is open (#435; the selector's callback asks for the redraw that shows the meter again). The peak's expiry is checked at draw time, so it goes out even with no new poll value.
- Both lists scroll through `S.lib.ui_field_list` (`first_visible`, `move`, `clamp`, and `draw` for the slots): the slots' marker at x 127, the fields' marker on the divider (`draw_marker(..., x = 56)`, level 4 over the divider's 1). No slot text reaches x 127, and nothing in the left column crosses the divider.
- A redraw measures no text it measured before: value, seconds and voices widths are memoized, field labels and slot names are cut once per text and width. The width and label caches hold at most `cache_limit` (256) entries each and are cleared past it (a turn through a long file's start makes a new text at every detent).
- The `start` label always fits whole: the value's resolution follows `start_bands`, each band's widest text fitting beside `start` under a width at least as wide as norns' font (the test takes the stub's width per character, or the font's where wider: `m` is 6 px).
- The page reads the waveform, heads and bookmarks only through `S.lib.waveforms.bins`, `S.lib.playheads` (`position`, `spread`, `record_head`, `cell_of`, `has_audio`, `moving`) and `S.lib.positions` (`bookmark`, `last_recalled`, `recall_bookmark`); it never reads a peaks file and sends no engine command of its own. `draw()` never asks for a redraw: `animates()` (`S.lib.playheads.moving(cursor slot)`) moves the heads at the frame rate.
- Voices' heads, their spreads and the bookmark ticks are drawn only on a slot that reports audio (`S.lib.playheads.has_audio`, the check the grid's position rows read, so the two never disagree), and `animates()` is true only while a head or the record head is drawn (`moving`): an empty slot and a replace take show and animate nothing (#433). It is false while the file selector is open, whatever moves under it (#435).
- A file name is drawn through `S.lib.ui_text.printable` (accented letters plainly, any other character norns' font lacks as `?`) and cut on the text drawn (#551): the slot rows here, the hint row in `draw_hints`. The slot keeps its real name and path for loading and saving.
- The `bm` field recalls through `S.lib.positions.recall_bookmark` only when the shown bookmark changes, so turning past 1 or 4 never restarts the scan again. It shows `-` until the selected voice recalls a bookmark, so the first detent either way lands on bookmark 1, and ALT+E3 recalls the bookmark it shows again (1 from `-`), with no jump to a neighbor first (#431). Each recall goes through `S.lib.positions.recall_bookmark_quantized` (3.4, key `bookmark<v>`, label `v<v> bm <n>`): under `quantize_actions` it waits for the beat or bar, the field keeps showing what plays, and while a recall waits the next detent (and ALT+E3) steps from the bookmark that waits (`S.lib.positions.waiting_bookmark`, the field's own or a grid strip key's that replaced it), so a quick turn of three detents lands three bookmarks on, not one. The `start` field moves the start only through `S.lib.buffers.set_start` (it clamps, does nothing while the slot records, and reloads once E3 rests).

## Controls

- E2 moves the slot cursor; ALT+E2 the field cursor (`alt_enc` returns true for E2 only). E3 edits the field (table above); ALT+E3 is fine adjustment.
- K3 press on the `slices` field: the slice editor (above). Elsewhere K3 press, and the arc button on every field (`arc_button`): `record_buffer(slot)`: records, stops early while recording (keeping what was captured), cancels while armed; does nothing while `finishing`.
- K2 release: before 0.5 s the file selector for the cursor slot (below); held 0.5 s or more, `clear_buffer(slot)` (no flash). K2's press only notes its time; K3 while K2 is held just records.
- ALT+K2 release: before 0.5 s `S.lib.files.random_into(slot)` (it flashes `buf <n>: <name>` or `no files in <folder>`, the folder as the player knows it: `docs/notes/lua/files.md`, #432); after, `S.lib.files.fill_empty()` (it flashes `filled <k> slots`, `filled 1 slot`, or `no files in <folder>`).
- ALT+K3 release: before 0.5 s saves the whole slot (`save_buffer`), after it its loop region (`save_buffer_loop`, trim), shown by:
  - `buf <n> busy` in the header (and no save) while the slot is `recording` or `finishing`;
  - else `saving buf <n>` (`saving buf <n> loop`) in the hint row (`buffer_page_flash`) when the save was sent (the slot reports audio, `seconds > 0`);
  - else `buf <n> empty` in the header.
- `buffer_save_result` (`lib/buffers.lua`) flashes `saved buf <n>` (`saved buf <n> loop`) in the hint row, or `buf <n> save failed` in the header (ending the hint row's flash), when the engine reports how the slot's newest save ended; a report of an older save flashes nothing.
- `buffer_load_failed` flashes `buf <n> load failed` and a take the engine could not write `take <n> unsaved`, both in the header; a playable recording refused while a load awaits the engine `buf <n> loading` in the header; one into a slot at another rate becomes a replace take and flashes `buf <n> replaced` in the header (`lib/record.lua`, #1027; the layout state `replaced flash`).
- Hints: while a hold key is down (see Held keys below) `buffer_hints` returns its release text instead; else `K2:ld/clr K3:rec` (`K3:edit` on the `slices` field, `K3:stop` while the cursor slot records or is armed, `K3:...` while it is `finishing`); with ALT `K2:rnd/fill K3:sv/trim`.
- `animates()`: false while the file selector is open (#435); else `held_hint() ~= nil` (a hold key is down, so the hint changes at 0.5 s with no clock of the page's own), or `S.lib.playheads.moving(cursor slot)`, true while a running voice reads the slot's audio or it records playably (#433), so `draw_frame` redraws the screen every frame then.

The flash: `buffer_page_flash(text)` = `S.lib.ui_flash.start("hints", text, 1.5, UI_PAGES.index.BUFFER)`. `redraw()` draws it on BUFFER's hint row instead of the key hints while it shows (a result reported while another page is up shows if BUFFER comes up within 1.5 s; a refusal or a failure is the header's, on every page, #878); its clock asks for a redraw when it ends; a new flash cancels the previous clock; cleanup step 140 cancels it (`docs/notes/lua/ui/header-and-flashes.md`).

## Held keys

A key counts as down for the hint (`held_hint()`) while `S.lib.ui_keys.held_seconds(n)` answers and `S.key_press_page[n]` is BUFFER's index; `S.key_press_alt[n]` picks the plain or ALT texts. Plain K3 records at the press and has no hold. A "hints" flash covers the hold hint (`redraw()` draws the flash first).

| State | `S.key_press_at[n]` | `S.key_press_page[n]` | `S.key_press_alt[n]` | Hint row |
|-------|---------------------|-----------------------|----------------------|----------|
| up | nil | nil | nil | the page's own hints |
| down short (under 0.5 s) | time | BUFFER | nil (K2) or true (ALT+K2, ALT+K3) | `K2 up: load`, `K2 up: random` or `K3 up: save` |
| down long (0.5 s or more) | time | BUFFER | as above | `K2 up: clear`, `K2 up: fill` or `K3 up: save loop` |
| taken (menu, selector, page change or a modal owner pushed over the page) | nil | nil | nil | the page's own hints |

Transitions: `key()` notes the press (page and time) and forgets it after the release handler ran (`held_long` reads it there); `forget_held_keys`, a page change and `S.lib.ui_modal.push` forget it (#234, #866), so its release then does nothing (a K2 held while the grid's step editor covered the page neither clears the slot nor opens the selector). The page keeps no press mark of its own, so none can go stale.

## Input meter

- `S.lib.pages_buffer.INPUT_METER = {segments = 8, floor_db = -48, db_per_segment = 6, peak_hold_seconds = 1}`.
- `input_meter_segments(amp)` = `clamp(ceil((20 * log10(amp) - floor_db) / db_per_segment), 0, 8)`; 0 for `amp <= 0`, NaN or a non-number. So 0.5 (-6 dB) lights 7, 1 (0 dB) and above 8, 0.001 (-60 dB) none.
- `enter` calls `S.lib.input_level.refresh()`, which looks both polls up again (`poll.set`), sets their time and starts them, and clears the held peak (`peak`, `peak_at`, `shown`). The record has no `leave`: the polls are `lib/input_level.lua`'s (since 3.4), run from its start step to its cleanup step on every page (#971).
- Each value sets that channel's amplitude; the level is the louder channel's segments. A value that changes the drawn level or peak asks for a screen redraw (`S.lib.ui_frame.request_screen_redraw()`, #434), unless the file selector is open (#435). When the level reaches or passes the held peak (or the hold has run out), the peak becomes the level and `peak_at` the time. The draw shows the level, plus the peak segment while `util.time() - peak_at < peak_hold_seconds` and the peak is above the level.

## The file selector (K2 release)

- K2 released before `hold_seconds` calls `fileselect.enter(_path.audio, cb)`. `cb` calls `S.lib.files.note_chosen(path)` (its folder becomes the next random folder) and `load_buffer(slot, path)` unless the path is `"cancel"`, then clears `S.BUFFER_PAGE.file_selector_open` and asks for a redraw (the next frame draws the page).
- `fileselect` is `lib/pages/buffer.lua`'s `local fileselect = require "fileselect"`. `strata.lua` requires it too, for `redraw()`, as norns' own `core/menu.lua` does: the library is a module, not a global.
- `buffer_key_release` sets the flag just before `fileselect.enter`. While it is set, `redraw()` calls `fileselect.redraw()` (lib/fileselect.lua's `fs.redraw`, which draws the file list) instead of the page.
- Why the flag: from play mode `fs.enter` calls `norns.menu.init()`, whose `_menu.set_mode(false)` puts Strata's `redraw` back in the global. Without the flag, the selector's own `redraw()` call and every frame-clock redraw (asked for by `key()`, buffer polls, sequencer steps, MIDI, grid/arc events) would draw over the file list.
- Drawing the selector rather than nothing also covers the norns menu opened and closed over it (K1 twice): `set_mode(false)` clears the screen and calls `redraw()`, which then shows the list again instead of leaving the screen blank.
- norns calls the callback on a choice and on a cancel alike (`fs.exit`, after its own `redraw()`), so the flag always clears.
- The callback calls `close_buffer_file_selector()`, which clears the flag, `S.BUFFER_PAGE.file_selector_callback` and the saved handlers, and asks for a redraw.
- If `fileselect.enter` raises (it runs in an `xpcall` with `with_traceback`), no callback will come:
  - Strata's `key`/`enc` go back in the globals, and `close_buffer_file_selector()` runs;
  - unless the menu is open, `pcall(norns.menu.init)` routes play mode again. Every realistic failure point in `fs.enter` comes after its `norns.menu.init()` has routed `fs.key`/`fs.enc`, and keys reach the script through `_menu.key`/`norns.encoders.callback`, which only `set_mode(false)` copies from the globals, as `fs.exit` relies on;
  - then the error is raised again.

A second selector (issue #49):
- norns has a single selector (`lua/lib/fileselect.lua`'s module state).
- From play mode `fs.enter` stores Strata's `key`/`enc`/`redraw` in `fs.key_restore`..., puts `fs.key`/`fs.enc` in the globals, and `norns.menu.init()` hands them to play mode (`_menu.key = key`, `norns.encoders.callback = enc`).
- If the menu is opened over it (K1) and a PARAMS file param (or TAPE) calls `fs.enter` from menu mode, that call overwrites `fs.callback` and the restore fields with the menu's.
- Its `fs.exit` restores the menu's handlers only. Strata's callback never comes, and the globals keep `fs.key`/`fs.enc`, which `set_mode(false)` would give play mode as the menu closes (a later exit from that stale selector would even install the PARAMS menu's handlers as the script's).
- So `buffer_key_release` records the callback (`S.BUFFER_PAGE.file_selector_callback`) and Strata's `key`/`enc` (`S.BUFFER_PAGE.script_key`/`script_enc`).
- `menu_watch.wrapper` calls `release_superseded_file_selector()` before norns' `set_mode(false)`, in a `pcall` that prints an error, so it can never stop the menu closing.
- On a real menu-to-play change (`norns.menu.status()` still true as `set_mode(false)` starts), while the flag is set and `fileselect.callback` is set but no longer Strata's, it puts Strata's `key` and `enc` back in the globals (norns' `set_mode(false)` then gives them to play mode) and calls `close_buffer_file_selector()`.
- The selector's own `set_mode(false)` calls (from `norns.menu.init` in `fs.enter`/`fs.exit`) run in play mode and change nothing.
- A norns whose fileselect keeps no `callback` field releases nothing (the flag may then stay set after a menu selector, as before #49), so an internals change can never break BUFFER K2 itself.
