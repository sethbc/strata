## Must not break

- **The format floor** (3.7, design decision 21): a file of format `SCENE_FORMAT_FLOOR` (10, since 3.8: the groundwork's 9 is set aside, never released) to `SCENE_DATA_VERSION` loads, every field it lacks filled from the defaults (`fill_scene`); a file below the floor (the bare array before 2.1 included) or above the build's version is set aside to its first free backup name with one console line, and never overwritten. One below the floor reads as older (`S.scene_file.problem` `"older"`), never as unreadable. No code is keyed on a file's version (a structure test finds, under `lib/`, a file's version compared, on either side and bare or wrapped, with a number literal or a name that is no floor (`_FLOOR`) and no build version (`_DATA_VERSION`), and the names `from_version` and `before_version`): a stored value whose meaning changes raises the floor with the version, never adds a conversion.
- **Format 10 is unreleased until 3.8.0, and a removed scene key is not converted**: `validate_scene` refuses a key no record has, so a package that removes or renames a voice scene key under format 10 (3.8's 1c removed `grain_env`) sets a scenes file of an earlier pre-release build aside whole, by design; `test/fixtures/format-10-files.lua` is re-recorded then. A key added under format 10 is filled at a load (`fill_scene`).
- `load_scenes_from_disk` (and the PSET file's read) reads the file through `S.lib.data_files.read`, which parses it and never runs it as Lua (#464, `docs/notes/lua/data-files.md`); never `tab.load`. On any failure it keeps the current scenes and moves the file aside to its first free backup name (`.bak`, `.bak.2` ... `.bak.9`, never over an earlier backup, #466), or blocks the autosave (`S.scene_autosave_blocked`), so a bad file is never overwritten.
- The live scenes.data is written only by `save_scenes_to_disk`, through `S.lib.data_files.write` (a checked `.part` renamed into place, nothing written when the file holds the same bytes, #301); never `tab.save`. A failed write leaves the file as it was and never prints `saved`; it sets `S.scene_file.write_problem = "not saved"` and `unsaved`.
- **The load's problem and the write's are two facts** (3.9, #868): `S.scene_file.load_problem` is what the last load found and `write_problem` what the last write found; neither clears the other but where the file says so (a load that takes the file clears both; a write that works clears its own, and the load's only while that file is still in place). `S.scene_file.problem`, what SETUP and the buffers' start flash read, is never stored: a metatable on `S.scene_file` (`SCENE_FILE_PROBLEM`) gives the write's while it is set, else the load's, so a write that works after a failed one brings back the row of a file set aside. A set of `problem` (SETUP's layout states, a test) sets the fact it names: `"not saved"` the write's, anything else the load's, with no write's. A PSET's `<pset>.scenes.data` goes only through `S.lib.side_files` (its spec: `docs/notes/lua/scenes/pset.md`), never `save_scenes_to_disk` (the groundwork's ruling 34).
- A load the player asks for goes through `S.lib.scenes.request_load` (SETUP's K3, the PARAMS trigger), which asks for a second request within `SCENE_LOAD.confirm_seconds` (2 s) while `S.scene_file.unsaved`, and loads at once otherwise (#328). init's load calls `load_scenes_from_disk` directly.
- No copy of an older format is kept at a save (3.7: the `.v<n>` copies of #467 are gone): at every instant scenes.data is the old file or the new one, whole, through the `.part` write.
- A load keeps `S.current_scene` only when the file's scene in that slot encodes to the same text as the one it replaces (`S.lib.data_files.encode`); otherwise it is 0 (#518).
- A loaded slot with no name gets `""` (`fill_scene`); every other name is the player's, whatever it reads.

## Disk persistence

- **Location**: `~/dust/data/strata/scenes.data`.
- **Format**: a Lua table in the layout norns' `tab.save` writes (written by `S.lib.data_files.encode`, each table's keys in a fixed order): `{version = SCENE_DATA_VERSION, scenes = {...}}` (version 9, since the work before 3.8: the lock's field `frozen` became `locked`, so the floor rose with it; each package of that work changes the format under 9, never raising it again).
  - **Versions**: a file of format `SCENE_FORMAT_FLOOR` (10) to `SCENE_DATA_VERSION` loads. A file below the floor (formats 1 to 9, 3.5's 7, 3.7's 8 and the groundwork's 9 among them, and the bare scenes array written before 2.1, which has no version) is set aside to its first free backup name, never converted, with one console line that names its format and the floor (`error: scenes file has format <n>, older than format 10, the oldest this version loads: it is set aside, not converted`), and reads as `"older"`; a version above the build's, or one that is no whole number, is set aside too, as `"unreadable"` (`error: scenes file has version <n>, expected format 10`, or `expected formats <floor> to <version>` once the two differ). 3.7 deleted every conversion by version (3.3's Pulse `res` mirror and whole-number rounding, 3.4's LFO import and slot names, 3.5's two fills).
  - When to bump `SCENE_DATA_VERSION`: once per release that adds scene fields, never per field. A field's default fills it in every file from the floor up, so a new field needs only its default. A stored value whose meaning changes raises `SCENE_FORMAT_FLOOR` to the new version with it (an older file is then set aside), never a conversion.
- **The fill**: `load_scenes_from_disk()` runs `fill_scene(scene)` on every loaded slot before `validate_scene_data()`. It fills only what is missing, so it can run twice.
  - A slot with no `name` gets `""`; the rest is filled on a populated scene only.
  - Each global from its `SCENE_GLOBAL_PARAMS` entry's `default` (the param default).
  - Top-level blocks from `S.SCENE_BLOCK_DEFAULTS` (`{key, default}`), then each registered block that is missing from its `default()`.
  - Per voice (the local `fill_voice`): a missing `source` is the synth; when `values` is a table, each scene key it lacks gets its default from `S.lib.params_setup.voice_scene_keys(i)` (a built-in key's param default; a registered key's `S.voice_scene_defaults(record, voice)`: a record's `scene_defaults` table, or the table its `scene_defaults` function gives for the voice, so the notes record's attack and release are each voice's own). A voice with no `values` is not given one.
  - Then each registered record's optional `normalize_scene(values)` on that table, in registration order: it puts back what the params would allow where a hand edit left values inconsistent (loops: a start past 0.999 or a length past `1 - start`), so a recall, which sets the values without the params' cross-clamps, ends where the params would. It leaves anything but numbers to `validate_scene`.
  - The registered global fields from their `default`, as entries of `SCENE_GLOBAL_PARAMS`.
  - Malformed scenes are left for validation to reject.
  - A later scene field adds its default to one of these tables (a voice key has its param's, or its record's `scene_defaults`). `S.SCENE_BLOCK_DEFAULTS` is empty: the LFO settings are globals in `SCENE_GLOBAL_PARAMS`, and a module's block brings its own `default` (Scene blocks, `docs/notes/lua/scenes/recall.md`).
- **What is known of the file**: `S.scene_file = {load_problem, write_problem, backup, unsaved, pset, start_outcome}`, and the derived `problem` (above); `start_outcome` (3.8) is what the start step's `load_scenes_from_disk` returned (`"loaded"`, `"missing"`, `"unreadable"`, `"older"`; nil before it ran): whether a scenes file was found at this start, which the factory's first run reads (`docs/notes/lua/factory.md`; a file set aside at step 100 would read as missing to a later `util.file_exists`). `load_problem` is nil, `"unreadable"` (the file could not be loaded) or `"older"` (a format below the floor: an older Strata's file), `write_problem` nil or `"not saved"` (the last write failed), and `problem` the write's, else the load's; `backup` is the name an unreadable or older file was kept under (nil while it is still in place); `unsaved` is true while a scene captured in this session may not be in the file (a failed or blocked write). `pset` is the path without `.pset` of the PSET that holds exactly these scenes (nil: none does; `docs/notes/lua/scenes/pset.md`). SETUP lists a problem (`docs/notes/lua/pages/setup.md`).
- **Robust loading**: `load_scenes_from_disk()` reads the file with `S.lib.data_files.read`, a parser of `tab.save`'s layout, so nothing in the file runs (#464). It returns `"loaded"`, `"missing"`, `"unreadable"` or `"older"`, and requests a redraw. Only ENOENT counts as missing (#1068). Permission denied and other open errors follow the unreadable-file backup and autosave rules below. A missing file prints `no saved scenes file found`; one that is not that layout (code, a truncated file) prints `error loading scenes file: <why>`, why naming the byte.
  - On any failure (unreadable, a version below the floor or unknown, invalid data after the fill) it prints a message and keeps the current scenes (empty at startup).
  - It preserves the file: it is renamed to its first free backup name, `scenes.data.bak`, then `.bak.2` ... `.bak.9` (`S.lib.data_files.set_aside`; an earlier backup is never replaced, #466), and `S.scene_file` records `load_problem = "unreadable"` (`"older"` for a format below the floor) and the backup; a write's problem stays what it was. If every name is taken or the rename fails, `S.scene_autosave_blocked` stops the scene saves' writes and `cleanup()`'s, and `backup` stays nil.
  - Its start step flashes `scenes unreadable (SETUP)`, or `scenes older (SETUP)`, on the hint row, on whatever page comes up, for `SCENE_LOAD.start_flash_seconds` (4 s) (#463). The line `-- Load saved scenes from disk` stays as it is: a test patches the script at it.
  - On `"loaded"` it drops a pending quantized scene recall, clears `load_problem`, `write_problem`, `backup` and `unsaved`, keeps `S.current_scene` only if the slot's scene is unchanged (#518), raises every slot's revision and reads `pset` from the file's field (a value that is no string reads as nil). The local `scenes_problem(scene_table)` (the fill, then `validate_scene_data`: nil or `"corrupted or incompatible"`) and `take_scenes(scene_table, from)` (the transition canceled, the #518 rule, `S.scenes` set, the revisions raised, the cache set, `scenes loaded from <from>`, `grid_redraw()`) are this read's two halves; the PSET load uses both.
  - Missing slots in a valid file are filled with empty scenes, before the #518 comparison.
- **Saving** (`save_scenes_to_disk()`, true and `"written"` or `"unchanged"`, or false and why): it makes the folder, then writes `{version = SCENE_DATA_VERSION, scenes = S.scenes, pset = S.scene_file.pset}` through `S.lib.data_files.write` (`pset` is no scene: `validate_scene_data` reads only `scenes`).
  - Success: `unsaved` false, `write_problem` cleared (and a `load_problem` with no backup: the write replaced the file still in place; one set aside stays, #868, and the write is format 10, `SCENE_DATA_VERSION`), `S.scene_autosave_blocked` false; `scenes saved to ...` printed only for `"written"`.
  - Failure: `write_problem = "not saved"` (the load's problem kept), `unsaved` true, `error: scenes not saved to <file> (<why>); the file is as it was`, and the file as it was.
- **Auto-save** (#327): every user's scene save writes the file, through `S.lib.scenes.autosave()`: nil (and `unsaved` set) when the scenes were never loaded in this session or `S.scene_autosave_blocked`, else `save_scenes_to_disk()`. `cleanup()` saves too (step 30), with the same two guards: only once `load_scenes_from_disk()` has run in this session (`S.scenes_loaded`, set when it returns), so a start that failed before init's loads (the engine did not load, an error earlier in `init`) never overwrites the saved file with the empty in-memory state (#72), and not while blocked. With nothing new the exit writes nothing (the bytes are the same). buffers.data has the same guards (`docs/notes/lua/buffers.md`).
- **Auto-load**: its start step (`START_ORDER.scenes_load`) loads them at init, before the buffers.
- **Manual**: the PARAMS triggers "save scenes to disk" (`save_scenes_to_disk`) and "load scenes from disk", and SETUP's `save scenes` and `load scenes` (K3). Both loads go through `S.lib.scenes.request_load()` (#328): while `S.scene_file.unsaved` the first request arms (`SCENE_LOAD.armed_until`, `confirm_seconds` = 2 s ahead) and returns `"confirm"` (SETUP flashes `K3 again: drop unsaved` for the 2 s; the PARAMS trigger prints a line), and a second inside the window loads; otherwise it loads at once, and returns what `load_scenes_from_disk` returns. With scenes written at every save, memory and the file hold the same scenes, so a stray load drops nothing.
- **What is saved**: all 16 slots, their names, populated state and data. Scenes persist across reboots, building a library of sonic palettes.
