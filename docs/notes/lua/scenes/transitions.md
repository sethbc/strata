## Must not break

- Discrete keys (a voice key with a `range` in `voice_scene_keys`: the grain mode, the mod sources and a record's `discrete` keys, 3.8's grain cloud among them; source, type, lock and active states, tempo, filter type, mutation and LFO settings) switch at the end of a transition, never crossfade. 3.8: a voice's synth keys (`synth = true`) of a scene whose type differs from the voice's type at the fade's start land at the end with the type; the shared keys fade. Continuous params fade linearly from start values snapshotted once.
- A fade toward a scene that stops a running LFO (`S.lib.lfos.transition_stops(n, scene_data)`: `strata_lfo<n>` on now, off in the scene) fades that LFO's depth to 0 and holds its rate and offset; the end sets the scene's exact values with the state (#408). The LFO entries of `S.SCENE_GLOBAL_PARAMS` are `lib/lfos.lua`'s `S.lib.lfos.SCENE_FIELDS` (the records themselves, appended after the built-in globals), carrying `lfo = n` and the depth's `stop_target = 0`; this file never lists the LFO fields itself.
- Every recall cancels a running transition first. Every exit of a transition (end, cancel, error) goes through the one local `end_scene_transition(how)`, which clears `S.scene_transition_active`, `S.scene_transition_clock` and the `SCENE_TRANSITION` fields together (#253). A fade that does not land puts the previous scene back as current, never leaving its target current; a landing keeps the target current while `recall_scene_instant` applies it, so no redraw during the landing shows the previous scene, and puts the previous scene back only if that recall fails. Inside the transition's clock its id is forgotten, never canceled. The clock runs on the clock helper (3.9, #870, `docs/notes/lua/clocks.md`): a superseding recall or a cancel stops it with `S.lib.clocks.stop` (retired while its wake may be posted, so the wake ends it with no error and no step; canceled farther off), its step waits are `handle.sleep`, its handle a local beside `S.scene_transition_clock` (its id); one whose coroutine has gone is only forgotten. Cleanup step 110 cancels it at once (`S.lib.clocks.cancel`).
- Every display of the current scene (the header's `S<n>`, SCENES' slot, the grids' recall keys) asks `S.lib.scenes.shows_current(slot)`, never compares with `S.current_scene` itself, so the scene a fade goes to blinks on all of them alike and is steady once it lands (#254). `SCENE_TRANSITION.step` is set before each step's redraws and cleared by `end_scene_transition` before a landing applies its scene.
- **A hand edit during a fade is a hand edit** (3.9, #867): `S.scene_transition_active` says a fade runs (up to 30 s), never that a scene sets a value now. A reader that stands down for a scene's own sets (the loop length's filter, the scale's re-snap, the FX faders' grid redraw) asks `S.lib.scenes.setting()`: true inside `apply_entries` and around a fade step's loop of sets and its through-zero switches (the local `fade_step_setting`, put back as it was found, after an error too), never inside `set_scene_value`, which morph's continuous writes go through too, so they keep the loop pair's filter on.

## Machines

### scene fade
- **State:** `S.scene_transition_active`, `S.scene_transition_clock`, `SCENE_TRANSITION`'s `next_step_due`, `target`, `previous`, `step` and `released`, `S.current_scene`, and the fade's closure (`targets`, `switches`, `switched`, `released`); `S.lib.scenes.fading_to()` names the scene it goes to, `S.lib.scenes.setting()` whether a scene sets its params now (the States table below). Before or after the midpoint is read from `step` (after it once `2 × step ≥ steps`, where the through-zero switches have run); landing is no flag with `setting()` true, inside the fade's clock (an instant recall's apply reads the same, and the table never asks the state inside one).
- **Invariant:** `scene transition`: `next_step_due`, `target`, `step` and `released` are set exactly while the flag is, and no clock is kept while idle.
- **Two facts:** `S.current_scene` 0 means both that no scene was recalled (the start, a load that zeroes the mark, #518) and that morph holds the sound (its apply sets 0, lib/morph.lua); morph reads the second as `current_scene == 0` with no fade (`taken_over`).
- **Test:** `test/unit/scenes_test.lua`: "scene fade: fading, before the midpoint + hand set".

The table (3.9: package 1d's hand edit and cancel rows, completed by 2c, #948) runs from scene 1 to scene 2 over 4 s (20 steps of 0.2 s): before the midpoint is step 9, after it step 12. Scene 2 holds a matrix routing scenes 1 and 3 lack, so its depth ramps through 0 and the routing switches at the midpoint. The timed and instant recalls are of scene 3; the hand set is voice 2's loop start 0.5, then its length 1; the capture is into scene 2, the fade's target; `release_voice` lets go of voice 2; the morph move sets `morph` to 0.5 and runs its first apply. Every row checks `S.current_scene`, the flag, the clock (live exactly while a fade runs) and that no scene sets after the event. Impossible: a step or the end while idle (no fade's clock wakes: one a recall or a cancel retired ends at its wake and runs no step and no end); the end before the midpoint (it follows the twentieth step); every event in the landing, which runs inside one resume of the fade's clock and never yields, so only its own sets run inside it (the end's row reads the state `landing` from inside it, as the landing applies the scene's matrix block, with the target current).

## Smooth transitions

- `scene_transition_targets(scene_data)` snapshots `{id, start, target, step}` for every continuous entry of `scene_entries` *once*, before the fade: the continuous globals in `SCENE_GLOBAL_PARAMS` (master density, filter freq/res/mix, delay time/feedback/mix, reverb, drift, and per LFO the free period, depth and offset), then per voice its continuous keys in recall order (synth, grain, crossmod amounts and speed, the registered keys).
- An LFO the fade stops (`S.lib.lfos.transition_stops(n, scene_data)`: running now, `strata_lfo<n>` off in the scene) gets a depth target of 0 (its entry's `stop_target`) and no rate or offset target, so what the player hears fades out instead of growing toward (or changing rate for) a setting the scene never plays (#408). An LFO the scene keeps on, or one that is off now, crossfades as before. The end sets the scene's depth, rate, offset and state.
- 20 steps whatever the transition time. Step k sets `util.linlin(0, 1, start, target, k / 20)` (the local `step_value`), so the fade is linear over the whole time. Never re-read the current value inside the loop: that makes the fade front-loaded. A target a block's `through_zero` named ramps through 0 instead, and its switches run once at the step that reaches f = 0.5 (Scene blocks, `docs/notes/lua/scenes/recall.md`).
- A step sets each target through `set_scene_value`, so a registered field with its own `set` is never `params:set`, in a step or at the end.
- A number param (`step` 1, which does not round itself) is rounded to whole numbers during the fade. 3.4's LFO depths and offsets are one-percent controls, which round themselves, so a fade lands on whole percents. The end applies the scene's exact value.
- Not interpolated: mod sources, grain modes and 3.8's grain clouds (their `range` in `voice_scene_keys`), lock and active states, tempo, filter type and mutation settings, a registered voice param's discrete keys (`discrete`) and a registered field with `discrete = true`. They switch at the end through `recall_scene_instant()`, which also lands every param exactly on its target.
- The registered voice params that are not discrete crossfade like the built-in ones (`scene_transition_targets`, by key name); a registered field without `discrete` crossfades with the continuous globals.
- `recall_scene_instant` sets a voice's registered keys (in sorted key order, #531) after its source and its built-in keys, so a discrete one such as freeze lands after the source it belongs to and after the voice's `freq`.
- Every param a recall, a fade step or `apply_entries` sets goes through `set_scene_value`, which calls a registered field's own `set` first, when the field has one; every other param goes through `set_scene_param`: a binary one through `set_binary_param`, so its MIDI map's value follows and a mapped controller with echo gets one CC per set (#538); the others through `params:set`, whose own `set` sends the map's CC on norns.
- Any recall ends a running transition first (`end_scene_transition("superseded")`, which stops the clock without a redraw, as the recall redraws itself).
- `S.scene_transition_clock` / `S.scene_transition_active` track the running transition; `cancel_scene_transition()` ends it.
- The fade cue (#254): each step sets `SCENE_TRANSITION.step` to its number (1 to 20; the first runs inside the recall) after its params and before its `request_redraw()` and `grid_redraw()`. `shows_current(slot)` is true when `slot == S.current_scene` and either `fading_to()` is not the slot or `step` is nil or odd, so the target is lit from the recall (while step 1 sets its params, before it sets `step`, a param action's direct `grid_redraw` lights it too) and after steps 1, 3, 5, ..., and dark after the even ones: a 2 s fade changes every 0.1 s. Dark is each display's level without the current scene: the header's `S<n>` at 2 (its level is 10 with the scene sequencer on, 6 without), SCENES' slot at 4, a recall key at 8 (populated) or 10 (the slot the sequencer recalls next). `end_scene_transition` clears `step`, so a landing's redraws, a cancel and a superseding recall all show the current scene steady.
- A successful `load_scenes_from_disk()` cancels a running transition before it replaces the scenes. Otherwise the fade's end would apply the file's data for that slot, or fail on a slot that is now empty. The fade stops where it is. The cancel puts the previous scene back as current; the load then keeps it current only if the file holds the same scene in its slot (#518).

### States

| State | `S.scene_transition_active` | `SCENE_TRANSITION.next_step_due` | `SCENE_TRANSITION.target` | `SCENE_TRANSITION.previous` | `SCENE_TRANSITION.step` | `S.scene_transition_clock` | `S.current_scene` |
|-------|-----|-----|-----|-----|-----|-----|-----|
| idle | false | nil | nil | nil | nil | nil | the last scene that landed (0 = none) |
| fading | true | the `util.time()` its next step or end is due | the scene it goes to | the current scene before it | the number of the step applied last (1-20) | its clock (or a lost id, which the sequencer's overrun ends) | `target` |
| landing | false | nil | nil | nil | nil | nil (the id forgotten, its coroutine still running the landing) | the fade's target, while `recall_scene_instant` applies it (`setting()` true) |

The Machines entry's table splits fading at its midpoint: before it while `2 × step < steps`, after it from the step that reaches f = 0.5, which ran the through-zero switches (the closure's `switched`).

- idle to fading: `recall_scene(n, t)` with `t > 0`, after ending any running transition. Before the first step runs it sets five of the seven columns, in this order: `S.scene_transition_active` (true), `next_step_due` (now), `target` (n), `previous` (`S.current_scene`) and `S.current_scene` (n), so the first step's redraw lights the target. The first step, which runs inside `S.lib.clocks.run` (`clock.run` resumes it before it returns), sets `step` (1) before its redraws. The seventh, `S.scene_transition_clock` (the handle's id), is assigned when `run` returns, after the first step (nil while it runs).
- fading to fading: each later step sets `step` to its number before its redraws (the only write of `step` outside `end_scene_transition`).
- fading to idle: only `end_scene_transition(how)`, local to `lib/scenes.lua`. It clears every field and returns the fade's `previous`. How it ends:
  - `"canceled"`: `cancel_scene_transition()` (the sequencer's overrun, a scenes file load, cleanup). It stops the clock, sets `S.current_scene` back to `previous`, and redraws the screen (`request_redraw()`) and grids (`grid_redraw()`) whenever a fade was running, also a fade back to the current scene: its blink phase (`step`) ended, so a mark left dark at an even step is lit again. Nothing is set back: every value stays where the fade's last step left it, and a through-zero switch the fade already ran (at its midpoint, a matrix routing or an LFO home) stays the target's, while `previous` is the current scene (3.9's ruling: not a fault, a cancel stops the fade where it stands and the header names the last scene reached whole; the table's row `fading, after it + cancel`).
  - `"superseded"`: a new recall. The same, without the redraw: the recall redraws itself (and a failed `recall_scene_instant` redraws before it raises).
  - `"failed"`: a fade step's error, inside the clock. The id is forgotten; `previous` is put back and the screen and grids are redrawn (as for a cancel, also when `previous` was the target), then the error is raised again.
  - `"landing"`: the fade's end, inside the clock. The id is forgotten and the target stays current while `recall_scene_instant` applies it, so no grid or screen redraw inside that recall (a voice it starts or stops) shows `previous`. The landing passes the `previous` that `end_scene_transition` returns to `recall_scene_instant` as `current_if_failed`: only if the recall fails is `previous` current again, set before that recall's one failure redraw.
- So the current scene is always the last one that landed or the one now fading: a fade superseded by another keeps the first fade's `previous`, since the second reads the scene the first put back.
- The `"scene transition"` invariant (`S.register_invariant`) checks that `next_step_due`, `target` and `step` are set exactly while the flag is (`step` is nil exactly when no fade runs), and that no clock is kept while idle.

Every exit of the transition clock ends the transition:
- at its end, before `recall_scene_instant`, which it passes the scene data it read when the fade started;
- when canceled;
- when a param action raises an error during a fade step. Each step runs in an `xpcall` with the global handler `with_traceback`, outside the `handle.sleep`, and the error is raised again with its traceback, so maiden shows where the param action failed. `with_traceback` adds a traceback only when the message has none yet.
