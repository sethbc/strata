## Must not break

- **Scenes travel with the PSET** (the groundwork before 3.8, design §6): a PSET load never recalls a scene and never takes the PSET's scenes over live scenes no PSET holds (`S.scene_file.pset` nil, a slot populated or named) until they are kept as a backup (`back_up_live`: the live file written, then set aside with the `.bak` names, one line `scenes in no PSET kept as <backup>`); when that fails (every backup name taken, the card refusing), one line `scenes from <path> not loaded: the scenes in no PSET could not be kept (<why>); the live scenes stay` and the hint row's flash `pset scenes not loaded` (`PSET_SCENES.refused`, for `SCENE_LOAD.start_flash_seconds`), and nothing changes; in a session whose live file is blocked the why is `the live scenes file is not written in this session`. `S.scene_file.pset` is cleared before the write at `capture_scene` and `set_name`, so an edit always counts, in a later session too (the field is read back at a start). The mark is trusted only while its PSET still holds these scenes (`mark_holds_live`, one read at each PSET load: `<mark>.scenes.data` there, at `SCENE_DATA_VERSION` (format 10), its scenes encoding as `S.scenes`); a stale mark (the file deleted, a PSET copied without it, an older copy put back) counts as no PSET and is cleared, and a load of the marked PSET that finds its scenes file missing or unusable clears the mark (#766).
- The scenes' PSET hook is registered at include, so it runs before morph's (which forgets its plan once the slots change).

## Scenes with the PSET

Since the groundwork before 3.8 (design §6, rulings 34 and 35) each PSET carries its sixteen scenes in `<path_base>.scenes.data`, the fifth side file, made at include with `S.lib.side_files.new{name = "scenes", contents = "scenes", version = SCENE_DATA_VERSION, floor = SCENE_FORMAT_FLOOR, key = "scenes", live_file = "scenes.data", side_suffix = ".scenes.data", backup_suffix = ".bak", capture, validate = scenes_problem, load = load_pset_scenes}` (`live_file` only because the helper requires it: the live file keeps its own writer, status rows and load prompt, `docs/notes/lua/scenes/disk.md`). With the floor at the version, the PSET's file loads at format 10 (`SCENE_DATA_VERSION`) exactly, and a file of another format reads `not a version 10 scenes file`. Its hook, `pset_hook(nil, nil, saved, deleted)`, is registered at include, before morph's.

- **A PSET save** writes the sixteen scenes beside it, an empty set too; when written, `S.scene_file.pset` becomes the PSET's path base and the live file is written again (when this session may write it).
- **A PSET load**: first a pending quantized scene recall is dropped and a running transition is canceled (its previous scene back as current), whatever the file holds, since the read has set the PSET's sound and the fade's later steps and landing would put the old target's params back over it (#859; a factory load too, `docs/notes/lua/factory.md`). Then no scenes file, or an unusable one (set aside by the helper with its line `error loading scenes file <path>: <why>; kept as <backup>`), leaves the live scenes; when `S.scene_file.pset` names that PSET it is cleared and the live file written again. Otherwise `back_up_live` first (Must not break, above), then `take_scenes` (told the read's `silent`: a silent read prints no `scenes loaded from` line), `S.scene_file.pset` set, `SCENE_LOAD.armed_until` 0, `autosave` (the live file rewritten naming the PSET) and a redraw. Nothing is recalled: the sound is the PSET's params. `S.current_scene` stays only when its slot encodes the same (#518); the scene sequencer keeps its position and its kept next slot while that can still play (`kept_next_scene` draws again otherwise), and the chain keeps `chain.current`, so both go on over the new scenes; morph's slot params are unchanged and its own hook stops its clock; the undo is not cleared. A PSET that turns `scene_sequencer_enabled` on still recalls position 1 at the next tick, over the new scenes (the hook runs inside `params:read`).
- **A factory set's scenes** (3.8, 4d, ruling 49; `docs/notes/lua/factory.md`): `S.lib.factory`'s load calls `S.lib.scenes.back_up_live()` itself (its step 3: false and why stops the load) and then runs the scenes' PSET hook inside `S.lib.side_files.read_only(fn)`. While `S.lib.side_files.reading_only()`, `load_pset_scenes` neither backs up again (the mark is nil by then, so a second backup would set aside the file just written) nor marks a PSET: `take_scenes`, `S.scene_file.pset = nil` (a mark naming `<script>/factory/<key>/set` would make `mark_holds_live` trust a file in the code folder), `SCENE_LOAD.armed_until` 0, `autosave`. An unusable or missing `set.scenes.data` is skipped, never renamed (`docs/notes/lua/data-files.md`, Side files), and leaves the live scenes, which `load_pset_scenes` then writes back (`autosave`, while reading only): the load's backup moved the live file aside, so `scenes.data` is on disk again at once.
- **A PSET delete** removes its scenes file; when `S.scene_file.pset` names that PSET it is cleared and the live file written again.
