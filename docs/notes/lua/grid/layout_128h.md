## Must not break

- Pattern keys (rows 1-7 on page 1 only) go through `step_key` (16 positions, the column) and scene save keys (page 3, row 3) through `scene_save_key`, and scene recall keys (page 3, rows 1-2) call `recall_scene` only inside `S.lib.quantize.schedule("scene", fn, "S" .. x)`, as on the 256. Pages 2, 4 and 5 never toggle steps.
- Row 8 works on every page and is handled before the page's own keys.
- The faders on page 2 use the 256's fader list and mapping (`fader_param_ids`, `fader_page_count`, `set_param_from_column`, `grid_redraw_fader_row` from `lib/grid/faders.lua`, through `S.lib.grid_faders.shown_fader_ids(port)`), four per fader page (`GRID_LAYOUT.fader_rows`), so `S.param_page` means the same page on both layouts. Row 5 accepts only columns up to `fader_page_count(S.grid_voice_select)`.
- Page 4 goes through the core's helpers only (`source_key`/`source_level`, `record_key`/`record_level`, `clear_key`/`CLEAR_LEVEL`) and `S.lib.freeze`, so its keys and LEDs match the 256's page 4. The layout adds no clock, hold or per-port state of its own.
- The layout record names `strip_page = 4`, the page its strip is on, so the playhead clock repaints that page when the strip's LEDs change off the grid (#322).
- Page 5 (positions) and page 4's strip go through `S.lib.positions` only (`grid_key`, `strip_key`, `grid_level`, `strip_level`), never `jump`/`set_loop` directly. The layout's `z == 0` early return does not exist: a release reaches `positions.grid_key` (page 5) and `strip_key` (page 4's strip) so held pairs and the store and hold keys end.
- Pages are per port (`S.lib.grid_core.page(port)` / `set_page`): two 128h grids show and change their own pages. They are numbered by `S.constants.GRID_PAGES` (aliased `PAGES`: the sources page `PAGES.sources`, the positions page `PAGES.positions`), and a position row has `PAGES.position_cells` cells (#451).
- Its voice, play, page, pick and lock keys and its scene keys light at the core's shared levels (`voice_level`, `play_level`, `lock_level`, `LEVELS`, `scene_recall_level`, `scene_fade_level`, `scene_save_level`; the fader page keys at `fader_page_level`, #526, #452); the sources key on page 5 (10) and the cycle key (8) keep their own.
- Page 4 marks the grid voice, the voice its strip acts on, with column 11 of its row at `LEVELS.picked` (#444): a light, not a key.
- The step toggle on release and the step editor's hold (page 1) are the core's (`docs/notes/lua/grid-core.md`); the layout passes no step release on.
- 3.4 (design §11): page 2's row 5 column 16 is the macro fader page key (`S.lib.grid_faders.macro_page_key(port)`, LED `macro_page_level(port)`); rows 1-4 are `S.lib.grid_faders.shown_fader_ids(port)` (the bank's macros while the port shows a bank, `shows_macros(port)`, per port), in keys and redraw alike. The key enters at the bank already shown and changes nothing elsewhere; the press after the fourth bank shown since entering goes back to the voice faders (ruling 81, `docs/notes/lua/grid-core.md`, Macro faders). A fader page key (row 5), a voice select key (row 6) and, on page 2, row 8's voice cycle key go through `S.lib.grid_faders.leave_macros(port)` first, so they show that page of that voice's faders (ruling 82); row 7's lock keys keep their meaning. Page 3's row 5 columns 13-16 are the recorders (`grid_core.gesture_key`, `gesture_level`; the layout passes their releases on, since they act at their release, ruling 73) and row 6 the morph fader (`set_param_from_column("morph", x)`). Page 4's freeze key calls `S.lib.freeze.toggle_quantized`. The layout record's `shows_modulation(port)` is `S.lib.grid_faders.shows_modulation` (page 3, and page 2 while it shows a bank).
