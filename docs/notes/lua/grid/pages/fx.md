## Must not break

- **Every key sets a param, through its owner, and the page sends no engine command**: a bypass key goes through `set_binary_param` on `S.lib.voice_mix.BYPASS[effect].param_id` (the bypass's action ends the freeze first), a freeze key through `S.lib.fx_hold.toggle(effect)` (refused while bypassed), DC through `S.lib.fx_hold.clear()` (`params:set("delay_clear", 1)`), ds through `set_binary_param("delay_sync", ...)`, fm through `S.lib.params_setup.toggle_filter_mix()` (read at each press), the interval and the filter's type through `params:set`. The page never names `S.fx_last_mix` (a test reads the file): only `lib/params_setup.lua` writes it (AGENTS "Filter restore mix").
- **The reverb's freeze is read only through `S.lib.fx_hold.offered("reverb")`** (plan ruling 27), never the param's presence: the press, the redraw (`frozen`, which checks `offered` first) and the signature each ask `offered` before any read, so on the standard tier, where `offered("reverb")` is false (3.9, #819: the freeze is the high tier's alone), RF is dark (0) and dead and no read of `reverb_freeze` happens, though the param exists; on the high tier RF shows 15 frozen and 4 not, with no tier test here. The page never writes a freeze id: they are `FX_HOLD`'s.
- **A freeze set while its effect is bypassed goes back off** (plan ruling 26, the param's own rule): the key shows the param, so DF stays 4 on a bypassed delay, and RF on a bypassed reverb.
- **The fader lines are the engine's** (`faders(pane)`): five lines a set, each a 16-key line; a missing (renamed) id raises in `faders` (`params:lookup_param`), inside the faders' containment, which prints it once and leaves the page no fader lines, never a line silently dropped (#853); the delay's time line is `S.lib.grid_faders.fx_fader_id("delay_time")` (the division while synced). The page's `press` never sees their keys.
- **What the follow must cover**: the FX params' actions redraw no grid but for `filter_freq`, `filter_res`, `delay_time`, `delay_feedback` and `delay_mix` (`fx_fader_changed`, gated by `any_fx_faders()` and off during a scene transition), `delay_sync` and `delay_division` (`delay_sync`'s `shown_changed`, gated the same), `delay_freeze` (always: so its term is not in the signature, #855) and `reverb_freeze` (always, 3.9, #819: its signature term, written before the param existed, is now redundant and harmless). A set changes only at a press, which repaints, so it has no term either. Everything else reaches the page through the drift tick (`S.lib.grid_faders.follow_faders`): the fader lines' positions are the engine's part of the signature, and `signature(pane)` adds the interval, sync (whose action stands down during a scene transition), the filter's type, whether its mix is above 0, each effect's bypass and the reverb's freeze (`-` while not offered). A press repaints through `grid_key`, so DC's held light (`pane.held`) needs nothing more. Each term has a test that fails without it, after a first look (the load's first tick always repaints): "a param set elsewhere reaches the page within a drift tick" (sync set during a scene transition while the reverb set hides the time line), "the delay's freeze and a set key repaint the grid at once, with no drift tick" for the two without a term, and "line 7's keys and levels" checks the reverb's freeze set elsewhere (on the high tier), which its action repaints at once; no test fails without the reverb's term since the param's action redraws.
- **Index checks**: a press needs z 1, a whole x in 1-16 and line 6 or 7; anything else does nothing. A stored set outside 1-3 reads as the delay.

## Owns

- `lib/grid/pages/fx.lua` (`S.lib.grid_pages_fx`): its record (`M.record`, one side, `faders`, `signature`), registered at `GRID_PAGES.fx`, and `M.FX_PAGE` (the lines, the sets' ids, the key positions, the param ids it names, `levels`).
- State: `pane.state().set` (1 delay, 2 reverb, 3 master; the delay while unset), per port: a 256 whose two panes both show FX shows one set on both, as every page's `pane.state()` is shared by a port's panes; it goes with the grid (`forget_port`).
- Unit tests: `test/unit/grid_pages_fx_test.lua`, on every arrangement of the pane harness that shows the keys each test needs, with the four tests 0e handed on: the 256's "grid page 4 shows FX faders in rows 3-7 and keeps row 8/16" as "the FX faders show and set", "the delay fader picks the division while the delay is synced" as "the time fader picks the division while synced" (ruling P6: unsynced, the last key is `S.lib.delay_sync.DELAY.max_seconds`), "a scene transition redraws the grid once per step on grid page 4" as "a scene transition redraws once per step", and `grid_core_test.lua`'s "an FX change redraws the grids only while one shows the FX faders" as "an FX change redraws only while a grid shows the FX page".
