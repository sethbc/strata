## Must not break

- The stubs mirror the real norns libraries (`~/src/norns/lua`) and matron. Check behavior there before changing a stub.
- A stub refuses what norns refuses: where matron reads an argument with `luaL_checkinteger`, `luaL_checkstring` or `luaL_checknumber`, the stub raises the same error, so a call that would stop a draw on the device fails its test (#475, #476). The calls checked: `screen.level`, `move`, `line`, `rect`, `text`, `text_right`, `text_center` and `text_extents`; the grid's and the arc's `led` and `all`; `clock.sleep`, `clock.sync` and `clock.cancel`. The other screen calls (`font_size`, `font_face`, `update`, `stroke`, `fill`, `clear`) check nothing; a new stubbed call that matron checks gets the same check.
- `param.t` holds numeric type codes (`params.tOPTION`, ...). Never compare it with a string; a test enforces this, with either quote and either order.
- Values are typed as matron pushes them (`matron/src/weaver.cc`). What it pushes with `lua_pushnumber` is a float, also for a whole number: every poll value (`poll.fire` adds `0.0`, so tests keep passing whole numbers), `clock.get_tempo()` and `clock.get_beats()`; norns' `util.time()` is `s + us / 1000000`, a float too. What it pushes with `lua_pushinteger` stays an integer: encoder deltas, keys, grid and arc events, MIDI bytes, metro stages and `audio.file_info`'s numbers. On Lua 5.3 a float slot builds `buf3.0_file` (#300), and LuaJIT, with one number type, cannot show it: run a new poll test on `lua`.

## The stubs

The stubs mirror the real norns libraries (`~/src/norns/lua`), so check behavior there before changing them.

### Params

- Types: number, control, option, binary, trigger, file, text, separator, group.
- As in `core/paramset.lua`, `params.lookup[id]` is the param's index in `params.params` (a number; use `params:lookup_param(id)` for the param), and `params:add` and the `add_*` helpers return nothing (#478).
- `set_action`, `hide`/`show`/`visible`.
- `params:write(filename, name)`, `params:read(filename, silent)` and `params:delete(filename, name, number)` as in `lua/core/paramset.lua`. A filename is an absolute path or a number n, the numbered PSET `norns.state.data .. norns.state.shortname .. "-<NN>.pset"` (`<data>/strata/strata-01.pset`; the stub's `norns.state` is the script's data folder and `strata`, as `Script.load` sets them, and a numbered write makes the folder, which norns makes as the script loads). Read sets each param in file order through its own `set`, so actions fire mid-read as on norns. Then each calls its action as norns does: `params.action_write(filename, name, number)`, `params.action_read(filename, silent, number)` (only when the file exists) and `params.action_delete(filename, name, number)`, with `number` the two-digit string of a numbered write or read and nil for a path; delete removes the file (`os.remove`, where norns runs `rm`) and passes the number its caller gives (the PSET menu gives one; a number filename gives none, as on norns). `params:set_save(id, false)` keeps a param out of the file, as norns does for most system params.
- Strings as `core/params/*.lua`: a control without a formatter shows `util.round(value, 0.01) .. " " .. units`; a number or binary returns its value, a number.
- A ControlSpec made without a default has `default` nil, and its control starts at raw 0. `spec:copy()` is `core/controlspec.lua`'s: range, warp, step, default, units and quantum (not `wrap`, as on norns).
- `params:get_raw(id)`/`params:set_raw(id, v, silent)` as `core/params/control.lua`, for control params only (the stub errors on any other type): `set_raw` wraps a wrapping spec or clamps to 0-1, stores the raw value unrounded and fires the action on a change unless silent; `get` maps raw and rounds to the step.
- A control's `params:set(id, v)` is `set_raw(controlspec:unmap(round(v, step)))`, as `core/params/control.lua`'s; `unmap` wraps a wrapping spec into its range by whole ranges before it rounds and clamps (a 0-10 wrapping control set to 12 reads 2), and raises where norns would loop forever (an infinite value) (#478).
- `params:delta(id, d)` calls the param object's own `delta(d)`, as `core/paramset.lua` does and as norns' PARAMS menu turns E3, so a script that replaces one param's `delta` (the quantized `freq`'s turn mark, #318; the number params' whole steps, #534) changes both. Each type's `delta` is `core/params/*.lua`'s: a control's is `set_raw(raw + d * quantum)`, which wraps a wrapping spec (#478); a number's `set(value + d)`, unrounded; an option's rounds `d` away from 0; a binary's follows its behavior.
- Warps: `exp`, `db` and `lin`.
- norns' system params come first (`audio.add_params` and `clock.add_params`: the LEVELS, REVERB, COMPRESSOR, SOFTCUT and CLOCK groups with their types, ranges and factory defaults, `clock_tempo` 120). Every id of `core/paramset.lua`'s `system_param_ids` is there but `clock_midi_out`, which norns never adds (its params are `clock_midi_out_1..16`). So a script param with a system id fails as a collision.

### Libraries

- `tab.save`/`tab.load`: lib/tabutil.lua's, ported unchanged. The `-- Table: {n}` layout; numbers go through `tostring`, so they keep 14 significant digits as on norns. A plain `return {...}` file loads as nil, so test fixtures are written with `tab.save`, or the `tabutil_text(value)` helper in `test/helpers.lua`.
- `require("pattern_time")`: `test/stub_pattern_time.lua` (3.4), `lua/lib/pattern_time.lua` line by line, over the stub's metro and `util.time()`, so a pattern's metro runs only when a test calls its `event` (`S.gestures[k].pattern.metro.event()`) and the times it records are the clock's. A fresh library table per install (the module returns a constructor, `package.preload` calls it).
- `require("er")` (3.4): `test/stub_er.lua`, through `package.preload`: `er.gen(k, n, w)` is `lua/lib/er.lua`'s, line for line (the bucket method, `w` shifting right and wrapping). Unlike the library it sets no global `er`, so a script that relies on one fails.
- `midi`: `test/stub_midi.lua`. 16 vports, `to_msg`/`to_data`. Helpers `context.midi.plug(port, name)`, `unplug(port)`, `send(port, msg)`, and `reassign(from_port, to_port)`, which moves a device between vports as SYSTEM > DEVICES does (`update_devices()` only, no `midi.add` or `midi.remove`; the grid's and arc's `reassign` logic).
- `grid` and `arc`: 4 vports each, mirroring `lua/core/grid.lua` and `arc.lua`; devices are kept by id in `devices[id]`, each named after its id (`grid 1`, `arc 1`), and every event reaches both `device.key`/`delta` and the vport's handler, as norns fires them.
  - `led(x, y, level, rel)` and `all(level, rel)` take integers (matron's `luaL_checkinteger`: 7.0 passes, 7.5 raises); `rel` adds to the level, clamped to 0..15, as `dev_monome_grid_set_led` and `dev_monome_all_led` do. The stubs also fail on an LED off the device and on an absolute level outside 0..15, which matron does not check (#476).
  - `context.grid.plug(port, cols, rows)` and `context.arc.plug(port)` put a new device on the port's vport (its name, `device`, the grid's `cols` and `rows`) and call `grid.add`/`arc.add`; `unplug(port)` calls `remove` with the device the port's vport holds and empties the vport.
  - `context.grid.press(port, x, y, z)`, `context.arc.turn(port, ring, delta)` and `context.arc.push(port, button, state)` deliver an event from the device the port's vport holds now.
  - `update_devices()` is norns': every device leaves its port, then each vport takes the device whose name it holds (a grid vport also its `cols` and `rows`).
  - A grid vport's `rotation(val)` is norns' `Grid:rotation`: the device takes rotation `val` (a whole number 0-3, anything else raises; kept as `device.rotation_value`), its `cols` and `rows` become its own size swapped for 1 and 3 (`native_cols`, `native_rows`), its LEDs stay as they were (as matron's `dev_monome_set_rotation` leaves them), and `update_devices()` copies the size to the vport.
  - `reassign(from_port, to_port)` is SYSTEM > DEVICES' K3 (`lua/core/menu/devices.lua`): `to_port` takes the name of the device on `from_port`, every other vport of that name becomes `"none"`, then `update_devices()`. It calls no `add` or `remove`, so the script hears of the move only as the norns menu closes (a test opens and closes it with `_menu.set_mode` around the call).
- `audio.file_info(path)`: `lua/core/audio.lua`'s (matron's `sound_file_inspect`): channels, frames and sample rate of a file a test lists in `context.audio.files[path] = {channels, frames, rate}`; `context.audio.register(path, {channels, frames, rate})` lists one too, and a path under a test's data folder is read from its WAV header (`fmt ` and `data` chunks); any other path returns 0, 0, 0, as for a file libsndfile cannot open.
- `poll.set`: the system polls plus the engine's `addPoll` names; unknown names return nil. `context.polls.fire(name, value)` reaches started polls, with a number turned into a float (`w_handle_poll_value`'s `lua_pushnumber`).
- `require("fileselect")`: a module through `package.preload`, never a global, so a script that relies on a `fileselect` global fails.
  - `enter` records `context.fileselect.last`, and its callback in `fileselect.callback` (as `fs.enter` keeps it in `fs.callback`, so a second `enter` replaces the first's). A folder that is not a string raises, as `fs.enter`'s `fs.folder:sub` does (#481).
  - `pushd(dir)` opens the selector in a folder below the one entered, as norns' PARAMS menu does with a file param's `dir`: it lists the folder through `util.scandir` (the folder between double quotes, as `fs.getlist` does) into `last.list` (#559).
  - From play mode, `enter` calls `norns.menu.init()`, whose `set_mode(false)` runs a script's `_menu.set_mode` wrapper and makes the `redraw()` call norns' `fs.enter` makes, then its own `fileselect.redraw()`.
  - `fileselect.redraw` draws nothing and counts its calls in `context.fileselect.redraws`.
  - `context.fileselect.close(path)` closes it as `fs.exit` does: from play mode `norns.menu.init()` (with its `redraw()`), then the callback with `path`, or `"cancel"` when nil.
  - Keys and encoders are not rerouted.
- `require("textentry")`: `test/stub_textentry.lua`, a module through `package.preload` (`context.textentry.library`), mirroring `lua/lib/textentry.lua`'s routing, unlike the file selector's stub.
  - `enter(callback, default, heading, check)` keeps `txt`, `heading` and the callback in `te.callback` (a second `enter` replaces the first's, as norns has one entry). From play mode it keeps the globals `key`, `enc`, `redraw` and `refresh`, puts `te.key` and `te.enc` in `key` and `enc`, calls `norns.menu.init()` (so a script's `_menu.set_mode` wrapper and its `redraw()` run, and play mode routes to the entry), then puts `norns.none` in `redraw`. From the menu it takes `_menu.key` instead and leaves the globals alone.
  - `te.key(2, 0)` cancels (calls back nil); `te.exit()` puts back what `enter` kept (from play mode, then `norns.menu.init()` again) before the callback. `te.enc` and K3 do nothing: typing is `context.textentry.finish(text)`, which ends the open entry with `text` as OK would (an error with none open). `context.textentry.open` says whether one is open.
  - `te.redraw` draws nothing and counts its calls in `te.redraws`.
- `require("musicutil").note_num_to_freq`, `_path.audio` (`context.audio_dir`), `util.scandir`/`util.os_capture`, `_menu.rebuild_params`.
- `util.make_dir(path)` runs `mkdir -p <path>` unquoted, as `lua/lib/util.lua` does, and refuses (raises) a path the shell would split or expand: anything but letters, digits and `._/-+,:@=` (#481).
- `metro.init(event, time, count)` or `metro.init{event = ..., time = ..., count = ...}` as `core/metro.lua`'s: time 1 and count -1 unless given; `context.metro.all` lists the timers made. The 31st returns nil and prints `metro.init: nothing available`, as norns does when its 30 script metros are taken (#481). Nothing runs on its own: a test calls a timer's `event`.
- `_menu.set_mode(mode)` is `lua/core/menu.lua`'s (#521): `true` opens the menu: `redraw` and `refresh` become `norns.none`, and the encoders and `_menu.key` go to the menu's own handlers (`context.menu.enc`, `context.menu.page_key`, which do nothing). `false` returns to the script: the screen is cleared, `redraw` and `refresh` become `norns.script.redraw` and `norns.script.refresh`, `_menu.key = key` and `norns.encoders.callback = enc`, then `redraw()` draws the script's screen. A test that replaced the global `redraw` loses that replacement as the menu closes, as on norns.
  - `norns.script.redraw` and `refresh` are what `Script.load` stores: `load_strata` stores them after the script's chunk runs, before `before_init` (so a test can close the menu before `init`, as norns can while the engine loads); before any load they are `norns.blank` and `norns.none`.
  - Not modeled: `load_strata` runs `init` in play mode with the script's `redraw` in place and makes no `norns.init_done` call; on norns `redraw` is `norns.none` until `init`, the menu is open while a script loads from it, and `init_done` closes it (`set_mode(false)`) after `init`. The screen save and restore and the menu's pages are not modeled either.
- `norns.menu.init()` is `_menu.set_mode(_menu.mode)`.
- `screen.level`, `screen.text`, `text_right`, `text_center`, `text_extents`, `screen.move`, `line` and `rect` check their arguments as matron does (`luaL_checkinteger` for the level: 7.0 and `"7"` pass, 7.5 raises; `luaL_checkstring` for the texts, which takes a number as its string; `luaL_checknumber` for the coordinates) (#475).
- `screen.line`/`screen.rect` are recorded in `context.screen.lines` (`x1, y1, x2, y2, level`) and `context.screen.rects` (`x, y, w, h, level`) beside the texts. `screen.fill()` and `screen.stroke()` close the current path as norns does (`lua/core/screen.lua`): they mark every line and rect drawn since the last fill or stroke (or `screen.clear()`) `filled = true` or `false`, so a test can tell a filled cell from an outline; `filled` is nil until then. They also set each one's `level` to the level in force at the fill or stroke, the one norns paints the path with, not the one set when it was built (#474); `test/render_pages.py` draws them at that level and leaves out a path never stroked or filled.
- Text widths (`stubs.text_width`, used by `screen.text_extents` and the layout tests) are norns' font advances: norns.ttf (04B_03) at 8 px, the face and size matron starts with, one advance per printable ASCII glyph (most capitals 5 px, `m`, `w`, `%`, `/`, `#`, `&`, `@` and `\` 6, space 4), measured with Pillow; any other character counts 6, the widest. matron's own `text_extents` returns the ink width, never more than the advance, so the stub's figures are never short (#479).
- `norns.enc.accel`/`sens`: state in `context.encoders.accel`/`sens`, starting at norns' script defaults (accel on, sens 2). `context.encoders.deliver(n, delta, interval)` delivers one hardware encoder event the way `encoders.process_with_accel` does, with `interval` seconds since the previous one.

### Param types

- Like norns, the param stub stores numeric type codes in `param.t` (`params.tOPTION` etc.), all from its one `PARAM_TYPE_CODES` table (exported as `stubs.PARAM_TYPE_CODES`).
- `params:add` with an unknown type raises an error (norns prints one and adds nothing).
- Never compare `param.t` with a string. A test enforces this for the script's sources, with either quote and either order: `p.t == "option"`, `'option' == p.t`.
- A file param lists its folder as `lua/core/params/file.lua`'s `File:loaddir` does (#480): at every set that changes its path to anything but `"-"` (silent or not) it calls `util.scandir` on the path's folder and keeps `dir`, `dirfiles` (the files, never a folder) and `dirpos` (the path's place among them); `"-"` clears all three, and a path with no folder lists nothing. A test counts the listings by wrapping `util.scandir`. `File.new`'s own listing is left out (only `dir` is set): it is norns' cost at a param's creation, not one the script chooses, and the eight buffer file params made at every `load_strata` were about 23,000 listings a run, doubling the suite's time.

### Group sizes

norns cannot see where a group ends (it takes the next `n` params), so the param stub requires each group to get exactly `n` params. It errors:
- when the next group arrives first (this is also the nesting error);
- when the param after the group's last one is neither a separator nor a group (`n` too small);
- in `context.check_param_groups()`, which `load_strata` calls after `init()`, when a group is still short at the end of the list.
