## Must not break

- buffers.data holds paths only, never audio. Audio reaches disk only when a take completes (the engine's scratch file) or on an explicit `buf<n>_save`.
- A buffers.data that cannot be loaded is moved aside to its first free backup name (`buffers.data.bak`, `.bak.2` ... `.bak.9`), never over an earlier backup (#466). If that fails, `S.buffer_autosave_blocked` stops every write of the file (`remember` and cleanup), so a bad file is never silently overwritten.
- **The load's problem and the write's are two facts** (#868): `S.buffer_file.load_problem` and `write_problem`, each set only by its own path; `problem`, what SETUP and the start flash read, is derived from them (the write's while one failed, else the load's) and never assigned in `lib/buffers.lua`. A good write clears only the write's problem, and the load's only when it replaced an unreadable file still in place.
- buffers.data is written only through its writer (`S.lib.side_files.writer`: `save_buffers_to_disk`, the timed write and the cleanup step's), which goes through `S.lib.data_files.write` (a checked `.part` renamed into place, nothing written when the bytes are the same, #301), never `tab.save`. It is written whenever what it would hold changes (#327): `remember()` runs at the end of `buffer_display_changed()` and at the end of `buffer_state_changed` when something changed, the two places every slot change passes, and compares `encode(remembered_buffers())` with `S.buffer_file.text`, so a report that changes no path or start costs no file read. A new place that changes a slot's `path`, `missing_path` or `start` must end in one of the two. `remember()` never writes the card itself (#566): through the side files' one debounced writer (`S.lib.side_files.writer`, 3.9, #906; `docs/notes/lua/data-files.md`), it starts one clock, kept in `S.buffer_file.save_clock` (nil when none is pending), that writes `BUFFER_DATA_SAVE.delay` (0.1 s) later if the encoded value still differs from `S.buffer_file.text`, so a burst of changes (filling eight slots) is one write carrying the newest state and none happens inside a poll callback. The cleanup step `buffer_paths_save` cancels that clock and then saves (the writer's `save_now`), so an exit inside the 0.1 s still writes the change, once, and no write follows cleanup: no timed write starts after it. A save that raises inside the deferred clock leaves no stuck clock: `save_clock` is set to nil first, so the next change starts a new one.
- **The format floor** (3.7, design decision 21): a file of version `BUFFER_FORMAT_FLOOR` (2, 3.3's) to `BUFFER_DATA_VERSION` loads (a missing start is 0); a version 1 file (3.2's), or one above the build's version or with no path list, is set aside as an unloadable file is, with one console line (`error: buffers file has version 1, older than version 2, the oldest this version loads: it is set aside, not converted`), never converted and never overwritten. No `.v<n>` copy is kept at a save.
- A remembered file that is missing at start keeps its path in `missing_path` and is saved again, so the sample comes back once the file is there. A clear, a load or a new recording in the slot forgets it.
- `S.buffers_restored` counts only the slots the engine's `bufferState` poll confirms holding audio.
- `buffer_load_failed` undoes exactly the load its `bufferLoadFailed` report names (by load number), never a later load, clear or recording.
- **A canceled replace take is decided by the engine's next length report** (#311): its "canceled" shows the slot empty and keeps what it replaced in `kept_state`, which the first `bufferState` report of the slot applies on audio and drops on 0 s; `kept_state` is never set while the slot records (the `"buffer slots"` invariant). A load's snapshot during an armed replace take is the two-way `{after_cancel = true, kept}`, resolved only by `resolve_previous` (at the failure report, or in `state_before_take`) from the length the engine reported after "canceled". No length settles a take stopped while still armed (`stopped_armed`: a synced take's slot still reports its old audio): only its "canceled" or "recording" report, or the finishing fallback, does. **That fallback leaves the slot as it was before the take** (#974): a take that never started recorded nothing, so it is settled as its "canceled" and the length report after it would be (`S.lib.buffers.settle_kept_state`, the same `settle_kept_state` the report runs), from the last known length: the file it replaced back (its name, path and binding) while the slot still reads audio, empty once the engine had emptied it (a threshold's take, or a synced one whose 0 s came), and never the scratch path of a take that was not written.
- **Lua never gives a long load's check up** (#317): only the engine knows how its check ends. `start_check_notice` changes no field: after `BUFFER_SETTLE.check_notice_seconds` (30 s) it prints one line and flashes `buf <n> still checking K2:ld/clr` (how the player leaves it, #904: a load or a clear, K2 on BUFFER; no other way out is added), and the load stays the slot's until a report settles it, a failure report undoes it, or a load, clear or recording replaces it (each ends the check and leaves no clock of it: "after a check's notice a load or a clear ends the check and leaves no clock of it"). A failure report whose undo puts back a state with no check (an empty slot, a restore's) ends the failed check's notice too ("a checking load that fails ends its notice clock"); the `"buffer slots"` invariant holds a `"notice"` clock only while the slot checks a load. A check starts only with the `bufferState` poll (without it no report could end one), and `checked_before_load(path, start)` counts what the engine reads from the start, as `loadSlot` does.
- **A check ends only at its own load's 0 s or at a later load's report** (#983): the engine names no load still in its check, so a report under the checked load's number (`checking_load`, the slot's newest) comes after its outcome, and only its 0 s says it took effect; any other length is the slot's old audio reported at its rejection, whose `bufferLoadFailed` undoes the load, and settles nothing. A check a later load's failure gave back (`checking_load` below `loads_sent`) ends at any report Lua acts on, since that report names a later load and every load up to it has an outcome (the checked load's 0 s may have come under its own number before the later load reached the engine, and was ignored then). `checking_from`, the length shown before, decides nothing in the end of a check. A given-back check whose load had canceled a recording, then is rejected, gets the engine's report of the length the cancel left under the checked load's own number, just before the failure (`rejectLoad`): no other report names that load once every later one has failed, so `buffer_state_changed` keeps its seconds for the failure's undo (`resolve_previous`) and ends nothing, but when the two numbers are equal modulo `BUFFER_STATE_LOADS` (7 loads apart: the wrap), where it stands down and the report acts as the later load's (#1016: under the later load's number, as before, it settled the slot as the checked file for a moment, whose bind forgot a grid's bank pick for good).
- **A check that ends ends in every snapshot of it** (#399): when a report ends a check, every tracked later load's `previous` that still holds that check loses `checking_from` and `checking_load` and gets the new `confirm_since`, so a failed later load puts back a load awaiting its read, never a check no report will end.
- **A load being checked is never forgotten while it is** (#980): `pending_loads` holds every load being checked (the slot's `checking_load`, or one a tracked load's `previous` would give back) and at most `BUFFER_SETTLE.tracked_loads` (4) others: `load_buffer` drops the oldest other, one at a time, until fewer than 4 are left before it adds its own, working out after each drop which loads are still being checked (a dropped load's `previous` may have been all that named a check, which then goes too: "a check no tracked load would give back is dropped with the bound"), so a check's failure always finds its entry and ends the check, and the list is back to 4 at the first load after a chain of checks has ended ("the tracked loads return to their bound after chained checks"). A load not being checked is forgotten as before, its late failure finding nothing, but for a restore's own: a restoring slot that tracks no load reads a failure of load 1 (init's first of the slot) with no entry as its restore's, the one outcome still to come, and empties as a tracked restore's failure empties it (`buffer_load_failed`). Such a late failure is a server read that failed after the fade, or, with no `bufferState` poll, a long file's check. A plain load forgotten so and given back with no load tracked, awaiting its read or settled `unsettled` since (#1040), empties on a failure with no entry that the engine reports emptied (#1035: emptied only while nothing has changed the slot since, so the engine's slot is empty with no load applied since, whichever load the report names; a failure not emptied is ignored), and so does a forgotten restore that settled `unsettled` (no longer `restoring`, `settled_empty == "restore"`) on load 1's emptied failure (#1040). Only those settled states: the engine's poll sends its last value again at a value request (`CronePoll`'s `requestValue`, which Lua's `poll:update()` makes), and such a repeat finds the slot it emptied, or a take recorded since, which it leaves ("a repeated emptied failure of a forgotten load leaves a take recorded since (#1040)"). A forgotten load's emptied failure while the load sent right after it is still tracked, the oldest, over the forgotten load's own state (its `previous` has `confirm_since`), is spliced into that load's `previous` as a tracked failure is (#1040: the engine's slot was empty when that load reached it, so if every later load fails the slot is empty). One further below is ignored: a load between may have taken effect after the failed read, and the slot then plays it. So is one with a clear or a recording between it and the next load, whose `previous` then has no `confirm_since`: a stopped take may still complete (#890), and its adoptable empty slot must stay.
- **One slot check** (#402): `valid_buffer_slot(slot)` is true for a whole number from 1 to `NUM_BUFFERS`, by `slot == math.floor(slot)` (a poll's `3.0` is slot 3; never `math.type`, which LuaJIT lacks), and `slot_index(slot)` gives the integer every name and param uses (`buf3_file`, never `buf3.0_file`). Every entry point that takes a slot (`load_buffer`, `clear_buffer`, `save_buffer`, `save_buffer_loop`, `record_buffer`, `set_start`, `recording_started`, `status`, `S.lib.files.random_into`, `S.lib.waveforms`, `S.lib.playheads.record_head` and `moving`) goes through them, so anything else sends nothing and raises nothing.
- **The seconds a slot holds of a file** are `slot_file_seconds(sample_rate)` (`buffer_seconds`, times `NORNS_SAMPLE_RATE / sample_rate` above the server rate, #326), and the largest start is `longest_start(file_seconds, sample_rate)`; `set_start`, the restore's clamp and the BUFFER page's start field read only them. The server rate is `S.constants.NORNS_SAMPLE_RATE`, never a second copy (#516).
- **Buffer file parameters share one setter for PARAMETERS, OSC, PSETs and display updates** (#480, #559, #1203). The native file object keeps its display and E3 navigation. For a changed file Strata fills `dirfiles` and `dirpos` with the quoted directory reader in `lib/files.lua`. A clear, a take or a dub's end selects the audio folder without a listing. A silent set changes the selection only. After a silent PSET read, the buffer hook loads each named sound file that differs from its slot’s current or pending file. A slot keeps its own file selection for rollback and reapplies its browser display rules because native file actions run after the selection has changed (#1221, #1225).
- **A folder with a dollar sign, a backtick, a backslash or a double quote stays out of the native browser.** PARAMETERS opens that browser in the file object's `dir`, which the host passes to its shell scanner. Such a file can still play on an ordinary selection, and buffers.data keeps its path for startup. The param and its PSET show the audio folder. Ordinary spaces and apostrophes work in both folders and filenames.
- Both `save_buffer` and `save_buffer_loop` use `send_save` for admission and tracking (#246, #1262). Recording, finishing and pending file loads prevent either save. During a replacement the old audio may still play until the engine confirms which file the slot holds.
- A save is called saved (console `saved to <path>`, BUFFER `saved buf <n>`) only from its `bufferSaveResult` report, never when `save_buffer` sends it (#127). `buffer_save_result` flashes only for the slot's newest save (by save number), so a late report never speaks for a newer save.
- `BUFFER_STATE_STRIDE` and `BUFFER_STATE_LOADS` (top of `lib/buffers.lua`, each at the start of a line, where a test finds it) equal the engine's `bufferStateStride` and `bufferStateLoads`.
- **A `bufferState` report acts only for the slot's newest load** (#578): `buffer_state_changed` takes the publication outcome from the sign (negative means unavailable) and decodes the load number from the magnitude (`(load * (NUM_BUFFERS + 1) + slot index) * BUFFER_STATE_STRIDE + seconds`) and returns before anything else unless it is `loads_sent % BUFFER_STATE_LOADS`, or the own number of a check a later load's failure gave back, whose seconds alone it keeps (#1016, below): a report the engine sent before it had the slot's newest load tells what that load replaces, so two quick loads never show the first one's length or status. `loads_sent` counts every `loadBuffer` the slot was sent, failed ones too, as the engine counts them, and is never reset; the engine numbers a clear's and a recording's reports, and the periodic ones, with the same count, so they act. The engine names no load still in its check, nor any after it (#983, `docs/notes/engine/buffers.md`, Polls): a report of the old audio during a long load's check names the load before, so it never acts. More than `BUFFER_STATE_LOADS` loads in flight wrap the number and an older report then acts as in 3.3, which is why the #401 rule (`awaiting_zero`) and the check rule stay. The slots' length (slot index `NUM_BUFFERS`) acts only with load number 0. The seconds are rounded to the hundredth (`math.floor(x * 100 + 0.5) / 100`), so the same length gives the same number whatever load it names (`buffer_state_changed` compares them with the stored `seconds` to tell a change).
- **A slot's settings follow what it holds** (3.7): an accepted file load immediately closes the SLICE editor for that slot. `confirm_buffer_audio` binds the slot (`S.lib.samples.bind`; a replace take first starts its own record with `start_take`, its synced tempo in it), `apply_buffer_state` binds settled audio and unbinds an empty state, and `clear_buffer`, a settle with no audio and a canceled take's 0 s report that drops `kept_state` (when the slot is still bound) unbind it (a replace take's start unbinds it in `lib/record.lua`); a whole save keeps `S.lib.samples.snapshot(slot)` with its pending save and gives it to `store_file` on success (`docs/notes/lua/samples.md`).
- `BUFFER_DATA_VERSION` is 3 (3.7: `settings`, a take's record per slot or `false`; version 2 loads with none, and its `settings`, if any, is not read). A start reload (`set_start`) is canceled by a load, clear or recording in its slot, and never runs while the slot records.
- A playable recording (a dub) keeps the file's `start`, `sample_rate` and `file_seconds` until its "ended" report makes the slot `take <n>` (start 0, neither field); a canceled one keeps all three (#244). `recording_started` is told the take's kind (`record_buffer` calls it before it sets `recording`, so `S.lib.record.state` cannot say).
- Every poll decoder floors its slot (the rule and why: `docs/notes/lua/record.md`, #300). The `"buffer slots"` invariant checks the result: a name of the form `take <number>` is the slot's own `take <n>`, and a path in the scratch folder named `buf*.wav` is `buf<whole number>.wav`.
- **A load over audio settles only after its 0 s report** (#401): the engine reports 0 s at once when a load over audio takes effect, so a report of audio before it is the old audio's (one sent before the load reached the engine). `load_buffer` sets `awaiting_zero` for a load into a slot that reports audio (not a long file's check, which waits for a differing report already, and only with the `bufferState` and `bufferLoadFailed` polls); `buffer_state_changed` settles nothing while it is set and clears it at the slot's next 0 s report. A load into an empty slot, a failed load's report and a check are unchanged; a settle, `apply_buffer_state`, a clear and a recording clear it, and the `"buffer slots"` invariant keeps it only while a load awaits the engine (`confirm_since`).
- `load_buffer` calls `S.lib.waveforms.forget(slot)` (the old overview goes at the load, whatever the new file's length, #401); `confirm_buffer_audio` (a take or load that settles with audio) calls `S.lib.waveforms.stale(slot)`, and `apply_buffer_state` (a failed load undone, a canceled take's kept state) `stale` too, or `forget` for a restored load still checking or awaiting confirmation.
- `buffer_state_changed` calls `S.lib.waveforms.changed(slot)` when its seconds or peak publication status change (the old overview goes at once, #401, #1187), and `S.lib.waveforms.stale(slot)` when something else changed with audio (a dub's slot now loaded: a reread), and reads nothing itself.
- **A take the engine could not write is never remembered** (#312). The `takeWriteFailed` handler matches the report's recording number to the RAM audio it describes. While that recording is active, `take_unsaved` makes it settle with no path. A replace take's settle and a playable take's end (`end_playable` in `lib/record.lua`) attach `take_number` to the RAM audio. Each pending load and each armed replace take carries that number in the state it may restore. An older take can still own the audio after a newer recording is armed or canceled. The handler drops the matching take's path from the slot and its rollback state, including a failure passed along to a newer load. A take awaiting a late length report carries the failure through rollback so that adopting its audio cannot restore the path. An explicit file load has no take number, even when it names the same scratch WAV. A failure of the displayed take flashes `take <n> unsaved` in the header (#878). The take stays playable, and its slot's path in buffers.data is empty.
- **A save never takes a name in use** (#522): `buffer_save_path(slot, kind)` adds `-2`, `-3`, ... to `<date-time>-buf<n>` (`-buf<n>-loop` for `kind == "loop"`) while a file has the name or a tracked save of any slot (`pending_saves`) still writes it, so two saves within a second, or after the clock went back, never overwrite each other.
- Lengths come from `S.performance.buffer_seconds` (16 s standard, up to 300 s high), never a constant: `record_buffer` caps a take at it and the BUFFER page sizes its seconds column from it.
- What a slot holds has one answer, `S.lib.buffers.status(slot)` (States, below), derived only: it stores nothing and no field changes for it. Whether a slot is free is `S.lib.buffers.is_free(slot)` (status `"empty"` or `"missing"`), and the grid's source and record keys (`source_level`, level 2; `record_level`, from the status) read only it, never a test of their own (#247); the fill (`S.lib.files.fill_empty`, status `"empty"` only: a missing slot keeps its path, #877) and BUFFER's value column (`slot_value_text`) read the status itself. `S.lib.buffers.saving(slot)` (a tracked save awaits its report, `pending_saves`; false without the `bufferSaveResult` poll; each admitted save waits for its own numbered report) and `missing_file(slot)` (a missing slot's remembered path) are derived alike, for BUFFER's row (#905, #877).

## Machines

### buffer slot
- **State:** `S.buffers[slot]` (`loaded`, `recording`, `finishing`, `confirm_since`, `checking_from`, `awaiting_zero`, `restoring`, `settled_empty`, `kept_state`, `missing_path`, and for a restore whether `pending_loads` holds any load and whether a length is known, `seconds`), the slot's take, `S.lib.record.state(slot)` (`kind`, `phase`, and a replace take's `unbound`), and its clock's role (`S.lib.record.clock_role`, a stopped playable recording's `"fallback"`); `S.lib.buffers.status(slot)` names its case (States, below), and the table's sub-states split six of them (a check a later load's failure gave back, `checking_load` below `loads_sent`, among them: #983).
- **Invariant:** `buffer slots`: a slot finishes only a recording, and only a replace take's; records only with a take (3.9, #903: the SCENES layout state that shows REC makes a real take); keeps a canceled take's state only once it no longer records; checks a load or awaits its 0 s only while a load awaits the engine; never settles empty while loaded; remembers a missing file only as a path (no `path`, not `loaded`); restores only a load that awaits the engine (`confirm_since`); runs a check's notice clock (role `"notice"`) only while it checks a load; names a path with an unsaved take (`take_unsaved`) only while it records (a dub over a file keeps the file's path until it ends); names a take for its own slot on a whole-numbered scratch path; and shows a start other than the last sent one only while a start reload is pending.
- **Test:** `test/unit/buffers_slot_test.lua`: "buffer slot: every cell is decided" and its rows (twenty-nine states by seventeen events); the invariant's lines in `test/unit/record_test.lua` ("the buffer slots invariant: finishing only for a replace take, recording only with a take (#903)") and `test/unit/buffers_test.lua` ("the buffer slots invariant: a missing path holds no file, a restore awaits the engine (#903)", "the buffer slots invariant: a notice clock only while a load is checked (#903)", "the buffer slots invariant: a path with take_unsaved only while recording (#903)").

Its table is in `docs/notes/lua/buffers/slot.md` (with the states' and events' definitions and the impossible pairs, each with its reason): at about 280 rows it would take this file past the notes' word limit.

## States

`S.lib.buffers.status(slot)` is what the slot holds: the first of these cases that applies, read from `S.buffers[slot]` and the take `S.lib.record.state(slot)` (nil unless `recording`). It is nil only for what is not a slot (`status(0)`, `status(9)`, `status(1.5)`, a non-number); every valid slot has one (`status(3.0)` is slot 3's). `is_free(slot)` is true for `"empty"` and `"missing"` only (false out of range).

| # | Status | Fields that encode it | Entered by | Free |
|---|--------|------------------------|------------|------|
| 1 | `"finishing"` | `finishing` (with `recording`, `confirm_since`): a replace take that ended and waits for the engine's length, whatever the take's phase (an armed replace take stopped with K3 finishes until its "canceled" report, and no length report settles it meanwhile) | `finish_buffer_take` (`lib/record.lua`: the take's timer, a stop, an "ended" report) | no |
| 2 | `"armed"` | `recording`, the take's `phase == "armed"` (a delay or a threshold) | `record_buffer` | no |
| 3 | `"loop"`, `"dub"`, `"recording"` | `recording`, with a playable take (`kind == "playable"`) that loops, one that does not, or a replace take (never with no take: the `"buffer slots"` invariant, #903) | `record_buffer`, the "recording" report (`record_state_changed`) | no |
| 4 | `"loading"` | `confirm_since` set: a load the engine has not confirmed, checking (`checking_from`) or not | `load_buffer` | no |
| 5 | `"loaded"` | `loaded` | `settle_buffer_slot` or `confirm_buffer_audio` from a report of audio, a dub's "ended" report with a length, `buffer_load_failed` putting a loaded state back | no |
| 6 | `"unsettled"` | `settled_empty == "load"` or `"restore"`: a named load (`name` kept) that reported no length yet; a later report of audio adopts it (`"loaded"`) | `settle_buffer_slot` (a 0 s report `BUFFER_SETTLE.confirm_seconds` after the load) | no |
| 7 | `"missing"` | `missing_path` set: a remembered file not found at start, kept for buffers.data | `restore_buffers_from_file` | yes |
| 8 | `"empty"` | none of the above (a canceled take may keep `settled_empty == "take"`, which a later report of audio still adopts) | init, `clear_buffer`, a replace take that settled without audio, a replace take's "canceled" report (until the next length report: audio puts back what the take replaced, `kept_state`), a dub's "ended" report that arrives with 0 s (`take <n>`, not loaded), a dub canceled while armed over an unsettled slot (`record_buffer` cleared its `settled_empty`), `buffer_load_failed` with an empty state | yes |

The fields stay what other code and the tests read (`loaded`, `recording`, `finishing`, `seconds`, `name`, ...); `status` adds no field. A dub canceled while armed over an unsettled slot leaves a named, free slot: BUFFER shows its name without a length, and the fill may load over it. `buffer_load_failed` can put back any of cases 4-8 from the state a load replaced (`apply_buffer_state`). A dub into a slot with no file is `take <n>` once `slot_reported` marks it loaded (its path comes at "ended"), so a failed load during it puts back a named slot, never a loaded one named `empty` (#400). A load, a clear and a recording leave a state by setting its fields (`load_buffer`, `clear_buffer`, `record_buffer`); the `"buffer slots"` invariant (`finishing` only with `recording` and a replace take, `recording` only with a take, `checking_from` and `restoring` only with `confirm_since`, never `settled_empty` with `loaded`, `missing_path` only with no `path` and not `loaded`) keeps the cases apart. Every case by every event is the table `buffer slot` (Machines, above).

### What a canceled take leaves (#311)

The engine leaves a canceled take's slot as the take left it (untouched before its preparation, empty after) and follows every cancel with the slot's length (`docs/notes/engine/record.md`, The state table). Lua decides from those reports only:
- `record_buffer` for a replace take stores what it replaces in `S.lib.record.state(slot).previous`: `S.lib.buffers.state_before_take(slot)`, the shown state (`M.shown_state`), or, while the engine still checks long loads, what the earliest of them replaced (the take supersedes every one, so none arrives), or an empty slot if one is no longer tracked. A take sent with a delay leaves `seconds` as it is (the engine keeps reporting the slot's audio until it prepares it); one without zeroes it.
- recordState `canceled` (the slot's newest recording), replace take: the slot shows empty and `kept_state = previous`; the next `bufferState` report of the slot applies it on audio (row 6 of the table: the slot was never prepared) and drops it on 0 s (row 7).
- `load_buffer` while a replace take is still armed, also one K3 has stopped whose "canceled" report has not arrived (it never recorded; the cancel and the load reach the engine in that order): the load's `previous` is `{after_cancel = true, kept = the take's previous}`; while the take records, or finishes after recording, the empty state as before.
- `bufferLoadFailed`: `resolve_previous` turns an `after_cancel` previous into `kept` when the slot's seconds (the length the engine reported after its `canceled`) are above 0 (row 9), else into the empty state with `settled_empty = "take"` (row 10).
- `bufferState` while a take stopped with K3 is still `armed` (`finishing`, phase `armed`): settles nothing.
- `record_buffer` refuses a playable recording while a load awaits the engine (`confirm_since`): `buf <n> loading` in the header, on every page (#455, #878).

### The file fields

## Long buffers

On the high tier a slot holds up to `S.performance.buffer_seconds` (60, 120 or 300 s). `record_duration` ranges up to it (its spec reads it at init) and `record_buffer` sends at most that. The engine checks a file longer than 16 s in a routine before the load takes effect: meanwhile the slot keeps its old audio and reports its old length. So `load_buffer` asks norns how long the file is (`audio.file_info(path)`: channels, frames, rate) and, when the engine will check it (`checked_before_load(path, start)`: a tier above 16 s, and more frames than 16 s at the server rate `NORNS_SAMPLE_RATE`, 48 kHz, counting only what the slot reads, as `loadSlot` does: the frames left after `start` x the file's rate, a start past the end reading the slot's length of the last frames, and at most `buffer_seconds` at the file's rate and the server's), and only while the `bufferState` poll runs, sets `checking_from` to the length shown before the load (#171). While it is set, `buffer_state_changed` stores each report but settles nothing until the load's own 0 s (the engine reports it first when the checked load takes effect, and names no load in its check meanwhile, #983), or, for a check a later load's failure gave back, the first report it acts on: that clears it and restarts `confirm_since`, and the load then settles as any load does (Must not break, above). The BUFFER page shows `...` for the length meanwhile. A clear, a new recording or another load clears it, and `buffer_load_failed` puts back the failed load's state, `checking_from` included (a short load that fails while a long one checks leaves the check running). A file `audio.file_info` cannot open (0 frames) is never marked: the engine rejects it at once.
- **Notice** (#317): the load starts `start_check_notice`, the slot's clock in the role `"notice"` (`S.lib.record.run_slot_clock`, its id in `buffer_record_clocks[slot]`, #870, `docs/notes/lua/record.md`), which a load, clear, recording and cleanup end, and the end of the check ends too. After `BUFFER_SETTLE.check_notice_seconds` (30 s) with `checking_load` still that load, the console says `buffer <n>: the engine is still checking <path> 30 s after the load; ...` and BUFFER flashes `buf <n> still checking K2:ld/clr` (the way out the player has, said where the player is, #904; 120 of the hint row's 128 px for `buf 8`), once; nothing else changes. Only the engine knows how its check ends: several long files restored at once are checked by interleaved routines in one sclang thread and all end at about the sum of their times, so a check can outlast any bound Lua picks. A late report of the load taking effect settles it as any load (a restore still counts in `buffers_restored`), a late failure report undoes it, and a load, clear or recording ends the wait. 3.2 put back what the slot held after 30 s instead, and a slow check then left Lua showing the old file (or an empty slot) over the new audio, with the wrong path in buffers.data. A check the engine never ends leaves the row at `...` until the player loads or clears the slot, as the notice says. 30 s is about 45 times a 300 s load on a desktop (0.4-0.65 s, `docs/notes/engine/files.md`). A failed later load that puts back an earlier check starts that check's notice again (`buffer_load_failed`).
- **Snapshots of a check** (#399): a later load's `previous` copies an earlier check (`checking_from`, `checking_load`, `confirm_since`). When a report ends the check, `buffer_state_changed` clears both fields in every tracked load's `previous` and gives it the new `confirm_since`, so if the later load then fails, the slot comes back as the earlier load awaiting its read: the next report of audio settles it (a full high-tier slot reports 300 s before and after; a given-back check would end at that report anyway, #983).
- **The server rate**: `checked_before_load`, `slot_file_seconds` and `lib/record.lua`'s rate check read `S.constants.NORNS_SAMPLE_RATE` (48 kHz), the one copy (#516). Lua cannot learn the engine's rate: `performance_active.data` holds the tier, lengths, grain count and reason, and the `bufferState` poll seconds only. norns runs JACK and scsynth at 48 kHz; a file Lua misjudges near the 16 s edge only shows `...` until the engine's first report, or loads as before. A load superseded during its check is dropped without a `bufferLoadFailed` report; a later load that fails leaves the checked one to apply, which is the state `buffer_load_failed` puts back. A remembered 300 s file restored on a 60 s tier loads its first 60 s (the engine caps the read), and the poll reports 60.

## The start point of a long file

`S.buffers[slot].start` (seconds into the slot's file, 0 for a new file) is sent with every load of the slot (`engine.loadBuffer(slot, path, start)`), kept in buffers.data and put back by a failed load (`buffer_state_before_load` and `apply_buffer_state` carry `start`, `sample_rate` and `file_seconds` with the rest). `sample_rate` and `file_seconds` come from `audio.file_info` at each load (nil for a file it cannot open, and after a take or a clear).
- The seconds a slot holds of a file are `S.lib.buffers.slot_file_seconds(sample_rate)`: the engine's slot is `buffer_seconds` of frames at the server rate and `loadSlot` reads at most that many frames (`slotFrames`), so a file above `NORNS_SAMPLE_RATE` keeps `buffer_seconds x 48000 / rate` of its own seconds (8 of 16 at 96 kHz); at or below it, and for a nil rate, `buffer_seconds` (#326). `S.lib.buffers.longest_start(file_seconds, sample_rate)` is `max(0, file_seconds - slot_file_seconds(sample_rate))`: a 60 s 96 kHz file starts up to 52 s on a 16 s slot, a 12 s one up to 4 s; files at 44.1 and 48 kHz keep `file_seconds - buffer_seconds`.
- `S.lib.buffers.set_start(slot, seconds)` clamps to `[0, longest_start(file_seconds, sample_rate)]` and reloads the file there `FILES.restart_seconds` (0.3 s) after the last call: one clock per slot, a clock helper's (#870: its handle in the local `start_reload_handles`, its id in `M.start_reload_clocks`, which the tests and the cleanup-order test read), restarted by each call, stopped by `load_buffer`, `clear_buffer` and `recording_started` (`S.lib.clocks.stop`: a detent that falls as the reload's wake is posted retires it, and it loads nothing), canceled at once by its cleanup step (`CLEANUP_ORDER.buffer_start_reload`), and cleared by the clock itself before it calls `load_buffer`. It does nothing for a file that fits the slot, for a slot with no file length, and while `S.lib.record.state(slot)` is non-nil.
- `S.lib.buffers.recording_started(slot, playable)` (lib/record.lua's `record_buffer` calls it after it sends `recordBuffer`, with the `playable` it computed) cancels the pending reload either way. A replace take (`playable` false or nil) sets the start to 0 and forgets `sample_rate` and `file_seconds`, since a take is at the server rate and has no file; a playable recording leaves all three, since the slot keeps the file's audio. Its "ended" report (`record_state_changed`, `docs/notes/lua/record.md`) sets them as a replace take does; its "canceled" report changes none of them.
- `buffer_state_before_load(slot)` keeps the slot's state during a playable recording, so a failed load restores the slot as it was; during a replace take the slot comes back empty, unless the take was still armed and the engine reported audio after "canceled" (it had not prepared the slot): then the state the take replaced comes back (`resolve_previous`).

`set_start` acts only in the file state (States, The file fields).

`sent_start` is the start of the load last sent for the slot. `set_start` writes `start` at once and reloads 0.3 s later, so during that wait `start` is ahead of the file the engine holds; a load's snapshot (`buffer_state_before_load`) records `sent_start`, so a failed start reload puts the previous start back (#245). It is 0 at init, after `clear_buffer`, a replace take (`recording_started(slot, false)`), a dub's "ended" report and `empty_buffer_state`; `load_buffer` sets it to the start it sends and `apply_buffer_state` to the state's start. `buffers.data` saves `start`. The `"buffer slots"` invariant states that `start == sent_start` unless a start reload is pending (`start_reload_clocks[slot]`). Everything that cancels a reload without sending it keeps that true: a playable recording starting inside the wait sets `start` back to `sent_start` (the new start was never loaded), and the cleanup step that cancels reloads does the same after `buffers.data` is saved, so a script exit inside the 0.3 s saves the new, untried start (the player's last choice), which the next launch then tries. A remembered file missing at startup sets both fields. Loads that fail out of order each put back the start recorded in their own snapshot, so the slot ends at the start of the oldest failed load's predecessor.

## Trim

`save_buffer_loop(slot)` (global) saves the loop region of the selected voice if it reads the slot, else of the lowest-numbered voice that does, else the whole slot (`engine.saveBufferRequest(slot, path, start, length, number, token)`, fractions), to `<audio>/strata/<YYYYMMDD-HHMMSS>-buf<n>-loop.wav` (`buffer_save_path(slot, "loop")`, with a counter when the name is in use). Its `pending_saves` entry has `loop = true`, so the result flashes `saved buf <n> loop`.

## Save results

`save_buffer(slot)` and `save_buffer_loop(slot)` return true when they send `saveBufferRequest`. A refusal returns false and a reason. The reasons are `"invalid"` for an invalid slot, `"busy"` during recording or finishing, `"loading"` while a file awaits confirmation, `"empty"` before the engine reports audio, and `"save queue full"` when the next save number would exceed the slot's outstanding window (#1090). A missing session receipt returns `"save unavailable"`. A missing engine receipt and a full queue flash in the header. A recovery clock that cannot start also refuses the save before numbering it and logs the reason. PARAMETERS shows `buffer <n> save queue full` as the save trigger's name while the window is full.

`send_save` checks admission before choosing a filename, numbering the save or dispatching it. `saves_sent` counts this Lua session’s admitted requests. SC keeps its legacy physical command count independently. `pending_saves` holds the outstanding records in send order, with each save's number, reserved path, loop flag and whole-save settings snapshot. The oldest outstanding number and the next three fit in the same window (`BUFFER_SETTLE.tracked_saves`, 4). A later result can leave a hole, but the window advances only when its oldest save reports success or failure. A writer that has yet to finish can hold its slot indefinitely. A missed terminal notification is recoverable (#1091). Other slots continue independently.

**Confirming saves within a session (#1091).** During the buffer-polls start step Lua creates a private receipt in tmpfs and opens it unbuffered. The files area opens the same inode and marks it ready. Lua then unlinks its name. A delayed raw poll can reach the replacement object after norns re-registers polls. The raw poll wakes a scan of the slot's four pending records. Its physical save number can differ from the Lua request when an external caller saves directly. Lua reads that record's full number and terminal status from its own open inode before copying send-time settings or flashing a result. A delayed old callback holds the retired session and cannot settle the new save.

A single clock runs while any slot has pending saves. Once a second it checks all four local cells per pending slot. A later completed save can settle while the oldest writer is still running. It sends at most one `requestSaveResult` per slot for its oldest unresolved request, after that request has had a second to finish. The engine can then republish a known outcome. Fast completions stop the clock without sending a query. Cleanup retires the clock and callback, closes the receipt and logs each unresolved path as unconfirmed. A WAV already published before a missed acknowledgment can survive with its original settings unconfirmed. Acknowledged settings follow the usual samples store.

`buffer_save_result(value)` (global) ignores NaN, infinities, negative and fractional values. Zero acknowledges binding. A numbered poll wakes slot `value % NUM_BUFFERS + 1`. The first complete matching receipt removes its entry and the console says `buffer <n> saved to <path>` or `buffer <n>: cannot save <path> (...)`; `saved buf <n>` flashes in BUFFER's hint row, or `buf <n> save failed` in the header on every page (#878; ending the hint row's flash), only when it is the slot's newest save (`number == saves_sent`), so an older save's late report, in either order, never replaces what the newer save shows. Loads, clears and recordings leave `pending_saves` alone: a report is about the file written, not what the slot holds now. Why the engine reports both outcomes is under Save results in `docs/notes/engine/files.md`.

The BUFFER page is in `docs/notes/lua/pages/buffer.md`, its arc rings in `docs/notes/lua/arc-pages.md`, grid page 4 (sources) in `docs/notes/lua/grid/pages/sources.md`.

## buffers.data

Location: `~/dust/data/strata/buffers.data` (`buffer_data_file()`).
- It sits in the scenes' folder, `S.lib.scenes.scene_data_dir`, which `buffer_data_file()` reads at call time.

`S.buffer_file` is what is known of the file in this session, as `S.scene_file` is for scenes.data (`docs/notes/lua/scenes.md`): `load_problem` (nil or `"unreadable"`: what the start's read found), `write_problem` (nil or `"not saved"`: the last write failed), `problem` (what SETUP reads, derived by the table's `__index` and never stored: `write_problem` if set, else `load_problem`; #868: one field held both, so a failed write and then a good one dropped the "kept as .bak" row while the backup stayed on the card; a test or layout state that assigns `problem` itself sets a plain field, which wins), `backup` (the name an unreadable file was kept under; nil while it is still in place), `text` (the bytes last written or found unchanged) and `save_clock` (the clock of the pending write, nil while none waits); the writer (`S.lib.side_files.writer`, #906) keeps those two in this table. SETUP lists a problem (`docs/notes/lua/pages/setup.md`).

Saving (`save_buffers_to_disk()`, true and `"written"` or `"unchanged"`, or false and why):
- writes `remembered_buffers()`, `{version = BUFFER_DATA_VERSION, paths = {[n] = S.buffers[n].path or S.buffers[n].missing_path or ""}, starts = {[n] = S.buffers[n].start}, settings = {[n] = S.lib.samples.stored_own(n)}}` (version 3, 3.7; a missing file keeps its start with its path; `settings[n]` is the slot's take's record when it holds a take on its scratch path and the record is not at its defaults, else `false`), through `S.lib.data_files.write` (`docs/notes/lua/data-files.md`): a checked `.part` renamed over the file, nothing written when it already holds the same bytes;
- per slot, the loaded file or scratch take, or a remembered file that was missing on start;
- on success: `text` is the bytes, `write_problem` cleared (and an `"unreadable"` `load_problem` with no backup, which the write replaced; one with a backup stays, so SETUP's backup row comes back), `S.buffer_autosave_blocked` false; `buffer paths saved to ...` is printed only for `"written"`;
- on failure: `write_problem = "not saved"`, `error: buffer paths not saved to <file> (<why>); the file is as it was`, and the file is as it was; the next change (or the exit) tries again, since `text` still holds the last good bytes.

When (#327):
- `remember()`, whenever the slots changed (the end of `buffer_display_changed()`, and the end of `buffer_state_changed` when something changed, which covers a take that settles): it returns at once unless `S.buffers_loaded` and not `S.buffer_autosave_blocked`, and when `encode(remembered_buffers())` equals `S.buffer_file.text`. So a load, a take's end, a clear and a failed load's undo are on disk 0.1 s later (or at exit); the periodic reports, the restore at start (`S.buffers_loaded` is still false) and `set_start`'s detents (they only call `request_redraw`; the reload they schedule writes) write nothing. The first change after a start compares with the file itself (`text` is nil), so it writes only if something differs.
- `cleanup()` writes the file after the scenes save (step 40, the writer's `save_now`, which cancels a timed write first and starts none after), but only once `load_buffers_from_disk()` has run in this session (`S.buffers_loaded`, set when it returns), so a start that failed before init's restore never overwrites the saved paths with empty slots (#72). With nothing new it writes nothing. Its untried start (a reload still waiting) is the one saved, as before.

Loading (`load_buffers_from_disk()`, from its start step `START_ORDER.buffers_load`, after the scenes load):
- resets `S.buffers_restored`, `S.buffer_autosave_blocked` and `S.buffer_file`'s `load_problem`, `write_problem` and `backup` first, and sets a file of a version outside `BUFFER_FORMAT_FLOOR` to `BUFFER_DATA_VERSION` aside;
- `load_buffer`s each non-empty path that `util.file_exists` at its start, clamped to `longest_start` of the file as it is now (its length and rate: a file replaced by a shorter one keeps its start inside it; a file with no `starts` loads every start from 0; a start that is not a finite number, including the `inf` and `nan` the reader reads as numbers, is 0), and marks the slot `restoring` until it settles (with audio, or empty as `settled_empty = "restore"`, which a late report of audio still adopts and counts);
- `S.buffers_restored` counts only the slots the poll then confirms holding audio.
- A path that exists but that the engine cannot load (unreadable, unsupported, empty or damaged) is reported by `bufferLoadFailed`. The slot goes back to empty and the path is not saved again.
- A path that does not exist (deleted, or on an unmounted drive) is not loaded. The slot stays empty, the console names it, and it is kept in `missing_path`.
- SETUP shows `buffers: k restored`, or `buffers: k ok, m missing` (m = slots with a `missing_path`; "restored" would not fit beside the missing count).

A bad file, handled as the scenes file is:
- it is read with `S.lib.data_files.read`, which parses `tab.save`'s layout and never runs the file as Lua (#464, `docs/notes/lua/data-files.md`);
- when it is unreadable (not that layout: `error loading buffers file: <why>`), has a version other than 1 or 2 or has no `paths` table, the file is moved to its first free backup name, `buffers.data.bak` then `.bak.2` ... `.bak.9` (shared helper `S.lib.scenes.move_aside_unloadable_file(data_file, label)`, defined in `lib/scenes.lua`, through `S.lib.data_files.set_aside`), and `S.buffer_file` records `load_problem = "unreadable"` and the backup;
- if the move fails (every name taken, or the rename), `S.buffer_autosave_blocked` stops `remember` and `cleanup()` from writing, and `backup` stays nil (SETUP: `buffers file unreadable`, `not saved over`);
- its start step then flashes `buffers unreadable (SETUP)` on the hint row for `S.lib.scenes.SCENE_LOAD.start_flash_seconds` (4 s), on whatever page comes up, or `data files unreadable (SETUP)` when the scenes file could not be read either, `data files not loaded (SETUP)` when it is an older Strata's (`"older"`) (this flash replaces the scenes').
