## Must not break

- A data file is parsed, never run (#464): `scenes.data` and `buffers.data` are read only through `S.lib.data_files.read`, which parses the layout norns' `tab.save` writes. Nothing in `strata.lua` or `lib/` uses `tab.load` or calls `loadfile`, `dofile`, `loadstring` or `load` (a structure test enforces it), since `tab.load` runs the file as a Lua chunk that sees every global (`os`, `io`, `_norns`), and `pcall` contains only an error, not what the chunk does or an endless loop.
- `decode` accepts exactly `tab.save`'s layout and raises nothing: any other text (code, a truncated file, a reference to a table the file does not hold, more than `DATA_FILES.max_tables` tables, a NaN key, text after the end) returns nil and a message naming the byte, and the caller treats the file as unloadable (kept as `.bak`, `docs/notes/lua/scenes.md`). `read` refuses a file over `DATA_FILES.max_bytes` (12 MB; 16 full scenes, every letter full, are about 3.3 MB) before reading it.
- What a hostile file can cost stays bounded: time in proportion to the text's length; at most `max_tables` tables (98304, about 9 MB however many the text asks for); a string costs its own text and its value, never a table per escape; and the entries cost what the value they build costs, at most about 8 times the text's length (32 MB for a 4 MB file of two million numbers in one table, measured on Lua 5.3, so about 96 MB at the 12 MB cap; `tab.load` builds the same). Keep each table made once, when it is first read or first named, never wrapped or linked afterward; never collect a part per escape or per entry.
- **The table cap keeps four times the largest scenes file** (#627, ruling 90): `DATA_FILES.largest_scenes_tables` (19474: 3.4's 7394 and 3.7's `sequences` block, five tables a scene, less the groundwork's 672, a format 10 voice being two tables where 3.7's was eight, plus its 96, the six LFO home routings a scene in the `matrix` block, plus 3.9's 128, the `lanes` block's eight tables a scene, the block and one a voice: `docs/notes/lua/lanes.md`, and plus 3.9's 12448, the `variations` block's 778 a scene with every letter full: the block, three a voice, and 36 for each of the three stored letters a voice, `docs/notes/lua/pattern-letters.md`) is the one place that names the tables of the largest scenes file this version writes. That file is 16 full scenes, with every step attribute, macro target, matrix routing, LFO home routing and lane length set and every letter of every voice full, 3,278,194 bytes as `test/unit/matrix_test.lua` writes it on Lua, 3,271,986 on LuaJIT (which prints some numbers shorter). `test/unit/matrix_test.lua` writes it and fails if it holds more; `test/unit/data_files_test.lua` fails unless `max_tables` is at least four times it. A file the reader refuses is set aside and its scenes do not load, so a release that adds scene tables raises both. Until 3.4's review the cap was 8192, 1.1 times the file; 32768 was 4.66 times the 7026 of 3.9's `lanes` block (3.8's file was 6898), and 3.9's letters tripled it to 98304, 5.05 times the file. `max_bytes` was 4 MB, 3.4 times that file's 1.25 MB, and is tripled to 12 MB, 3.8 times the file's 3.3 MB. The layout is flat (a table names another by number), so there is no depth to limit.
- Every file `tab.save` wrote reads to the value `tab.load` reads, number subtypes included on Lua 5.3, with shared and self-referencing tables kept as one table. A change to the parser keeps the round-trip test (`decode reads every layout tab.save writes ...`) passing on Lua 5.3 and LuaJIT, with its files written by the stub's `tab.save` (norns' lib/tabutil.lua, ported unchanged).
- A data file is written only through `write` (#301): the text goes to `<file>.part`, the open, write, flush, close and rename each checked, and the `.part` is renamed over the file only when every step worked; on any failure the `.part` is removed, the file is left as it was, and the caller is told why (it never says saved). Nothing in `strata.lua` or `lib/` uses `tab.save` (a structure test enforces it): it rewrites the file in place, so a failed write leaves it empty or cut short, and checks nothing.
- The two rules above cover every data file Strata keeps: `scenes.data`, `buffers.data`, 3.4's `macros.data`, `matrix.data` and `gestures.data` and 3.7's `sequences.data` (the live files in data/strata/, and each but `buffers.data` also beside a PSET, through `lib/side_files.lua`, below: the scenes since the groundwork before 3.8), `grids.data`, 3.5's `notes.data`, 3.6's `io.data`, 3.7's `samples.data` (a file's settings, `lib/samples.lua`) and 3.8's `factory.data` (the factory sets' marker, `lib/factory.lua`) and `voices.data` (the voice preset library, `lib/voice_presets.lua`: the player's, never a PSET's side file and never read or written by a factory load; an unusable one is set aside and never written over, `docs/notes/lua/voice-presets.md`). Each is read only through `read` and written only through `write`. A factory set's own files, in the script's folder, are read only: `index.data` and `set.samples.data` through `read`, its five side files through their modules' specs (`read_only`, below), and its `set.params`, a PSET's text and no data file, through `read_text` (`docs/notes/lua/factory.md`).
- `encode` gives the same bytes for the same value: each table's array part, then its other keys in a fixed order (numbers, strings, false, true, each ascending), tables numbered in the order first reached. `write`'s `"unchanged"` (no write when the file already holds those bytes) and `remember`'s comparison (`docs/notes/lua/buffers.md`) rely on it; never iterate with `pairs` into the text. The layout stays `tab.save`'s, so 3.2 (which reads with `tab.load`) reads what this writes.
- **Every data file's problem has one record** (3.9, #895, plan ruling 8, and 5f's review): `read`, `set_aside` and `write` keep what they found, by path, and `problems()` is the only reader (SETUP's rows); no caller sets or copies it, and a new data file needs nothing more than going through these calls to get its row. The two files whose modules keep their own record, `scenes.data` and `buffers.data` in Strata's data folder (`S.scene_file`, `S.buffer_file`), get none here (`own_records`): never a second record of one fact, which would disagree (a scenes file below the format floor parses and is set aside, so this module would record it with no cause, while its own record says older). Design section 8's "every data file" therefore reads "every data file no module records itself". A `set_aside` of a file this session wrote since its last read (a write that worked) records nothing (the scenes kept before a PSET load).
- A backup never replaces an earlier one (#466): `set_aside` takes the first free of `<file><suffix>`, `<file><suffix>.2` ... `.9` (`DATA_FILES.backups`), and refuses when every one is taken. Unreadable files, folders and symbolic links occupy their names. Only a lookup reporting no such entry makes a name available. Any other lookup error leaves the source in place.
- **The format floor** (3.7, design decision 21): a data file from its floor (`SCENE_FORMAT_FLOOR` 10 for scenes.data, 3.8's, `BUFFER_FORMAT_FLOOR` 2 for buffers.data) to the build's version loads, its missing fields filled from the defaults; one below the floor or above the build's version is set aside (`set_aside(file, ".bak")`) with one console line, and never overwritten. No copy of an older format is kept (3.7 deleted `keep_copy` and its `.v<n>` copies, #467).
- The call sites look `read` and `write` up at call time (`S.lib.data_files.read(...)`, `S.lib.data_files.write(...)`), so the start- and cleanup-steps structure tests can observe them.
- **The side files' rules are written once** (#648): the five modules with a live file and a file beside each PSET (the macros, the gestures, the matrix, the sequences and the scenes) make their PSET files with `S.lib.side_files.new(spec)` (`lib/side_files.lua`, below) and never read, set aside or write them themselves; the four but the scenes make their live files there too. The scenes' live file keeps its own writer, status rows and load prompt (`docs/notes/lua/scenes.md`; the groundwork's ruling 34). A rule about those files (a file that could be neither used nor set aside is never written over, #590; a factory set's file read under `read_only(fn)` is never set aside, 3.8; the PSET write always writes; one timed write per burst) is changed there, once, and its test is `test/unit/side_files_test.lua`; what each module's data is, how it validates and what an unknown id in it means stay the module's. **One debounced writer** (3.9, #906): every live file written after a change, `buffers.data` and `samples.data` too, times its write and writes at cleanup through `S.lib.side_files.writer(spec)` (below), never a clock of its own; only `scenes.data` keeps its own writer. The helper looks `read`, `write` and `set_aside` up at each call, as every call site does.

## Machines

### data files
- **State:** each file's own fields: the side files' `live.loaded` (`lib/side_files.lua`, the macros, matrix, gestures and sequences); the writer's `closed` (`S.lib.side_files.writer`, theirs and `buffers.data`'s and `samples.data`'s, 3.9, #906); `S.scenes_loaded`, `S.scene_autosave_blocked` and `S.scene_file`; `S.buffers_loaded`, `S.buffer_autosave_blocked` and `S.buffer_file`; `samples.data`'s and `voices.data`'s local `store.started` and `store.blocked`; `io.data`'s local `started`. `grids.data`, `notes.data` and `factory.data` keep no state of their file. Beside them (3.9, #895, plan ruling 8) `S.lib.data_files` keeps, by path, what its own `read`, `set_aside` and `write` last found, and `problems()` names every file with a problem (below); SETUP draws a row for each. It is the only record of a problem for every file but `scenes.data` and `buffers.data`, of which it keeps none: their `S.scene_file` and `S.buffer_file` are their records, and SETUP reads those.
- **Invariant:** none: a file's state is what its start step found, kept in the fields above, and no illegal combination of them is checked; each module's rules are its own (the table below).
- **Two facts:** a side file's `live.loaded` is false both before the start step read it and after a read that could neither use the file nor set it aside; either way nothing writes it, which is what the field guards, so the two are never told apart.
- **Test:** `test/unit/side_files_test.lua`: "side files: a live file that can be neither used nor set aside is never written over (#590)".

Six states every live file goes through (3.9, #948): unread, before its start step reads it; then what the read found, ok (its data loaded), missing (the defaults), set aside (unusable, renamed to `<file>.bak` with one console line, the defaults) or unusable in place (unusable and not renamed: one console line, the defaults); then closed, once the cleanup step has written it. From ok, missing or set aside a change the file holds writes it (ok); from unusable in place the file's own rule decides whether anything writes it in the session. No table: the rules differ by file and no test runs them (converging them is a design decision); each file's states are in Each file's states, below, a row a file and a column a state.

## lib/data_files.lua (`S.lib.data_files`)

Included just before `lib/buffers.lua`. It holds the reader and the writer of the data files and their backups.

- **`encode(value)`**: `tab.save`'s text for a table (norns' lib/tabutil.lua): `return {`, then per table reached from `value` a `-- Table: {n}` line and `{`, its entries one per line (`   value,` for the array part, `   [key]=value,` for the rest), `},`, and a closing `}`. A string is written through `%q` and a number or boolean through `tostring` (so a float keeps 14 significant digits, as `tab.save` writes it), a table value as `{n}`. The array part (`ipairs`) comes first, then the other keys: numbers ascending (a whole key inside the array part is not repeated), strings ascending, `false`, `true`; tables are numbered in the order first reached, so a shared table is written once. A function or userdata value and a table key are left out (Strata's data has none; `tab.save` leaves the first out). It raises for a value that is not a table.
- **`write(path, value)`**: `true, "unchanged"` when `read_text(path)` equals `encode(value)` (nothing is opened for writing); else `true, "written"` after the checked write to `path .. ".part"` and the rename over `path`; or `false` and the system's message (the `.part` removed, `path` untouched). The caller makes the folder. `buffers.data` and `samples.data` are written 0.1 s after the first change of a burst that asked for it (one clock per burst, carrying the newest state), or by cleanup, through the side files' writer (#566, #906; `docs/notes/lua/buffers.md`, `docs/notes/lua/samples.md`); `scenes.data` is written at each scene save.
- **`set_aside(path, suffix)`**: renames `path` to its first free backup name (`path .. suffix`, then `path .. suffix .. ".2"` ... `".9"`, a name taken by a file or a folder): that name, or nil and why (every name taken, or the rename failed; `path` is then still in place). A name is free when `util.file_exists` cannot open it for reading; a file there that cannot be read would count as free and be renamed over, which on a norns cannot happen, since one user (`we`) owns every file in the data folder.
- **`decode(text)`**: the value `text` holds, or nil and what is wrong (`"<what> at byte <n>"`). A scanner over `text` with a position:
  - between tokens, spaces, newlines and `--` comments to the end of the line;
  - a string from `"` to the next unescaped `"`, found without copying, then unescaped in one `gsub` over its text: the escapes `%q` writes on Lua 5.3 and LuaJIT (`\"`, `\\`, backslash-newline, one to three decimal digits up to 255) and older Lua's `\n` and `\r`; a raw newline or any other escape is an error;
  - `true`, `false`, and `inf`, `-inf`, `nan`, `-nan` (what `tostring` writes for those numbers: `tab.load` reads them as nil globals or raises, so they are new here; the callers judge them: `validate_scene` refuses any number that is not finite, and the buffers restore loads a start that is not finite from 0);
  - a number matched by `^%-?[%d%.]+[eE][%+%-]?%d+` or `^%-?[%d%.]+` and accepted only if `tonumber` takes it (so `3` stays an integer and `3.0` a float on Lua 5.3);
  - a table reference `{digits}`.
  - The grammar: `return`, `{`, tables each followed by `,`, `}`, then the end of the text. A table is `{`, entries each followed by `,`, `}`; an entry is `[key]=value` or `value`. A positional value takes the next index and wins over a keyed entry for the same index wherever that stands, as a table constructor sets them.
  - Table `n` is made when it is first read or first named by a reference, whichever comes first, so a reference is the table itself (it may name a later table, or its own) and nothing is linked afterward. A reference to a number above `max_tables`, or a table past it, fails at once; one to a table the file never holds fails at the end.
- **`read(path)`**: the value; or nil and `"missing"` when opening the path returns ENOENT (no such file or directory); or nil, `"unreadable"` and why (the system message for any other open error, a file larger than `max_bytes`, a read that fails, or `decode`'s message).
- **`read_text(path)`**: the file's bytes (binary mode, nothing changed), or nil when it cannot be read.
- **`problems()`** (3.9, #895): the files with a problem this session, in the order each was first read, written or set aside (the start steps read most of them first), each `{file = <path>, problem = <"not saved", "unreadable" or "set aside">, backup = <the name it was set aside under, or nil while in place>}` (a copy); never `scenes.data` or `buffers.data` in Strata's data folder (`own_records`, above). The record behind it, by path, is set only by this module's three calls: `read` sets it to `"unreadable"` in place when it could not parse the file, clears it for a value (a file that later reads well loses its row, as a scenes load clears `S.scene_file`), and for a missing file clears it unless the file was set aside, whose row stays while its backup is on the card (as a write keeps it, so a probe read such as `mark_holds_live` or a PSET reload drops no row); `set_aside` after a read keeps `"unreadable"` for a file that did not parse and sets `"set aside"` for one that did, naming no cause, since `set_aside` is passed none and the causes differ (its reader refused it whole, another version or a shape it checks, or, `voices.data`, kept its damaged presets aside while its good ones loaded, #848; SETUP shows ` set aside` or ` file not moved`, never a cause the file may not have), with the backup's name or in place when the move failed, and does nothing to a file this session wrote since its last read with a write that worked (the scenes kept before a PSET load are a file moved on purpose, not a problem; a failed write is no such write, so `voices.data`'s backup moved back after one is recorded again at the next set-aside); `write` sets `"not saved"` when it fails, and when it works ends that and a problem still in place (it wrote over the file), leaving a set-aside's row (#868's rule). The write's problem is listed before the read's. A factory set's file read under `read_only` that does not parse has a row too (in place); one its reader refuses after reading has none, since it is never set aside.
- **`DATA_FILES`** (`M.DATA_FILES`): `max_bytes`, 12 MB; `max_tables`, 98304; `largest_scenes_tables`, 19474 (Must not break, above); `backups`, 9 (the backup names per suffix).

A third, small file goes through the same `read` and `write`: `grids.data`, each grid port's rotation (`lib/grid/core.lua`'s `read_rotations` and `set_rotation`, `docs/notes/lua/grid-core.md`); a file it cannot use reads as rotation 0. So does a fourth (3.5): `notes.data`, `{version = 1, pool = <n>}`, the note pool (`lib/notes.lua`'s start step `notes_load` and `set_pool`, which writes before it sets, `docs/notes/lua/notes.md`); a file it cannot use gives the tier's default. Since the groundwork before 3.8 (ruling 35) each sets such a file aside (`set_aside(file, ".bak")`) at the read, as `io.data` does, with one console line ending `kept as <name>` or `not moved: <why>`; one that can be neither used nor set aside stays, and the next change writes over it. And a fifth (3.6): `io.data`, `{version = 1, values = {<key> = <value>, ...}}`, the rig settings (`lib/io/rig.lua`'s start step `io_rig`, `set`, which writes before it sets, and the cleanup step `io_rig_save`, `docs/notes/lua/io/rig.md`); a file it cannot use (unreadable, another version, a value out of its spec) is set aside (`set_aside(file, ".bak")`) with one console line and gives the defaults.

The callers: `read_scenes_file` (`lib/scenes.lua`, `docs/notes/lua/scenes.md`) and `restore_buffers_from_file` (`lib/buffers.lua`, `docs/notes/lua/buffers.md`) print `no saved ... file found` for `"missing"` and `error loading ... file: <why>` for anything that is not a table, then move the file aside (`set_aside(file, ".bak")`, through `S.lib.scenes.move_aside_unloadable_file`); so do a version below the floor or above the build's, and a shape their checks refuse. `save_scenes_to_disk` and `save_buffers_to_disk` write through `write`. When each file is written (at every scene save; whenever a slot's path or start changes) is in those notes.

Durability: Lua has no fsync. `flush` hands the bytes to the kernel and the rename replaces the old file; ext4 with its default options writes a renamed-over file's data out with the rename, so a power cut leaves the old file or the new one, never a short one (the card's filesystem was not checked on a device). Within the filesystem's commit interval after a save, a power cut can leave the previous file. A `.part` left by a crash is deleted by the engine's `deleteStaleParts` at a later start (`docs/notes/engine/files.md`).

Cost: `encode` gives the same bytes as #301's prototype but without its cache of key texts, which makes it about 25-30% slower on Lua 5.3: 3.9 ms against the prototype's 3.1 ms for a 190 KB value (1.5 against 1.4 ms on LuaJIT), timed on a desktop in the review. The prototype measured eight full scenes (about 97 KB) at about 2.4 ms for its `encode`, 2.2 ms for `tab.save` and 2.3 ms for a whole scene save (capture, encode, the comparison read and the write), so this code's scene save is about 3 ms on a desktop. A device is several times slower: some tens of milliseconds per scene save gesture.

Cost: decoding a scenes file of eight full scenes (about 97 KB) takes about 6 ms on a desktop with Lua 5.3, against about 1 ms for `tab.load` (a device is several times slower), once at start and once per `load scenes`. The largest file 3.4 writes (7394 tables, 1.02 MB; built as `matrix_test.lua` builds it) reads in 84-86 ms on Lua 5.3 and 28-34 ms on LuaJIT (`read`, CPU time, 14 runs each on a desktop, 3.4's review). Measured with the collector stopped, at 3.8's `max_tables` 32768 and `max_bytes` 4 MB (3.9's caps are three times both, so these costs are about three times as large; `data_files_test.lua` bounds the cost a table at the caps in force): 4 MB texts of empty tables, of one-entry tables or of one-reference tables give up at table 32769. They allocate 2.25, 2.75 and 2.75 MB on Lua 5.3 (72 to 88 bytes a table) in 30, 56 and 67 ms, and 2.26, 3.01 and 3.02 MB on LuaJIT in 8, 17 and 23 ms, so a hostile text costs less than the largest real file. A 4 MB string of `\0` escapes allocates about 6 MB (9 MB on LuaJIT).

Tests: `test/unit/data_files_test.lua` (the writer: `encode`'s layout against a literal and the same bytes for keys set in two orders, read back by the stub's `tab.load` and `decode`; `write`'s `"unchanged"` opening nothing, a write, flush or close that fails leaving the file byte for byte and no `.part`, a rename and a folder that fail; `set_aside` never replacing a backup and refusing when all nine names are taken. The reader: eleven texts that are code, a loop, a value built by a call, a missing reference, a truncated file, trailing code, an empty text and a binary chunk header, through `decode` and `read`, with nothing run; the round trip against the stub's `tab.save` and `tab.load`, and the `\n` and `\r` escapes by hand; `max_tables`, its margin over `largest_scenes_tables`, and the heap a hostile 4 MB text costs; `read`'s outcomes and `max_bytes`; a scenes and a buffers file holding code at start; 3.9's `problems()`: a file that later reads well, or is missing, loses its row, a missing read keeps a set-aside's row, a set-aside's backup (`set aside` for a file that parsed), a failed write, a write over an unreadable file, three files in the order first touched, a file kept on purpose after this session's write, and a failed write that does not make the next set-aside one). `test/unit/pages_setup_test.lua` draws the rows: a damaged `gestures.data` naming its backup; an unusable file under each of the three rules (`macros.data` never written, `scenes.data` by an explicit save, `grids.data` at the next change, whose row the rotation's write ends); a scenes file below the floor and an unreadable buffers file that leave `problems()` empty while SETUP says `older`; a partly damaged `voices.data`, `voices set aside` after a failed save and a good one; and side files of another version, `gestures set aside` moved and `macros file not moved` in place, naming no cause. `test/unit/structure_test.lua` checks that nothing in the script uses `tab.load`, `tab.save` or a chunk loader, and observes `write` in the cleanup steps and `read` in the start steps. The callers' tests are in `scenes_test.lua`, `buffers_test.lua` and `pages_setup_test.lua`.

Under every rule the file has its SETUP row while it is in place, and a set-aside one its row naming the backup: the scenes' and buffers' from their own fields (`S.lib.data_files` keeps no record of those two), every other file's from `S.lib.data_files.problems()`; under next change and explicit save the write that replaces the file ends its row (`write`, above).

## Side files: lib/side_files.lua (`S.lib.side_files`)

Included right after `lib/data_files.lua`, before its users (`lib/scenes.lua`, for its PSET file only, `lib/macros.lua`, `lib/gestures.lua`, `lib/random_sequences.lua`, `lib/matrix.lua`), #648. `new(spec)` gives one module's files: its live file `data/strata/<live_file>` and its side file `<path_base><side_suffix>` beside each PSET (the PSET's path without `.pset`), both `{version = <version>, [<key>] = <data>}`.

- **The spec**: `name` (the console's word, `macros`, and the PSET hook's name), `contents` (what the live line says will not be saved: `targets`), `version` and `key` (the layout above), `live_file`, `side_suffix`, `backup_suffix`, `capture()` (the data written, read at each write), `validate(data)` (what is wrong with a file's data, or nil; called only for a table of the right version, with its `[key]`, nil when the file has none), `load(data, path, silent)` (data nil for a missing file or one set aside; the path, so a module can name the file in its own console lines, as the macros and the matrix do for an unknown id at each file load; `silent`, a PSET read's flag), and, for a timed write, `save_delay` (s) with `clock_field` (the clock waits in `S[clock_field]`: `S.macro_save_clock`, `S.matrix_save_clock`, `S.gesture_save_clock`, `S.sequences_save_clock`), and an optional `floor` (a number no higher than `version`: a file from `floor` to `version` loads, the matrix's version 1 under its version 2; the groundwork before 3.8). `new` raises for a spec missing any of them, and for a floor above the version (`side_files.new: a floor is a number no higher than the version`).
- **`read(path, silent)`**: `S.lib.data_files.read`; a missing file loads nothing; an unreadable one (the reader's why), one that is no table of a version from the floor to `version`, a whole number (`not a version <version> <name> file`, or `not a version <floor>-<version> <name> file` when the floor is below the version; 2.5 or NaN is no version) or one `validate` refuses (its why) is set aside, `set_aside(path, backup_suffix)`, with one line `error loading <name> file <path>: <why>; kept as <backup>` (or `; not moved: <why>`) and loads nothing. Then `load`, whatever happened. Returns whether path may be written over: false only for a file that could be neither used nor set aside.
- **`write(path)`**: `S.lib.data_files.write(path, {version, [key] = capture()})`; a failure prints `error: <name> not saved to <path> (<why>)`. Returns whether it was written.
- **`load_live()`**, the start step's: `read` of the live file; the live file is loaded (may be written) only when it was read, missing or set aside, else one line says `<name>: <path> could not be read or moved aside; the <contents> will not be saved this session`, and neither the timed write nor `save_now` writes it in the session. Returns whether it loaded.
- **`save_live()`**: while the live file is loaded and no timed write waits, starts one clock that sleeps `save_delay` and writes the live file (making `data/strata/` first when it is missing), carrying the data as it is then: one write per burst. None starts once `save_now` has run (a later cleanup step may still change the data, as the gestures' stop of every recorder ends a recording, which that write already held as if it stopped then, #651). It raises for a spec without `save_delay`.
- **`save_now()`**, the cleanup step's: cancels the timed write (the one place it is canceled) and writes the live file at once, when it is loaded: the session's last write of it.
- **`read_only(fn)`** and **`reading_only()`** (3.8, 4d, ruling 50): `read_only` runs `fn` with a module flag set and puts it back as it found it after, an error in `fn` included (raised again with the traceback of where `fn` raised; a non-function `fn` raises), so a nested call leaves the outer one's flag set (#847). While it is set every `read` leaves an unusable file where it is: one line `error loading <name> file <path>: <why>; a factory file, never moved: skipped` (`SIDE_FILES.skipped`), the path stays writable, and `load(nil, path, silent)` runs as for a missing file (the macros and the matrix empty, the gestures cleared, the live scenes left). A factory set's five side files are read so, in the script's folder (`docs/notes/lua/factory.md`); the scenes' load also skips its backup and its mark then (`docs/notes/lua/scenes.md`).
- **`writer(spec)`** (3.9, #906): one live file's debounced writer, which `new`'s `save_live` and `save_now` run on and `lib/buffers.lua` and `lib/samples.lua` make for `buffers.data` and `samples.data`. The spec: `name` (a raised error's word), `path` (a string, or a function read at each write), `value()` (the whole table written, so each file keeps its own layout), `holder` and `clock_field` (the timed write's clock waits in `holder[clock_field]`: `S` and the side file's field, `S.buffer_file.save_clock`, the samples' local `store.save_clock`), `may_write()` (whether the file may be written now: the side files' `live.loaded`, `S.buffers_loaded` and not `S.buffer_autosave_blocked`, the samples' `store.started` and not `store.blocked`), and optionally `text_field` (`holder[text_field]` keeps the text last written, or found by the start step: `S.buffer_file.text`, `store.text`), `save_delay` (s) and `report(written, detail, path)` (after each write: the module's console line and SETUP's fields). It returns `write()` (at once, whatever `may_write` says, the path's folder made first: written and detail, as `S.lib.data_files.write`), `save()` (while `may_write`, the text differs and no clock waits, one clock that sleeps `save_delay` and writes if the file still may be written and its text still differs: one write per burst; none after `save_now`; it raises without `save_delay`) and `save_now()` (the cleanup step: the clock canceled, the one place it is, then `closed` set and the file written at once while `may_write`, even when the text is unchanged, so the cleanup steps' test sees the write; false otherwise). `writer` raises for a spec missing a required field.
- **`pset_hook(before_read, after_read, after_write, after_delete)`**: the record `S.register_pset_hook` takes, named `name`: its `write` always writes the side file (empty data too, so a PSET saved over never keeps an older one), then runs `after_write(written, path_base)`; its `read` runs `before_read(silent)`, `read(side file, silent)` and `after_read(silent)`; its `delete` removes the side file, then runs `after_delete(path_base)` (each of the four may be nil; the scenes pass the last two, to mark which PSET holds the live scenes).

What each module passes, and what it does around the calls (its redraws, what a PSET read stops or drops first, its start and cleanup step registrations), is in its notes: `docs/notes/lua/macros.md`, `docs/notes/lua/gestures.md`, `docs/notes/lua/matrix.md`, `docs/notes/lua/random-sequences.md`, `docs/notes/lua/scenes.md`.

Tests: `test/unit/side_files_test.lua`, with a probe spec: a missing file loading nothing, with no line; a file of the right version loading its data with the read's silent flag; five unusable files (not a data file, another version, no data, data `validate` refuses, a list) each set aside whole with its one line; a live file that can be neither used nor set aside never written over by the timed write or `save_now`, with its one line; a damaged live file set aside and saved normally afterward; `write`'s layout and a failed write's line; the timed write (none before `load_live`, one per burst after the delay with the newest data, the live folder made, `save_now` writing at once and leaving no clock, and no timed write after it); the PSET hook (an empty write, `before_read`, `load` and `after_read` in order with `silent`, the delete, `after_write` with the write's outcome and `after_delete` once the file is gone); the spec's checks; the writer (#906: no timed write while the file may not be written or its text is unchanged, one write a burst into the holder's clock with the text kept, a change undone or a file closed to writes inside the delay writing nothing, `write` at once, `save_now` canceling and writing, nothing after it, `save_now` writing nothing while the file may not be written, a failed write reported and keeping no text, the spec's checks); a floor (a file from its floor to its version loading, one below or above set aside with the range in its line, a floor equal to the version naming one version, a floor above the version refused, and a version that is no whole number set aside with or without a floor; `read_only`: a file never set aside, the flag cleared after an error, a nested call and an error's traceback). Each module's own files are tested in its test file.
