## Must not break

- A data file is parsed, never run (#464): `scenes.data` and `buffers.data` are read only through `S.lib.data_files.read`, which parses the layout norns' `tab.save` writes. Nothing in `strata.lua` or `lib/` uses `tab.load` or calls `loadfile`, `dofile`, `loadstring` or `load` (a structure test enforces it), since `tab.load` runs the file as a Lua chunk that sees every global (`os`, `io`, `_norns`), and `pcall` contains only an error, not what the chunk does or an endless loop.
- `decode` accepts exactly `tab.save`'s layout and raises nothing: any other text (code, a truncated file, a reference to a table the file does not hold, more than `DATA_FILES.max_tables` tables, a NaN key, text after the end) returns nil and a message naming the byte, and the caller treats the file as unloadable (kept as `.bak`, `docs/notes/lua/scenes.md`). `read` refuses a file over `DATA_FILES.max_bytes` (4 MB; eight full scenes are about 100 KB) before reading it.
- What a hostile file can cost stays bounded: time in proportion to the text's length; at most `max_tables` tables (8192, under 1 MB however many the text asks for); a string costs its own text and its value, never a table per escape; and the entries cost what the value they build costs, at most about 8 times the text's length (32 MB for a 4 MB file of two million numbers in one table, measured on Lua 5.3; `tab.load` builds the same). Keep each table made once, when it is first read or first named, never wrapped or linked afterward; never collect a part per escape or per entry.
- Every file `tab.save` wrote reads to the value `tab.load` reads, number subtypes included on Lua 5.3, with shared and self-referencing tables kept as one table. A change to the parser keeps the round-trip test (`decode reads every layout tab.save writes ...`) passing on Lua 5.3 and LuaJIT, with its files written by the stub's `tab.save` (norns' lib/tabutil.lua, ported unchanged).
- A data file is written only through `write` (#301): the text goes to `<file>.part`, the open, write, flush, close and rename each checked, and the `.part` is renamed over the file only when every step worked; on any failure the `.part` is removed, the file is left as it was, and the caller is told why (it never says saved). Nothing in `strata.lua` or `lib/` uses `tab.save` (a structure test enforces it): it rewrites the file in place, so a failed write leaves it empty or cut short, and checks nothing.
- `encode` gives the same bytes for the same value: each table's array part, then its other keys in a fixed order (numbers, strings, false, true, each ascending), tables numbered in the order first reached. `write`'s `"unchanged"` (no write when the file already holds those bytes) and `remember`'s comparison (`docs/notes/lua/buffers.md`) rely on it; never iterate with `pairs` into the text. The layout stays `tab.save`'s, so 3.2 (which reads with `tab.load`) reads what this writes.
- A backup never replaces an earlier one (#466): `set_aside` and `keep_copy` take the first free of `<file><suffix>`, `<file><suffix>.2` ... `.9` (`DATA_FILES.backups`), and find no name when every one is taken (`set_aside` then refuses, `keep_copy` copies nothing and returns `true, "full"` so its caller writes: copies of that format are kept already, and refusing would block every save of the session, the exit's included); `keep_copy` never touches the file it copies, so at every instant the data file is the old one or the new one, whole.
- The call sites look `read` and `write` up at call time (`S.lib.data_files.read(...)`, `S.lib.data_files.write(...)`), so the start- and cleanup-steps structure tests can observe them.

## lib/data_files.lua (`S.lib.data_files`)

Included just before `lib/buffers.lua`. It holds the reader and the writer of the two data files, their backups and the copies of an older format.

- **`encode(value)`**: `tab.save`'s text for a table (norns' lib/tabutil.lua): `return {`, then per table reached from `value` a `-- Table: {n}` line and `{`, its entries one per line (`   value,` for the array part, `   [key]=value,` for the rest), `},`, and a closing `}`. A string is written through `%q` and a number or boolean through `tostring` (so a float keeps 14 significant digits, as `tab.save` writes it), a table value as `{n}`. The array part (`ipairs`) comes first, then the other keys: numbers ascending (a whole key inside the array part is not repeated), strings ascending, `false`, `true`; tables are numbered in the order first reached, so a shared table is written once. A function or userdata value and a table key are left out (Strata's data has none; `tab.save` leaves the first out). It raises for a value that is not a table.
- **`write(path, value)`**: `true, "unchanged"` when `read_text(path)` equals `encode(value)` (nothing is opened for writing); else `true, "written"` after the checked write to `path .. ".part"` and the rename over `path`; or `false` and the system's message (the `.part` removed, `path` untouched). The caller makes the folder. `buffers.data`'s writer (`save_buffers_to_disk`) is called 0.1 s after the last change that asked for it, or by cleanup (#566; `docs/notes/lua/buffers.md`); `scenes.data` is written at each scene save.
- **`set_aside(path, suffix)`**: renames `path` to its first free backup name (`path .. suffix`, then `path .. suffix .. ".2"` ... `".9"`, a name taken by a file or a folder): that name, or nil and why (every name taken, or the rename failed; `path` is then still in place). A name is free when `util.file_exists` cannot open it for reading; a file there that cannot be read would count as free and be renamed over, which on a norns cannot happen, since one user (`we`) owns every file in the data folder.
- **`keep_copy(path, suffix)`**: copies `path` to its first free backup name, through a `.part` and a rename: that name and `"copied"`; or the name of a backup that already holds the same bytes and `"found"` (nothing copied again; the callers name the copy on the console only when it is `"copied"`); `true` when `path` has no file; `true` and `"full"` when every backup name is taken, after printing `<path>: every <suffix> copy name is taken (9 copies of that format are kept), so it is written over without another copy` (the callers write: copies of that format exist); or nil and why (the file cannot be read, the copy failed).

- **`decode(text)`**: the value `text` holds, or nil and what is wrong (`"<what> at byte <n>"`). A scanner over `text` with a position:
  - between tokens, spaces, newlines and `--` comments to the end of the line;
  - a string from `"` to the next unescaped `"`, found without copying, then unescaped in one `gsub` over its text: the escapes `%q` writes on Lua 5.3 and LuaJIT (`\"`, `\\`, backslash-newline, one to three decimal digits up to 255) and older Lua's `\n` and `\r`; a raw newline or any other escape is an error;
  - `true`, `false`, and `inf`, `-inf`, `nan`, `-nan` (what `tostring` writes for those numbers: `tab.load` reads them as nil globals or raises, so they are new here; the callers judge them: `validate_scene` refuses any number that is not finite, and the buffers restore loads a start that is not finite from 0);
  - a number matched by `^%-?[%d%.]+[eE][%+%-]?%d+` or `^%-?[%d%.]+` and accepted only if `tonumber` takes it (so `3` stays an integer and `3.0` a float on Lua 5.3);
  - a table reference `{digits}`.
  - The grammar: `return`, `{`, tables each followed by `,`, `}`, then the end of the text. A table is `{`, entries each followed by `,`, `}`; an entry is `[key]=value` or `value`. A positional value takes the next index and wins over a keyed entry for the same index wherever that stands, as a table constructor sets them.
  - Table `n` is made when it is first read or first named by a reference, whichever comes first, so a reference is the table itself (it may name a later table, or its own) and nothing is linked afterward. A reference to a number above `max_tables`, or a table past it, fails at once; one to a table the file never holds fails at the end.
- **`read(path)`**: the value; or nil and `"missing"` when the file cannot be opened (as `util.file_exists` decides); or nil, `"unreadable"` and why (larger than `max_bytes`, a read that fails, or `decode`'s message).
- **`read_text(path)`**: the file's bytes (binary mode, nothing changed), or nil when it cannot be read.
- **`DATA_FILES`** (`M.DATA_FILES`): `max_bytes`, 4 MB; `max_tables`, 8192 (a scenes file of eight full scenes holds 546 tables, so fifteen times that); `backups`, 9 (the backup names per suffix).

A third, small file goes through the same `read` and `write`: `grids.data`, each grid port's rotation (`lib/grid/core.lua`'s `read_rotations` and `set_rotation`, `docs/notes/lua/grid-core.md`); a file it cannot use reads as rotation 0 and is replaced at the next change, with no backup.

The callers: `read_scenes_file` (`lib/scenes.lua`, `docs/notes/lua/scenes.md`) and `restore_buffers_from_file` (`lib/buffers.lua`, `docs/notes/lua/buffers.md`) print `no saved ... file found` for `"missing"` and `error loading ... file: <why>` for anything that is not a table, then move the file aside (`set_aside(file, ".bak")`, through `S.lib.scenes.move_aside_unloadable_file`); their version and shape checks are unchanged. `save_scenes_to_disk` and `save_buffers_to_disk` write through `write`, after `keep_copy(file, ".v" .. version)` when the file read was of an older format (#467). When each file is written (at every scene save; whenever a slot's path or start changes) is in those notes.

Durability: Lua has no fsync. `flush` hands the bytes to the kernel and the rename replaces the old file; ext4 with its default options writes a renamed-over file's data out with the rename, so a power cut leaves the old file or the new one, never a short one (the card's filesystem was not checked on a device). Within the filesystem's commit interval after a save, a power cut can leave the previous file. A `.part` left by a crash is deleted by the engine's `deleteStaleParts` at a later start (`docs/notes/engine/files.md`).

Cost: `encode` gives the same bytes as #301's prototype but without its cache of key texts, which makes it about 25-30% slower on Lua 5.3: 3.9 ms against the prototype's 3.1 ms for a 190 KB value (1.5 against 1.4 ms on LuaJIT), timed on a desktop in the review. The prototype measured eight full scenes (about 97 KB) at about 2.4 ms for its `encode`, 2.2 ms for `tab.save` and 2.3 ms for a whole scene save (capture, encode, the comparison read and the write), so this code's scene save is about 3 ms on a desktop. A device is several times slower: some tens of milliseconds per scene save gesture.

Cost: decoding a scenes file of eight full scenes (about 97 KB) takes about 6 ms on a desktop with Lua 5.3, against about 1 ms for `tab.load` (a device is several times slower), once at start and once per `load scenes`. Measured on Lua 5.3 with the collector stopped: 4 MB texts of empty tables, of one-entry tables or of one-reference tables give up at table 8193 having allocated under 0.8 MB; a 4 MB string of `\0` escapes allocates about 6 MB (9 MB on LuaJIT).

Tests: `test/unit/data_files_test.lua` (the writer: `encode`'s layout against a literal and the same bytes for keys set in two orders, read back by the stub's `tab.load` and `decode`; `write`'s `"unchanged"` opening nothing, a write, flush or close that fails leaving the file byte for byte and no `.part`, a rename and a folder that fail; `set_aside` and `keep_copy` never replacing a backup, copying the same bytes once, `set_aside` refusing and `keep_copy` returning `true, "full"` (copying nothing) when all nine names are taken. The reader: eleven texts that are code, a loop, a value built by a call, a missing reference, a truncated file, trailing code, an empty text and a binary chunk header, through `decode` and `read`, with nothing run; the round trip against the stub's `tab.save` and `tab.load`, and the `\n` and `\r` escapes by hand; `max_tables` and the heap a hostile 4 MB text costs; `read`'s outcomes and `max_bytes`; a scenes and a buffers file holding code at start). `test/unit/structure_test.lua` checks that nothing in the script uses `tab.load`, `tab.save` or a chunk loader, and observes `write` in the cleanup steps and `read` in the start steps. The callers' tests are in `scenes_test.lua`, `buffers_test.lua` and `pages_setup_test.lua`.
