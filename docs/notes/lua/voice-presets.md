## Must not break

- **Every voice scene key is in or out** (design §8.1, ruling 48): `VOICE_PRESETS.keys` names every key of `S.lib.params_setup.voice_scene_keys(v, t)` that is no synth key, for every voice and every type, `true` (in) or `false` (out), and no other key; every type's synth keys (`synth = true`, `amp` and `pan` among them) are in by rule and never listed. A test fails on a key the table does not name, so a package that adds a voice scene key makes the choice. The rule: what shapes the sound whatever the voice reads is in; what names a place in audio, another voice, a running state, the rig or the pattern is out (`mod_speed` with the crossmod slots, the six `env_*` keys and `reverse` in).
- **`voices.data` is the player's library**: read at its start step (`START_ORDER.voice_presets_load`), written at each save and clear, only through `S.lib.data_files.read` and `write`; never a PSET's side file, never read or written by a factory load or at exit. Its version is compared only with `VOICE_PRESET_DATA_VERSION` and `VOICE_PRESET_FORMAT_FLOOR`.
- **An unusable `voices.data` is set aside, never written over**: unreadable, of a version outside the floor and this build's, or not `{version, presets = <table>}`, it goes to its first free backup name (`voices.data.bak`, ... `.bak.9`, never over an earlier backup) with one console line, and the library is empty; when every backup name is taken the file stays and every write is refused this session (a save or a clear returns false with a flash). A damaged preset (a name that is no printable string of at most `name_max`, a type that is no key, a value that is no finite number) is left out with one line; before the first write that would drop it, the file as read is set aside whole (`set_aside`, its first free backup name) and kept there only once the write lands (one line); a write that fails moves it back, so `voices.data` is as it was and the next write sets it aside again (#848). When no backup name is free that write is refused (false, a flash) as the blocked case is.
- **A load takes the sound and keeps the place**: the data it hands `S.lib.scenes.apply_voice` is, for each entry of `voice_scene_keys(v, preset.type)`, a synth key from the preset else the voice's remembered value (`S.voices[v].values`, which holds every type's keys); an in key from the preset else the voice's capture; an out key from the capture; `active` and `source` the voice's own; `type` the preset's. A preset key this build lacks is in no list and dropped. A preset of a type this build lacks loads nothing (false, one console line, a flash). A locked voice can be loaded into.
- **A load or a copy lets go of the voice in a running fade once it has applied** (`S.lib.scenes.release_voice`, `docs/notes/lua/scenes.md`), so neither the fade's later steps nor its landing pull the loaded sound back; the other voices land on the scene. The fade's steps run on its clock, so none comes between the apply and the release; a refused apply (a value out of its key's range, a type this build lacks) never lets go of the voice, which then lands with the fade. `copy(from, to)` is a load of `capture(from)`; a voice is never copied into itself.
- **A load into a spectral-frozen voice needs no case of its own**: the type param, VOICE's row and a scene show the new type at once, and the engine plays it at the unfreeze (`docs/notes/lua/types.md`); a load cancels the voice's pending type choice through its type entry (`apply_entries`, ruling 63), so the later act stands.
- **A load into a buffer, input or voice-source voice keeps the source** and takes the type for later: the engine records the type and its keys (0d's senders reach by type, so the type change's one sync sends them), and a switch to the synth source plays it.
- **The undo holds the sound only**: a load or a copy hands `S.lib.mutation.hold_voice` the voice's sound from before it (`sound_of` its capture: the type, its synth keys and the In keys), so the undo puts back what a load can change and leaves every Out key at its present value (ruling 46 as amended, `docs/notes/lua/mutation.md`).
- **A load names its preset; a copy names `v<n>`**: `loaded_name(v)` is what VOICE's `preset` row shows; it is not stored. A PSET read (the PSET hook `voice_presets`) and a scene recall (a `scene_recalled` hook: an instant recall, or a fade's first step) set every voice anew and clear every voice's name, so the row never names a sound the voice no longer has (#850); a load or a copy during a fade names its voice again. A factory set's load runs only its own PSET hooks and leaves the names.
- **Names are printable ASCII, cut to `name_max`** (`SCENE_NAME_MAX`, 12) at the save, as a scene's name is (`S.lib.scenes.set_name`).

## lib/voice_presets.lua (`S.lib.voice_presets`)

Fields: `VOICE_PRESETS` (`file`, `slots` 64, `name_max`, `backup_suffix`, `copy_prefix`, `texts`, `keys`), `capture(v) -> {type, values}` (the voice's capture filtered to its type's synth keys and the in keys), `load(v, slot) -> boolean`, `copy(from_voice, to_voice) -> boolean`, `preset(slot) -> {name, type} | nil`, `loaded_name(v) -> string | nil`, `save(v, slot, name) -> boolean, why`, `clear(slot) -> boolean`. No cleanup step: the file is written at each save and clear.

The file: `{version = 1, presets = {[slot] = {name, type, values}}}`, sparse by slot. A failed write leaves the slot as it was in memory too, with the hint row's flash `preset not saved` (VOICE's page).

Tests: `test/unit/voice_presets_test.lua`.
