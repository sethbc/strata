## Must not break

- Morph writes params and never recalls: it never calls `recall_scene` or `recall_scene_instant`, never starts a transition and never calls `clear_undo` itself (a param it sets ends the randomize undo through its own action, as any set does). This holds for the four corners as for two.
- Each continuous value is set through `S.lib.scenes.set_value(id, value)`, the setter a transition's step uses (a registered field's own `set`, a macro's silent one; otherwise `params:set`, or `set_binary_param` for a binary), never through `apply_entries`, and morph never sets `S.scene_recall_in_progress` for it. So a quantized voice's `freq` snaps to the scale as under a fade's step (the `freq` filter stands down only for a recall, `docs/notes/lua/variation.md`).
- The discrete entries switch through `S.lib.scenes.apply_entries(entries, {only = "discrete"})`, in recall order: voices that stop stop first, sources before their params, discrete extras after their source, blocks, voices that start start last, one sync per running voice whose source changed.
- **A corner counts only while its weight is above 0 (ruling 87).** An entry, continuous or discrete, joins an apply only when it differs among the counting corners (`counting_corners`) or the morph set it before (it then follows its blend, back to an edge too, never stranded at an interior value). So on an edge of the square the morph is the two-scene morph of that edge, value for value and entry for entry, whatever the other two corners hold: a hand change to something the edge's two corners agree on stays (the review's probe: at y 0 a hand-set `filter_freq` and a hand-started voice survive a move of `morph` with C and D saved and different). Inside the square all four count. At a corner point, where one corner alone weighs, its row's other corner counts too (its column's when that one is empty), so a corner point is the end of its row's two-scene morph: at y = 0, 0 and 1 are the ends of the morph between A and B (a first apply there sets what A and B differ in). The other edge through that point (x = 0 for A) is the reading's cost: arriving at (0, 0) along it, what A and B differ in joins.
- **At `morph_y` 0 the XY morph is the two-scene morph between A and B, value for value and entry for entry** (design §5.5, ruling 87): C and D weigh 0 there and do not count, a continuous value is `A + x × (B − A)` with the arithmetic of a transition step's `util.linlin(0, 1, A, B, x)` (bit for bit), the corner switches at 0.52 and 0.48, the first apply takes A below 0.5 and B from it, a ramp is A × (1 − 2x) and B × (2x − 1), and nothing A and B agree on is written. Every test of the two-scene morph (1g) but its params test (a group of six now) holds unchanged, with C and D empty, and the 3a test `at y 0 the XY morph is the two-scene morph` holds it with C and D populated and different.
- A continuous value is the weighted sum of the counting corners' values, computed as the first counting corner's value plus each other's weight times its difference from it (so on every edge its two-scene morph's arithmetic); a corner of weight exactly 1 gives its own value exactly, so a morph at rest at a corner holds that scene's exact values. A number param rounds to whole numbers, as a fade rounds it.
- A voice's loop pair (`loop_start`, `loop_length`, `lib/loops.lua`) is one unit of the round robin: written whole whenever either value is due, the start first, then the length. A recall sets the length first because the length's filter stands down while `S.scene_recall_in_progress` is set; morph's sets are a fade step's, with the filter on, so a length set first would be cut to the old start's room. The start's action cuts a length the new start leaves no room for, and the blended length, a blend of fitting pairs, always fits the blended start.
- The discrete entries take one corner, the current one (`state.applied.corner`). The first apply after a plan change (and after a recall, a PSET load or an error) takes the valid corner with the largest weight, a tie going to the later corner (d, c, b, a), so at y = 0 A below 0.5 and B from it, as §5.2. After that the corner changes only when another valid corner's weight leads the current one's by at least twice `MORPH.hysteresis` (0.04, within `MORPH.epsilon`), to the largest other, a tie going to the earlier corner (a, b, c, d): at y = 0 that is 0.52 and 0.48.
- The discrete entries an apply sets (`discrete_writes`, the corner's recall order): an entry the morph set before (`state.applied.owned`) when the corner changed from one that holds it otherwise; an entry it never set when it differs among the counting corners. Each becomes owned. An entry equal in every valid corner is never in the plan (ruling 26), so morph never touches it.
- Every apply writes inside one `S.lib.engine_sync.deferrable(fn)`, and `fn` never yields: the clock sleeps outside it.
- One clock, `S.morph_clock`, applies at most `MORPH.apply_hz` (10) times a second: the `morph` and `morph_y` actions only mark a move (and whether morph held the state then, the current scene and the scenes' takeover count) and start the clock if none runs. Its first apply is on the next scheduler tick, so a PSET load's hook can retire it before it applies, whether or not its resume was posted meanwhile.
- A recall or a fade that comes after the latest move wins: the move is dropped, never applied over it (`move_overtaken`). That includes a second recall of the scene current at the move (#584): the move notes `S.lib.scenes.takeovers()`, which every recall and every transition's start raises, and a move whose count changed is overtaken. A move made after a recall applies, starting again from the recalled state.
- At most `MORPH.max_values_per_apply` (120) continuous values per apply, round robin from where the last apply stopped (a loop pair whole or not at all), so a still morph converges within a few applies. A crossing's discrete switch, and its ramps' writes to 0, are applied whole, outside that count (they happen only when the corner changes; a block's ramps are few, the matrix's at most 16).
- **A crossing's discrete switch is applied whole, in recall order, and its uncounted part is outside the send budget** (#649, ruling 93; `docs/notes/lua/engine-sync.md`, The exception). Its voice starts and stops, source switches and the option actions that call the engine themselves go at once inside the apply's `deferrable`, uncounted, however full the window, as a recall's do. The uncounted burst, measured:
  - 1 engine message per running voice's envelope, grain mode or mod source;
  - 58 per running voice whose source switches;
  - 59 per voice that starts, 1 per voice that stops;
  - 14 for envelope and mode across seven voices, 417 when all seven start.

  Only its counted discrete entries (`docs/notes/lua/engine-sync.md` lists them) and its continuous values go through the budget, and they wait when the window is full.
- **A crossing's discrete switch is applied at most once per `MORPH.crossing_seconds` (0.3 s)** (#653, ruling 94):
  - **Immediate:** a single crossing still switches at once.
  - **Waiting:** an apply that finds a crossing within 0.3 s of the last one (`corner_now`) keeps the applied corner and marks the crossing waiting (`state.crossing_waits`). The continuous values still move on every apply, and a ramp stays on the old corner's group, which is at 0 there.
  - **The wait's end:** the corner the position calls for then is applied (`corner_at` at that apply), so the newest corner wins, and a crossing there and back inside the wait applies nothing. `corner()` answers the applied corner while a crossing waits.
  - **The clock:** the apply clock keeps ticking while a crossing waits; it holds no clock of its own, and the `morph clock` invariant counts the wait.
  - **Dropping:** a waiting crossing is dropped as a pending move is: by a recall or a fade since the last apply (`next_apply`), a PSET load and cleanup (`stop_clock`), a plan change and an error (`forget_applied`).
  - **Not bounded:** a recall, a transition's end, a PSET load and a first apply after them are not crossings.
  - **Why 0.3 s:** the heaviest sustained case is every crossing starting all seven voices (417 engine messages) and the way back stopping them (7). That is 424 messages each 0.6 s, about 707 a second. Swept across the crossing on every apply for 2 s (the test), the morph switches 7 times (1 + floor(2 / 0.3)), 4 starts and 3 stops: 1689 messages, 844 a second, where it switched 20 times, 4240 messages, before. A crossing of about 417 messages both ways (every running voice's source switched both ways) would be about 1390 a second.
  - **The total load:** these messages are uncounted, so they come on top of the send budget's counted 1500 a second, never inside it. The worst sustained load on sclang is the sum: about 2207 a second for the start and stop case, about 2890 for a crossing of 417 both ways (`docs/notes/lua/engine-sync.md`, The exception). Leaving voice starts and source switches outside the count, as the design has it, was the maintainer's decision (2026-11-12).
- While the morph moves, a value that moved less than `MORPH.send_threshold` (1/1000) of its param's range since morph last set it is skipped. The applies at rest set every value that moved at all, so a morph resting at a corner holds that scene's exact continuous values (still 120 an apply). A value that did not move is never due, so the clock stops once every value is on its blend.
- A block's ramp through 0 (its `through_zero`, design §10.2) is asked once per plan for each ordered pair of valid corners, `through_zero(X's value, Y's value)` for the switch from X to Y (with A and B only: A's to B's, then B's to A's), so each switch points at its own corner's value; `plan.named[X][Y]` holds the ids it names for the pair. **A ramp is between groups of corners, never between two corners that agree, and on its corners' lead (rulings 88 and 88a):** among the counting corners, those for which no pair names the id (a routing with the same source and destination) form a group. With G the current corner's group, m the largest weight among G's corners and w' the largest among the counting corners outside G, the value is `(sum over G of w × v) × max(0, m − w') / m`. It measures the lead corner against corner, as the corner rule does, and does not depend on which corner of G is the current one (moving between two corners that agree changes nothing). So two corners that differ give the current one's value times its lead (at y = 0 the two-scene ramp, A × (1 − 2x) and B × (2x − 1)); a routing every counting corner shares is its plain weighted mean (m − 0 over m is 1: along the A to C edge with A and C sharing it, 40 all the way, or a straight blend of their depths); just inside such an edge it stays near the mean and is continuous with it (B's routing differing, D empty: 39.40 at x 0.01, y 0.5, 39.94 at x 0.001). **The value is 0 wherever G can be left:** the corner rule switches only to the heaviest other corner (the largest weight, a tie going to the earlier corner; never a lighter one, even when two are past the lead at once), and a corner outside G that is the heaviest outweighs, or ties, every corner of G, so w' ≥ m there; the new group then starts at its value times the hysteresis's lead, as the two-scene morph does at 0.52. The sweep in the tests (A and C sharing lfo1 at 40, B on lfo2 at 60, D empty, y 0.5, x from 0 to 1 in steps of 0.01) finds A and C's depth at 0 from x 0.5 (where B's weight passes theirs) to the switch at 0.53, where B starts at 60 × 0.0408 = 2.45, the sweep's largest step; the largest other step is 1.78, from x 0.99 to 1, where B's depth, 60 (2x − 1) / (2 − x), is steepest. At a crossing from X to Y each id named for that pair that joins goes to 0 first, then its switch runs, then the discrete entries; an id the two share neither goes to 0 nor switches. The ids are written before any other value in every apply.
- An empty or invalid corner is left out: its weight is shared among the valid corners in proportion. Where every valid corner weighs 0 (a far edge or corner point whose own corners are empty) the weights are the limit from inside the square (`weights_of`: a factor at 0 counts as vanishing, the valid corners with the fewest such factors share by the product of their others), so along a far edge they follow x or y as along the near one (with only A and B saved, at y = 1, 1 − x and x; with only C and D saved, at y = 0, the same), and they are equal only at a corner point between two diagonal corners. With fewer than `MORPH.min_corners` (2) valid corners the plan is not ready: an apply flashes the first empty or invalid corner (A, B, C, D) by `S.lib.scenes.label` (`S5 empty`, `S5 dusk empty`; #641) once per plan and changes nothing.
- A PSET load never applies the morph: the PSET hook `morph` drops the apply the PSET's `morph` and `morph_y` lines started (ruling 24), and the loaded values stand. It retires the clock, never cancels it (#626): matron may have posted the clock's resume while Lua read the PSET, and norns' `clock.resume` raises on a canceled coroutine. The clock checks its token (`state.clock`) after each wait and, retired, ends at its next wake without applying or touching a newer clock. Only cleanup cancels it (the script is ending).
- The params `morph`, `morph_a` to `morph_d` and `morph_y` are never a scene field, an LFO destination or a macro target (`morph_y` is no LFO destination, so no macro target either; the matrix's destinations leave out `^morph`); the corners take their maximum from `NUM_SCENES`.
- **An LFO one scene has on and another off** (ruling 30): morph blends the LFO's rate, depth and offset toward the corners' stored values and switches the LFO on or off with the discrete entries, with no fade to 0, for four corners as for two (the same rule; below, Differences from a transition).

## Owns

`lib/morph.lua` (`S.lib.morph`, 3.4, packages 1g and 3a, design §5.1-§5.5):
- `add_params()`: the group `strata_morph` ("morph", `MORPH.param_count` 6) with `morph` (control 0-1, shown in whole percents, default 0), `morph_a` to `morph_d` (numbers 1..`NUM_SCENES`, defaults 1-4; menu names `morph A` ... `morph D`) and `morph_y` (control 0-1, percent, default 0). `lib/params_setup.lua`'s menu record `morph` calls it, after the LFOs and the macros.
- `plan_ready()`: whether at least two corners hold populated scenes that pass `validate_scene`.
- `weights()`: `a, b, c, d`, the corners' weights at the position now: A (1 − x)(1 − y), B x(1 − y), C (1 − x)y, D xy (x = `morph`, y = `morph_y`), an invalid corner's shared among the valid ones in proportion, the limit from inside the square where every valid corner weighs 0 (above); all 0 with no valid corner.
- `corner()`: `"a"` to `"d"`, the current discrete corner (the one the next apply takes at the position now, given the corner applied; `"a"` with no valid corner).
- `MORPH`, the module's one table of tunables (`apply_hz` 10, `hysteresis` 0.02, `max_values_per_apply` 120, `send_threshold` 1/1000, `epsilon`, `param_count` 6, `corners` `{"a", "b", "c", "d"}`, `min_corners` 2, `row_partner` and `column_partner`, `crossing_seconds` 0.3).
- `S.morph_clock`, the cleanup step `CLEANUP_ORDER.morph_clock` (112, cancels the clock, the one place that does, and drops the waiting apply), the PSET hook `morph` and the invariant `morph clock` (a move, a value left or a waiting crossing always has a clock, and the clock's coroutine is not dead).

Elsewhere: `S.lib.scenes.set_value` (`lib/scenes.lua`) is the scenes' own `set_scene_value`, exported for morph; `S.lib.scenes.takeovers()` counts recalls and transitions started (#584). The MOD page's rows `A`-`D`, `morph` and `y` are `lib/pages/mod.lua`'s; the 256's XY pad is `lib/grid/layout_256.lua`'s (`docs/notes/lua/grid/layout_256.md`).

## The plan

Built from the four slots `morph_a` to `morph_d` name, and rebuilt (lazily, at the next apply, `plan_ready`, `weights` or `corner`) when a corner's param or its slot's `S.lib.scenes.revision` changes (a capture, a save, a name, a load from disk):
- The valid corners (`plan.corners`, in a, b, c, d order).
- `scene_entries` of each valid corner's scene, paired by identity: a param by id, a block by key, a voice state (`active`, `lock`, `pattern`) by key and voice. An entry missing from a valid corner, or of another kind there, is left out.
- Continuous entries that differ between the valid corners, each with every valid corner's value, in the first valid corner's entry order (the round robin's order), as units: one value each, a voice's loop pair one unit (above; it joins an apply whole when either of it joins). Entries equal in every valid corner are left out, so morph never touches them; of the rest an apply writes only those that join (ruling 87: they differ among the corners counting there, or morph set them before), so with C and D valid an entry A and B agree on is still never written at y = 0.
- Per corner (`plan.discrete`), its discrete entries (blocks, discrete params, voice states, patterns) that differ from another valid corner's, in that scene's recall order, each with every valid corner's value; an apply picks those that join (`discrete_writes`, above).
- The ramps: every id a block's `through_zero` names for any ordered pair of valid corners (`plan.ramps`, `ramp_by_id`), kept whether or not the corners differ there (a routing that changes moves its old destination otherwise), with the ids named per pair (`named`, which makes the groups of ruling 88) and their switches per pair (`switches[from][to]`, `{id, switch}`). An id that is no continuous entry only switches.

## Applying

- The `morph` and `morph_y` actions set a move, note whether morph held the state (no scene current, no fade), the current scene and `S.lib.scenes.takeovers()`, and start the clock if none runs. The clock sleeps 0 (its first apply runs on the next tick), then, at each tick:
  - a move waiting that a recall or a fade overtook (morph held the state at the move but no longer does, the current scene changed since the move, or the takeover count changed since: a recall or fade started after it, even of the scene current then) is dropped;
  - a move waiting is applied with the 1/1000 threshold;
  - a crossing waiting (#653) when a recall or a fade took over since the last apply is dropped;
  - else, while nothing took over, an apply at rest (no threshold) runs while the last apply left values, a crossing waits (its wait ends at one of these applies), or a value of the current plan is off its exact blend;
  - else the clock stops.
  After each apply it sleeps 1 / `apply_hz`. So a fast turn is coalesced (100 moves over 1 s apply 11 times: at once, every 0.1 s, and once more for the last position), and the clock stops at the first tick that has nothing to set. A press on the 256's pad sets both axes at once: one move, one apply.
- An apply: build or reuse the plan; if a recall or a transition took over since the last apply (`S.current_scene ~= 0` or `S.scene_transition_active`: morph leaves no scene current), forget what was applied, so this apply starts again from the recalled state (the first apply's corner, every value due); `cancel_scene_transition()`, so the scene sequencer's wait moves on; the weights at the position and the corners counting there; inside `deferrable`, at a crossing the ramps named for the two corners at 0 and their switches, then the discrete entries that join (`apply_entries(those entries, {only = "discrete"})`), then up to 120 continuous values that join, each through `S.lib.scenes.set_value`; then `S.current_scene = 0`, `request_redraw()` and `grid_redraw()`.
- A recall while values are left stops the convergence: the next tick sees the recalled scene current and the clock ends without writing. A recall never moves the morph params; the next move applies from the recalled state, as above.
- A PSET load (the PSET hook `morph`, after norns has set every param) retires the clock (#626, above) and forgets what was applied: the PSET's values stand, and the next move starts again from them, on a clock of its own if the retired one has not woken yet.
- An error in an apply ends the clock (it forgets its own id first), forgets what was applied and is raised again with its traceback.

## Differences from a transition

- **An LFO one scene has on and another off** (known difference, ruling 30): a transition toward a scene that stops a running LFO fades that LFO's depth to 0 and holds its rate and offset (#408, `S.lib.lfos.transition_stops`). Morph has no such rule, with two corners or four: it blends the LFO's rate, depth and offset toward the corners' stored values and switches the LFO on or off when the corner changes (at y = 0, 0.52 or 0.48). Design §5 gives morph no rule for it, and one would need a helper from the LFO module.
- Morph ends nowhere: the discrete entries switch with the hysteresis, `S.current_scene` stays 0, and the result is params, which a save can store as a new scene (design §5.4).
- Morph sets a value only when it moved (past the threshold while moving, at all at rest); a fade sets every target at every step.
- A ramp's routing switches with the current discrete corner, as every discrete entry does; its depth measures the lead corner against corner (ruling 88a, above), so it is already 0 when the corner leaves its group and the switch never drops it (ruling 88's group totals did: A and C together could still lead B where B alone led A, and the depth fell from about 12 to 0 at the switch).
