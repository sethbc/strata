## Must not break

- **A type is only appended, never reordered.** The registry gives each record its `index` in include order (`strata.lua`'s `lib/types/<key>.lua` lines), the engine's type is `index - 1`, and the engine's `voiceTypeDefs` (`lib/engine/StrataVoices.sc`) lists the defs in the same order (a docs test, "the engine's voiceTypeDefs equal Lua's types in order"). `v<i>_type` is saved in PSETs by index, so a type moved or removed would turn every saved voice into another type. A new type appends its include line, its def to `voiceTypeDefs` and `noteMainRanges`, and nothing else in the list moves.
- **A synth key's sender reaches the engine only while the voice's type has it.** Every voice has every type's synth keys (`S.lib.types.keys()`), each with its sender, gated by the synth record's `reaches` (`S.lib.voices.is_synth_key`): a hidden key's `setVoiceParam` is never sent (the engine stub refuses a key the voice's def lacks), the send budget counts it as no message (`reaches_engine` false, so the LFOs' round robin skips it), and the voice's engine parts leave it out. A start, a sync and `voiceOn`'s pan follow the current type (a type without `pan` plays it at 0).
- **A scene's synth keys are its own type's.** A format 10 scene voice is `{active, source, type, values}`; `valid_voice_data` checks `values` against `voice_scene_keys(voice, type)`, the scene's type, never the voice's current one, so a scene is valid whatever type the voice has now (`docs/notes/lua/scenes.md`).
- **Every path that sets a voice's type cancels its pending choice**, even when it gives the type the voice already has, and the later act stands (ruling 63, P13 amended). norns' `Option:set` runs the `v<i>_type` action only on a change, so `S.lib.types.cancel` is called in five places: the action (any change: MIDI, the PARAMS menu), `S.lib.types.set` before its `params:set` (a grid's type key, a preset), `lib/scenes.lua`'s `apply_entry` for a type entry (a recall, a fade's landing, morph's discrete apply and `apply_voice`), `S.lib.params_setup.migrate_read_pset` for every voice after a PSET read, and `S.lib.factory`'s apply of a set's params for every voice, before its sets (`docs/notes/lua/factory.md`). A test sets each of `set`, `apply_entry` and `migrate_read_pset` to the current type over a pending turn.
- **Nothing reads a voice's type at include time.** `S.voices[i].name` and `param_order` are nil until the synth record's `add_first` sets them at init; the registry closes at init; a record whose `count`, `voice_keys` or `scene_defaults` is a function is checked at init (ruling 19); `first_field_row` returns 1 without reading the voice.
- **A key two types share has one spec and one format** (the registry refuses another), so one param serves both; its default may differ (a voice's default is its own type's, else the first type's that has the key).
- **A type change by hand keeps every other value**: the voice's attack and release, its freeze, its other synth keys (at whatever the voice last left them). It works on a locked voice, ends an undo holding one of the voice's synth keys, and no randomize or mutation draws `v<i>_type`.

## The registry (`lib/state.lua`)

`S.register_voice_type(record)`, kept in `S.registry.voice_types` (in type order), which closes at init (`INIT_READ`). The registry keeps a copy of the record, with `formats` filled in (`{}` when absent) and `index` set. The record's fields, exactly:

- `key`: `^[%w_]+$`, unique; the type's name in scenes and the docs (`"resonator"`).
- `name`: the option's text (`v<i>_type`'s options) and the voice heading's (`voice <i>: <name>`).
- `list_name`: at most 5 characters: MAIN's voice list, VOICE's voice line and a mod source's value.
- `def`: the engine def's name (`"strataResonator"`).
- `param_order`: its synth keys in display order, `freq` first, `amp` then `pan` (when it has one) last.
- `defaults`, `specs` (controlspecs) and `formats` (format strings, optional), by key of `param_order` and no other.
- `main = {key, label, format}`: MAIN's E3, its third field's label and value format, and arc ring 2 (`main_param_entry`).
- `note_main`: the key 3.5's per-note main expression moves (the engine's `noteMainRanges` entry for `def`; a docs test compares the range with `specs[note_main]`).
- `envelope = {attack, release}`: the attack and release defaults of a voice that starts on the type (`v<i>_attack`, `v<i>_release`, `lib/notes.lua`); a notes test compares them with the def's `attackTime` and `releaseTime` defaults, found by name in any engine file.

It refuses: a record that gives `index`; a field outside the set; a record without `freq` or `amp`, or with `freq` not first or `amp` and `pan` not last; a list name over 5 characters; a second record with the same key; a key of `param_order` with no default, no spec or a default outside its spec; a `main` or `note_main` that is no key of `param_order`; an envelope without both times; a key an earlier type has with another spec (`minval`, `maxval`, `warp`, `step`, `quantum`, `units`) or another format; any registration after init.

## The built-in types (`lib/types/<key>.lua`)

Twelve files, included right after `lib/types.lua` (itself after `lib/voices.lua`) in type order: `resonator`, `fm`, `folder`, `sub`, `pulse`, `karplus`, `ring` (3.7's seven voices, each with 3.7's keys, defaults, specs and formats; 3.7's `VOICE_PARAM_SPECS`, `SYNTH_FORMATS`, `MAIN_PARAMS` and `NOTES.envelope` are gone into them), then 3.8's `wave`, `additive`, `noise`, `saw`, `formant`. Each is a constructor that registers its record and returns an empty table (`S.lib.types_<key>`). A type added later is a file of its own (`lib/types/<key>.lua`, its tests `test/unit/types_<key>_test.lua`), an include line after the last, and its def appended to the engine's two lists.

## lib/types.lua (`S.lib.types`)

Read at each call, after init:
- `list()`: the records, in type order (a fresh list). `record(key)`: the record, or nil when this build lacks the type. `of(voice_idx)`: the voice's current record (nil for a number that is no voice, and before init). `default_key(voice_idx)`: the type voice `i` starts on, the `i`-th type (3.7's roster).
- `keys()`: every distinct synth key, in type order (each record's `param_order`, a key at its first type). `spec(key)`: a copy of the key's one spec (an unknown key errors, #315; `get_param_spec` keeps its name and reads it). `format(key)`.
- `set(voice_idx, key) -> boolean`: cancels the voice's pending choice and applies at once through `params:set("v<i>_type", index)`; false for an unknown key or voice.
- The type row's pending choice (ruling 63: one pending choice and one settle clock a voice): `turn(voice_idx, d)` moves it by `d` types from the pending one or the current type, clamped to the list, and restarts the voice's settle clock (`S.type_settle_clocks[voice]`, `TYPES.settle_seconds` 0.3); at rest the clock runs `flush`. `pending(voice_idx)`: its index, or nil. `flush(voice_idx)`: applies it at once (a choice turned back to the current type only ends). `cancel(voice_idx)`: forgets it and its clock. A voice pick (`S.lib.ui_keys.select_voice_by`), leaving VOICE (`set_ui_page`) and the voice's stop (an `S.register_voice_stop` hook) flush; cleanup (`CLEANUP_ORDER.type_settle`, 86) cancels every clock and applies nothing.

## The type param and every key on every voice (`lib/voices.lua`'s synth record)

- `v<i>_type`: an option over the records' `name`s in type order, default the voice's own type's index (`default_key`), added by the synth record's `add_first`, so it is the first param under the voice's heading, ahead of variation's `quantize`. A 3.7 PSET has no line for it, and the read hook's default gives each voice its old type (`docs/notes/lua/params.md`, the PSET read hook).
- Every voice has `v<i>_<key>` for every key of `keys()`: the default type's `param_order` first, then the rest in type order, so every 3.7.0 param keeps its place (the params fixture's allowances are generated from `S.lib.types`, so a type package adds none). Each default is the default type's, else the first type's that has the key (`v1_ratio` 1.5, `v7_ratio` 1.618, `v4_pan` 0); the formatter is the key's format. The current type's keys are shown and the rest hidden (`params:show`, `params:hide`); a hidden param is still saved in a PSET and still follows a MIDI map, and sends nothing.
- The action (`type_changed`): cancel the voice's pending choice; set `S.voices[i].name` and `param_order` (a copy); show and hide the keys and call `_menu.rebuild_params()`; rename the heading (`voice <i>: <name>`; its id stays the text it was added with); send `setVoiceType` always (`S.lib.engine_sync.send_voice_type`, the one caller of the command, also sent by a start right after `setGrainSource`); `note_param_edit` every synth key of the voice (an undo holding one ends); outside a scene recall, a running voice's `sync_voice_values_to_engine` (a recall syncs once after its last entry); the grid's fader page clamp; `update_voice_list()`, `request_redraw()`, `grid_redraw()`.
- The record's fields: `count` 1 + `#keys()`; `voice_keys` every key (static, so every key gets a sender at init); `reaches = is_synth_key`; `scene_keys = fn(voice_idx, type_key)` the type's `param_order` (nil: the current type; none for a type this build lacks); `voice_rows` the synth section (the current type's keys but amp and pan, a buffer voice's buffer params, none for input; `before = "mix"`); the fader, randomize and mutation groups read `param_order`, so they follow the type.

## VOICE, MAIN and the arc

- VOICE's first row is `{label = "type", param_id = "v<i>_type", section = "voice", kind = "type", selectable = true}`, with no label row above it (`lib/ui/voice_rows.lua`); `sections_of` (`lib/pages/voice.lua`) starts section `"voice"` at it, so K2 and K3 and the `<section> k/n` text count it. E3 and the arc's ring on it call `S.lib.types.turn` (the arc a step per 20 ticks), never the param: the pending name is drawn at level 4 until the settle applies it. ALT+K2 held resets it to the voice's own type (`set`); a quick press draws nothing there (the section has no draws). 3b's `preset` row joins section `"voice"`.
- MAIN's list shows each voice's `list_name`, and E3, the third field and arc ring 2 follow the current type's `main` (`docs/notes/lua/pages/main.md`). Everything aimed at `v<i>_main` resolves at each use (an LFO's home, a matrix routing, a macro target).
