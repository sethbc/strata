## Must not break

- Grid handlers live on the vport only (norns' `vports[port]`, through `attach_grid`). Never store the raw device passed to `grid.add`, and never set `key` on it.
- `grid_layout()` matches the exact `cols`/`rows`. Never test `rows >= 16`, which also catches 8×16.
- Anything the grid shows calls `grid_redraw()` when it changes, wherever it changes. It is cheap without a grid.
- A grid key repaints each grid once (#161): while `grid_key` handles a key, `grid_redraw()` calls from its actions return at once, and `grid_key` paints when the handler returns. The handler runs in an `xpcall`, so a failing key still repaints, the hold on redraws always ends, and the error is raised once, after the repaint. A release forgets its key (`release_key`, in an `xpcall` of its own) even when the layout's release handler or the step toggle raised (#620), so no key stays held and no later step key of its voice becomes a level key for it.
- A layout's redraw runs contained (#441): `grid_redraw` calls each grid's `layout.redraw` through `S.lib.ui_frame.contained_call` (keyed by port, so another grid of the same layout drawing well never clears the message), so a failing layout prints its traceback once per distinct message, its grid is still refreshed, the grids after it are drawn, and whoever asked for the redraw (`toggle_voice`, a param action, the pattern clock, a poll, the drift tick, a key) is never raised into. Each pane's page is contained again, per pane (`docs/notes/lua/grid/pane.md`).
- The grids follow every fader line and page signature they show (#324): the drift tick (`drift_update`, 10 Hz) calls `S.lib.grid_faders.follow_faders()`, which redraws the grids only when `S.lib.grid_pane.signature()` (each shown pane's view, its fader lines' positions and its page's `signature(pane)`) differs from its last look, so a param set on the screen, the arc, a MIDI map or in PARAMETERS reaches a grid within a tick and idle ticks repaint nothing; while no pane shows a fader line or a page with a signature it does nothing. Never go back to a redraw on every tick.
- A port's rotation (#323) is applied at every attach (`attach_grid`: `grid_port:rotation(n)`, norns' `Grid:rotation`, which reads the grid's rows and cols again and updates the vport) and changes only through `set_rotation`, which writes `grids.data` first (a failed write sets nothing) and then turns the grid and forgets the port. A grid whose size changes under an attached port with no add or remove (a rotation made outside Strata) starts over too (`follow_size`, before a key and before each redraw). `grids.data` is read through `S.lib.data_files.read` (parsed, never run) and written through `write`.
- The key levels every page shares come from the core (#526, #452): `voice_level`, `lock_level`, `play_level`, `M.LEVELS` (`S.constants.GRID_LEVELS`: the page and pick pairs, 3.8's `side_two`), `scene_recall_level`, `scene_fade_level` and `S.lib.grid_faders.fader_page_level`. A page never works out one of these levels itself, so one state lights alike on every grid.
- A grid page outside `lib/grid/` is named (`S.constants.GRID_PAGES`: `patterns`, `faders`, `scenes`, `sources`, `positions`, `voices`, `fx`, `count` 7, `names`, and `position_cells`, the 16 cells of a position line), never a bare number (#451; `grid_core_test.lua` refuses `any_page(<digit>` outside `lib/grid/`).
- Bounds-check every voice, step and grid coordinate before indexing `S.patterns`.
- Faders follow each controlspec's warp (`set_param_from_column`), and a range that spans 0 has a zero key that sets exactly 0, at 16 keys and at 8.
- **A voice's faders are its records' `fader` groups** (`fader_param_ids`, the groundwork before 3.8): sorted by `rank` stably, so 3.7's faders (the built-in records, rank 0) keep their order and pages and the newer ones follow them; a voice never has more than ten pages (the faders page's line 5 has ten page keys).
- **Pages are per port and pane** (3.8): `S.grid_panes[port][pane] = {page, side, half}`, read through `page(port, pane)`, `side`, `half` and `view` and set only through `set_page` and `set_half`; a check for a page shown anywhere uses `any_page(n)` or `any_page(n, side)`, and one for the FX page `any_fx_faders()` (`any_page(GRID_PAGES.fx)`). There is no global grid page. `set_page` accepts a page with no record yet (ruling 55), so outside tests keep their redraw gates; only the strips refuse one.
- **A page change ends only its own pane's keys** (ruling 54): `set_page` and `set_half` call `end_pane_keys(port, pane)`, which ends the step gestures, pending holds and roles of the keys the layout puts in that pane (`layout.pane_at`), never a strip key and never the other pane's, so fill, a tempo repeat, NV and a step held in the other pane go on.
- Held keys are per port: `S.grid_held[port][x][y]` holds the press time while a key is down. `grid_key` clears a key on its release; `grid.remove` and `grid.add` forget the port's held, consumed and step keys and its panes; cleanup forgets every port's. A forgotten port has no held keys' table (`S.grid_held[port]` nil, as a port never attached; a press makes it again).
- **A port's grid goes through one `detach(port)`** (#932): `grid.remove`, `reconcile_ports`' emptied vport and `detach_virtual` all call it, which clears the attached grid's `key`, its `S.grids` slot, `attached_devices[port]` and its noted size, then forgets the port (`forget_port`). Each caller adds only its own print and redraw.
- Every other per-grid state a page or the pane engine keeps lives in `port_state(port)` (a page's through `pane.state()`), never in a local or on `S`, so each grid has its own and it goes with the grid.
- Cleanup leaves nothing of Strata's on the devices (#468): the grids' step clears every attached vport's `key`, puts its grid back to rotation 0 (norns' `grid.cleanup()` keeps a rotation, so the next script would find a turned 128 as an 8x16; the port's setting stays in `grids.data`) before darkening it, and sets norns' own module's `add` and `remove` to no-ops (the arc's and MIDI's steps do the same for theirs), since norns' SLEEP runs only `cleanup()` before it shuts down, so a key pressed meanwhile would start a voice after the voices went off.
- A delayed key action goes through `on_hold`, never a clock of its own: a new press or the release of the key, a page change on its pane and `grid.remove` of its port stop its hold clock (`S.lib.clocks.stop`, which retires one whose wake may be posted, #870) and cleanup cancels it (`S.lib.clocks.cancel`), so a grid unplugged mid-hold, or turned to another page, never acts and no clock errors.
- **A release acts only for the key pressed in its role** (3.4): a key that acts at its release (a recorder key, NV) is recorded at its press with `press_as(port, x, y, role)` and acts at its release only when `pressed_as(port, x, y, role)`, so a key pressed on another page does nothing when it comes up on a cell that acts at release. A key's role goes with its release, a new press of it, a page change on its pane (`end_pane_keys`) and `forget_port`. The step keys keep their own record (`step_keys`) under the same rules.
- A grid moved to another port in SYSTEM > DEVICES gets no `grid.add` or `grid.remove` (norns' menu calls `update_devices()` only, `lua/core/menu/devices.lua`), so `reconcile_ports()` runs as the norns menu closes (a `S.register_menu_close` hook) and brings `S.grids` back in line with the vports (#256).
- Pattern keys go through `step_key` (a page's through `pane.step_key`), so the step-level gesture, the release toggle and the step editor's hold work the same everywhere. A step key toggles at its release (3.4, design §8.7), in the core's release path (`release_step_key`), never at its press and never in a page: unless it was consumed (by the level gesture, or by opening the step editor) or its gesture ended meanwhile. Gesture recorder keys go through `gesture_key` and light at `gesture_level`.
- **The step editor never outlives its key** (3.4, so a held step whose release never comes leaves no editor open): a step key held `GRID_HOLD.step_edit_seconds` opens it through `on_hold` (`S.lib.pages_seq.open_step_editor(voice, step, port)`; the key is consumed and recorded as `step_editor.key`), and every way the key's gesture ends closes it (`close_step_editor(port)`, through `drop_step_key`): the key's release, a press with no release before it, the end of the voice's step gestures (`replace_pattern`), its pane's keys ending (`end_pane_keys`: a page, side or half change, the 64's chooser opening), the end of the port's (`end_port_step_gestures`) and the port's `forget_port` (unplug, plug, the menu's reconcile, a rotation, cleanup). It closes only an editor still open for that port (`S.lib.pages_seq.step_editor()`), so a stale key never closes one opened elsewhere since. A level key's press stops the held step's pending editor hold. A dropped key's release toggles nothing and no later key takes it as held.
- **The editor's own replacements keep it open** (ruling 71): while `S.lib.pages_seq.step_editor_replacing()` is true (the SEQ page's: an action of the open editor, its `euclid` or `clear` row, its randomize or undo, is replacing the pattern), `end_step_gestures` keeps the key that opened the editor, so the editor stays open and the key's release still closes it and toggles nothing; every other step key of the voice ends as always. The core asks only while a grid key holds the editor open.
- Every freeze key calls `S.lib.freeze.toggle_quantized` (3.4, design §8.9), never `toggle`, so it waits for the beat or bar under `quantize_actions`.
- A voice's on/off key lights through `voice_level`: 12 running, 6 running and silenced (`S.lib.voice_mix.silenced`, design §8.14), 2 stopped. A stopped voice stays at 2 whether it is silenced or not.
- Every whole-pattern change ends the voice's step gestures (`end_step_gestures`, run by `S.lib.sequencer.replace_pattern`), and a page, side or half change ends its pane's (`end_pane_keys`), so a held step never takes a level, toggles or keeps the step editor open in a pattern, page or half it was not pressed in (#242).
- **Virtual grids (3.6's 0a)**: a grid that is no norns device (a remote grid, the midigrid mod's) attaches only through `S.lib.grid_core.attach_virtual(port, device)` on a port of `S.constants.GRID_PORTS` (`remote` 5, `midigrid` 6), above norns' four, and leaves through `detach_virtual(port)`. Ports 1 to `S.MAX_GRID_PORTS` take norns' own vports only (`norns_vport`, read from norns' module, never through `grid.connect`), so a mod that replaces `grid.connect` never puts a device on them. The loops that reconcile, rotate and count ports stay 1 to `S.MAX_GRID_PORTS`; every per-port check (`set_page`, `end_port_step_gestures`, the cleanup's `forget_port`, the "grid keys" invariant) takes a virtual port, and `grid_redraw`, `grid_key` and the cleanup's dark step walk `S.grids` as they do for any grid.
- **norns' own grid module, whatever a mod put in the global `grid`** (#700, `docs/design/3.6-facts/checks.md` §7): the midigrid mod replaces the global with a facade whose `connect` ignores the port and which has no `__newindex`. So for ports 1 to `S.MAX_GRID_PORTS` the core reads `vports[port]` of norns' module (`norns_grid()`: `package.loaded["core/grid"]`, what norns' startup's `grid = require 'core/grid'` loaded, found without naming a mod's field; the global where it is not found, as in the test stubs) and never calls `grid.connect` with a port, and it installs its hot-plug handlers on that module (`grid_added`, `grid_removed`, at include) and makes them no-ops there at cleanup. Never assign `grid.add`, `grid.remove` or read a port's vport through the global. Virtual ports are unchanged; 3.6's remote and midigrid attach call the global `grid.connect()` on purpose.
- The pane engine's rules are in `docs/notes/lua/grid/pane.md`, each page's in `docs/notes/lua/grid/pages/<page>.md`, each layout's spec in `docs/notes/lua/grid/layout_<size>.md`; the pattern sequencer's in `docs/notes/lua/sequencer.md`.

## Machines

### grid keys
- **State:** per port and key, `S.grid_held[port][x][y]` (`held`), the pending hold (`hold_clocks`, `hold_pending`), the consumed mark (`consumed_keys`, `consumed`), the role (`key_roles`, `pressed_as`) and the step gesture's entry (`step_keys`), all locals of `lib/grid/core.lua` but the first; the key that opened the step editor (`step_editor.key`) against SEQ's open editor (`S.lib.pages_seq.step_editor()`); per port, `S.grids[port]` and `attached_devices[port]` (States: the attached ports, below). The table follows one step key, whose state is read from `held`, `hold_pending`, `consumed` and the open editor.
- **Invariant:** `grid keys`: only a held key is a step key, consumed, waiting for a hold or held in a role (#930 added the step keys); the step editor's key is held, consumed and a held step (no level key); an open step editor has its key on the editor's port (the grid is its one opener while the script runs; an opening from Lua breaks this, as the SEQ page's own `layout_states` do, `lib/pages/seq.lua`'s "step editor v7 step 16", "a step with three notes" and "a step with eight notes", which call `open_step_editor(NUM_VOICES, PATTERN_LENGTH, 1)` with no key, and the tests that open it directly: a test that ends with an editor opened that way must close it or call `h.allow_broken_invariants`); a port has a device recorded exactly while it is attached, and no grid is on any other port.
- **Test:** `test/unit/grid_core_test.lua`: "grid keys: every cell is decided" and its rows (a 256 on port 1; the key is (5, 1), voice 1's step 5; the level key (8, 1); the page change sets pane 1 to scenes; the pattern replaced is voice 1's, through `S.lib.sequencer.replace_pattern`), and the invariant's own: "the grid keys invariant fails for a step key that is not held", "the grid keys invariant fails for a step editor key that is not a held, consumed step key" and "the grid keys invariant fails for an open step editor with no held, consumed step key on its port". The walk: `test/unit/grid_walk_test.lua` (3.9's package 3b), below.

Whether a held key is still a step key is no field a reader sees: `waiting` is a held step whose editor hold waits, `dropped` a held key whose gesture ended, and the rows that enter either release the key to show it (a held step's release toggles its step, a dropped key's nothing). Every cell is a row: no pair of these states and events is impossible.

**The grid walk** (`test/unit/grid_walk_test.lua`, an `h.walk` a layout: the 256, the 128h, the 128v and the 64, four seeds of 400 steps each) drives this machine at random on every layout, port 1. Its ops: a key down (any key the grid shows, on whatever page its pane shows, strip keys among them; now and then a key already down pressed again, a release that never came), a held key up, the clock advanced 0.05 to 0.6 s, a pane's page, side or (on the 64) half changed, the 64's chooser opened (NV held past its hold) and closed, a voice's pattern replaced (`S.lib.sequencer.replace_pattern`), the grid unplugged (and plugged back at the next key down), a rotation (`set_rotation`; a 128 turns between its two layouts). Its model keeps, per key the core holds, what its release does: toggle its step (a held step whose gesture stands), nothing (a level key, a consumed key, a dropped one) or end a hold (NV closes the chooser, FL lets fill go, a positions HD key lets its voice's scan go), from the rules above: a press of a voice with a held step sets that step's level, a held step's hold opens the editor 0.3 s on, NV's opens the chooser 0.5 s on and ends pane 1's keys, a pane's view changing ends its keys, a replacement ends its voice's, an unplug, a plug or a rotation forgets the port. It sees only when a pattern was replaced (it wraps `replace_pattern` and passes every call on), since a scene recall, CL, RN and a paste all go through it. After every op it compares the model with `S.patterns`, `S.grid_held[1]`, the open step editor and the 64's chooser, checks that a key whose pane's view changed waits for no hold and that a released key's hold, fill and scan hold ended, and every invariant runs; at the end every key goes up and, a second on, no hold clock lives (`hold_clocks`, `S.lib.clocks.retired`), no positions record holds a key, no voice's scan is held, no step editor and no chooser is open. Each walk must have reached a hold that fired, a hold a page change ended, an unplug with a key held, a step toggled, a level set and an HD key let go, and the 64's a release under the chooser, the others' a fill key let go. Two timed events of one clock op closer than 3 ms (the stub's tick is 1 ms) are left to the code's order: the model then takes the editor the code shows, if it is one of the keys it holds. A fault put back (one line, but the fill key's two) in `set_pane` (no `end_pane_keys`), the chooser's opening or closing, a fill key that never lets go (its `still` always true, its release gone), positions' `held_still`, an HD key's release, `stop_hold`, `forget_port`'s held keys, `release_step_key`'s consumed test or `replace_pattern`'s `end_step_gestures` each fails it.

## Device lifecycle

- `grid_init()`: reads `grids.data` (the rotations), then connects up to 4 grid ports at init (start step `START_ORDER.grids`).
- `grid_added(device)`: installed as `add` on norns' own grid module (`norns_grid()`, #700), which norns' hot-plug calls when a grid connects.
- `grid_key(port, x, y, z)`: norns' key callback (on the vport). It ignores a port with no grid and a key outside the grid, runs the press or release through the layout (`handle_key`) with `grid_redraw()` held (`key_repaint.handling`), then repaints every grid once and requests a screen redraw.
- `grid_removed(device)`: installed as `remove` on norns' own grid module, which norns' hot-plug calls when a grid disconnects. It detaches the port (`detach`: the vport's `key` handler, the `S.grids` slot, the recorded device and the size cleared, then `forget_port`): its pending holds are stopped, its held, consumed and step keys (its held keys' table goes), its `port_state` and its panes are dropped. `grid_added` forgets the port too, so a grid plugged in starts with no held keys, on its layout's start pages.
- `S.grids` stores the **vport** (norns' `vports[port]`, through `norns_vport`) of each connected grid, indexed by port (1-4). `grid_init`, `grid_added` and `reconcile_ports` go through `attach_grid(port)`, which also records the device the vport holds then (`attached_devices[port]`) and turns the grid to the port's rotation (`apply_rotation`, which notes the size it then reports).
- `S.lib.grid_core.reconcile_ports()`: SYSTEM > DEVICES moves a grid between ports through norns' `update_devices()` alone, which rewrites the vports' `device`, `cols` and `rows` and the device's `port` but calls neither `grid.add` nor `grid.remove`. So, as the norns menu closes (registered with `S.register_menu_close`), for each port 1..`S.MAX_GRID_PORTS`: a vport holding a device that is not attached, or another device than `attached_devices[port]`, is forgotten and attached, as `grid.add` does; an attached port whose vport is empty is detached (`detach`), as `grid.remove` does. Then `grid_redraw()` and `request_redraw()` (SETUP counts the grids). A grid moved from port 1 to 2 thus starts on port 2 with no held keys, on its start pages, and port 1 is no longer drawn.
- Why never the raw device: devices have no `.device` field (so `grid_redraw` would skip them), and norns fires both `device.key` and `vports[port].key`, so handlers on both would run every press twice. The arc uses the same vport-only pattern (`attach_arc`).
- `attach_virtual(port, device) -> boolean` (3.6): `port` one of `S.constants.GRID_PORTS`' values, `device` a table with whole-number `cols` and `rows` (at least 1), a truthy `device` field and the methods `led`, `all`, `refresh` and `rotation`; false for anything else, with nothing attached. It forgets the port's old state (and clears an old device's `key`), stores the device in `S.grids[port]` with `attached_devices[port] = device.device` and its size (so `follow_size` keeps it), sets `device.key` to call `grid_key(port, x, y, z)` and redraws the grids. Its layout is picked by its size, as for any grid; no rotation is applied at attach (cleanup still turns it to 0). `detach_virtual(port)`: `detach(port)`, as for any grid that goes (its held keys and holds forgotten, `S.grid_held[port]` nil, `device.key` cleared, the entry removed); any other port does nothing.

## Rotation

A monome 128 reports 16x8 (norns' matron reads its rows and cols once, at connect) until a script turns it: `Grid:rotation(n)` (`lua/core/grid.lua`) sets the rotation, reads rows and cols again and runs `update_devices()`, which copies them to the vport, so `grid_layout()` sees 8x16 with no change of its own. `grid.cleanup()` leaves a rotation in place, so a grid can arrive turned by an earlier script, and Strata's own cleanup puts every attached grid back to rotation 0 for the script that runs next.

- `GRID_ROTATION` (local): `file` `grids.data` in `_path.data .. "strata/"`, `version` 1, `last` 3, `settings[port]` (nil reads as 0), `sizes[port]` and `backup_suffix` (`".bak"`). The file holds `{version = 1, rotation = {r1, r2, r3, r4}}` in `tab.save`'s layout (`S.lib.data_files.encode`).
- `read_rotations()` (from `grid_init`, before any port is attached): a version-1 table's whole numbers 0-3 are the settings; any other entry, a missing file, one that does not parse or another version reads as 0. A file that fails whole (it does not parse, another version, no rotation table; not a version 1 file with bad entries, which keeps its good ones) is set aside (`set_aside(file, GRID_ROTATION.backup_suffix)`, as `io.data` is; the groundwork's ruling 35) with one line, `strata: grids.data not used (<why>): every grid rotation is 0; kept as grids.data.bak` (or `; not moved: <why>`); one that can be neither used nor set aside stays, and the next change writes over it.
- `rotation(port)`: 0-3. `set_rotation(port, n)`: false for a port outside 1..`S.MAX_GRID_PORTS` or `n` not a whole number 0-`MAX_ROTATION`; true at once when unchanged; else the four settings go to `S.lib.data_files.write` (the folder made first), false when it fails (nothing changes); then the setting is kept, a grid on the port is forgotten (`forget_port`) and turned (`apply_rotation`), and `grid_redraw()` and `request_redraw()` run. SETUP's rotation fields call it (`docs/notes/lua/pages/setup.md`).
- `follow_size(port, grid_port)`: when the grid's `cols`x`rows` is not `sizes[port]` (a rotation made outside Strata, or a grid moved in SYSTEM > DEVICES before the menu closes), the port is forgotten and the new size noted. `grid_key` runs it before the bounds check, `grid_redraw` before each grid's draw. `detach` (from `grid.remove`, `reconcile_ports` and `detach_virtual`) clears `sizes[port]`.

## Layouts

`grid_layout(grid_port)` matches the exact `cols`/`rows` (16x16 is tested as `cols == 16 and rows == 16`) and names the layout. `grid_key` and `grid_redraw` call that name's record in `S.registry.grid_layouts`: `{key, redraw, panes, pane_at, start_pages}`, made by `S.lib.grid_pane.arrange(spec)` from each layout file's spec (`docs/notes/lua/grid/pane.md`). A grid of any other size gets no keys and, between `all(0)` and `refresh()`, no LEDs.
- **16×16 (256 buttons)**: two panes, rows 1-7 and 9-15, the strips on rows 8 and 16 (`docs/notes/lua/grid/layout_256.md`).
- **16×8 (128 horizontal)**: one pane, its strip on row 8 (`docs/notes/lua/grid/layout_128h.md`).
- **8×16 (128 vertical)**: one pane turned, its strip down column 8 (`docs/notes/lua/grid/layout_128v.md`).
- **8×8 (64 buttons)**: a half of one pane, its small strip on row 8 (`docs/notes/lua/grid/layout_64.md`).

Several grids:
- Each grid's panes show and change their own pages; everything else (patterns, voice status, the fader page and voice) is shared.
- `grid_redraw()` iterates over `S.grids` and calls each grid's layout with its port: `redraw(port, grid_device)`.
- Held keys, holds and the step-level gesture are per port: a step held on one grid never sets levels from another.

## Pages, held keys and holds

- `grid_key(port, x, y, z)` ignores events outside the grid's size. A press sets `S.grid_held[port][x][y] = util.time()` (and forgets any earlier state of that key, for a press with no release before it: its step gesture ends through `drop_step_key`), then calls the layout's `key(port, x, y, 1)`. A release stops the key's pending hold, calls `key(port, x, y, 0)` unless the key was consumed, toggles a held step's step (`release_step_key`, below), then clears the key (held, consumed, step key, closing a step editor it opened), also when the layout or the toggle raised. Either way it redraws the grid and requests a screen redraw.
- `page(port, pane)`, `side(port, pane)`, `half(port, pane)` (pane defaults to 1): what `S.grid_panes[port][pane]` holds, or for a pane with no entry its layout's `start_pages[pane]` (patterns for a port with no layout, and for a start page with no record yet), side 1, half 1. `view(port, pane)` is `"<pane>:<page>:<side>:<half>"`, a string a press record keeps to know whether its pane still shows what it was pressed on.
- `set_page(port, page, pane, side)` (pane and side default to 1): refused for a port that is not one of norns' 1..`MAX_GRID_PORTS` or a virtual one (`S.constants.GRID_PORTS`), a page outside 1..`GRID_PAGES.count` (`MAX_GRID_PAGES`), a pane the grid has not (`layout.panes`, 1 with no grid) and a side the page has not (its record's `sides`, 1 for a page with no record). A page with no record is accepted and drawn dark. `set_half(port, pane, half)`: half 1 or 2 (the 64's chooser). A change of page, side or half ends the pane's keys (`end_pane_keys`); the half is kept across a page change.
- `end_pane_keys(port, pane)`: for each key of the port the layout puts in that pane (`layout.pane_at(x, y) == pane`), its step gesture ends (`drop_step_key`), its pending hold is stopped and its role forgotten; the keys stay held, consumed marks stay. A strip key (`pane_at` nil) is never touched. `end_port_holds(port)` and `end_port_step_gestures(port)` end every key of the port, for `forget_port` and for a port check.
- `any_page(page, side)` is true while any pane of any connected grid with a layout shows the page (and the side, when given): `buffer_state_changed` (page 4, and page 5's side 2, its record keys), the playheads' clock and the waveforms' peaks read (page 5) and the FX params' actions (page 7, through `any_fx_faders()`) redraw only then. `layout_of(port)` is the layout record of the grid connected to the port (nil for no grid or a size with no layout).
- `held(port, x, y)`: the press time of a held key, or nil.
- `on_hold(port, x, y, seconds, fn)`: for a held key, a clock of the helper (`S.lib.clocks.run`; `hold_clocks` keeps its handle) that sleeps `seconds` and runs `fn` once unless it was stopped. A new press or the release of the key, a page change on its pane (`end_pane_keys`) and `grid.remove` of the port stop it (`S.lib.clocks.stop`: one stopped as its wake is posted is retired, its sleep returns false and `fn` never runs); cleanup cancels it. `hold_pending(port, x, y)` is true while it waits. A hold may arm itself again from `fn` (the tempo keys' repeat).
- `consume(port, x, y)` marks a held key so its release does nothing; `consumed` reads it. The mark goes with the release.
- `port_state(port)`: a table for a page's or the pane engine's per-port state, created on demand and dropped when the port's grid is removed. `existing_port_state(port)` returns that table, or nil when the port has none, and never creates one: an invariant, or a check on a port whose grid may have left, reads through it.
- **Step keys** (`step_key(port, x, y, z, voice, step, position, positions)`, 3.4's release toggle and step editor, design §8.7): on press, if the voice has a held step on the same port (a key pressed through `step_key` that is not a level key), that step gets `level_for_position(position, positions)` = `max(1, round(position * MAX_STEP_LEVEL / positions))`, both keys are consumed and the held step's pending editor hold is stopped; the pressed key never toggles and is a level key while held, never taking a level itself. Otherwise the key becomes the voice's held step, toggling nothing yet, and arms `on_hold(port, x, y, GRID_HOLD.step_edit_seconds, ...)`. Its release (the core's `release_step_key`, whatever the page does with `z == 0`; `step_key` itself ignores it) toggles the step unless the key was consumed or its gesture ended. Held `step_edit_seconds` (0.3 s), it opens the step editor (`S.lib.pages_seq.open_step_editor(voice, step, port)`, the SEQ page's; on true the key is consumed and becomes `step_editor.key`); its release closes it (`close_step_editor(port)`) and toggles nothing. A voice has at most one held step on a port (#450), whichever pane its keys are in: every further key of the voice sets that step's level for as long as it stays down (`held_step` finds it), also while the editor is open. `end_step_gestures(voice)` ends the gesture on that voice's step keys on every port (they stay held; their releases do nothing; the next step key of the voice is a held step of its own): `S.lib.sequencer.replace_pattern` calls it, so a step held from before a clear, a randomize, a paste, a scene recall or a chain link never takes a level in the new pattern, never toggles and closes the editor it opened. A voice, step or position out of range (not a whole number in 1..`NUM_VOICES`, 1..`PATTERN_LENGTH`, 1..`positions`) does nothing. A page passes the key's pane coordinates through `pane.step_key`, whose `position` is the key's place among the pane's shown columns: 16 positions on a full pane, 8 on a 64's half.
- **The step editor's interface** (the SEQ page's, `S.lib.pages_seq`): the core calls `open_step_editor(voice, step, port)` (true when it opened; it pushes the editor as the screen's modal owner) and `close_step_editor(port)`, directly. It keeps the key that opened the editor itself (`step_editor.key`, replaced when another key opens it, so an older key's release closes nothing), reads `step_editor()` only to check the editor is still that port's before closing it and `step_editor_replacing()` only in `end_step_gestures` (ruling 71), and never asks whether the editor edited anything: a key whose editor opened never toggles, edited or not. The grid tests run held steps against the real editor (#630; `h.shown_step_editor()`, in `test/helpers.lua`, reads what it has open) and reach its states through its own controls: an edit by E3, a replacement of its own by its euclid row (ruling 67, ruling 71), a close on the screen by K2.
- **Gesture recorder keys** (`gesture_key(port, x, y, z, k)`, 3.4, design §7.2, ruling 73; a page's through `pane.gesture_key`): they act at their release. A release before `SHARED_KEYS.gesture_clear_seconds` (0.5 s, `GRID_HOLD.action_hold_seconds`) is `S.lib.gestures.press(k)`; the hold (`on_hold`) clears the recorder (`S.lib.gestures.clear(k)`, which redraws) and consumes the key, so its release does nothing and a clear never plays, records or ends another recorder's recording first. Only a key pressed as that recorder's key (`press_as`, `"gesture <k>"`) acts at its release, so a key pressed on another page, a release the core never saw pressed and a recorder outside 1..`NUM_GESTURES` do nothing. `gesture_level(k)`: empty 2, stopped 5, playing 10, recording 15. The scenes page has them (its package's).
- **Source and slot keys**: `source_key(voice, option)` sets `v<voice>_source` for option 1..`#SOURCE_OPTIONS` (anything else, or a voice outside 1..`NUM_VOICES`, is ignored); `source_level(voice, option)` is 15 for the selected source, 2 for a free buffer (`S.lib.buffers.is_free(slot)`: status `"empty"` or `"missing"`, the answer the fill and BUFFER share; a named load the engine has not reported yet is 4, #247), 4 otherwise. `record_key(slot)`/`clear_key(slot)` call `record_buffer`/`clear_buffer` for slots 1..`NUM_BUFFERS`; `record_level(slot)` reads the slot's `S.lib.buffers.status`, so both keys give one answer: 11 `"armed"`, 15 `"recording"`, `"dub"`, `"loop"` and `"finishing"` (an armed replace take stopped with K3 is 15 until its canceled report), 2 when `is_free`, else 8 (loading, loaded, or a named load the engine has not reported yet, #247); `CLEAR_LEVEL` is 4. Out-of-range levels are 0.

## States: the step-level gesture

The gesture's state is `step_keys[port][x][y]` (local to `lib/grid/core.lua`): `{voice, step, level_key}` for a key pressed through `step_key` and still held, alongside `S.grid_held[port][x][y]` (the press time), the key's pending editor hold (`hold_clocks`), its consumed mark and `step_editor.key` (the key that opened the step editor, or nil). It registers no invariant of its own: the `grid keys` invariant (Machines, above) checks that every step key, consumed or pending key is held, that `step_editor.key` is a held, consumed held step and that an open editor has its key on its port.

| State of a key | Fields | Meaning |
|----------------|--------|---------|
| Not a step key | `step_keys[port][x][y]` nil | Not held, or held but outside the gesture (ended, or pressed through no `step_key`); its release toggles nothing; a step key of its voice pressed now is a held step of its own |
| Held step, waiting | entry with `level_key` nil, its editor hold pending, not consumed | At most one per voice on a port; its release (within 0.3 s) toggles its step |
| Held step, leveled | the same entry, consumed (by a level key), hold stopped | It took a level key's level; its release toggles nothing |
| Held step, editing | the same entry, consumed, `step_editor.key` naming it | The step editor is open for it; its release closes the editor and toggles nothing |
| Level key | entry with `level_key = true` (and consumed) | Set a held step's level; never takes a level itself |

An entry exists only while its key is held (every release and press clears it). One function per transition:

| Transition | Function |
|------------|----------|
| A step key pressed: the voice's held step (its editor hold armed), or a level key that sets the held step's level (and stops its editor hold) | `step_key` |
| A held step held `step_edit_seconds`: the editor opens, the key is consumed | `open_step_editor` (the hold's action) |
| A key released: its step toggles unless consumed; the entry goes, closing the editor it opened | `release_step_key`, then `release_key` (`drop_step_key`) |
| A key pressed again with no release seen: the old entry goes, closing its editor | `press_key` (`drop_step_key`) |
| The voice's pattern replaced: its entries on every port go (holds stopped, editor closed) | `end_step_gestures(voice)`, from `S.lib.sequencer.replace_pattern` |
| A page, side or half change on a pane, or the 64's chooser opening: the pane's entries go | `end_pane_keys(port, pane)`, from `set_page`, `set_half` and the pane engine |
| The port's grid added or removed (also through `reconcile_ports` as the menu closes), a rotation, cleanup: the editor a key of the port opened closes | `forget_port` |

## States: the attached ports

A port's attachment is `S.grids[port]` (the vport, or nil) with `attached_devices[port]` (the device it held when attached), against what the vport holds now (`norns_vport(port).device`). The `attached_devices[port]` entry exists exactly while the port is attached: `attach_grid` sets it, `detach` (from `grid_removed`, `reconcile_ports` and `detach_virtual`) clears it, and the `grid keys` invariant checks it. Nothing checks the vports against the attachment: they change under the script, inside norns' menu, so the two disagree while the menu is open.

| State of a port | Fields | Meaning |
|-----------------|--------|---------|
| Not attached | `S.grids[port]` nil, `attached_devices[port]` nil | No key handler from Strata; not drawn, not counted on SETUP |
| Attached | `S.grids[port]` the vport, `attached_devices[port]` its device | Keys reach `grid_key`; drawn and counted while the vport holds a device |
| Stale (menu open, or before the menu closes) | the vport's device is not `attached_devices[port]`, or it holds a device and `S.grids[port]` is nil | Set right by `reconcile_ports` as the menu closes |

| Transition | Function |
|------------|----------|
| Attach (init, hot-plug, the menu closing) | `attach_grid`, from `grid_init`, `grid_added`, `reconcile_ports` |
| Detach (unplug, the menu closing, a virtual grid leaving) | `detach`, from `grid_removed`, `reconcile_ports` and `detach_virtual` |
| Attach a virtual grid (ports 5 and 6) | `attach_virtual` |

## LEDs

- **Active steps**: at their level (15 for steps set by hand).
- **Current playback position**: each voice's own sounding step (`S.lib.sequencer.sounding_step(voice)`, which follows the voice's length and division), through `step_brightness(voice, step)`: 15 if the step is active, 4 if empty; a set step past the voice's length lights at 1, an empty one stays dark. The patterns page draws its keys through `step_brightness`, so the grids show what SEQ shows.
- The levels every page shares (#526), `S.constants.GRID_LEVELS` (`M.LEVELS`): a voice's on/off key 12 running, 2 stopped (`voice_level`; 3.4: 6 running and silenced, `SHARED_KEYS.voice_silenced`); a page key 15 shown, 10 on its second side (`side_two`), 2 other; a pick key (the grid voice's, a fader page's: `S.lib.grid_faders.fader_page_level`) 15 picked, 4 not; a lock key 12 locked, 2 not (`lock_level`); the play keys 15 playing, 4 stopped (`play_level`). The strips' own keys (fill, tempo, mute, NV) keep the pane engine's levels (`docs/notes/lua/grid/pane.md`).
- The scene keys (#452): a recall key 8 saved, 2 empty, 10 the slot the running sequencer recalls next (`S.lib.scenes.sequencer_next_slot()`, #303; empty slots skipped, #513), 15 the current scene, which wins (`S.lib.scenes.shows_current`: the scene a fade goes to blinks, #254) (`scene_recall_level(slot)`); a fade key 6 saved, 2 empty (`scene_fade_level`). A slot outside 1..`NUM_SCENES` is 0.
- Always call `grid_port:refresh()` after updating LEDs, and `grid_port:all(0)` to clear them before redrawing.
- Any state shown on the grid calls `grid_redraw()` when it changes, wherever it changes (`toggle_voice`, `toggle_lock`, `randomize_voice`, scene recall, ...). `grid_redraw()` returns at once when no grid is connected, so calling it is cheap.
- Fader lines are redrawn from the drift tick (`drift_update`, 10 times a second) through `S.lib.grid_faders.follow_faders()`, only when what a pane shows changed (#324).

## Faders (`lib/grid/faders.lua`)

Which faders:
- `fader_param_ids(voice)` reads the voice-param records' `fader` groups (the groundwork before 3.8; `docs/notes/lua/params.md`): every group whose `when` holds for the voice, sorted by `rank` (default 0) and, within a rank, in registration order. A param with a fader is one line in its record.
- The built-in records' groups (rank 0) give 3.7's faders, in 3.7's order: the voice's `param_order` (synthesis params, amp/pan last) on a synth source.
  - For a buffer source it starts instead with buf_pos/buf_rate/buf_scan, then `voice_level_fader_keys(voice)`: `amp`, and `pan` for every voice but sub, which has none (the engine pans buffer and input grains); the grain record's group names them.
  - For the input source there are no first keys: the grain params, then `voice_level_fader_keys`.
  - The source action clamps `S.param_page` to the new count.
- Then grain size/density/pitch/spread/envelope/mode, then source/amp mod/freq mod for crossmod slots 1-3.
- Then the newer params: the voice filter's cutoff, resonance and mix and the delay and reverb sends (voice_mix, rank 1), the loop's start and length on a buffer voice only (loops, rank 2), the pitch, size and pan jitters (variation, rank 3), attack and release (notes, rank 4). Options get no fader.
- Voices have 7 or 8 fader pages (`fader_page_count`): 26 to 32 faders, four a page.

Setting a value (each function's `width`, the fader's keys: 16 when not given, 8 on a 64's half):
- `set_param_from_column(param_id, x, width)`: control params `spec:map(fader_column_fraction(id, x, width))`, so faders follow each controlspec's warp (exp for freq, cutoff, mod speed). Number params (mod sources) and option params (`param_range` gives `1, count`): `round(util.linlin(0, 1, min, max, fraction))`. It tests `param.options`, because norns' `param.t` is a number. Everything goes through `params:set`, then the touch hooks run as `"grid"`, so a gesture recorder records it.

Keys:
- `fader_column_fraction` is `(x - 1) / (width - 1)`, except for a range that spans 0 (pan, `buf_scan`, the crossmod amounts; issue #49). 16 keys have no center, so the plain sweep gives ±0.07 for pan there and never 0.
- Such a fader has a zero key (`fader_zero_column(id, width)`: the key nearest `param_value_fraction(id, 0)`, clamped to 2..`width - 1`; key 9 of 16 for the symmetric ranges), which sets exactly 0.
- Each side of the zero key sweeps its part of the range (in the warp's terms) evenly over its own keys, so key 1 is still the minimum and the last key the maximum.
- `fader_position(id, width)` is the inverse: `param_fraction(id) * (width - 1) + 1`, piecewise around a zero key, so 0 shows there. `param_fraction` is `param_value_fraction(id, params:get(id))`: `spec:unmap(value)`, or the linear fraction of a number or option param's range.
- A fader line is drawn by the pane engine: a bar at 8 up to the value, the value's key at 15.
- `shown_macro_ids()`: the four `macro_<m>` ids of the shown bank (`S.lib.macros.bank_macros(S.lib.macros.bank())`), so no page works out a bank's macro numbers. `modulation_signature()`: the shown bank, its macros' keys, the morph's key, its scenes A to D and its position, for a page's `signature`. `faders_signature()`: the grid voice, its fader page, its page count and the shown faders' keys.

## Registering a grid page or layout

- A page: `docs/notes/lua/grid/pane.md` (Registering a page).
