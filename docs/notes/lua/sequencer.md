## Must not break

- **Pattern steps never create nodes, ratchets included**: the `voices` step output gives a running voice `engine.retrigger(voice - 1, level / MAX_STEP_LEVEL)` at every hit, and starts a stopped one with `S.lib.engine_sync.start_voice(voice)` at the step's first hit (a gated voice is then retriggered too; an ungated one is not, as in 3.3). Never retrigger by toggling a voice off and on; no hit ever calls `voiceOn` for a running voice (a test plays 64 steps with ratchets and locks).
- **The sequencer plays only through the step outputs** (`S.register_step_output`, `S.registry.step_outputs`, read at each hit): every hit is one event handed to every registered output in registration order, `voices` (registered in the constructor) first. Each output's `play` (and `available`, and `stop`) runs in a coroutine of its own: an error, or a `play` that yields (`clock.sync`, `clock.sleep`: it runs inside the voice's coroutine, between its syncs), prints `step output <name>: <error>` once and skips that output until the patterns next start. A broken output never stops the clocks or the other outputs. **The `voices` output is the one exception** (ruling 38): it is Strata's own, so an error in it is a bug in Strata, never skipped; it is called directly and its error reaches the clock's guard, which stops the patterns and raises it again, as a step's error did before 3.4 (#243, #382).
- **Step locks and notes are base overrides** (`S.lib.engine_sync.set_base_override`): the stored param never changes. A step's first hit sets them; the overrides the voice's previous played step set and this one lacks are cleared (`clear_base_override`). Every override of a voice ends at once when the patterns stop, its pattern is replaced or cleared (`M.replace_pattern`, so a scene recall and a chain link too), or its length is set below the step that set them (Review Focus 2: no later step of that voice would end them); and at the voice's wrap when no set step is left inside its length (its only set step was turned off). Only a hand edit of the param ends one earlier (the touch hook, `lib/engine_sync.lua`). A synth voice's freq override moves its grain quantize's reference note too, so `set_override` and `clear_override` resend `scaleNote` (`S.lib.variation.send_scale_note`): the step's freq, then the voice's own.
- **Strata follows the transport and never leads it**: `clock.transport.start` and `stop` (installed by start step 160) move the patterns only while `seq_follow_transport` is on and the clock source is external (`M.follows_transport()`); a start restarts every voice at step 1 at once, never through the quantizer. Nothing in the script calls `clock.internal.start`, `clock.link.start` or their stops. The handlers found at install always run after the script's, and cleanup step 90 gives them back if the script's are still installed. A handler never chains to itself.
- **The clocks only sync** (`clock.sync`), so external clock sources keep working. Each voice's coroutine waits for exact beats it works out from its anchor (`wait_for`), so swing and divisions never drift. A wait goes in hops of at most a 16th (`SEQ.hop_beats`): onto the clock's next 16th, then onto the target once it lies within a hop (`clock.sync(hop, offset)` with the offset in (-hop, 0], counted from the coroutine's last sync beat), so a jump of the clock's beat reaches every clock within a hop.
- **One count for every clock** (rulings 47, 54 and 58): every participant's beats are on the sequencer's own count, the clock's beats plus `play.offset` (`M.count_offset()`), 0 from every pattern start (a followed start too). Whenever the clock's beat jumps while the patterns play, `play.keep_count()` sets the offset so the transport's pending 16th waits for the clock's first 16th at or after the moment it is due: a 16th after the transport's last 16th, in time (`played_at`; a jump does not move time), or now when that has passed (a 16th within `SEQ.wake_tolerance` before now counts as now, as a wake does). Every voice shifts by as much, at most one 16th late and never early, whether the handler keeps the count at the jump or a clock notices it up to a hop later: steps that fell together still do, 16th steps land on the clock's 16ths, no step plays twice, and the chain's and the division reset's bars and the ratchets keep their places. A transport start the patterns do not follow (the internal clock's reset, an external start with `seq_follow_transport` off) is kept by the handler at once. Any jump nobody announced (a new clock source, crow's input division, a reset another script's handler hides from Strata's) is kept by the first clock that notices it, as the handler would, and every other clock then waits on that offset.
- **No clock waits on an old reference** (ruling 58). matron counts a coroutine's next sync from the beat its last sync landed on, so a clock that syncs again after the count moved would wait on the old beat. Before each sync `wait_for` compares the beat with that landing (`state.last_sync`): below it (the beat went back after the clock's resume was posted: a reset between the post and the delivery, which matron's order makes the clock's delivery come before the start event, or during its step), the count moved and the clock keeps it unless it was kept meanwhile (`play.generation` against the one it synced in); a 16th or more above it (a late delivery), the sync would land in the past. Either way, and after any count change, `clock.sleep(0)` first makes matron count from now. No clock is canceled for this: matron posts the resumes of the clocks a reset woke within a millisecond of it, often before Strata's handler runs, and norns would deliver each to a coroutine it no longer has (`clock.resume` errors).
- **At each wake a clock tests the beat its `clock.sync` returned** (rulings 54 and 58; the beat matron's tick fired it on, never the live beat, which a late tick pulls back): from `SEQ.wake_tolerance` (1/32 beat) before the hop's beat to under `SEQ.late_beats` (a 16th) after it, it is on time and plays, late or not, whatever was kept meanwhile (a resume posted before a reset); outside that the count moved, kept meanwhile or kept now, and it waits again on the new count. An on-time wake whose beat has meanwhile gone further than the time since its sync explains, even at the faster of the two tempos (`jumped_forward`: a jump forward after the post, such as a new clock source, which a param action sets on Lua's own thread while resumes wait behind it), keeps the count too and plays on it. A late delivery (Lua busy) moves the beat and the time together, so it never reads as a jump: the count stays.
- **Ending a clock never cancels one whose resume may be posted**: norns delivers every resume matron posted, and one whose coroutine was canceled meanwhile makes `clock.resume` raise (maiden prints `bad argument #1 to 'resume'`, a line per clock). Every end of a pattern clock (`pattern_clock_start`, a followed transport start, `pattern_clock_stop`, so the play key, a followed stop, the error path and cleanup, and `restart_voice`, so the division reset's restarts) goes through `end_clock(id, state, all_posted)`. A clock whose resume may be posted is retired (`state.retired` holds its id, and `play.retired` lists it): at its next wake `wait_for` returns false (at once if the clock ends itself, in its own step), the coroutine ends there, playing nothing, and `finished` forgets it. Any other is canceled at once. `resume_may_be_posted(state)` says which: the clock sleeps (`state.waiting`; a sleep of 0 is due at once), its sync's beat (`state.last_sync`) is within `SEQ.wake_tolerance` of the beat or passed, the beat is below the one it synced at (`state.sync_beat`: a reset or a new clock source has moved its sync since), or it runs now (it never cancels itself). A followed transport start retires every clock (`all_posted`): matron has just put every waiting sync on beat 0, so every resume is posted within a tick, also for a clock that synced just after an earlier start, which the beats alone would show clearly ahead. Every participant of a start, and a restarted voice, gets a fresh state, so a retired clock never shares one with its successor. A retired clock keeps its scheduler slot until that wake: at most a hop (a 16th) away, a tick after a reset. Cleanup cancels every retired clock still waiting (norns cancels every coroutine right after a script's cleanup anyway).
- **No bursts** (ruling 58, rule 4): at a wake a voice plays at most one step that has come. While its next tick has come too, the step at its tick is skipped (its position moves on, nothing plays: `skip_due_ticks`), so it plays the latest, at the position the count puts it at; a ratchet's hits that have come are skipped to the latest, and all of them when the next tick has come (`due_hit`). The transport's 16th moves on the same way (its skipped 16ths move `S.pattern_position`), with no catch-up loop. So after any wake a clock's next step comes within its division and one 16th.
- **Limits**: a jump back that leaves matron's syncs where they are (no source matron has today does this: a reset puts them on beat 0, a source change reschedules them) wakes no clock, so every clock pauses until the beat climbs back to where it was (a clock retired meanwhile keeps its scheduler slot until then); a jump forward of that kind is noticed at the next wake. A jump that falls inside a clock's resume, between its check and matron's scheduling of its sync (microseconds), leaves that clock on the old beat. A stop, play-key start or restart that runs after a reset and before Strata's handler sees it (or after one another script's handler hides), while a clock last synced at a beat below the beats counted since the reset, cannot tell the reset by `resume_may_be_posted`: that clock is canceled with its resume posted. That is a second reset before the clocks' first sync after a start (each syncs at the start's beat and wakes up to a 16th later; resets 1 ms or 100 ms apart alike), with a stop, play-key start or restart between that reset and its handler. It stays rare: matron posts the start event right after the reset, so that gap is about a millisecond.
- `pattern_clock_start` ends every running clock (`end_clock`) before starting new ones; it starts the voices' clocks before the transport's, so from a start the transport holds the higher scheduler slot and fires after the voices due on the same beat (the tests' `wake(context, "pattern_clock")` relies on it). Nothing else depends on that order: a chain link is made by whichever participant reaches its bar first, and the repaint by whichever is last.
- **The `"pattern clock"` invariant**: `S.pattern_playing == (S.pattern_clock ~= nil)`, and the same for every voice's `S.pattern_clocks[voice]`; every recorded clock runs (in `clock.threads` and not dead) and is not a retired one; every retired clock still runs (it is forgotten when it finishes). A retired clock may run beside its successor until its next wake, but it is never recorded and plays nothing.
- **One grid repaint per beat** (#527): the participants (the seven voices and the transport) whose steps fall on one beat repaint the grid once, after the last of them (`finish_beat`: a participant whose step is due on that beat and has not played it yet leaves the repaint to it), with `update_voice_list()` and `request_redraw()` when one of them started a voice. Starts go through `start_voice`, which redraws nothing.
- Each step's work runs through `xpcall` (`guarded`), every wait outside it: an error of the sequencer itself or of the `voices` output (not another output's) forgets the clock's own id, calls `pattern_clock_stop()` (every clock, so the others stop too), `update_voice_list()` and `request_redraw()`, and raises the error again (#243). Never leave `S.pattern_playing` true after a clock died.
- Bounds-check every voice and step before indexing: `toggle_pattern_step` ignores a voice outside 1..`NUM_VOICES` and a step outside 1..`PATTERN_LENGTH` (#414); `step_attr` and `set_step_attr` ignore an out-of-range voice, step, key or value.
- Step levels come from `MAX_STEP_LEVEL`, never a written-out 15: a toggled step and a Euclidean hit are `MAX_STEP_LEVEL`, a random one `RANDOM_STEP_FLOOR` (half of it, rounded up: 8) to `MAX_STEP_LEVEL` (#418).
- Anything that changes a pattern or the playhead calls `grid_redraw()`. Every edit of a voice's pattern or step attributes (`toggle_pattern_step`, `replace_pattern`, `set_step_attr`, `euclid`, and the writers in SEQ, the arc and the grid's level gesture) calls `S.lib.mutation.note_pattern_edit(voice)`, which ends a pattern undo of that voice (#557).
- A whole-pattern change (clear, randomize, Euclidean fill, the 256's paste, a scene recall's restore, a chain link) goes through `S.lib.sequencer.replace_pattern(voice, steps)`, never a loop over `S.patterns[voice]` of its own: it ends the voice's held step gestures (`S.lib.grid_core.end_step_gestures`, #242) and its overrides.
- Every playhead is a sounding step, never `S.pattern_position`, which is already the next 16th between steps (#113): `S.lib.sequencer.sounding_step(voice)` for a voice's row (`step_brightness` reads it), `sounding_step()` for the transport's 16th (the 8×8's column 1 until Wave 2 moves it; SEQ's rows read their voice's since 3.4's edit view, `docs/notes/lua/pages/seq.md`). Both are nil while stopped and before the first step plays.
- A gated voice's `gateSeconds` is sent only when it differs from the value last sent for the voice (`gate_sent`), before the hit's `retrigger`; `seqGate` only as 0 or 1 (the grain key's `value`); an ungated voice gets nothing per hit beyond its retrigger.
- The step attributes validate by one table of checks (`ATTR_CHECKS`) for `set_step_attr` and the `steps` scene block alike (design 9.2).

## Data

- **Levels**: `S.patterns[voice][step]`, `NUM_VOICES` × `PATTERN_LENGTH` steps, 0-`MAX_STEP_LEVEL` (15). The 64 grid shows and edits only steps 1-8 or 9-16, but patterns play all 16.
- **Attributes** (design 8.1, 8.12): `S.pattern_steps[voice][step]` is nil for a plain step, or a table of any of `prob` (whole 0-100; nil plays always), `ratchet` (whole 1-4), `notes` (a list, keys 1..n with no hole, of 1 to `SEQ.max_step_notes` (8) whole degrees -14..14), `pos`, `pitch`, `size` (in `v<i>_buf_pos`'s, `v<i>_grain_pitch`'s and `v<i>_grain_size`'s ranges), `bookmark` (whole 1..`NUM_BOOKMARKS`) and `gate` (0.05-16 steps). `set_step_attr` stores a copy of a notes list; nil, or an empty notes list, clears a key, and a step with no key left is nil. `step_attr` returns a copy of a notes list.
- **The `steps` scene block** (`S.register_scene_block`, key `steps`, discrete): `data.steps[voice] = {[step] = {...}}`, sparse; `default` is `NUM_VOICES` empty tables (what migration fills into an older scene: every step plain); `capture` and `apply` copy, dropping empty steps; `validate` (`M.valid_steps`) wants exactly the voices 1..`NUM_VOICES`, each a table keyed by whole steps 1..`PATTERN_LENGTH`, each step a table of known keys in range (anything else rejects the scene). A recall applies the block before the patterns (blocks come first in `scene_entries`).
- **The `seq` voice-param record** (`S.register_voice_params`, no VOICE rows, `fader = false`), its params `v<i>_<key>` in `S.voices[i].extras`:

  | Key | Param | Default | Scenes |
  |---|---|---|---|
  | `seq_length` | number 1-16 | 16 | discrete |
  | `seq_division` | option `SEQ.division_names` (`1/32` .. `1 bar`; `SEQ.division_beats` 1/8, 1/6, 1/4, 1/3, 1/2, 1, 2, 4 beats) | 3 (`1/16`) | discrete |
  | `seq_gate` | option off, on; grain key `seqGate` (index - 1) | off | discrete |
  | `seq_gate_length` | control 0.05-16 steps, exp | 0.5 | crossfades (`scene_ranges`) |
  | `seq_gate_release` | control 0.005-4 s, exp; grain key `gateRelease` | 0.1 | crossfades (`scene_ranges`) |
  | `seq_swing` | number 50-75 (%) | 50 | discrete |

  Its `sync` (the voice sync, and a start before `voiceOn`) sends a gated voice's `gateSeconds` when it changed. `seq_length`'s action ends the voice's overrides when the new length is below the step that set them and redraws the grid; `seq_gate`'s and `seq_gate_length`'s send a running gated voice's `gateSeconds` when it changed.
- **`strata_seq`** (`M.add_params()`, `SEQ.group_params` (6) + `S.lib.quantize.PARAM_COUNT` params, in this order): `seq_chain` (binary, 0), `seq_chain_from` (1..`NUM_SCENES`, 1), `seq_chain_scenes` (1..`NUM_SCENES`, 2), `seq_chain_bars` (1-16, 4), then `S.lib.quantize.add_params()`, `seq_division_reset` (trigger), `seq_follow_transport` (binary, 1, `follow transport`). PSETs store them; scenes don't.

## The clocks

- **Participants**: one coroutine per voice (`S.pattern_clocks[voice]`) and the transport's (`S.pattern_clock`, counting 16ths: `S.pattern_position` is the next, `S.pattern_sounding_step` the one played last, both 1-16). `pattern_clock_start()` takes the start beat `b0 = clock.get_beats()`, loads the chain's first scene if the chain is on, then starts every voice (`restart_voice`: step 1 at once, inside `clock.run`) and the transport (its 16th 1 at once), in that order. A start while playing starts over.
- **A voice's ticks**: tick k falls on `anchor + k × division`, and every odd tick (the voice's 2nd, 4th, ... step since its anchor) `(swing - 50) / 50 × division` late. After each step the coroutine works out its next tick from the beat it played last (so a division or swing change applies from the next step, on the anchor's grid) and waits for it with `wait_for(state, target)`. Parity counts ticks, not step numbers, so an odd length never puts two swung steps in a row.
- **Position**: a voice's position is the next step it plays; it wraps at the pass's length. A length change applies at once while the position is inside the new length, at the wrap otherwise (the pass finishes first). At the wrap a voice holding overrides with no set step inside its length (`has_set_step`) ends them. `sounding_step(voice)` is the step played last (`S.pattern_sounding_steps[voice]`).
- **A step**: first a chain link due on its beat (`at_beat`: the first participant to reach a link's bar links, for all). A set step with `prob` draws once (`math.random() × 100 < prob`; none for 100, nil or 0), then plays `hits = min(ratchet, max(1, floor(step_seconds / SEQ.min_ratchet_seconds)))` hits, `step_seconds` the step's own length (a swung pair's: `division ± swing`) × `S.lib.params_setup.beat_seconds_now()`, spaced `step_length / hits` (`wait_for` for each). Every hit is one event to every output. A step or hit skipped at a late wake (No bursts, above) draws nothing and plays nothing.
- **The event** (design 8.10): `voice`, `step`, `hit`, `hits`, `first`, `level`, `velocity` (level / `MAX_STEP_LEVEL`), `notes` (a copy, or nil), `semitones` (each note through `degree_semitones`, worked out once per step as it plays, `step_semitones`; each hit's event a copy, or nil), `locks` (`{pos, pitch, size, bookmark}` as stored, only those set, or nil), `beat` (`clock.get_beats()` at the hit: the clock's beat) and `gate_beats` (a gated voice: its gate's length in steps, the voice's `v<i>_seq_gate_length` or `SEQ.gate_length_default`, × division / hits; otherwise division / hits).
- **The `voices` output**: at a step's first hit a stopped voice is started (`start_voice`), then the locks are set (`set_base_override` on `v<i>_buf_pos`, `v<i>_grain_pitch`, `v<i>_grain_size`), the bookmark recalled (`S.lib.bookmarks.recall`, only when `is_set` and the bookmark lies inside `[loop_start, loop_start + loop_length)`, so the jump never resets the loop; Question 25) and the note set (a base override on `v<i>_freq` (synth), `v<i>_buf_rate` (buffer) or `v<i>_grain_pitch` (input, on the step's pitch lock), the stored value × 2^(semitones / 12), clamped; a synth voice's `scaleNote` follows the freq); the previous played step's overrides this one lacks are cleared first. Then a running voice (and a just-started gated one) gets the gate length when it changed (gated) and `retrigger`. It runs outside the outputs' protection (ruling 38).
- **Notes** (design 8.4, plan ruling 22): degree k of a voice is the k-th tone above (below, for k < 0) the voice's pitch among the global scale's tones (`S.lib.variation.scale_mask()`, `root()`), its root included; `degree_semitones(voice, k)` is the distance. The voice's pitch is its freq as a note for a synth voice, and `S.lib.midi_in.MIDI.rate_root_note + 12 × log2(rate)` for a buffer (`v<i>_buf_rate`) or input (`v<i>_grain_pitch`, the stored one, not the lock) voice. A pitch within `SEQ.tone_tolerance` (0.01 semitone) of a tone counts as on it. On the chromatic scale (the scale off, mask 4095) a degree is exactly k semitones from the voice's pitch, so a voice tuned between two notes keeps its tuning. Only `notes[1]` plays on Strata's voices; outputs get the list.
- **The gate**: `gate_seconds(voice, step, hits)` is the step's `gate` (or `v<i>_seq_gate_length`) × the voice's nominal step (`division_beats × beat_seconds_now()`) / hits, clamped to 0.005-120 s; swing never changes it.
- **Division reset** (`seq_division_reset`, while playing): the transport's next bar (`anchor + 4 m` after its last 16th) becomes the reset beat. A voice whose next tick would pass it waits for the bar instead; one due on the bar plays step 1 there with the bar as its new anchor; the transport, at the bar, restarts (`restart_voice`) every voice still on its old anchor (one that was waiting past the bar).
- **Stop** (`pattern_clock_stop`, also the transport's stop, cleanup step 90 and the error path): every clock ended (`end_clock`), the playheads cleared, the reset and the chain's next link dropped, every override ended, then (when the patterns played) every output's `stop`, and `grid_redraw()`.
- **States** (the `"pattern clock"` invariant):

  | State | `S.pattern_playing` | `S.pattern_clock`, `S.pattern_clocks[v]` | sounding steps |
  |-------|---------------------|-------------------|---------------------------|
  | stopped | false | nil | nil |
  | playing | true | the running clocks' ids | nil before the first step plays, then the step played last |

  A clock that fails on its first run (which `clock.run` makes at once) leaves its id unrecorded, because `clock.run` re-raises before it returns, and its stop ends the clocks started before it.

## The chain (design 8.8)

- While `seq_chain` is on and the patterns play, every `seq_chain_bars` bars (counted by the transport from the start beat, on the bar) the next populated, valid scene of `seq_chain_from .. seq_chain_from + seq_chain_scenes - 1` (slots wrap past `NUM_SCENES`; after the range's last, its first; empty slots skipped) gives its patterns (`replace_pattern`), its `steps` block and each voice's `seq_length` and `seq_division`, and nothing else (no other param, source, voice state or lock). Every override ends. A start with the chain on loads the range's first scene at once; switching it on while playing waits for the transport's next bar.

## Transport (#530, design 8.11)

- norns calls `clock.transport.start` and `stop` when the clock source starts or stops (matron's `clock_start_from_source` and `clock_stop_from_source`, for the source in use only): a MIDI start (on the first clock tick after it) or stop, a Link start or stop with PARAMETERS > CLOCK > link start/stop sync enabled, and PARAMETERS > CLOCK > reset on the internal clock (a start). At a start norns has already put the beat at 0 and every waiting sync on beat 0.
- With `follows_transport()` (the param on, the source MIDI, Link or crow), a start runs `pattern_clock_start()` at once (every voice at step 1 on the new beat 0, a running chain from its first scene), never through the quantizer; a stop runs `pattern_clock_stop()`. Both ask for a redraw. Otherwise a stop does nothing, and a start keeps the sequencer's own count through the reset while the patterns play (`play.keep_count`, rulings 47, 54 and 58, above); both then call the ones found at install. A followed start retires every clock and cancels none (`end_clock`'s `all_posted`, Ending a clock, above), so no resume matron posted after the reset reaches a coroutine norns no longer has. The play key (`pattern_toggle`) starts through `S.lib.quantize.schedule("patterns", pattern_clock_start, "play")` and stops at once; a press while that start waits takes it back (`S.lib.quantize.cancel("patterns")`), and every start (a followed transport start too) and every stop (`pattern_clock_stop`) drops a waiting start, so it never fires after them (#625).

## Operations

- `toggle_pattern_step(voice, step)`: an empty step on at `MAX_STEP_LEVEL`, a set one off; a voice or step out of range does nothing.
- `clear_pattern(voice)`: every level 0 (the attributes stay); `randomize_pattern(voice)`: a random pattern at 50% density (per step `math.random() > 0.5`, then `math.random(RANDOM_STEP_FLOOR, MAX_STEP_LEVEL)`, in that order, so seeded tests keep their values).
- `S.lib.sequencer.replace_pattern(voice, steps)`: steps 1..`PATTERN_LENGTH` take `steps[step]` floored and clamped to 0..`MAX_STEP_LEVEL` (a missing or non-number entry is 0), then the voice's overrides end and `end_step_gestures(voice)` runs. A voice outside 1..`NUM_VOICES` or a `steps` that is not a table does nothing. It redraws nothing: callers do.
- `S.lib.sequencer.euclid(voice, hits, rotation)` (design 8.5): the voice's first `seq_length` steps from `er.gen(hits, length, rotation)` (norns' `lua/lib/er.lua`, `require "er"`; `test/stub_er.lua` off the device), hits at `MAX_STEP_LEVEL` and the rest 0, through `replace_pattern`; the steps past the length and every attribute are kept. Any whole, finite hits and rotation: the hits clamped to 0..length, the rotation wrapped into 0..length - 1 (design 8.6), and that pair is `S.seq_euclid[voice] = {hits, rotation}`. Nothing while `S.scene_recall_in_progress`, or for a hits or rotation that is not a whole number.
- `step_brightness(voice, step)`: at the voice's sounding step 15 for a set step and 4 for an empty one; past the voice's length `SEQ.past_length_level` (1) for a set step and 0 for an empty one; otherwise the stored level.

Bounds check before indexing:
