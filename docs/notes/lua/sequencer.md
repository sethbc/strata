## Must not break

- **Pattern steps never create a node for the voice's own note, ratchets included**: the `voices` step output gives a running voice `engine.retrigger(voice - 1, level / MAX_STEP_LEVEL)` at every hit (3.9: a move voice's at 0, `docs/notes/lua/sequencer/modes.md`), through `S.lib.engine_sync.retrigger(voice, velocity, "step", gate_seconds)` (3.7: the hit's door, with a gated voice's gate length), and starts a stopped one with `S.lib.engine_sync.start_voice(voice, {retrigger_follows = gated})` at the step's first hit (a gated voice is then retriggered too, that retrigger the step's one hit; an ungated one is not, as in 3.3, and its start is the hit). Never retrigger by toggling a voice off and on; no hit ever calls `voiceOn` for a running voice (a test plays 64 steps with ratchets and locks). A chord's further notes are extra notes, one synth each through `S.lib.notes`: a node only where a note starts in a slot, never for a note the next played step keeps or at a ratchet's later hit (a test plays 64 steps of chords with ratchets and locks).
- **A step's notes are a chord through `S.lib.notes`** (design §4; rulings 13, 27, 32, 33, 35 and 55), owner `"seq"` (`SEQ.note_owner`), key k the step's k-th note, `park = false`. **A step never takes a slot or a note from another owner** (ruling 35): MIDI's held notes are never cut, stolen in place or re-pitched by the sequencer, while a MIDI note may still steal or re-pitch a sequenced one (the player wins). **But only a key physically down keeps the voice's own note** (ruling 55, refining 35): MIDI's own note whose key is up (latched) gives way to a step's first note, as in 3.4: `S.lib.midi_in.keeps_own(voice)` forgets it (`S.lib.notes.forget`: nothing sent, the own note sounds on as nobody's), and the step re-pitches and accents the own note. MIDI's latched extra notes stay MIDI's.
  - **The first note** plays in `apply_step`, where 3.4 set its note override. While the voice's slot 1 is free, parked or the sequencer's, it plays with `quiet = true` and every one of `play`'s branches (it is the step's note, as in 3.4): it takes slot 1 and its `set_own` sets 3.4's override, and a slot 1 the sequencer holds from an earlier step is played again by branch 1, never reaching a steal. So a step without notes on any voice, and a one-note step on a voice nothing else holds that is not a frozen synth voice, send 3.4's messages exactly; on a running frozen synth voice a step with a note also sends the allocator's slot-0 `noteOn` (its rate) at each first hit (ruling 33). While another owner holds slot 1 (a held, unparked note in `S.lib.notes.slots(voice)` whose key is down, `other_owns_slot_1`), the first note is `extra_only` too (not quiet): a free extra slot or nothing, and no note override is set (decided by the slot `play` returns, kept as the chord's `own`). Its `noteExpression` and `noteOn` then go inside `apply_step`, before the gate length and the `retrigger` (accepted: the voice runs, MIDI holds it). When MIDI lets go of slot 1 (its latched note given way, or a reset) while the first note sits in an extra slot, that note is released there first (`leave_extra_slot`) so it plays as the voice's own again, never an extra note over the own note's drone (the final review's minor 1); a parked own note is left (it is silent). When a MIDI note takes slot 1 from the step's own note (branch 6, the cap or pool full), `M.own_note_taken(voice)` (called by `midi_note_on`) ends the step's note override at once, as for a first note that is not the voice's own, so MIDI's pitch plays now (minor 2).
  - **The further notes** play after the voice's start and `retrigger` (`play_chord`: only a running voice gets an extra slot), each `extra_only` (ruling 32): its own held slot again, or a free extra slot under the cap with room in the pool, never slot 1 and never a steal; else refused. So a chord takes only free room: past the cap or the pool it keeps its first notes at every step (a note that did not fit never steals a kept one), and a cap of 1 or a pool of 0 sends 3.4's messages.
  - A ratchet's later hit plays again every note held in an extra slot (an accent, no node); the `retrigger` accents slot 1's. Every note's pitch is measured from the one base the first note's override is worked out from (the note param's stored value or the step's lock on it), so a chord never splits from its first note.
  - **On an arpeggiating voice** (3.8, package 2b, `docs/notes/lua/arp.md`) the further notes are the arpeggiator's list for the step, never extra notes: `S.lib.notes.play` hands each to `S.lib.arp.hold` (no `noteOn`, no slot, no accent of their own: the step's `retrigger` is the hit), so the step's chord is `{0}` and each note less the first, in the mode's order. It ends where the chord ends (the next step's `release` of each key it lacks, `release_owner(voice, "seq")`), with no sequencer code of its own; a ratchet's later hit replays nothing for them (they hold no extra slot).
- **A chord ends where its override ends**: the next played step releases (`release`) each key it lacks and plays again in place each one it keeps; every other ending of the overrides (`end_overrides`: a stop, `replace_pattern`, a shorter length, the wrap, a chain link) releases the voice's chord (`release_owner(voice, "seq")`). A released first note sends nothing (it asked no park); its override ends as before. The `voices` output's `stop` ends every voice's chord; at a pattern stop `end_all_overrides` runs first and has done it, so nothing is released twice.
- **The sequencer plays only through the step outputs** (`S.register_step_output`, `S.registry.step_outputs`, read at each hit): every hit is one event handed to every registered output in registration order, `voices` (registered in the constructor) first, then 3.6's `targets` (`lib/io/targets.lua`, registered at its start step 161: the hits to the external note targets, `docs/notes/lua/io/targets.md`). Each output's `play` (and `available`, and `stop`) runs in a coroutine of its own: an error, or a `play` that yields (`clock.sync`, `clock.sleep`: it runs inside the voice's coroutine, between its syncs), prints `step output <name>: <error>` once and skips that output until the patterns next start. SEQ's status line names it until then (`M.failed_outputs()`, #921). A broken output never stops the clocks or the other outputs. **The `voices` output is the one exception** (ruling 38): it is Strata's own, so an error in it is a bug in Strata, never skipped; it is called directly (its `play` and its `stop`) and its error reaches the clock's guard, which stops the patterns and raises it again, as a step's error did before 3.4 (#243, #382).
- **Step locks and notes are base overrides** (`S.lib.engine_sync.set_base_override`): the stored param never changes. A step's first hit sets them; the overrides the voice's previous played step set and this one lacks are cleared (`clear_base_override`). Every override of a voice ends at once when the patterns stop, its pattern is replaced or cleared (`M.replace_pattern`, so a scene recall and a chain link too), or its length is set below the step that set them (no later step of that voice would end them); and at the voice's wrap when no set step is left inside its length (its only set step was turned off). Only a hand edit of the param ends one earlier (the touch hook, `lib/engine_sync.lua`), and a MIDI note that takes the voice's own note from the step ends its note override and a held pitch value (`own_note_taken`). 3.9's step values (`va`, `vb`) are base overrides too but stay through the steps without one, kept apart from these (`held_values`); a lock over one wins for its step and gives the value back at its end (`docs/notes/lua/lanes.md`). A synth voice's freq override moves its grain quantize's reference note too, so `set_override` and `clear_override` resend `scaleNote` (`S.lib.variation.send_scale_note`): the step's freq, then the voice's own.
- **Strata follows the transport and never leads it**: `clock.transport.start` and `stop` (installed by start step 160) move the patterns only while `seq_follow_transport` is on and the clock source is external (`M.follows_transport()`); a start restarts every voice at step 1 at once, never through the quantizer. Nothing in the script calls `clock.internal.start`, `clock.link.start` or their stops. The handlers found at install always run after the script's, and cleanup step 90 gives them back if the script's are still installed. A handler never chains to itself. Once cleanup has run (`transport.installed` false, #924), the script's handlers move nothing: a handler installed later that still chains to them reaches only the ones they found.
- **The clocks only sync** (`clock.sync`), so external clock sources keep working. Each voice's coroutine waits for exact beats it works out from its anchor (`wait_for`), so swing and divisions never drift. A wait goes in hops of at most a 16th (`SEQ.hop_beats`): onto the clock's next 16th, then onto the target once it lies within a hop (`clock.sync(hop, offset)` with the offset in (-hop, 0], counted from the coroutine's last sync beat), so a jump of the clock's beat reaches every clock within a hop.
- **One count for every clock** (rulings 47, 54 and 58): every participant's beats are on the sequencer's own count, the clock's beats plus `play.offset` (`M.count_offset()`), 0 from every pattern start (a followed start too). Whenever the clock's beat jumps while the patterns play, `play.keep_count()` sets the offset so the transport's pending 16th waits for the clock's first 16th at or after the moment it is due: a 16th after the transport's last 16th, in time (`played_at`; a jump does not move time), or now when that has passed (a 16th within `SEQ.wake_tolerance` before now counts as now, as a wake does). Every voice shifts by as much, at most one 16th late and never early, whether the handler keeps the count at the jump or a clock notices it up to a hop later: steps that fell together still do, 16th steps land on the clock's 16ths, no step plays twice, and the chain's and the division reset's bars and the ratchets keep their places. A transport start the patterns do not follow (the internal clock's reset, an external start with `seq_follow_transport` off) is kept by the handler at once. Any jump nobody announced (a new clock source, crow's input division, a reset another script's handler hides from Strata's) is kept by the first clock that notices it, as the handler would, and every other clock then waits on that offset. `keep_count` asks for a redraw, whoever calls it (#921's review: SETUP's offset row).
- **No clock waits on an old reference** (ruling 58). matron counts a coroutine's next sync from the beat its last sync landed on, so a clock that syncs again after the count moved would wait on the old beat. Before each sync `wait_for` compares the beat with that landing (`state.last_sync`): below it (the beat went back after the clock's resume was posted: a reset between the post and the delivery, which matron's order makes the clock's delivery come before the start event, or during its step), the count moved and the clock keeps it unless it was kept meanwhile (`play.generation` against the one it synced in); a 16th or more above it (a late delivery), the sync would land in the past. Either way, and after any count change, `clock.sleep(0)` first makes matron count from now. No clock is canceled for this: matron posts the resumes of the clocks a reset woke within a millisecond of it, often before Strata's handler runs, and norns would deliver each to a coroutine it no longer has (`clock.resume` errors).
- **At each wake a clock tests the beat its `clock.sync` returned** (rulings 54 and 58; the beat matron's tick fired it on, never the live beat, which a late tick pulls back): from `SEQ.wake_tolerance` (1/32 beat) before the hop's beat to under `SEQ.late_beats` (a 16th) after it, it is on time and plays, late or not, whatever was kept meanwhile (a resume posted before a reset); outside that the count moved, kept meanwhile or kept now, and it waits again on the new count. An on-time wake whose beat has meanwhile gone further than the time since its sync explains, even at the faster of the two tempos (`jumped_forward`: a jump forward after the post, such as a new clock source, which a param action sets on Lua's own thread while resumes wait behind it), keeps the count too and plays on it. A late delivery (Lua busy) moves the beat and the time together, so it never reads as a jump: the count stays.
- **Ending a clock never cancels one whose resume may be posted**: norns delivers every resume matron posted, and one whose coroutine was canceled meanwhile makes `clock.resume` raise (maiden prints `bad argument #1 to 'resume'`, a line per clock). Every end of a pattern clock (`pattern_clock_start`, a followed transport start, `pattern_clock_stop`, so the play key, a followed stop, the error path and cleanup, and `restart_voice`, so the division reset's restarts) goes through `end_clock(id, state, all_posted)`. A clock whose resume may be posted is retired (`state.retired` holds its id, and `play.retired` lists it): at its next wake `wait_for` returns false (at once if the clock ends itself, in its own step), the coroutine ends there, playing nothing, and `finished` forgets it. Any other is canceled at once. `resume_may_be_posted(state)` says which: the clock sleeps (`state.waiting`; a sleep of 0 is due at once), its sync's beat (`state.last_sync`) is within `SEQ.wake_tolerance` of the beat or passed, the beat is below the one it synced at (`state.sync_beat`: a reset or a new clock source has moved its sync since), or it runs now (it never cancels itself). A followed transport start retires every clock (`all_posted`): matron has just put every waiting sync on beat 0, so every resume is posted within a tick, also for a clock that synced just after an earlier start, which the beats alone would show clearly ahead. Every participant of a start, and a restarted voice, gets a fresh state, so a retired clock never shares one with its successor. A retired clock keeps its scheduler slot until that wake: at most a hop (a 16th) away, a tick after a reset. Cleanup cancels every retired clock still waiting (norns cancels every coroutine right after a script's cleanup anyway).
- **No bursts** (ruling 58, rule 4): at a wake a voice plays at most one step that has come. While its next tick has come too, the step at its tick is skipped (its position moves on, and its free lanes, 3.9: `docs/notes/lua/lanes.md`; nothing plays: `skip_due_ticks`), so it plays the latest, at the position the count puts it at; a ratchet's hits that have come are skipped to the latest, and all of them when the next tick has come (`due_hit`). The transport's 16th moves on the same way (its skipped 16ths move `S.pattern_position`), with no catch-up loop. So after any wake a clock's next step comes within its division and one 16th.
- **Limits**: a jump back that leaves matron's syncs where they are (no source matron has today does this: a reset puts them on beat 0, a source change reschedules them) wakes no clock, so every clock pauses until the beat climbs back to where it was (a clock retired meanwhile keeps its scheduler slot until then); a jump forward of that kind is noticed at the next wake. A jump that falls inside a clock's resume, between its check and matron's scheduling of its sync (microseconds), leaves that clock on the old beat. A stop, play-key start or restart that runs after a reset and before Strata's handler sees it (or after one another script's handler hides), while a clock last synced at a beat below the beats counted since the reset, cannot tell the reset by `resume_may_be_posted`: that clock is canceled with its resume posted. That is a second reset before the clocks' first sync after a start (each syncs at the start's beat and wakes up to a 16th later; resets 1 ms or 100 ms apart alike), with a stop, play-key start or restart between that reset and its handler. It stays rare: matron posts the start event right after the reset, so that gap is about a millisecond.
- `pattern_clock_start` ends every running clock (`end_clock`) before starting new ones; it starts the voices' clocks before the transport's, so from a start the transport holds the higher scheduler slot and fires after the voices due on the same beat (the tests' `wake(context, "pattern_clock")` relies on it). Nothing else depends on that order: a chain link is made by whichever participant reaches its bar first, and the repaint by whichever is last.
- **The `"pattern clock"` invariant**: `S.pattern_playing == (S.pattern_clock ~= nil)`, and the same for every voice's `S.pattern_clocks[voice]`; every recorded clock runs (in `clock.threads` and not dead) and is not a retired one; every retired clock still runs (it is forgotten when it finishes). A retired clock may run beside its successor until its next wake, but it is never recorded and plays nothing.
- **One grid repaint per beat** (#527): the participants (the seven voices and the transport) whose steps fall on one beat repaint the grid once, after the last of them (`finish_beat`: a participant whose step is due on that beat and has not played it yet leaves the repaint to it), with `update_voice_list()` and `request_redraw()` when one of them started a voice. Starts go through `start_voice`, which redraws nothing.
- Each step's work runs through `xpcall` (`guarded`), every wait outside it: an error of the sequencer itself or of the `voices` output (not another output's) forgets the clock's own id, calls `pattern_clock_stop()` (every clock, so the others stop too), `update_voice_list()` and `request_redraw()`, and raises the error again (#243). Never leave `S.pattern_playing` true after a clock died.
- Bounds-check every voice and step before indexing: `toggle_pattern_step` ignores a voice outside 1..`NUM_VOICES` and a step outside 1..`PATTERN_LENGTH` (#414); `step_attr` and `set_step_attr` ignore an out-of-range voice, step, key or value.
- Step levels come from `MAX_STEP_LEVEL`, never a written-out 15: a toggled step and a Euclidean hit are `MAX_STEP_LEVEL`, a random one `RANDOM_STEP_FLOOR` (half of it, rounded up: 8) to `MAX_STEP_LEVEL` (#418).
- Anything that changes a pattern or the playhead calls `grid_redraw()`. Every edit of a voice's pattern or step attributes (`toggle_pattern_step`, `replace_pattern`, `set_step_attr`, `euclid`, and 3.9's `set_level`, the one writer of a level, which SEQ, the arc and the grid's level gesture write through: `docs/notes/lua/sequencer/modes.md`) calls `S.lib.mutation.note_pattern_edit(voice)`, which ends a pattern undo of that voice (#557) and a chain start's hold of all seven (#922).
- **A start's first link is held by the one undo** (#922): `start_patterns` makes it through `S.lib.mutation.hold_patterns({SEQ, "pattern"}, chain_link)`, which captures the seven patterns, their step attributes and each voice's `SEQ.chain_keys` before the link and holds them on SEQ when the link changed any of them (a chain that links nothing leaves an earlier undo). A quick ALT+K2 on SEQ, on any voice, puts them back. The links after it are not held, and the next one ends the hold (it edits the patterns). `docs/notes/lua/mutation.md`
- A whole-pattern change (clear, randomize, Euclidean fill, a scene recall's restore, a chain link) goes through `S.lib.sequencer.replace_pattern(voice, steps)`, never a loop over `S.patterns[voice]` of its own: it writes the step levels only (`S.patterns[voice]`; the step attributes, `S.pattern_steps[voice]`, are left as they are, and a scene recall or chain link restores those itself) and ends the voice's held step gestures (`S.lib.grid_core.end_step_gestures`, #242) and its overrides. 3.9's whole pattern (the levels, the steps' settings and the lane lengths: a letter's switch, the voices page's PC, the chain start's undo) goes through `replace_whole(voice, pattern)`, which writes the levels through `replace_pattern` (`docs/notes/lua/pattern-letters.md`).
- Every playhead is a sounding step, never `S.pattern_position`, which is already the next 16th between steps (#113): `S.lib.sequencer.sounding_step(voice)` for a voice's row (`step_brightness` reads it), `sounding_step()` for the transport's 16th (the 8×8's play key, column 1 of row 8; SEQ's rows read their voice's since 3.4's edit view, `docs/notes/lua/pages/seq.md`). Both are nil while stopped and before the first step plays.
- A gated voice's `gateSeconds` is sent only when it differs from the value last sent for the voice (`gate_sent`), before the hit's `retrigger`; `seqGate` only as the gate rule's 0 or 1 (the grain key's `value`, 3.9: `docs/notes/lua/sequencer/modes.md`); an ungated voice gets nothing per hit beyond its retrigger. A retrigger outside the patterns (a MIDI note: `midi_note_on` calls `M.note_gate(voice)` first) opens the voice's own gate length, sent when the last one was a step's (its gate, a ratchet's share), which the stage keeps until the next send (#639).
- The step attributes validate by one table of checks (`ATTR_CHECKS`) for `set_step_attr` and the `steps` scene block alike (design 9.2).
- **Conditions and directions draw only where 3.6 drew** (3.7, design §5.1, §5.5): forward with misstep 0 and no condition makes no draw beyond a probability's (a test replaces `math.random` over 64 plain steps), so a 3.6 pattern plays the same steps. A conditioned step (a set step with a `cond` or a `prob` under 100) tests its condition first (`S.lib.conditions.test`), draws its probability only if it holds, then records its outcome (`S.lib.conditions.record`); a step that is not conditioned records nothing (`docs/notes/lua/conditions.md`).
- **The position, the direction, the pass and the misstep** (`take_position`, `start_position`, `ping_pong_step`): their rules, their Machines entry `position and pass` and how they work are in `docs/notes/lua/sequencer/pass.md` (skipped ticks advance by `take_position`; every position starts at `start_position`; a direction change ends the pass where the new direction wraps; a misstep's neighbor, from past the length and in ping-pong). Read it before changing them.
- **A step's slice** (3.7, design §3.5, ruling 32; package 2b): `slice` (whole 1..`S.lib.slices.SLICES.max`) reaches the `voices` output as `event.slice`. At the first hit, when the voice's slot has that slice (`S.lib.slices.voice_region`): on a voice set to one, or off, `apply_step` sets the own region (`S.lib.notes.set_own_region`) before the start or the retrigger, so the hit creates no node, the chord's notes carry the same `region`, and the region ends where the step's overrides end (`end_overrides`) and at the voice's next played step without one (only while it is still the one the step set). On an overlap voice the own note comes first (design §3.5, decision 23, the final review's I-2): the step's slice takes it as on one, a chord's step always so, unless another owner holds slot 1 or an earlier step's slice still rings on the own note to its end (`rings`: `step_region_to_end` true, the region playing to an end in one shot, and `M.playing_region` still naming it), so the own note never plays the voice's loop under a slice. Then the slice plays after the start, the retrigger and `play_chord`, through `S.lib.slices.play` with owner `"seq"`, key `"slice<step>"` (`SEQ.slice_key_prefix`), `extra_only` and `steals` (only the voice's own step slices: never another owner's slot), and is not the step's chord; while the own note's slice rings, every hit of the step is its slice's (`step_slices[voice].rings`): no retrigger (it would restart and accent the own note's slice), the slice's start is the hit (`S.lib.engine_sync.extra_note_hit(voice, slot, velocity, gate_seconds, "step")`), a ratchet plays the slice again in its slot, and a slice that finds no room (the pool at 0 or full), or a ratchet's whose note was stolen, takes the own note with its own slice (`take_own_slice`: the own region, `step_regions` and `step_region_to_end` as on one, and no step slice left, so the step's later hits are the own note's) before the retrigger, never restarting the ringing slice (#744); a one-shot one rings to its end; one that does not play to its end (wrap, bounce, a scan of 0) is released at the voice's next played step and at `end_overrides` (`release_step_slices`), so no step slice outlives the pattern. A slice the slot lacks changes nothing: the step plays as a plain step. While another owner holds slot 1 the step sets no region; each step's slice is a hit (`set_own_region(..., true)`, its scan restarts); `M.playing_region(voice)` gives the region the last played step set while it is still the own region, the voice runs and, in one shot, the scan has not played it out (`S.lib.playheads.finished`, the scan's own end: a restart of the scan, a jump or `S.lib.positions.restart_scan`, names it again, #740) (`S.lib.slices.playing` names it).
- **A chain link's move is `S.lib.scenes.next_slot`'s** (ruling 36; the groundwork's stepper): only `"repeat"` links nothing; every other move links its slot, the scene playing included. The chain never calls `validate_scene`: its list is `S.lib.scenes.playable_slots`, so an invalid scene is never drawn and no walk goes on from one (#738).

## Machines

### pattern clock
- **State:** `S.pattern_playing`, the transport's `S.pattern_clock` and the voices' `S.pattern_clocks[v]` (the running clocks' ids; nil while stopped), and a start the play key left waiting (`S.lib.quantize.waiting("patterns")`): `stopped`, `armed` or `playing`, named by `S.lib.sequencer.play_state()` (#876; it stores nothing), which SEQ's hint and the grid's play key read. The table's test keeps its own reading of the two facts.
- **Invariant:** `pattern clock`: playing exactly while the transport's and every voice's clock is recorded, each running and not retired; every retired clock still runs.
- **Test:** `test/unit/sequencer_test.lua`: "pattern clock: stopped + play key" (one test a row: `quantize_actions` on bar, the MIDI clock followed), and "an error in a step stops the pattern clock and shows it stopped (#243)".

A participant's wait and end (`wait_for`, `end_clock`, `finished`; this file's own code):

```
running -> waiting ("sync" or "sleep") for a beat on the count (the clock's beats + play.offset)
waiting -> running at a wake from 1/32 before its beat to under a 16th after it: it plays
waiting -> waiting at any other wake or a stale reference: the count kept, clock.sleep(0), a new wait
end_clock -> retired (resume may be posted; at its next wake it ends, playing nothing) or canceled
```

With `quantize_actions` off the play key starts at once. A step's error stops as the play key does (#243).

| State | Event | Next | Effect |
|---|---|---|---|
| `stopped` | `play key` | `armed` | `play at bar` flashes |
| `stopped` | `the bar` | `stopped` | nothing |
| `stopped` | `transport start` | `playing` | step 1 at once |
| `stopped` | `transport stop` | `stopped` | nothing |
| `stopped` | `cleanup` | `stopped` | nothing |
| `armed` | `play key` | `stopped` | the start taken back |
| `armed` | `the bar` | `playing` | step 1 on the bar |
| `armed` | `transport start` | `playing` | step 1 at once; the start dropped |
| `armed` | `transport stop` | `stopped` | the start dropped |
| `armed` | `cleanup` | `stopped` | the start canceled |
| `playing` | `play key` | `stopped` | at once, never quantized |
| `playing` | `the bar` | `playing` | the same clocks play on |
| `playing` | `transport start` | `playing` | every clock retired; step 1 at once |
| `playing` | `transport stop` | `stopped` | every clock ended |
| `playing` | `cleanup` | `stopped` | every clock ended |

### step holds
- **State:** per voice, this file's locals `overrides`, `last_played`, `chords`, `step_regions`, `step_region_to_end`, `step_slices`, `stepping` (a begun step's inputs until its first hit), 3.9's `held_values` (the values a voice's hits hold, `docs/notes/lua/lanes.md`; read through `held_value(voice, target)`) and `gate_sent`. No other accessor names them.
- **Invariant:** `step holds`: while stopped all but `gate_sent` are empty; `step_region_to_end[v]` implies `step_regions[v]`; `step_slices[v].step` is `last_played[v]`; every held value's param has a base override (its own, or a lock's over it); `gate_sent` holds only voices and lengths `gate_seconds` gives. A stop never empties `gate_sent`: it is the gate length the engine still holds (#639), set while stopped too.
- **Test:** `test/unit/sequencer_test.lua`: "step holds: the invariant names each hold it forbids".

No table of its own: a first hit sets them (the two machines below); every end is `end_overrides`'s (Must not break, above), but a held value's, which `docs/notes/lua/lanes.md`'s table `held values` walks (it outlives the steps without one; a length cut ends it only past its own step, and `end_held_values` ends it at a target, mode, source or type change, `end_held_value` a position value at a jump).

### slice decision
- **State:** the slices option (`one` stands for one or off), another owner on slot 1 (`held`, its key down), the next step's `notes` (`chord`), and an earlier slice ringing on the own note to its end (`rings`: `M.playing_region` in one shot).
- **Invariant:** none: every combination is legal; what it leaves is `step holds`'s.
- **Test:** `test/unit/sequencer_test.lua`: "slice decision: one, plain + first hit" (one test a row: voice 1 on four slices in one shot, step 2 on slice 2).

| State | Event | Next | Effect |
|---|---|---|---|
| `one, plain` | `first hit` | `one, plain` | the own region, then the retrigger |
| `one, chord` | `first hit` | `one, chord` | the region on every note; one retrigger |
| `one, held` | `first hit` | `one, held` | the slice dropped; one retrigger |
| `overlap, plain` | `first hit` | `overlap, rings` | the own region, then the retrigger |
| `overlap, rings` | `first hit` | `overlap, rings` | an extra slot, its start the hit, no retrigger; with no room, the own note's (#744) |
| `overlap, chord` | `first hit` | `overlap, chord` | the region on every note; one retrigger |
| `overlap, held` | `first hit` | `overlap, held` | the retrigger, then an extra slot if there is room |

### voice hit
- **State:** the voice running (`S.voices[v].active`) and gated (3.9: the gate rule's answer, `gate_wanted(v)`, the machine `step gate` in `docs/notes/lua/sequencer/modes.md`; these states set `v<i>_seq_gate` to accent or gate).
- **Invariant:** none: all four are legal; `gate_sent` is `step holds`'s.
- **Test:** `test/unit/sequencer_test.lua`: "voice hit: stopped, ungated + first hit" (one test a row: voice 3, a step gate of one step).

| State | Event | Next | Effect |
|---|---|---|---|
| `stopped, ungated` | `first hit` | `running, ungated` | `start_voice`: its `voiceOn` is the hit |
| `stopped, gated` | `first hit` | `running, gated` | the start, the step's gate, one retrigger |
| `running, ungated` | `first hit` | `running, ungated` | one retrigger, nothing else |
| `running, gated` | `first hit` | `running, gated` | the step's gate if it changed, one retrigger |

## The clocks

- **Participants**: one coroutine per voice (`S.pattern_clocks[voice]`) and the transport's (`S.pattern_clock`, counting 16ths: `S.pattern_position` is the next, `S.pattern_sounding_step` the one played last, both 1-16). `pattern_clock_start()` takes the start beat `b0 = clock.get_beats()`, loads the chain's first scene if the chain is on, then starts every voice (`restart_voice`: step 1 at once, inside `clock.run`) and the transport (its 16th 1 at once), in that order. A start while playing starts over.
- **A voice's ticks**: tick k falls on `anchor + k × division`, and every odd tick (the voice's 2nd, 4th, ... step since its anchor) `(swing - 50) / 50 × division` late. After each step the coroutine works out its next tick from the beat it played last (so a division or swing change applies from the next step, on the anchor's grid) and waits for it with `wait_for(state, target)`. Parity counts ticks, not step numbers, so an odd length never puts two swung steps in a row.
- **Position, direction and pass** (3.7, design §5.5; 3.9): `take_position` moves each voice by its `seq_direction` and `seq_misstep` and counts its passes: `docs/notes/lua/sequencer/pass.md` (How it works).
- **A step**: first a chain link due on its beat (`at_beat`: the first participant to reach a link's bar links, for all, once however late: `chain.next_beat` moves on by the periods that passed, from the participant's beat, and `chain_link(periods)` links once, #1051), then, at a bar of the count, 3.9's bar hooks (`on_bar(fn)`: `fn(first, bars)` at every `SEQ.bar_beats` from the start, in the order registered, once however late, `bars` the bars that passed; the start's own bar from `start_patterns`, `first` true, after its chain link and before the voices' clocks, the two run through `guarded`, so an error in either stops the patterns and is raised again; `play.next_bar`, nil while stopped; the letters' hook, `docs/notes/lua/pattern-letters.md`). A set step with a `cond` (3.7) plays only when `S.lib.conditions.test(voice, cond)` holds, tested before any draw; a set step with a `cond` or a `prob` under 100 records whether it played (`S.lib.conditions.record`). A set step with `prob` whose condition holds draws once (`math.random() × 100 < prob`; none for 100, nil or 0), then plays `hits = min(ratchet, max(1, floor(step_seconds / SEQ.min_ratchet_seconds)))` hits, `step_seconds` the step's own length (a swung pair's: `division ± swing`) × `S.lib.params_setup.beat_seconds_now()`, spaced `step_length / hits` (`wait_for` for each). Every hit is one event to every output. A step or hit skipped at a late wake (No bursts, above) draws nothing and plays nothing. 3.9: the `prob`, `ratchet` and `gate` read are their lanes' (`S.lib.lanes`: the step's own while a lane follows, its own cell while free), read once at the tick (`docs/notes/lua/lanes.md`).
- **The event** (design 8.10): `voice`, `step`, `hit`, `hits`, `first`, `level`, `velocity` (level / `MAX_STEP_LEVEL`), `notes` (a copy, or nil), `semitones` (each note through `degree_semitones`, worked out once per step as it plays, `step_semitones`; each hit's event a copy, or nil), `locks` (`{pos, pitch, size, bookmark}` as stored, only those set, or nil), `beat` (`clock.get_beats()` at the hit: the clock's beat), `gate_beats` (a gated voice: its gate's length in steps, the voice's `v<i>_seq_gate_length` or `SEQ.gate_length_default`, × division / hits; otherwise division / hits) and 3.6's `pitches` (package 0a, for the targets: a list of fractional MIDI notes, the step's chord's pitches as `step_chord` gives them when it has notes, else the voice's own pitch, both after the step's pitch lock: an input voice's lock is on the note's own param, so it is in the chord's base already; on a synth or buffer voice the lock is on `v<i>_grain_pitch`, which is a rate ratio (0.25-4, not semitones), and every pitch moves by the lock's distance from the standing grain pitch, `12 × log2(lock / stored)` semitones, the standing grain pitch itself never added (unlocked, the pitches are the chord's or the voice's own as they are); each hit's event a copy, a ratchet's hits the first's). What the `voices` output sends is untouched by it: the lock reaches the engine as the grain pitch's base override, as before.
- **One reckoning per step** (3.6): `begin_voice_step` works out the step's locks, the values they want and its chord once (`step_inputs`), before any output plays; the hits' `pitches` come from them (`step_pitches`) and the `voices` output's `apply_step` plays the same chord (`stepping[voice]`, consumed at the first hit), so the pitches the targets get are what the voices play, and an output that edits its event's `pitches`, `semitones` or `locks` changes neither the chord the `voices` output plays nor the next hit's.
- **The `voices` output**: at a step's first hit the locks are set (`set_base_override` on `v<i>_buf_pos`, `v<i>_grain_pitch`, `v<i>_grain_size`), the bookmark recalled (`S.lib.bookmarks.recall`, only when `is_set` and the bookmark lies inside `[loop_start, loop_start + loop_length)`, so the jump never resets the loop; Question 25) and the note set (a base override on `v<i>_freq` (synth), `v<i>_buf_rate` (buffer) or `v<i>_grain_pitch` (input, on the step's pitch lock), the stored value × 2^(semitones / 12), clamped; a synth voice's `scaleNote` follows the freq); the previous played step's overrides this one lacks are cleared first, and its chord's notes this one lacks released. The note is the chord's first, played through `S.lib.notes` (quiet; its `set_own` sets the override). Then a stopped voice is started (`start_voice`): its sends waited (a stopped voice's senders send nothing, the overrides are recorded), and the start carries the overrides in its first values, `voiceOn`'s and the `scaleNote` its sync sends (from `engine_base_value` of the freq) included, so its first grain plays the step's locks and note (#632). Then a running voice (and a just-started gated one) gets the gate length when it changed (gated) and `retrigger`, then the chord's further notes (`play_chord`; a later hit: the notes held in extra slots). It runs outside the outputs' protection (ruling 38), its `stop` too: every voice's chord released.
- **Notes** (design 8.4, plan ruling 22): degree k of a voice is the k-th tone above (below, for k < 0) the voice's pitch among the tuning's allowed tones (3.8: `S.lib.tuning.step`; the global scale's tones in twelve tones to an octave, every tone otherwise), its root included; `degree_semitones(voice, k)` is the distance. The voice's pitch is its freq as a note for a synth voice, and `S.lib.samples.rate_root(voice) + 12 × log2(rate)` (3.7: 60, or a buffer voice's file's key) for a buffer (`v<i>_buf_rate`) or input (`v<i>_grain_pitch`, the stored one, not the lock) voice. A pitch within `SEQ.tone_tolerance` (0.01 semitone) of a tone counts as on it. Where the allowed tones are an equal division (`S.lib.tuning.equal_step()`: the scale off in twelve equal steps, 19 equal, ...) a degree is exactly k steps from the voice's pitch (k semitones in twelve equal steps), so a voice tuned between two tones keeps its tuning (3.8 ruling 40). Strata's voices play the whole list as a chord (Must not break, above); outputs get the list.
- **The gate**: `gate_seconds(voice, step, hits)` is the step's `gate` (or `v<i>_seq_gate_length`) × the voice's nominal step (`division_beats × beat_seconds_now()`) / hits, clamped to 0.005-120 s; swing never changes it.
- **Division reset** (`seq_division_reset`, while playing): the transport's next bar (`anchor + 4 m` after its last 16th) becomes the reset beat. A voice whose next tick would pass it waits for the bar instead; one due on the bar starts its position there (`start_position`: its direction's first step, pass 1) with the bar as its new anchor; the transport, at the bar, restarts (`restart_voice`) every voice still on its old anchor (one that was waiting past the bar). `M.reset_armed()` (#921) is true while the reset beat is set: from the trigger to its bar, a start or a stop; SEQ's status line shows it.
- **Stop** (`pattern_clock_stop`, also the transport's stop, cleanup step 90 and the error path): every clock ended (`end_clock`), the playheads cleared, the reset and the chain's next link dropped, every override and chord ended, then (when the patterns played) every output's `stop`, `grid_redraw()` and `request_redraw()` (#921: the header's play mark, SEQ's status line and SETUP's count offset, whoever stopped them; SEQ stops animating with the patterns).
- **States**: the Machines entry `pattern clock`, above; the sounding steps are nil while stopped and before the first step plays. A clock that fails on its first run (which `clock.run` makes at once) leaves its id unrecorded, because `clock.run` re-raises before it returns, and its stop ends the clocks started before it.

## The chain (design 8.8)

- While `seq_chain` is on and the patterns play, every `seq_chain_bars` bars (counted by the transport from the start beat, on the bar) a populated, valid scene of `seq_chain_from .. seq_chain_from + seq_chain_scenes - 1` (slots wrap past `NUM_SCENES`) gives its patterns (`replace_pattern`), its `steps` block, 3.9's `lanes` block (`S.lib.lanes.apply_block`) and `variations` block (`S.lib.pattern_letters.apply_block`, a copy) and each voice's `SEQ.chain_keys` (`seq_length`, `seq_division`, 3.7's `seq_direction` and `seq_misstep`), and nothing else. 3.7 (design §5.4, 1e's review) and the groundwork's stepper: `next_chain_scene(current)` is `S.lib.scenes.next_slot(chain.current, S.lib.scenes.playable_slots(seq_chain_from, seq_chain_scenes), {seq_chain_next, seq_chain_previous, seq_chain_random})`, the list the range's playable slots (populated and valid, by `lib/scenes.lua`'s cache: no draw calls `validate_scene`) in range order. With no current scene (a start, the chain switched on) it is the range's first playable scene, with no draw: a start with the chain on loads it at once, held by the undo on SEQ (#922, Must not break); switching the chain on while playing links it at the transport's next bar. A current scene cleared or made invalid since it linked is not in the list, so the chain goes on to the next playable slot after it with no draw, as the scene sequencer does (ruling 29: clearing 3 of 1-4 moves on to 4 whatever the chances); otherwise the chances pick from the playing scene's place, random's draw among the other playable scenes alone, so an invalid scene is never drawn and never walked on from (#738). With the playing scene the range's only playable one, random keeps it (a repeat: nothing is loaded again). `chain_link` links the slot of every move but `"repeat"`, which links nothing (ruling 36). After a late wake past several periods (#1051) it makes a move a period from the place, each from the last (a draw each), and links once, the slot reached, unless every move was a repeat; the scenes between never load, as the letters' order moves by the bars that passed and switches once. The steps block's apply (`set_all_steps(steps, skip)`) leaves the voices in `skip` (a recall's released voices, #1050); a link passes none. At 100, 0, 0 (the defaults) the chain plays in order with no draw, as 3.6 did: after the range's last, its first (no other param, source, voice state or lock). Every override ends. SEQ's status line shows the chain's place (`M.chain_place()`, #921): `chain.current` and the whole bars from the sequencer's count (the clock's beats plus `play.offset`) to `chain.next_beat`, the bar in progress counted.

## Transport (#530, design 8.11)

- norns calls `clock.transport.start` and `stop` when the clock source starts or stops (matron's `clock_start_from_source` and `clock_stop_from_source`, for the source in use only): a MIDI start (on the first clock tick after it) or stop, a Link start or stop with PARAMETERS > CLOCK > link start/stop sync enabled, and PARAMETERS > CLOCK > reset on the internal clock (a start). At a start norns has already put the beat at 0 and every waiting sync on beat 0.
- With `follows_transport()` (the param on, the source MIDI, Link or crow), a start runs `pattern_clock_start()` at once (every voice at step 1 on the new beat 0, a running chain from its first scene), never through the quantizer; a stop runs `pattern_clock_stop()`. Both ask for a redraw. Otherwise a stop does nothing, and a start keeps the sequencer's own count through the reset while the patterns play (`play.keep_count`, rulings 47, 54 and 58, above) (which asks for a redraw, #921: SETUP shows the offset while the patterns play, so a jump a clock keeps redraws too); both then call the ones found at install. A followed start retires every clock and cancels none (`end_clock`'s `all_posted`, Ending a clock, above), so no resume matron posted after the reset reaches a coroutine norns no longer has. The play key (`pattern_toggle`) starts through `S.lib.quantize.schedule("patterns", pattern_clock_start, "play")` and stops at once; a press while that start waits takes it back (`S.lib.quantize.cancel("patterns")`), and every start (a followed transport start too) and every stop (`pattern_clock_stop`) drops a waiting start, so it never fires after them (#625).

## Operations

- `toggle_pattern_step(voice, step)`: an empty step on at `MAX_STEP_LEVEL`, a set one off, through `set_level`; a voice or step out of range does nothing.
- `clear_pattern(voice)`: every level 0 (the attributes stay); `randomize_pattern(voice)`: a random pattern at 50% density (per step `math.random() > 0.5`, then `math.random(RANDOM_STEP_FLOOR, MAX_STEP_LEVEL)`, in that order, so seeded tests keep their values).
- `S.lib.sequencer.replace_pattern(voice, steps)`: steps 1..`PATTERN_LENGTH` take `steps[step]` floored and clamped to 0..`MAX_STEP_LEVEL` (a missing or non-number entry is 0), then `S.seq_euclid[voice]` is forgotten (#923: only `euclid` sets it, after), the voice's overrides end and `end_step_gestures(voice)` runs. A voice outside 1..`NUM_VOICES` or a `steps` that is not a table does nothing. It redraws nothing: callers do.
- `S.lib.sequencer.euclid(voice, hits, rotation)` (design 8.5): the voice's first `seq_length` steps from `er.gen(hits, length, rotation)` (norns' `lua/lib/er.lua`, `require "er"`; `test/stub_er.lua` off the device), hits at `MAX_STEP_LEVEL` and the rest 0, through `replace_pattern`; the steps past the length and every attribute are kept. Any whole, finite hits and rotation: the hits clamped to 0..length, the rotation wrapped into 0..length - 1 (design 8.6), and that pair is `S.seq_euclid[voice] = {hits, rotation}`, set after its `replace_pattern`; any other whole-pattern change (a clear, a randomize, a paste, an undo, a recall, a chain link) leaves it nil. Nothing for a hits or rotation that is not a whole number. (3.9, #875: it no longer reads `S.scene_recall_in_progress`, which is true only across a recall's synchronous apply, where no turn of the euclid row can arrive.)
- `step_brightness(voice, step)`: at the voice's sounding step 15 for a set step and 4 for an empty one; past the voice's length `SEQ.past_length_level` (1) for a set step and 0 for an empty one; otherwise the stored level.

Bounds check before indexing:

```lua
function toggle_pattern_step(voice_idx, step)
  -- bounds checks keep the table from growing
  if voice_idx < 1 or voice_idx > NUM_VOICES then return end
  if step < 1 or step > PATTERN_LENGTH then return end

  -- safe to access
  S.patterns[voice_idx][step] = ...
end
```
