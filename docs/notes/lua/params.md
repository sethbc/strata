## Must not break

- Param ids are unique and prefixed (`strata_fx`, ...). norns has built-ins such as `reverb`, and the stub's system params make a collision fail.
- A group's size `n` equals the number of params that follow it. Groups cannot nest; the test stub errors on a group opened inside another, or one left short.
- The PARAMS menu order is the order of the `S.registry.params` records, and `init` runs each record's `add` in that order.
- A control param that reaches the engine stores its value and calls `send_param_to_engine` from its action, with a sender in `S.engine_senders` (`docs/notes/lua/engine-sync.md`).
- The actions of every param a randomize may set call `note_param_edit(param_id)`, so an edit ends the randomize undo (`docs/notes/lua/mutation.md`): the voice params `randomize_voice` sets (the synthesis params, `buf_pos`, `buf_rate`, `buf_scan`, `grain_size`, `grain_pitch`), the other grain and crossmod params a page randomize draws (`grain_density`, `grain_spread`, `grain_env`, `mod_speed`, `mod_amp_amt_<n>`, `mod_freq_amt_<n>`), `master_density`, `drift_amount` and the master filter's, delay's and reverb's (`filter_type`, `filter_freq`, `filter_res`, `delay_time`, `delay_feedback`, `delay_mix`, `reverb_mix`, `reverb_size`, `reverb_damp`; #557), and every registered voice param (`add_voice_extra`).
- `redraw_on_param_changes()` runs once, after the last param is added. A param added, or an action set with `params:set_action`, after it runs requests no redraws.
- The tempo handler is installed once (never chaining to itself) and given back only while the script's is still installed.
- **What is timed from the tempo right after a change reads `S.lib.params_setup.beat_seconds_now()`, and the tempo shown reads `clock_tempo_now()`**, never `clock.get_tempo()` or `clock.get_beat_sec()` alone (#567): `beat_seconds_now` times a synced take's length and delay (`lib/record.lua`) and so BUFFER's `len` field (through `take_length`); `clock_tempo_now` is the 256's tempo flash. They differ on Link: timing reads the session's own tempo there, the flash the param a key set. A clocked LFO's rate (`lib/lfos.lua`) reads `beat_seconds_now` too, so a tempo change reaches an engine-run LFO at once.
- The script never bangs its params, so Lua defaults are what the engine plays, and the filter and delay SynthDef defaults must equal the Lua param defaults (a test checks).
- The registries (`S.registry.voice_params`, `fx_params`, `param_filters`, `source_change`) are read at init, inside a params record's `add`, never at include time, so a module that registers can be included before or after this one.
- Nine registries are closed once init begins to read them (`S.close_registries()`, run by the first params record, `performance`): `voice_params`, `scene_fields`, `lfo_destinations`, `fx_params`, `start`, `menu_close` and 3.4's `scene_blocks`, `scene_migrations` and `pset_hooks`. A register function raises after that, naming the registry (#384), so a late record is never silently ignored. Register at include time. A record with a field outside the documented set is refused too, naming the field (#385).
- **The PSET actions run every PSET hook, each in its own `pcall`** (3.4): `params.action_read`, `action_write` and `action_delete` are installed once, by the master record (`pset.install_actions`), and a read runs `M.migrate_read_pset` first, then the hooks. A hook that raises prints `pset hook <name>: <error>` and never stops the next hook or the PSET's own read, write or delete. No other code sets the three actions.
- **The seven 3.4 menu records add nothing until their module exists** (`macros`, `morph`, `scatter`, `matrix`, `input`, `gestures`, `seq`, after `lfos`): each calls `S.lib.<module>.add_params()` only when that module is loaded and has the function, read at init. `seq` is the one with a second case (plan item 11): while `S.lib.sequencer` has no `add_params`, it adds the group `strata_seq` with `S.lib.quantize`'s `PARAM_COUNT` params alone (`quantize_actions`) when that count is above 0.
- A registered record's `add` (with its `add_first`, if any) adds exactly `count` params (an error names the record otherwise), and every key its `grain_keys`, `scene_defaults` and `voice_rows.rows` name is one of the params it added with `add_voice_extra`.
- Registered voice params are never on the 256 fader pages (`fader` is never true) and never touched by MAIN's randomize or the mutations: they live in `S.voices[i].extras`, which neither reads. A page randomize of their own VOICE section, through their record's `randomize` draws, is the one exception (#557).
- The fx group's size is its 11 params plus every registered fx record's `count`, and the registered fx params follow tape drift.
- Every number param a params record adds (Strata's own, never norns' system params) steps whole numbers through its own `delta` (#534): norns' PARAMS menu turns a param by `d / 20` while K3 is held, and norns' number param adds that unrounded, so without it `midi_device` raised and the mod sources, the sequence length and `record_beats` held fractions. `register_params` replaces each one's `delta` after its record's `add`, with one that rounds `d` away from 0 as norns' option param does; the same loop lists each one in `pset.number_params` for the PSET read hook (#554).
- A filtered synthesis param's own `delta` marks a turn (`turn_on_own_delta`, #318): norns' PARAMS menu turns E3 with the param object's `delta`, which never passes `delta_with_detent`.
- **PSETs keep their sound** (#314): every PSET saved holds the hidden number param `strata_pset_format` (`PSET_FORMAT`, 2), and `params.action_read`, set in the master record, runs `M.migrate_read_pset(filename, silent)` after every read. A file of a format below `PULSE_RES.pset_format` (no `strata_pset_format` line is format 1: saved before 3.3) gets the Pulse voice's `res` mirrored after the read when the file sets it (`PULSE_RES.mirror - res`, from the value the read set, so a PSET read again is never mirrored twice; keyed on a voice having a `res` param, not on voice 5); the hook then puts `strata_pset_format` back to `PSET_FORMAT`, so the next save writes today's format and is never mirrored. The mirror and the rounding go through `params:set` with the read's `silent`; the format reset is always silent (the param has no action). The console names each voice whose res was mirrored, and says nothing when none was. A test reads `\strataPulse`'s `RLPF` line from the engine source (comments stripped) and fails unless its mirror is `PULSE_RES.mirror` and its clip the param's range, so neither side can change alone. A later change of a param's meaning bumps `PSET_FORMAT` and adds its conversion to the hook, keyed on the file's format.
- **A PSET's number params load whole** (#554): after the read the hook rounds every number param a params record added (`pset.number_params`, collected by `register_params`: Strata's own and the registered voice params, never norns' system params) to its step, a whole number (`util.round`). A non-silent read runs each param's action with the file's value first (norns sets each line through the param's own `set`), so a number param whose action reaches the engine makes its value whole in the action, through `pset.whole(param_id, x)`, before storing or sending it, and writes a fraction back silently (the param shows what is stored, and the hook has nothing left to round or resend): the crossmod sources (`setModSource` carries an `"i"`, which matron casts: 0.05 - 1 was voice 1) and every number param `add_voice_extra` builds (the custom intervals, sent with `setGrainParam`). A new number param whose action reaches the engine does the same. The others (`tempo`, `scene_sequence_length`, `midi_device`, `record_beats`) reach no engine command with their value, and the hook rounds them.
- `S.performance` is never the constant `S.constants.STANDARD_PERFORMANCE` itself (a copy, or the table `lib/performance.lua` reads at init). A tier-dependent spec reads it when its param is added (`record_duration`'s maximum is `S.performance.buffer_seconds`).

## Owns

`lib/params_setup.lua` (`S.lib.params_setup`):
- the PARAMS menu: one `S.registry.params` record `{name, add}` per part (performance, master, mutations, scenes, fx, lfos, 3.4's macros, morph, scatter, matrix, input, gestures and seq, buffers, record, positions, midi, scale, voices), added with its local `register_params(name, add)`;
- the PSET read hook: the hidden `strata_pset_format` param (in the master record, after the `strata` separator), `params.action_read` and `S.lib.params_setup.migrate_read_pset(filename, silent)` (#314, #554), with the number params it rounds (`pset.number_params`, filled by `register_params` as each record's `add` runs);
- the PSET actions (3.4): `params.action_read`, `params.action_write` and `params.action_delete` (`pset.install_actions`, from the master record), which run the PSET hooks (`S.registry.pset_hooks`, below);
- `add_voice_params`, `get_param_spec` (a copy of an entry of one table built once; a name with no entry is an error, #315, and every spec carries its display units, `s`, `Hz`, `/s` or `x`, and the params whose step is finer than 0.01 a three-decimal formatter: display only, never a value, #386, #387), `redraw_on_param_changes`;
- `S.fx_last_mix` (`{filter}`: `filter_mix`'s action stores the mix when it rises and `toggle_filter_mix` (FX's K3 on a filter row) stores the mix at the press, which K3 restores from 0; the delay and reverb keep their mix through their bypass params) and `fx_fader_changed` (the grid's FX faders);
- the tempo-follow handlers `follow_clock_tempo`, `install_tempo_change_handler`, `restore_tempo_change_handler`;
- `S.lib.params_setup.beat_seconds_now()` (a beat's length, for timing) and `clock_tempo_now()` (the tempo to show), below;
- the readers of the voice-param, fx-param, param-filter and source-change registries (below), and `S.lib.params_setup.add_voice_extra`;
- `S.performance` (the tier's values, standard until `lib/performance.lua` fills it at init);
- cleanup step 10: the tempo handler given back.

## Parameter system

Every adjustable value is a norns param:
1. Defined in its `S.registry.params` record with `params:add{}`, run from `init()`.
2. With an `action` function that updates the engine.
3. Read with `params:get("id")`, set with `params:set("id", value)`.
4. Grouped with `params:add_separator()`, or `params:add_group(id, name, n)` for a collapsible section (`strata_fx`, `strata_lfo_<n>` per LFO, `strata_buffers`, `strata_midi`).

Menu order:
- `strata` (the hidden `strata_pset_format`, master density, tempo), `strata_mutations` (named `mutations`), `strata_scenes` (named `scenes`);
- the fx, LFO 1-6, input (`strata_input`, `lib/input_level.lua`) and buffers groups, then the `strata_record` and `strata_positions` groups, the `midi` group and the `scale` section;
- then each voice's synthesis (after any registered record's `add_first` params), granular and cross-modulation sections, and, when any voice-param record is registered, its `voice <i> extras` section.

## Registries

`lib/state.lua` holds the registries and their register functions; each checks its argument and refuses a duplicate name. This module reads four of them at init (scenes, the LFOs and VOICE read the rest: `docs/notes/lua/scenes.md`, `docs/notes/lua/lfos.md`, `docs/notes/lua/ui/field-list-and-cursors.md`).

**Voice params** (`S.register_voice_params(record)`, `S.registry.voice_params`). A module's per-voice params, as one record:

```lua
{ name = "freeze", count = 2, add = function(voice_idx) ... end,
  add_first = nil,             -- optional fn(voice_idx): params a PSET must read before the built-in ones
  grain_keys = { freeze = "freeze", freeze_mode = { name = "freezeMode", value = function(x) return x - 1 end } },
  sync = nil,                  -- optional fn(voice_idx): the voice sync's sends after grain_keys (setGrainParam only)
  scene_defaults = { freeze = 0, freeze_mode = 1 },   -- each the param's default
  discrete = { freeze = {0, 1}, freeze_mode = {1, 2} }, -- whole range; the other scene keys crossfade
  voice_rows = { section = "mix", rows = {"freeze", "freeze_mode"}, when = nil, before = nil },
  layout_states = nil,         -- optional {{name, setup = fn(context)}}
  normalize_scene = nil,       -- optional fn(extras): a loaded scene's values made consistent (migrate_scene)
  fader = false }
```

- `add_voice_params(i)` adds, after the cross-modulation params, a separator `voice <i> extras` and then each record's params, in registration order, through its `add(i)`. A record may also have `add_first = fn(voice_idx)`: its params come right after the `voice <i>: <name>` separator, ahead of the synthesis params, because norns reads a PSET line by line in param order and a filter on a built-in param may read them (variation's `quantize`, read by the `freq` filter: #125). Both add with `add_voice_extra`, and together they add exactly `count` params.
- `add` calls `S.lib.params_setup.add_voice_extra(voice_idx, record, key, param)` for each param: `param` is a `params:add` table without an `id` (its own `action`, if any, runs last). The param's id is `v<i>_<key>`. Its action:
  1. runs `S.registry.param_filters[key]` (a changed value is written back with `params:set(id, v, true)`);
  2. stores the value in `S.voices[i].extras[key]` (`add_voice_params` makes `extras` fresh at each init);
  3. calls `note_param_edit` and `send_param_to_engine`;
  4. runs the param's own action.
- A key in `grain_keys` gets an `S.engine_senders` entry: `setGrainParam` with the engine name (and `value(x)`, if given), only while the voice runs. `sync_voice_values_to_engine` sends every record's grain keys (by key name) and then its `sync` (`docs/notes/lua/engine-sync.md`). A start sends them before `engine.voiceOn`, with the other grain values, so a record's `sync` sends grain params only (`setGrainParam`): `voiceOn` resets the voice-level controls, and a test fails on anything else before it (#325). The variation record's (the intervals and `scaleNote`) and the bookmarks record's (`scrubRate` 0 and `scanHold` 0) do.

**Param filters** (`S.register_param_filter(key, fn)`, one per key). `fn(voice_idx, value, previous, turned) -> value` runs in the action of every `v<i>_<key>` voice param, the synthesis params (`param_order`) as well as registered ones, before the value is stored. `previous` is the value stored before; `turned` is true when the set is a turn of this param (`S.turning_param == id`: an encoder detent or arc tick through `delta_with_detent`, a mutation step, or the param's own `delta`, #318; `docs/notes/lua/ui/detents-and-fine.md`). A synthesis param whose key has a filter gets a `delta` that marks the turn (`turn_on_own_delta`), since norns' PARAMS menu turns E3 with the param object's `delta` and `params:delta` calls it too. 3.2's quantized `freq` uses it; the loop filters ignore `turned`.

**Source change hooks** (`S.register_source_change(fn)`). `fn(voice_idx, source)` runs in every `v<i>_source` action right after the source is stored and sent, before the voice's sync and the grid redraw (so the sync sends what the hooks set: a switch never sends the old freeze first), except while `S.scene_recall_in_progress`: a recall sets every value itself. 3.2's freeze clears itself through one.

**Fx params** (`S.register_fx_params({name, count, add})`). The fx group's size is 11 plus every record's `count`; init runs each `add()` after tape drift, in registration order, and checks the count.

**PSET hooks** (`S.register_pset_hook({name, write = fn(path_base, number), read = fn(path_base, number, pset_path, silent), delete = fn(path_base, number)})`, each function optional; 3.4, for the per-PSET side files of the macros, the matrix and the recorders). The master record installs norns' three PSET actions (`lua/core/paramset.lua`), which run the hooks in registration order:
- `params.action_read = function(filename, silent, number)`: `M.migrate_read_pset(filename, silent)` first, then every hook's `read(path_base, number, filename, silent)` (a hook that sets params passes `silent` on, as the LFOs' 3.3 import does);
- `params.action_write = function(filename, name, number)`: every hook's `write(path_base, number)`, after norns has written the PSET;
- `params.action_delete = function(filename, name, number)`: every hook's `delete(path_base, number)`, after norns has deleted it.
- `path_base` is `filename` without its `.pset` (`<data>/strata/strata-01` for PSET 1). `number` is what norns passes: the PSET's two-digit number (`"01"`) for a PSET the PARAMS menu writes, reads or deletes, nil for one a script reads or writes by path. Each hook runs in its own `pcall`: one that raises prints `pset hook <name>: <error>`, and the next still runs.

**3.4's menu records** (package 0a, design §0.1): seven records after `lfos`, in menu order, `macros`, `morph`, `scatter`, `matrix`, `input`, `gestures` and `seq`, each calling its module's `add_params()` (`S.lib.macros`, `S.lib.morph`, `S.lib.scatter`, `S.lib.matrix`, `S.lib.input_level`, `S.lib.gestures`, `S.lib.sequencer`) when that module is loaded and has one, and adding nothing otherwise. So no later package edits this file: a module gets its place in the menu by having `add_params`. `strata_seq` is shared (plan item 11): the sequencer's `add_params` adds the group, 6 + `S.lib.quantize.PARAM_COUNT` params, and calls `S.lib.quantize.add_params()` for its fifth; until the sequencer has one, the `seq` record adds `strata_seq` holding quantize's params alone (`docs/notes/lua/quantize.md`). `macros` adds `strata_macros` (16, `docs/notes/lua/macros.md`), `scatter` adds `strata_scatter` (8, `docs/notes/lua/scatter.md`) and `gestures` adds `strata_gestures` (8, `docs/notes/lua/gestures.md`).

**`S.performance`** (`{tier, buffer_seconds, max_grains, history_seconds}`). This module's constructor sets it to a copy of `S.constants.STANDARD_PERFORMANCE` (standard: 16 s buffers, 128 grains, 16 s of input history). lib/performance.lua fills it at init (`read_active`), from the `"performance"` params record, which runs before any param is added ([performance.md](performance.md)). Every tier-dependent spec reads it as its param is added: `record_duration` goes from 0.5 s to `S.performance.buffer_seconds`.

## Tempo

- The script's `tempo` param is initialized from `clock_tempo`, with its range, read with `param_range("clock_tempo")`: 1-300, so a scene captured at any clock tempo recalls it exactly.
- Its action sets `clock_tempo`. Grid tempo buttons adjust `tempo`. The pattern clock only syncs (`docs/notes/lua/sequencer.md`), so external clock sources still work.
- `install_tempo_change_handler()` (from `init`, in the master params record) installs the global `follow_clock_tempo` as `clock.tempo_change_handler`.
  - It keeps the previous handler in `previous_tempo_change_handler`, a local of the module (#394), and calls it after its own work.
  - Installing again is a no-op, so the handler never chains to itself.
- `restore_tempo_change_handler()` (from `cleanup()`, step 10) puts the previous handler back only while the script's is still installed, so a handler installed after it stays.
- A tempo set elsewhere (PARAMETERS > CLOCK, an external source) is thus mirrored into `tempo` silently, clamped to the param's range (an external source's tempo reaches the handler unclamped).
- So scenes and grid buttons always start from the playing tempo.
- `beat_seconds_now()`, for timing (take lengths, sync delays), is a beat's length in seconds from now on (#567): `60 / params:get("clock_tempo")` when `params:string("clock_source")` is `internal`, otherwise `60 / clock.get_tempo()`.
  - On the internal clock `clock_tempo`'s action sets the clock at once, while `clock.get_tempo()` lags: matron's clock thread publishes a tempo from its tick after next (one tick at the old tempo plus one at the new, 1/24 beat each: about 42 ms at 120 BPM, about 0.9 s going to 3 BPM).
  - On Link, MIDI and crow the param is a whole BPM (an `add_number`) that norns' clock refreshes from the clock's tempo only once a second (`lua/core/clock.lua`): a fractional Link session would be timed off on every pass (16 beats of a 123.45 BPM session timed at the param's 123 are 29 ms too long), and a peer's or an external clock's change would be stale for up to 1 s. So timing reads the clock there.
- `clock_tempo_now()`, for showing the tempo (the 256's flash), is `params:get("clock_tempo")` on `internal` and `link`, the tempo a key set, otherwise `clock.get_tempo()` (MIDI and crow ignore the param).

## Registering params

- **Registering a param group**: one `register_params(name, add)` call in `lib/params_setup.lua`, at its place in the PARAMS menu (the registration order is the menu order). Keep the group's body in the owning module where you can, and call it from `add` (as the "lfos" record calls `add_lfo_params`).
- **Registering per-voice params** (3.2's freeze, variation, loops, history, voice filter and sends): one `S.register_voice_params(record)` call in the owning module's constructor; nothing central lists the params. The record is `{name, count, add = fn(voice_idx), add_first = fn(voice_idx), grain_keys, sync, scene_defaults, discrete, voice_rows = {section, rows, when, before}, layout_states, normalize_scene = fn(extras), fader = false, randomize = {key = fn(voice_idx) -> value}}` (`randomize`, optional: the keys a press of ALT+K2 on their VOICE section randomizes, each with its draw, called with the voice's index, #557). `add` adds exactly `count` params, each with `S.lib.params_setup.add_voice_extra(voice_idx, record, key, param)` (id `v<i>_<key>`, value in `S.voices[i].extras[key]`); they follow the voice's cross-modulation params under a `voice <i> extras` separator, except the optional `add_first`'s, which come ahead of the voice's synthesis params: norns reads a PSET in param order, so a param that a built-in param's filter reads must load first (variation's `quantize` before `freq`, #125). Its grain keys reach the engine through their senders and the voice sync, its scene keys are captured, crossfaded (or, `discrete`, set at the end after the source), validated and migrated (`normalize_scene`, if any, makes a loaded scene's values consistent), its rows join the VOICE page (a binary param is a `"binary"` row) and its `layout_states` VOICE's. Registered params never reach MAIN's randomize, mutations or the 256 fader pages; a page randomize of their own section (`randomize`) is the one exception.
- **Registering the other shared spots**: `S.register_scene_field({id, default, discrete, set})` (a global scene field, read after `SCENE_GLOBAL_PARAMS`; `set = fn(value)`, optional, 3.4, is what a recall, a transition step and `apply_entries` call in place of `params:set`), `S.register_pset_hook({name, write, read, delete})` (above), `S.register_source_change(fn(voice_idx, source))` (runs in each `v<i>_source` action once the source is stored and sent, before the voice's sync, never during a scene recall), `S.register_param_filter(key, fn(voice_idx, value, previous, turned) -> value)` (one per key; every `v<i>_<key>` action applies it before storing), `S.register_lfo_destination(label, suffix)` (`v<i> <label>`, after every built-in destination, by registration then voice, so stored indices keep their meaning) and `S.register_fx_params({name, count, add})` (the fx group grows by `count`; its params follow the 11). Each is one line in the owning module.
