## Must not break

- Every page draws the header at y=8 and the hint row at y=62. No two strings on a row overlap and nothing leaves 128×64. The layout tests check it on every page record with every voice, source, ALT state and flash, and each record's `layout_states` (the part files `test/unit/ui_layout_<part>_test.lua`, which `test/unit/ui_layout_test.lua` checks draw every case once). A page adds layout states only through its record's `layout_states`.
- The layout tests catch only strings that overlap on the same baseline, text off-screen, header rects under header text, the hint row and the MAIN divider. They do not catch strings on nearby baselines that collide, nor text drawn over a rect or a line in the page body: look at the page renders (Page renders below) for those.

## Layout tests

`assert_screen_layout(context, where)` (`test/helpers.lua`) checks one drawn screen:
- no two strings on a row overlap, and nothing leaves 128×64 (measuring with norns' font advances, `stubs.text_width`: `docs/notes/test-harness/stubs.md`);
- the page title at 0,8, then one page dot per page (ten 2×2 rects at x 32, 36, ..., 68, the first at least 4 px after the title; FX's a 2×5 bar exactly while `S.lib.fx_hold.any_frozen()`, 3.8; every header rect over the dots' span must be one of them, so a rect of another shape there fails), or, while a header flash shows (`S.lib.ui_flash.text("header")`), its text at 40,8 and no dots;
- a string with a descender (g, j, p, q, y) has no string it overlaps horizontally less than 7 px below it (the font draws 2 px under the baseline; #422);
- no header rect (a dot, the play mark: rects above y 9) lies under a header string;
- a hint row is drawn at y=62;
- on MAIN every string between the header and the hint row ends by x=60 or starts at x=65 or later (never across the divider).

The layout check runs it on every page record with every voice (1-7), source (synth, buf 1, input), ALT state (up, down) and flash (none, a long header flash, the longest hints flash), then on each record's `layout_states` (each on a fresh script, with ALT up and down). It is split by page across five unit files so a run's processes, and a CI shard's, share it (#1001): `test/layout_parts.lua` (`require("layout_parts")`, test-side as `test/notes_model.lua` is) holds the loops and its `PARTS`, and each `test/unit/ui_layout_<part>_test.lua` registers one part's test (`pages_1`: MAIN, SEQ, FX, LFO and MOD; `pages_2`: BUFFER, SCENES, SETUP and IO; `voice_1` to `voice_3`: VOICE, its grid cases with `voice_1` and its layout states one in three each, since its 542 states are the weight: a fresh script each). A part that starts after MAIN first sets every voice's source to the last one, as the earlier pages' loops left them when one test drew every page. `test/unit/ui_layout_test.lua` runs every part file's test with the draws counted, not made (`draw_case` and `draw_state` replaced), and fails unless together they draw each case of the full product and each record's states with ALT up and down exactly once: a page left out of `PARTS`, a page in two parts or a state skipped or drawn twice fails it. Its probe (a state a record lists is drawn, with ALT up and down, each on a fresh script) runs against FX's states alone. `test/unit/ui_layout_test.lua` also keeps the older every-page checks (the widest SETUP page with four grids, the voice list's last row above the hint row). Each page's own layout tests are in its unit file (`pages_main_test.lua`, ...); the header and flash tests in `test/unit/ui_header_test.lua`.
- Keep them passing when adding text. The widths are `stubs.text_width` in `test/norns_stubs.lua` (norns' font advances; it counts UTF-8 characters, not bytes), which the screen stub also uses for `screen.text_extents` (returns width, 8).
- The stub records each string's `x`, `y`, `align` (`left`, `right`, `center`) and `level`, and each rect and line with `filled` (true after `screen.fill()`, false after `screen.stroke()`).
- The stub's `UI.ScrollingList:redraw` is the real one from `lua/lib/ui.lua`, so the list's entries are recorded like any other text (an empty string where the list scrolls past an end).

## Page renders

Run on demand, never in `lua test/run.lua`: `lua test/render_pages.lua <dir>`, then `python3 test/render_pages.py <dir> --font <path to a .ttf>` (Pillow).
- `test/render_pages.lua` loads the script through the stubs (it requires `test/helpers.lua`) and, for each state, on a fresh script after startup, shows the page, runs the state's setup and writes `<page>-<state>.json`: the page and state names and every text (`x`, `y`, `text`, `align`, `level`), rect (`x`, `y`, `w`, `h`, `level`, `filled`) and line (`x1`, `y1`, `x2`, `y2`, `level`, `filled`) the draw made. Its states are its own `STATES` (MAIN synth, buffer, input, ALT and a header flash; VOICE; SEQ playing; FX; LFO; BUFFER and BUFFER recording; SCENES; SETUP), then each page record's `layout_states`. As a module it returns `render_page_states(out_dir)`, which returns the file names it wrote. Each state runs on its own fresh script and is ended by `cleanup()`, which the layout tests never run after a state; a state whose page, setup, draw or cleanup raises fails the dump with `<PAGE> state <name>: ` and the error's traceback (#860), so one line of a run's output names the state. A record's states are counted, with their names, in one load and each is run by index in a fresh one: the fresh load's state must bear the counted name, or the dump fails naming both (a source edited since the count), never writing one state's draw under another's name.
- `test/render_pages.py` draws each JSON file as a 128×64 PNG beside it, scaled 4× without smoothing (an RGB copy through `Image.transform`, since `Image.resize` fails on Pillow 12.3.0, #665; the script is known to run on Pillow 12.3.0, the version run when it was fixed, and CI never runs it): levels as grays, rects filled or outlined, texts at their baseline (left, right or center) in the `--font` file at 8 px. Without `--font` it uses `~/src/norns/resources/norns.ttf` (norns' 04B_03) when it exists, else Pillow's built-in font.
- The suite's test "the render dump writes one file per page state" (`ui_layout_test.lua`) runs `render_page_states` into a temporary folder: at least 13 files, each well-formed JSON naming a page from `UI_PAGES`, and a render of every page; "a render dump failure names the page state that failed" checks a probe state's error names it, and "a render dump state shifted after the count fails, naming both" a state slipped in after the count. #860's one failure (its detail lost) did not recur in 144 dumps (24 at a time, 12 at once, Lua and LuaJIT runs side by side, three rounds) and two `ui_` runs at X14's head: the dump's inputs are deterministic but for `pairs` order, which Lua 5.3 seeds per process (the stub's `util.time()` and clocks are virtual, `math.random` starts from one seed, the JSON's keys are sorted, each process's data folder is its own). What does fail it is a source edited while a run goes: the dump, the layout tests' `check_layout_states` and mutation_test's randomize check count each record's layout states in one load and run them by index in fresh loads, each reading `lib/` again, so a state added, moved or removed in between runs the wrong state or none (seen in Y7's own LuaJIT run, a VOICE state added mid-run; X14's failure came while it was editing VOICE's layout states). Edit nothing while the suite runs.
