## Must not break

- **Nothing by default**: with every param at its default no message goes to any port. A voice is routed only while `v<i>_out_port` is above 0, a CC slot sends only while its source is not `off`, and program change in and out are off.
- **One door**: every message goes through the vport `S.lib.io_ports.out(port)` gives (`note_on`, `note_off`, `cc`, `pitchbend`, `channel_pressure`, `program_change`); `S.lib.io_ports.device(port)` says whether a device is there. The module never reads the `midi` global and never sets anything on a vport.
- **An off for every on**: each sounding id keeps the port, channel and note its on went to, and its off goes there whatever the params say by then. Ids on one port, channel and note are counted, and the note off goes when the last ends. A route param's change that changes the route calls `S.lib.io_targets.route_changed(voice)` once, before the zone follows, so the old notes' offs go out first. The route is what a note's destination or the zone depends on: off, or the port with its channel (plain) or its members (MPE); a change that leaves it alone (a channel while the port is 0, members on a plain voice, a channel on an MPE voice) ends no note, on MIDI or any other target (review finding 2).
- **A played note is never sent back to the port it arrived on** (ruling 17): a note with `info.source == "midi"` is skipped when the voice's port is the `midi_device` param's.
- **One MPE voice a port, in its lower zone** (decision 20): a change of a voice's mode, port, channel or members that would put a second MPE voice on a port, or a plain voice's channel inside an MPE zone on its port (1 to members + 1), is put back silently to the value the module last applied, with the header flash `port has an mpe voice`. The invariant `midi out` holds it.
- **A PSET's routes are judged as a whole** (ruling C): norns' read sets the route params one at a time in file order, so the per-param check can refuse part of a legal file (a plain channel still at its default inside a zone; two MPE voices swapping ports). The module's PSET hook (`io_midi_out`) then reads the file's port, channel, mode and members for all seven voices (a param the file has no line for at its default, as the read's migration leaves it, #628) and judges them together. Legal: every voice ends exactly on the file's values, whatever the order of the lines, and a refusal flash the read's own order caused is cleared. Not legal (a file edited by hand): the voices are placed in index order, a voice that conflicts with those placed before it gets port 0 and keeps its other values, and the read shows the flash once. Each voice whose route then differs from what the module had gets one `route_changed`; every zone that went is taken down before any that came or moved is set up, so a swap ends set up on both ports. The per-param refusal still acts for every change outside a read; during a read it may refuse and flash as before, and the hook puts the whole set right. A silent read sets the route params silently to the judged values and applies nothing, as norns' silent read runs no action: the module plays its old routes, and sends nothing, until a route param next changes.
- **A played MPE note's first values go before its note on**, on its member channel and in this order: pitchbend, channel pressure (when it has one), CC 74 (when it has one), read from `S.lib.expression.raw(voice, owner, key)`. That read works at the note on because `lib/midi_in.lua` calls `S.lib.expression.first_touch` before `S.lib.notes.play` (ruling A, `docs/notes/lua/expression.md`). A step note gets a centered bend (8192) before its note on and no expression.
- **Later values are read, not waited for** (ruling B): the LFO step hook reads `raw` for each sounding played MPE note and sends each of bend, pressure and slide whose outgoing value differs from what that note last sent, at most `MIDI_OUT.express_per_step` (24) messages a step, round robin from the note the last step stopped at, always the value current at the send. The note hook `expressed` fires only when a voice's own mapped values change (`lib/expression.lua`'s `hand_over`), so a pressure or slide the voice maps to nothing would never reach the target through `express`; a played note's bend, pressure and slide go out whatever the voice's mapping, which decides only what Strata's engine does with them. So the target has no `express` field. A step reads `raw` once for each sounding played MPE note and keeps none of its tables across steps. Those notes number at most 23: each MPE voice (one a port, so up to all seven) holds its own note in slot 1 and extra notes from the pool all voices share, at most `NOTE_POOL.max` (16) together (`S.constants.NOTE_SLOTS` caps a voice at 8 notes, 7 extra): 7 + 16, with every voice MPE on a port of its own and the pool at 16 (11 at the standard tier's default pool of 4, 15 at the high tier's 8). The bound of 24 messages a step holds whatever the count. A note that ended sends nothing more.
- **A device's return gets all notes off** (Review Focus 2): CC 123 on each channel the module had notes on as the device left or has now, then the MPE setup of a voice on that port; a channel that never had a note gets none. Expression a note sent while its device was gone is not sent again: after that all notes off no note it played is held on the device, so nothing is owed.
- **Program change in is not echoed** (Review Focus 3, ruling D): each input port has at most one guard, `asked[port] = scene`, set by `program_change_in(port, value)` before it asks `S.lib.io_actions.recall_scene(value + 1)` (with quantize off the recall lands inside that call) and dropped at once when the recall is refused (an empty scene); a newer program change in on the port replaces it. The first `scene_recalled(n)` for that same scene consumes it and sends nothing on that port; a recall of any other scene meanwhile sends its own program change and leaves the guard, so the quantized recall it waits for still does not echo when it lands. The cost: if the scheduled recall never lands (replaced or canceled), the next recall of that scene sends no program change on that port, once. Not echoing wins, because two devices that each echo would loop.
- **Params are PSET-only**: none is a scene field, a macro target, an LFO destination, a fader-page param or drawn by a randomize or mutation. The CC slots' sources are kept by key (`S.lib.io_keyed`, ruling 24).
- **Hooks and targets never yield** and never call `S.lib.notes.play`.

## How it works

- **The route** of each voice is kept as applied (`config`): the param actions check the proposed routes (`conflict`), then apply, end the voice's notes and move the zone. Setup, sent when the mode turns on, the port or the members change, the bend range changes or the port's device arrives: `cc(101, 0, 1)`, `cc(100, 6, 1)`, `cc(6, members, 1)`; `cc(101, 0, 2)`, `cc(100, 0, 2)`, `cc(6, bend_range, 2)`; `cc(101, 0, 1)`, `cc(100, 0, 1)`, `cc(6, 2, 1)`. Takedown, when the mode turns off or the port changes or goes to 0, on the old port: `cc(101, 0, 1)`, `cc(100, 6, 1)`, `cc(6, 0, 1)`.
- **Plain**: note `clamp(round(pitch), 0, 127)`, velocity `max(1, round(velocity * 127))`, on the voice's channel.
- **MPE allocation**: the free member channel released longest ago; with none free, the one with the fewest notes, and among those the one given a note longest ago. A bend is `clamp(round(8192 + 8192 * 12 * log2(bend) / bend_range), 0, 16383)`; pressure and slide `round(value * 127)`.
- **CC out**, from the step: each slot whose source is not `off` and whose port has a device sends `cc(number, round(fraction(key) * 127), channel)` when the value differs from its last, at most 8 a step. A slot's settings changing, or its port's device arriving, sends it again at the next step. A slot following an LFO the engine runs shows ` ~` on IO: it sends Lua's model of it (decision 20).
- **Program change out**: with `midi_pc_out` on, each recall sends `program_change(scene - 1, midi_pc_out_channel)` on `midi_pc_out_port` (a fade tells the hook at its first step), unless a guard of that port names the scene (above).
- **Cleanup** (143, after the targets' 142 sent every off): `stop()` drops the express queue and the module sends nothing more.

## IO

- The target's `rows(voice)`: one `detail` row `midi` in the `voice` section (text `off`, `port 2  ch 3` or `port 2  mpe 15`; fields port, channel, mode, members).
- The section `midi` (title `midi out`): a `param` row `bend range`; eight `detail` rows `cc 1` to `cc 8` (text `off` or `lfo1  p2 ch3 #20`, fields source, port, channel, number); five `param` rows `pc in`, `pc channel`, `pc out`, `pc out port`, `pc out channel`. Status `[--]` when a port some setting sends on has no device. Layout states: `without its device`, `with its device` (each with an MPE voice, a plain voice, a slot and program change out set) and `a detail list open` (`cc 1`'s).
