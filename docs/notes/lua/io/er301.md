## Must not break

- **Every message goes through `S.lib.io_ii`** (`send`, `send_off`), never to crow directly. The module reads `S.lib.io_ii` at each call: where it is absent, or its params were never added, `routed` is false, `rows` is empty and nothing is sent. `routed` is also false while `S.lib.io_ii.leads()` is not, as Just Friends' and W/'s are, so a voice routed only here is not available under `off` or `teletype`, and the targets core records the device on no note that sent nothing.
- **A port is one line that plays one note at a time, whatever voices feed it** (build ruling 10): `lines[port]` holds the sounding notes across voices, oldest first, each with its voice, id and pitch. The newest note's pitch is the port's cv (`volts(pitch)`, clamped to -10 to 10), then its trigger goes high. When the newest ends and others remain on the line, the cv goes to the newest left, whichever voice it belongs to, and no trigger is sent; the trigger goes low (`send_off`) once, when the line's last note ends. A second note on sends the cv and the trigger again. A note stays on the port it started on until it ends, even if its voice's port param changes.
- A note joins its port only when the ii queue accepts its trigger. The queue admits the pitch and trigger together. A refused note leaves the earlier notes owning the gate. A refused return pitch is retried while its note is still current (#1191, #1240, #1241).
- **Bookkeeping never goes negative or keeps an id that ended**: `note_off` for an id that never started (a `note_on` that raised, a repeat) sends nothing; a `note_on` for a sounding id replaces it; `stop_all` empties every line and lowers each port's trigger once.
- **A `note_on` whose send raises leaves the line and the device as they were** (best effort): the note is added only after the sends return; then, each send protected (a raise during the repair is swallowed), the newest note left on the line gets its cv sent again (no trigger repair exists: the trigger is sent last, and one whose own send raised was not sent); the send's own error is raised again. The targets core records a target for a note only when its `note_on` returned, so no `note_off` would ever come for it. A route change ends the voice's notes on the ports they started on. The param action records the applied port and calls `S.lib.io_targets.route_changed(voice)`. After a silent PSET read, the `io_er301` hook compares each added port with its applied value and runs the same change for each port that moved.
- **No `ready`, no `release`**: the device needs no setup. The bus leaving ends its notes through the targets core (`end_target`).

## Owns

- `lib/io/er301.lua` (`S.lib.io_er301`): `ER301` (every tunable), the note target `er301`, the ii device `er301` (7 params; `ports = true`: every command with an argument takes the port first, so the ii queue gives each port one turn, `docs/notes/lua/io/ii.md`), the row `er-301` (marked `ER301.idle_mark`, `[idle]`, while it names a port and Strata does not lead the bus, #937).
- Tests: `test/unit/io_er301_test.lua`, against a double of `S.lib.io_ii` and the real ii queue with a crow stub.
- User page: `docs/user/io/er301-txo.md`.

## Params

`v<i>_out_er301` for voices 1 to 7: 0 off, port 1 to 100 (0). PSET-only, no scene, no engine sender. Shown as `off` or `port <n>`.

## Messages

Per `docs/design/3.6-facts/crow-ii.md` section 2 (crow's `lua/ii/er301.lua`): `ii.er301.cv(port, volts)` and `ii.er301.tr(port, state)`. A note on is `send("er301", "cv", port, volts)` then `send("er301", "tr", port, 1)`; the last note's off is `send_off("er301", "tr", port, 0)`.

Unverified on the device until the 4.0 hardware check.
