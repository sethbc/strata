## Must not break

- **Every message goes through `S.lib.io_ii`** (`send`, `send_off`), never to crow directly. The module reads `S.lib.io_ii` at each call: where it is absent, or its params were never added, `routed` is false, `rows` is empty and nothing is sent.
- **A port is one line that plays one note at a time, whatever voices feed it** (ruling 10): `lines[port]` holds the sounding notes across voices, oldest first, each with its voice, id and pitch. The newest note's pitch is the port's cv (`volts(pitch)`, clamped to -10 to 10), then its trigger goes high. When the newest ends and others remain on the line, the cv goes to the newest left, whichever voice it belongs to, and no trigger is sent; the trigger goes low (`send_off`) once, when the line's last note ends. A second note on sends the cv and the trigger again. A note stays on the port it started on until it ends, even if its voice's port param changes.
- **Bookkeeping never goes negative or keeps an id that ended**: `note_off` for an id that never started (a `note_on` that raised, a repeat) sends nothing; a `note_on` for a sounding id replaces it; `stop_all` empties every voice.
- **A `note_on` whose send raises leaves the line as it was** (it is rolled back and the error goes on): the targets core records a target for a note only when its `note_on` returned, so no `note_off` would ever come for it. A route change (whose param action calls `S.lib.io_targets.route_changed(voice)` after the value moved) ends the voice's notes on the ports they started on.
- **No `ready`, no `release`**: the device needs no setup. The bus leaving ends its notes through the targets core (`end_target`).

## Owns

- `lib/io/er301.lua` (`S.lib.io_er301`): `ER301` (every tunable), the note target `er301`, the ii device `er301` (7 params), the row `er-301`.
- Tests: `test/unit/io_er301_test.lua`, against a double of `S.lib.io_ii`.
- User page: `docs/user/io/er301-txo.md`.

## Params

`v<i>_out_er301` for voices 1 to 7: 0 off, port 1 to 100 (0). PSET-only, no scene, no engine sender. Shown as `off` or `port <n>`.

## Messages

Per `docs/design/3.6-facts/crow-ii.md` section 2 (crow's `lua/ii/er301.lua`): `ii.er301.cv(port, volts)` and `ii.er301.tr(port, state)`. A note on is `send("er301", "cv", port, volts)` then `send("er301", "tr", port, 1)`; the last note's off is `send_off("er301", "tr", port, 0)`.

Unverified on the device until the 4.0 hardware check.
