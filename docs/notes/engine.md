# Engine and Lua/engine interface notes

Detailed reference moved out of CLAUDE.md (which keeps the rules and the command table). Read the section you need; grep for the function or SynthDef name.

## Architecture

### Dual-Language System

This project uses two languages that work together:

1. **strata.lua** - The norns script (Lua)
   - User interface and control logic
   - Parameter management
   - Encoder/key handling
   - Communicates with the SuperCollider engine via `engine.*` commands

2. **lib/Engine_Strata.sc** - The audio engine (SuperCollider)
   - All synthesis and audio processing
   - Exposes commands to Lua via `this.addCommand()`
   - Manages audio buses, synths, and signal routing

### Audio Signal Flow

```
Voice Synth → Voice Bus → Granular Processor → Main Bus → Filter → Filter Bus → Delay → Delay Bus → Reverb → Reverb Bus → Master (drift/limiter/saturation) → Output
                  ↓
              Mod Synth → Mod Bus → Other Voice Synths (cross-modulation)

Buffer source:  Buffer pair (L/R) → strataGrainBuf → Main Bus (and mirrored to the Voice Bus → Mod Synth)
Input source:   SoundIn → strataInput → Input Bus → strataGrain → Main Bus (and mirrored to the Voice Bus → Mod Synth)
```

Each of the 7 voices follows this path (synth source; see Audio Sources for buffer and input sources):
1. Voice synth (strataResonator/strataFM/strataFolder/strataSub/strataPulse/strataKarplus/strataRing) outputs to its own `granBuses[i]`
2. Granular processor (`strataGrain`) reads from voice bus, outputs to shared `mainBus`. A buffer-sourced voice has no voice synth: `strataGrainBuf` reads its buffer pair; an input-sourced voice's `strataGrain` reads `inputBus`. Both also write their output to `granBuses[i]` (the mirror)
3. Modulation synth (`strataMod`) analyzes voice bus output (the voice synth, or the mirror) and generates control signal to `modBuses[i]`
4. Other voice synths can read from any `modBuses[i]` to modulate their amplitude and/or frequency
5. Filter (`strataFilter`) processes mainBus, outputs to `filterBus`; delay (`strataDelay`) processes filterBus, outputs to `delayBus`
6. Reverb (`strataReverb`) processes delayBus, outputs to `reverbBus`
7. Master (`strataMaster`) applies drift, a `Limiter.ar(sig, 0.95)` safety stage that catches peaks before saturation, then saturation, and outputs to norns output

### Cross-Modulation System

Each voice generates a modulation signal (envelope follower + slow LFO) that can modulate other voices:
- **Modulation Output**: Each voice has a `strataMod` synth that analyzes its audio output and creates a control signal (0-1 range)
- **Modulation Input**: Each voice synth can receive modulation from up to 3 different sources simultaneously
- **3 Modulation Slots**: Each voice has 3 independent modulation slots, each with its own source and depth controls
- **Routing**: Controlled via `setModSource(voice, slot, sourceVoice)` where slot is 1-3. The three crossmod commands ignore a slot outside 1..`numModSlots` (3, mirroring Lua's `NUM_MOD_SLOTS`; `validModSlot`), which would name a control no SynthDef has and stay in `voiceControls` for good
- **Depth Control**: Each slot has independent `modAmpAmt` and `modFreqAmt` controls
- **Signal Mixing**: The 3 modulation signals are mixed together (weighted sum) before applying to voice parameters
- **Signal Character**: The mod signal combines envelope following (70%) with slow LFO movement (30%) for organic evolution


### Lua ↔ SuperCollider details

The command table itself is in CLAUDE.md (the docs test reads it there).

**Poll `bufferState`** (engine → Lua): each slot's valid seconds. matron's `/poll/value` handler is typed `"if"` (one float) and its data-blob polls are broken (`w_handle_poll_data` writes every byte to index 1), so a string or table cannot reach Lua: every message carries **one** slot as `slot_index * 100 + seconds` (`bufferStateStride = 100`; seconds ≤ 16, rounded to 0.01). Decode in Lua with `slot = math.floor(value / 100)` (0-based, so Lua slot `slot + 1`) and `seconds = value - slot * 100`. The poll is periodic (0.25 s) and cycles through the eight slots; every change (load, record start, completion and early stop, clear) is also sent immediately via `bufferStatePoll.update`. A slot reads 0 s while it records and its length once the recording completes. Lua: `init` calls `poll.set("bufferState", buffer_state_changed)` and starts it (it prints a message if the poll is missing); `buffer_state_changed` decodes the value with `BUFFER_STATE_STRIDE` (100) into `buffers[slot].seconds`, ignores slots outside 1..`NUM_BUFFERS`, and settles a take or load waiting for the engine, or adopts a late take or load (see the buffers table under Audio Sources); `cleanup` stops it.

**Poll `bufferLoadFailed`** (engine → Lua, not periodic: `addPoll(\bufferLoadFailed, func, false)`, sent only through `bufferLoadFailedPoll.update`): one message per failed load, whether or not the slot held audio. `rejectLoad` sends it at once for a missing, unreadable, unsupported, empty or damaged file, which leaves the slot as it was. `loadSlot`'s read sends it after the fade and the read when the server's `/b_readChannel` fails, which leaves the slot empty (below). `bufferState` cannot carry this: over audio the slot keeps its old length, so its reports look like a good load's, and its `slot * 100 + seconds` layout has no room for a load identifier. A second poll keeps both encodings plain. The value is one float, `bufferLoadFailedValue(i, load, emptied)` = `(load * 2 + emptied) * numBuffers + i`: `load` is the failed load's number, from `bufferLoads[i]`, which counts the slot's `loadBuffer` commands from 1 (in `loadSlot`, after the slot check); `emptied` is 1 when the failed server read left the slot zeroed and 0 when the slot is as it was. Lua's `load_buffer` counts the same commands in `buffers[slot].loads_sent`. Both start at 0 when the script starts, because norns builds a new engine for every script load. It is exact for the first 2^20 loads of a slot (float32 integers). It is sent after `rejectLoad`'s own `bufferState` 0 for a cancelled recording. A failed read is reported after the fade wait and the read, so it can arrive after a later load's immediate rejection: reports are not in load order, and Lua does not assume they are. Its poll function returns the last value (0.0 before any failure, which names load 0, never sent), so a value request only repeats a report, and Lua ignores repeats. Lua: `init` sets `buffer_load_failed` as its callback and starts it (`buffer_polls.load_failed`; it prints a message if the poll is missing), and `cleanup` stops it.

**Index Conversion**: Voice indices are 0-indexed in SuperCollider but 1-indexed in Lua. Always subtract 1 when calling engine commands from Lua (e.g., `engine.voiceOn(voice_idx - 1, ...)`). Mod sources are converted by `engine_mod_source()` (Lua 0=none / 1-7 → SC -1=none / 0-6).

**Starting a voice (`toggle_voice` → `sync_voice_to_engine`)**: `voiceOn` only carries the initial freq/amp/pan and grain size/density/pitch (density = `engine_param_value("v<i>_grain_density") * engine_param_value("master_density")`, the values the engine has, as the senders use), and param actions only reach the engine while a voice is active. So `toggle_voice` calls `sync_voice_to_engine(voice_idx)` right after `engine.voiceOn`, which sends `setGrainSource(voice, source - 1)` **first**, then (`sync_voice_values_to_engine`) every `voices[i].params` entry (`setVoiceParam`), all nine grain params (`setGrainParam`: size, density × `master_density`, pitch, spread, `envShape` and `grainMode` = option index − 1, `bufPos`, `bufRate`, `bufScan`), every crossmod slot (`setModSource`/`setModAmpAmt`/`setModFreqAmt`) and `setModSpeed`. The engine holds no per-voice defaults of its own (there is no `getVoiceParams`); the Lua `voices` table is the only source of values. The `v<i>_source` param action is the one voice param that also reaches a stopped voice: it always sends `setGrainSource` (the engine only records it, so the next `voiceOn` builds the right synths), then, for a running voice, `sync_voice_values_to_engine` (not while `scene_recall_in_progress`: a scene recall syncs once at its end, see Scene System). `setGrainSource` after `voiceOn` in `sync_voice_to_engine` is then a no-op in the engine.

**Silent bus**: An unrouted mod slot must read a bus that is always zero. Control bus 0 is not safe on norns (CroneAudioContext allocates the input amplitude follower `amp_in_b` there before any engine loads), so the engine allocates `silentBus` in `alloc`, sets it to 0, uses its index for `sourceVoice = -1` and as the `voiceOn` default for `modBus1..3`, and frees it in `free`.

**Retrigger**: Pattern steps never create synth nodes. For a running voice the pattern clock calls `engine.retrigger(voice - 1, level / MAX_STEP_LEVEL)` (step level 1-15, so a step's brightness is its velocity). The engine sets `velocity` and `t_trig` in one message on the voice synth and on the grain synth. Every voice SynthDef has a plain `velocity=1` control and an accent envelope `EnvGen.kr(Env.perc(0.005, 0.4), t_trig, levelScale: velocity)` applied as `modAmp * (1 + accent)` inside the amplitude clamp. `levelScale` is sampled when the envelope (re)starts, so a new velocity never rescales a running accent tail; never multiply a running signal by `velocity`. Karplus also feeds `T2A.ar(t_trig) * velocity` (a single-sample impulse, so only that trigger's excitation is scaled) into its exciter and `Pluck` trig inputs so it re-plucks as hard as the velocity. In `\strataGrain` the trigger only matters in triggered grain mode (one grain per trigger). For buffer and input sources there is no voice synth, so the accent lives in the grain synth: `\strataGrainBuf` and `\strataGrain` have the same `EnvGen.kr(Env.perc(0.005, 0.4), t_trig, levelScale: velocity)` accent. `\strataGrain` applies it only with `accentAmt = 1` (input source); for the synth source the engine sets `accentAmt = 0` so voices are not double-accented and velocity reaches triggered grains through the voice accent. Grain-side velocity is always per trigger (`levelScale`), never a bare multiplier on the output (`GrainIn`/`GrainBuf` grains still playing would jump); the engine check asserts `velocity` feeds only `EnvGen` `levelScale` inputs in every voice SynthDef and both grain SynthDefs. The sole allowance is `\strataKarplus`'s `T2A.ar(t_trig) * velocity` pluck impulse, checked strictly: the `T2A`'s input must be the `t_trig` control, and the product (the `MulAdd` sclang fuses `T2A * velocity + Impulse` into, or a `*` `BinaryOpUGen` whose users are `+` sums) may reach only a `Decay`'s input (the noise burst) and `Pluck`'s trigger. The check checks itself: check-only copies of the Karplus excitation compiled in the engine check must fail it when the impulse is a `T2A` of the gate, when the velocity-scaled impulse also scales the output, and when the excitation trigger is smeared into a level (a `Lag`) that scales it; a faithful copy must pass. A step on a stopped voice starts it with `toggle_voice`. K3 on MAIN keeps its start/freeze meaning: triggered grains fire from pattern steps and MIDI notes only (a deliberate deviation from the spec's "K3 on MAIN with the voice already on").

**Pitchbend (`bend`)**: every voice SynthDef has `bend=1` multiplying its frequency (`modFreq = freq * bend * (1 + ...)`; FM's `modFreqVal`), and `\strataGrainBuf` has `bend` in its rate (`bufRate * bend * ...`; `\strataGrain` declares it unused). It is transient: not a Lua param, not in `voices`, not captured by scenes. Lua sends it only as `setVoiceParam(voice, "bend", ratio)` (never `setGrainParam`): the engine's `setVoiceControl` keeps it in `voiceControls` and passes it to `\strataGrainBuf` for a buffer source, so a source switch carries the current bend to the new synths. `voiceOn` resets it to 1 in the engine and `sync_voice_values_to_engine` then sends `midi_state.bend[i]` (the wheel's current position, 1 at rest), so a restart never leaves a stale bend and a voice started while the wheel is held plays bent.

**Current Voice Parameters** (as of latest sync):
- **Resonator**: freq, rq, noise, mod1, mod2, amp, pan
- **FM**: freq, ratio, index, modFreq, amp, pan
- **Folder**: freq, fold, mod, amp, pan
- **Sub**: freq, drift, amp
- **Pulse**: freq, width, cutoff, res, amp, pan
- **Karplus**: freq, decay, damping, excite, amp, pan
- **Ring**: freq, ratio, mod, brightness, amp, pan

**Current Granular Parameters**: grainSize, grainDensity, pitchShift, posSpread, envShape, grainMode, bufPos, bufRate, bufScan (the last three only matter to `\strataGrainBuf`, i.e. buffer sources; Lua `v<i>_buf_pos` 0-1 lin step 0, `v<i>_buf_rate` 0.25-4 exp, `v<i>_buf_scan` -2..2 lin, in `voices[i].grain.buf_pos|buf_rate|buf_scan`)
- `envShape` (Lua option `v<i>_grain_env`, `GRAIN_ENV_OPTIONS = {"hann", "sine", "perc", "linen", "trap"}`, default hann; `voices[i].grain.env` holds the option index 1-5) is sent as index − 1. The engine's `envBufnumFor(index)` turns it into the grain synth's `envBuf`: 0 = `-1` (GrainIn's built-in Hann), 1-4 = `envBuffers[index - 1].bufnum`; any other index is ignored. `envBuffers` are four 1024-frame `Buffer.loadCollection`s of `Env.sine`, `Env.perc(0.1, 0.9)`, `Env.linen(0.1, 0.8, 0.1)` and the trapezoid `Env([0, 1, 1, 0], [0.25, 0.5, 0.25])`
- `grainMode` (Lua option `v<i>_grain_mode`, `GRAIN_MODE_OPTIONS = {"continuous", "triggered"}`, default continuous; `voices[i].grain.mode` holds the option index 1-2) is sent as index − 1. `\strataGrain` picks its `GrainIn`s' trigger with `Select.ar(mode, [Impulse.ar(grainDensity), T2A.ar(t_trig)])` (`mode = grainMode.round.clip(0, 1)`): continuous fires `grainDensity` grains per second, triggered fires one grain per `retrigger` (its level follows the voice accent, not a grain-side velocity) and mutes the position-spread path so only the triggered grains sound (`spreadLevel` is lagged 50 ms, so a mode change fades instead of clicking). In triggered mode `grainDensity` does nothing, and neither does `posSpread` for synth and input sources (`\strataGrainBuf` still jitters each triggered grain's position by it). MAIN shows `[TRIG]` for a voice in triggered mode
- `DISCRETE_GRAIN_KEYS` (`{ env = #GRAIN_ENV_OPTIONS, mode = #GRAIN_MODE_OPTIONS }`) maps the grain keys that hold an option index to their option count: `scene_transition_targets` skips them (they switch when the fade ends), mutation and randomize never touch them, and `validate_scene` requires integers from 1 to the count
- `pitchShift` (Lua `grain_pitch`, 0.25-4) is a real transposition: the grain output runs through `PitchShift.ar` (window = the engine's fixed `pitchShiftWindow`, 0.1 s, whatever the grain size; ratio = `pitchShift.lag(0.5)`). It is not a gain. The window is fixed because `PitchShift` allocates its delay line from scsynth's real-time memory when the synth starts, sized by that window: when it followed `grainSize` (up to 0.5 s) seven voices could exhaust norns' pool (see Real-time memory).

**Cross-Modulation Parameters** (per voice, 3 slots per voice):
- **Slot 1, 2, 3** - Each slot has:
  - **source**: Which voice modulates this slot (0=none, 1-7 in Lua, -1=none, 0-6 in SC)
  - **amp_amt**: Amplitude modulation depth (-2 to 2, bipolar)
  - **freq_amt**: Frequency modulation depth (-2 to 2, bipolar)
- **speed**: Modulation signal LFO speed (0.1 to 50 Hz, shared across all slots). The engine keeps each voice's last `setModSpeed` in `modSpeeds[voice]` (nil until one arrives) and passes it (`modSpeedPairs`) to every `\strataMod` it starts or re-gates, so a mod synth `onFree` restarts (re-gated just as its release ended) runs at the voice's speed, not the SynthDef default of 10

### Audio Sources (buffers and live input)

Every voice's grain stage has a source (`grainSource[voice]`): 0 = its own synth (the voice synth writes `granBuses[i]`, `\strataGrain` reads it), 1-8 = buffer slot, 9 = live input. The engine side:

- **Buffer slots**: `numBuffers = 8` slots (mirrors Lua `NUM_BUFFERS`), each a pair of mono buffers `buffersL[i]`/`buffersR[i]` (GrainBuf reads mono buffers only) of `sampleRate * bufferSeconds` frames (`bufferSeconds = 16`, mirrors `BUFFER_SECONDS`). Memory: 8 × 2 × 16 s × 48 kHz × 4 bytes ≈ 49 MB of scsynth memory. Never allocate longer buffers. `bufferFrames[i]` is the valid length (0 = empty); `bufferSampleRates[i]` the content's sample rate. bufnums never change: loads read into the existing buffers
- **`\strataGrainBuf`**: two `GrainBuf.ar(1, ...)` (left, right) sharing one trigger, position, rate and duration, so grains stay sample-aligned and the stereo image is kept; `Balance2` with `LFNoise1.kr(2).range(panSpread.neg, panSpread)`, then one `PitchShift` stage on the pair, then the voice's `pan` (`panBalance`, see Voice-level controls). The output (main and mirror) is multiplied by `(bufFrames > 0).lag(0.05)`: an empty slot or one being recorded (`bufFrames` 0 until the take completes) is silent instead of every grain reading position 0 and looping the take's first grain. `bufPos` (0-1) and the scan are fractions of the valid region (`bufFrames`), so a 2 s sample uses the whole range; `bufScan` moves the position in **valid-region lengths per second** (spec §1; bipolar, wraps); grain position jitter ± `posSpread * 0.5`. **Grain end**: no grain reads past the valid region into the zeroed rest of the 16 s buffer (which made the level dip every time a scan wrapped). GrainBuf reads `rate × BufRateScale.kr(bufnumL)` frames per output sample (it applies the buffer's own rate scale to the rate it is given; with the division above that is `bufRate × bend × bufRateScale × (1 + rateMod)`), so a grain covers `grainDur × SampleRate × readRate` frames; `grainDur` is `grainSize` capped at the valid region less `grainEndMargin` (4 frames, for the interpolation and rounding) at that rate, and the scanned position (jitter included, wrapped 0-1) is scaled to the frames before `bufFrames - grainEndMargin - grainFrames`. While the slot reads empty (`bufFrames` 0: cleared, reloading or recording, faded out by `hasAudio`) the last valid length is held (`Gate.kr(bufFrames, bufFrames > 0)`), so the grains fading out keep their size and place instead of shrinking to a few samples at position 0, which clicked. When a grain (grain size × read rate) covers the whole valid region, every grain starts at its beginning, so `bufPos`, `bufScan` and the position spread stop doing anything. So `bufPos` 1 is the last start that still ends inside the region, and a region shorter than a grain gets grains as long as the region. The engine check fills the frames past a silent region with 1 and hears nothing (at the server rate, at 22050 Hz and rate 2, and with a region shorter than a grain). Rate = `bufRate * bend * (bufRateScale / BufRateScale.kr(bufnumL)) * (1 + rateMod)` where `bufRateScale` = content rate / server rate, tracked by the engine (`b_alloc`/`b_zero` keep a loaded file's rate on the server buffer and norns' scsynth predates `b_setSampleRate`, so `BufRateScale.kr` would be wrong after recording into a slot that held a file). `GrainBuf` itself already multiplies the rate by the buffer's own rate scale (the server's `BufRateScale`), so dividing it out applies the engine's scale exactly once: without the division a 44.1 kHz file played 1.5 semitones flat on a 48 kHz server (the engine check measured a 1 kHz sine at 920 Hz), and dropping `bufRateScale` instead would play a take recorded over a 44.1 kHz file flat. The engine check measures both with `Pitch` (1 kHz from a 44.1 kHz file, 440 Hz from a take recorded over it). Crossmod applies to amplitude and rate like voices (`rateMod` clamped -0.9..2), the accent is per trigger, and `grainMode` works as in `\strataGrain`
- **Live input**: the persistent `\strataInput` synth (`SoundIn.ar([0, 1])` → stereo `inputBus`) at the head of `voiceGroup`. Input-sourced voices run `\strataGrain` with `in = inputBus`
- **Mirror to the voice bus**: with no voice synth, a buffer- or input-sourced voice's `granBuses[i]` would be silent and its `\strataMod` (and every voice it modulates) would go dead. So both grain SynthDefs write `sig * mirrorLevel` to `mirrorOut` (= `granBuses[i]`) as well as `mainBus`. `mirrorLevel` defaults to 0 in both (and `mirrorOut` to bus 0), so a grain synth built without them mirrors nothing; `startGrainSynth` always sets it: 1 for `\strataGrainBuf` and the input `\strataGrain`, 0 in synth mode (that grain synth reads `granBuses[i]`, so mirroring would feed back). Mirroring grain synths run right before their voice's `\strataMod` (see Node Ordering), so the mirror reaches it in the same block
- **Voice-level controls follow the source**: `voiceControls[voice]` keeps every `setVoiceParam` and crossmod value (reset by `voiceOn` to its freq/amp/pan and silent routing) and `grainControls[voice]` every `setGrainParam` (`voiceOn` merges its size/density/pitch into it with `putAll` and keeps the rest, so a grain synth `voiceOn` builds starts in the voice's grain mode, envelope and buffer position instead of firing continuous grains until Lua's `grainMode` arrives; `envShape` stored as `envBuf`). When the source is not the synth, `setVoiceControl` also sends the controls the grain SynthDef has: `amp` (the voice's level), `pan`, `bend` and the crossmod routing/amounts for `\strataGrainBuf`, `amp`, `pan` and the amplitude crossmod (`modBus1..3`, `modAmpAmt1..3`) for the input `\strataGrain`, which applies it like the voices (`(1 + mod).clip` on the level) only with `modLevel = 1`. Frequency crossmod has no meaning for live input and is ignored (`\strataGrain` has no `modFreqAmt`). **Pan**: both grain SynthDefs apply `pan` after their `PitchShift` through `panBalance(sig, pan)`, a balance (`sig * [1 - pan.clip(0, 1), 1 + pan.clip(-1, 0)]`): pan -1 leaves only the left channel, 1 only the right, and a centred voice is unchanged (a `Balance2` would take 3 dB off both channels at the centre). The synth-source `\strataGrain` keeps `amp = 1`, `pan = 0` and `modLevel = 0` (the voice synth applies the level, the pan and the crossmod; applying them again would double them), and gets `modBus1..3 = silentBus` so it never reads control bus 0 (the SynthDef defaults are 0). `controlPairs` filters against a per-SynthDef `IdentitySet` of control names (`controlNameSets`, built in `alloc` for the voice and grain SynthDefs)

**Replace, never stack.** `setGrainSource` on a running voice calls `replaceGrainSynth`: the new grain synth is created with the voice's current `grainControls` (and voice-level controls) and the old one gets a forced release (`release(grainRelease)`, 2 s, linear) in the same call, so one voice never runs two grain paths beyond that release. First `cutFadingSynths(voice)` cuts everything an earlier switch (or a `voiceOn` for another source, see Synth Lifecycle) left releasing (`fadingSynths[voice]`, an `IdentitySet` emptied by the cut and by `onFree`), and any grain or voice synth still in `releasingSynths` (none should be: `voiceOn` re-gates them or hands them to `fadingSynths`), so once a switch has been processed (within `switchCutTime`) a voice has at most one releasing grain synth and at most one releasing voice synth, however fast or slowly the sources are scrolled (one switch per E3 detent); there is no Lua-side debounce. A switch first frees at once whatever an earlier cut left still in its kill fade (`freeCuttingSynths`), so even switches faster than `switchCutTime` leave at most one cutting set per voice (see Real-time memory). **Cutting is `cutSynth`, the kill fade, never a second forced release**: EnvGen starts a forced release only when its gate crosses -1 from above (`gate <= -1 && prevGate > -1`), so a synth already in `release(grainRelease)` (gate -3) ignores `release(0.05)` (gate -1.05) and would run its full 2 s. Every voice and grain SynthDef multiplies `killFade(kill)` into its ASR: `EnvGen.kr(Env([1, 0], [switchCutTime]), kill, doneAction: 2)`, which holds level 1 until the `kill` control rises above 0 and then fades linearly to 0 in `switchCutTime` (0.05 s; built into the SynthDefs in `alloc`, so changing it later has no effect) and frees the synth, whatever the ASR is doing. `kill` is that EnvGen's trigger, not its gate (`Env.cutoff` on `1 - kill` would never start in a synth killed in its creation block and would play on at full level). `cutSynth(synth)` sends `\kill, 1` to a synth that `isPlaying`; a killed synth is never re-gated (it has already left `synths` and `releasingSynths`). Leaving the synth source releases the voice synth with `release(grainRelease)` (a forced release: its sound only reached the output through the old grain synth, so it does not run its own up-to-12 s release silently) and adds it to `fadingSynths`; returning to the synth source starts a new voice synth from `voiceControls`. New grain synths are placed by `startPlacedGrainSynth` (see Node Ordering), never next to a releasing synth: that one may have freed on the server already, and an `/s_new` to a missing target creates nothing. `voiceOn` for a voice whose source is not 0 builds `\strataGrainBuf` (or the input `\strataGrain`) directly and no voice synth. `setGrainSource` with the current source does nothing (Lua sends it on every voice start).

**Buffer commands** (`loadSlot`, `recordSlot`, `clearSlot`, `writeSlot` in the engine): load opens the file with `SoundFile` (frames, channels, rate) and `readChannel`s at most `bufferSeconds` of it into the existing buffers, capped by the buffers' size (`bufferSeconds` at the **server** rate): a 96 kHz file keeps 8 s on a 48 kHz server, a 44.1 kHz file the full 16 s. **Damaged files and failed reads** were probed with scsynth 3.14:
- A WAV whose header claims more data than the file holds, and a truncated WAV, are not failures. libsndfile shortens `numFrames`, and sclang and the server both read the frames that are there.
- A corrupt or truncated FLAC keeps a sound header (48000 frames) but stops decoding early (12288 frames). The server's `/b_readChannel` then fills the rest with silence and reports nothing. So `loadSlot` decodes the frames it will read itself first (`fileDecodes`, one reused chunk array of `loadCheckFrames` = 16384 frames, synchronously: 16 s of 48 kHz stereo takes about 2 ms for a WAV and 9 ms for a FLAC on a desktop, and the file is then in the page cache for the server). A file that decodes more than `loadShortfallFrames` (4096) frames short is rejected like an unreadable one. That tolerance is one default FLAC block (85 ms at 48 kHz) and more than an MP3's encoder delay and padding (under 2 × 1152 frames), so a header count that overshoots by a codec's padding still loads. The damaged FLAC (35712 frames short) is rejected. Damage inside a FLAC's last block slips through as at most 4096 frames of silence at the end. A format whose header count is only a rough estimate that overshoots by more is rejected: an MP3 without a Xing/LAME header, which needs libsndfile 1.1 or later and is therefore not readable on norns' libsndfile anyway. libFLAC 1.4 prints `Rewinding, seeking necessary` to stderr when it seeks in a damaged FLAC; sclang cannot silence it, it is harmless, and `run_engine_check.sh` does not count it as an error.
- A corrupt Ogg reads as 0 frames, so it is rejected as empty.
- The server's read itself fails (`/fail /b_readChannel <message> <bufnum>`) only when the file vanishes or becomes unreadable between those checks and the read, for example a drive unplugged during the fade wait. The read's `fork` watches for that `/fail` with an `OSCFunc` from the server's address that matches `/b_readChannel`, one of the slot's bufnums and the quoted path in the message (`File '<path>' could not be opened: ...`). Matching the bufnum alone would not do: two back-to-back loads into an unplayed slot both read at once, so a vanished file's `/fail` would also fail the next load's good read. A next load of the very same path cannot be told apart, but it reads a file that has just vanished. The `/fail` arrives before the `/synced` that ends the wait, and the `OSCFunc` is freed after it. The slot has already been zeroed, so it keeps 0 frames (its rate is reset to the server's, only if `slotChanges` is unchanged), and the load is reported as emptied whatever came after it (Lua relies on the report to keep its tracked loads right). A load that a later load, clear or recording superseded inside the fade wait never reads, so it reports nothing.

A missing, unreadable, empty or damaged file (`rejectLoad`) is logged, reported by the `bufferLoadFailed` poll (above) and leaves the slot unchanged (before anything is zeroed), except that it cancels a recording in progress or waiting to start in that slot, or one `stopRecord` ended whose frame count has not arrived yet (`stopReplies[i]` holds that stop's `slotChanges` count until the reply; the bad load's `slotChanged` drops the reply; every `slotChanged` empties `stopReplies[i]`, so once a good load, record or clear has followed the stop there is no take left to cancel and a bad load sent after it leaves that command alone) (`stopRecording`, `slotChanged`): Lua's `load_buffer` ends the recording state, so a take that completed anyway would be adopted under the bad file's name and path (and lost at the next restore). The slot then reads 0 frames, as for a recording a clear cancelled. A good load sets the slot's frames to 0 at once, zeroes the pair and reads after the fade (below); the slot's `bufferFrames`/`bufferSampleRates`, the grain synths reading it and the poll get the new length only once the reads have completed (a `server.sync` after them in a `fork`). **Fade before zeroing**: `b_zero` and `b_readChannel` complete within about a millisecond, far inside `\strataGrainBuf`'s 50 ms `hasAudio` lag, so load, record and clear first set the slot's `bufferFrames` to 0 (`bufferChanged` sends it to every grain synth reading it, and the poll reports 0) and only then zero or overwrite the buffers, through `afterSlotFade(index, change, action)`: `bufferFadeWait` (0.06 s, settable; the engine check lengthens it) later when any grain synth reads the slot (`slotPlaying`), at once otherwise, so a recording into an unplayed slot starts without delay. The delayed action runs only if `slotChanges[index]` is still `change`, so a later load, record or clear inside the wait wins (the earlier command's zeroing, read or record start is dropped, the later one does its own). `free` bumps every slot's count, so nothing waiting runs on freed buffers (the engine check frees it with a clear, a load and a recording waiting). **Grain synths that are no longer a voice's** still read their slot: one releasing after `voiceOff` (2 s), fading after a source switch, or in its kill fade. `grainSlots` maps every `\strataGrainBuf` (set in `startGrainSynth`, removed in `onFree`) to the slot it reads, and `slotGrainSynths(index)` lists the playing ones; `slotPlaying` counts them all, so a slot change waits for their fade too, and `bufferChanged` sends them `bufFrames 0` only (never a new take's length, which their tail would replay, and never a rate). `voiceOn` re-gates a releasing one with the slot as it is then (`bufferSlotPairs`). **The rate follows the audio**: `bufferChanged` and `bufferSlotPairs` send `bufRateScale` only with a valid length (`slotLengthPairs`), so a clear or recording, which set the slot to the server rate, never retunes the grains still fading out (a 44.1 kHz file's grains started in the 50 ms fade played about 1.5 semitones sharp); a take's rate arrives with its length. **`slotChanges[i]`** counts the changes to slot i (load, record, clear, stop, through `slotChanged(i)`); a reply that arrives later (the load's completion, `stopRecord`'s frame count) applies only if the count is what it was when the reply was requested, so a clear (or load, or new recording) sent before it wins. Record sets the slot to 0 frames, zeroes the pair after the fade and, after a `server.sync` (so the zeroing never lands on the take), starts a `\strataRecord` synth (two `RecordBuf`s of `In.ar(inputBus, 2) * level`, `loop: 0`, plus a `Line` with `doneAction: 2` for the duration) right after `inputSynth`, unless the recording was cancelled meanwhile (`recordSynths[i]` is the token; do not use a zero completion message: it cannot be cancelled before the node exists). The slot reads 0 frames until the recording completes (`onFree`), then gets its frames and the take is written to `scratchDir +/+ "buf<n>.wav"`. A new record, load (even one whose file cannot be read) or clear on the slot cancels a recording in progress or pending (`stopRecording`), which writes nothing. `stopRecord` (`stopRecordSlot`) instead keeps the take: the record synth writes its frame count (`Sweep.kr(0, SampleRate.ir)`) to the slot's `recordFrameBuses[i]`; the engine frees the synth, reads that bus (`/c_get` is answered after the `/n_free`, and the bus keeps its last value), sets `bufferFrames[i]` to it and writes the scratch take (unless `slotChanges[i]` moved meanwhile: `stopRecord` then `clearBuffer` in one go leaves the slot empty and writes nothing). Read `isPlaying` before freeing (`Node.free` clears it). A recording still waiting for its zeroed buffers has captured nothing and is just cancelled. `writeSlot(index, path)` (scratch takes and `saveBuffer`) has the server write each mono buffer's valid frames to a temporary float file, then sclang interleaves them in 8192-frame chunks (a per-frame loop: an array-level `lace` measured about twice as slow, since the `_ArrayLace` primitive only descends into `Array`s and each chunk would be converted FloatArray -> Array -> FloatArray; yielding `writeChunkWait`, 1 ms, between chunks; a 16 s take interleaves in about 0.06 s on a Mac) into a stereo 16-bit WAV at the content's rate and deletes the temporaries; it creates no synth nodes. The buffers are float and `record_level` goes to 2, so a take can hold samples beyond ±1: the interleave clips every sample to ±`int16Peak` (32767 / 32768), so the file is clipped deliberately and symmetrically (+32767 / -32767) whatever libsndfile's own float-to-int conversion does (without its clipping mode it wraps; with it, it clips to +32767 / -32768). Writes to the same path can overlap (a full 16 s take is still being written when the next, shorter take completes), so each write gets a generation number in `writeGenerations[path]`, interleaves into its own `path.<instanceTag>-<generation>.part` file (`instanceTag` is `UniqueID.next` at `alloc`, so two engine instances in one sclang session, before and after a script reload, never share a `.part` or temporary float file `strata-buf<n>-<tag>-<gen>-<L|R>.wav`), and renames it into place (`mv -f`, atomic on one filesystem; sclang has no `File.rename`) only if it is still the newest write for that path. An older write checks after every chunk, abandons as soon as a newer one starts, and deletes its `.part`. The newest write always wins, two writes never mix, and a reader never sees a half-written file. The newest write removes its `writeGenerations` entry when it ends, whether it succeeded or failed (a directory that cannot be made, `File.mkdir` throwing, is caught and reported as `cannot write`); an abandoned write leaves the newer one's entry. `alloc` calls `deleteStaleParts`, which deletes the `*.part` files a crash left in `scratchDir` (scratch takes) and in its parent (`saveBuffer`'s `<date>-buf<n>.wav.<tag>-<gen>.part` in `_path.audio/strata/`, visible in the file browser), and `writeSlot`'s temporary float files (`strata-buf*-*.wav`) in `Platform.defaultTempDir`; nothing else, and only files last modified more than `stalePartAge` (60 s) ago (`File.mtime` against `Date.getDate.rawSeconds`). `File.mtime` throws for a file deleted since the glob, so it is wrapped in `try`: such a file is skipped silently, while one that is still there (or whose existence cannot be read either: a directory without search permission makes `File.exists` throw too) is left and posted (`strata: cannot read when <path> was last written`); `deleteStaleParts` returns those paths. A temporary float file is written just before its interleave opens it, and deleting an open file does not stop it being read, so the age check also keeps a running write's files: after a script reload in the same sclang session the previous instance's write routine may still be interleaving, and a running write touches its `.part` with every chunk. `stalePartDirs` picks the directories: `scratchDir` (with `~` expanded, trailing slash dropped) and its `dirname`, keeping only absolute paths below the root, so an empty, relative (`"."`, `"scratch/"`, whose `dirname` is `"."`) or root `scratchDir` never globs the working directory or `/` (never `standardizePath` it: that turns `"."` into the working directory). `test/run_engine_check.sh` starts sclang in its temp dir, so the check's working-directory marker never lands in the caller's directory. Never open the final path directly for writing: `SoundFile.openWrite` truncates it, and libsndfile rewrites the header on `close`. The engine check sets `writeChunkWait` to 0.02 s so the overlap is certain. Every change updates `bufferFrames`, the grain synths reading the slot (`bufFrames`, and `bufRateScale` when the slot holds audio) and the `bufferState` poll.

**Scratch directory**: `scratchDir` (engine variable, settable) defaults to `Platform.userHomeDir +/+ "dust/audio/strata/scratch/"`, which equals Lua's `_path.audio .. "strata/scratch/"` on norns; it is created on demand before writing. `test/engine_check.scd` points it at a temporary directory so the check never writes into `~/dust`.

"strata/scratch/buf<n>.wav"` (a load keeps its name), and a slot with `restoring` set (a `load_buffers_from_disk` load) counts once in `buffers_restored` (`restoring` stays set until then). Either way `recording`/`finishing` clear and the fallback clock is cancelled. **Late takes and loads**: under sclang load a take can complete more than 1 s after the Lua timer, and the engine reports a load only when its reads complete (16 sequential `readChannel`s for a full restore on a CM3), so a periodic 0 can settle the slot empty first; a later report with seconds > 0 for a slot with `settled_empty` set adopts it through `confirm_buffer_audio` (loaded, named, counted when restoring). Load, clear and a new recording clear `settled_empty`, so they always win. **Fallback**: if no report arrives at all (no `bufferState` poll), the fallback clock settles a still-finishing slot `BUFFER_SETTLE.fallback_seconds` (5 s) after the take ended, from the last known seconds, so K3 is never ignored for good; load, clear, a new recording, a settle and `cleanup` cancel it (it lives in `buffer_record_clocks`). **Failed loads**: `bufferState` alone cannot reveal a bad file loaded over audio (the engine keeps the old audio, so the report of its seconds settles the load as loaded), so the engine reports every rejected load on the `bufferLoadFailed` poll. `load_buffer` counts the slot's loads (`loads_sent`) and appends `{number, path, previous}` to `pending_loads` (at most `BUFFER_SETTLE.tracked_loads`, 4, the oldest dropped). `previous` is `buffer_state_before_load(slot)`: the slot's `name`, `loaded`, `restoring`, `settled_empty`, `confirm_since`, `path`, `missing_path` and its `buf<n>_file` value. For a slot that is `recording` or `finishing`, the engine cancels the recording when the load fails, so `previous` is the empty slot with `settled_empty = "take"` and the file param at `_path.audio`: a take that had already completed is still adopted from the next report. `buffer_load_failed(value)` (global) decodes `slot = value % NUM_BUFFERS + 1`, then from `floor(value / NUM_BUFFERS)` the `emptied` bit (its lowest) and `load_number` (the rest); it ignores NaN, infinities, negative, fractional and out-of-range values. It then looks the number up in the slot's `pending_loads`. The state the failed load left is its `previous`, or, when `emptied`, an empty slot (`empty_buffer_state(false)`). Not found (a repeat, a load before the newest `tracked_loads`, or a clear or new recording since, both of which empty `pending_loads`): nothing happens. Found and newest: the slot gets that state, including the file param (silently, `set_buffer_file_param`), so the bad path never reaches `buffers.data` and a failed restore is forgotten. Found but superseded by a load sent before the report arrived: the next tracked load inherits that state, so if it fails too the slot shows what the failed load left. Only the reported entry is removed: reports can arrive out of load order (a failed read is reported after the fade), and the splice gives the right result in either order. `buffers_restored` needs no undo: a restore loads into a slot that is empty at start, so no report of old audio counted it. "strata/<YYYYMMDD-HHMMSS>-buf<n>.wav"`) and prints the path; a slot the engine reports as empty (`seconds <= 0` from the poll) is not saved: `loaded` is set optimistically by `load_buffer` until the poll settles it, and a recording reads 0 s until it completes. `seconds` comes only from the poll. `scratch_take_path(slot)` is the take path; `load_buffer` names a scratch-take path `take <n>`, so a restored take keeps its name. Load, record (start, stop, timer end) and clear call `buffer_display_changed()` (`request_redraw()` + `grid_redraw()`: the BUFFER page and grid page 4 show the state); `buffer_state_changed` requests a screen redraw, and the grid while `grid_page == 4`, only when a slot's seconds change or it settles (the periodic poll repeats values). All four check the slot (1..`NUM_BUFFERS`); `cleanup` cancels the timers and stops the poll

## SuperCollider Architecture

### SynthDef Organization

Each voice type has its own SynthDef with unique parameters:
- `\strataResonator` - DynKlank resonator bank with filtered noise
- `\strataFM` - Two-operator FM with slow modulation
- `\strataFolder` - Wavefolder with sine input
- `\strataSub` - Ultra-low sine with drift
- `\strataPulse` - Pulse width modulation with resonant filtering
- `\strataKarplus` - Karplus-Strong plucked string physical model
- `\strataRing` - Ring modulation between two oscillators

All voice SynthDefs take `t_trig` and `velocity` controls driving an accent envelope (see Retrigger above), gate their ASR through `openedGate` and multiply in `killFade(kill)` like both grain SynthDefs (see Synth Lifecycle and "Replace, never stack"), and include multi-source cross-modulation inputs (3 slots):
- `modBus1`, `modBus2`, `modBus3` - Control buses to read modulation signals from (one per slot)
- `modAmpAmt1`, `modAmpAmt2`, `modAmpAmt3` - Amplitude modulation depths (-2 to 2)
- `modFreqAmt1`, `modFreqAmt2`, `modFreqAmt3` - Frequency modulation depths (-2 to 2)
- The 3 modulation signals are mixed together (weighted sum) before application

**Modulation Signal Clamping (v2.0+, frequency floor in v2.1)**:
To prevent excessive amplitude spikes when multiple modulation sources are active, every voice SynthDef (including FM and Sub) clamps:
```supercollider
// Mix modulation signals with clamping to prevent excessive modulation
modSig = ((mod1Sig * modAmpAmt1) + (mod2Sig * modAmpAmt2) + (mod3Sig * modAmpAmt3)).clip(-2, 2);
modFreq = freq * (1 + ((mod1Sig * modFreqAmt1) + (mod2Sig * modFreqAmt2) + (mod3Sig * modFreqAmt3)).clip(-0.9, 2));
modAmp = (amp * (1 + modSig) * (1 + accent)).clip(0, 2);
```
This prevents the theoretical 4× amplitude spike that could occur with 3 sources all at maximum positive modulation. The frequency modulator is clamped to -0.9 (not -2) so the modulated frequency never reaches zero or goes negative (Karplus uses `modFreq.reciprocal` as a delay time, Resonator uses it as a filter cutoff).

**Signal safety**: the Resonator's `RLPF` cutoff (`modFreq` × a 1-4 noise factor) is capped at `SampleRate.ir * filterCeiling` (0.45): high freq, positive frequency crossmod (×3), pitchbend and the noise factor can push it past Nyquist, where RLPF's poles leave the unit circle (for cutoff × rq between SR/2 and SR, rq up to 1) and the resulting NaN killed the output until a restart. Below 0.45 × SR with rq ≤ 1 it is always stable. As a second line, `\strataFilter` (first in the effects chain) replaces any NaN, inf or denormal sample on `mainBus` with 0 (`CheckBadValues` per channel into a `Select`), so a voice that blows up can never poison the delay feedback or the reverb combs; normal samples pass unchanged. `\strataMod` guards the same way (`zeroBadValues`, the helper both use), on its summed input before `Amplitude.kr` (a NaN would poison the follower's state, so it follows again once the bad values stop) and on its output: a NaN or inf on a voice bus never reaches its mod bus, where it would spread through crossmod into every voice it modulates and, through their own mod synths, on, for good. The engine check feeds 50 ms of inf and NaN over a tone into a `\strataMod` on a private bus and finds its mod bus finite and following the tone again, and a Resonator it modulates at full depth free of bad values. The engine check runs sixteen Resonators far past Nyquist and injects 50 ms of inf and NaN on `mainBus` (delay feeding back, reverb on) and finds no bad value at the master output afterwards.

**Resonator level**: `DynKlank` driven by noise rings far hotter than the other voices: at its defaults (amp 0.3) it peaked about 23 before the master limiter (the others 0.05-0.5), and at reachable extremes (freq 20, noise 1, amp 1, accents) in the thousands, so whenever it played the master `Limiter` pulled every other voice down by about 28 dB. The SynthDef now scales it by `resonatorGain` (0.02: default peak about 0.5, so its level alone at the output is within about 2 dB of what the limiter used to leave) and puts a mono `Limiter.ar(..., voiceCeiling, voiceLimiterLookahead)` (level 1; lookahead `dur` 0.003 s: `Limiter` delays its output by 2 × dur, so its default 0.01 s put the Resonator about 20 ms behind the other voices and their accents, now 6 ms; under 6 KB of real-time memory per synth; the engine check asserts a lookahead of 2-5 ms) on `sig * resonatorGain * modAmp` before `Pan2`. At the defaults it only catches the hottest moments: sixteen default Resonators measured over 10 s peaked 19-84 before the change (median about 27, so about 0.55 after `resonatorGain`), the spread coming from the cutoff's slow 1-4 noise factor, and full-velocity accents add up to 2×. There the master limiter used to act on every sample. At the extremes, accents and full crossmod included, the voice peaks at most 1 (0.71 per channel when centred). A smaller gain that kept the limiter idle even then (about 0.007) would have made the Resonator alone about 8 dB quieter than it sounded before. The engine check measures it: eight default Resonators have a median RMS of 0.045-0.2 (about 0.1; a gain 3× too high gives about 0.29) and peak at most 0.75 per channel, the centred extremes peak at most 0.75 (the limiter's 1 × `Pan2`'s 0.707), and one extreme panned hard right reaches 0.9-1.05 on its right channel. **Crossmod from the Resonator changed with it**: `\strataMod` follows `Amplitude.kr` of the voice bus (× 0.7, plus a 0-0.3 LFO), so before the fix the Resonator as a mod source put out about 3.8-16 (median 8.7; measured at its defaults), which drove every voice it modulated to the ±2 clip of `modSig` at almost any depth; now it puts out about 0.13-0.77 (median 0.33), like the other voices, so its depth controls work. Patches and scenes that used voice 1 as a mod source modulate far less than before: listen for that on hardware.

Shared processing SynthDefs:
- `\strataMod` - Envelope follower + LFO for generating modulation signals
- `\strataGrain` - Granular processor for a stereo bus (one per synth- or input-sourced voice); two mono `GrainIn.ar(1, ...)` (left and right input channel) on one trigger (envelope `envBuf`, default -1 = built-in Hann; trigger chosen by `grainMode`: `Impulse.ar(grainDensity)` or `T2A.ar(t_trig)`), panned as a pair with `Balance2` by `LFNoise1.kr(2).range(panSpread.neg, panSpread)` exactly like `\strataGrainBuf`, then one `PitchShift` stage on the pair for `pitchShift`, then `panBalance` for the voice's `pan` (input source; 0 for the synth source). Never give it a stereo `GrainIn` on the stereo input: that expands to two GrainIns each panning its own channel, which `Out` folds back to one channel apiece (pan spread does nothing, the position-spread path is added twice, four `PitchShift`s). A synth-sourced voice's `pan` is applied by its voice synth (`Pan2`/`Balance2`). Since this fix synth- and input-sourced voices are about 3-6 dB quieter than before it; compare levels across sources on hardware (no makeup gain has been added). The engine check asserts two mono GrainIns, two PitchShifts, `Balance2` and two stereo `Out`s. Input-source extras: `accentAmt` (grain-side accent), `mirrorOut`/`mirrorLevel` (copy to the voice bus, default 0), amplitude crossmod `modBus1..3`/`modAmpAmt1..3` gated by `modLevel` (default 0); `bend` is unused here. The position-spread path's level (`spreadLevel`) is lagged 50 ms
- `\strataGrainBuf` - Granular processor for a buffer slot (one per buffer-sourced voice); see Audio Sources
- `\strataInput` - Persistent live input: `SoundIn.ar([0, 1])` to `inputBus`
- `\strataRecord` - One recording into a slot's buffer pair; reports its frame count on `framesOut`; frees itself when done (or is freed by `stopRecord`)
- `\strataFilter` - Master multimode filter (`in, out, freq=5000, res=0.5, filterType=0, mix=0`), whose input first goes through the NaN/inf guard (see Signal safety): `RLPF`/`RHPF`/`BPF` at rq `1 - res * 0.95`, all three running, each weighted by `BinaryOpUGen('==', type, index).lag(0.02)` (`type = filterType.round.clip(0, 2)`; the weights sum to 1 once settled), so a type change crossfades over 20 ms instead of stepping (`Select.ar` jumped between the antiphase lowpass and highpass outputs; the engine check measures the largest sample step across type changes on a sine). Never compare a UGen with `==` directly: that is object identity in sclang, not a UGen. `mix` crossfades dry to filtered (0 = bypass)
- `\strataDelay` - Master stereo delay (`in, out, time=0.375, feedback=0.4, mix=0`): `DelayC` (max 2 s, `time.lag(0.1)`) fed by the input plus `LocalIn`, with the delayed signal times `feedback` sent back through `LocalOut`; `mix` crossfades dry to delayed
- The filter and delay SynthDef defaults equal the Lua param defaults: the script never bangs its params, so the engine starts from these values
- `\strataReverb` - Global reverb processor; outputs `FreeVerb2` only (it already crossfades dry/wet by `mix`)
- `\strataMaster` - Master output with drift, then `Limiter.ar(sig, 0.95)` to catch filter resonance and delay feedback peaks, then the tanh saturation. The limiter must stay before the saturator: `(sig * 2).tanh * 0.5` bounds its output to ±0.5, so a limiter after it could never act (the engine check asserts the order). Drift (master and Sub) is an LFO at a fixed slow rate scaled by the drift amount: tape drift 0 = none; the Sub drift param's minimum stays 0.001

### Audio Bus Management

Buses are allocated in `alloc` (`numVoices = 7` in the engine must match `NUM_VOICES` in Lua; use it for every per-voice `Array.fill`):
- `numVoices` stereo `granBuses` (one per voice, for audio)
- `numVoices` mono `modBuses` (one per voice, for control signals)
- 1 mono `silentBus` (always 0; "no modulation source")
- 1 stereo `mainBus` (granular outputs mix here; filter input)
- 1 stereo `filterBus` (filter output, delay input)
- 1 stereo `delayBus` (delay output, reverb input)
- 1 stereo `reverbBus` (reverb output, master input)
- 4 `envBuffers` (grain envelope shapes, 1024 frames each; see `envShape`)
- 1 stereo `inputBus` (live input from `\strataInput`)
- `numBuffers` mono control `recordFrameBuses` (frames recorded so far, for `stopRecord`)
- `numBuffers` (8) slot pairs `buffersL`/`buffersR`, mono, 16 s each (≈ 49 MB total; see Audio Sources)

Buses, buffers, the input synth and groups are freed in `free` to prevent resource leaks (recordings in progress are cancelled first so nothing is written on free).

### Real-time memory

Every UGen's delay lines and tables come from scsynth's real-time pool, allocated when a synth starts. norns never raises it: `Crone.sc` boots `Server.local` with `memSize` left at the `ServerOptions` default, **8192 KB** (its `memSize = 2**16` line is commented out). A UGen that cannot get its memory prints `<UGen>_Ctor: alloc failed` and outputs zeros, and a synth whose own node cannot be allocated fails with `/s_new out of real time memory`: either way that voice goes silent with nothing on screen. Buffers (`b_alloc`, the 49 MB of slots) are not in this pool.

What a grain synth takes, at 48 kHz (sizes round up to a power of two):
- `PitchShift`: `nextPow2(ceil(window × SR × 3 + 3) + 64)` floats per channel, two channels. At the fixed `pitchShiftWindow` of 0.1 s that is 16384 floats, 64 KB per channel, 128 KB per synth. Before #19 the window was `grainSize` (0.01-0.5 s): 1 MB per synth at 0.5 s.
- `GrainIn`/`GrainBuf` grain tables: `maxGrains` × 72 bytes (`GrainIn`) or × 96 bytes (`GrainBuf`) each, two per synth. `maxGrains` is 128 (the UGens' default is 512): the largest overlap Lua can ask for is grain size 0.5 s × density 100 × master density 2 = 100 grains, and a `GrainIn`/`GrainBuf` runs at most `maxGrains - 1` (beyond that it drops grains and prints `Too many grains!`, on which `test/run_engine_check.sh` fails). 128 saves about 55 KB per `\strataGrain` and 72 KB per `\strataGrainBuf` against 512.
- `\strataGrain`'s position-spread `DelayC` (0.2 s, stereo): 64 KB per channel.

**Why 0.1 s for `pitchShiftWindow`**: every voice's default pitch is 1 (no transposition), so at the defaults the change is only the shifter's latency; and 0.1 s is the largest common window in the 16384-float step (up to 0.113 s at 48 kHz, 0.123 s at 44.1 kHz). Anything from 0.114 s to 0.2 s (SuperCollider's default, used by `\strataMaster`'s drift) costs twice as much, 256 KB per grain synth, and at the peak below (21 grain synths) those 2.7 MB would exceed the pool. A shorter window also adds less delay (the shifter delays by about one window), so accents stay tight. A larger window is smoother on low, sustained material; at small grain sizes the fixed window is smoother than the old one (0.01 s windows buzzed).

**Budget** (measured on scsynth 3.14 at 48 kHz with `/rtMemoryStatus`; used KB of the pool):
- engine idle (effects chain, input, mod buses; delay 2 s stereo = 1 MB, master `PitchShift` 0.2 s = 256 KB, `FreeVerb2`): about 1460 KB
- one synth-sourced voice (voice, grain and mod synths): about 310 KB more; seven: about 3690 KB
- the peak: seven voices at grain size 0.5 and density 200, each switched synth -> buffer -> input -> synth with each switch processed before the next (as E3 detents arrive), then stopped and started. At the last switch every voice holds its live voice, grain and mod synths, the input grain synth in its 2 s release and the buffer grain synth in its 50 ms cut: 21 grain synths and 7 voice synths, about 6920 KB, leaving about 1270 KB of the 8192 KB pool (largest free block about 1240 KB)
- bursts: switches that arrive inside one 50 ms cut (a chord of grid scene buttons recalls each scene at once and every recall switches each voice; PMAP-mapped `v<i>_source` params) would leave a synth in its kill fade per switch. Every step that makes a new fading set therefore first frees, at once (`freeCuttingSynths`: `/n_free` in a bundle with `/error -1`, since one may have just ended its fade on the server), the synths an earlier cut left in their fade (`cuttingSynths[voice]`, filled by `cutVoiceSynth`, emptied by `onFree`), then cuts the current fading set (`replaceFadingSynths`): a switch (`cutFadingSynths`), and a `voiceOn` that meets releasing synths built for another source (`gateVoice` hands them to `fadingSynths` through `fadeSupersededSynths`, before it starts anything; `releaseVoice` does the same with a superseded synth, which `gateVoice` no longer leaves). A synth freed this way stops without the rest of its 50 ms fade; that only happens to a synth already fading out under a newer one
- recalls (#46): scenes A = on/synth, B = off/input, C = on/buffer recalled A -> B -> A -> C at once (a grid chord, a fast scene sequencer). Before #46 `gateVoice` left the input grain synth B had built releasing beside the new one and outside `fadingSynths`, so C's switch found live, fading, and two cutting sets per voice (about 967 KB against 693 KB, about 1.9 MB past the pool over seven voices: new grain synths got `alloc failed`). Now the voice holds its live synths, one fading set (at most one grain and one voice synth) and one cutting set, however switches, stops and starts interleave, and A -> B -> A -> C ends with the same synths as the peak above (21 grain synths, 7 voice synths): the peak is the real bound. Lua also stops a voice a recall stops before setting its source (see `docs/notes/lua.md`, Scenes), so B no longer builds that input grain synth at all
- before #19, seven voices at grain size 0.5 alone used about 10300 KB (measured on a 64 MB pool), more than the whole pool: allocations failed as soon as several voices ran at large grain sizes

The engine check boots its server with `memSize = 8192` (norns' value, set explicitly), runs that peak, the burst (three switches of every voice at once) and the A -> B -> A -> C recalls at once (in the order Lua sent them before #46, the worst one), and each time starts four 256 KB probes (`\strataCheckMemProbe`, a `DelayN` that passes 1 or reads 0 when its allocation failed) at once (on a zeroed bus, so a probe whose `/s_new` fails reads 0): all must allocate, so the worst case leaves at least 1 MB free (about 250 KB more than that today, so a per-voice addition of more than about 10 KB per synth needs a look at the budget first). `test/run_engine_check.sh` also fails on any `alloc failed` in the server output. A new UGen with a delay line or table in a per-voice SynthDef multiplies by up to three grain (or two voice) synths per voice: rerun the check, and keep the headroom.

### Node Ordering

Everything runs inside the engine group `context.xg`, so norns' output group (`og`) and its meters come after the engine:
```
context.xg: voiceGroup (strataInput, voice synths, strataRecord) -> processGroup (bus-reading grain synths, then mirroring grain synths each before its voice's mod synth) -> strataFilter -> strataDelay -> strataReverb -> strataMaster
```
`voiceGroup = Group.head(context.xg)`, `processGroup = Group.after(voiceGroup)`, and filter, delay, reverb and master are added in that order with `\addToTail` on `context.xg`. `inputSynth` is added at the head of `voiceGroup` and record synths right after it. Mod synths go to the tail of `processGroup`. Grain synths are placed by `startPlacedGrainSynth`, so the order holds after any history of source switches and voice restarts: one that reads the voice bus (synth source) at the **head** of `processGroup`, before every grain synth that mirrors into a voice bus (so it never re-grains a releasing mirror); one that mirrors (buffer and input sources) is created at the tail of `processGroup` and then moved before the voice's running `\strataMod` (`moveBefore`), or stays at the tail when the voice has none yet (`gateVoice` starts or re-gates the mod synth after the grain synth; a re-gated mod synth is moved after a mirroring grain synth with `moveAfter`). A move whose target has just freed on the server (its `/n_end` not yet in sclang) only fails, and the mod synth's `onFree` restart goes to the tail; an `/s_new` relative to such a node would create nothing and leave a phantom grain synth that never frees, so no grain synth is ever created relative to another synth. Every grain synth of a voice therefore runs before that voice's mod synth (not necessarily before other voices' mod synths, which do not read its bus); the engine check reads `/g_queryTree` with controls after 0 -> 3 -> 9 -> 0 switches within 1 s.

### Synth Lifecycle

Synths use `gate` with ASR envelopes:
- Starting: `voiceOn` resets `voiceControls`, merges its grain values into `grainControls` and calls `gateVoice`, which never stacks synths. Synths the voice still has are **re-gated**: a running voice's only take the voiceOn values (`set`); a released voice's synths still in their release (`releasingSynths[voice]`, liveness = `isPlaying`) get `\gate, 1` (the ASR restarts its attack from the current level) plus the voiceOn values with `set`; the ones that have already freed are created (`Synth.new` with `gate=1`). The voice synth's release is 2-12 s but the grain synth's is 2 s and the mod synth's 0.5 s, so late in a release only the voice synth is re-gated. Controls not in the voiceOn reset keep their old values on a re-gated synth until Lua's `sync_voice_to_engine` (always right after `voiceOn`) sends them; a re-gated buffer grain synth also gets the slot's current `bufnumL/R`, `bufFrames` and (with audio) `bufRateScale` (`bufferSlotPairs`), since `bufferChanged` sends a releasing grain synth only `bufFrames 0` and the slot may have been loaded, recorded or cleared during the release. A releasing synth that no longer fits the source (it changed while the voice was stopped) is treated like a synth a switch replaces, before anything new starts (`fadeSupersededSynths`): a grain synth built for another source (`releasedGrainSource[voice]`) finishes its release and a voice synth when the source is no longer the synth is given a forced release (`release(grainRelease)`), both as the voice's `fadingSynths`, after the cutting synths are freed and the fading ones cut (`replaceFadingSynths`). So the next switch, or the next such start, cuts them, and a voice never holds more than its live synths, one fading and one cutting set (#46; the new grain synth is placed by `startPlacedGrainSynth`). Buffer- and input-sourced voices re-gate their grain and mod synths the same way
- Stopping: `releaseVoice` sets `\gate, 0` (release phase), removes the trio from `synths` (a buffer- or input-sourced voice has only a grain and a mod synth) and keeps it in `releasingSynths[voice]` (the grain's source in `releasedGrainSource`) for `voiceOn` to re-gate. `gateVoice` leaves nothing releasing beside running synths, so no different synth should already be releasing under the same key; one that is joins the fading set as `gateVoice`'s do (`fadeSupersededSynths`), so no releasing synth goes untracked (voice and grain keys only: a releasing mod synth is always re-gated, never superseded, and `\strataMod` has no kill fade). Fast voiceOff / source change / voiceOn / switch cycles inside one 50 ms cut never pile up synths. The engine check runs six such cycles on one voice, through the synth, buffer and input sources, twice. First it counts the engine's own tracking (live, releasing, fading and cutting synths) after every command, with all 24 commands sent without a yield: no `/n_end` is handled meanwhile, so the count does not depend on server timing. It finds at most three grain synths and three voice synths, and two voice synths at once after a stop on the synth source, a start on the input and a switch back to the synth (so the count measures something; the engine before #46 held five grain synths there). Then it counts the server's node tree after every step, as an upper bound only. Should a superseded synth ever be found in `releasingSynths` (by `releaseVoice`, or by `cutFadingSynths` for a running voice), the engine handles it as above and posts one `WARNING: Strata invariant broken: ...` line (`warnInvariant`), which shows in maiden and fails `test/run_engine_check.sh`. The engine check provokes both cases with stand-in synths. It captures the lines through `postInvariantWarning` (nil by default: `String.warn`) so its own run does not fail, and checks that the script's failure pattern matches them
- Gate of every ASR: `openedGate(gate)` = `Select.kr(Impulse.kr(0) > 0, [gate, 1])`, used by every voice, grain and mod SynthDef. EnvGen starts only when its gate rises above 0, so a synth created and gated off in one control block (a MIDI note on and note off in one ~1.3 ms block, `voiceOn` + `voiceOff` in one bundle) would never start its ASR and never free. The opened gate is 1 in the synth's first block and the plain `gate` control after it, so that synth starts and releases from its second block, and normal releases, forced releases (negative gates; never `gate.max(...)`, which clamps them to a plain gate 0 and turns the 2 s cut into the full natural release) and re-gates are unchanged
- Watching: every voice, grain and mod synth is created through `startVoiceSynth`/`startGrainSynth`/`startModSynth`, which call `watchVoiceSynth` (`register(true)`, so `isPlaying` holds from creation, then `onFree`). A freed synth is dropped from `releasingSynths`. A synth still in `synths` when it frees was re-gated just as its release ended (the gate arrived too late); it is started again so the voice is never left without it. `free` empties `synths` after freeing them so nothing restarts
- Switching source: `replaceGrainSynth` (see Audio Sources); the synths it releases are tracked in `fadingSynths[voice]` and cut (`cutVoiceSynth`: `cutSynth`, the kill fade, recorded in `cuttingSynths[voice]`) by the next switch, which also frees at once any synth still in its kill fade from the switch before (see Real-time memory)
- `doneAction: 2` frees the synth after release (or after its kill fade)
- Per-voice commands go through `setSynth(key, ...)`, which ignores voices that are not running, and voice indices are range-checked with `validVoice`
- **Messages to synths that can end on their own go through `sendToSynth`**: a bundle with `/error -1`, which turns the server's error reports off for that bundle only. Such a synth may have freed on the server a moment ago with its `/n_end` not yet in sclang (`isPlaying` still true), and a message to it would post `FAILURE IN SERVER ... Node not found` (which `test/run_engine_check.sh` fails on: a flake) and send a `/fail`. The racy sends: `gateVoice` re-gating releasing synths (`set`), giving a superseded voice synth its forced release and moving a re-gated mod synth (`moveAfter`); `cutSynth` on fading synths; `freeCuttingSynths`; `bufferChanged` on releasing and fading grain synths; and, for live synths (which free when their release ended just as `voiceOn` re-gated them), `setSynth`, `releaseVoice`, `replaceGrainSynth`'s forced releases and `startPlacedGrainSynth`'s `moveBefore` the mod synth; `stopRecording` freeing a record synth whose take may have just ended (`freeMsg`, then `free(false)` to mark it freed). The engine check provokes each: it frees the synths on the server behind sclang's back, sends the command at once and expects no `/fail`
