# Engine and Lua/engine interface notes

Detailed reference moved out of CLAUDE.md (which keeps the rules and the command table). Read the section you need; grep for the function or SynthDef name.

## Architecture

### Dual-Language System

This project uses two languages that work together:

1. **strata.lua** - The norns script (Lua)
   - User interface and control logic
   - Parameter management
   - Encoder/key handling
   - Communicates with the SuperCollider engine via `engine.*` commands

2. **lib/Engine_Strata.sc** - The audio engine (SuperCollider)
   - All synthesis and audio processing
   - Exposes commands to Lua via `this.addCommand()`
   - Manages audio buses, synths, and signal routing

### Audio Signal Flow

```
Voice Synth → Voice Bus → Granular Processor → Main Bus → Filter → Filter Bus → Delay → Delay Bus → Reverb → Reverb Bus → Master (drift/limiter/saturation) → Output
                  ↓
              Mod Synth → Mod Bus → Other Voice Synths (cross-modulation)

Buffer source:  Buffer pair (L/R) → strataGrainBuf → Main Bus (and mirrored to the Voice Bus → Mod Synth)
Input source:   SoundIn → strataInput → Input Bus → strataGrain → Main Bus (and mirrored to the Voice Bus → Mod Synth)
```

Each of the 7 voices follows this path (synth source; see Audio Sources for buffer and input sources):
1. Voice synth (strataResonator/strataFM/strataFolder/strataSub/strataPulse/strataKarplus/strataRing) outputs to its own `granBuses[i]`
2. Granular processor (`strataGrain`) reads from voice bus, outputs to shared `mainBus`. A buffer-sourced voice has no voice synth: `strataGrainBuf` reads its buffer pair; an input-sourced voice's `strataGrain` reads `inputBus`. Both also write their output to `granBuses[i]` (the mirror)
3. Modulation synth (`strataMod`) analyzes voice bus output (the voice synth, or the mirror) and generates control signal to `modBuses[i]`
4. Other voice synths can read from any `modBuses[i]` to modulate their amplitude and/or frequency
5. Filter (`strataFilter`) processes mainBus, outputs to `filterBus`; delay (`strataDelay`) processes filterBus, outputs to `delayBus`
6. Reverb (`strataReverb`) processes delayBus, outputs to `reverbBus`
7. Master (`strataMaster`) applies drift, a `Limiter.ar(sig, 0.95)` safety stage that catches peaks before saturation, then saturation, and outputs to norns output

### Cross-Modulation System

Each voice generates a modulation signal (envelope follower + slow LFO) that can modulate other voices:
- **Modulation Output**: Each voice has a `strataMod` synth that analyzes its audio output and creates a control signal (0-1 range)
- **Modulation Input**: Each voice synth can receive modulation from up to 3 different sources simultaneously
- **3 Modulation Slots**: Each voice has 3 independent modulation slots, each with its own source and depth controls
- **Routing**: Controlled via `setModSource(voice, slot, sourceVoice)` where slot is 1-3
- **Depth Control**: Each slot has independent `modAmpAmt` and `modFreqAmt` controls
- **Signal Mixing**: The 3 modulation signals are mixed together (weighted sum) before applying to voice parameters
- **Signal Character**: The mod signal combines envelope following (70%) with slow LFO movement (30%) for organic evolution


### Lua ↔ SuperCollider details

The command table itself is in CLAUDE.md (the docs test reads it there).

**Poll `bufferState`** (engine → Lua): each slot's valid seconds. matron's `/poll/value` handler is typed `"if"` (one float) and its data-blob polls are broken (`w_handle_poll_data` writes every byte to index 1), so a string or table cannot reach Lua: every message carries **one** slot as `slot_index * 100 + seconds` (`bufferStateStride = 100`; seconds ≤ 16, rounded to 0.01). Decode in Lua with `slot = math.floor(value / 100)` (0-based, so Lua slot `slot + 1`) and `seconds = value - slot * 100`. The poll is periodic (0.25 s) and cycles through the eight slots; every change (load, record start, completion and early stop, clear) is also sent immediately via `bufferStatePoll.update`. A slot reads 0 s while it records and its length once the recording completes. Lua: `init` calls `poll.set("bufferState", buffer_state_changed)` and starts it (it prints a message if the poll is missing); `buffer_state_changed` decodes the value with `BUFFER_STATE_STRIDE` (100) into `buffers[slot].seconds`, ignores slots outside 1..`NUM_BUFFERS`, and settles a take or load waiting for the engine, or adopts a late take or load (see the buffers table under Audio Sources); `cleanup` stops it.

**Index Conversion**: Voice indices are 0-indexed in SuperCollider but 1-indexed in Lua. Always subtract 1 when calling engine commands from Lua (e.g., `engine.voiceOn(voice_idx - 1, ...)`). Mod sources are converted by `engine_mod_source()` (Lua 0=none / 1-7 → SC -1=none / 0-6).

**Starting a voice (`toggle_voice` → `sync_voice_to_engine`)**: `voiceOn` only carries the initial freq/amp/pan and grain size/density/pitch (density = `engine_param_value("v<i>_grain_density") * engine_param_value("master_density")`, the values the engine has, as the senders use), and param actions only reach the engine while a voice is active. So `toggle_voice` calls `sync_voice_to_engine(voice_idx)` right after `engine.voiceOn`, which sends `setGrainSource(voice, source - 1)` **first**, then (`sync_voice_values_to_engine`) every `voices[i].params` entry (`setVoiceParam`), all nine grain params (`setGrainParam`: size, density × `master_density`, pitch, spread, `envShape` and `grainMode` = option index − 1, `bufPos`, `bufRate`, `bufScan`), every crossmod slot (`setModSource`/`setModAmpAmt`/`setModFreqAmt`) and `setModSpeed`. The engine holds no per-voice defaults of its own (there is no `getVoiceParams`); the Lua `voices` table is the only source of values. The `v<i>_source` param action is the one voice param that also reaches a stopped voice: it always sends `setGrainSource` (the engine only records it, so the next `voiceOn` builds the right synths), then, for a running voice, `sync_voice_values_to_engine` (not while `scene_recall_in_progress`: a scene recall syncs once at its end, see Scene System). `setGrainSource` after `voiceOn` in `sync_voice_to_engine` is then a no-op in the engine.

**Silent bus**: An unrouted mod slot must read a bus that is always zero. Control bus 0 is not safe on norns (CroneAudioContext allocates the input amplitude follower `amp_in_b` there before any engine loads), so the engine allocates `silentBus` in `alloc`, sets it to 0, uses its index for `sourceVoice = -1` and as the `voiceOn` default for `modBus1..3`, and frees it in `free`.

**Retrigger**: Pattern steps never create synth nodes. For a running voice the pattern clock calls `engine.retrigger(voice - 1, level / MAX_STEP_LEVEL)` (step level 1-15, so a step's brightness is its velocity). The engine sets `velocity` and `t_trig` in one message on the voice synth and on the grain synth. Every voice SynthDef has a plain `velocity=1` control and an accent envelope `EnvGen.kr(Env.perc(0.005, 0.4), t_trig, levelScale: velocity)` applied as `modAmp * (1 + accent)` inside the amplitude clamp. `levelScale` is sampled when the envelope (re)starts, so a new velocity never rescales a running accent tail; never multiply a running signal by `velocity`. Karplus also feeds `T2A.ar(t_trig) * velocity` (a single-sample impulse, so only that trigger's excitation is scaled) into its exciter and `Pluck` trig inputs so it re-plucks as hard as the velocity. In `\strataGrain` the trigger only matters in triggered grain mode (one grain per trigger). For buffer and input sources there is no voice synth, so the accent lives in the grain synth: `\strataGrainBuf` and `\strataGrain` have the same `EnvGen.kr(Env.perc(0.005, 0.4), t_trig, levelScale: velocity)` accent. `\strataGrain` applies it only with `accentAmt = 1` (input source); for the synth source the engine sets `accentAmt = 0` so voices are not double-accented and velocity reaches triggered grains through the voice accent. Grain-side velocity is always per trigger (`levelScale`), never a bare multiplier on the output (`GrainIn`/`GrainBuf` grains still playing would jump); the engine check asserts `velocity` feeds only `EnvGen` `levelScale` inputs in both grain SynthDefs. A step on a stopped voice starts it with `toggle_voice`. K3 on MAIN keeps its start/freeze meaning: triggered grains fire from pattern steps and MIDI notes only (a deliberate deviation from the spec's "K3 on MAIN with the voice already on").

**Pitchbend (`bend`)**: every voice SynthDef has `bend=1` multiplying its frequency (`modFreq = freq * bend * (1 + ...)`; FM's `modFreqVal`), and `\strataGrainBuf` has `bend` in its rate (`bufRate * bend * ...`; `\strataGrain` declares it unused). It is transient: not a Lua param, not in `voices`, not captured by scenes. Lua sends it only as `setVoiceParam(voice, "bend", ratio)` (never `setGrainParam`): the engine's `setVoiceControl` keeps it in `voiceControls` and passes it to `\strataGrainBuf` for a buffer source, so a source switch carries the current bend to the new synths. `voiceOn` resets it to 1 in the engine and `sync_voice_values_to_engine` then sends `midi_state.bend[i]` (the wheel's current position, 1 at rest), so a restart never leaves a stale bend and a voice started while the wheel is held plays bent.

**Current Voice Parameters** (as of latest sync):
- **Resonator**: freq, rq, noise, mod1, mod2, amp, pan
- **FM**: freq, ratio, index, modFreq, amp, pan
- **Folder**: freq, fold, mod, amp, pan
- **Sub**: freq, drift, amp
- **Pulse**: freq, width, cutoff, res, amp, pan
- **Karplus**: freq, decay, damping, excite, amp, pan
- **Ring**: freq, ratio, mod, brightness, amp, pan

**Current Granular Parameters**: grainSize, grainDensity, pitchShift, posSpread, envShape, grainMode, bufPos, bufRate, bufScan (the last three only matter to `\strataGrainBuf`, i.e. buffer sources; Lua `v<i>_buf_pos` 0-1 lin step 0, `v<i>_buf_rate` 0.25-4 exp, `v<i>_buf_scan` -2..2 lin, in `voices[i].grain.buf_pos|buf_rate|buf_scan`)
- `envShape` (Lua option `v<i>_grain_env`, `GRAIN_ENV_OPTIONS = {"hann", "sine", "perc", "linen", "trap"}`, default hann; `voices[i].grain.env` holds the option index 1-5) is sent as index − 1. The engine's `envBufnumFor(index)` turns it into the grain synth's `envBuf`: 0 = `-1` (GrainIn's built-in Hann), 1-4 = `envBuffers[index - 1].bufnum`; any other index is ignored. `envBuffers` are four 1024-frame `Buffer.loadCollection`s of `Env.sine`, `Env.perc(0.1, 0.9)`, `Env.linen(0.1, 0.8, 0.1)` and the trapezoid `Env([0, 1, 1, 0], [0.25, 0.5, 0.25])`
- `grainMode` (Lua option `v<i>_grain_mode`, `GRAIN_MODE_OPTIONS = {"continuous", "triggered"}`, default continuous; `voices[i].grain.mode` holds the option index 1-2) is sent as index − 1. `\strataGrain` picks its `GrainIn`s' trigger with `Select.ar(mode, [Impulse.ar(grainDensity), T2A.ar(t_trig)])` (`mode = grainMode.round.clip(0, 1)`): continuous fires `grainDensity` grains per second, triggered fires one grain per `retrigger` (its level follows the voice accent, not a grain-side velocity) and mutes the position-spread path so only the triggered grains sound (`spreadLevel` is lagged 50 ms, so a mode change fades instead of clicking). In triggered mode `grainDensity` does nothing, and neither does `posSpread` for synth and input sources (`\strataGrainBuf` still jitters each triggered grain's position by it). MAIN shows `[TRIG]` for a voice in triggered mode
- `DISCRETE_GRAIN_KEYS` (`{ env = #GRAIN_ENV_OPTIONS, mode = #GRAIN_MODE_OPTIONS }`) maps the grain keys that hold an option index to their option count: `scene_transition_targets` skips them (they switch when the fade ends), mutation and randomize never touch them, and `validate_scene` requires integers from 1 to the count
- `pitchShift` (Lua `grain_pitch`, 0.25-4) is a real transposition: the grain output runs through `PitchShift.ar` (window = the engine's fixed `pitchShiftWindow`, 0.1 s, whatever the grain size; ratio = `pitchShift.lag(0.5)`). It is not a gain. The window is fixed because `PitchShift` allocates its delay line from scsynth's real-time memory when the synth starts, sized by that window: when it followed `grainSize` (up to 0.5 s) seven voices could exhaust norns' pool (see Real-time memory).

**Cross-Modulation Parameters** (per voice, 3 slots per voice):
- **Slot 1, 2, 3** - Each slot has:
  - **source**: Which voice modulates this slot (0=none, 1-7 in Lua, -1=none, 0-6 in SC)
  - **amp_amt**: Amplitude modulation depth (-2 to 2, bipolar)
  - **freq_amt**: Frequency modulation depth (-2 to 2, bipolar)
- **speed**: Modulation signal LFO speed (0.1 to 50 Hz, shared across all slots)

### Audio Sources (buffers and live input)

Every voice's grain stage has a source (`grainSource[voice]`): 0 = its own synth (the voice synth writes `granBuses[i]`, `\strataGrain` reads it), 1-8 = buffer slot, 9 = live input. The engine side:

- **Buffer slots**: `numBuffers = 8` slots (mirrors Lua `NUM_BUFFERS`), each a pair of mono buffers `buffersL[i]`/`buffersR[i]` (GrainBuf reads mono buffers only) of `sampleRate * bufferSeconds` frames (`bufferSeconds = 16`, mirrors `BUFFER_SECONDS`). Memory: 8 × 2 × 16 s × 48 kHz × 4 bytes ≈ 49 MB of scsynth memory. Never allocate longer buffers. `bufferFrames[i]` is the valid length (0 = empty); `bufferSampleRates[i]` the content's sample rate. bufnums never change: loads read into the existing buffers
- **`\strataGrainBuf`**: two `GrainBuf.ar(1, ...)` (left, right) sharing one trigger, position, rate and duration, so grains stay sample-aligned and the stereo image is kept; `Balance2` with `LFNoise1.kr(2).range(panSpread.neg, panSpread)`, then one `PitchShift` stage on the pair. The output (main and mirror) is multiplied by `(bufFrames > 0).lag(0.05)`: an empty slot or one being recorded (`bufFrames` 0 until the take completes) is silent instead of every grain reading position 0 and looping the take's first grain. `bufPos` (0-1) and the scan are fractions of the valid region (`bufFrames / BufFrames`), so a 2 s sample uses the whole range; `bufScan` moves the position in **valid-region lengths per second** (spec §1; bipolar, wraps); grain position jitter ± `posSpread * 0.5`. Rate = `bufRate * bend * (bufRateScale / BufRateScale.kr(bufnumL)) * (1 + rateMod)` where `bufRateScale` = content rate / server rate, tracked by the engine (`b_alloc`/`b_zero` keep a loaded file's rate on the server buffer and norns' scsynth predates `b_setSampleRate`, so `BufRateScale.kr` would be wrong after recording into a slot that held a file). `GrainBuf` itself already multiplies the rate by the buffer's own rate scale (the server's `BufRateScale`), so dividing it out applies the engine's scale exactly once: without the division a 44.1 kHz file played 1.5 semitones flat on a 48 kHz server (the engine check measured a 1 kHz sine at 920 Hz), and dropping `bufRateScale` instead would play a take recorded over a 44.1 kHz file flat. The engine check measures both with `Pitch` (1 kHz from a 44.1 kHz file, 440 Hz from a take recorded over it). Crossmod applies to amplitude and rate like voices (`rateMod` clamped -0.9..2), the accent is per trigger, and `grainMode` works as in `\strataGrain`
- **Live input**: the persistent `\strataInput` synth (`SoundIn.ar([0, 1])` → stereo `inputBus`) at the head of `voiceGroup`. Input-sourced voices run `\strataGrain` with `in = inputBus`
- **Mirror to the voice bus**: with no voice synth, a buffer- or input-sourced voice's `granBuses[i]` would be silent and its `\strataMod` (and every voice it modulates) would go dead. So both grain SynthDefs write `sig * mirrorLevel` to `mirrorOut` (= `granBuses[i]`) as well as `mainBus`. `mirrorLevel` defaults to 0 in both (and `mirrorOut` to bus 0), so a grain synth built without them mirrors nothing; `startGrainSynth` always sets it: 1 for `\strataGrainBuf` and the input `\strataGrain`, 0 in synth mode (that grain synth reads `granBuses[i]`, so mirroring would feed back). Mirroring grain synths run right before their voice's `\strataMod` (see Node Ordering), so the mirror reaches it in the same block
- **Voice-level controls follow the source**: `voiceControls[voice]` keeps every `setVoiceParam` and crossmod value (reset by `voiceOn` to its freq/amp/pan and silent routing) and `grainControls[voice]` every `setGrainParam` (`voiceOn` merges its size/density/pitch into it with `putAll` and keeps the rest, so a grain synth `voiceOn` builds starts in the voice's grain mode, envelope and buffer position instead of firing continuous grains until Lua's `grainMode` arrives; `envShape` stored as `envBuf`). When the source is not the synth, `setVoiceControl` also sends the controls the grain SynthDef has: `amp` (the voice's level), `bend` and the crossmod routing/amounts for `\strataGrainBuf`, `amp` and the amplitude crossmod (`modBus1..3`, `modAmpAmt1..3`) for the input `\strataGrain`, which applies it like the voices (`(1 + mod).clip` on the level) only with `modLevel = 1`. Frequency crossmod has no meaning for live input and is ignored (`\strataGrain` has no `modFreqAmt`). The synth-source `\strataGrain` keeps `amp = 1` and `modLevel = 0` (the voice synth applies the level and the crossmod; applying it again would double it), and gets `modBus1..3 = silentBus` so it never reads control bus 0 (the SynthDef defaults are 0). `controlPairs` filters against a per-SynthDef `IdentitySet` of control names (`controlNameSets`, built in `alloc` for the voice and grain SynthDefs)

**Replace, never stack.** `setGrainSource` on a running voice calls `replaceGrainSynth`: the new grain synth is created with the voice's current `grainControls` (and voice-level controls) and the old one gets a forced release (`release(grainRelease)`, 2 s, linear) in the same call, so one voice never runs two grain paths beyond that release. First `cutFadingSynths(voice)` cuts everything an earlier switch left releasing (`fadingSynths[voice]`, an `IdentitySet` emptied by the cut and by `onFree`) and any grain or voice synth `voiceOff` left in `releasingSynths` that `voiceOn` did not re-gate, so once a switch has been processed (within `switchCutTime`) a voice has at most one releasing grain synth and at most one releasing voice synth, however fast or slowly the sources are scrolled (one switch per E3 detent); there is no Lua-side debounce. A switch first frees at once whatever an earlier cut left still in its kill fade (`freeCuttingSynths`), so even switches faster than `switchCutTime` leave at most one cutting set per voice (see Real-time memory). **Cutting is `cutSynth`, the kill fade, never a second forced release**: EnvGen starts a forced release only when its gate crosses -1 from above (`gate <= -1 && prevGate > -1`), so a synth already in `release(grainRelease)` (gate -3) ignores `release(0.05)` (gate -1.05) and would run its full 2 s. Every voice and grain SynthDef multiplies `killFade(kill)` into its ASR: `EnvGen.kr(Env([1, 0], [switchCutTime]), kill, doneAction: 2)`, which holds level 1 until the `kill` control rises above 0 and then fades linearly to 0 in `switchCutTime` (0.05 s; built into the SynthDefs in `alloc`, so changing it later has no effect) and frees the synth, whatever the ASR is doing. `kill` is that EnvGen's trigger, not its gate (`Env.cutoff` on `1 - kill` would never start in a synth killed in its creation block and would play on at full level). `cutSynth(synth)` sends `\kill, 1` to a synth that `isPlaying`; a killed synth is never re-gated (it has already left `synths` and `releasingSynths`). Leaving the synth source releases the voice synth with `release(grainRelease)` (a forced release: its sound only reached the output through the old grain synth, so it does not run its own up-to-12 s release silently) and adds it to `fadingSynths`; returning to the synth source starts a new voice synth from `voiceControls`. New grain synths are placed by `startPlacedGrainSynth` (see Node Ordering), never next to a releasing synth: that one may have freed on the server already, and an `/s_new` to a missing target creates nothing. `voiceOn` for a voice whose source is not 0 builds `\strataGrainBuf` (or the input `\strataGrain`) directly and no voice synth. `setGrainSource` with the current source does nothing (Lua sends it on every voice start).

**Buffer commands** (`loadSlot`, `recordSlot`, `clearSlot`, `writeSlot` in the engine): load opens the file with `SoundFile` (frames, channels, rate) and `readChannel`s at most `bufferSeconds` of it into the existing buffers, capped by the buffers' size (`bufferSeconds` at the **server** rate): a 96 kHz file keeps 8 s on a 48 kHz server, a 44.1 kHz file the full 16 s. A missing, unreadable or empty file (`rejectLoad`) is logged and leaves the slot unchanged (before anything is zeroed), except that it cancels a recording in progress or waiting to start in that slot, or one `stopRecord` ended whose frame count has not arrived yet (`stopReplies[i]` holds that stop's `slotChanges` count until the reply; the bad load's `slotChanged` drops the reply) (`stopRecording`, `slotChanged`): Lua's `load_buffer` ends the recording state, so a take that completed anyway would be adopted under the bad file's name and path (and lost at the next restore). The slot then reads 0 frames, as for a recording a clear cancelled. A good load sets the slot's frames to 0 at once, zeroes the pair and reads after the fade (below); the slot's `bufferFrames`/`bufferSampleRates`, the grain synths reading it and the poll get the new length only once the reads have completed (a `server.sync` after them in a `fork`). **Fade before zeroing**: `b_zero` and `b_readChannel` complete within about a millisecond, far inside `\strataGrainBuf`'s 50 ms `hasAudio` lag, so load, record and clear first set the slot's `bufferFrames` to 0 (`bufferChanged` sends it to the running grain synths reading it, and the poll reports 0) and only then zero or overwrite the buffers, through `afterSlotFade(index, change, action)`: `bufferFadeWait` (0.06 s, settable; the engine check lengthens it) later when a running voice's grain synth reads the slot (`slotPlaying`), at once otherwise, so a recording into an unplayed slot starts without delay. The delayed action runs only if `slotChanges[index]` is still `change`, so a later load, record or clear inside the wait wins (the earlier command's zeroing, read or record start is dropped, the later one does its own). `free` bumps every slot's count, so nothing waiting runs on freed buffers. A grain synth that is releasing (after `voiceOff` or a source switch) does not get the fade and can still be cut. **`slotChanges[i]`** counts the changes to slot i (load, record, clear, stop, through `slotChanged(i)`); a reply that arrives later (the load's completion, `stopRecord`'s frame count) applies only if the count is what it was when the reply was requested, so a clear (or load, or new recording) sent before it wins. Record sets the slot to 0 frames, zeroes the pair after the fade and, after a `server.sync` (so the zeroing never lands on the take), starts a `\strataRecord` synth (two `RecordBuf`s of `In.ar(inputBus, 2) * level`, `loop: 0`, plus a `Line` with `doneAction: 2` for the duration) right after `inputSynth`, unless the recording was cancelled meanwhile (`recordSynths[i]` is the token; do not use a zero completion message: it cannot be cancelled before the node exists). The slot reads 0 frames until the recording completes (`onFree`), then gets its frames and the take is written to `scratchDir +/+ "buf<n>.wav"`. A new record, load (even one whose file cannot be read) or clear on the slot cancels a recording in progress or pending (`stopRecording`), which writes nothing. `stopRecord` (`stopRecordSlot`) instead keeps the take: the record synth writes its frame count (`Sweep.kr(0, SampleRate.ir)`) to the slot's `recordFrameBuses[i]`; the engine frees the synth, reads that bus (`/c_get` is answered after the `/n_free`, and the bus keeps its last value), sets `bufferFrames[i]` to it and writes the scratch take (unless `slotChanges[i]` moved meanwhile: `stopRecord` then `clearBuffer` in one go leaves the slot empty and writes nothing). Read `isPlaying` before freeing (`Node.free` clears it). A recording still waiting for its zeroed buffers has captured nothing and is just cancelled. `writeSlot(index, path)` (scratch takes and `saveBuffer`) has the server write each mono buffer's valid frames to a temporary float file, then sclang interleaves them in 8192-frame chunks (a per-frame loop: an array-level `lace` measured about twice as slow, since the `_ArrayLace` primitive only descends into `Array`s and each chunk would be converted FloatArray -> Array -> FloatArray; yielding `writeChunkWait`, 1 ms, between chunks; a 16 s take interleaves in about 0.06 s on a Mac) into a stereo 16-bit WAV at the content's rate and deletes the temporaries; it creates no synth nodes. The buffers are float and `record_level` goes to 2, so a take can hold samples beyond ±1: the interleave clips every sample to ±`int16Peak` (32767 / 32768), so the file is clipped deliberately and symmetrically (+32767 / -32767) whatever libsndfile's own float-to-int conversion does (without its clipping mode it wraps; with it, it clips to +32767 / -32768). Writes to the same path can overlap (a full 16 s take is still being written when the next, shorter take completes), so each write gets a generation number in `writeGenerations[path]`, interleaves into its own `path.<instanceTag>-<generation>.part` file (`instanceTag` is `UniqueID.next` at `alloc`, so two engine instances in one sclang session, before and after a script reload, never share a `.part` or temporary float file `strata-buf<n>-<tag>-<gen>-<L|R>.wav`), and renames it into place (`mv -f`, atomic on one filesystem; sclang has no `File.rename`) only if it is still the newest write for that path. An older write checks after every chunk, abandons as soon as a newer one starts, and deletes its `.part`. The newest write always wins, two writes never mix, and a reader never sees a half-written file. The newest write removes its `writeGenerations` entry when it ends, whether it succeeded or failed (a directory that cannot be made, `File.mkdir` throwing, is caught and reported as `cannot write`); an abandoned write leaves the newer one's entry. `alloc` calls `deleteStaleParts`, which deletes the `*.part` files a crash left in `scratchDir` (scratch takes) and in its parent (`saveBuffer`'s `<date>-buf<n>.wav.<tag>-<gen>.part` in `_path.audio/strata/`, visible in the file browser); nothing but `*.part` files, and only those last modified more than `stalePartAge` (60 s) ago (`File.mtime` against `Date.getDate.rawSeconds`; `File.mtime` throws for a file deleted since the glob, so it is wrapped in `try` and such a file is skipped): after a script reload in the same sclang session the previous instance's write routine may still be interleaving, and a running write touches its `.part` with every chunk. `stalePartDirs` picks the directories: `scratchDir` (with `~` expanded, trailing slash dropped) and its `dirname`, keeping only absolute paths below the root, so an empty, relative (`"."`, `"scratch/"`, whose `dirname` is `"."`) or root `scratchDir` never globs the working directory or `/` (never `standardizePath` it: that turns `"."` into the working directory). `test/run_engine_check.sh` starts sclang in its temp dir, so the check's working-directory marker never lands in the caller's directory. Never open the final path directly for writing: `SoundFile.openWrite` truncates it, and libsndfile rewrites the header on `close`. The engine check sets `writeChunkWait` to 0.02 s so the overlap is certain. Every change updates `bufferFrames`, the grain synths reading the slot (`bufFrames`, `bufRateScale`) and the `bufferState` poll.

**Scratch directory**: `scratchDir` (engine variable, settable) defaults to `Platform.userHomeDir +/+ "dust/audio/strata/scratch/"`, which equals Lua's `_path.audio .. "strata/scratch/"` on norns; it is created on demand before writing. `test/engine_check.scd` points it at a temporary directory so the check never writes into `~/dust`.

**Lua side** (strata.lua):
- **Per-voice source**: option `v<i>_source` over `SOURCE_OPTIONS = {"synth", "buf 1", ..., "buf 8", "input"}` (built from `NUM_BUFFERS`), default synth, held in `voices[i].source`. The action always sends `setGrainSource(i - 1, x - 1)`, then for a running voice `sync_voice_values_to_engine`, clamps the grid `param_page` and redraws the grid (the screen and arc follow on the next frame, as for every param action: `request_redraw`, see Redraws in `lua.md`). `voice_uses_synth(i)` (source 1), `voice_uses_buffer(i)` (sources 2-9; input is not a buffer) and `voice_source_label(i)` (the option name) are the helpers. The source params sit at the top of each voice's granular section with `v<i>_buf_pos`, `v<i>_buf_rate`, `v<i>_buf_scan`
- **Behaviour rules (spec §1, input amended by controller ruling)**: for a buffer source (`voice_uses_buffer`): E3, arc ring 2 and MAIN's main parameter are `buf_pos` (label `pos`, through `main_param_entry`), the 256 grid's first faders are `BUFFER_FADER_KEYS`, `randomize_voice` sets `buf_pos` (0-1), `buf_rate` (0.5-2, `2 ^ (r * 2 - 1)`) and `buf_scan` (-0.5..0.5) plus grain size/pitch instead of synthesis params, `gentle_mutate` mutates the buffer params instead of synthesis params, and `drift_update` drifts `buf_pos` as well as grain pitch. For the input source both the synth and the buffer params are dead in the engine, so the main param is `grain_size` (`INPUT_MAIN_PARAM`, label `size`, `%.2f s`), its faders start with the grain params (then `amp`), and `randomize_voice`, `gentle_mutate` and `drift_update` touch only grain params. Test with `voice_uses_synth` / `voice_uses_buffer`, never `not voice_uses_synth` (that includes input). `source` is never randomized or mutated; freeze covers the buffer params. `voice_buffer_slot(i)` is the slot (1-8) a buffer-sourced voice reads, or nil
- **Buffers table**: `buffers[slot]` = `{name, loaded, recording, finishing, restoring, settled_empty, seconds, path, confirm_since, missing_path}` per slot (`name = "empty"` until something is loaded or recorded). `load_buffer(slot, path)` sends `loadBuffer`, shows the path in `buf<n>_file` without running its action (`set_buffer_file_param`, a silent `params:set`) and sets `name` (the file name), `loaded` (optimistic, settled by the poll), `path`, `confirm_since = util.time()`, and clears `missing_path`; it ignores `""`, norns' `"-"` (no file chosen) and directory paths. norns' file param runs its action only when the path changes, so `record_buffer` (on start) and `clear_buffer` silently put `buf<n>_file` back at its starting folder `_path.audio` (which loads nothing and keeps the PARAMS browser in the audio folder): picking the same file again from PARAMS then loads it. The BUFFER page's file selector calls `load_buffer` directly, so it reloads even a file the param already shows, and a restored slot's param shows its path. `record_buffer(slot)` sends `recordBuffer(slot - 1, record_duration, record_level)`, sets `recording` and starts a `clock.run` timer of `record_duration` (`buffer_record_clocks[slot]`) that ends it with `finish_buffer_take(slot)`; called while the slot records, it sends `stopRecord` and calls `finish_buffer_take` at once. `finish_buffer_take` sets `finishing` and `confirm_since` (`recording` stays set, so the slot still shows `REC`; the BUFFER hint shows `K3:...`) and starts the slot's fallback clock in `buffer_record_clocks[slot]`: a press while `finishing` does nothing (no new take, no stop). **The poll settles takes and loads**: `buffer_state_changed` stores the seconds and, for a slot with `confirm_since` set, on any report (repeated or not), calls `settle_buffer_slot(slot)` when the seconds are > 0 or when 0 arrives at least `BUFFER_SETTLE.confirm_seconds` (1 s) after `confirm_since` (the periodic poll can carry a value read before the engine finished: the Lua timer ends just before the engine's take completes). `settle_buffer_slot` (global) works from `buffers[slot].seconds`: with audio it calls `confirm_buffer_audio(slot, is_take)` (global): `loaded = true`, a take gets `name = "take <n>"` and `path` = the scratch take `_path.audio .. "strata/scratch/buf<n>.wav"` (a load keeps its name), and a slot with `restoring` set (a `load_buffers_from_disk` load) counts once in `buffers_restored` (`restoring` stays set until then). Without audio a take leaves the slot empty (`name = "empty"`, `path = nil`; stopped in the engine's start-up window) and a load gets `loaded = false` (keeping its name); `settled_empty` records `"take"` or `"load"`. Either way `recording`/`finishing` clear and the fallback clock is cancelled. **Late takes and loads**: under sclang load a take can complete more than 1 s after the Lua timer, and the engine reports a load only when its reads complete (16 sequential `readChannel`s for a full restore on a CM3), so a periodic 0 can settle the slot empty first; a later report with seconds > 0 for a slot with `settled_empty` set adopts it through `confirm_buffer_audio` (loaded, named, counted when restoring). Load, clear and a new recording clear `settled_empty`, so they always win. **Fallback**: if no report arrives at all (no `bufferState` poll), the fallback clock settles a still-finishing slot `BUFFER_SETTLE.fallback_seconds` (5 s) after the take ended, from the last known seconds, so K3 is never ignored for good; load, clear, a new recording, a settle and `cleanup` cancel it (it lives in `buffer_record_clocks`). Known edge: an unreadable file loaded over earlier audio keeps that audio in the engine, so it settles as loaded under the new name. `clear_buffer(slot)` sends `clearBuffer` and resets the slot (including `finishing`, `restoring`, `settled_empty`, `confirm_since`, `missing_path`; a new recording clears `restoring`, `settled_empty`, `confirm_since` and `missing_path` too, and a load all but `confirm_since`, which it sets). Load, clear and stop cancel the slot's timer (the engine cancels its recording, even for a file it cannot read, so a bad load during a recording settles as a load that is not loaded, never as a take under the bad file's name). `save_buffer(slot)` does `util.make_dir(buffer_audio_dir)` and `saveBuffer(slot - 1, buffer_save_path(slot))` (`_path.audio .. "strata/<YYYYMMDD-HHMMSS>-buf<n>.wav"`) and prints the path; a slot the engine reports as empty (`seconds <= 0` from the poll) is not saved: `loaded` is set optimistically by `load_buffer` until the poll settles it, and a recording reads 0 s until it completes. `seconds` comes only from the poll. `scratch_take_path(slot)` is the take path; `load_buffer` names a scratch-take path `take <n>`, so a restored take keeps its name. Load, record (start, stop, timer end) and clear call `buffer_display_changed()` (`request_redraw()` + `grid_redraw()`: the BUFFER page and grid page 4 show the state); `buffer_state_changed` requests a screen redraw, and the grid while `grid_page == 4`, only when a slot's seconds change or it settles (the periodic poll repeats values). All four check the slot (1..`NUM_BUFFERS`); `cleanup` cancels the timers and stops the poll
- **Buffer params**: group `strata_buffers` (size `2 + NUM_BUFFERS * 4`): `record_duration` (0.5-`BUFFER_SECONDS` s, default 8), `record_level` (0-2, default 1), then per slot `buf<n>_file` (`params:add_file`, starting folder `_path.audio`; action `load_buffer`), `buf<n>_record`, `buf<n>_clear`, `buf<n>_save` triggers
- **Scenes** capture `voices[i].source` and the three buffer params (through `GRAIN_PARAM_IDS`), never buffer contents: a recalled scene plays whatever is in the slot now. `source` switches at the end of a smooth transition (it is not in `params`/`grain`, so `scene_transition_targets` skips it); the buffer params crossfade. `VOICE_SCENE_DEFAULTS` gives older scenes `source = 1` and the buffer params' defaults; `validate_scene` requires `source` to be an integer 1..`#SOURCE_OPTIONS`


## SuperCollider Architecture

### SynthDef Organization

Each voice type has its own SynthDef with unique parameters:
- `\strataResonator` - DynKlank resonator bank with filtered noise
- `\strataFM` - Two-operator FM with slow modulation
- `\strataFolder` - Wavefolder with sine input
- `\strataSub` - Ultra-low sine with drift
- `\strataPulse` - Pulse width modulation with resonant filtering
- `\strataKarplus` - Karplus-Strong plucked string physical model
- `\strataRing` - Ring modulation between two oscillators

All voice SynthDefs take `t_trig` and `velocity` controls driving an accent envelope (see Retrigger above), gate their ASR through `openedGate` and multiply in `killFade(kill)` like both grain SynthDefs (see Synth Lifecycle and "Replace, never stack"), and include multi-source cross-modulation inputs (3 slots):
- `modBus1`, `modBus2`, `modBus3` - Control buses to read modulation signals from (one per slot)
- `modAmpAmt1`, `modAmpAmt2`, `modAmpAmt3` - Amplitude modulation depths (-2 to 2)
- `modFreqAmt1`, `modFreqAmt2`, `modFreqAmt3` - Frequency modulation depths (-2 to 2)
- The 3 modulation signals are mixed together (weighted sum) before application

**Modulation Signal Clamping (v2.0+, frequency floor in v2.1)**:
To prevent excessive amplitude spikes when multiple modulation sources are active, every voice SynthDef (including FM and Sub) clamps:
```supercollider
// Mix modulation signals with clamping to prevent excessive modulation
modSig = ((mod1Sig * modAmpAmt1) + (mod2Sig * modAmpAmt2) + (mod3Sig * modAmpAmt3)).clip(-2, 2);
modFreq = freq * (1 + ((mod1Sig * modFreqAmt1) + (mod2Sig * modFreqAmt2) + (mod3Sig * modFreqAmt3)).clip(-0.9, 2));
modAmp = (amp * (1 + modSig) * (1 + accent)).clip(0, 2);
```
This prevents the theoretical 4× amplitude spike that could occur with 3 sources all at maximum positive modulation. The frequency modulator is clamped to -0.9 (not -2) so the modulated frequency never reaches zero or goes negative (Karplus uses `modFreq.reciprocal` as a delay time, Resonator uses it as a filter cutoff).

Shared processing SynthDefs:
- `\strataMod` - Envelope follower + LFO for generating modulation signals
- `\strataGrain` - Granular processor for a stereo bus (one per synth- or input-sourced voice); two mono `GrainIn.ar(1, ...)` (left and right input channel) on one trigger (envelope `envBuf`, default -1 = built-in Hann; trigger chosen by `grainMode`: `Impulse.ar(grainDensity)` or `T2A.ar(t_trig)`), panned as a pair with `Balance2` by `LFNoise1.kr(2).range(panSpread.neg, panSpread)` exactly like `\strataGrainBuf`, then one `PitchShift` stage on the pair for `pitchShift`. Never give it a stereo `GrainIn` on the stereo input: that expands to two GrainIns each panning its own channel, which `Out` folds back to one channel apiece (pan spread does nothing, the position-spread path is added twice, four `PitchShift`s). The voice's `pan` is applied by the voice synth's `Pan2`. Since this fix synth- and input-sourced voices are about 3-6 dB quieter than before it; compare levels across sources on hardware (no makeup gain has been added). The engine check asserts two mono GrainIns, two PitchShifts, `Balance2` and two stereo `Out`s. Input-source extras: `accentAmt` (grain-side accent), `mirrorOut`/`mirrorLevel` (copy to the voice bus, default 0), amplitude crossmod `modBus1..3`/`modAmpAmt1..3` gated by `modLevel` (default 0); `bend` is unused here. The position-spread path's level (`spreadLevel`) is lagged 50 ms
- `\strataGrainBuf` - Granular processor for a buffer slot (one per buffer-sourced voice); see Audio Sources
- `\strataInput` - Persistent live input: `SoundIn.ar([0, 1])` to `inputBus`
- `\strataRecord` - One recording into a slot's buffer pair; reports its frame count on `framesOut`; frees itself when done (or is freed by `stopRecord`)
- `\strataFilter` - Master multimode filter (`in, out, freq=5000, res=0.5, filterType=0, mix=0`): `RLPF`/`RHPF`/`BPF` at rq `1 - res * 0.95`, all three running, each weighted by `BinaryOpUGen('==', type, index).lag(0.02)` (`type = filterType.round.clip(0, 2)`; the weights sum to 1 once settled), so a type change crossfades over 20 ms instead of stepping (`Select.ar` jumped between the antiphase lowpass and highpass outputs; the engine check measures the largest sample step across type changes on a sine). Never compare a UGen with `==` directly: that is object identity in sclang, not a UGen. `mix` crossfades dry to filtered (0 = bypass)
- `\strataDelay` - Master stereo delay (`in, out, time=0.375, feedback=0.4, mix=0`): `DelayC` (max 2 s, `time.lag(0.1)`) fed by the input plus `LocalIn`, with the delayed signal times `feedback` sent back through `LocalOut`; `mix` crossfades dry to delayed
- The filter and delay SynthDef defaults equal the Lua param defaults: the script never bangs its params, so the engine starts from these values
- `\strataReverb` - Global reverb processor; outputs `FreeVerb2` only (it already crossfades dry/wet by `mix`)
- `\strataMaster` - Master output with drift, then `Limiter.ar(sig, 0.95)` to catch filter resonance and delay feedback peaks, then the tanh saturation. The limiter must stay before the saturator: `(sig * 2).tanh * 0.5` bounds its output to ±0.5, so a limiter after it could never act (the engine check asserts the order). Drift (master and Sub) is an LFO at a fixed slow rate scaled by the drift amount: tape drift 0 = none; the Sub drift param's minimum stays 0.001

### Audio Bus Management

Buses are allocated in `alloc` (`numVoices = 7` in the engine must match `NUM_VOICES` in Lua; use it for every per-voice `Array.fill`):
- `numVoices` stereo `granBuses` (one per voice, for audio)
- `numVoices` mono `modBuses` (one per voice, for control signals)
- 1 mono `silentBus` (always 0; "no modulation source")
- 1 stereo `mainBus` (granular outputs mix here; filter input)
- 1 stereo `filterBus` (filter output, delay input)
- 1 stereo `delayBus` (delay output, reverb input)
- 1 stereo `reverbBus` (reverb output, master input)
- 4 `envBuffers` (grain envelope shapes, 1024 frames each; see `envShape`)
- 1 stereo `inputBus` (live input from `\strataInput`)
- `numBuffers` mono control `recordFrameBuses` (frames recorded so far, for `stopRecord`)
- `numBuffers` (8) slot pairs `buffersL`/`buffersR`, mono, 16 s each (≈ 49 MB total; see Audio Sources)

Buses, buffers, the input synth and groups are freed in `free` to prevent resource leaks (recordings in progress are cancelled first so nothing is written on free).

### Real-time memory

Every UGen's delay lines and tables come from scsynth's real-time pool, allocated when a synth starts. norns never raises it: `Crone.sc` boots `Server.local` with `memSize` left at the `ServerOptions` default, **8192 KB** (its `memSize = 2**16` line is commented out). A UGen that cannot get its memory prints `<UGen>_Ctor: alloc failed` and outputs zeros, and a synth whose own node cannot be allocated fails with `/s_new out of real time memory`: either way that voice goes silent with nothing on screen. Buffers (`b_alloc`, the 49 MB of slots) are not in this pool.

What a grain synth takes, at 48 kHz (sizes round up to a power of two):
- `PitchShift`: `nextPow2(ceil(window × SR × 3 + 3) + 64)` floats per channel, two channels. At the fixed `pitchShiftWindow` of 0.1 s that is 16384 floats, 64 KB per channel, 128 KB per synth. Before #19 the window was `grainSize` (0.01-0.5 s): 1 MB per synth at 0.5 s.
- `GrainIn`/`GrainBuf` grain tables: `maxGrains` × 72 bytes (`GrainIn`) or × 96 bytes (`GrainBuf`) each, two per synth. `maxGrains` is 128 (the UGens' default is 512): the largest overlap Lua can ask for is grain size 0.5 s × density 100 × master density 2 = 100 grains, and a `GrainIn`/`GrainBuf` runs at most `maxGrains - 1` (beyond that it drops grains and prints `Too many grains!`). 128 saves about 55 KB per `\strataGrain` and 72 KB per `\strataGrainBuf` against 512.
- `\strataGrain`'s position-spread `DelayC` (0.2 s, stereo): 64 KB per channel.

**Why 0.1 s for `pitchShiftWindow`**: every voice's default pitch is 1 (no transposition), so at the defaults the change is only the shifter's latency; and 0.1 s is the largest common window in the 16384-float step (up to 0.113 s at 48 kHz, 0.123 s at 44.1 kHz). Anything from 0.114 s to 0.2 s (SuperCollider's default, used by `\strataMaster`'s drift) costs twice as much, 256 KB per grain synth, and at the peak below (21 grain synths) those 2.7 MB would exceed the pool. A shorter window also adds less delay (the shifter delays by about one window), so accents stay tight. A larger window is smoother on low, sustained material; at small grain sizes the fixed window is smoother than the old one (0.01 s windows buzzed).

**Budget** (measured on scsynth 3.14 at 48 kHz with `/rtMemoryStatus`; used KB of the pool):
- engine idle (effects chain, input, mod buses; delay 2 s stereo = 1 MB, master `PitchShift` 0.2 s = 256 KB, `FreeVerb2`): about 1460 KB
- one synth-sourced voice (voice, grain and mod synths): about 310 KB more; seven: about 3690 KB
- the peak: seven voices at grain size 0.5 and density 200, each switched synth -> buffer -> input -> synth with each switch processed before the next (as E3 detents arrive), then stopped and started. At the last switch every voice holds its live voice, grain and mod synths, the input grain synth in its 2 s release and the buffer grain synth in its 50 ms cut: 21 grain synths and 7 voice synths, about 6920 KB, leaving about 1270 KB of the 8192 KB pool (largest free block about 1240 KB)
- bursts: switches that arrive inside one 50 ms cut (a chord of grid scene buttons recalls each scene at once and every recall switches each voice; PMAP-mapped `v<i>_source` params) would leave a synth in its kill fade per switch. `cutFadingSynths` therefore first frees, at once (`freeCuttingSynths`: `/n_free` in a bundle with `/error -1`, since one may have just ended its fade on the server), the synths an earlier cut left in their fade (`cuttingSynths[voice]`, filled by `cutVoiceSynth`, emptied by `onFree`). So however fast the switches come, a voice holds at most its live synths, one releasing grain (and voice) synth and one cutting set: the peak above is the real bound. A synth freed this way stops without the rest of its 50 ms fade; that only happens to a synth already fading out under a newer one
- before #19, seven voices at grain size 0.5 alone used about 10300 KB (measured on a 64 MB pool), more than the whole pool: allocations failed as soon as several voices ran at large grain sizes

The engine check boots its server with `memSize = 8192` (norns' value, set explicitly), runs that peak and the burst (three switches of every voice at once), and each time starts four 256 KB probes (`\strataCheckMemProbe`, a `DelayN` that passes 1 or reads 0 when its allocation failed) at once (on a zeroed bus, so a probe whose `/s_new` fails reads 0): all must allocate, so the worst case leaves at least 1 MB free (about 250 KB more than that today, so a per-voice addition of more than about 10 KB per synth needs a look at the budget first). `test/run_engine_check.sh` also fails on any `alloc failed` in the server output. A new UGen with a delay line or table in a per-voice SynthDef multiplies by up to three grain (or two voice) synths per voice: rerun the check, and keep the headroom.

### Node Ordering

Everything runs inside the engine group `context.xg`, so norns' output group (`og`) and its meters come after the engine:
```
context.xg: voiceGroup (strataInput, voice synths, strataRecord) -> processGroup (bus-reading grain synths, then mirroring grain synths each before its voice's mod synth) -> strataFilter -> strataDelay -> strataReverb -> strataMaster
```
`voiceGroup = Group.head(context.xg)`, `processGroup = Group.after(voiceGroup)`, and filter, delay, reverb and master are added in that order with `\addToTail` on `context.xg`. `inputSynth` is added at the head of `voiceGroup` and record synths right after it. Mod synths go to the tail of `processGroup`. Grain synths are placed by `startPlacedGrainSynth`, so the order holds after any history of source switches and voice restarts: one that reads the voice bus (synth source) at the **head** of `processGroup`, before every grain synth that mirrors into a voice bus (so it never re-grains a releasing mirror); one that mirrors (buffer and input sources) is created at the tail of `processGroup` and then moved before the voice's running `\strataMod` (`moveBefore`), or stays at the tail when the voice has none yet (`gateVoice` starts or re-gates the mod synth after the grain synth; a re-gated mod synth is moved after a mirroring grain synth with `moveAfter`). A move whose target has just freed on the server (its `/n_end` not yet in sclang) only fails, and the mod synth's `onFree` restart goes to the tail; an `/s_new` relative to such a node would create nothing and leave a phantom grain synth that never frees, so no grain synth is ever created relative to another synth. Every grain synth of a voice therefore runs before that voice's mod synth (not necessarily before other voices' mod synths, which do not read its bus); the engine check reads `/g_queryTree` with controls after 0 -> 3 -> 9 -> 0 switches within 1 s.

### Synth Lifecycle

Synths use `gate` with ASR envelopes:
- Starting: `voiceOn` resets `voiceControls`, merges its grain values into `grainControls` and calls `gateVoice`, which never stacks synths. Synths the voice still has are **re-gated**: a running voice's only take the voiceOn values (`set`); a released voice's synths still in their release (`releasingSynths[voice]`, liveness = `isPlaying`) get `\gate, 1` (the ASR restarts its attack from the current level) plus the voiceOn values with `set`; the ones that have already freed are created (`Synth.new` with `gate=1`). The voice synth's release is 2-12 s but the grain synth's is 2 s and the mod synth's 0.5 s, so late in a release only the voice synth is re-gated. Controls not in the voiceOn reset keep their old values on a re-gated synth until Lua's `sync_voice_to_engine` (always right after `voiceOn`) sends them; a re-gated buffer grain synth also gets the slot's current `bufnumL/R`, `bufFrames` and `bufRateScale` (`bufferSlotPairs`), since `bufferChanged` only reaches running grain synths and the slot may have been loaded, recorded or cleared during the release. A releasing synth that no longer fits the source (it changed while the voice was stopped) is left to free itself: a grain synth built for another source (`releasedGrainSource[voice]`) releases beside the new one (the new one placed by `startPlacedGrainSynth`), and a voice synth when the source is no longer the synth is given a forced release (`release(grainRelease)`). Buffer- and input-sourced voices re-gate their grain and mod synths the same way
- Stopping: `releaseVoice` sets `\gate, 0` (release phase), removes the trio from `synths` (a buffer- or input-sourced voice has only a grain and a mod synth) and keeps it in `releasingSynths[voice]` (the grain's source in `releasedGrainSource`) for `voiceOn` to re-gate. A different synth already releasing under the same key (a grain synth for the previous source that `voiceOn` left beside the new one) is cut with `cutSynth` first, so no releasing synth goes untracked (voice and grain keys only: a releasing mod synth is always re-gated, never superseded, and `\strataMod` has no kill fade)
- Gate of every ASR: `openedGate(gate)` = `Select.kr(Impulse.kr(0) > 0, [gate, 1])`, used by every voice, grain and mod SynthDef. EnvGen starts only when its gate rises above 0, so a synth created and gated off in one control block (a MIDI note on and note off in one ~1.3 ms block, `voiceOn` + `voiceOff` in one bundle) would never start its ASR and never free. The opened gate is 1 in the synth's first block and the plain `gate` control after it, so that synth starts and releases from its second block, and normal releases, forced releases (negative gates; never `gate.max(...)`, which clamps them to a plain gate 0 and turns the 2 s cut into the full natural release) and re-gates are unchanged
- Watching: every voice, grain and mod synth is created through `startVoiceSynth`/`startGrainSynth`/`startModSynth`, which call `watchVoiceSynth` (`register(true)`, so `isPlaying` holds from creation, then `onFree`). A freed synth is dropped from `releasingSynths`. A synth still in `synths` when it frees was re-gated just as its release ended (the gate arrived too late); it is started again so the voice is never left without it. `free` empties `synths` after freeing them so nothing restarts
- Switching source: `replaceGrainSynth` (see Audio Sources); the synths it releases are tracked in `fadingSynths[voice]` and cut (`cutVoiceSynth`: `cutSynth`, the kill fade, recorded in `cuttingSynths[voice]`) by the next switch, which also frees at once any synth still in its kill fade from the switch before (see Real-time memory)
- `doneAction: 2` frees the synth after release (or after its kill fade)
- Per-voice commands go through `setSynth(key, ...)`, which ignores voices that are not running, and voice indices are range-checked with `validVoice`
