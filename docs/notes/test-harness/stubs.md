## Must not break

- The stubs mirror the real norns libraries (`~/src/norns/lua`) and matron. Check behavior there before changing a stub.
- A stub refuses what norns refuses: where matron reads an argument with `luaL_checkinteger`, `luaL_checkstring` or `luaL_checknumber`, the stub raises the same error, so a call that would stop a draw on the device fails its test (#475, #476). The calls checked: `screen.level`, `move`, `line`, `rect`, `text`, `text_right`, `text_center` and `text_extents`; the grid's and the arc's `led` and `all`; `clock.sleep`, `clock.sync` and `clock.cancel`. The other screen calls (`font_size`, `font_face`, `update`, `stroke`, `fill`, `clear`) check nothing; a new stubbed call that matron checks gets the same check.
- `param.t` holds numeric type codes (`params.tOPTION`, ...). Never compare it with a string; a test enforces this, with either quote and either order.
- Values are typed as matron pushes them (`matron/src/weaver.cc`). What it pushes with `lua_pushnumber` is a float, also for a whole number: every poll value (`poll.fire` rounds a number to the OSC wire's float32 before delivery), `clock.get_tempo()` and `clock.get_beats()`; norns' `util.time()` is `s + us / 1000000`, a float too. What it pushes with `lua_pushinteger` stays an integer: encoder deltas, keys, grid and arc events, MIDI bytes, metro stages and `audio.file_info`'s numbers. On Lua 5.3 a float slot builds `buf3.0_file` (#300), and LuaJIT, with one number type, cannot show it: run a new poll test on `lua`.

## The stubs

The stubs mirror the real norns libraries (`~/src/norns/lua`), so check behavior there before changing them.

### Params

- Types: number, control, option, binary, trigger, file, text, separator, group.
- As in `core/paramset.lua`, `params.lookup[id]` is the param's index in `params.params` (a number; use `params:lookup_param(id)` for the param), and `params:add` and the `add_*` helpers return nothing (#478).
- `set_action`, `hide`/`show`/`visible`, and `params:t(id)`, the type code (an id that is no param raises, through `lookup_param`, as on norns).
- `params:write(filename, name)`, `params:read(filename, silent)` and `params:delete(filename, name, number)` as in `lua/core/paramset.lua`. A filename is an absolute path or a number n, the numbered PSET `norns.state.data .. norns.state.shortname .. "-<NN>.pset"` (`<data>/strata/strata-01.pset`; the stub's `norns.state` is the script's data folder and `strata`, as `Script.load` sets them, and 3.8's `path`, the script's folder with its trailing `/` (`lua/core/script.lua`): `load_strata`'s `script_dir`, else the load's own `<data>/script/`, made at install and left empty, so no test start finds a factory set (`docs/notes/lua/factory.md`; `context.script_dir` names it), and a numbered write makes the folder, which norns makes as the script loads). Read sets each param in file order through its own `set`, so actions fire mid-read as on norns. Then each calls its action as norns does: `params.action_write(filename, name, number)`, `params.action_read(filename, silent, number)` (only when the file exists) and `params.action_delete(filename, name, number)`, with `number` the two-digit string of a numbered write or read and nil for a path; delete removes the file (`os.remove`, where norns runs `rm`) and passes the number its caller gives (the PSET menu gives one; a number filename gives none, as on norns). `params:set_save(id, false)` keeps a param out of the file, as norns does for most system params.
- Strings as `core/params/*.lua`: a control without a formatter shows `util.round(value, 0.01) .. " " .. units`; a number or binary returns its value, a number.
- A ControlSpec made without a default has `default` nil, and its control starts at raw 0. `spec:copy()` is `core/controlspec.lua`'s: range, warp, step, default, units and quantum (not `wrap`, as on norns).
- `params:get_raw(id)`/`params:set_raw(id, v, silent)` as `core/params/control.lua`, for control params only (the stub errors on any other type): `set_raw` wraps a wrapping spec or clamps to 0-1, stores the raw value unrounded and fires the action on a change unless silent; `get` maps raw and rounds to the step. Every control set updates its MIDI map's value from the stored raw value, including silent and unchanged sets. A number or option set does the same with its stored number or selected index. Each update follows any parameter action. With echo enabled, it sends one CC to the mapped port and channel (#1063, #1254).
- A control's `params:set(id, v)` is `set_raw(controlspec:unmap(round(v, step)))`, as `core/params/control.lua`'s; `unmap` wraps a wrapping spec into its range by whole ranges before it rounds and clamps (a 0-10 wrapping control set to 12 reads 2), and raises where norns would loop forever (an infinite value) (#478).
- `params:delta(id, d)` calls the param object's own `delta(d)`, as `core/paramset.lua` does and as norns' PARAMS menu turns E3, so a script that replaces one param's `delta` (the quantized `freq`'s turn mark, #318; the number params' whole steps, #534) changes both. Each type's `delta` is `core/params/*.lua`'s: a control's is `set_raw(raw + d * quantum)`, which wraps a wrapping spec (#478); a number's `set(value + d)`, unrounded; an option's rounds `d` away from 0; a binary's follows its behavior.
- Warps: `exp`, `db` and `lin`.
- norns' system params come first (`audio.add_params` and `clock.add_params`: the LEVELS, REVERB, COMPRESSOR, SOFTCUT and CLOCK groups with their types, ranges and factory defaults, `clock_tempo` 120). Every id of `core/paramset.lua`'s `system_param_ids` is there but `clock_midi_out`, which norns never adds (its params are `clock_midi_out_1..16`). So a script param with a system id fails as a collision. Their actions do nothing but `clock_tempo`'s (the internal clock's tempo and `clock.tempo_change_handler`) and, added for the tape loop's PSET read, the three SOFTCUT params' (`cut_input_adc`, `cut_input_eng`, `cut_input_tape`): each sets its mixer level as `lua/core/audio.lua` does (`audio.level_adc_cut(util.dbamp(x))`, ...; `norns.state.mix` left out), so a PSET that changes one reaches `context.audio.levels`.

### Param types

- Like norns, the param stub stores numeric type codes in `param.t` (`params.tOPTION` etc.), all from its one `PARAM_TYPE_CODES` table (exported as `stubs.PARAM_TYPE_CODES`).
- `params:add` with an unknown type raises an error (norns prints one and adds nothing).
- Never compare `param.t` with a string. A test enforces this for the script's sources, with either quote and either order: `p.t == "option"`, `'option' == p.t`.
- A file param's public set dispatches to its own setter, including a script's override. Its E3 delta selects the adjacent file in its directory list. The default file param lists its folder as `lua/core/params/file.lua`'s `File:loaddir` does (#480): at every set that changes its path to anything but `"-"` (silent or not) it calls `util.scandir` on the path's folder and keeps `dir`, `dirfiles` (the files, never a folder) and `dirpos` (the path's place among them); `"-"` clears all three, and a path with no folder lists nothing. A test counts the listings by wrapping `util.scandir`. `File.new`'s own listing is left out (only `dir` is set): it is norns' cost at a param's creation, not one the script chooses, and the eight buffer file params made at every `load_strata` were about 23,000 listings a run, doubling the suite's time.

### Group sizes

norns cannot see where a group ends (it takes the next `n` params), so the param stub requires each group to get exactly `n` params. It errors:
- when the next group arrives first (this is also the nesting error);
- when the param after the group's last one is neither a separator nor a group (`n` too small);
- in `context.check_param_groups()`, which `load_strata` calls after `init()`, when a group is still short at the end of the list.
