## Must not break

- Only one engine check runs per scsynth port: runs on the same port collide.
- `test/StrataTestNoBoot.sc.in`, `test/StrataTestTempDir.sc.in` and `test/StrataTestNoBootOSX.sc.in` stay `.sc.in` files: norns compiles every `.sc` under `~/dust`, and these test classes disable Crone's boot and replace the platform's temp dir. A structure test fails on any tracked `.sc` that is not `lib/Engine_Strata.sc` or `lib/engine/Strata*.sc` (#332), and `.gitignore` keeps `test/**/*.sc` out of a commit.
- A signal (INT, TERM, HUP) to the script stops sclang's whole tree, its scsynth and the work folder, and exits 130 (#331; GNU `timeout` keeps sclang in a process group of its own, so the script's death alone would leave it running on the port).
- Any `WARNING` line fails a run, as `ERROR` does (#486).
- Every 3.13 container keeps its memory cap, and a run is classified by its log, never by a signal alone (#544, #545; below).
- A full run on 3.13 is the workflow's shards, each in a container (a fresh sclang) of its own, read from `.github/workflows/test.yml` at each start and never copied into the script, and it passes only when every one of its shards passed (#581; below).
- A full local run is the workflow's shards too, each in a sclang of its own, one after another, the list read only through `test/run_engine_check_313.sh -l` (never a second reader or copy of it), and it passes only when every shard passed; the 3.13 image's `check` runs one sclang a container (`STRATA_ENGINE_CHECK_ONE_SCLANG=1`), since its script makes the shards (#671; below). A signal is only noted until the run's next check, so it always stops the shard it came in (or none) and the run says where; no shard starts while the last one's scsynth may still hold the port.
- A failed precondition (an unknown area, a bad port) or a failed start ends the run with its own `ENGINE CHECK FAILED:` line and nothing after it (#485, #471, #472).

## The engine check

`test/run_engine_check.sh [path/to/norns]`:
- compiles `lib/Engine_Strata.sc` against the real norns `sc/core` classes (default `~/src/norns`, or `$NORNS_DIR`);
- boots a local scsynth with its output on a private bus (silent) and runs `test/engine_check.scd`, which drives every engine command.

Full runs (#671):
- With `$STRATA_ENGINE_CHECK_AREAS` unset or empty the run is CI's shards: the `engine-shard` matrix of `.github/workflows/test.yml`, read at each start through `test/run_engine_check_313.sh -l`, the one reader of that list. The script runs itself once a shard (`STRATA_ENGINE_CHECK_AREAS=<shard>`), one after another on the same `$STRATA_SC_PORT`, so each shard is a run of its own: its own sclang, work folder, timeout, deadline and server stop. Every shard runs, a failed one too; then one line a shard (`shard <areas>: passed in <n> s`, or `shard <areas>: failed in <n> s (exit <status>)`) and the result (`ENGINE CHECK PASSED: <n> of <n> shards`, or `ENGINE CHECK FAILED: <k> of <n> shards failed: <areas>; <areas>`). The script exits 0 only when every shard passed.
- Why: one sclang running every area in turn dies on SuperCollider 3.14.1 at the start of the `modulation` area about half the time, on `main` itself: measured at 3.5's Wave 1, two runs at once, 4 of 8 full runs, by signal 11, by signal 6 after the collector's count-error lines, and twice by a failed primitive on a corrupt object (an `Array` index; a check SynthDef's UGen name read back garbled). The modulation area starts by building its check SynthDefs, which is where a heap the run has corrupted shows. No one area sets it off alone: each area before it, with `positions,modulation` after it, passed 3 of 3 runs (`positions,modulation` alone 6 of 6), but for the waveform area, whose 300 s check broke the collector in 1 of 6 (#211; sclang then ended on signal 11 in `positions`). In shards, 6 of 6 full runs passed, every shard of each, in about 1098 s a run against 1073 s in one sclang.
- `STRATA_ENGINE_CHECK_ONE_SCLANG=1` runs a full run in one sclang, as before #671 (for studying it and #131); it must be 1 or empty (anything else fails the start, exit 2). With areas named it changes nothing.
- A shard list the 3.13 script cannot read fails the start (its reason, then `ENGINE CHECK FAILED: no shard list to run ...`, exit 2) before any sclang starts. The settings (the port, the norns folder, `ENGINE_CHECK_TIMEOUT`, `STRATA_ENGINE_CHECK_ONE_SCLANG`) are checked before the first shard.
- A signal to a run in shards is only noted, from before the list is read (the trap sets `pending`), and acted on at the run's own checks: before each shard, and once a second while one runs (the shard runs in the background and is polled, never waited for in a way a noted signal could not end). So no signal falls between a shard's start and the note of its PID, and the run always knows where it came. One during a shard sends that shard's run TERM (a background job ignores INT), whose own stop ends its sclang, its scsynth and its folder (#331), and its line reads `shard <areas>: interrupted after <n> s`. Then the lines of the shards that ran and `ENGINE CHECK FAILED: interrupted in shard <areas>` (or `before the first shard`, or `after shard <areas>`), `; <k> of <n> shards did not run`, exit 130; no later shard starts.
- A shard whose scsynth outlived its stop (below: exit 3) fails with `shard <areas>: failed in <n> s (exit 3: its scsynth was still running 10 s after it was stopped)`, and no later shard starts: it would meet that server on the port and take the blame. The result line then adds `; <k> did not run`.
- The structure tests run the script against a fake sclang that records the areas of each start: a full run starts one sclang per shard of the workflow, in its order and never two at once; a failed shard fails the run and the others still run; named areas, and `STRATA_ENGINE_CHECK_ONE_SCLANG=1`, start one; a workflow without the list starts none; a signal stops the first shard's sclang and server, starts no other and names the shard; a signal between a shard and the next (the first shard's sclang holds the run with SIGSTOP until that shard's run has ended) or before the first (while a stand-in for the list's reader waits) prints what ran and says where it came; a crashed shard's server that ends 2 s after TERM is waited for before the next shard starts, and one that ignores TERM fails its shard (exit 3) and starts no other; and `test/docker/sc313/check.sh` passes `STRATA_ENGINE_CHECK_ONE_SCLANG=1`. The tests of the one-sclang path (#152, #131, #331, #486) set `STRATA_ENGINE_CHECK_ONE_SCLANG=1`. Every runner test clears the caller's `STRATA_ENGINE_CHECK_AREAS` and `STRATA_ENGINE_CHECK_ONE_SCLANG` first, and waits up to 10 s for a process it expects stopped to end, counting a zombie as ended, instead of asking once (#673: a signaled process ends a moment after `kill` returns, and `kill -0` still finds a zombie; the test of that wait keeps its zombie unreaped past a 2 s bound, so only the zombie check can pass it). The Lua tests read the workflow's shard list through one helper, `h.workflow_shards()` (`test/helpers.lua`)..

Its own SynthDefs, to hear what a bus carries:
- `\strataCheckTone`: a 440 Hz tone written into `inputBus`;
- `\strataCheckPeak`: a resettable peak meter on a stereo bus;
- `\strataCheckSine`/`\strataCheckStep`: a sine of any frequency, and the largest sample-to-sample step on a bus, for the filter crossfade;
- added by `addAudioCheckDefs`: `\strataCheckChannelPeaks` (per-channel peaks, for pan), `\strataCheckBadValues` (NaN/inf seen on a bus), `\strataCheckRms` (a bus's RMS over about 1.5 s) and `\strataCheckBadSource` (50 ms of inf and NaN; a float overflow, since `log(0)` is not -inf in scsynth).

Structure:
- The check routine is at sclang's per-function selector limit: new checks go in top-level functions called from it.
- After each area it checks that nothing of a voice is left and that norns' poll registry holds `h.engine`'s own polls, running as it left them (it puts back polls an area moved), and clears every slot, so none of the three reaches the next area in the same sclang (#652; `docs/notes/engine/structure.md` says what still carries over).
- Every server reply it waits for goes through `awaitReply` (5 s, then a FAIL), and the whole check fails after its deadline (`STRATA_ENGINE_CHECK_DEADLINE`, the timeout less 30 s: 1770 s by default, 540 s in CI), so a reply that never comes fails the check instead of hanging it (CI kills the job at 600 s and passes `ENGINE_CHECK_TIMEOUT=570`).

What fails it, besides a failed check: any output line with `ERROR` or `WARNING` at its start, `FAILURE` (the server's report of a failed command), `alloc failed`, `Too many grains` (a grain UGen past `maxGrains`) or `Strata invariant broken`.

Timeouts and processes:
- The script runs sclang under `timeout` (`ENGINE_CHECK_TIMEOUT`, default 1800 s for each sclang: each shard of a full run, or a full run in one sclang, whose areas sum to about 1030 s at 3.4.0, about 17 minutes, and which took 1073 s on 3.14.1 at 3.5's Wave 1; CI shards set 570 s) with line-buffered output (`stdbuf`).
- It stops sclang as soon as the output shows a compile error (a syntax error in `engine_check.scd`, `Library has not been compiled successfully`): sclang never exits by itself then, and would hold the machine and CI's job until killed.
- `timeout` signals the whole process group, so the scsynth sclang booted goes too. Without a `timeout` command, the script's own watch loop enforces the limit.
- It stops the scsynth too, even after a sclang crash (through the PID the check writes to its work dir, #152), without needing `pgrep` or `timeout`, and waits up to 10 s (`server_stop_seconds`) for it to end, a zombie counting as ended, so the next run on the port (a full run's next shard) never meets it. One still running then fails the run with its own `ENGINE CHECK FAILED:` line, and the script exits 3.
- The script's own stop signals sclang and every descendant (`kill_tree`, children first), so no scsynth is left on its port. Exit 124 or 137 (timeout's `--kill-after` SIGKILL) reports as a timeout. A signal to the script itself runs the same stop (`stop_on_signal`) and exits 130.

Start-up (the check's own, `test/engine_check.scd`):
- Before booting, it sends `/status` to `$STRATA_SC_PORT`; any reply fails the run at once with `ENGINE CHECK FAILED: port <n> already has a server`, and it never quits a server it did not start (#471).
- A scsynth that exits without booting (a port held by a program that does not answer, JACK not running) fails the run within seconds with `ENGINE CHECK FAILED: scsynth did not boot` instead of at the deadline (#472). The script's summary prints scsynth's `*** ERROR` lines.
- The temp dir override the check needs lives in `test/StrataTestTempDir.sc.in`, copied into a `SystemOverwrites` folder of the work dir's classes, where sclang does not warn that an extension overwrites a system method (#486).
- CI's engine shards also run the check with an unknown area and require its failure line without an `ERROR` line (#485). The record and waveform shard also runs it against a port a `scsynth` already holds (the failure line naming the port, and that server still running afterward, #471) and against a port held by a silent UDP socket (`scsynth did not boot` within 40 s, #472). A boot is ended by a watch on the server's pid: `waitForBoot`'s own limit and `onFailure` are not applied by sclang 3.13 or 3.14.1.

Ports:
- Each run boots scsynth on `$STRATA_SC_PORT` (default 57110). Runs on different ports (avoid 57120 and the few above it, used by sclang itself) can overlap; runs on the same port collide. `docs/checks.md` (The engine check) has the details.

Setup:
- Needs SuperCollider: sclang is `$SCLANG` if set, else `sclang` on `PATH`, else the macOS app path.
- The record area needs `python3` on `PATH`: its #565 check sends two `recordBuffer` messages from outside sclang while it holds sclang, through a short python3 script it writes to its folder. CI's runner has python3, and the 3.13 image installs it explicitly (`test/docker/sc313/Dockerfile`). The script exits after 10 s if its go file never appears, so a check that dies early leaves no sender waiting.
- On Linux scsynth also needs a running JACK server. CI and local runs use a dummy driver: `jackd --no-realtime -d dummy -r 48000 -p 1024 &` (check with `jack_lsp`). `QT_QPA_PLATFORM=offscreen` keeps sclang headless.

### The engine check on SuperCollider 3.13 (Docker)

`test/run_engine_check_313.sh [-n runs] [-j parallel] [-o log_dir] [-1] [-l] [-c] [path/to/norns]` runs the engine check on SuperCollider 3.13, norns' version, whatever version the machine has:
- **A full run is CI's shards** (#581): one container, and so a fresh sclang, per shard of the `engine-shard` matrix in `.github/workflows/test.yml` (its `areas` list, one `- a,b,c` item a shard), each running only its shard's areas (`STRATA_ENGINE_CHECK_AREAS=<shard>`). The list is read from the workflow at each start, never copied into the script, so CI and the local runner cannot drift; a missing list, or an item that is not area names joined by commas, fails the start (exit 2, naming the workflow) before any container runs. Why: one sclang running every area in turn (about 940 s) is where 3.13 gives out (#131's family). With 3.4's `modulation` area added last, 2 of 8 such runs segfaulted as sclang quit after every check had passed, and heavier versions of that area's checks crashed inside it, while CI's shard holding it passed 12 of 12.
- `-1` runs each full run in one container, every area in one sclang, as before (for studying #131). `STRATA_ENGINE_CHECK_AREAS`, set and not empty, also runs one container per run, with those areas, as before. `-l` prints the shards a sharded run would use, one a line, and starts nothing (a docs test compares its output with the workflow's list).
- The image (`strata-sc313`, from `test/docker/sc313/Dockerfile`) is CI's setup: Ubuntu 24.04, `supercollider-language` and `supercollider-server` at CI's `SC_APT_VERSION` (`1:3.13.0+repack-1ubuntu3`; a docs test checks the two pins match), `jackd2`, `procps` and `coreutils`. Its `check` command (`test/docker/sc313/check.sh`) starts a dummy JACK, waits for `jack_lsp`, then runs `test/run_engine_check.sh /norns` on the repo at `/src` with `STRATA_ENGINE_CHECK_ONE_SCLANG=1`: one sclang a container, since this script makes the shards itself (and `-1` means every area in one sclang, #671).
- The script builds the image when it is missing or the folder's files changed (the image's `strata.dockerfile-sha256` label holds their hash), so a fresh machine needs no manual step. The one-time build takes about a minute (55 s measured; longer on a slow connection: it downloads Ubuntu 24.04 and its SuperCollider and JACK packages, about 230 MB); later runs reuse the image.
- Each container is `docker run --rm --user $(id -u):$(id -g) -e HOME=/tmp -e XDG_RUNTIME_DIR=/tmp -v <repo>:/src:ro -v <norns>:/norns:ro strata-sc313 check`. It runs as a non-root user because QtWebEngine refuses root. The mounts are read-only: the check writes only to its container's `/tmp`.
- Every container has its own network, so parallel containers never clash on a port. Local sclang runs exhaust sclang's language ports past a few at once, so use this script for more than three or four parallel runs.
- `-n` is the number of runs (1), `-j` how many containers run at once (1; the shards of one run and of different runs alike, each started as one ends: a sharded run is one container per shard, so `-n 8` starts eight times as many containers as the workflow has shards, `-j` at a time. A container's job counts as running while its status file, emptied as it starts, is still empty, so a PID the system has since given to another process cannot hold a slot; only a job killed before it wrote its status is looked up by PID), `-o` the log folder (created if missing; default a new `${TMPDIR:-/tmp}/strata-sc313-logs.XXXXXX`). A sharded run `<i>`'s shard writes `run-<i>-<shard>.log` and `run-<i>-<shard>.status`, its commas written as `_` (`run-3-voices_freeze_grains.log`); a run in one container writes `run-<i>.log` and `run-<i>.status`. Each log ends with `strata container seconds: <n>`, the container's wall-clock time. The script never deletes a log. `STRATA_ENGINE_CHECK_AREAS`, `ENGINE_CHECK_TIMEOUT` (which applies to each container, so to each shard of a sharded run), `STRATA_SOAK_ROUNDS` and `STRATA_SOAK_SECONDS` pass through to every container.
- Every container has a memory cap, `--memory` and `--memory-swap` both `$STRATA_SC313_MEMORY` (default 8g; a healthy run of every area peaked at 1.42 GiB, sampled with `docker stats` every 3 s), so a collector gone wrong (#211) is killed inside its own container and not by the machine's out-of-memory killer, which once took sclang at 59 GB (#544). The image's `check` command prints `strata cgroup oom_kill: <n>` from the container's `memory.events` (cgroup v2) after the run.
- The summary classifies each container by its log, in this order (#545): **passed** (status 0); **failed** (any `FAIL`, `ERROR` or `Strata invariant broken` line, whatever ended it, with a note when the collector or the cap was involved too); **capped** (the cap killed a process: `oom_kill` above 0 in the container's own count); **killed** (exit 137 with no cap kill: stopped from outside, such as a `docker kill`); **collector failure** (sclang ended on a signal after the collector's count-error lines: #211); **crashed** (a signal with none of those: #131). A sharded run that did not pass takes the class of its worst shard, the first in that order after passed (of two alike, the first in the run's order: the workflow's), and its line names that shard (`run 3: crashed in effects,voices (sclang ended on signal 11 after 90 s), <log>`), then each other shard that did not pass on a line of its own (`  and failed in ...`), in the run's order. The summary counts runs by class, then, for sharded runs, their shards by class (`shards: passed ... of ...; ...; crashed <n> (#131); missing <n>`: a run counts once, so a crash beside a failure in another shard shows only there; take #131's rate from this line) and names the slowest shard with its time (to rebalance the workflow's shards by). The script exits 0 only when every run passed.
- `-c` classifies the runs already in the `-o` folder (required; it makes no folder), of either layout, and starts nothing (the structure tests feed it fixture logs). A run with `run-<i>-*.log` files is read as sharded, against the workflow's list (read as at a start, so the same summary as the live run): its shards in the list's order, then any shard log the list no longer names, by file name. A run lacking the log of one of the list's shards is **incomplete** (`run 2: incomplete (no log for zeta,delta)`, then any shard of it that did not pass), counted apart (`incomplete <n>` among the runs, `missing <n>` among the shards), and not passed. A run in the old layout (`run-<i>.log` alone) is never incomplete.
- The structure tests run the script, and a copy of it beside a workflow of its own, against a fake `docker`, with the caller's `STRATA_ENGINE_CHECK_AREAS`, `STRATA_SC313_IMAGE` and `STRATA_SC313_MEMORY` cleared (one exported while working on an area must not change what they see): every container carries the cap, a full run is one container per shard, `-j` bounds the containers at once (also in a reused log folder), `-1` and the areas variable keep one container per run, a list it cannot read starts nothing, and `-c` keeps the workflow's order and reports a run missing shards as incomplete. An interrupt stops only the containers this start launched (named `strata-sc313-<pid>-<i>`, or `strata-sc313-<pid>-<i>-<shard>` for a shard).
- Examples: an engine package's gate, four full runs (four times the workflow's number of shards in containers), eight at once: `test/run_engine_check_313.sh -n 4 -j 8 -o /tmp/full-313` (at 3.4's package 0c, with seven shards, eight full runs at `-j 8` took 1048 s on a 32-thread machine and passed 8 of 8; the slowest shard, voices, freeze and grains, took 158 s a container, memory and modulation 83 s). #131's rate on the files area: `STRATA_ENGINE_CHECK_AREAS=files test/run_engine_check_313.sh -n 16 -j 8 -o /tmp/files-313`. #131's rate on full runs in one sclang: `test/run_engine_check_313.sh -1 -n 8 -j 8 -o /tmp/one-313`.
