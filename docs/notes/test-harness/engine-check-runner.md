## Must not break

- Only one engine check runs per scsynth port: runs on the same port collide.
- `test/StrataTestNoBoot.sc.in`, `test/StrataTestTempDir.sc.in` and `test/StrataTestNoBootOSX.sc.in` stay `.sc.in` files: norns compiles every `.sc` under `~/dust`, and these test classes disable Crone's boot and replace the platform's temp dir. A structure test fails on any tracked `.sc` that is not `lib/Engine_Strata.sc` or `lib/engine/Strata*.sc` (#332), and `.gitignore` keeps `test/**/*.sc` out of a commit.
- A signal (INT, TERM, HUP) to the script stops sclang's whole tree, its scsynth and the work folder, and exits 130 (#331; GNU `timeout` keeps sclang in a process group of its own, so the script's death alone would leave it running on the port).
- The native runner requires the whole `ENGINE CHECK PASSED` line and rejects a leading `FAIL`, `ENGINE CHECK FAILED:`, `WARNING`, `ERROR` or scsynth's `*** ERROR:` even if sclang exits zero (#486, #1255). Both runners resolve relative paths from the caller's directory even when the shell sets `CDPATH` (#1257). A collector count error appears in the output and fails the run even if sclang posts its pass marker and exits 0 (#1082).
- Every Docker container keeps its memory cap, on 3.13 and 3.14.1 alike, and a run is classified by its log, never by a signal alone (#544, #545; below).
- The Docker runner's default is 3.13, CI's version: only `-s 3.14` runs the 3.14.1 image, CI never passes it, and any other `-s` starts nothing (#1039; below).
- A full run in Docker, on 3.13 or 3.14.1, is the workflow's shards, each in a container (a fresh sclang) of its own, read from `.github/workflows/test.yml` at each start and never copied into the script, and it passes only when every one of its shards passed (#581; below).
- A full local run is the workflow's shards too, each in a sclang of its own, one after another, the list read only through `test/run_engine_check_313.sh -l` (never a second reader or copy of it), and it passes only when every shard passed; the 3.13 image's `check` runs one sclang a container (`STRATA_ENGINE_CHECK_ONE_SCLANG=1`), since its script makes the shards (#671; below). A signal is only noted until the run's next check, so it always stops the shard it came in (or none) and the run says where; no shard starts while the last one's scsynth may still hold the port.
- A failed precondition (an unknown area, a bad port) or a failed start ends the run with its own `ENGINE CHECK FAILED:` line and nothing after it (#485, #471, #472).
- Reverb and shimmer use `h.measureWindows` for their batches. Freeze uses it to read the grain-start probe after its server-timed window (#1139). Each `batch` line names the area, case count, planned server audio duration, stage and elapsed wall time. The allocation and release messages travel in groups of at most 32 commands, each acknowledged before the next. Every buffer command can return a separate `/done` datagram, so one large OSC bundle still risks overflowing the receiver and losing its `/synced`. The probes report completion in server time. An independent SystemClock timer uses an absolute wall-clock deadline even if the caller's logical time is behind. The reverb area's first measurement exercises that case. The timer ends the shard if a sync or window bus read takes over 5 s, if the probes take over twice their audio duration plus 5 s, or if the whole batch takes over twice its duration plus 10 s. Its failure line names the outstanding stage and completed probe count. The private server and shell runner release the resources when the shard exits.
- During voice teardown, the barrier after the stop commands waits up to 5 s for its own `/synced`. After 1 s without a reply it logs the area, stage and ID and sends the same `/sync` once more. The stop and free commands run once, and the original deadline holds. Each check for remaining nodes waits up to 5 s for `/g_queryTree.reply` with the requested group's ID and control flag. A missing reply raises an error naming the area, teardown stage, reply and expected arguments. A group still holding voice nodes after the 3 s fade allowance reports their names. An area's explicit sync after freeing a test engine, the record area's slot resets, and shared end-of-area and end-of-run barriers use the same deadline. The structure unit tests check the areas for an unbounded sync after a free or stop. Each timer uses absolute wall time and each responder is removed when its wait ends. The runner quits its private server on an uncaught error and the shell checks that scsynth exited. The structure area drops the first sync reply and checks that the second, on the same ID, completes the stop. It then withholds both sync replies and a tree reply, checks both errors and runs the normal stop again (#1119).
- A check never waits a fixed time for a load, a recording or a fade: it waits on the thing itself (#706, #718, #714).
- After a `loadBuffer` that must take effect a check calls `h.awaitLoad(slot)`: `h.awaitLoad(slot, target, timeout, load)` for another engine, or for a load that a later rejected one follows (`load` is its number in `bufferLoads`). It waits until that load (the slot's newest unless named) is in place: the slot's frames above 0 and `loadsSuperseded` at the load's number. The count is 0 from the command (or from a long file's check's end) until the peaks file is in place. It then syncs, and fails the check with a line naming the area and the slot when the load is not in place within 5 s. A fixed 0.3 s once read 0 frames on a slow runner, and the loops area then filled its whole slot with the value it listens for.
- A take's length comes the same way, once its peaks file is in place. After a recording that must have ended (its length, its rate, a stop's count) a check calls `h.awaitTake(slot)` (`h.awaitTake(slot, target, timeout)`; the timeout counts from the call, so a long or delayed take adds its length). It waits until the slot has no record synth and no take (the engine clears the take only once its length is set, or when it is canceled), syncs, and fails the check by area and slot otherwise. The scratch take is renamed into place after that, so a check that reads it waits for the file. The record area's `waitDone` is this helper. A value that must arrive while the take runs (a playable take's length at the voice) is read with the take still running, and the check asserts it is.
- A state that ends on its own, such as a synth in its 50 ms kill fade, is held for the read by the check's own messages (`/n_run 0` on the group before the commands, as `checkCuttingBound` in the notes area and the memory area's held voices do), never read inside the fade's time.
- A fixed wait stays only where it is for something else: a read inside a take or a fade on purpose (the take running, the fade not yet over), or a window in which a late step must not happen (a dropped load, a canceled take, a report or a length that must not come). Such a window comes before the helper when the late step would run on an earlier command's own time, and after it when it would come with the load or the take itself.

## Abrupt restart during a WAV save

On Linux the files area runs `test/engine_check/fixtures/save-restart.py` with the same sclang executable and class-library configuration as the shard. It starts two successive sclang processes on private temporary directories and kernel-selected scsynth ports. Each runs only the `save-restart.scd` fixture through the normal engine-check harness. The first forces its WAV save through the subprocess fallback. Once the real carrier reaches the private `mv` barrier and its source matches the first stereo input, the supervisor kills the language with SIGKILL while the child waits at the barrier. It frees that server’s root-group nodes, waits for `/synced`, then sends `/quit` and waits for the PID to exit. This avoids an occasional crash in SuperCollider 3.14’s server cleanup with a live graph and releases shared memory before the successor boots. The new process saves different audio to the same destination and must report success. The supervisor checks the destination against the new input before resuming the orphan and after observing its rename attempt and exit. The new process keeps its engine live until both comparisons finish. Both inputs have the same format and length, with distinct samples in each channel. All waits have deadlines. A Linux child subreaper also quits any recorded server after an assertion fails, rejects abnormal server exits, and collects the remaining descendants.

## The engine check

`test/run_engine_check.sh [path/to/norns]`:
- compiles `lib/Engine_Strata.sc` against the real norns `sc/core` classes (default `~/src/norns`, or `$NORNS_DIR`);
- boots a local scsynth with its output on a private bus (silent) and runs `test/engine_check.scd`, which drives every engine command.

Full runs (#671):
- With `$STRATA_ENGINE_CHECK_AREAS` unset or empty the run is CI's shards: the `engine-shard` matrix of `.github/workflows/test.yml`, read at each start through `test/run_engine_check_313.sh -l`, the one reader of that list. The script runs itself once a shard (`STRATA_ENGINE_CHECK_AREAS=<shard>`), one after another on the same `$STRATA_SC_PORT`, so each shard is a run of its own: its own sclang, work folder, timeout, deadline and server stop. Every shard runs, a failed one too; then one line a shard (`shard <areas>: passed in <n> s`, or `shard <areas>: failed in <n> s (exit <status>)`) and the result (`ENGINE CHECK PASSED: <n> of <n> shards`, or `ENGINE CHECK FAILED: <k> of <n> shards failed: <areas>; <areas>`). The script exits 0 only when every shard passed.
- Why: one sclang running every area in turn dies on SuperCollider 3.14.1 at the start of the `modulation` area about half the time, on `main` itself: measured at 3.5's Wave 1, two runs at once, 4 of 8 full runs, by signal 11, by signal 6 after the collector's count-error lines, and twice by a failed primitive on a corrupt object (an `Array` index; a check SynthDef's UGen name read back garbled). The modulation area starts by building its check SynthDefs, which is where a heap the run has corrupted shows. No one area sets it off alone: each area before it, with `positions,modulation` after it, passed 3 of 3 runs (`positions,modulation` alone 6 of 6), but for the waveform area, whose 300 s check broke the collector in 1 of 6 (#211; sclang then ended on signal 11 in `positions`). In shards, 6 of 6 full runs passed, every shard of each, in about 1098 s a run against 1073 s in one sclang. The crash was #211's (a frame left pointing at freed memory, `docs/notes/engine/structure.md`): with its fix (#681) every area in one sclang passed 6 of 6, and the shards stay the full run for the fresh sclang each gets.
- `STRATA_ENGINE_CHECK_ONE_SCLANG=1` runs a full run in one sclang, as before #671 (for studying it and #131); it must be 1 or empty (anything else fails the start, exit 2). With areas named it changes nothing.
- A shard list the 3.13 script cannot read fails the start (its reason, then `ENGINE CHECK FAILED: no shard list to run ...`, exit 2) before any sclang starts. A signal while the list is read is an interrupt instead, even when it ended the reader too (a Ctrl-C reaches both): `ENGINE CHECK FAILED: interrupted before the first shard, while the shard list was read`, exit 130. The settings (the port, the norns folder, `ENGINE_CHECK_TIMEOUT`, `STRATA_ENGINE_CHECK_ONE_SCLANG`) are checked before the first shard.
- A signal to a run in shards is only noted, from before the list is read (the trap sets `pending`), and acted on at the run's own checks: before each shard, and once a second while one runs (the shard runs in the background and is polled, never waited for in a way a noted signal could not end). So no signal falls between a shard's start and the note of its PID, and the run always knows where it came. One during a shard sends that shard's run TERM (a background job ignores INT), whose own stop ends its sclang, its scsynth and its folder (#331), and its line reads `shard <areas>: interrupted after <n> s`. Then the lines of the shards that ran and `ENGINE CHECK FAILED: interrupted in shard <areas>` (or `before the first shard`, or `after shard <areas>`), `; <k> of <n> shards did not run`, exit 130; no later shard starts.
- A shard whose scsynth outlived its stop (below: exit 3) fails with `shard <areas>: failed in <n> s (exit 3: its scsynth was still running 10 s after it was stopped)`, and no later shard starts: it would meet that server on the port and take the blame. The result line then adds `; <k> did not run`.
- The structure tests run the script against a fake sclang that records the areas of each start: a full run starts one sclang per shard of the workflow, in its order and never two at once; a failed shard fails the run and the others still run; named areas, and `STRATA_ENGINE_CHECK_ONE_SCLANG=1`, start one; a workflow without the list starts none; a signal stops the first shard's sclang and server, starts no other and names the shard; a signal between a shard and the next (the first shard's sclang holds the run with SIGSTOP until that shard's run has ended) or before the first (while a stand-in for the list's reader waits, or after a stand-in that signals the run and then fails, as a reader a Ctrl-C reached would) prints what ran and says where it came; a crashed shard's server that ends 2 s after TERM is waited for before the next shard starts, and one that ignores TERM fails its shard (exit 3) and starts no other; and `test/docker/sc313/check.sh` passes `STRATA_ENGINE_CHECK_ONE_SCLANG=1`. The tests of the one-sclang path (#152, #131, #331, #486) set `STRATA_ENGINE_CHECK_ONE_SCLANG=1`. Every runner test clears the caller's `STRATA_ENGINE_CHECK_AREAS` and `STRATA_ENGINE_CHECK_ONE_SCLANG` first, and waits up to 10 s for a process it expects stopped to end, counting a zombie as ended, instead of asking once (#673: a signaled process ends a moment after `kill` returns, and `kill -0` still finds a zombie; the test of that wait keeps its zombie unreaped past a 2 s bound, so only the zombie check can pass it). The Lua tests read the workflow's shard list through one helper, `h.workflow_shards()` (`test/helpers.lua`), and its area-times table through another, `h.workflow_area_times(text)`.

Its own SynthDefs, to hear what a bus carries:
- `\strataCheckTone`: a 440 Hz tone written into `inputBus`;
- `\strataCheckPeak`: a resettable peak meter on a stereo bus;
- `\strataCheckSine`/`\strataCheckStep`: a sine of any frequency, and the largest sample-to-sample step on a bus, for the filter crossfade;
- added by `addAudioCheckDefs`: `\strataCheckChannelPeaks` (per-channel peaks, for pan), `\strataCheckBadValues` (NaN/inf seen on a bus), `\strataCheckRms` (a bus's RMS over about 1.5 s) and `\strataCheckBadSource` (50 ms of inf and NaN; a float overflow, since `log(0)` is not -inf in scsynth).

Structure:
- The check routine is at sclang's per-function selector limit: new checks go in top-level functions called from it.
- After each area it checks that nothing of a voice is left and that norns' poll registry holds `h.engine`'s own polls, running as it left them (it puts back polls an area moved), and clears every slot, so none of the three reaches the next area in the same sclang (#652; `docs/notes/engine/structure.md` says what still carries over).
- **The bookkeeping sweep** (#943, `sweepBookkeeping`, the first step of `finishArea`): seven conditions on `h.engine`'s records as the area left them, read from sclang's state alone (no wait, no server round trip, no message, so its cost over every area is a few milliseconds). Each broken one posts `Strata invariant broken: <which> (<what breaks it>; after area <name>)` and counts a failure; the areas' own checks are unchanged. The conditions (`sweepConditions`): a stop reply (`stopReplies[i]`) only with a stopping replace take in `takes[i]` (#261); a record synth (`recordSynths[i]`) only as its take's `\synth` (a take with none is ending, `takeEnding`); each effect's bypass, pending free and synth one of the three legal triples (running: not bypassed, no free pending, its synth; fading: bypassed, its free pending, its synth; freed: bypassed, neither); every LFO and envelope route place's synth a key of its area's `nodeChannels` (12872c74); `writeGenerations` and `pathRenames` empty and the mover's `pending` 0; in each slot with no take live (no take, `slotRecording` false), `announced[i]` equal to `bufferStateSeconds(i)`; and no start in `unconfirmedStarts` older than twice `startConfirmWait` (#1019: each is judged by its own timer at `startConfirmWait`, the second a backstop for the timer's wake and sync). Its own check (`checkSweep`) runs once before the areas, on `h.engine` as built: every condition holds there; each, broken by hand (a record set and put back with no yield between, so no reply or timer meets it), shows its line and no other ("sweep: a stop reply with no take: its line, and no other", and so on); a legal neighbor of each shows none, but of the fifth, whose one legal state is empty (twenty checks in all). A check's own line never quotes the line's prefix, which the script fails on: the lines it got are shown without it.
- Every server reply it waits for goes through `awaitReply` (5 s, then a FAIL), and the whole check fails after its deadline (`STRATA_ENGINE_CHECK_DEADLINE`, the timeout less 30 s: 2970 s by default, 540 s in CI), so a reply that never comes fails the check instead of hanging it (CI passes `ENGINE_CHECK_TIMEOUT=570` and runs the script under `timeout --kill-after=15 600`, in a step of 11 minutes).

What fails it, besides a failed check: any output line with `ERROR` or `WARNING` at its start, `FAILURE` (the server's report of a failed command), `alloc failed`, `Too many grains` (a grain UGen past `maxGrains`), `Strata invariant broken` or the collector's count-error text anywhere on the line.

Timeouts and processes:
- The script runs sclang under `timeout` (`ENGINE_CHECK_TIMEOUT`, default 3000 s for each sclang, 2700 s until 3.9's `reverb` area: each shard of a full run, at most 363 s of areas, fits with room, and a full run in one sclang, whose areas sum to 1889 s in the workflow's area times (CI's run 44395161831, and the checks since), about 31 minutes, has 1081 s of room under the 2970 s deadline at CI's speed; the default is 1.59 times that sum, and `test/unit/docs_test.lua` holds it at 1.5 times the workflow's sum, #816; a full run in shards took 1202 s on 3.14.1 at the 3.5.0 release; CI shards set 570 s) with line-buffered output (`stdbuf`).
- It stops sclang as soon as the output shows a compile error (a syntax error in `engine_check.scd`, `Library has not been compiled successfully`): sclang never exits by itself then, and would hold the machine and CI's job until killed.
- `timeout` signals the whole process group, so the scsynth sclang booted goes too. Without a `timeout` command, the script's own watch loop enforces the limit.
- It stops the scsynth too, even after a sclang crash (through the PID the check writes to its work dir, #152), without needing `pgrep` or `timeout`, and waits up to 10 s (`server_stop_seconds`) for it to end, a zombie counting as ended, so the next run on the port (a full run's next shard) never meets it. One still running then fails the run with its own `ENGINE CHECK FAILED:` line, and the script exits 3.
- The script's own stop signals sclang and every descendant (`kill_tree`, children first), so no scsynth is left on its port. Exit 124 or 137 (timeout's `--kill-after` SIGKILL) reports as a timeout. A signal to the script itself runs the same stop (`stop_on_signal`) and exits 130.

Start-up (the check's own, `test/engine_check.scd`):
- Before booting, it sends `/status` to `$STRATA_SC_PORT`; any reply fails the run at once with `ENGINE CHECK FAILED: port <n> already has a server`, and it never quits a server it did not start (#471).
- A scsynth that exits without booting (a port held by a program that does not answer, JACK not running) fails the run within seconds with `ENGINE CHECK FAILED: scsynth did not boot` instead of at the deadline (#472). The script's summary prints scsynth's `*** ERROR` lines.
- The temp dir override the check needs lives in `test/StrataTestTempDir.sc.in`, copied into a `SystemOverwrites` folder of the work dir's classes, where sclang does not warn that an extension overwrites a system method (#486).
- CI's engine shards also run the check with an unknown area and require its failure line without an `ERROR` line (#485). The record, waveform, onsets, delay and shimmer shard also runs it against a port a `scsynth` already holds (the failure line naming the port, and that server still running afterward, #471) and against a port held by a silent UDP socket (`scsynth did not boot` within 40 s, #472). A boot is ended by a watch on the server's pid: `waitForBoot`'s own limit and `onFailure` are not applied by sclang 3.13 or 3.14.1.

Ports:
- Each run boots scsynth on `$STRATA_SC_PORT` (default 57110). Runs on different ports (avoid 57120 and the few above it, used by sclang itself) can overlap; runs on the same port collide. `docs/checks.md` (The engine check) has the details.

Setup:
- Needs SuperCollider: sclang is `$SCLANG` if set, else `sclang` on `PATH`, else the macOS app path.
- The record area needs `python3` on `PATH`: its #565 check sends two `recordBuffer` messages from outside sclang while it holds sclang, through a short python3 script it writes to its folder. CI's runner has python3, and the 3.13 image installs it explicitly (`test/docker/sc313/Dockerfile`). The script exits after 10 s if its go file never appears, so a check that dies early leaves no sender waiting.
- On Linux scsynth also needs a running JACK server. CI and local runs use a dummy driver: `jackd --no-realtime -d dummy -r 48000 -p 1024 &` (check with `jack_lsp`). `QT_QPA_PLATFORM=offscreen` keeps sclang headless.

### The engine check on SuperCollider 3.13 or 3.14.1 (Docker)

`test/run_engine_check_313.sh [-s version] [-n runs] [-j parallel] [-o log_dir] [-1] [-l] [-c] [path/to/norns]` runs the engine check on SuperCollider 3.13, norns' version (the default), or with `-s 3.14` on 3.14.1, whatever version the machine has:
- **`-s` picks the version** (#1039): `3.13` (the default, CI's) or `3.14`; anything else, an empty value too, prints the usage line and exits 2 before anything starts, `-l` included. Every other option, the shards, the logs and their classification work the same under either. Why 3.14.1 in Docker: the local runner plays a full run's seven shards one after another on one port (about 31 minutes, near an hour on a busy machine), since local sclangs exhaust the language ports past a few at once; in containers `-s 3.14 -j 7` runs them all at once, in about the time of the slowest shard (#1039: 368 s on a 32-thread machine, 2026-11-24, as long as its slowest shard, buffers, loops and types, against 1826 s for the same shards one after another through `test/run_engine_check.sh`). The local runner stays the way to run a package's own areas while it works.
- The 3.14.1 image (`strata-sc314`, from `test/docker/sc314/Dockerfile`) is the local machines' 3.14.1: Ubuntu 26.10 with `supercollider-language` and `supercollider-server` at `1:3.14.1+repack2-1build1`, the host's package (`apt-cache policy supercollider-language`), pinned as `SC_APT_VERSION` the way the 3.13 image pins CI's, and the same other packages, user, mounts and `QT_QPA_PLATFORM=offscreen`. Its build's context is `test/docker`, so it copies `sc313/check.sh`: both images run the one `check` command, and both images' hashes cover it. To move the pin, set `FROM` and `SC_APT_VERSION` to a release whose archive carries the build (check with `docker run --rm ubuntu:<release> sh -c 'apt-get update -qq; apt-cache policy supercollider-language'`), and the pin's line in `docs/checks.md` (CI, Pins) with them; a docs test checks the Dockerfile pins a 3.14.1 package and that `docs/checks.md` names it with its Ubuntu release. Dependabot never moves it.
- A log names its version: each container's log begins `strata engine check on SuperCollider <release> (option -s <version>, image <image>)` (`3.13.0 (option -s 3.13, image strata-sc313)` or `3.14.1 (option -s 3.14, image strata-sc314)`), which no classification pattern reads, and the start prints the same before its areas. Containers are named `strata-sc313-<pid>-...` or `strata-sc314-<pid>-...`, and a default log folder `strata-sc313-logs.XXXXXX` or `strata-sc314-logs.XXXXXX`, so a folder given with `-o` is told apart by its logs' first lines.
- **A full run is CI's shards** (#581): one container, and so a fresh sclang, per shard of the `engine-shard` matrix in `.github/workflows/test.yml` (its `areas` list, one `- a,b,c` item a shard), each running only its shard's areas (`STRATA_ENGINE_CHECK_AREAS=<shard>`). The list is read from the workflow at each start, never copied into the script, so CI and the local runner cannot drift; a missing list, or an item that is not area names joined by commas, fails the start (exit 2, naming the workflow) before any container runs. Why: one sclang running every area in turn (about 940 s) is where 3.13 gives out (#131's family). With 3.4's `modulation` area added last, 2 of 8 such runs segfaulted as sclang quit after every check had passed, and heavier versions of that area's checks crashed inside it, while CI's shard holding it passed 12 of 12.
- `-1` runs each full run in one container, every area in one sclang, as before (for studying #131). `STRATA_ENGINE_CHECK_AREAS`, set and not empty, also runs one container per run, with those areas, as before. `-l` prints the shards a sharded run would use, one a line, and starts nothing (a docs test compares its output with the workflow's list).
- The 3.13 image (`strata-sc313`, from `test/docker/sc313/Dockerfile`) is CI's setup: Ubuntu 24.04, `supercollider-language` and `supercollider-server` at CI's `SC_APT_VERSION` (`1:3.13.0+repack-1ubuntu3`; a docs test checks the two pins match), `jackd2`, `procps` and `coreutils`. Its `check` command (`test/docker/sc313/check.sh`) starts a dummy JACK, waits for `jack_lsp`, then runs `test/run_engine_check.sh /norns` on the repo at `/src` with `STRATA_ENGINE_CHECK_ONE_SCLANG=1`: one sclang a container, since this script makes the shards itself (and `-1` means every area in one sclang, #671).
- The script builds the image when it is missing or its sources changed (its Dockerfile and `test/docker/sc313/check.sh`; the image's `strata.dockerfile-sha256` label holds their hash), so a fresh machine needs no manual step. The one-time build takes about a minute (55 s measured for 3.13; about 60 s for 3.14.1; longer on a slow connection: it downloads Ubuntu and its SuperCollider and JACK packages, about 230 MB for 3.13); later runs reuse the image.
- Each container is `docker run --rm --user $(id -u):$(id -g) -e HOME=/tmp -e XDG_RUNTIME_DIR=/tmp -v <repo>:/src:ro -v <norns>:/norns:ro strata-sc313 check` (`strata-sc314` under `-s 3.14`). It runs as a non-root user because QtWebEngine refuses root. The mounts are read-only: the check writes only to its container's `/tmp`.
- Every container has its own network, so parallel containers never clash on a port. Local sclang runs exhaust sclang's language ports past a few at once, so use this script for more than three or four parallel runs.
- `-n` and `-j` take positive decimal counts. Leading zeros are allowed. An all-zero count under either option exits 2, including in classify-only mode (#1084).
- `-n` is the number of runs (1), `-j` how many containers run at once (1; the shards of one run and of different runs alike, each started as one ends: a sharded run is one container per shard, so `-n 8` starts eight times as many containers as the workflow has shards, `-j` at a time. A container's job counts as running while its status file, emptied before the launch starts any container, is still empty, so a PID the system has since given to another process cannot hold a slot; only a job killed before it wrote its status is looked up by PID), `-o` the log folder (created if missing; default a new `${TMPDIR:-/tmp}/strata-sc313-logs.XXXXXX`, or `strata-sc314-logs` under `-s 3.14`). A sharded run `<i>`'s shard writes `run-<i>-<shard>.log` and `run-<i>-<shard>.status`, its commas written as `_` (`run-3-voices_freeze_grains.log`); a run in one container writes `run-<i>.log` and `run-<i>.status`. Each log ends with `strata container seconds: <n>`, the container's wall-clock time. The script never deletes a log. `STRATA_ENGINE_CHECK_AREAS`, `ENGINE_CHECK_TIMEOUT` (which applies to each container, so to each shard of a sharded run), `STRATA_SOAK_ROUNDS` and `STRATA_SOAK_SECONDS` pass through to every container.
- Every container has a memory cap, `--memory` and `--memory-swap` both `$STRATA_SC313_MEMORY` (default 8g; a healthy run of every area peaked at 1.42 GiB, sampled with `docker stats` every 3 s), so a collector gone wrong (#211) is killed inside its own container and not by the machine's out-of-memory killer, which once took sclang at 59 GB (#544). The image's `check` command prints `strata cgroup oom_kill: <n>` from the container's `memory.events` (cgroup v2) after the run.
- The summary classifies each container by its log, worst first (#545, #687): **collector failure** (the log holds the collector's count-error lines, #211, whatever else it shows: a `FAIL` line, a cap kill, exit 137, a signal, and exit status 0 too, since a collector line is a regression even when sclang survived it; its detail starts `#211; count errors` and then says what else the log shows: the first `FAIL`, `ERROR` or `Strata invariant broken` line, the cap's note, `exit 137`, the signal, or that the check itself passed if it exited 0 without a failure line, cap kill or signal); **failed** (any `FAIL`, `ERROR`, `*** ERROR:` or `Strata invariant broken` line, even with exit status 0 (#1193), with a note when the cap was involved too); **capped** (the cap killed a process: `oom_kill` above 0 in the container's own count); **killed** (exit 137 with no cap kill: stopped from outside, such as a `docker kill`); **crashed** (the runner reports sclang ended on a signal with none of those: #131); a remaining `ENGINE CHECK FAILED:` report also counts as **failed**; **passed** (status 0 with none of those diagnostics). A sharded run that did not pass takes the class of its worst shard, the first in that order after passed (of two alike, the first in the run's order: the workflow's), and its line names that shard (`run 3: crashed in effects,voices (sclang ended on signal 11 after 90 s), <log>`), then each other shard that did not pass on a line of its own (`  and failed in ...`), in the run's order. The summary counts runs by class, then, for sharded runs, their shards by class (`shards: passed ... of ...; ...; crashed <n> (#131); missing <n>`: a run counts once, so a crash beside a failure in another shard shows only there; take #131's rate from this line) and names the slowest shard with its time (to rebalance the workflow's shards by). The script exits 0 only when every run passed.
- `-c` classifies the runs already in the `-o` folder (required; it makes no folder), of either layout, and starts nothing (the structure tests feed it fixture logs). In folders from older runners, a run with `run-<i>-*.log` files is read as sharded, against the workflow's list: its shards in the list's order, then any shard log the list no longer names, by file name. A run lacking the log of one of the list's shards is **incomplete** (`run 2: incomplete (no log for zeta,delta)`, then any shard of it that did not pass), counted apart (`incomplete <n>` among the runs, `missing <n>` among the shards), and not passed. Each missing workflow shard contributes one to the shard total and missing count, however many areas it contains (#1083). If an unmarked run has both a single-process log and shard logs, its layout is ambiguous and the runner reports it as incomplete. A run with no shard logs needs its single-process `run-<i>.log`. If it is missing, the run is incomplete even when its status file contains 0 (#1085).
- On a new launch, `current-run` identifies the results that belong to this attempt (#1189). Keep it with the logs when copying a folder. It is empty during setup. Before starting any container the launcher empties the expected status files and publishes the run count, attempt identifier and shard list (empty for single-container runs). Replay uses that list even if the workflow changes. A requested run outside the recorded count or a result without its log and finished status is incomplete. After an interrupt, completed shards still contribute their diagnostics and counts. Files from other layouts stay in place. A second writer to the same folder exits 2 while the launcher or its container jobs hold the folder lock (`flock`, or Perl's flock on macOS). The operating system releases the lock when those processes exit.
- The structure tests run the script, and a copy of it beside a workflow of its own, against a fake `docker`, with the caller's `STRATA_ENGINE_CHECK_AREAS`, `STRATA_SC313_IMAGE`, `STRATA_SC314_IMAGE` and `STRATA_SC313_MEMORY` cleared (one exported while working on an area must not change what they see): every container carries the cap, a full run is one container per shard, `-j` bounds the containers at once (also in a reused log folder), `-1` and the areas variable keep one container per run, a list it cannot read starts nothing, `-c` keeps the workflow's order and reports a run missing shards as incomplete, an unknown `-s` starts nothing, `-l` prints the same shards under either version, and `-s` picks the image, its Dockerfile and build context, the containers' names, the logs' first line and the default log folder's name (#1039). An interrupt stops only the containers this start launched (named `strata-sc313-<pid>-<i>`, or `strata-sc313-<pid>-<i>-<shard>` for a shard; `strata-sc314-` under `-s 3.14`).
- Examples: an engine package's gate, four full runs (four times the workflow's number of shards in containers), eight at once: `test/run_engine_check_313.sh -n 4 -j 8 -o /tmp/full-313` (at 3.4's package 0c, with seven shards, eight full runs at `-j 8` took 1048 s on a 32-thread machine and passed 8 of 8; the slowest shard, voices, freeze and grains, took 158 s a container, memory and modulation 83 s). #131's rate on the files area: `STRATA_ENGINE_CHECK_AREAS=files test/run_engine_check_313.sh -n 16 -j 8 -o /tmp/files-313`. #131's rate on full runs in one sclang: `test/run_engine_check_313.sh -1 -n 8 -j 8 -o /tmp/one-313`. A full 3.14.1 check, its shards at once: `test/run_engine_check_313.sh -s 3.14 -j 7 -o /tmp/full-314` (at #1039, 368 s and 7 of 7 shards passed; each shard, 192 to 368 s, took within 5 s of its time in a sequential local run).
