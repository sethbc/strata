## Must not break

- CI's LuaJIT is built without Lua 5.2 compatibility, so `table.unpack`, `table.pack`, `table.move`, `math.type`, `math.tointeger`, `utf8.*`, `string.pack` and `string.unpack` are nil there, though a local LuaJIT may have them. Never use them in `lib/`, `test/` or `strata.lua` without a fallback in the same expression (`table.unpack or unpack`). A static check in `test/unit/structure_test.lua` fails any other use (comments and strings are skipped).
- No unguarded recursive delete, in code or in the shell commands you run. The code's rule (`h.remove_tree`, the engine check's own templates, the structure test) is under Temporary folders below. In your own commands, quote the path, fail on an empty variable and pass it after `--` (`rm -rf -- "${dir:?}"`), spell out an absolute prefix rather than a bare `$var/...`, and remove a worktree with `git worktree remove`, never `rm`.

- **The last line of every run is `<tests> tests, <failures> failures`**, with the totals a single-process run of the same tree prints: workers, the landings and CI read that line and the exit status. A parallel run changes only the time a run takes.
- **One process prints what the runner printed before it ran in parallel, byte for byte**: `--jobs 1`, a run that takes one file, and a run started from inside a run.
- **A parallel run never hides a failure.** Each process's output is printed whole when it ends, never interleaved; every `FAIL` is printed again just before the totals; a process that ends abnormally (a crash, a signal, an exit without its report, a file that does not load or registers no test) and a file reported by no process or by two each fail the run, are named in a `FAIL <file>: ...` line and count as a failure in the totals.
- **The shards are a partition**: `h.shard_files` deals every unit file (never only a filter's) to exactly one of N shards by its weight, with whole numbers and names only, so the shards are the same on every machine and interpreter. A line in `UNIT_FILE_SECONDS` (`test/helpers.lua`) is optional: a unit file with none weighs `UNIT_FILE_DEFAULT_SECONDS`, runs and lands in exactly one shard like any other, so no landing fails for a missing line; a test fails only on a stale line, one naming no unit file (`h.stale_unit_weights`).
- **A run inside a run is single-process**: every command a run starts carries `STRATA_TEST_INSIDE_RUN` (the runner wraps `os.execute` and `io.popen`), so a test that starts a run never fans out again; only the runner's own tests clear it, to test the parallel run.
- **Every process's folder is inside the run's** (`<h.data_root>workers/<file>/`, from `STRATA_TEST_DATA_ROOT`, which `test/helpers.lua` accepts only beside the run's `worker.sh`), so the run removes them all on every way out, a crashed process's too (#483).

## The Lua test run

- `lua test/run.lua` and `luajit test/run.lua` load every `test/unit/*_test.lua` (listed and sorted by `load_unit_files` in `test/helpers.lua`, so a new unit file needs no runner edit) and run their tests. With an argument (`lua test/run.lua scenes`) they load only the unit files whose name contains it.
- Each unit file is `return function(h) ... end`: it registers its tests with `h.test(name, fn)` and takes the helpers from `h`. A unit file that returns no function, or whose function registers no test, stops the load with an error naming it, so an emptied file never passes as 0 tests (#484).
- The run exits 1 when a test fails, when no unit file matches the filter, when the files loaded registered no test, or when loading or running stops on an error (printed as `the run stopped:` and the traceback), and 2 on a malformed option (with a usage line, before any test runs). On every one of those ways out it removes `h.data_root` first (#483).

### The parallel run

- **Options**: `--jobs N` (`-j N`) runs the unit files in N processes at once, each file in a process of its own; `STRATA_TEST_JOBS=N` sets N where no option is given; with neither, N is the machine's cores (`h.core_count()`: `nproc`, else `getconf _NPROCESSORS_ONLN`, else 1), at most `DEFAULT_JOBS_CAP` (8, `h.default_jobs()`). N is never more than the files the run takes; at 1 every test runs in the runner's own process. `--shard K/N` takes only shard K of N (`h.shard_files`); a filter then keeps the shard's files whose name contains it, and a shard with none of them fails as a filter matching nothing does. `--dir DIR` reads the unit files from DIR (the runner's own tests); `--only NAME` and `--report PATH` are the parallel run's processes' own.
- **How it runs**: Lua has no fork, so the runner writes `<h.data_root>workers/worker.sh` and pipes the files, heaviest first (`h.heaviest_first`, by `UNIT_FILE_SECONDS`), to `xargs -n 1 -P N sh worker.sh` (GNU and BSD xargs both have `-P`). Each process runs `test/run.lua --jobs 1 --only <file> --report <file>.report` under the run's own interpreter, its output to `<file>.out`, and the script then echoes `done <file> <exit status>`, a line short enough to reach the pipe whole. The runner reads those lines as they come and prints each file's output whole, then checks its report: `strata test report`, the counts, each failure's text with its length, and `end`, written to a `.part` file and renamed into place, so a report is whole or missing. A process whose report is missing or not whole, or whose exit status does not match it (0 with no failure, 1 with some), ended abnormally.
- **What it prints**, after the files' lines: `the failures again (<n>):` and each failure as printed (only when there are some), `<files> unit files in <N> processes, <s> s` (`os.time()`, whole seconds), a blank line, and the totals. A process that ended abnormally adds no tests and one failure.
- **The weights** (`UNIT_FILE_SECONDS`) are each file's seconds run alone under Lua 5.3, rounded, at least 1, measured at 3.8's package x5 with several files at once; `UNIT_FILE_DEFAULT_SECONDS` (3) stands in for a file with none. A line is optional and only improves the balance: a heavy new file (over ten seconds alone, say) is worth one, a light one needs none. Re-measure when a file's time changes much: a stale weight only unbalances the shards (and the order the processes start in), it never leaves a file out.
- **Why at most 8 by default**: one file is the unit of work, and one test is the floor: `ui_layout_test.lua`'s "every page lays out with every voice, source, ALT state and flash" takes about 95 s alone, and the file about 125 s (on a 32-core machine, at 3.8's package x5). From 4 processes on, a run takes about that long whatever N is (Lua 5.3: 136 s at 4 and at 8, 148 s at 32; LuaJIT 144, 144 and 157 s; single measurements with other work running), so more processes only load a shared machine. Five workers each starting a full run at 8 processes run 40 at once on 32 cores, where 32 each would run 160: the files are CPU-bound, so the five runs share the cores and each takes about the five's work over the cores, then its heaviest files' own time (about 2 to 3 minutes each, where one alone takes about 2); nothing a run uses runs short (a process holds a few file handles and its own folder inside its run's, and a single-process run peaks at about 0.8 GB, a file's process at less). The tests with real waits (`structure_test.lua`'s engine check runner tests, which bound their fake sclang's and scsynth's waits) are where heavy oversubscription could tell, which the cap keeps from 160 processes. `--jobs` and `STRATA_TEST_JOBS` can still go higher.
- **The tests of a file are not split between processes.** 3.8's package x5 found the heavy files' tests independent of each other and of their order (`ui_layout`, `structure`, `docs`, `mutation`, `io_system`, `scenes` and `sequencer`: each half, the odd and the even tests alone, and the whole file reversed, passed under both interpreters), but a split gains little: the floor is `ui_layout_test.lua`'s first test (about 95 s alone), so splitting would take a local run from about 125 s to about 100, and nothing on CI's 4 cores, where the run is bound by its work. A follow-up could split that test by page in its own file instead.
- `test/helpers.lua` holds the harness: the stubs, the test registry and `run_test`, the assertions, `load_strata`, `find_upvalue`/`local_value`, the clock drivers and the helpers several unit files share.
- **Temporary folders.** Every test writes below `h.data_root` (a fresh `os.tmpname()` folder, made as `test/helpers.lua` loads and removed by the runner on every way out) and deletes only through `h.remove_tree(path)`, which refuses (raises, deletes nothing) any path that is not `h.data_root` or inside it, is relative or has a `.` or `..` segment, and quotes the path for the shell (`h.shell_quote`) after `rm -rf --`. Never call `rm` through `os.execute` directly. The engine check deletes only `<temp dir>/strata-engine-check-*`, and `test/run_engine_check.sh` only its own `strata-engine-run.XXXXXX` folder (#134). ### State machines: tables and walks

3.9's package 0a (its design's section 2). Three helpers in `test/helpers.lua`; their names, fields and the test names they register are what every later package of 3.9's first part uses. Their own tests are in `test/unit/stubs_test.lua` (the six at the end of the file, from "a transition table with an undecided cell fails, naming the cell").

- **`h.transition_table(spec)`** runs a machine's table as tests. `spec`:
  - `name`: the machine's name, which starts each test's name.
  - `states = {<state> = function(context) end}`: each brings a fresh script into that state (the helper has already run `h.load_strata()` and `h.finish_startup(context)`; a function may keep what it needs on `context`).
  - `events = {<event> = function(context) end}`: each fires that event.
  - `state_of = function(context) -> string`: the state the script is in now, a key of `states`.
  - `rows = {{state, event, next, check = function(context) end, known = <issue number>}}`: `check` and `known` optional.
  - `impossible = {{state, event, reason}}`: the cells that cannot happen, each with its reason (a non-empty string).
  - `notes = {path, machine}` (optional): the notes file (from the repository's root) and the heading whose table must equal the rows.

  It registers, in this order: one test a row, named `<name>: <state> + <event>`, which loads the script, calls the state's function, asserts `state_of` gives the state ("entering <state>"), calls the event's, asserts `state_of` gives `next` ("expected <next>, got <found>"), runs `check`, then every invariant (unless the test called `h.allow_broken_invariants`); one named `<name>: every cell is decided`, which fails naming each state and event pair (of every key of `states` and of `events`) with neither a row nor an `impossible` entry, a cell decided twice, a row or entry naming no state or event, a `next` that is no key of `states`, a `known` that is no whole number and an impossible entry with no reason; and, with `notes`, one named `<name>: the notes' table equals these rows`, which compares `h.notes_table(path, machine)` with the rows' state, event and next as sets of cells and fails naming each cell that differs, is missing from either side or is in the notes twice. A row with `known = <n>` asserts what the code does today where that is a fault with the open issue #n, so a table lands before the fault's fix (the fix then drops `known` and changes `next`); its test prints `<name>: <state> + <event> -> <next> (known #n): asserts today's fault` when it passes, and the helper returns `{known = {<those lines>}}`. A bad `spec` (no name, a field of the wrong type) raises as the unit file loads.
- **`h.notes_table(path, machine) -> {{state, event, next}}`**: the rows of the first table under the heading `### <machine>` of a notes file (`path` from the repository's root, or absolute), from its columns State, Event and Next wherever they stand (an Effect column or any other is skipped), each cell trimmed with its backticks stripped and `\|` read as a pipe. Headings and tables inside code fences do not count, and the table must come before the section's next heading of any level. It raises on a file it cannot read, no such heading, no table under it, or a column missing. The example below is what its own test reads.
- **`h.walk(spec)`** runs seeded walks. `spec`:
  - `name`, `seeds` (a list of whole numbers from 1) and `steps` (ops a seed).
  - `setup = function(context, random) -> state`: run after `h.load_strata()` and `h.finish_startup(context)`; what it returns is the walk's state, passed to every other function (keep `context` in it if the ops need it). `random` is the walk's own generator (below), passed so that a setup's draws are part of the seeded sequence.
  - `ops = {{weight, name, fn(state, random)}}`: each step picks one by weight (`random(1000) * total / 1000`, then the ops in order) and calls it.
  - `after = function(state, op_name) -> problems` (optional): a list of strings (or one string), empty or nil when all is well; an oracle's comparison goes here.
  - `finish = function(state) -> problems` (optional): run after the last step, an end check or a tidy-up.
  - `reached = {<counter names>}` and `counts = function(state) -> {<counter> = <n>}` (optional, together): the paths every walk must have moved.

  It registers one test a seed, named `<name> (seed <n>)`: after each op, `after`'s problems and then every invariant (`invariant <name>: <message>`; skipped once the test called `h.allow_broken_invariants`), and after `finish` its problems and every invariant again; any problem fails the test with `<name> (seed <n>), step <k> (op <op>): <problems>` (or `at the end`) and a line `the ops so far: <op>, <op>, ...`, so the sequence can be replayed: the same seed picks the same ops (the generator is MINSTD, `state * 48271 % 2147483647`, `random(n)` 1 to n, the same under Lua and LuaJIT and apart from the script's `math.random`). Each seed that walks to the end adds `counts(state)` to the walk's sums; with `reached`, one more test, `<name>: the walks reached every path`, registered after the seeds' and run after them, fails naming each counter whose sum is not above 0 (and the seeds that walked to the end). The notes walk of `test/unit/strata_test.lua` (ruling 57) is its first user.

### Reaching script state

- Add a test for every behavior change.
- Script values are reached through `find_upvalue()`/`local_value()`. They look in the shared table `S` (`lib/state.lua`, found as the upvalue `S` of `init`; a key ever assigned into `S`, even to nil, is recorded in `S.__declared` and found while nil), then in `S.constants`, then in the script locals (the upvalues of global functions). The setter writes where the name was found (every upvalue of that name). A script local must have one value among all the global functions' upvalues of its name: two different ones (every module's own `local M`) raise an error naming the functions, since which one `pairs(_G)` meets first changes from run to run (#482).
- The stub's `include(file)` follows norns' `lua/core/startup.lua`: it runs the script folder's `<file>.lua` with `dofile` on every call.
- Only `strata.lua` includes, each module once, by its `lib/` path. A test checks this, and that a reload builds an `S` sharing no table with the last one.
- `load_strata { source = text }` loads a patched copy of `strata.lua`, and `load_strata { module_sources = { ["lib/x"] = text } }` patched modules. `patched_script(pattern, replacement)` builds either from whichever file holds the pattern.
- `read_lua_sources()` returns the script's Lua files (`strata.lua`, then `lib/**/*.lua`) for the tests that read the source.
- `MODULE_HOMES` (`test/unit/structure_test.lua`) maps a module path to the global functions it must define.
- Each `load_strata` gets a data directory of its own, named by a counter (tests reseed `math.random`, so a random name could repeat). `load_strata { data_subdir = name }` shares one between loads (the persistence tests).

### Module safety nets

The Wave 0 golden master (a logged scripted session compared with a fixture) proved the module split changed no behavior and was retired once the split was done; git history keeps it.

- **Global-reference check** (Lua 5.3 only; it needs `luac` or `luac5.3` on PATH and fails without one; LuaJIT prints a skip note):
  - `luac -l -l -p` lists each file's `GETTABUP`/`SETTABUP` on `_ENV` (the name in the comment, or for a key past the first 256 constants the `LOADK` into its register);
  - every global read must be written by some script file or be a key of `_G` right after `stubs.install` (norns and the standard library);
  - `KNOWN_UNDEFINED_GLOBALS` lists reads allowed while their bug is open (none today).
- **Duplicate-global check** (same listing, Lua 5.3 only): no global, function or value, is written by more than one file, since a later include would silently replace the earlier definition. `GLOBALS_WRITTEN_IN_TWO_FILES` allows `key` and `enc`, which `lib/pages/buffer.lua` puts back when the file selector fails.
- **Locals probe**:
  - inserts `local p1, ..., pN` at the end of each file's main chunk (before a module's final top-level `return`) and of each constructor (before its final `  return M\nend`; every module but the plain constants table must end that way);
  - finds the largest N that loads;
  - requires at least 30 in each main chunk and each constructor, `strata.lua` included (195 free in its main chunk today).
