# 3.9 decisions (the state machines made explicit, the grid's sequencer reworked, the reverb's freeze)

The other releases: [README](README.md).

This file opens with 3.9's first part: the state machines made explicit (`docs/design/3.9-state-machines-design.md`, written 2026-11-21, approved 2026-11-22, marked as built). Ten read-only audits found about 110 state machines the code keeps without naming and filed every finding, #864-#949; the work makes each machine explicit in the forms its history earns (one name and one reader, a table a test runs, a seeded walk, a state shown where it changes what a key does) and adds no stored state. It was built from 2026-11-23 to 2026-11-24 and landed whole with its docs pass (6e). Below the maintainer's decisions come the plan's sixteen rulings ("The design against the merged code"), cited as plan ruling N; the build's rulings that bind more than one package, B1 to B11; and the build's rulings by wave, unnumbered, each under the package it was taken for. Each says what it costs if it was wrong. Its second part, the grid's sequencer reworked, and its third, the high tier's reverb freeze, follow in sections of their own (below). All three shipped in 3.9.0 (2026-11-25).

## The state machines made explicit

Decided by the maintainer:
- **The design's five decisions** (2026-11-21, listed in the design's "Decided"). By number:
  1. Find every implicit state machine and make it explicit, in the way that serves the player, the developer and the agent together, and break nothing. If wrong: the forms are tests, notes and accessors, each removed in a normal pull request.
  2. The findings are filed, the design and its plan are written, and no implementation starts until the maintainer says so. If wrong: a day's wait.
  3. Every agent dispatched for the audits, the checks and the reviews of the design and the plan runs on the top model. If wrong: its cost.
  4. Every finding is an issue and every issue is fixed, whatever its size. If wrong: a longer plan (57 packages) than a triage would have left.
  5. Three calls put at the hand-over, and kept: a direction change ends the pass where the new direction wraps (#874); clear on a frozen delay releases the freeze, then clears (#912); an LFO that is on keeps its engine node at depth 0 (#925). If wrong: each is in the design's "Cost if wrong" or its package; #874's old rule is one line of `take_position`, #912's alternatives are a refusal or a held empty loop, #925 moves a few sends that its package names.
- **The other calls that change what plays or what a key does** (2026-11-22, each put in the question dialog with its options; all stand as the design wrote them):
  - #864: a waiting freeze key schedules the value its press asked for, not a toggle. If wrong: a second press during the wait takes the set back instead of flipping what lands.
  - #920: a misstep wraps by the pass's own length until the pass ends. If wrong: one step of a pass lands on another step while a shorter length waits.
  - #883: a silent set that leaves the delay bypassed and frozen releases the freeze (bypass wins). If wrong: a PSET that held both comes back unfrozen, and the loop it held is gone.
  - #877: fill skips a slot whose file is missing, and keeps its path. If wrong: a fill leaves a gap the player must fill by hand.
  - #922: the undo holds a chain start's replaced patterns and a random sequence's `new`. If wrong: an undo on SEQ or MOD brings back more than the player meant.
  - #927: the undo holds a learn's rewired routing; no key cancels a learn. If wrong: a learn made by mistake costs one undo.
  - #866: the grid's step editor may cover any modal owner, and the covered owner forgets its presses. If wrong: an owner that needs its release after being uncovered never gets it (none does today).

## The high tier's reverb freeze

The design is `docs/design/3.9-reverb-freeze-design.md` (#819), written and approved on 2026-11-25, built the same day and marked as built. Below come the design's nine decisions (its "Decided": five carried from 3.8 and four of 2026-11-25), its twelve calls by number, and the build's rulings, unnumbered. Each says what it costs if it was wrong.

Carried from 3.8's design (its decision 15) and its plan's rulings, and not reopened (the design's decisions 1 to 5):
1. The freeze is the high tier's alone: the standard tier's reverb (`FreeVerb2`) has no way in, and there the freeze is not offered. If wrong: a standard-tier player has no reverb freeze; a second freeze for `FreeVerb2` is a design of its own.
2. It is a toggle like the delay's: a binary param, in no PSET and no scene, no LFO destination and no macro target. If wrong: a player who wants a scene to freeze the reverb maps it to MIDI instead.
3. A bypass ends the freeze first, and a freeze set while the reverb is bypassed is refused, as the delay's. If wrong: none in sound; a reverb is never bypassed and frozen.
4. Frozen, the reverb's input is closed after the diffusers, which also shuts shimmer's loop, and the size is held until the release. If wrong: a frozen tail cannot be fed; an accumulating freeze would grow without bound.
5. The pages reach the freeze only through `S.lib.fx_hold` (`offered`, `frozen`, `freezable`, `toggle`), never through the param's presence. If wrong: none; the pages lit up on the high tier with no change of theirs.

Decided by the maintainer (2026-11-25, each in the question dialog; the design's decisions 6 to 9):
- **The bar is a minute**: frozen, the level and the band above 6 kHz stay within 1 dB after 60 s, and the level's step at the freeze stays within 1 dB. 3.8's rule measured about seven seconds, which a tail that fades over a minute can pass. If wrong: a freeze that would have served is held back; the bar is one figure in the check.
- **Measure before designing**: a throwaway measurement of the candidate freezes on SuperCollider 3.13 and 3.14.1 came before the design, so nothing is cut mid-build. If wrong: an hour spent.
- **The FDN's lines move into buffers** (two a line, one for each read) rather than a second read in the real-time pool: about 144 KB back to the pool for about 288 KB of ordinary RAM. If wrong: more code to keep; the second read in the pool changes only the def.
