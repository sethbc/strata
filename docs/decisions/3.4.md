# 3.4 decisions (modulation and sequencing)

The other releases: [README](README.md).

The design's questions (all decided), its calls and its "Cost if wrong" list are in `docs/design/3.4-design.md`, with its amendments of 2026-11-11 (step gates, swing, mute and solo, the input level as a source, the XY morph) and the lines amended to what was built (2026-11-12). What follows was decided while it was built: by the maintainer, by the plan where the design met 3.3's merged code, and as rulings while the packages were built, reviewed and landed. A ruling keeps the number the build gave it (`ruling 71`), which code comments and notes cite. *To confirm* marks a ruling the maintainer has yet to confirm, among them those that depart from the design's text.

Decided by the maintainer on 2026-11-11, each asked with its alternatives:
- **Questions 41-44 as recommended:** step gates in the per-voice stage, swing per voice, mute and solo per voice, the input level as a modulation source. If wrong: each is its own params and one engine control or source; the defaults keep 3.3's sound.
- **The internal clock's reset still leaves the patterns alone** (#530's rule): PARAMETERS > CLOCK > reset neither starts nor stops them; only an external clock's transport is followed. If wrong: one condition in `lib/sequencer.lua`.
- **What LFO's, MOD's and SEQ's page randomize draws:** on LFO the selected LFO's shape, rate (or clocked rate) and phase; on MOD scatter's depth (whole percents, 0-30) and rate (even in octaves, 0.02-0.5 Hz) and the depth of every complete routing (whole percents, −50 to 50), while the macros, morph, gestures and LFO sections draw nothing (a macro's apply writes up to eight params the undo would not hold); on SEQ the pattern's levels in both views, the held press opening the edit view from the pattern view and resetting the row in it. If wrong: one spec per section.
- **A PSET without a side file loads empty:** no macro targets, routings or recorded loops (a 3.3 PSET has none). If wrong: a PSET whose side file was lost keeps the session's targets instead; one branch in each side file's hook.
- **The XY morph is built in 3.4** (design §5.5, amended): a 5×5 pad on the 16×16's page 3 (rows 11-15, columns 12-16, since row 16 has been every page's lock row since #442), the existing `morph` as the first axis and a new `morph_y` as the second, so the two-scene morph is unchanged at y = 0. If wrong: the second axis and two corner params go unused; nothing else depends on them.

Decided by the maintainer on 2026-11-12:
- **Voice starts and source switches stay outside the send budget's count** (ruling 93, #649, "leave it as designed"): the budget counts the deferrable writers' continuous sends; a discrete switch made by a recall, a transition's end or a morph crossing (a voice start or stop, a source switch, an envelope or grain mode change) goes out at once and in order, uncounted, as the design never defers hand edits, steps, recalls or a crossing's switch, applied whole and in recall order (ruling 27). The contract is stated in `docs/notes/lua/engine-sync.md` and the exception pinned by a test. Measured: 59 messages for a voice start, 58 for a running voice's source switch, 417 for a crossing that starts all seven voices. If wrong: a crossing's burst stays outside the budget's count, as documented; counting whole voice starts against a window meant for continuous values would starve the sends the budget protects.
- **#211 is held for now,** to be fixed later, with no release named: the waveform area's 300 s load-and-save check fails with sclang's collector error about 1 run in 10 to 16 as measured at the release on SuperCollider 3.13 and 3.14.1, on the 3.3 engine about as often as on 3.4's: the 1 in 80 recorded at 3.3 no longer holds on either, and what changed since was not tested (the machine, the test image's unpinned packages and the kernel are candidates), more under load, and a failed shard is rerun (`docs/status.md`). If wrong: CI reruns a `record,waveform` shard about as often, until it is fixed.

The design against 3.3's merged code (the design cites `main` before 3.3), as the plan resolved each:
- **Scenes are format 6:** 3.3 took format 5 (#314), so every "version 5" in the design reads 6. If wrong: none; it is the next number free.
- **3.4's data files** (`macros.data`, `matrix.data`, `gestures.data` and the three per-PSET side files) go through `S.lib.data_files.write` and `read`, never `tab.save` or `tab.load` (3.3's rule). If wrong: none; one rule for every file.
- **Transport following shipped in 3.3** (#530, from an external clock source only, with no param): 3.4 adds `seq_follow_transport` (on by default), SETUP's row and the restart of every voice at step 1 and of a running chain, and keeps 3.3's start and cleanup steps; the design's own transport orders are not added. If wrong: a second pair of steps for one handler.
- **Page randomize shipped in 3.3.2** (#557): the design's SEQ ALT+K2 hold became the held press (`alt_hold`), and a page record's optional `alt_hold_hint` names a held press other than `K2:reset` (SEQ's `K2:edit`, MOD's `K2:clear`). If wrong: one hint field.
- **The 3.4 registries that shape init close at init** (`scene_blocks`, `scene_migrations`, `pset_hooks`, #384's rule); `param_touch`, `lock_change`, `step_outputs` and `mod_sources` are read at each use and stay open. If wrong: a late registration of one of the first three is refused at load instead of being missed silently.
- **A silent macro set is a scene field's own setter** (`S.register_scene_field`'s optional `set`), which a recall, a transition step and `apply_entries` call instead of `params:set`, not an option of `apply_entries`. If wrong: a field-level hook where a recall-level flag would do.
- **Registered continuous scene fields are range-checked** by `validate_scene` against their param's range, which covers the macro values, the routing depths and scatter without code of their own. If wrong: a field whose valid range is not its param's needs its own check.
- **`v<i> amp` is registered from `lib/voice_mix.lua`,** after `rsend`, so the saved indices of 3.2's registered destinations keep their meaning: 68 built-in, `hist` 69-75, `vfilt` 76-82, `dsend` 83-89, `rsend` 90-96, `amp` 97-103, `macro 1`-`macro 16` 104-119. If wrong: saved LFO destinations point at other params; the order is the contract.
- **Global LFO destinations share the `lfo_destinations` registry** as `{label, param_id, global = true}` records, in registration order with the per-voice ones. If wrong: one more registry and reader.
- **The PSET read hook stays first:** the installer of 3.4's PSET hooks keeps `migrate_read_pset` (3.3's Pulse mirror and whole-number rounding) ahead of the registered hooks, and the stub's PSET actions follow norns' paramset (`action_write`, `action_read`, `action_delete`, with the PSET's number). If wrong: a hook that reads a param before its migration.
- **`strata_seq` is one group filled by two modules:** the sequencer adds the group and calls the quantizer's `add_params` for `quantize_actions`. If wrong: two groups in the menu; one record.
- **Quantized actions wrap the player's call sites** (BUFFER's keys, the grid keys, the scene recalls, the pattern start, the grids' freeze keys), never `jump` and `recall_bookmark` themselves, which a step's bookmark lock also reaches and which must never wait for a bar. If wrong: one wrap per call site.
- **The LFOs notice a transport start themselves** (`clock.get_beats()` lower than at their last step) and resync every clocked engine LFO, so the LFOs and the sequencer share no call. If wrong: a resync a step late after a start that moved the beat less than a step.
- **Cleanup reaches no engine** (#461): norns frees the engine before `cleanup()`, so 3.4's cleanup steps cancel clocks and save files and send nothing (the design's `stopFastLfo` and zeroed offsets at cleanup, §2.7 and §10.2, are not built). If wrong: none; nothing could arrive.
- **MAIN's `~` goes after the voice's name** on y 18, which it shortens: `OFF [L] [T] [F]` already reaches x 127. If wrong: the mark in another place; one draw call.
- **Arc sweeps are 1024 ticks** (#552), and the LFO depth rings step whole percents through `arc_whole_steps`, as merged. If wrong: none; 3.3's rule.
- **The user docs:** `docs/user/modulation.md` (from 3.3) gains the macros, morph, scatter, recorders and matrix; `docs/user/sequencer.md` is new. If wrong: none.
- **The two-quick-loads blink is closed in 3.4** (#578, outside the design, closing 3.3's ruling): every `bufferState` report names the slot's load count modulo 7, and Lua acts only on its newest load's reports. If wrong: one comparison in `buffer_state_changed`; more than 7 loads of one slot in flight bring back 3.3's blink.
- **The scene name entry has no modal owner:** norns' `textentry` takes the keys, encoders and redraw itself and cancels on a K2 release, so it opens on ALT+K2's release, as BUFFER opens the file selector; the design's modal owner for it (§9.3) is dropped, and the step editor is the modal owner's one user. If wrong: a modal owner for a screen norns already owns.
- **A step note's reference pitch:** a buffer or input voice has no frequency, so its pitch is the note MIDI plays at its rate (`rate_root_note` at rate 1, middle C), and the scale's root applies to every source. If wrong: such voices' degrees count from another note; one function.

The plan's own calls, beside those above:
- **Wave 1 in three steps** (its first six packages; then the engine's fast modulation, the macros and scatter, and the sequencer; then the matrix), each landed as a batch, with a sibling package's interface read defensively inside a step where two were built at once. If wrong: more landings than one wave would take.
- **The 20 ms ratchet rule** is `hits = min(ratchet, max(1, floor(step_seconds / 0.02)))`: a step plays at most as many hits as fit 20 ms apart, and at least one. If wrong: ratchets thin differently at fast tempos; one line.

Scenes, recalls and the morph:
- **A voice a recall starts is started after its last entry other than its pattern entry,** as 3.3's recall did (ruling 3). If wrong: none; the order is 3.3's.
- **`apply_entries`' `only = "discrete"` includes the scene blocks** (step data, macro targets, routings), which the morph switches at its crossing (ruling 4). If wrong: the morph filters blocks itself.
- **A scenes load may raise every slot's revision,** changed or not (ruling 5). If wrong: one wasted morph plan per load.
- **Per-voice entries carry their voice** (`voice = i`), never parsed from the id (ruling 6). If wrong: one redundant field.
- **A block's `apply` gets a deep copy of the scene's value;** `validate` and `through_zero` get the stored value, read-only (ruling 7). If wrong: a few hundred table copies per recall.
- **The old default name `scene <n>` is cleared only in files older than format 6** (ruling 36), so a player's own "scene 3" survives a load. If wrong: none.
- **`S.lib.scenes.label(slot)` (`S3 dusk`, or `S3`) names a scene in every flash;** the quantizer's wait flash keeps `S<n>` (ruling 40), since `S16 <12 characters> at bar` would cut what matters. If wrong: the wait flash shows no name.
- **ALT+E2 on a slot moves a bank only when the slot eight away exists,** and acts as E2 on a field row (ruling 41). If wrong: one condition.
- **A PSET load sets the morph without applying it** (ruling 24): the PSET holds the blended values, which an apply would overwrite. If wrong: a PSET whose scenes changed since it was saved re-blends only when the morph moves.
- **A recall or a transition stops an unfinished morph apply,** and the next move starts over from the recalled state (ruling 25). If wrong: none seen.
- **Discrete entries equal in A and B stay out of the morph's plan** (ruling 26), so a hand change to what both scenes agree on survives a crossing. If wrong: a crossing does not restore it; a recall does.
- **The 120-value limit counts continuous values;** a crossing's discrete switch is applied whole, in recall order (ruling 27). If wrong: a crossing sends a recall's worth of messages at once, as a recall does.
- **At a crossing the through-zero ids are set to 0 before the switches run** (ruling 28, design §10.2). If wrong: a routing's old depth on its new source for one apply.
- **The morph's continuous writes are a transition step's** (`S.lib.scenes.set_value`, outside `scene_recall_in_progress`), so a quantized voice's freq snaps under a morph as under a fade (rulings 29 and 34). If wrong: one export and one call.
- **An LFO that one scene has on and the other off blends its depth toward the stored depth and switches at the crossing,** with no fade to 0 first (ruling 30): a transition's rule (#408) ends in a recall, which a morph never does. *To confirm.* If wrong: a step in that LFO's depth at the crossing, among the crossing's other switches; the fix is §10.2's ramp through 0 for it.
- **The apply made when the morph comes to rest ignores the 1/1000 threshold** (ruling 35), so a morph at 0 or 1 holds the scene's exact values. If wrong: a few more sends when a morph stops.
- **The XY morph counts a corner only while its weight is above 0** (ruling 87): an entry joins an apply only when it differs among the counting corners, so on an edge the morph is that edge's two-scene morph, value for value, and a hand change to what the edge's scenes agree on survives whatever the other corners hold. *Departs from the design (its four-corner rule overwrote such edits at y 0); to confirm.* If wrong: an entry that differs only in a zero-weight corner is not written until that corner gains weight.
- **A through-zero setting under the XY morph** (a routing) takes the weighted sum over its group of corners that hold the same thing for it, times `max(0, m − w') / m`, `m` the largest weight in the current corner's group and `w'` the largest among the counting corners outside it (ruling 88a, which replaced ruling 88's formula, measured on the groups' total weights, after that one left a dip): two corners that differ give the design's lead rule, and corners that agree blend with no dip between them. *Departs from the design; to confirm.* If wrong: a step in a routing's depth somewhere inside the square.
- **A crossing's discrete switch is applied at most once per `MORPH.crossing_seconds`** (about 0.3 s; ruling 94, #653, sized from the measured 417 messages of one crossing against the budget's 1500 a second): a single crossing is immediate, continuous values keep moving while a second one waits, at the wait's end the then-current corner's entries are applied (there and back applies nothing), and a recall, a transition, a PSET load and cleanup drop a waiting crossing. The budget exists because sclang cannot take more than its rate for long, and ruling 93's exception is sized for one crossing, not ten a second. If wrong: a second crossing within 0.3 s switches its voices up to 0.3 s late.

The script's hooks, the send budget and the LFOs:
- **A voice sync and a start re-send the voice's params that hold a base override or an extra offset,** after their direct sends (ruling 9; with nothing set, nothing more is sent). If wrong: a few extra sends per sync while a lock or a routing is active.
- **A `pset hook <name>:` line is a script error in the test harness** unless the test expects it (ruling 10). If wrong: a test that hides a failing hook.
- **`delta_with_detent` takes `opts.source`,** and every arc ring passes `"arc"`, whole-step rings too (ruling 11), since 3.6's controllers read the source. If wrong: three one-line edits.
- **`set_base_override` requires a finite number and raises otherwise;** a caller clears with `clear_base_override` (ruling 12). If wrong: one check.
- **A modal owner gets only the releases of presses it received** (ruling 13). If wrong: one table of pressed keys.
- **A PSET hook's read gets the read's silent flag** (`read = fn(path_base, number, pset_path, silent)`), and a hook that sets params passes it on (ruling 53). If wrong: none; hooks that ignore it are unchanged.
- **The random shapes' wave on the LFO page is a fixed picture of the kind,** as in 3.3, and the dot shows the script's draws (ruling 52). If wrong: a later page draws a trace of the draws.
- **Comments that named functions the LFO rewrite deleted were corrected in the rewrite** (ruling 51): a false comment is worse than a one-line conflict. If wrong: none.

The engine:
- **Every continuous argument of the five commands is checked for finiteness before it is clipped,** and a non-finite one makes the command do nothing (ruling 17): `clip` passes NaN. If wrong: one check per argument.
- **The mix stage's check limit is 42 KB** (40 in 3.3) and the buffer def's margin under 3.2's copy 4 KB (6 before; ruling 42): the stage measures 40.87 KB with the cutoff and level offsets, the step gate and the mute and their lags, every floor holds with room, an equivalent rewrite saves only 0.2 KB, and a gate or mute outside the stage would cost a second node per voice. The design (§8.12) left the stage's limit to the maintainer. *To confirm.* If wrong: the stage is reworked to fit 40 KB (the gate or the mute moves out, or the filter bank is simplified).
- **The ring def's margin under 3.2's copy is 10 KB** (12 before; ruling 55), since 3.4 adds the fast-modulation read to both grain defs by design; the 88 KB limit is what protects the pool. *To confirm,* with ruling 42. If wrong: as ruling 42.
- **The stage is measured with forty stages** (steps of about 0.42 KB) and its limit stays 42 KB (ruling 56): a finer reading, not a looser limit. If wrong: a reading within one step of 42 needs a decision then.
- **The gate's attack is rounded up to whole control blocks** (5.35 ms; ruling 43). If wrong: none audible.
- **A releasing LFO given a new shape gets a new node,** not a `Synth.replace`, and the check asserts the bound: one node per LFO that is not releasing, a releasing one gone within its 20 ms (ruling 44). If wrong: none; the bound is checked.
- **The amp offset follows the design's law** (`(amp × (1 + modSig + m4) × (1 + accent)).clip(0, 2)`): −1 silences and +1 doubles only with no crossmod and no accent (ruling 45). If wrong: none; the law is the design's.
- **A flaky check is fixed in its package,** never left flaky (ruling 46: the pitch check got a steadier measure). If wrong: none.
- **The cutoff LFO's docs give its measured behavior** (#612): the stage's 0.05 s lag on linear Hz and the filter's rise limiter reshape a deep, fast cutoff LFO (at 100 % depth about 61 % of its swing kept at 10 Hz and 12 % at 50 Hz), and the engine's path is not changed this late, with no lag in octaves (ruling 83). If wrong: a deep, fast cutoff LFO stays shallower than a player expects, as documented.

The sequencer and quantized actions:
- **Strata's own voices are the exception to "a failing step output is skipped":** an error in the `voices` output stops the patterns as before 3.4 (#243, #382), shows them stopped and raises the error again, while any other output is skipped until the next start (ruling 38). If wrong: a `start_voice` bug stops the patterns, where skipping would have kept silent clocks running.
- **With the scale off, a note degree is exactly k semitones from the voice's own pitch** (ruling 39). If wrong: none.
- **One count for every clock after an unfollowed jump:** when the beat count is set back and the sequencer does not follow it (the internal clock, or follow off) while the patterns play, every voice's clock, the transport's counter, the chain, the division reset and the ratchets keep one count of their own (the clock's beats plus one shared offset), fixed as 3.3's single clock behaved (the next 16th waits for the new count's next 16th, at most a 16th late) and gone at the next pattern start or followed start (ruling 47). If wrong: after an ignored reset the sequencer's bars are not the clock's until the next start, and quantized actions land on the clock's bars, not the pattern's.
- **At each wake a clock tests the beat its sync returned:** at its target, or within a small named tolerance below it, the step plays; further below, the count moved, and the clock waits again on the new offset (or handles the jump itself); no path waits for the beat to climb back (ruling 54). If wrong: a jump within the tolerance shifts steps by that much, unnoticed.
- **After any move of the count every sequencer clock restarts from its saved state:** a noticed jump maps the transport's pending 16th to the first 16th at or after the beat, a wake late by less than a 16th is a late step, and at one wake a voice plays at most one step already due and skips the rest (ruling 58), so a busy moment never makes the patterns burst. If wrong: a starved scheduler skips steps where it used to bunch them.
- **A voice with no step holding a level inside its length ends its overrides at a wrap** (ruling 48). If wrong: none.
- **Euclid takes any integer rotation** and wraps it into 0..length − 1, storing the wrapped pair (ruling 49). If wrong: none.
- **A step's probability has no `off`:** the step editor's ring 4 clamps at its ends, and a step without one always plays (ruling 69). If wrong: an off below the range, a few lines.
- **A pattern replacement made from inside the step editor keeps it open** (its euclid and clear rows, ALT+K3, its randomize and undo): the held key stays the editor's, and its release closes the editor and toggles nothing; a replacement from anywhere else closes it (ruling 71, through `S.lib.pages_seq.step_editor_replacing()`). If wrong: the editor closes on its own euclid turns.
- **A modal owner may have `animates`,** read by the frame clock, so the step editor animates (ruling 72, #592). If wrong: none.
- **BUFFER's `bm` field keeps a per-voice record of the waiting bookmark,** so E3 steps from it while a quantized recall waits (ruling 31). If wrong: E3 moves one bookmark per bar.
- **The grid's two-key loop waits under the same key as the jump** (`position<v>`; ruling 32), so the first key's delayed jump never follows it. If wrong: the loop sets early.
- **The recorders' play params are not saved in PSETs,** so a PSET's loops load stopped (ruling 33): the PSET hook stops every recorder before it loads the side file. If wrong: a player restarts loops by hand after a PSET load.
- **The recorders' test of a beat count that goes back replaces `clock.get_beats` inside the test** (ruling 37). If wrong: a test rewritten on the transport helpers.
- **A grid's waiting bookmark repaints every connected grid** while one shows the position page, and nothing while none does (ruling 75). If wrong: a redundant repaint of other grids, a few times a second for at most a bar.
- **The clock stub's instant is matron's tick** (ruling 92, #588): every event due within 1 ms of an instant's first event is posted with it before any is delivered, and with a latency every instant due up to the delivery is posted in time order first, so `advance`, `run_for` and `advance_until` alike show a clock canceled while norns may have posted its resume: two wake-ups less than a tick apart can share a tick on a device, so the stub shows what norns could do, not only what it usually does. A clock that sleeps forever is never due (#650). If wrong: a test fails for a cancel that on a device needs two wake-ups in one tick, which is the hazard the stub exists to show.

Macros, scatter and the matrix:
- **The live macros file is written 0.1 s after a burst of target edits** (ruling 59); cleanup writes at once, and a PSET write uses the current targets. If wrong: a crash within 0.1 s of an edit loses it from the live file.
- **Scatter has no cleanup step** (ruling 60): it keeps no clock or handler, and cleanup reaches no engine. If wrong: two lines bring it back.
- **A routing to a fast destination sends `setFastOffset`, never `setGrainParam`** (ruling 62): design §10.2 binds over §13's test lines, amended. If wrong: the stub's rule and the tests move back.
- **The matrix's cleanup sends nothing** (ruling 63, #461): it cancels learn's timeout and forgets the offsets. If wrong: none.
- **A macro's fast extra joins the matrix's sum one LFO step after the macros' hook works it out** (ruling 64, about 21 ms). If wrong: a few lines in `lib/matrix.lua`.
- **The matrix's fast sends count against the send budget,** each fast channel one deferrable id with the newest sum winning (ruling 65). If wrong: the cap of 12 a step alone bounds the matrix at 576 a second; only the added path costs.
- **Bookkeeping that reaches no engine takes no round-robin slot and no budget count** (ruling 84, #636). Its remainder was not parked: the budget counts exactly the messages that reach the engine (#642, #644, #645, #646): a send to a stopped voice's param counts nothing, never waits and takes no slot of the LFOs' 12 a step, a param with no engine sender counts nothing, and the master density counts one message per running voice it reaches, a send larger than a whole window going when the window is empty. If wrong: an LFO on a macro gets about half the cap.
- **The budget's flush clock ends at its own wake,** never canceled while the script runs (#654; only cleanup cancels it). If wrong: one idle coroutine for up to a window.

Pages, grids and arc:
- **`S.lib.voice_mix.soloed(voice)`** joins `silenced(voice)` as the one answer for a soloed, heard voice (ruling 21). If wrong: one helper.
- **BUFFER's visit restarts the input level's polls** (`S.lib.input_level.refresh()`), keeping #438's protection now that the polls run on every page (ruling 22). If wrong: one redundant `poll.set` per visit.
- **A silenced voice's key lights at 6 while it runs and at 2 when stopped** (ruling 70, from the design's three levels). If wrong: one line.
- **The recorder keys act on release** (ruling 73, which replaced ruling 70's press-time action): a release before the half-second hold runs `press(k)`, the hold clears, and the release after it does nothing, so a clear never records or plays first. If wrong: a recording starts a tap's length after the press.
- **On MOD, the ALT hint's K2 part says what ALT+K2 does on the row** (ruling 76): `K2:rand` (or `K2:undo`) only where the section has a randomize spec, `K2:clear` where only the hold acts and would clear something, nothing elsewhere; the design's `K2:rand K3:dub` on a recorder named a key that does nothing there. *Departs from the design; to confirm.* If wrong: one string per row kind.
- **A routing's source choices are every registered source,** visible or not, in registry order (ruling 77), so all sixteen macros are reachable and a stored source has its place; the list view keeps the visible ones. *Departs from the design; to confirm.* If wrong: a longer E3 travel through the sources.
- **A grid's page change cancels every key hold pending on that grid** (ruling 78), a held scene save and the 16×16's row 15 clear or randomize among them: it can only stop an action, never cause one, and it is the rule that already ended a port's held steps. A change from 3.3 the design does not list. *To confirm.* If wrong: one line in `set_page` restores the held save.
- **Learn stays armed across page changes** (ruling 80, #595), with a header notice while it waits; K2 in its view, a new learn and its 10 s timeout still cancel it. The design (§4.5) canceled it on a page change, which left no way to finish it from the norns or the arc. *Departs from the design; to confirm.* If wrong: a learn armed by mistake lives up to its timeout on other pages.
- **A 128's macro key enters at the bank already shown** and steps on through the four banks, back to the voice faders after the fourth (ruling 81, #618): the bank is shared with MOD, the arc and every grid. *Departs from the design; to confirm.* If wrong: one line puts bank 1 back.
- **On a 128 showing macros, a fader page key or a voice key leaves the macros** for that page of voice faders (ruling 82, #619). *Departs from the design; to confirm.* If wrong: one condition.
- **The final review's set-aside lines stand as built or as designed,** but for three taken as defects (ruling 85): a MIDI note reusing a step's gate length (#639), a mute during a stopped voice's release (#640) and the morph's empty-scene flash without the scene's name (#641). Left as built, for the maintainer: after an unfollowed reset the patterns keep their own count while the LFOs, loops and quantized actions follow the clock's bars (ruling 47); a clocked engine LFO keeps running while an external MIDI clock is stopped (#6); MAIN's `~` lights for a routing to a param the script plays. If wrong: each is a small change of its own. (`gestures.data`, written only at cleanup as design §7.4 had it, was among these; it is written 0.1 s after a recording, an overdub, a clear, a quantize change or a PSET load since #651.)

PSETs, data files and MIDI:
- **The MIDI map repair touches only 3.3's own LFO ids** that 3.4 lacks (ruling 89, #602): each moves where 3.4 has a param of the same meaning and is removed otherwise; a map on any other id that is not a param is left as it is, and nothing is written when nothing was repaired. *Departs from the design (which has no repair); to confirm.* If wrong: a stale id of another origin still makes norns raise on its CC, as before (the MIDI page says how to clear it).
- **The data file reader's table cap is 32768** (8192 before; ruling 90), four times the largest scenes file 3.4 can write (7394 tables), since a refused scenes file is every scene unloaded. *Departs from the design; to confirm.* If wrong: a damaged or hostile file four times larger is parsed before it is refused.

How it was built (calls about process, not behavior):
