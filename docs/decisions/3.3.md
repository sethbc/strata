# 3.3 decisions (buffers as instruments, and the review fixes)

The other releases: [README](README.md).

The design's questions (all decided), its calls and its "Cost if wrong" list are in `docs/design/3.3-design.md`. Its main decisions, each with what it costs if wrong:
- **The high floor is 3.5 MB** (Question 1; 4 MB before), the standard floor stays 3 MB, with an all-buffer worst case and recordings added to the check. If wrong (4 MB must stay): 3.3 and 3.4 together need about 230-370 KB back on high (the design's estimate; the measured margins are in `docs/notes/engine/memory.md`); the levers, largest first, are a lowpass-only voice filter on high (about 88 KB), sharing the head guard's arithmetic with `slotGrainPos`'s clips, dropping the pre-roll (4 KB a recording) and a cheaper 3.4, and even all of them leave the all-buffer case short.
- **Recordings with feedback or loop are playable** (Question 5): the slot keeps playing and grains avoid the head. If wrong (overdub should silence the slot): one branch in `recordSlot`, and the guard goes unused.
- **Recordings start at frame 0** (Question 6). If wrong: recording into a voice's loop needs a ninth `recordBuffer` argument (the start frame) and the guard's modulo over the region.
- **Clock sync through a `delay` argument and a timed bundle** (Question 8). If wrong (timed bundles drift against Link): Lua sends at `clock.sync` with `delay` 0 and accepts the preparation's lateness on replace takes.
- **Synced takes prepare late** (Question 4, `recordPrepMargin` 0.15 s). If wrong (the margin is short on a busy Pi): the take starts late and posts so; one constant.
- **5 ms fades on every recording** (Question 10). If wrong (a replace take must be bit-identical to 3.2's): `recordFadeSeconds` 0 for takes, making the fade a playable-only feature.
- **A slot at another sample rate becomes a replace take** (Question 3). If wrong (overdubbing a 44.1 kHz file in place matters): resample on load in a later release, an sclang pass with #131's allocation risk.
- **Bookmarks are positions only** (Question 12). If wrong (3.4 needs loops in bookmarks): hidden `bookmark_<n>_start`/`_length` params set by `recall_bookmark`; the interface keeps its names.
- **Bookmarks crossfade in scenes** (Question 2). If wrong (a mid-transition recall should land on the old or new value): a `held` set of keys switched at a transition's end; if a recall replacing them surprises, drop them from the scene defaults (they stay in PSETs).
- **The peaks file sits in Strata's data folder** (Question 14). If wrong: one method (`peaksPath`) and one Lua function.
- **Grid position pages per layout** (Questions 15-16). If wrong: each layout's file alone; the 8×16's columns can become one voice at a time.
- **ALT+ring 1 holds the scan, released with K1** (Question 19). If wrong (it should engage on K1 alone): `hold_scan` moves to BUFFER's ALT press.
- **BUFFER's K2, ALT+K2 and ALT+K3 act on release, by hold length** (Question 20). If wrong (release feels slow for clear and save): the holds move to grid-only or to fields with K3, and clear and save go back to presses.
- **A re-gated buffer voice restarts its scan** (Question 24). If wrong (carrying on mid-scan was wanted): the engine stops sending the reset and Lua's estimate restarts from a stored phase.
- **One persistent mix stage per voice** (the amendment, Questions A1-A4). If wrong: a per-synth fade heard through a low, resonant filter is fixed in `\strataVoiceMix` alone (give it the voice's ASR); the second path, if not worth 7 KB a voice, can go at the cost of exactness in synth-to-other crossfades; if the stages' idle CPU matters on a CM3, a stage whose voice holds no grain synth is paused (`/n_run 0`); a filter per note in 3.5 is a third path per note, not a return to filters in grain synths.

The calls made while building it:

A PSET load or scene recall that lowers the mix counts as a fall, so K3 restores the older, higher value; no load hook special-cases it. If wrong: after 80% is turned down to 30% and later to 0, K3 restores 80%, and after loading a PSET with a lower mix, turning the mix to 0 and pressing K3 brings back the mix from before the load; one rule in `lib/params_setup.lua`.

- **Fade cue:** the fading target blinks, one change per fade step, on the header's scene mark, SCENES' slot and the grids' recall keys. If wrong: one function, `S.lib.scenes.shows_current`.
- **BUFFER hold hint:** while K2, ALT+K2 or ALT+K3 is down the hint row names what its release will do and changes at 0.5 s, drawn by the frame clock. If wrong: one function in the page's hints.
- **Layout gaps:** the 16×8 shows the scene sequencer's light at 10, as the 16×16 and 8×16 do (since #303, on the scene it recalls next); the 8×16 gets lock keys on its faders page, column 7 rows 10-16. If wrong: one constant each.

### 3.3.1 (the fix release)

- **#565's encoding: the send time modulo 1000 s.** `recordBuffer`'s ninth argument, `sent`, is Lua's wall clock modulo 1000 s (`util.time() % 1000`); the engine takes the difference from its own clock modulo 1000, wrapped into [0, 1000), as the message's wait and starts the take at `now - wait + delay`. An absolute time does not fit a float32 OSC argument (an epoch time of about 1.8e9 s keeps only about 128 s of resolution; 1000 s keeps about 61 microseconds). A negative `sent` means unknown, and a wait over 10 s is treated as unknown. If wrong: a take's start is off by the clock's disagreement between matron and sclang, or by the wait when both disagree by a multiple of 1000 s.
- **#567's tempo source: the tempo the clock will run at.** Take lengths and sync delays read the `clock_tempo` param on the internal clock and `clock.get_tempo()` on Link, MIDI and crow, since the param's action sets the internal clock at once and `clock.get_tempo()` lags up to two ticks, but on MIDI and crow the param only follows norns' external-tempo poll, and on Link the param lags a session tempo that is fractional (reading it would drift every loop). The 256 grid's tempo flash keeps the param on internal and Link, since it shows the tempo the key set. If wrong: on Link, a take started within about 20 ms (one or two 10 ms Link steps) of a local tempo change uses the old tempo.
- **#566's delay: 0.1 s.** A changed `buffers.data` is written 0.1 s after the first change of a burst that asked for it, as one write carrying the newest state (later changes inside the 0.1 s do not push it back), and cleanup's existing save writes it at exit and cancels the pending write's clock. If wrong: a crash within 0.1 s of a load or clear loses that change's path, which the next start finds as an empty slot.
- **Engine-check default timeout:** raised to 1800 s after 3.3.0 (#570); a full local run takes about 16 minutes. If wrong: a hung local run holds the machine 10 minutes longer.

### 3.3.2 (page randomize)

- **ALT+K2 randomizes on every page of parameters, with its undo on the same key.** Where ALT+K2 did something else, that action moved. If wrong: a player who knew the old keys presses the wrong one until the new ones are learned.
- **SEQ swaps its keys:** ALT+K2 randomizes the pattern, ALT+K3 clears it. If wrong: a clear where a randomize was meant (the undo brings the pattern back only for a randomize).
- **VOICE, FX and LFO randomize the section under the cursor,** not the whole page; MAIN keeps its whole-voice randomize. If wrong: a press changes less than a player expected and needs several presses.
- **Registered per-voice params (variation, voice filter and sends, history, bookmarks, loop regions) are randomized on a press of their own section only;** MAIN's randomize, the mutations and the fader pages still never touch them. If wrong: a section a player did not mean to disturb changes on a press while the cursor sits on it.
- **On SEQ, page randomize wins over 3.4's Question 12:** ALT+K2 randomizes there, and 3.4's step edit view opens on ALT+K2 held. If wrong: 3.4 moves the step view's key again.
- **It ships now, before 3.4,** on today's pages; 3.4's LFO package re-applies the LFO randomize to its rebuilt page, and its MOD page, with its sub-views as well as its rows, follows the same rule (its "clear the rows" moves to its hold; 3.4's plan settles which new fields are randomized). If wrong: 3.4's pages are rebuilt twice over.
- **BUFFER, SCENES and SETUP keep their keys** (proposal A): BUFFER's randomize is K2 held and its ALT+K2 is clear or fill. If wrong: the gesture is not the same on every page.
- **Reset to default moves to ALT+K2 held on VOICE and LFO** (proposal B), since ALT+K3 is taken on both. If wrong: a reset is slower to reach.
- **Every randomizing page acts on release** (proposal C), so a quick press randomizes about a fraction of a second after the press. If wrong: the gesture feels late on MAIN, which acted on press before.
- **One shared undo** for whichever page randomized last (proposal D), valid within 5 s on the same page, section and voice. If wrong: a second page's randomize costs the first one's undo.
- **A held ALT+K2 on a page with no hold action shows `K2:cancel`,** and letting go does nothing: the hint names what letting go will do. If wrong: one hint word.
- **The buffer voice's synth section has its own undo key ("synth (buffer)")** and the LFO's key names the LFO and its mode, so `K2:undo` is never offered over rows or params it would not change. If wrong: an undo is lost across a synth to buffer switch or a mode switch on that section.
- **A mutation of the undo's voice still ends its undo,** as designed, though a mutation that changes none of the undo's params could leave it. If wrong: with mutation on, a second ALT+K2 sometimes randomizes again instead of undoing.
- **It lands after 3.3.1,** as 3.3.2, so the fix release carries no new feature. If wrong: none; only the version it ships in.
