# 3.5 decisions (polyphony and MPE)

The other releases: [README](README.md).

The design's twelve questions, its calls and its approaches are in `docs/design/3.5-design.md`, with the lines the build changed marked *amended 2026-11-13, as built*. What follows was decided while it was built: by the maintainer, and as rulings while the packages were built, reviewed and landed. A ruling keeps the number the build gave it (`ruling 47`), which code comments and notes cite; where a later ruling changed an earlier one, both say so.

Decided by the maintainer:
- **The design's twelve questions** (2026-11-12), each asked with its alternatives: all as recommended (per-note controls on the note's own synth and one fast-modulation block per voice; a pool of 16, defaulting to 8 on high and 4 on standard; the largest value for a voice-wide target; relative slide; polyphony on from the first start; attack and release params; the own note parks; MIDI notes pitch an input voice; zone and range with learn; sixteen read-only sources; `amp` and `level` both), except Question 8: a frozen synth voice plays its notes as streams of its frozen ring, where the design recommended refusing them. If wrong: each question's cost is in the design; Question 8's is a second kind of note on a synth voice, started at a freeze and cut at an unfreeze, which the engine check covers.
- **README.md no longer summarizes releases** (2026-11-13, outside the plan, PR #675): it gives the version and points at CHANGELOG.md, and a release changes only that number there. If wrong: a summary written again by hand.
- **#211 is fixed before the release** (2026-11-13), as ruling 50 records.

The pool and the engine's memory:
- **The pool's maximum stays 16** (ruling 11, from package 0b's arithmetic: about 1443 KB free on high and 2225 KB on standard with the pool full, above the 1280 KB floor; confirmed by ruling 42). If wrong: the maximum drops to 12, one literal on each side and the docs test.
- **Measured, the pool of 16 holds** (ruling 42, confirming ruling 11): the memory area's two pool cases leave 2070 KB at the tightest on high in CI's shard on SuperCollider 3.13 and 1960 KB in a full run on 3.14.1, against the 1280 KB floor. The controller's sum before them (about 1390 KB) charged every pool slot a live and a cutting synth of the costliest kind on top of the tightest case. If wrong: a worst state the cases do not reach (seven Karplus notes cutting at once, about 56 KB more), which still leaves about 1900-2025 KB on high.
- **Each voice def's memory limit is its size with the note controls plus 2 KB,** rounded up to a whole KB (ruling 22: Resonator 24, FM 22, Folder 18, Sub 17, Pulse 19, Karplus 83, Ring 20), since the plan's "Wave 0 size + 4 KB" left 0.6 KB, under one probe step. If wrong: a limit a later package raises, with its reason.
- **One method gives every voice def its expression control** (ruling 5, `noteMainValue`): the check proves the method through a probe def and each def's use of it by its control list and graph, since a def with random UGens cannot be compared by its audio. If wrong: a def that ignores `noteMain` passes the check; a reviewer reads each def's line.
- **The constants' comment says `FAST_MOD_NOTE_SLOTS` stays 1** (ruling 4): per-note values are controls on the note's own synth (Question 1). If wrong: a comment.

Slot 1, the voice's own note (`lib/notes.lua`):
- **Slot 1's order is `set_own`, then the start, then the accent** (ruling 6), as MIDI played in 3.4: the plan's order would start a voice at its old pitch and re-pitch it a message later. The note record's `quiet` lets a caller start and accent the voice itself (the sequencer keeps its own order). If wrong: a caller finds `quiet` insufficient; none has.
- **A parked own note is unparked with `noteOn` on slot 0, then accented with `retrigger`** (ruling 15, changing design §2.2's branch 2; its engine side changed by ruling 47), never `noteOn` in place of the `retrigger`: the stage's step gate and accent open only on `retrigger`, so a gated voice's unparked note would stay silent. A quiet play over a parked note sends the `noteOn` alone, and its caller accents. If wrong: the own synth accented twice in a block, which ruling 47 found and removed in the engine.
- **A frozen synth voice's slot 1 always gets the slot-0 `noteOn`** (ruling 18), quiet or not, since it alone carries the rate; slot 1 is one rule: after `set_own`, the slot-0 `noteOn` when the own note was parked or the voice is a frozen synth voice, then `retrigger` unless quiet. If wrong: one redundant message per such play.
- **On a stopped voice slot 1 is always free** (ruling 19, replacing ruling 16's refusal): any play there takes it, replacing a quiet record its caller never started, and no play is refused for a stopped voice. Ruling 16 had refused an extra slot on a stopped voice, which could strand a voice behind a record nobody clears. If wrong: none known.
- **A running voice with no held note never keeps its own note parked** (ruling 39, an allocator invariant): a release, a steal or a freeze's cuts that leave a voice noteless under its parked own note unpark it (`noteOn` on slot 0 at velocity 0, after a neutral `noteExpression` when the engine's is not neutral), so the voice sounds on as its drone, nobody's note. A parked, silent, noteless voice was the root of two review findings, and stopping it would be wrong whenever another owner or the player's drone is on it. If wrong: a voice returns to its drone where a player expected silence; one rule.
- **A player's reset forgets, never parks** (ruling 40, `forget_owner`): the owner's extra notes are released and its own note dropped with nothing sent; MIDI's reset under latch uses it, and in release mode the last key's note off stops the voice without releasing through the allocator first. If wrong: none known.
- **The free-slot test runs at cap 4, slot 1's `noteExpression` goes only when it differs from the engine's, and a re-pitched note keeps its start time** (ruling 17): the first two follow design §2.2 and keep neutral notes at 3.4's exact messages; the third keeps the cutting bound. If wrong: none known.
- **A frozen synth voice's scale note is its freeze reference** (ruling 7, `S.lib.variation.scale_note`), whatever freq a resend passes, so no path moves it. If wrong: quantized notes on a frozen synth voice snap from the wrong note.
- **A slot's stored expression is readable** (ruling 36, `S.lib.notes.expression(voice, slot)`), and the expression module seeds a new record (and a latch's) from it, so a module never drops a note's first value when its caller's order drifts. If wrong: none known.

The sequencer's chords:
- **A step's first note is played quiet** inside `apply_step` (ruling 13): the override is set as before, the sequencer keeps its start and `retrigger`, and the further notes are played once the voice runs; a ratchet's later hit replays only the further notes, which the `retrigger` already accents. If wrong: a double accent on a chord's first note.
- **A chord past the cap or the pool keeps its first notes** (ruling 26, changing design §4, which kept the first and the last three): a `fallback` field refused what would re-pitch the own note. Replaced by ruling 32, which kept its decision.
- **A chord's further notes take only free room** (ruling 32, replacing ruling 26's `fallback`): the note record's `extra_only` takes only branch 1 (already held) or branch 3 (a free extra slot with room in the pool), never slot 1, never a steal, and is otherwise refused. A sequenced chord so keeps its first notes at every step, never cuts a held MIDI note, and a MIDI note may take a sequenced one's place: both of the review's findings came from further notes reaching branches meant for a player's own note. If wrong: a sequenced chord cannot take a note back from an older MIDI note; one field.
- **A step never takes anything from another owner** (ruling 35, completing ruling 32): when another owner holds the voice's slot 1, the step's first note is played `extra_only` too. The promise that the sequencer never cuts a note you hold is true rather than weakened, and 3.4's quirk of a step's override hiding a held MIDI note goes. If wrong: a step's note no longer re-pitches a voice MIDI holds, as 3.4's did; one condition.
- **A chord's further notes are measured from the base its first note's override uses in that step** (ruling 27), an input voice's pitch lock included, so a chord never splits from its first note. If wrong: none known.
- **On a running frozen synth voice a step with a note sends the slot-0 `noteOn` at each first hit** (ruling 33, the allocator's rule); "3.4's messages exactly" binds a step without notes and a one-note step on any other voice. With MIDI holding slot 1, the first note's `noteExpression` and `noteOn` inside `apply_step` stand as built. If wrong: one redundant message per such step.

MIDI, MPE and expression:
- **The MPE modes' names were added before MIDI played them** (ruling 8, reversing the plan's ruling 9, which kept them out until the MIDI package): the MPE package's tests and SETUP needed modes 3 and 4, which played as per voice until the MIDI package landed. If wrong: `main` between two landings offered two modes that did nothing new; no release shipped from there.
- **A layout change has a hook** (ruling 14, `S.lib.mpe.on_layout_change`): it runs after any change of a member count or a voice's zone, so MIDI releases what it holds (design §5.4). If wrong: none; an unused hook.
- **A latched note keeps the highest pressure it reached and its slide** (ruling 12, `S.lib.expression.latch`), later updates change nothing, and the module forgets a note the allocator no longer holds at its step. If wrong: a latched chord's swell falls away as fingers lift.
- **A new touch forgets the old one** (ruling 30, `S.lib.expression.forget`), which MIDI calls at every note on before its first update, so a re-pressed latched key takes pressure again. If wrong: none known.
- **A latch on a note that never had an update keeps the sound it has** (ruling 38): its record is seeded from what the allocator holds and only blocks later updates. If wrong: none known.
- **A voice-wide target follows the note whose mapped value is furthest from 0** (ruling 31, Question 3's "largest" read as strongest), so with a negative depth the hardest-pressed note still wins. If wrong: one comparison.
- **Slide on `level` acts as on `amp`** (ruling 34, changing design §6.2 for slide): `1 + depth × slide`; level's own formula is pressure's, since a relative slide is 0 at every touch's start and cannot be a loudness. If wrong: a player who wants slide as an absolute level; one more field passed to `note_values`.
- **A change of `midi_note_off` releases every MIDI note,** as a channel mode change does (ruling 37), so no chord is carried from one note-off behavior into the other. If wrong: a player who flips it mid-chord loses the chord; documented.

The UI and scenes:
- **The zones editor names notes as norns does** (ruling 28, changing design §9.3's mock): 60 is C3, so 0 is C-2 and 127 G8; the test stub gained `musicutil.note_num_to_name`, mirroring norns'. If wrong: one formatter.
- **A current-version scene lacking a voice's `attack` or `release` gets voice 1's times** (ruling 29): documented, not closed (closing it needs per-voice scene defaults no package owned), and the expression and envelope packages landed together, so `main` never wrote a version-7 scene without the keys. If wrong: a hand-edited scene missing a key plays voices 2-7 with a 4 s attack; the fix is a per-voice default in the record's shape.

The engine's notes:
- **Engine restarts are silent** (ruling 45): notes the engine restarts itself (a source switch, an unfreeze) start with no accent and no trigger, so a switch under a held chord does not strike it again. If wrong: a Karplus note restarted with no pluck waits for its free-running exciter (0.1-2 Hz); then restarts of Karplus notes alone would fire the pluck.
- **`noteOn`'s `note` is kept and not used yet** (ruling 46): the scale note comes from the voice's reference and the note's rate, the same today; 3.8's tunings will need the note apart from its rate. If wrong: an argument the engine ignores.
- **The slot-0 `noteOn` fires no accent and no trigger on an unfrozen voice** (ruling 47, changing ruling 15's engine side and design §3.4's slot 0): `retrigger` alone accents and plucks, once. On a frozen synth voice it sets the own grain synth's `noteRate` and fires that synth's `t_accent` at the velocity. The pair `noteOn` and `retrigger` had plucked Karplus twice and accented a buffer voice's own note twice. If wrong: none known.
- **The park follows the own voice synth through a freeze** (ruling 44, refined by rulings 48 and 49): on a synth voice the own voice synth's `noteGate` always follows the park, frozen or not, and while frozen the own grain synth's follows it too; at the unfreeze the grain synth's returns to 1. A note parked during a freeze otherwise sounded and faded over the voice's release at the unfreeze. If wrong: none known.
- **The tail at an unfreeze under an own note parked during the freeze is accepted** (ruling 48, refining ruling 44; its bound replaced by ruling 49): the grains already started keep playing the frozen ring while the own grain synth's park rises, and delaying the park would cut a hole of a grain's length in a held chord.
- **That tail is the voice's ordinary ring tail, displaced to the unfreeze** (ruling 49, replacing ruling 48's bound and keeping its decision): the unfreeze resumes the ring writer where it paused, so for the reader's lookback grains replay the audio from just before the freeze, the lifted note's included: at most `ringReadMargin` + `posSpread` × `ringSpreadSeconds` + the grain size (about 0.3 s at the defaults, about 1 s at the extremes), at up to the level the voice played before the freeze. The check bounds it in time on the heard path and proves the note does not return. Silencing or skipping the stale region would cut the held chord for the same span at every unfreeze and change 3.2's unfreeze, which has always resumed this way. If wrong: the lifted note is heard for up to a second at an unfreeze; the remedy is a fresh grain synth at the unfreeze reading from the resumed head, the old one cut. A listening item for the hardware check (#6).
- **#211 is fixed in the product before the release** (ruling 50): sclang 3.13.0 and 3.14.1 free a block's frame while a method frame a kept closure holds still points at it, and the collector can then corrupt the heap; every area hook, `strataAreas`, the two grain readers, the record area's `onFree` and the freeze area's `inputHeadFrame` go through one method frame (`areaCall` in `StrataUtil.sc`), with a structure test on the hook lines and one rule in AGENTS.md. The cause is in the product as well as the check (a long load or save on a high-tier norns could corrupt sclang the same way), the experiment's counts were decisive and the change is mechanical. If wrong: one more method frame per hook call and a rule to keep; the 300 s check stays as the detector.

How it was built (calls about process, not behavior):
- **0a and 0b added the same two constant lines,** verbatim, so each branch passed its own checks (ruling 1). If wrong: a cherry-pick conflict on two lines; it came, and one copy was kept.
- **`count_sends`' test sits at the budget's edge** (ruling 2: 149 counted, then one deferrable send goes and the next waits), since the plan's "send of 20 messages" does not exist. If wrong: none.
- **The notes cleanup step came with something to clean up** (ruling 9, replacing ruling 3, which had 0a add `CLEANUP_ORDER.notes` only if the structure test allowed a step with no effect): the test demands an observable effect, so the allocator package added the order (119) with the flush's end. If wrong: none.
- **Small fix diffs read by the controller with no re-review** (rulings 10 and 23: a moved comment block, two notes lines and one assertion), and a duplicated notes sentence carried to the file's next owner instead of a fifth fix round (ruling 21). If wrong: a docs line or comment read once, which the release's docs pass reads again.
- **A fourth fix round resumed the same worker** (ruling 20): each round had fixed everything it was given, the new finding was in the previous round's own diff, and no tier above opus may be dispatched. If wrong: a fifth round with a fresh worker.
- **Wave 2 ran in two steps** (ruling 24): MIDI was built stacked on the expression package's branch, since every MIDI note calls its functions, while the SETUP package used a test double of MIDI's note tap. If wrong: MIDI lands a batch later; nothing else waited on it but the release.
- **The runner's #671 and #673 got a package of their own beside Wave 2** (ruling 25): the local full run in CI's shards, each in a fresh sclang, and a stop test that waits for the process. If wrong: none.
- **Two of MIDI's commits were squashed at landing** (ruling 41), since the first alone failed two tests the second updates, and `main` keeps no red commit. If wrong: one commit where the branch had two.
- **A Lua-only batch ran a third CI attempt** that failed only on #211's check (ruling 43), where `docs/workflow.md` counts a batch red after one rerun. If wrong: a real regression hidden behind a known flake, which the third attempt and `main`'s own run would show.

Left as built (the reviews' deferred minors, none a defect):
- An unconfirmed pool start is forgotten after 0.5 s pool-wide (#497's trade-off): a start slower than that is freed while Lua still counts the note held, until the slot's next note.
- The notes check's park-through-freeze case leaves a few grain settings changed on its voice (later checks use other voices and resend), and a failure in its middle leaks its two probe buses.
- The engine check runner: a TERM that reaches a shard before it sets its trap leaks that shard's work folder; `child_pids` falls back to `pgrep -P` without `ps`; a test's stand-in waits for its PID file with no bound; and the 3.13 runner's summary counts collector lines only, so a run its own line flags as #211 can read `collector failure 0`.
