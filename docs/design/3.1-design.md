# Strata 3.1: playable from the norns alone

Date: 2026-11-07
Status: approved 2026-11-07.
Builds on: Strata 3.0.2 and `docs/design/3.1-3.6-roadmap.md` (3.1 section), which this document refines and supersedes for 3.1.

## Intent

Without a grid, Strata can't stop a voice, save or recall a scene, or edit a pattern, and several screen controls are hard to use. The 128h, 128v and 64 grids miss whole features the 256 has. 3.1 makes every action reachable from the norns' three keys and three encoders, with grid and arc as faster ways to do the same things. It also splits `strata.lua` into modules first, because the later releases (3.2-3.6) can't fit in a main chunk that already uses 184 of Lua's 200 locals.

No engine change. No sound change.

A second aim (added 2026-11-07): the code and the documents are restructured however is most efficient for agent-driven development, and the work is planned to run as parallel as possible, in 3.1 and in every later release. Several agents working in separate git worktrees should be able to build different features at once without editing the same files.

## Goals

0. The repository restructured for parallel, agent-driven work: features in their own files, registries instead of central lists, tests and notes split per module, changelog fragments, and checks that can run side by side (Design §0).
1. `strata.lua` split into modules under `lib/`, in a pull request that changes no behavior and keeps every test passing.
2. A shift layer on K1 (held), fine adjustment on E3, and center detents.
3. Starting and stopping voices from the norns and the arc.
4. "Freeze" renamed "lock"; "freeze" kept free for 3.2's audio freeze.
5. One level of undo for randomize.
6. Eight pages (MAIN, VOICE, SEQ, FX, LFO, BUFFER, SCENES, SETUP) with a field cursor, a new header, and every param reachable. SEQ edits the patterns and runs the sequencer without a grid.
7. The 128h, 128v and 64 grids reach every feature the 256 has, as far as their size allows: faders, sources, buffers and scenes on 128h and 128v; all seven voices and both pattern halves on the 64 (its 64 keys hold no more).
8. Arc: center fill for values that go below zero, rings on the new pages, and the button on every page.

## Non-goals

- Anything in 3.2 or later: freeze, the performance setting, waveforms, macros, morph, 16 scenes, scene names, polyphony.
- New params that change the sound. 3.1 adds UI state only. The single exception is the LFO default depth (Design §5, LFO).
- Supporting grids of other sizes (the four exact sizes stay).

## Anti-goals

- Breaking muscle memory without need. On MAIN, K3 still starts a voice (and now also stops it). Randomize moves from K2 to ALT+K2 on purpose, because a single press next to K3 wiped sounds (the UI review); K2 becomes "next field". Lock moves to ALT+K3. The 256's existing rows keep their meaning.
- Making old scenes or PSETs unloadable. 3.1 adds no scene fields, so `SCENE_DATA_VERSION` stays 2.
- Any grid or arc change that a test can't check.

## Constraints

- Everything in CLAUDE.md applies. In particular:
  - redraws only through `request_redraw()`;
  - grid and arc handlers on vports only;
  - `send_param_to_engine` for every engine-bound value;
  - the screen tests: no overlap, nothing off-screen, the hint row, and the MAIN divider.
- norns delivers K1 to the script only once it has been held for `KEY1_HOLD_TIME` (0.25 s, `lua/core/menu.lua`). A shorter press opens the norns menu. So K1 can be a hold-to-shift key, never a tap key.
- norns' `include(file)` is a `dofile` (`lua/core/startup.lua`): every call runs the file again and returns a new value. A module included twice is two copies with separate state.
- norns' `include` looks in the script's own folder (`norns.state.path`) first, then `_path.code` (`lua/core/startup.lua:52-58`). `include("lib/<name>")` therefore works whatever the install folder is called; `include("strata/lib/<name>")` only if it is `strata`.
- The test harness reaches script locals through `find_upvalue()`/`local_value()` (49 distinct names), and some tests write them through `find_upvalue`'s setter. Five tests read `strata.lua`'s source (`test/run.lua` lines 256, 404, 514, 3615, 4066), and two load patched copies of it (517, 3620).
- `test/sync_check.lua` scans `strata.lua` only. The docs check reads CLAUDE.md, README.md, `docs/status.md` and `docs/notes/*.md` (not Lua), and its path check covers only paths under docs/, test/ and .github/.
- norns' param `delta` can't make steps finer than a param's own resolution: a control param's value is rounded to its `controlspec.step`, a number param adds `d` unrounded (a fraction breaks integer params), and an option param rounds up to a whole step (`lua/core/params/{control,number,option}.lua`, `controlspec.lua:111-113`).

## Approaches

### Module split

- **A. Modules that each return a table (chosen).** Each feature moves to `lib/<name>.lua`. `strata.lua` includes each module exactly once and wires them through a shared context table. Locals stop running out for good, and later releases add modules instead of growing one file. Costs: an `include` stub in the harness, the tests' local lookups redirected to the context table, and the sync and docs checks taught to scan every Lua file.
- **B. One file, with features grouped into global tables.** Less churn and the tests barely change, but the file keeps growing (about 8000 lines by 3.6) and the local limit comes back with each release.
- **C. Split only what 3.1 adds.** Quick, but it leaves two styles side by side and puts the same question to every later release.

A was chosen (2026-11-07).

### Shift key

- **K1 held as ALT (chosen).** Works on every page and is the norns convention many scripts use. Cost: the 0.25 s wait before ALT engages, and a K1 tap opens the menu.
- **K2 held as ALT on pages where K2 does nothing on press.** No wait, but it doesn't work on MAIN or BUFFER, where K2 acts, so it can't be one rule.
- **Long presses of K2/K3 instead of a shift.** No chord, but every long-press action waits on a timer and gives no feedback until it fires.

K1 is the shift. If it feels wrong on hardware, long presses are the fallback; the key map in Design §2 lists a long-press equivalent for every ALT action so the change is contained.

## Design

### 0. Built for parallel, agent-driven work

The rule behind every choice below: **a feature should live in files that only that feature's work edits.** Two agents building two features should touch disjoint files, apart from one-line registrations.

**Where parallel work collides today** (each is a file every feature edits):
- `strata.lua` (5063 lines): `init()` adds every param, and the `PAGE_*` and `ARC_PAGE_*` tables, `cleanup()` and the grid dispatch list every feature.
- `test/run.lua` (6769 lines, 206 tests in one file).
- `docs/notes/lua.md` (780 lines of dense paragraphs) and `docs/notes/engine.md`.
- CHANGELOG.md, `docs/status.md`, README.md and CLAUDE.md, edited by every pull request.
- The engine check, which can't run twice on one machine (scsynth's fixed UDP port 57110).
- `main`'s branch rule (pull requests must be up to date with `main`): every merge forces every other open pull request to rebase and rerun CI, up to 10 minutes each.

**Changes:**

1. **Registries instead of central lists.** `S` holds registries that modules add to at load:
   - `S.registry.pages`: the page's draw/enc/key/key-release/ALT/arc functions, in one record per page;
   - `S.registry.params`: a module's param-adding function, run by `init` in a fixed order;
   - `S.registry.cleanup`: a module's cleanup function;
   - `S.registry.grid_pages`: per layout, the page records;
   - `S.registry.scene_fields`: for 3.2 onwards, each captured field with its validator and migration default.

   Page order stays in one list (`UI_PAGES` in `lib/constants.lua`), so it's still one line to edit. Adding a page means a new file plus one line there and one `include` in `strata.lua`.
2. **One file per page, layout and ring set.** `lib/pages/<name>.lua` (main, voice, fx, lfo, buffer, scenes, setup), `lib/grid/<layout>.lua` (layout_256, layout_128h, layout_128v, layout_64), `lib/arc/<page>.lua`. Shared helpers in `lib/ui/` (header, hints, field list, ALT state, detents, flash) and `lib/grid/core.lua` (devices, holds, dispatch, faders).
3. **Tests per module.** `test/run.lua` becomes a runner that loads `test/unit/<module>_test.lua` files (one per module, matching the module table). `lua test/run.lua scenes` runs one file; `lua test/run.lua` runs all, as CI does. Shared helpers (`load_strata`, `local_value`, `next_frame`, ...) move to `test/helpers.lua`. An agent changing one module runs its file in seconds and the whole suite before pushing.
4. **Notes per module.** `docs/notes/lua.md` and `docs/notes/engine.md` become one short file per module, named like the code (`docs/notes/lua/scenes.md`, `docs/notes/lua/pages.md`, ...; `docs/notes/engine/*.md` follows the engine split in 3.2). Each file opens with a short "what you must not break" list for that module, so an agent reads one file, not 780 lines. Paragraphs become short lists. The docs check extends to the new paths.
5. **CLAUDE.md as an index.** It keeps the rules every change needs (sync, invariants that cross modules, the command table, how to run checks) and a table of "module → its notes file → its test file". Module-specific detail moves to the notes. It gains a "Working in parallel" section: one worktree per pull request, which files a feature may edit, how to register a page or param, and what to do on a conflict in a registration line.
6. **Changelog fragments.** Each pull request adds `changes/<pr-or-branch>.md` (one or two lines under Added/Changed/Fixed) instead of editing CHANGELOG.md. A release pull request merges the fragments into CHANGELOG.md and deletes them. `docs/status.md` likewise: decisions go in the release's design doc or in fragments, and status.md is updated only at a release or by the pull request that closes an open item.
7. **Parallel engine checks.** `test/run_engine_check.sh` takes the scsynth port from `$STRATA_SC_PORT` (default 57110) and `test/engine_check.scd` reads it, so checks in different worktrees can run at once on different ports. (Harmless in 3.1, which changes no engine code; needed from 3.2.)
8. **Merging without a rebase storm.** Recommend turning on GitHub's merge queue for `main`: pull requests join a queue and CI runs on the combined result, instead of each author rebasing after every merge. This is a repository setting, outside the code; the README's development section explains it once it is on. If it stays off, the pull request waves below still work, with rebases.
9. **Design docs carry work packages.** From 3.1 on, each release's design ends with work packages: for each pull request, the files it owns, the interfaces it depends on (by name), its tests, and which packages can run at the same time. §9 does this for 3.1.
10. **User docs split.** README.md becomes a short overview, quick start and index; user documentation moves to one page per area under `docs/user/` (added 2026-11-07). Work packages edit the page for their area (`docs/user/controls.md`, `docs/user/grid.md`, `docs/user/arc.md`, ...) instead of README.md, and the docs check covers `docs/user/`.

### 1. Module split (its own pull request, first)

**Layout.** `strata.lua` keeps the norns entry points (`init`, `redraw`, `key`, `enc`, `cleanup`) and the wiring. Modules in `lib/`:

| Module | Holds |
|---|---|
| `lib/constants.lua` | the Constants block (`NUM_VOICES` ...), option tables (`GRAIN_ENV_OPTIONS`, `SOURCE_OPTIONS` ...), `GRAIN_PARAM_IDS`, `DISCRETE_GRAIN_KEYS` |
| `lib/state.lua` | the mutable shared state now in script locals: `voices`, `frozen` (the code name stays; only the UI says lock, §3), `patterns`, `scenes`, `buffers`, `selected_voice`, `ui_page`, `current_scene`, ... Returns a fresh table each time it is loaded |
| `lib/engine_sync.lua` | `send_param_to_engine`, `engine_senders`, `engine_param_values`, `sync_voice_to_engine`, `toggle_voice` |
| `lib/params_setup.lua` | `add_voice_params`, `get_param_spec`, the param definitions from `init` |
| `lib/lfos.lua` | LFO destinations, actions, phase estimate |
| `lib/mutation.lua` | drift, randomize, `gentle_mutate` |
| `lib/scenes.lua` | capture, recall, transitions, sequencer, migration, validation, persistence |
| `lib/buffers.lua` | buffer state, record/load/clear/save, polls, persistence |
| `lib/midi_in.lua` | MIDI input |
| `lib/ui_pages.lua` | header, hints, frame clock, `PAGE_*` tables, page draw/enc/key functions |
| `lib/grid_ui.lua` | grid layouts, keys, redraws, pattern sequencer |
| `lib/arc_ui.lua` | arc pages, rings, device following |

`lib/ui_pages.lua`, `lib/grid_ui.lua` and `lib/arc_ui.lua` above are then split further by page and layout, as §0 item 2 describes (`lib/pages/`, `lib/grid/`, `lib/arc/`, `lib/ui/`).

The table is a starting point. The builder may merge or split modules, but no module's main chunk may come within 30 locals of the limit (the probe described in CLAUDE.md, run per file).

**Loading.** Each module file returns a constructor: `return function(S) ... return M end`. `strata.lua` runs:

```lua
local S = include("lib/state")          -- shared state and the registries
S.constants = include("lib/constants")
S.engine_sync = include("lib/engine_sync")(S)
...                                     -- every module, once, in this file only
```

Modules reach each other through `S` at call time (`S.scenes.recall(...)`), never by including each other, so load order matters only for code that runs at load. `include("lib/<name>")` resolves in the script's own folder whatever it is called (Constraints). A test asserts that no file except `strata.lua` calls `include`.

**What "a pure move" means for review.** The split is accepted as a move when:
- code moves into modules unchanged, except for the mechanical rewrites below;
- **shared state:** every script-level variable used by more than one module becomes a field of `S`, and each use is rewritten `x` → `S.x` (scalars such as `selected_voice`, `ui_page`, `current_scene` and `grid_page` included);
- **private state and helpers:** a local used by one module only stays local to that module;
- **cross-module helpers:** a local function used by several modules (`select_voice_by`, `fit_text`, `update_voice_list`, the page handlers, ...) becomes a field of its module (`S.ui.fit_text`); functions that are global today stay global, defined inside their modules (for example `function toggle_voice(...)` in `lib/engine_sync.lua`), so tests call them as now.

A short script in the pull request lists every rewritten name, so the reviewer can check the moves against it.

**Test harness changes:**
- `test/norns_stubs.lua` gets an `include(file)` stub that loads `<repo root>/<file without the "strata/" prefix>.lua` with `dofile` semantics. It also takes an override table (`options.module_sources = {["lib/fx"] = patched_source}`), which replaces `load_strata { source = ... }` for the two tests that patch the script.
- `local_value(name)`/`find_upvalue(name)` look in `S` first (found as the upvalue `S` of `init`), then in `S.constants`, then fall back to the upvalue search. Their setter writes into `S` for names found there. The 206 tests keep their lookups unchanged.
- A helper `read_lua_sources()` returns every Lua file of the script (`strata.lua` and `lib/**/*.lua`) for the five tests that read source. The `BUFFER_STATE_STRIDE` test reads `lib/buffers.lua`.
- `test/sync_check.lua` scans `strata.lua` plus `lib/**/*.lua`. A test asserts that it catches a bad `engine.<name>(` in a module.
- The docs check's path check also covers paths under `lib/`, so notes naming `lib/scenes.lua` and the like are checked.
- **New test:** a locals probe per Lua file. It appends locals to a copy of each file until `load` fails and asserts at least 30 free; the CLAUDE.md probe becomes this test.

**Docs.** CLAUDE.md's 200-locals paragraph changes to "per file, checked by a test"; the notes get the module table above; `test/` paths in docs stay valid.

**Acceptance.** All three checks pass with no test changed except the harness helpers and the source readers above. A manual diff review confirms code moved verbatim, apart from `local` declarations becoming fields of `S`.

### 2. Keys

**ALT.** K1 held (after norns' 0.25 s) sets `alt_held`. The hint row shows the ALT layer while it is held. Releasing K1 clears it. Keys held into the norns menu are already forgotten (`forget_held_keys`); `alt_held` is cleared there too.

| Page | E2 | E3 | K2 | K3 | ALT+K2 | ALT+K3 |
|---|---|---|---|---|---|---|
| MAIN | voice | selected field | next field | start/stop voice | randomize, or undo within 5 s | lock/unlock |
| VOICE | field | value | previous section | next section | reset field to its default | lock/unlock |
| FX | row | value | — | bypass/restore that row's effect | — | — |
| LFO | field | value | previous LFO | next LFO | reset field | on/off |
| BUFFER | slot | slot field | load (on release) | record/stop | clear slot | save slot |
| SEQ | step | step level (0 = off) | play/stop | step on/off | clear the voice's pattern | randomize the voice's pattern |
| SCENES | scene | transition time | recall with fade | recall instantly | — | save (twice if populated) |
| SETUP | field | value | — | run the field's action (save/load scenes) | — | — |

- **ALT+E3 is fine adjustment** on control params: they travel a tenth as far per detent (the delta goes through the param's raw 0-1 value, `params:set_raw`, at a tenth of the usual raw step). A param's own `controlspec.step` still limits its resolution, so a param with a coarse step (grain density, step 1) moves more slowly but not more finely. Number and option params (mod sources, envelope, destination, ...) ignore ALT and keep whole steps, except where a page gives ALT+E3 its own meaning (the LFO destination's group jump). ALT+E2 is page-defined (BUFFER: the field cursor). The arc has no fine mode: its 512 ticks per sweep are already fine, and ALT changes MAIN's rings instead.
- **Long-press fallback:** if the 3.1 hardware check rejects K1, long presses (0.6 s) of K2/K3 take the ALT+K2/ALT+K3 actions. Build `alt_action(page, key)` so either trigger can call it.
- **MAIN K3 changes meaning:** it now starts *and stops* the selected voice. Lock moves to ALT+K3. The arc button follows K3.
- **BUFFER:** E2 now picks a slot, not a voice. The voice whose buffer is shown is the selected voice, picked on MAIN or VOICE. E3 edits the field under a small cursor in the left column (source, duration, level), stepped with ALT+E2.
- **Center detents:** a param whose range spans 0 (pan, scan, crossmod amounts, LFO offset if present) holds at 0 for the next 3 detents after crossing it, from encoders and arc (arc: the next 24 ticks). `params:delta` callers go through one helper, `delta_with_detent(id, d)`.

### 3. Lock

- The UI says "lock" everywhere: `[L]` in the voice list, `[L]` on MAIN after ON/OFF on the status row, `L` on grid LEDs' docs.
- The value stays at full brightness while locked, because it can still be edited.
- The code name `frozen` and the scene field `frozen` stay. A rename would need a scene migration for no gain; `docs/notes/lua.md` says "lock (stored as `frozen`)". (The 3.2 audio freeze gets a new field name.)
- README, CLAUDE.md and the notes are updated wherever they say freeze for this feature.

### 4. Randomize undo

- `randomize_voice` stores the voice's previous values (synth params, buffer params, grain size and pitch: the params it changes) in `S.undo = {voice, values, until}`.
- For 5 s (`UNDO_SECONDS`), MAIN's ALT hint shows `K2:undo`, and ALT+K2 restores those values through `params:set` (so LFO offsets, the engine and the grid all follow) and clears the undo.
- A randomize of another voice, a scene recall, a mutation step (`gentle_mutate`) on that voice, or a manual edit of one of the stored params (so undo never overwrites an edit) clears the undo. The drift's 10 Hz pitch writes (`drift_writing`) don't clear it; undo restores the stored pitch and the drift carries on from there.
- Locked voices are not randomized (as now), so nothing is stored.

### 5. Pages

`UI_PAGES = {"MAIN", "VOICE", "SEQ", "FX", "LFO", "BUFFER", "SCENES", "SETUP"}`, `NUM_UI_PAGES` 8. E1 still steps pages and stops at the ends. Every page uses the shared field-cursor helper (`field_list`: rows, cursor, a view that keeps one row above the cursor, a scroll marker) except MAIN, which keeps its two columns.

**Header (all pages):**

```
VOICE ··•····     [M] ▶ REC  S3
```

- Title at x 0.
- Page dots: eight 2×2 px dots from x 40, 4 px apart, the current one at 15 and the rest at 3.
- `[M]` while mutations run (x 80).
- A play mark (a filled 3×5 triangle) while patterns play (x 94).
- `REC` at level 15 while any slot records (x 100).
- Scene `S1`-`S8` right-aligned at 127.
- Master density moves to FX (first row) and MAIN's arc ring 1. The `dens:` header test changes to check the page dots and indicators instead.
- A transient value (tempo changed from the grid, `buf 3 saved`, ...) can replace the dots and indicators for 1.5 s, through one `header_flash(text)` (the BUFFER page's flash generalized; it keeps working on BUFFER's hint row as now).

**MAIN:**

```
MAIN ·•·····            ▶ REC  S3
1+ reso     RESONATOR    synth
2+ fm       ON
3- karp    >freq       100 Hz
4+ sub      size       0.10 s
            dens        20 /s
K2:field K3:stop
```

- The voice list entries become `<n><+|-> <name>` (for example `3- karp [L]`). The widest, `7+ pulse [L]`, must still end by x 60 (the existing divider test).
- The list keeps four voices visible at the ends: `num_above_selected` becomes 0 for the first voice and 2 for the last, so the list never scrolls past an end (the blank top row goes away).
- The details column:
  - **row y 18:** full name, and the source right-aligned (`synth`, `buf 2`, `input`);
  - **row y 26:** ON/OFF, then `[L]` when locked and `[T]` in triggered mode (the long forms don't fit: `OFF [LOCK] [TRIG]` is about 92 px by the harness estimate, the column 62 px);
  - **rows y 34, 42 and 50:** three fields, each label and value with its unit: the main param, grain size and grain density. An input voice's main param already is grain size, so its fields are grain size, grain density and grain pitch (and arc ring 3 is pitch for it). The cursor (`>`) marks the field E3 edits; K2 steps it.
- `mod:V3 V5` moves to VOICE (crossmod section). MAIN has no room for it with three fields, and VOICE shows it in full.
- Hints: `K2:field K3:start|stop`, with ALT: `K2:rand|undo K3:lock|unlock`.

**VOICE (new):** every param of the selected voice, in four sections. The section name is drawn small at the top right (`synth 1/4`).
- **synth:** `param_order` without amp and pan; for a buffer source, `buf_pos`, `buf_rate`, `buf_scan`; for input, nothing (the section is skipped).
- **grain:** size, density, pitch, spread, envelope, mode.
- **crossmod:** speed, then each slot's source, amp and freq amounts, with the source shown as a voice name (`3 karp`), not a number.
- **mix:** source, level (amp), and pan where the voice has one.

The rows come from a new `voice_page_rows(voice)`, not from `fader_param_ids`: the 256's fader pages stay exactly as they are (anti-goal), and the VOICE page adds the params they lack (mod speed, source). Values use each param's own string with its unit, cut with `fit_text`. E2 picks a field, E3 edits it; K2/K3 jump sections; ALT+K2 resets the field to its default. E2 at a section's end moves into the next.

**FX:**
- Rows grouped under section labels drawn at level 2 (master, filter, delay, reverb). Labels take no cursor stop.
- Mixes, feedback and damping shown in percent.
- A 1 px scroll marker at x 127 showing the view's position in the list.
- K3 bypasses the effect of the row under the cursor (filter, delay or reverb) and restores its last non-zero mix, generalizing today's filter bypass (`fx_filter_last_mix` becomes one entry per effect).

**LFO:**
- The waveform rows stay. The right side shows destination and depth as now.
- A one-line field strip under the selected LFO's row shows its fields: destination, shape, mode (free or clocked), rate, depth, offset (if Strata applies the library's offset; otherwise left out), on/off. Rate shows the free period in seconds as the library stores it (`lfo_free_<n>`, 0.1-300 s), or the clocked division. Phase, baseline and reset stay in PARAMS. E2 moves along the strip, E3 edits. K2/K3 select the LFO.
- **Destination editing:** E3 steps both ways. ALT+E3 jumps a group: none, global, then v1 ... v7.
- **Default depth:** LFOs start at 25% depth, so turning one on is audible. This is the one default change in 3.1. Scenes saved before 3.1 store their depth and are unaffected.

**BUFFER:**

```
BUFFER ····•··              S3
KARPLUS  src: buf 2     1 buf1        7.3s
>dur 8.0s               2 field_rec  16.0s  v6
 lvl 1.00               3 -
 in ▮▮▮▮▮▯▯▯           4 buf4         REC
                        ...
K2:load K3:rec  ALT:clr/save
```

- **Left column:** the selected voice and its source, then the fields source, duration and level (E3 edits; ALT+E2 moves the cursor), and an input meter.
- **The input meter** comes from norns' `amp_in_l`/`amp_in_r` polls (started while BUFFER shows, stopped otherwise and in cleanup): 8 segments, the louder channel, with a peak hold of 1 s.
- **Right column:** the eight slots (E2 picks one; the cursor row is bright). Each row shows the voices reading it (`v2 v6`, cut to fit). Empty slots show `-`, without `0.0s`.
- **Spacing:** rows grow to 7 px apart. Eight rows then fill y 14-63, which collides with the hint row, so the slot list scrolls: six rows visible, with a scroll marker.
- **File names** use the full width up to the seconds column. Only the cursor row shows the voices column, so names in other rows get that space too.
- **Recording targets the slot under the cursor,** whether or not a voice uses it.
- **Hints:** `K2:load K3:rec|stop|...` and ALT `K2:clear K3:save`. The busy/saved/empty flashes stay.

**SEQ (new; chosen 2026-11-07 over a pattern strip on VOICE or keeping patterns grid-only):** all seven patterns at once, the sequencer's transport and the tempo.

```
SEQ ··•·····      ▶ 120 bpm   S3
1 ■·■··■·■···■··■·  +
2 ··■···■···■···■·  +
3 ················  -
...
7 ■···■···■···■···  +
K2:play K3:step  E3:level
```

- **Rows:** one per voice, `<n>` at x 0, then 16 cells (4×4 px, 6 px apart, from x 10), each at the step's level (0 dark, 1-15 as stored, the same levels the grid shows). A `+`/`-` at the right shows whether the voice runs. Rows sit 6 px apart from y 13, so seven fit above the hint row.
- **Cursor:** a 6×6 outline around the selected step. E2 moves along the steps; ALT+E2 moves to another voice row (the selected voice follows, as on MAIN).
- **Editing:** E3 sets the step's level (0-`MAX_STEP_LEVEL`); K3 turns the step on (at 15) or off. ALT+K2 clears the voice's pattern and ALT+K3 randomizes it (`clear_pattern`, `randomize_pattern`), the same as the 256's row 15.
- **Transport:** K2 starts or stops the sequencer (`pattern_toggle`). While it plays, the playing step's column is drawn brighter on every row.
- **Tempo:** ALT+E3 changes the `tempo` param (patterns are not params, so fine adjustment has nothing to act on here). The header shows `▶` and the tempo on this page.
- **Room for 3.4:** per-voice length, division, probability and step locks will appear here, with `field_list` rows under the patterns or on a second view.

**SCENES (new):**
- Two columns of four slots: number, a filled box if populated, the current scene bright, and the sequencer's position marked.
- Below them, fields: transition time, sequencer on/off, length, scene duration.
- **Cursor:** E2 moves through the slots, then the fields. E3 on a slot changes the transition time; on a field, the field's value.
- **Keys:** K2 recalls with the transition, K3 recalls instantly. ALT+K3 saves; on a populated slot the first ALT+K3 shows `K3 again: overwrite S3` for 2 s and a second saves.
- **Hints:** `K2:fade K3:recall` and ALT `K3:save`.

**SETUP:**
- **Fields:** MIDI port, channel mode, mutations on/off, mutation rate, probability and amount, save scenes, load scenes. K3 on a save/load field runs it.
- **Status lines below the fields:** grids, arc, buffers restored or missing. The empty grid-size line is drawn only when a grid is connected.
- The list scrolls like FX.

### 6. Grid

**Pages are per grid.** `grid_page` (one global today, `strata.lua:475`) becomes one page per port, so with two grids attached each shows and changes its own page.

Grid keys are acted on at press today (releases are ignored). 3.1 adds a held-key table per port (`grid_held[port][x][y] = press time`), cleared on release, on grid removal and in cleanup, so holds and two-key gestures work.

**All layouts:**
- **Step level:** while a step key is held, pressing another key on the same voice row sets that step's level to the pressed column's share of `MAX_STEP_LEVEL` (16 columns, or 8 on 8-wide grids). The held step doesn't toggle on release.
- **Scene save on hold:** a scene save key must be held 0.5 s, lighting up on press and saving once held (no accidental overwrites).

**256** (existing rows keep their meaning):
- **Row 16, columns 9-15 (dead today):** copy/paste. Press a voice's key to copy its pattern (it lights); press another voice's key to paste. Column 16 clears the clipboard.
- **Tempo keys** flash on press and show the new tempo in the header flash.
- **Scene page:** the sequencer position lights at level 10, the current scene at 15.
- **Lock:** row 16 columns 1-7 keep their behavior under the new name.

**128h:**
- **Page 2 becomes a fader page:**
  - rows 1-4: four faders for the selected voice;
  - row 5: the fader page selector;
  - row 6, columns 1-7: voice select;
  - row 7, columns 1-7: lock.
- **Page 4 (new, row 8 column 8):**
  - rows 1-7, columns 1-10: each voice's source (as the 256's rows 9-15);
  - row 1, columns 13-16: record slots 1-4;
  - row 2, columns 13-16: record slots 5-8;
  - rows 3-4, columns 13-16: clear slots 1-4 and 5-8.
- **Column 16** of row 8 keeps cycling the voice, now with a visible effect on page 2.

**128v:**
- **Row 8, column 8:** cycles pages (patterns, faders, scenes, sources), with its LED level showing the page.
- **Sources page:** column v (1-7) is voice v, rows 1-10 its source options (row 1 synth, rows 2-9 buffers, row 10 input, as the 256's rows 9-15 turned on their side); row 12, columns 1-8 record slots 1-8; row 13, columns 1-8 clear them.
- **Faders page:** columns 1-4 are four vertical faders (row 16 minimum, row 1 maximum), column 5 the fader page selector, column 8 rows 10-16 voice select (now useful).
- **Scenes page:**
  - column 1, rows 1-8: recall instantly;
  - column 2, rows 1-8: recall with fade;
  - column 3, rows 1-8: save on hold;
  - column 4: row 1 sequencer on/off, rows 9-16 sequence length 1-8.
- **Column 8, rows 1-7:** voice toggles on every page.

**64:**
- **Row 8:**
  - column 1: tap toggles play/stop (on release); a hold of 0.5 s toggles which half of the pattern is shown (steps 1-8 or 9-16);
  - columns 2-8: voices 1-7 on/off, so voice 7 is reachable.
- The shown half's playhead lights. When the other half plays, column 1 blinks with the beat.

Every change ships with grid tests on each layout (key → state, state → LEDs), as the existing grid tests do, and README's grid sections are rewritten.

### 7. Arc

- **Center fill:** a ring whose param range spans 0 fills from the top (12 o'clock) toward the value, clockwise for positive and counter-clockwise for negative, through a new `arc_ring_fill_bipolar` that uses `param_fraction` (the existing invariant "every ring through `param_fraction`" extends to it). The zero point is the param's own 0 (`param_value_fraction(id, 0)`), not the ring's middle.
- **MAIN:** as now (density, main param, grain size, grain density). With ALT held, the rings become grain pitch, grain spread, level and pan of the selected voice.
- **VOICE:** the rings edit the four fields starting at the cursor's group of four (rows 1-4, 5-8, ... of `voice_page_rows`); the screen marks the group. Control params sweep as every ring does. Option and number params (envelope, mode, source, mod sources) step one whole value per 20 ticks, through the LFO page's `arc_whole_steps`; CLAUDE.md's ring-scale exception list grows to include them.
- **SCENES:** ring 1 moves the scene cursor (10 ticks per slot), ring 2 is the transition time, rings 3-4 dark (3.4's morph will take ring 3).
- **SEQ:** ring 1 moves the step cursor (10 ticks per step), ring 2 sets the step's level (10 ticks per level), ring 3 the tempo (a number param: one BPM per 10 ticks, through `arc_whole_steps`), ring 4 the voice row (20 ticks per voice).
- **SETUP:** dark, as now.
- **The button** acts as K3 on most pages (MAIN and VOICE start/stop, SEQ play/stop, BUFFER record/stop, SCENES instant recall); on LFO it toggles the selected LFO on/off, since K3 there selects the next LFO. On FX and SETUP it does nothing.
- **Center detents** apply to rings as in §2 (fine adjustment does not; see §2).

## Cost if wrong

- **K1 as ALT:** the long-press fallback in §2 is built in, so the switch is a small change.
- **MAIN K3 stopping voices:** a stopped voice is one press away from running again, and lock moving to ALT+K3 is the only relearning.
- **Eight pages:** E1 travels further (seven turns end to end at 4 ticks per page). If that bothers in play, the order can change in one line (`UI_PAGES`).
- **BUFFER E2 picking slots rather than voices:** the selected voice comes from MAIN or VOICE. If that feels indirect, ALT+E2 could pick the voice instead of the field cursor.
