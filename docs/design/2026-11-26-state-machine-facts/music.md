## Reproduced findings, controls and bounded changes

Running the [four saved PSET and chain fixtures](probes.md) at this revision on Lua and LuaJIT gives **20 tests, 10 failures**. Nine are silent-PSET cases, one is a display case. Ordinary PSET reads and explicit switch cycling provide ten passing controls. The probes used norns stubs. Existing suites mainly enter each owner by its own actions. The gap is the norns post-read entry point.

1. **Scene transport**. `params_setup.lua:282,335,455` and `scenes.lua:1018,1112,1134`. Saving the opposite of the live setting then silently reading either 0 or 1 leaves the enabled flag and clock where they were. The registered invariant checks agreement between the runtime flag and clock, so a stale pair can pass. Compare final param to owner and take the start/stop edge once. Start defers the first recall by a scheduler turn because loaded scene/voice params and side files must settle first. On an unchanged read preserve running clock identity, current hold and kept next draw. Stop must revoke posted/initial resumes. Include saved-before-param/default and a real populated side scene. Show one actual recall after start and no subsequent one after stop.
2. **Pattern chain admission**. `sequencer.lua:1556,2089,2131,2156,2179,2189`. Under playing transport, silently enabling leaves no deadline and disabling leaves a live deadline; the two normal-read controls agree with settings after 2.1 s. With stopped transport the enable setting simply takes effect on next start. Reconcile **only** a mismatch between intended `seq_chain == 1 and pattern_playing` and deadline presence, using the same switch transition. An unconditional switch discards the linked scene and rebases the countdown even on an identical PSET. Count actual links, prove no link when disabled, next bar on enable, continuity under repeated/ordinary reads, cancellation on stop and #1051 late wake.
3. **Random-sequence clock and length**. `random_sequences.lua:104,165,197,314`. The side-file hook loads the four lists; their positions and clocks are live. Quarter-note to one-bar recall at beat 8.5 compares numeric counts from different grids; the first tick moves position 3→4, ordinary controls hold 3. The count belongs to a clock option; on a changed option reset the count and prime at the next division observation without drawing or stepping. Preserve legitimate boundary advances on unchanged reads and voice-triggered advance. Independently verified a second edge on **both VMs**: start clean, set rseq1_length=2 and write PSET, set 16, run `clock.set_beat(i); c.clock.advance_until(S.lfo_clock)` for i=1..11, read short PSET, then set 16 before a further tick. Normal read reports positions 11→1→1; silent read 11→1→11. `position_of` masks an out-of-range stored index while short; the normal action commits position 1. Normalize stored position once on shrink, preserving valid position, list, and same-option clock continuity. Add these owner tests including division↔voice and sequential silent reads. Do not reset all four sequence positions or re-seed their lists on every read.
4. **MIDI input ownership**. `params_setup.lua:754–797`, `midi_in.lua:91,154,226,254,635`, `mpe.lua:221–269`. PSET port 2 silently read while port 1 has a held key leaves port 2 unable to play; silent channel/note-off changes leave the old allocator entry and silent split-zone change leaves its former member key. Normal reads pass. `midi_in.reconcile` currently checks attached device identity on the recorded vport on menu close; assigning an unclaimed listener depends on desired vport and claims too. A comparison of listener identity alone cannot catch mode, rule or zone changes; an empty/claimed selected port can also have no listener. Use a small record of the *applied input configuration* where historical identity is needed, compare with final loaded values after migration, and route changes through the narrow owner operations. No parameters or file-schema change required. A changed port reattaches, resets MIDI input/tap and master ranges. Mode/note-off change resets input and keeps the controller's negotiated master range (#688). A changed member count or zone in active MPE uses the layout hook, releasing notes while retaining tap/master range; in plain routing the layout does nothing to held input. Follow established release/latch semantics, including the difference between releasing a voice and relinquishing own-note ownership, unrelated owners and existing panic behavior (#407). Preserve RPN/master-range on unaffected reads and distinguish port claims from selected ports. Test multi-field change, unchanged repeated reads during a note, ordinary read, startup/defaulted legacy PSET and MPE layout invariants. Malformed or cross-field inconsistent PSET bounds need an explicit expected normalization order if included; saved valid PSET suffices for the observed failures.
5. **Chain display**. `pages/seq.lua:223` returns none only when last slot is nil. `sequencer.chain_place` promises *last linked*, and `scenes.next_slot` deliberately uses history to choose the next cyclic playable scene after an invalid or excluded position. Start linked to S1, set a one-slot range to empty S2, wait through a bar: SEQ gives `[S1 1 bar]` rather than the documented `chain [none]`. Switching off/on first hides it. Derive empty range at render from the same playable predicate as playback (existing slot validity cache), retaining history/deadline. No chance draws, persisted extra flags or scheduler changes in the view. Cover immediate and post-bar display, compact form with reset plus failed output, invalid/empty/wrapped ranges, refilling with multiple valid slots and recovery in cyclic order, unchanged countdown. A **nonempty** range with last linked slot outside the range has distinct semantics: slot is history of the sounding pattern until next link. Do not infer a new current slot from membership alone.

#951 (0b378a98) gave stored per-voice values an ordered reconciliation; #965 (93cbb8a1, 3f7ff503) compares engine senders against their owner's expected values, sends once per group, and #994 (6352bacd) avoids duplicate chord lists. Those rules stay. An ordinary callback is too late to snapshot the old *param* value: paramset reads first and invokes action_read last. `read_defaulted` records only old-file defaulting. A post-read hook cannot reconstruct held MIDI routing or the pre-read musical clock from that map. Reuse observable runtime state and add only irreducible change identity where needed. Trigger replay, globally banging every param, immediate scene recall inside a read, or treating a same-state read as a restart changes working behavior. Count ordinary/unchanged sends against their existing contracts rather than promising literal zero across all senders (the scale is intentionally refreshed). Separate odd cases, e.g. conflicting port and note-off changes, by writing the desired event-order test first with an ordinary read as reference.

Working evidence is off-device. #6 §14 remains the authority for Lua's intended engine state versus a physical failed voice start, §15 for grid interaction and audible gate/roll/late bar phase, and §16 for high-tier reverb.
