## Reproduced transitions and bounded work

**G-1a. A repeated coordinate revives a role after a side change.** The 128h real layout receives HD down on marks, switches to VOICES, sees the up there, then revisits positions side 1 and presses the former HD coordinate as a jump before stale sweep. At 0.5 seconds scan is still held. A jump in column 8 instead of 7 clears it. `grid/pages/positions.lua:43` marks every such key "positions", then asks whether the coordinate currently has that role. The old closure becomes true for a different press with a different action. `grid/pane.lua:183` already maps a pane coordinate to its token, and `grid/core.lua:438` compares the captured token. Use that exact press in the page adapter. Retain the intentionally supported direct call without a predicate. Replace tests/notes that assumed role overwrite repaired all re-presses.

**G-1b. Two panes can share logical voice/cell and represent different held keys.** In the 256, top and bottom down on cell 4, older top up, then bottom press 9 changes position to 0.5 instead of making loop [3/16,9/16]; control with bottom only makes the loop (start .1875, length .375). The single anchor matches release by voice/cell/width but ignores pane. More serious: top plays slice 4; bottom selects bank 2 and plays slice 20 via its cell 4. Both play until top up ends 20; after both ups slice 4 is still held. Using bottom cell 5 plays 4 and 21 and leaves neither. At `positions.press_slice_key/release_slice_key` both entries shared the same `record.slices[voice][cell]`. The note key is per (port,slice), which differs for 4 and 20. A token-only change repairs neither shared record.

Keep the one-anchor-per-port musical rule; associate anchor with the press/pane which owns it and release only that owner. Give slice presses physically distinguishable records within the port (pane, voice, cell plus exact still and its quantize token). Preserve the original slice, note key and release semantics until completion. When two panes play the same logical slice, retrigger its existing per-port/slice note and hold it until its last live physical holder releases. This preserves its one-note allocation. Check replacement pending tokens cannot cancel a newer request; use both release orders in both same-bank and different-bank cases; leave stuck chronological or quantized one-shot notes only under the documented natural-duration rule. Keep two grids' note IDs separate and test direct API with default pane, detach, cleanup, pre-tick remaps, mutable bank, lost release and no extra node after quiescence. See `positions.md`, `slices.play/note_off`, `notes.play/release` and `quantize.schedule/waiting`.

**I-6a. A queued TXo deactivation can disappear.** `io/txo.lua:sync` issues a plain env_act 0 and drops `active[output]` even for false or later queue loss. `io/ii.lua:crow_gone` keeps queued offs, drops ordinary sends. `give_up_lead` flushes true offs within limit then invokes TXo release, which sees no record for the already-cleared output.
