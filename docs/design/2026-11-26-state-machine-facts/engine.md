## What changes the plan

The same defect reaches three public file types. A callback proves a particular rename completed. Once another carrier can still mutate the same final path, a success callback gives the reader no guarantee about the next open. A newer save reported success before the older WAV replaced it. In the onset experiment, the older pass put its markers on disk and then reported failure. A handed-off subprocess can outlive engine teardown. File naming in Lua and physical publication in the engine need independent acceptance tests. In particular the fixed scratch WAV per slot makes the engine's case reachable independently of Lua timestamp suffixes.

### Physical ownership and history

- `StrataFiles.sc:268` defines `writeSlot`, which records the current generation at line 287 in `writeGenerations[path]`. A newer generation cancels interleave at a chunk. After that it waits for the prior `pathRenames[path]` only while elapsed time is below `2 * peaksMoverTimeout` (2 seconds). At `StrataFiles.sc:337` the newest write hands off, sets or clears the rename token according to callback timing and removes its write-generation entry. The callback token test protects dictionary removal. Neither that check nor `reported` recalls a child that already owns the final filename. For user WAVs and predictable per-slot scratch files `StrataRecord.sc:endTake` shares this path. Docs explicitly promise newest wins. A scratch rewrite/restore failure is a direct implication of the shared method. The probes used user WAVs.
- `StrataWaveform.sc:72 writeSlotPeaks` guards `action` against `slotChanges[index]`/caller `current` in `finish`. Cache `written[index]` receives every completion's content, including obsolete ones. There is no equivalent pre-publication same-path ownership for peaks. `renameIntoPlace` chooses the FIFO while alive, backlog below four and filenames safe for its line protocol. At one second it launches a subprocess for the same part and continues waiting for the old acknowledgment. A backlog-full newcomer can go straight to another subprocess. `renameBySubprocess` treats a missing part as a possible earlier mover success. Any fix that explicitly unlinks a superseded part must distinguish revocation from that success case. `stopPeaksMover` drops outstanding FIFO poll callbacks and closes its input. An admitted rename can still land, as documented.
- `StrataOnsets.sc:onsetPassCurrent` correctly checks slot generation, analysis count and `pastStop` during reading and before handoff. `writeOnsetsFile` at line 284 bounds the same predecessor wait to two seconds. At line 293 an asynchronous completion checks slot generation and may delete the output only if its analysis is still the newest. This prevents a stale callback from deleting a newer file and leaves a stale child's completed rename untouched. The scratch test shows the stale file surviving even when the stale callback reports failure.
- The player can open the wrong WAV after a success. The UI's waveform frame clock and `lib/slices.lua:read_onsets` read asynchronously. File validators check slot/duration and content shape. The peaks file has a generation, but the validator has no expected engine generation paired with the length report. The onset file has no analysis count. For two equal lengths the wrong file can pass validation if that read falls after the overwrite. Actual UI read timing, wrong gain or wrong slice selection was not measured.
- Historical evidence in local history: 9e65cd64 (#127) delayed success until a save was reported. 14b3ae62 and 3c30c513 (#210) avoided frequent expensive forks and added slow-mover fallback. 1fa66ffe and 335bea95 (#217) routed WAVs through the mover and bounded predecessor waits. f022affa (#312/#313/#401/#522/#523 among its fixes) coupled scratch failures, peak refresh and Lua save names. f386225f (#872/#888) stopped obsolete onset work and guarded deletion. e30f74ec (#963) copied the bounded WAV rule to onsets. `test/engine_check/files.scd` around 637 releases its held mover after 0.5 s. `onsets.scd:checkRenameOrder` keeps it held long enough for a normally quick fallback. Neither holds the fallback syscall past the second deadline. Current timeout tests remain valuable positive controls.

### Proposed work and verification

1. Agree on one physical publication authority per standardized destination, covering the FIFO, fallback and retiring instances. Model submitted, waiting, commit in flight, superseded before handoff, committed/failed, and owner retired. Give each operation an identity distinct across engine instances. One older physical mutation must complete, be provably revoked or become unable to change the public path before newer success. A timeout means outcome unknown. Increasing it or predicates around the callbacks cannot enforce that ordering.
2. Keep a bounded active commit and at most the latest waiting candidate per destination, plus an explicit global admission/resource bound. Reuse `current`, `areaCall`, existing chunk cancellation and the four-entry nonblocking FIFO. Scope an arbiter to the shared publication lifetime or fence old actors at the filesystem commit, including engines across a script reload. If using a generation file, comparison and final rename require one serialized critical section for **all** carriers. If revoking an old `.part`, separately track proven mover success, revocation and failure. Name each script-stop, stale ack and missing-poll outcome. Prove recovery on unavailable carrier or refuse before dispatch with truthful feedback. Do not leave one waiting routine or child per submission against a permanently blocked destination. An unrelated destination and commands must still progress.
3. Preserve file formats and one-float command/report shapes where ownership can supply the guarantee. An old WAV canceled during interleave is silent under the current contract, while a checked failure and a committed save have numbered results. A superseded analysis should terminate under its own count. Stale completion cannot update current cache, delete newer onsets or confirm a newer UI save. A peaks failure must still release the audio/length continuation and leave the UI able to represent unavailable peaks without accepting a stale equal-length file. Any changed busy/superseded or timeout user feedback needs coordinated Lua and engine tests. Preserve previous valid audio on real failure and atomic visibility of complete files.
4. Add smallest deterministic failures in the area tests, using a barrier around commit initiation/completion, a real same-filesystem commit, independent contents and independent expected poll order. Cover (a) both carriers in each order, slow fallback beyond both timeouts, full FIFO and failure ack, (b) three generations, superseding a waiting middle and repeated events, (c) free and rebuild before late publication, (d) WAV samples/frames plus scratch restore, equal-duration/widely different waveform bins and onset markers, and (e) failed write/folder/full disk, two unrelated paths, queue saturation and no leaks of child/part/ack or responder after retirement. After a successful publish, release all delayed older actors and reopen final bytes. For onset, schedule the Lua deferred reader **after** late completion. For peaks, count actions/cache updates and compare audio on the server as well as the side file. A run of the existing sweeps alone misses a transient false publication.
5. Run focused files/waveform/onsets/record/buffers on supported SC 3.13 and local SC, then engine shards, Lua plus LuaJIT and sync checks. Preserve real-time responsiveness, byte-identical saved format and audio. Measure heap/temp-file/mover bounds and confirm the old `unixCmd`-per-refresh cost did not return. #6 can cover audible/playable saved and restored takes with rapid operations, reboot/reload and SD-card variability. No hardware frequency claim or new 3.x hardware gate follows.
