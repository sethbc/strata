# Buffers, recording, files and positions at v3.9.0

The row numbers refer to the [November 21 inventory](../3.9-state-machines-facts/lua-buffers.md). Paths and function names below refer to `d8621dd5`. Test file names refer to `test/unit/`. A file can be published after the slot has changed, a saved file can have settings even after the player cleared the slot, and a scan can have several holders. Each needs its own identity.

Row 12 also grouped the following protocols. They keep the representation and tests shown here.

- **Take write failure.** `buffers.take_write_failed` matches the newest recording, preserving audio while dropping an unwritten path. A clear or replacement disowns that report. #312 and `d434e21d`, `buffers_test.lua` and `record_test.lua`.
- **Recalled and waiting bookmark.** `positions` tracks the recalled source/mark while `quantize` owns the pending action. Cancel, replace, fire and source change have different display outcomes. #240, #431, #593, `positions_test.lua` and `quantize_test.lua`. The physical Store/bookmark display is also covered by row 2.
- **Playhead.** `playheads.advance` integrates under the previous speed, `reset` anchors on restart. The periodic tick contains faults separately by part. #322 and `98bce41c`, `playheads_test.lua`. A fault in the *same* estimate called inside the hold edge exposed row 11.
- **Tempo follow and loop pair.** `scan.following` and `bar_sync` derive eligibility and phase from source, tempo, transport and prior bar. `loops` clamps the start and length in the scene recall order. #739, #167 and #531, `scan_test.lua` and `loops_test.lua`.
- **File selector and BUFFER holds.** `pages/buffer.lua` owns the selector callback, saved handlers, page-local hold timing and resulting ALT key release. Leaving via the norns menu restores ownership. #49 and #435, `pages_buffer_test.lua`. Keep short and long save gestures in the save control tests.
- **Input metering.** `input_level.refresh` owns polls across start, demand changes and cleanup. #438, `input_level_test.lua`. The meter reads the existing levels.

### The save counterexample

A fixed timestamp, slot 2 with audio, six whole save requests and no file visible before the sixth request gave filename suffixes `1, 2, 3, 4, 5, 1` (`1` means the unsuffixed name). Six injected success polls forwarded four of six instrumented send-time settings snapshots. Lua and LuaJIT agreed. The injected polls demonstrate lost bookkeeping. They do not establish that the engine successfully wrote six distinct files. Existing `samples_test.lua` establishes the separate contract for real settings on a whole, loop and failed save. The engine inventory examines byte ordering independently.
