# Before 3.8: groundwork

Status: approved by the maintainer on 2026-11-16, with the builder check's questions answered; amended the same day where the plan's fact pass found the code to differ (the plan's rulings 1 to 37, kept in `docs/decisions/3.8.md` with the build's; each amended passage says so); built and landed by 2026-11-17, and marked "as built" where the build differs. It designs the work `ROADMAP.md` lists under "Between 3.7 and 3.8": three revisions, fourteen fixes, and the three architecture questions moved up from the pre-4.0 review. The facts it rests on were gathered the same day from `main` at 3bb75daa (`.superpowers/sdd/2026-11-16-before-3.8/facts-*.md` in the main checkout).

## Intent

3.8 adds voice types, voice presets, a delay freeze and the factory presets' code. Each of those would be built on a seam that grew release by release: two kinds of per-voice value, two ways for an LFO to reach a destination, two steppers over the scene slots, and scenes that live apart from the PSET they belong to. This work settles those seams first, so 3.8's design starts from one model of each. It also clears every known finding, so 3.8 starts with no open fault but the hardware check (#6).

## Decided (the maintainer, 2026-11-16)

1. **One plan, no release.** The three revisions, the fixes and what this design changes are one plan. Its changelog fragments ride to 3.8.0; there is no 3.7.1.
2. **3.8's design starts while this plan is built.** Its fact gathering and brainstorm begin once this design is approved and the plan is written. 3.8's plan waits until this work has landed.
3. **An LFO's own destination becomes a matrix routing: the full move, with a home routing each.** Each LFO owns one routing, stored by the matrix beside R1-R16. The LFO page looks as it does today: its `dest`, depth and offset edit that routing. Further destinations for the same LFO are R routings, as today.
4. **The pattern chain and the scene sequencer keep their front ends over one stepper.** One shared piece lists the playable slots and draws the next.
5. **Built-in and registered per-voice params fold into one value table with one registration path, now.** The scene format is reshaped; scenes files from 3.5 to 3.7 are set aside.
6. **Scenes travel with the PSET**, as macros, routings, recorders and sequences do. An unusable `grids.data` or `notes.data` is set aside like every other data file.
7. **MIDI note off has two modes, `latch` and `release`. The default is `latch`.**
8. **At the hand-over, three of this design's calls were put to the maintainer:** a home routing ramps through 0 in a fade (kept); the fourteen IO and zone params stay out of the value table (kept); a PSET load sets live scenes with unsaved edits aside first (changed from replacing them at once).
9. **The revisions and fixes stand as the roadmap lists them:** `frozen` becomes `locked`; the 256's fader pages take newer params; #738-#744 and #747-#753 are fixed, with #754 (filed from this design's facts).

## Goals

- One table and one registration path for every value of a voice's sound and playing (section 2 names the one exception).
- One store and one sum for every modulation destination a player routes.
- One list of playable scene slots and one draw.
- A PSET that carries its scenes.
- No known finding left open but #6.

## Non-goals

- **Voice types, voice presets and voice copy.** 3.8 designs them. This work gives them the value table and a per-voice capture and apply.
- **A reworked 256 layout.** 3.8 reworks it whole. Here the fader pages only grow.
- **Engine-rate R routings from an LFO.** An R routing from an LFO still updates from Lua.
- **Fewer data files, or one container file.** Ten stay ten.

## Anti-goals

- A change to the default sound. A fresh Strata plays what 3.7.0 plays.
- A new engine command, SynthDef or node. The only engine change is #742's fix.
- A conversion of an old file. Since 3.7's ruling 30 a file below its floor is set aside, never converted.
- A longer AGENTS.md. It has 225 words left; every rule this work rewrites comes out no longer than it went in.

## Constraints

- Every param id that survives keeps its id, default and spec, so PSETs and MIDI maps keep working. The ids that go are the six `strata_lfo<n>_dest` and `strata_lfo<n>_dest_key` pairs.
- Every package keeps the Lua suites green on both Lua and LuaJIT. The whole-system check that compares a default start with an earlier release is a regression net: a package that moves it on purpose re-bases it in the same commit and names it in its report.
- Lua's 200-local limit, the send budget and the 12 sends a step hold as they are.
- The scenes file stays under the reader's cap of 32768 tables; the package that reshapes it re-measures the largest file.

## Approaches

### An LFO's destination

- **Leave the model** (this design's first recommendation): one registration already feeds LFOs, macros and the matrix. Not chosen: it keeps two stores and two offset layers for one idea.
- **A source with a level, or a pure source:** the `dest` row leaves the LFO page and every destination takes one of the shared routings, raised to 24. Not chosen: the LFO page loses its quickest gesture, and the sixteen slots are tied to the envelopes' sixteen engine routes.
- **A home routing each (chosen):** the store, the sum and the scene block are the matrix's; the page keeps its shape. It needs no engine change, because the LFO's engine node can own a fast home routing as an envelope owns its routing since 3.7.

### The two chains

- **One stepper under both (chosen):** the two do different jobs (a whole scene on seconds with a crossfade; a scene's sequencing part on bars), so their clocks, params and pages stay. What they duplicate, and where #738 and #754 sit, becomes one piece.
- **Names and docs only:** not chosen; the two copies would each be fixed alone and drift again.
- **One merged chain with links:** not chosen; it needs a store for links and reconciles bars with seconds. 3.4 rejected an explicit link list.

### Per-voice values

- **A seam now, one format change in 3.8** (this design's first recommendation): not chosen.
- **Fold everything in now (chosen):** 3.8's design then starts from the finished model. The cost is accepted: scenes files from 3.5 to 3.7 are set aside, and 3.8's voice types may change the format again.
- **Leave it and write the map:** not chosen.

### The data files

- **Scenes travel with the PSET (chosen):** a PSET becomes a whole project, and a factory set installs as one PSET without touching a player's scenes.
- **Ten files, one rule only; fewer files; one container per PSET:** not chosen. The first leaves the factory presets with no way to load scenes beside a player's; the others merge files whose damage would then be shared.

## Design

### 1. `locked`

`S.frozen` becomes `S.locked`, and a scene's `frozen` field becomes `locked`, in code, tests, notes and user docs (amended: 32 lines in 9 files under `lib/`, about 100 in tests and 27 doc sites; no function says "frozen" for the lock, so none is renamed). A scenes file below the new floor shows as older, not unreadable (amended). "Freeze" then means only the audio freeze, and the AGENTS.md rule that kept the two apart shrinks to one line. This package runs alone, first.

### 2. One value table per voice

**The table.** `S.voices[i].values[key]` holds every per-voice value. A key is the param's id without its `v<i>_` prefix, so `values.grain_size` is `v<i>_grain_size`. The tables `params`, `grain`, `crossmod` and `extras` go. A voice keeps `name`, `active`, `source` and `param_order` as fields.

**One registration path.** Every per-voice param is added by an `S.register_voice_params` record through one generic action (today's `add_voice_extra`, renamed `add_voice_param`). The built-in params become three records: `synth` (a voice's own synth params, read from its `name`), `grain` and `crossmod`. The roughly 290 hand-written lines of `add_voice_params` go. A record gains what the built-ins need:

- `voice_keys`: keys sent with `setVoiceParam` or a send of their own, beside today's `grain_keys`, with `send_order` for a record whose sends have a fixed order;
- `fader`: groups of keys with a fader, in order, each with an optional `when(voice_idx)` (section 7);
- `main_randomize` and `mutate`: the groups of keys MAIN's randomize and the mutations draw;
- `separator`: the menu separator a record's params sit under, and `count` may be a function of the voice.

Amended: no `action` field. A param filter (the frequency's scale snap is one) and a param's own action already cover every built-in. The three built-in records register in `lib/voices.lua`, the first module that can, so they come first. Amended (the plan's review): a `grain_keys` or `voice_keys` entry may say `carry = false` (the grain envelope and mode and the ten crossmod keys), so it skips the carried offsets, as 3.7.0 did.

**The start path.** A voice start and a voice sync send from the one table, through key lists that `lib/params_setup.lua` hands `lib/engine_sync.lua` by one function. The first package builds that function over fixed lists; the records replace the lists behind it, so the later package does not edit `lib/engine_sync.lua`.

**What stays the same.** Every id, default, spec and menu order; what MAIN's randomize, the mutations and each page randomize draw; and the messages a voice start sends. Their order holds wherever today's is defined. The synth params go out in `pairs` order today, which differs between Lua and LuaJIT; they go out in sorted key order from now on, and their test compares that group as a set against 3.7.0. The rule "registered per-voice params never reach MAIN's randomize or the mutations" becomes "a record names the keys they reach", with today's sets.

**The one exception.** Fourteen per-voice params stay where they are: the eleven `v<i>_out_*` (`lib/io/targets.lua`) and the three `v<i>_zone*` (`lib/mpe.lua`). They say where a voice's notes go and which keys reach it, belong to the rig, are saved in PSETs only and sit in their own menu groups.

**What 3.8 gets.** A voice type becomes a record's set of keys. How a voice changes type, and what a scene does with a key its voice lacks, are 3.8's to design.

### 3. Scene format 9

`SCENE_DATA_VERSION` and `SCENE_FORMAT_FLOOR` both become 9. A scenes file below 9 is set aside as a backup, by the rule the floor already follows. One version covers every change in this work, since nothing is released between its packages.

- **A voice:** `scene.voices[i] = {active, source, values = {...}}`, flat, in place of four nested tables.
- **The lock:** `scene.locked[i]`.
- **LFO destinations:** the six `strata_lfo<n>_dest_key` blocks go; the `matrix` block holds the home routings (section 4).
- **Recall order** (amended): a voice's built-in keys apply first, sorted, then its registered keys, sorted, discrete keys at a transition's end. That keeps `loop_length` before `loop_start`, and `freq` before `freeze`: one fully sorted order would freeze a running voice at its old note.
- **Per voice:** `S.lib.scenes.capture_voice(i)` returns that table, and `S.lib.scenes.apply_voice(i, data)` applies one. `capture_scene` and a recall are built on the same per-voice entries (amended: a recall is not seven `apply_voice` calls, which would run the scene-applied hooks eight times). Neither touches a voice's pattern, its lock or the global blocks.
- **Fixtures:** the tests that load 3.6 and 3.7 files become tests that they are set aside whole; a format 9 fixture is added for later releases to load, by the last package that changes the file (amended).

### 4. LFO home routings

**The store.** The matrix holds 22 routings: R1-R16 as today, and a home routing for each LFO at slots 17-22. `MATRIX_SLOTS` stays 16, as the engine's envelope routes do; the six are `NUM_LFOS` more. A home routing's source is fixed (`lfo<n>`). Its destination is any entry of the destination list, the macros included, or none. Its depth, offset and on/off are the LFO's own params (`strata_lfo<n>_depth`, `_offset`, `strata_lfo<n>`), so it has no `matrix_<k>` params.

**What goes.** The params `strata_lfo<n>_dest` and `_dest_key` (an LFO's group is 12 params), the six scene blocks, `S.lfo_last_dest`, `S.lfo_scaled`, the LFOs' term in `with_lfo_offsets`, the LFO's own Lua send and `restore_lfo_destination`.

**Who plays a home routing.**

- **A Lua destination:** the matrix. The routing's `m` is the LFO's (`value × depth' / 100 + 2 × offset / 100`), summed with the R routings on the same param into the matrix's one extra offset, sent through the round robin under the param's key. The matrix's rules apply: one sum and one clamp, a resend past the threshold, one more send when a sum returns to 0.
- **A fast destination:** the LFO's engine node, with today's `setFastLfo`, `syncFastLfo` and `stopFastLfo`. `S.lib.lfos.owns(n, id)` says so and the matrix's read skips it, as it skips an envelope's owned routing.
- **A macro:** the LFO module hands it over in its own step, as today, and owns it the same way.

An LFO's rate ceiling follows its home routing as it followed its destination: 50 Hz when the engine plays it, else 10 Hz.

Amended (the plan's rulings 16 to 18): a home on `v<i>_main` that resolves to a fast param is the matrix's, sent as `setFastOffset`; a restore after an LFO goes off, to depth 0 or elsewhere reaches the engine at the matrix's next step, a macro's at once; a voice start and sync carry a Lua home's offset at once.

**R routings are unchanged.** They read an LFO's shape before its depth, refuse macros, and keep the 25 % rule, which a home routing does not need (an LFO's depth defaults to 25).

**The pages.** The LFO page's `dest` row calls `S.lib.matrix.edit_home(n, id)`; its ALT jump, the `~` mark and the `R` mark read as they do. MOD's `L1`-`L6` rows are the home routings; its routing view, learn and arc rings stay on R1-R16.

**Storage.** `matrix.data` and a PSET's `.matrix.data` become version 2 with floor 1: a version 1 file loads with no home routing. `S.lib.side_files` sets aside any file that is not exactly its spec's version today, so this package gives a spec an optional `floor`; section 6's scenes file uses it too. The scene block `matrix` holds slots 17-22 beside 1-16. A destination this build lacks is kept and not played, by the matrix's rule.

**Transitions.** A home routing whose destination differs between two scenes ramps the LFO's depth through 0 and switches at the midpoint, the matrix's rule for every routing. Until now the destination switched at the fade's end.

**What a player notices.** A PSET written by 3.7 comes back with its LFOs aimed at nothing: its destination lines name params that no longer exist. Everything else an LFO does sounds as before.

**Names.** `S.LFO_DESTINATIONS` (built in `lib/lfos.lua`) and the functions `S.register_lfo_destination` and `S.register_lfo_global_destination` (`lib/state.lua`) keep their names and stay where they are. They name the list every modulator shares, and renaming them buys nothing.

**Readers outside the package.** `lib/pages/main.lua`, `lib/io/crow.lua` and `lib/io/midi_out.lua` read an LFO's destination through `S.lib.lfos` (`destination`, `is_engine_run`, `engine_playing`), which keep their names and answers. crow's self-check, which sets `strata_lfo1_dest`, sets the home routing instead; the package edits that one call.

### 5. One stepper

`S.lib.scenes.playable_slots(first, count)` lists the slots of a range, wrapping past 16, that hold a scene that is populated and valid. `S.lib.scenes.next_slot(position, slots, chances)` draws from that list with `S.lib.chance.pick`. A scene's validity is worked out when it is saved or loaded, never at a draw.

- **The chain** (`lib/sequencer.lua`) draws with it and no longer walks on from an invalid pick (#738).
- **The scene sequencer** (`lib/scenes.lua`) draws with it, so an invalid scene is never drawn (#754).
- **The next-scene action** (`lib/io/actions.lua`) steps through the same list.
- **Labels:** the three chances read alike on SEQ and SCENES, in the one word that fits both pages.

A draw with no other playable slot keeps the playing scene (amended: applied again at 100, 0, 0 and held on a repeat; a cleared playing scene on the chain goes on to the next saved one with no draw, plan ruling 29). Clocks, params, pages and grid keys do not change.

### 6. Scenes with the PSET

Scenes become the fifth user of `S.lib.side_files`: the live file stays `data/strata/scenes.data`, and each PSET gets `<pset>.scenes.data`.

- **A PSET save** writes the sixteen scenes beside it, an empty set too.
- **A PSET load** replaces the sixteen live scenes with the PSET's and rewrites the live file. Nothing is recalled: the sound is the PSET's params. A running transition ends first; the scene sequencer and the chain go on over the new scenes.
- **Unsaved edits are backed up first.** When the live scenes changed since the last PSET save or load, the load sets the live scenes file aside as a backup before it replaces them, with one console line naming the backup. A load with no such change makes none, so the nine backup names are not used up. An edit made in an earlier session counts: the live file itself records whether a PSET holds its scenes. When the backup cannot be made (all nine names taken, or the card refuses), the live scenes stay, and one console line says so (as built: and the hint row's flash `pset scenes not loaded`). As built (#766): the live file's mark is trusted only while its PSET still holds these scenes; a stale mark counts as no PSET and is cleared.
- **A PSET with no scenes file** (one saved before this work) leaves the live scenes as they are.
- **An unusable scenes file** beside a PSET is set aside with one console line, and the live scenes stay.
- **A PSET delete** removes its scenes file.

SETUP's status rows and its `load scenes` action keep working on the live file.

**One rule for an unusable file.** `grids.data` and `notes.data` set an unusable file aside as a backup before they write a new one, as the other eight do.

**What 3.8 gets.** A factory set is one PSET with its five side files and its samples.

### 7. Fader pages

`fader_param_ids` reads the records' `fader` keys, so a param with a fader is one line in its record. The existing faders keep their order and pages. These follow them, in this order: the voice filter's cutoff, resonance and mix; the delay and reverb sends; the loop's start and length; the pitch, size and pan jitters; the voice's attack and release (the notes record's `attack` and `release`, not the modulation envelopes'). The maintainer kept this order on 2026-11-17, at the plan's approval, over the plan's first call of registration order; a fader group carries a `rank` for it. Amended: the loop's faders show on buffer voices only, as VOICE's rows do, so a voice has 7 or 8 fader pages, inside row 13's sixteen keys. Options get no fader. The 128h and 128v show the same pages through `S.param_page`.

### 8. MIDI note off

`midi_note_off` offers `latch` and `release`, in that order, with `latch` the default. `auto` and its dependence on the MIDI mode go, with the paragraph of `docs/user/midi.md` that explained it. An MPE player sets `release` once. An old PSET's `auto` and `release` keep their meaning by position; its `latch`, the third option, reads as `release`.

## Left to the builder

- The exact fields of the three built-in records, and whether `synth` is one record or one per voice name.
- Where a scene's validity is kept between a save and a draw.
- How the live scenes file records that a PSET holds its scenes.
- Whether the live scenes file moves onto `S.lib.side_files`' own writer or keeps its writer and status rows, so long as each PSET's file goes through the helper.
- The label the three chances share.
- How #750 tells an owed note MIDI out still holds from one it has forgotten.

## Cost if wrong

- **Folding in now:** if 3.8's voice types need another scene shape, format 10 sets format 9 files aside. The only scenes at risk are the ones made between this work and 3.8.
- **Home routings:** if players want an LFO as a plain source, the home slot's destination is simply left at none; nothing is lost. If the home routing should have been an R slot, six stored slots change place.
- **The ramp through 0:** a recalled LFO that changes destination now dips at the fade's midpoint. If that is unwanted, the home slots take the old switch at the end: one line of the block's `through_zero`.
- **Scenes with the PSET:** a player who loads PSETs often without saving fills the nine backup names, and the tenth such load leaves the live scenes in place until a backup is removed. If that proves a nuisance, the oldest backup can give way.
- **Setting old scenes files aside:** every scenes file made with 3.5 to 3.7 becomes a backup that no build reads. The maintainer accepted this (2026-11-16).

## Calls made in this design

Each can be reversed at the review.

- The home routings are slots 17-22 of the matrix's one table, not a table of their own.
- The destination list keeps its names and its home in `lib/lfos.lua`.
- A PSET with no scenes file keeps the live scenes; a PSET load recalls nothing; a backup that cannot be made keeps the live scenes.
- `midi_note_off` lists `latch` first, so an old PSET's `auto` and `release` keep their meaning.
- The new faders. (Their order was put to the maintainer with the plan and kept.)
- #750's fix is the owed notes' own offs (amended: with every note's number kept there is no rest, and no CC 123).
- `matrix.data` takes floor 1; the scenes file takes floor 9.
