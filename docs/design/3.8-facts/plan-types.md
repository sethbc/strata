### 5. Risks and open points

1. **The design's "a voice then holds two voice synths at most" fails on one path.** `gateVoice` hands a superseded releasing voice synth to `fadeSupersededSynths` as a forced release (`release(grainRelease)`, `StrataLifecycle.sc:149-152`, 156): stop a voice, change its type, start it (fading: the old synth, 2 s), then switch it again at once (cutting: the live one; live: the new): three voice synths, 21 at the worst. Proposed: a releasing synth of another type is **cut** in `gateVoice` (`freeCuttingSynths`, then `cutVoiceSynth`), not released, so the bound is the design's two. The design's "another type's is superseded" leaves it open.
2. `releasedVoiceType` as state is unnecessary (one def a type); see Names. Unsure whether the design intends a type whose def another type shares; nothing in §3 does.
3. **"Sixteen live and sixteen cutting voice synths of the costliest def" is not reachable by one switch**: a switch changes the def, so the cut set is the old def and the live set the new. The worst a real switch makes is the costliest live and the second costliest cutting (or the reverse). The case can be built conservatively (every note cut and played again on the costliest def inside the hold, as the facts' scratch case was, plus a switch from the second costliest), or as the real switch. The builder must measure; the plan should say which.
4. `switchVoiceType` frees the voice's whole cutting set, grain synths included (a cutting grain synth from a source switch in the last 50 ms loses the rest of its fade). The same happens at every source switch (`cutFadingSynths` → `replaceFadingSynths` → `freeCuttingSynths`), so it is today's rule, not new.
5. A switch while the voice runs but its voice synth failed to start (`synths[voiceKey]` nil) only records the type; the watcher's restart (`voiceSynthFreed`) or the next start uses it. Fine, but worth a line in types.md.
6. The `voiceControls` of the old type stay (`StrataVoices.sc:281-293`); a name two types share with another meaning reaches the new def until Lua resends (`ratio` FM/Ring, `mod` Folder/Ring, and after 1j `width`, `cutoff`, `res`, `detune`). Lua's sync after a running voice's switch covers it (0d); a stopped voice gets every value at its start.

### 5. Risks and open points

1. **`voice_engine_parts` and `add_voice_param` read the same `voice_keys`**: if the synth record's `voice_keys` were the current type's (to keep the sync right), the other types' keys would get no sender at init (`lib/params_setup.lua:864-866` asks `voice_keys_of(record, voice_idx)` at the add, when the voice is on its default type). Hence `voice_keys` static and the new `reaches` gate. The design says "each with its sender, a sender reaches the engine only while the voice's current type has the key" without naming the mechanism.
2. **The fade's targets** (`scene_transition_targets`, `lib/scenes.lua:570-603`) take every continuous entry; synth entries of a scene whose type differs from the voice's type at the fade's start must be left out so they land at the end (`recall_scene_instant` applies every entry, the type entry first). The voice's type is read once, at the fade's start; a hand type change during the fade then meets the landing's type anyway.
3. **Morph** keeps an entry only if every valid corner holds it (`corner_values`, `lib/morph.lua:183-194`); the design's "a synth key that not every corner holds joins the discrete set" needs `corner_values` to accept a `synth` entry missing from a corner (a sentinel such as `false` for the missing corners), then `differs_among` is true whenever the counting corners include one lacking it, and `discrete_writes` writes the type entry and the keys in the corner's recall order. A key held by every corner, of whatever type (`width` in a Pulse corner and a Saw corner after 1j), keeps blending.
4. **Include-time reads of the type registry**: `register_voice_params` calls a function-valued `scene_defaults` for every voice at registration (`lib/state.lua:316-340`), i.e. at include. The notes record's `scene_defaults` (`lib/notes.lua:925-928`) reads `NOTES.envelope`; read from the types, it would read the registry at include, which AGENTS.md forbids ("never at include time"). Proposed: that check moves to init (`check_record`, `lib/params_setup.lua:898-924`, already checks built-ins' discrete defaults there), or the notes record uses the new `scene_keys` field (defaults `param_default` at the call) and leaves `scene_defaults`; the second changes the recall order (attack and release would leave the registered keys' sorted block), which ruling 4's tests may pin.
5. **`first_field_row` runs at include** (`lib/ui/cursors.lua:19`) and today walks `section_keys` (which reads `param_order`, nil before init in 0d). With the type row first it must return 1 without reading the voice. And `sections_of` (`lib/pages/voice.lua:67-78`) starts a section only at a label row: the screen sketch (§12) shows `type` and `preset` with no label above them, so either the row gets a section label (another row on a 64-px screen) or `sections_of` must start a section at a first row that has none; the K2/K3 section jump and the "<section> k/n" text (133) follow from that choice. The design is silent.
6. **The arc's VOICE rings** edit the cursor's group of four rows (`lib/arc/voice.lua:19-41`): an option row moves one option every 20 ticks with no settle, so a ring on the `type` row cuts once a step. Not in §14's list for 0d; one line routes the row to `S.lib.types.turn` (or the row is left out of ring groups, which shifts every group).
7. **ALT+K2 on the type row**: a held press resets the row to its default (`voice_reset_row`, `lib/pages/voice.lua:~285`), an instant type change and cut; a quick press randomizes the section, which must draw nothing for the type. The design says only "never drawn by a randomize".
8. **`apply_voice` "sets the type before it checks the keys"** (§2.4) contradicts its contract (`lib/scenes.lua:1263-1272`: it validates a copy and applies nothing when invalid). With validation by the data's own type, no order is needed: validate, then apply (the type entry first). Recommend dropping the design's wording.
9. **A scene of a type this build lacks**: validation must then accept keys it cannot name (they are the unknown type's); proposed: for an unknown `type`, every key `voice_scene_keys` lists for the voice (the shared ones) must be present and valid, and any other key must only be a finite number. That also accepts a later build's shared key on such a scene, which a known type's scene refuses today; acceptable, but say so in scenes.md.
10. **A type's own defaults for a shared key are never a voice's**: no voice defaults to a new type, so a voice switched to `saw` plays Pulse's `width`/`cutoff`/`res` defaults (or its own last values). If the docs table shows the record's own default for such a key, it states a value no voice gets. Proposed: a new type gives a shared key the first type's default (the registry can require it for keys of types beyond the first seven, or the docs test can check it).
11. **The norns menu** when a type change hides rows while PARAMETERS is open (`_menu.rebuild_params` rebuilds the page and keeps `m.pos`, `lua/core/menu/params.lua:697-707`): a voice's synth keys follow its `v<i>_type` row, so a change made from that row keeps the cursor on it; a change from elsewhere (MIDI, a scene) with the cursor further down the menu moves what the cursor points at. Not run on a device (#6). A hidden MIDI-mapped param still moves (`menu/params.lua:720-744`) and sends nothing.
12. A silent PSET read (`params:read(file, true)`) runs no actions, so `S.voices[i].name` would not follow a `v<i>_type` line; Strata never reads silently (grep of `lib/`), and `source` has the same exposure today.
13. The largest scenes file's table count (`DATA_FILES.largest_scenes_tables` 6898, `lib/data_files.lua:40`): a type is a string, so it should stay 6898; 0d measures it again (`data_files_test.lua:183-187`).

### 1f wave (`wave`, list `wave`, `\strataWave`)

- Keys (prototype `\strataScratchWavetable3`, `engine-voices.md` appendix 297-317): `freq, morph, morphRate, morphDepth, detune, amp, pan`. Proposed specs: `morph` 0-1 lin 0.01, default 0.3 (main, label `morph`, `"%.2f"`); `morphRate` 0.01-1 Hz lin 0.01, 0.05; `morphDepth` 0-1 lin 0.01, 0.2; `detune` 0-0.02 lin 0.001, 0.003, format `"%.3f"` (#386's rule for steps under 0.01). `note_main` `morph`, `noteMainRanges` `strataWave: [\morph, 0, 1]`. Envelope 3 and 6 s (the prototype's). `freq`, `amp`, `pan` take the first type's defaults (100, 0.3, 0) unless the record gives its own; amp 0.3.
- The bank: 8 tables of 2048 samples in wavetable format, 4096 floats each = **131,072 bytes (128 KiB)**, `Buffer.allocConsecutive(8, context.server, 4096, 1, { arg buffer, index; buffer.sine1Msg(<spectrum index>, true, true, true) })` in the area's `allocState` (filled on the server by `/b_gen sine1`, no sclang loop; `VOsc3` needs consecutive bufnums, which `allocConsecutive` gives and "bufnums never change" keeps), freed in its `free`. State `areaState[\typeWave][\bank]`; named values `waveBankSize { ^8 }`, `waveTableFloats { ^4096 }`, the spectra in one method (the prototype's eight lists are a start; "the eight spectra" are left to the builder). It allocates against 0b's `fixedBufferBytes` and edits neither `StrataPerformance.sc` nor `lib/performance.lua`; the check should compare the bank's bytes with the part of `fixedBufferBytes` 0b reserves for it (0b should name the parts, e.g. `wavetableBankBytes`, so this is a check and not a copy).
- Cost: 17.7 KB (`VOsc3`, 64 UGens) or 16.0 (`VOsc`); CPU 0.53 / 0.38 Karplus.
- **The def bakes the bank's base bufnum** (as the grain defs bake `scaleBuffer`'s, `docs/notes/engine/variation.md:8`): the last engine built on a server owns the def, so a check that plays the wave voice after a second engine was built (structure, files, memory's high run) must rebuild it for `h.engine`, as variation.scd does for the grain defs. Alternatively the base is a control, which would join `engineOwnedControls`.
- Checks: the bank is 8 consecutive bufnums, each non-zero after the fill (a `/b_get` of one frame), the def's VOsc3 reads constants from the bank's range, `free` leaves no buffer (structure area's accounting), morph 0 and 1 both play.

### 1g additive (`additive`, list `add`, `\strataAdditive`)

- Keys (prototype `addScratchAdditive`, appendix 235-267; its `drift` renamed `wander`, since `drift` is Sub's key with Sub's spec 0.001-0.1): `freq, tilt, stretch, oddEven, wander, amp, pan`. Proposed: `tilt` 0-3 lin 0.01, 1 (main, label `tilt`, `"%.2f"`); `stretch` -1-1 lin 0.01, 0; `oddEven` 0-1 lin 0.01, 0.5; `wander` 0.01-1 Hz lin 0.01, 0.2. `noteMainRanges` `strataAdditive: [\tilt, 0, 3]`. Envelope 4 and 8 s.
- **The partial count rule** (§3): 16 if a partial without its own wander oscillator fits 52 KB, else 12, else 8; one slow wander for every partial. Measured prototype figures: 41.3 / 68.3 / 123.0 KB at 8 / 16 / 32 partials **with** a per-partial `LFNoise1` (3.4 KB a partial, 16.25 UGens a partial). (est.) Without the per-partial LFO, about 13 UGens (2.9 KB) a partial on a base of about 14 KB: 16 partials about 60 KB (over), 12 about 49 KB. So **12 is the likely count**; the package measures 16 first, as the design says, and commits the count as a named constant (`additivePartials`). At about 49-52 KB it would be the costliest def (Karplus trimmed is 49.7): the memory area's casts then use it, and the worst cases fall by up to 14 × 2.3 = 32 KB (high synth -> buffer -> synth) and 46 × 2.3 = 106 KB (the switch case) against the design's 700 KB of margin.

### 1h noise (`noise`, list `noise`, `\strataNoise`)
