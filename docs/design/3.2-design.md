# Strata 3.2: performance setting and one grain path

Date: 2026-11-07
Status: approved 2026-11-08. It was revised after the builder check of 2026-11-07 (its rulings are marked "Call made in review"). The five open questions were decided on 2026-11-08 (see Decisions).
Builds on: Strata 3.1 (`docs/design/3.1-design.md`, approved) and `docs/design/3.1-3.6-roadmap.md` (3.2 section and its decisions of 2026-11-07, which bind this document). It refines and supersedes the roadmap for 3.2.

Citations are `file:line` against `main` at c531645 (3.0.2 plus the 3.1 docs). The norns facts come from norns commit `227aa044`, the one CI pins.

## Intent

3.2 reworks the engine so that every voice's grains read a buffer.
- **Synth voices** write their audio into a short ring buffer.
- **The live input** writes one shared ring, which keeps a history.
- **Buffer voices** read their slot, as now.

Pitch becomes the grain's playback rate. The `PitchShift` and the spread `DelayC` that take most of today's real-time memory go away. On top of that one grain path come:
- real freeze;
- reverse grains, per-grain jitter, interval sets and scale quantize;
- loop regions;
- a per-voice filter, and delay and reverb sends;
- effects that free their CPU and memory when bypassed;
- a hardware performance setting: Pi 4 and CM4 class norns get longer buffers, a longer input history, a richer reverb and spectral freeze.

The engine is split into files first, so the rest can be built in parallel.

The sound of synth voices changes: granular rate transposition instead of a pitch shifter, and grains that start a little in the past. This was accepted on 2026-11-07 (roadmap, Decisions 1). Everything else defaults to 3.1's sound.

## Goals

0. `lib/Engine_Strata.sc` split into class-extension files under `lib/engine/`, in a pull request that changes no behavior: every SynthDef compiles to the same bytes and the command list is unchanged. Norns and CI compile the split engine.
1. A performance setting (`auto`, `standard`, `high`), known to the engine at `alloc`, stored outside scenes and PSETs, applied at the next start.
2. One grain path. Every grain synth is a `GrainBuf` pair reading a buffer, with pitch as the grain rate. There is no `PitchShift` and no spread `DelayC` in any grain synth.
3. Real-time memory at the 3.0.2 worst case drops from about 6.9 MB to about 2.8 MB on the standard tier (§2.7). The engine check requires at least 3 MB free on standard and 4 MB on high at that worst case, floors set from 3.5's note-stream estimate (§2.7).
4. Live-input history: an input voice can read anywhere in the last 16 s (standard) or 60 s (high).
5. Real freeze for every source, plus spectral freeze on the high tier.
6. Per-grain reverse probability, pitch, pan and size jitter, interval sets and scale quantize, all drawn per grain at no memory cost.
7. Loop regions for buffer voices.
8. Per-voice filter and per-voice delay and reverb sends, whose defaults sound like 3.0's serial chain; bypassed delay and reverb free their CPU and memory.
9. Longer buffers on the high tier (16, 60, 120 or 300 s, default 60 s), within the Pi 4's RAM.

## Non-goals

- Polyphony, notes per voice and MPE (3.5). 3.2 only frees the memory for them.
- Grid position rows, arc scrub, waveforms, overdub and resampling (3.3). 3.2's loop regions are params only; the two-key grid gesture comes in 3.3.
- Engine-side fast modulation (3.4).
- Changing `memSize` or anything else in norns.
- Per-voice scales. 3.2 has one global scale and root.

## Anti-goals

- Breaking a CM3. Everything works on the standard tier, and `auto` never picks high on a CM3 or a Pi 3.
- Old scenes that sound different beyond the accepted pitch change. Every new scene field gets a default that reproduces 3.1: no reverse, no jitter, no intervals, no quantize, the whole slot as the loop, history 0, freeze off, sends 1, voice filter bypassed.
- New engine commands where a grain param will do. 3.2 adds two commands: `setScale` (a global table no grain param can carry) and `setBypass` (an effect-level state, §6.3).
- A second grain path kept "just in case". `\strataGrain` (`GrainIn` plus `PitchShift`) is removed, not left beside the new one.
- Stacking. Ring writers, freeze copies, spectral writers and re-created effects follow replace-never-stack like grain synths.

## Constraints

**Platform:**
- **scsynth's real-time pool is 8192 KB.** norns' `Crone.sc` leaves `memSize` at the default (`sc/core/Crone.sc:61`, commented out). Buffers (`b_alloc`) come from ordinary RAM.
- **norns compiles every `.sc` under `~/dust`.** `sc/norns-config.sc:15` adds `~/dust` to sclang's include paths, and sclang compiles include paths recursively, so `lib/engine/*.sc` is compiled with no setup. This was checked with sclang 3.14.1: a class in `lib/`, extended from `lib/engine/A.sc` and `lib/engine/B.sc`, compiled, and the extension read the class's instance variable.
  - Class extensions (`+ Engine_Strata { ... }`) add methods only, never instance or class variables. All variables stay in `lib/Engine_Strata.sc`.
  - The class library is built when sclang starts, so a new or renamed engine file needs a norns restart, as `.sc` changes already do.
- **CI compiles the same tree.** `test/run_engine_check.sh:39-41` puts `$repo_root/lib` on the include path, so `lib/engine/` is compiled with no change. CI is `.github/workflows/test.yml:79-80`.
- **Platform values.** matron's `matron/src/hardware/platform.h:9-17` defines `0` unknown, `1` other, `2` CM3, `3` Pi 3, `4` Pi 4, `5` CM4, `6` CM4S. It reads them from `/sys/firmware/devicetree/base/model` (`matron/src/hardware/platform.cc:10-32`). `norns.platform` exposes the number to Lua (`lua/core/norns.lua:213`; its comment lists only 0-3).
- **The engine runs before the script.** `CroneEngine.init` runs `alloc` in a routine and calls back when it is done (`sc/core/CroneEngine.sc:25-28`). The script's `init` runs from `engine.load`'s callback (`lua/core/script.lua:243`), so a file the engine writes in `alloc` is there when `init` runs.
- **sclang reads `/proc` files as empty with `File.readAllString`** (they report size 0; checked: 0 bytes for `/proc/meminfo`). Read them with `getLine` or `unixCmdGetStdOut`.
- **SuperCollider versions.** norns and CI run SuperCollider 3.13.0 (norns `Dockerfile:42`, `.github/workflows/test.yml` `SC_APT_VERSION`). The probes below ran on 3.14.1 on a desktop, and `docs/notes/engine.md`'s memory figures were measured on scsynth 3.14. Package 1b re-checks all of them on 3.13 (§10).
- **`GrainBuf` wraps and plays backward.** A non-realtime probe (scsynth 3.14) confirmed that a grain starting at 90% of a buffer, crossing its end, continues from frame 0, and that a grain at rate -1 crossing frame 0 continues from the end. Rings rely on the wrap. Buffer slots must keep avoiding it (§5).
- **sc3-plugins.** norns ships sc3-plugins 3.13.0 (norns `Dockerfile:42-43`, `:131-135`), but CI does not install them. `SVF` and `JPverb` are sc3-plugins; `PV_MagFreeze`, `BLowPass`, `RLPF`, `RHPF`, `BPF` and `FreeVerb2` are core.
- **matron polls carry one float** (`docs/notes/engine.md`, poll `bufferState`).

**Project:**
- Everything in CLAUDE.md, in particular:
  - replace-never-stack, `cutSynth`, `openedGate`, `sendToSynth`;
  - fade-before-zeroing and `slotChanges`;
  - the mirror rules and `silentBus`;
  - limiter before the saturator;
  - the velocity invariant;
  - the command table;
  - Lua as the only source of values.
- 3.1's structure: modules under `lib/` with registries (`S.registry.*`), tests in `test/unit/`, notes per module, changelog fragments, engine checks on `$STRATA_SC_PORT`.
- The engine check fails on `alloc failed`, `Too many grains`, `FAILURE` and `Strata invariant broken` (`test/run_engine_check.sh`), and requires 1 MB free at today's worst case (`docs/notes/engine.md`, Real-time memory).

## Approaches

### How the engine learns the tier

- **A. The engine decides at `alloc` and tells Lua through a file (chosen).**
  1. The engine reads the setting Lua last saved, the board model and `/proc/meminfo`.
  2. It picks the tier and the buffer length.
  3. It writes the result to a small file before `alloc` returns, which Lua reads synchronously in `init`.

  The first start on a Pi 4 is already high. Lua's param ranges (density, record duration) are right before any PSET loads. Only one place decides.
- **B. The engine starts standard, and Lua sends `setPerformance` at `init`.** The engine would reallocate the buffers (same bufnums, `/b_alloc`) and re-add the SynthDefs with the new `maxGrains`. That races with the buffer restore and with `/d_recv` completing. It also adds a command.
- **C. Lua and the engine each compute the tier from the same inputs.** That is two implementations of the memory check that can drift.

A, with one rule: the engine commits to the high tier only if it could write the file. If it couldn't, it runs standard, and Lua, finding no file, assumes standard too.

### The grain path

- **Rings for every live source (accepted; roadmap Decisions 1).** All the memory win; one path.
- **Rings only for the input and freeze** (rejected on 2026-11-07). Keeps most of the memory cost.
- **One SynthDef for rings and slots, or two built from one function.** Two defs (`\strataGrainRing`, `\strataGrainBuf`) are built by one builder that differs only in how the grain position is computed. Each def's control set stays tight (`controlNameSets`), the slot def keeps its fade logic (`hasAudio`, `grainSlots`) unchanged, and the shared part is written once.

### Effects routing

- **Sends that reproduce 3.0's crossfade mixes (chosen; Decision 1).** Each voice's output is split three ways with gains that depend on its sends and the global mixes, so all sends at 1 is exactly 3.0's chain (§6.2).
- **Plain send/return (rejected).** The dry signal is always at full level and the mixes become return levels. Old scenes would play their dry signal 3 dB louder at the default reverb mix (0.3), and louder still with delay.
- **Keep the serial chain and add per-voice pre-levels (rejected).** This gives no per-voice sends, which the roadmap asks for.

### Upward pitch on ring sources

- **Continuous mode starts grains further back; triggered mode shortens them (chosen; Decision 2).** Continuous textures keep their grain size. Triggered accents stay within a grain of the step (§2.3).
- **Always start further back (rejected).** It keeps full-length grains everywhere, but triggered accents arrive up to 1.5 s late at pitch 4.
- **Always shorten grains (rejected).** Continuous textures would thin out at high pitch.

### Per-voice filter placement

- **After the grain stage, inside the grain synth (chosen).** It works the same for all three sources, and a cutoff sweep also moves frozen and buffer audio. Each grain synth filters only itself, so a fading synth keeps its own filter state and a switch never steps it.
- **Before the grain stage (in the ring writer).** This only exists for synth and input voices, and frozen audio would keep the cutoff it was recorded with.

### Bypass

Only the explicit bypass (K3 on the FX row, or its param) triggers it, never a mix that reaches 0 (Call made in review).
- **Free the delay or reverb node after a fade, and re-create it when the bypass is lifted (chosen; Decision 3).** Its CPU and its real-time memory (the delay's 1 MB) come back, and it restarts empty.
- **`/n_run 0`, the roadmap's wording (rejected).** CPU only. A paused delay line keeps audio from before the pause and plays it on resume, sometimes minutes old.

### High-tier reverb

- **A core-UGen feedback delay network (chosen; Decision 4).** CI and every norns stay identical.
- **JPverb from sc3-plugins (rejected for 3.2).** It needs sc3-plugins installed in CI and pinned to norns' 3.13.0. It remains a later option once CI carries sc3-plugins for another reason.

### The freeze control

The approved 3.1 design gives ALT+K3 on MAIN and VOICE to lock.
- **A `freeze` row on the VOICE page, plus grid keys and a MIDI CC mapping (chosen; Decision 5).** It changes no 3.1 key and still works under 3.1's long-press fallback for ALT.
- **K3 held 0.5 s on MAIN (rejected).** It would make start/stop act on release, and it collides with the long-press fallback.
- **Grid and MIDI only (rejected).** Freeze would not be playable from the norns alone.
- **MAIN ALT+K3 to freeze, with lock on VOICE only (rejected for now).** It changes an approved 3.1 key. It can be revisited once 3.1's hardware check settles K1-as-ALT.

### 1. The performance setting

**Setting (Lua):**
- Two SETUP fields, `performance` (`auto`, `standard`, `high`) and `buffer length` (16, 60, 120, 300 s; offered on the high tier only).
- They are not params, so PSETs and scenes never hold them (roadmap). They are saved to `data/strata/performance.data` as `key value` lines:

  ```
  performance auto
  buffer_seconds 60
  ```

- The field shows the setting and, when it differs from what runs, `(next start)`: for example `performance: high (next start)` or `buffer: 300 s -> 120 s (memory)`.

**Decision (engine, the performance area, first in `order`):**
1. Read `performance.data`. A missing file means `auto` and 60 s. The directory is `settingsDir`, a classvar that is nil on norns (it then defaults to `~/dust/data/strata/`, the literal folder Lua's scenes already use, `strata.lua:2745`); the engine check sets it.
2. Tier:
   - `standard` gives standard;
   - `high` gives high on any board (the user asked for it; SETUP warns `may xrun` on a CM3 or Pi 3);
   - `auto` gives high when the board model contains `Raspberry Pi 4` or `Compute Module 4`, which includes CM4S (the strings matron matches, `matron/src/hardware/platform.cc:18-29`). Otherwise, CM3, Pi 3, an unknown board, a desktop or CI, it gives standard.

   The model path and the meminfo path are classvars too, so the check can feed fake files.
3. Buffer length: standard is always 16 s. High is the setting, stepped down (300, 120, 60, 16) until the slots and rings leave at least 1 GB of `MemAvailable` in `/proc/meminfo`. The slots take 3.07 MB per second of slot length (8 slots × 2 × 48 kHz × 4 bytes). An unreadable meminfo gives 16 s.
4. Write `data/strata/performance_active.data`:

   ```
   tier high
   buffer_seconds 60
   max_grains 128
   history_seconds 60
   reason auto: Raspberry Pi 4 Model B Rev 1.4
   ```

   Delete the old file first. If the new one can't be written, fall back to standard (and post why), so Lua and the engine always agree.

**What the tier sets:**

| | standard | high |
|---|---|---|
| `bufferSeconds` (slot length) | 16 | 16/60/120/300 (default 60) |
| `maxGrains` (every `GrainBuf`) | 128 | 128 (see below) |
| `grain_density` maximum (Lua spec) | 100 | 100 |
| input history | 16 s | 60 s |
| spectral freeze mode | not offered | offered |
| reverb | `FreeVerb2` | core FDN (§6.4) |
| per-voice filter | offered | offered |

- **The high tier keeps 128-grain tables and density 100** (Call made in review). 256-grain tables (and density 200) fail the 3.5 arithmetic in §2.7: they would nearly double every note stream's memory on the very tier meant to carry the most notes. `maxGrains` stays a tier value in `performance_active.data`, so a later release can raise it if 3.5's measurements leave room. The largest overlap, 0.5 s × 100 × 2 = 100, stays inside `maxGrains - 1` on both tiers, which the existing Lua test keeps (`test/run.lua:844`).
- Lua reads `performance_active.data` in `init`, before any param is added, into `S.performance` (`tier`, `buffer_seconds`, `max_grains`, `history_seconds`). A missing or unparsable file gives standard and a console line. `BUFFER_SECONDS` stops being a constant: code uses `S.performance.buffer_seconds`.
  - The stub test that compares `bufferSeconds` with `BUFFER_SECONDS` changes. It now compares the engine's `standardBufferSeconds` (16) with `S.constants.STANDARD_BUFFER_SECONDS`.
  - The engine stub reads the tier from the test's `performance_active.data`.
- **`bufferStateStride` becomes 1000** (from 100, `lib/Engine_Strata.sc:47`, `:1430-1432`). `slot * 100 + seconds` can't carry 300 s. The largest value, 7 × 1000 + 300, is still exact to 0.01 s in a float. `BUFFER_STATE_STRIDE` follows it, and the CLAUDE.md poll text and the "seconds ≤ 16" wording change with it.

### 2. One grain path

#### 2.1 Rings

- **Voice rings.** Each voice gets a pair of mono buffers (`ringL[i]`, `ringR[i]`) of `ringSeconds` = 4 s at the server rate, allocated once in the rings area's `allocState`. Their bufnums never change. RAM: 7 × 2 × 4 s × 192 KB/s = 10.8 MB.
- **Input ring.** One pair of `historySeconds + ringGuardSeconds + 1 s` (16 + 4 + 1 = 21 s standard, 65 s high): 8.1 MB or 25 MB. The guard covers the lookback (§2.3) and a freeze copy's 4 s (§3); the extra second covers the writer moving on while a copy runs.
- **Ring writers.** `\strataRingWrite` (`in`, `bufL`, `bufR`, `phaseOut`):
  - a `Phasor.ar` over the ring's frames drives two `BufWr`s;
  - its frame position goes to a control bus (`Out.kr(phaseOut, A2K.kr(phase))`; `ringPhaseBuses`, one per voice plus one for the input);
  - one writer per voice reads `granBuses[i]`, and the input writer reads `inputBus`;
  - writers are persistent, like the effects: started in the rings area's `start`, never released, messaged plainly (the area registers their keys in `effectKeys`), freed in its `free`.
- **Node order.** The writers go at the tail of `voiceGroup`, after the voice synths (head, `:1076-1077`), `inputSynth` and the record synths (`:1670-1677`). A voice writer therefore records only its voice synth: mirroring grain synths write `granBuses[i]` later in the cycle, in `processGroup`, and `In.ar` reads a bus not yet written this cycle as silence. No gating is needed, and returning to the synth source never re-grains a fading buffer voice's mirror.
- **Buffer slots** are read as now.

#### 2.2 Grain synths

`\strataGrain` is deleted. One builder, `this.grainDef(name, positionFunction)`, makes:
- `\strataGrainRing` for the synth and input sources: reads a ring pair and its phase bus;
- `\strataGrainBuf` for buffer sources: reads a slot, with today's `bufFrames`, `bufRateScale`, `hasAudio`, grain-end and scan logic (`:630-703`) minus the `PitchShift` (`:686-693`).

The shared chain, for every source:
1. **Trigger.** `Impulse.ar(grainDensity)` or `T2A.ar(t_trig)`, by `grainMode`, as now.
2. **Per-grain draws** on that trigger (§4): rate, reverse, pan offset, size. `GrainBuf` latches its inputs per grain, so a draw never moves a sounding grain.
3. **Rate.** `pitchShift × jitter × interval × bend × (1 + rateMod)`, quantized when the voice quantizes, times -1 for a reverse grain. The `bend` and `rateMod` terms are 1 for the synth source, whose voice synth already applies them. Ring rates are clipped to ±`ringMaxRate` (4) so the lookback stays bounded (§2.3). Slot rates are not clipped, as now.
4. **Two `GrainBuf.ar(2, ...)`**, one per channel buffer, each with a per-grain pan (§4). At zero pan jitter the left buffer's grains pan to -1 and the right buffer's to +1, which is the pair as today.
5. **Slow pan wander.** The `Balance2` by `LFNoise1.kr(2).range(panSpread.neg, panSpread)` stays as it is (`:586`, `:684`).
6. **Voice filter, level, accent and crossmod.** `this.voiceOutput(...)` (§6) writes the dry, delay and reverb buses and the mirror.

- **The param name `pitchShift` stays** (Lua's `grain_pitch` sends it, `strata.lua:1758`). It now means the grain rate: 0.25-4, an exact transposition of two octaves either way, with no smearing. Because the rate is latched per grain, a pitch change (drift, LFO, scene fade) reaches new grains only: pitch steps grain by grain instead of gliding through `pitchShift.lag(0.5)`. This is part of the accepted change, and CHANGELOG says so.
- **The rules that stay:**
  - the synth-source grain synth keeps `mirrorLevel 0`, `pan 0`, `accentAmt 0` and `modLevel 0`, with `silentBus` routing (`:1114-1119`). `mirrorLevel 0` now keeps the mod synth from following the voice synth twice (there is no feedback any more: the writer reads before the mirror);
  - input and buffer grain synths mirror (`mirrorLevel 1`) and take the voice's `pan` through `panBalance`;
  - `openedGate`, `killFade` and the accent's `levelScale` are unchanged, and the velocity check covers `\strataGrainRing`.
- **New for the input source**, because pitch is now a rate: the input source takes `bend` and frequency crossmod (`rateMod`), as buffer voices already do.

#### 2.3 Where a ring grain starts

A grain reads behind the writer. The time between its start and the write head is its lookback `D`. The writer moves forward one frame per frame, and a grain at rate `r` moves `r` frames per frame. For a forward grain of duration `dur` never to overtake the head:

```
D = margin + history + spreadOffset + max(r - 1, 0) * dur          (r > 0)
D = margin + history + spreadOffset                                (r < 0: it reads older audio)
```

- **`margin`** (`ringReadMargin`, 5 ms) covers the block that `A2K` reports at its start, plus interpolation.
- **`history`** (input voices; §2.5) is seconds back, chosen by the user.
- **`spreadOffset`** is a per-grain draw in `[0, posSpread × ringSpreadSeconds]`, with `ringSpreadSeconds` = 0.5 s. It is a real random position, backward only, since forward of the head is the future. This replaces 3.0's 0.3-level smeared `DelayC` copy (`:588-593`), as the roadmap accepted.
- **The ring must hold the oldest audio any grain reads.** A reverse grain at rate -4 and 0.5 s ends `D + (1 + 4) × 0.5` = D + 2.5 s back. The worst case is margin + 0.5 s spread + 2.5 s ≈ 3.0 s, inside a 4 s voice ring. The input ring adds `historySeconds` to the same 4 s guard. Size jitter never makes a grain longer than 0.5 s (§4), so the bound holds.
- **Continuous mode** uses `D` as written, with full-length grains: at rate ≤ 1 a grain starts 5 ms back, at rate 2 a grain length back (the roadmap's accepted cost), and at the extremes (rate 4, 0.5 s grains) 1.5 s back (Decision 2).
- **Triggered mode reads the newest audio it safely can, and shortens grains above rate 2** (Decision 2):

  ```
  dur' = min(dur, dur / (r - 1))
  D'   = margin + history + max(r - 1, 0) * dur'
  ```

  The lookback is never more than one grain length (plus margin and history), whatever the pitch. A grain at pitch 4 with 0.5 s grains lasts 0.17 s and starts 0.5 s back, instead of 1.5 s. Reverse grains keep their length, since they need no lookback.

  As in 3.0, position spread does nothing in triggered mode for synth and input voices (`docs/notes/engine.md`, `grainMode`), so `spreadOffset` is 0 there. A triggered synth-voice grain at rate 1 starts 5 ms before the accent's attack and reaches it 5 ms in. The engine check's `rings` area asserts the triggered bound and the continuous grain length.
- The phase bus is read at control rate, so a grain triggered later in a block finds the head up to 63 frames further on than it was told. That only adds lookback.

#### 2.4 Lifecycle, replace-never-stack, fades

- The grains area registers `\strataGrainRing` for sources 0 and 9 and `\strataGrainBuf` for 1-8 in the `grainDefs` table that `grainDefFor` consults (§0). `startGrainSynth` (`:1108-1128`) passes the ring pair and phase bus for sources 0 and 9.
- Placement (`startPlacedGrainSynth`, `:1159-1165`), `gateVoice`, `replaceGrainSynth`, the fading and cutting sets, `freeCuttingSynths` and `sendToSynth` are unchanged. Rings add no synth that can end on its own.
- **`ringReaders`** maps every `\strataGrainRing` that reads a voice ring to its voice until it frees, set in `startGrainSynth` and cleared in `watchVoiceSynth`'s `onFree`, like `grainSlots` (`:43`, `:1126`, `:1244`).
- **Fade before overwriting a ring.** Writers only ever append. The one other write into a voice ring is an input voice's freeze copy (§3), which follows fade-before-zeroing:
  1. the voice's ring readers (for example a synth-source grain synth still fading after a switch to input) get `ringLevel 0` (a lagged 50 ms gain, like `hasAudio`);
  2. the copy waits `bufferFadeWait` when any reader is playing, at once otherwise;
  3. it runs only if the voice's `ringChanges` count is unchanged, so a later unfreeze, freeze or source switch wins (the `slotChanges` pattern, `:1611-1629`).
- Ring writers are swapped (spectral freeze, §3) with `Synth.replace`, which frees the old node in the same server step. The new writer starts from the phase on its bus, so readers never see the head jump.

#### 2.5 Input history

- **`v<i>_history`**: 0 to `S.performance.history_seconds` s, default 0. It is a per-voice param, used by input voices only.
- It moves the read point back from the input ring's head, so an input voice can play what came in up to 16 s (60 s) ago while the input keeps recording. The whole history is reachable even at rate 4 with 0.5 s grains, because the 4 s guard covers the lookback.
- It is not `buf_pos`: an old scene whose voice is on input and whose `buf_pos` is non-zero would otherwise jump into the past.
- Scenes capture it (default 0), it crossfades, and it is an LFO destination.

#### 2.6 CPU

Two `GrainBuf`s with two-channel output cost about what two mono `GrainIn`s did, and each grain synth loses a `PitchShift`, plus a `DelayC` for synth and input voices. The writers are two `BufWr`s each. Overall CPU should drop. The 3.2 hardware check (#6) measures seven voices at the default settings and at the density maximum on both tiers, on a CM3 and on the Pi 4.

#### 2.7 Real-time memory, before and after

From `docs/notes/engine.md` (Real-time memory), at 48 kHz:
- `PitchShift` at the fixed 0.1 s window: 16384 floats × 4 bytes × 2 channels = 128 KB per grain synth.
- `\strataGrain`'s spread `DelayC` (0.2 s, stereo): 64 KB × 2 = 128 KB.
- Grain tables: `GrainIn` 2 × 128 × 72 B = 18 KB per synth; `GrainBuf` 2 × 128 × 96 B = 24 KB, or 48 KB with 256 grains.
- The worst case (measured 6920 KB): every voice holds its live synth-source grain synth, an input grain synth in its 2 s release and a buffer grain synth in its 50 ms cut. That is 21 grain synths and 7 voice synths.

Both tiers use 128-grain tables (§1). The "256-grain" column shows the option that was weighed and rejected.

| Per grain synth | 3.0.2 | 3.2 (both tiers) | rejected: 256-grain tables |
|---|---|---|---|
| synth or input (`\strataGrain` → `\strataGrainRing`) | 128 + 128 + 18 = 274 KB | 24 KB | 48 KB |
| buffer (`\strataGrainBuf`) | 128 + 24 = 152 KB | 24 KB | 48 KB |
| worst case per voice (2 ring-type + 1 buffer) | 274 + 274 + 152 = 700 KB | 72 KB | 144 KB |
| worst case, seven voices | 4900 KB | 504 KB | 1008 KB |

**Standard:** 6920 − 4900 + 504 ≈ 2524 KB. Add about 300 KB for what 3.2 adds to graphs:
- per-voice filter, draws and sends, about 10 KB per grain synth × 21;
- eight ring writers;
- two more master-filter instances (§6.2).

That gives **about 2.8 MB used and 5.3 MB free**. The roadmap estimated "about 5 MB freed". The exact figure is 4.4 MB, because a buffer grain synth never had the `DelayC`.

**High:** 2.8 MB plus:
- at most 560 KB for spectral writers (seven at about 80 KB of FFT buffers each, only while spectral freeze is engaged);
- about 200 KB more for the FDN reverb than `FreeVerb2`.

That gives **about 3.6 MB used, 4.6 MB free**. A bypassed delay gives back another 1 MB.

**What 3.5 needs** (Call made in review). One note stream is one grain synth: its tables plus about 11 KB of graph, so **about 35 KB with 128-grain tables and about 59 KB with 256**.
- Streams **replace** a voice's single grain synth; they do not add to it. A buffer or input voice playing N notes runs N live streams instead of one. Synth voices keep one grain stage per voice (roadmap 3.5) but run N voice synths.
- Under today's lifecycle rule, a source switch or recall moves all N streams into the fading set and the previous fading set into the cutting set. The worst case is therefore 3N streams per voice, where 3.2 has 3.
- Each note beyond the first adds 21 streams across the seven voices and about 14 voice synths (live and fading). The voice synths are about 10 KB each, except Karplus at 64 KB for its two `Pluck` lines: about 250 KB per extra note.
- **Standard** (roadmap: 2 notes): 21 × 35 + 250 ≈ 1.0 MB more than 3.2's worst case. With today's 1 MB rule kept for 3.5 and 1 MB of margin for these estimates, the **standard floor is 3 MB free** at 3.2's worst case (12 probes of 256 KB). The 5.3 MB estimate clears it by 2.3 MB.
- **High, 128-grain tables:** about 21 × 35 + 250 ≈ 1.0 MB per extra note. Four notes need 3 MB plus the 1 MB rule, so the **high floor is 4 MB free** (16 probes), measured with spectral freeze engaged on every voice. The 4.6 MB estimate clears it by 0.6 MB.
- **Six notes on high** (the roadmap's example) need about 5 MB plus the 1 MB rule, which does not fit under today's lifecycle rule. The 3.5 design must either cap high at four notes or stop a switch from keeping a full fading set of notes (for example, cut the old notes instead of releasing them). This document records the limit.
- **256-grain tables:** about 21 × 59 + 250 ≈ 1.5 MB per extra note, and 504 KB more in 3.2 itself (4.1 MB free). Even three notes on high would leave no margin, so **high keeps 128-grain tables** (§1).

**Measured (package 1b, 2026-11-07, on SuperCollider 3.14.1; correction).** The estimates above came out low; measured with `/rtMemoryStatus` on 3.14.1, and since then by the engine check's `memory` area with allocation probes (3.13 has no `/rtMemoryStatus`), which give the same figures on 3.14.1 and print them on every run (CI's run prints SuperCollider 3.13.0's):
- one grain synth takes about **48-51 KB**, not 24 KB: `\strataGrainRing` 47.6 KB, `\strataGrainBuf` 51.4 KB. The two 128-grain tables are about 26 KB (13.6 KB per `GrainBuf`, whatever its channel count); the rest is graph, about 250 bytes for each of the 85 and 103 UGens. So **a 3.5 note stream is about 50 KB**, and each note beyond the first costs about 21 × 50 + 250 ≈ 1.3 MB.
- the 3.2 worst case, with its cutting synths still in their fade, uses **2758-2786 KB (about 5.4 MB free)** on standard; the idle engine about 1.5 MB. The high run measures the same until spectral freeze (2a) and the FDN reverb (2d) join it.
- **Both floors are kept** (3 MB on standard, 4 MB on high). Standard's two notes need 1.3 + 1 = 2.3 MB, inside its floor. **High fits three 3.5 notes** under today's lifecycle rule (2 × 1.3 + 1 = 3.6 MB, inside 4 MB); **four need a lifecycle change** (a switch that cuts the old notes instead of keeping a full fading set) **or a smaller grain graph** (4.9 MB otherwise). The bullets above that say four notes fit the 4 MB floor, and the six-note bullet's arithmetic, are superseded by these figures; the 3.5 design re-measures on norns' own scsynth (the hardware check, #6) before it settles the note count.

**The engine check** runs today's worst-case scenarios (the peak, the burst, the A → B → A → C recalls) on each tier with probes: at least 3 MB free on standard and at least 4 MB on high. These replace the 1 MB rule. Package 1b's `memory` area enforces both floors, on CI's SuperCollider 3.13. ### 3. Freeze

`v<i>_freeze` is a binary param, off by default. `v<i>_freeze_mode` (`hold`, `spectral`) is offered on high only, and standard always uses `hold`. Both reach the engine as grain params (`freeze`, `freezeMode`); `setGrainParam` routes them to `StrataFreeze.sc`, as it already special-cases `envShape` (`:860-865`). Both are declared as controls of the grain SynthDefs, so the engine stub's name check accepts them.

| Source | `hold` | `spectral` (high) |
|---|---|---|
| synth | the voice's ring writer is paused (`/n_run 0`). The phase bus keeps its last value, so grains keep reading the frozen ring; spread, pitch, reverse and jitter still move, and `bufScan` moves the read point back through the frozen 4 s (wrapping) | the writer is replaced by `\strataRingWriteSpectral` (`PV_MagFreeze` between `FFT` and `IFFT`, freeze 1), so the ring keeps receiving one held spectrum, which the grains then granulate |
| input | the 4 s of the input ring **ending at the voice's current read point** (the head minus `margin + history`, so freezing never jumps to the present; Call made in review) are copied into the voice's own ring (idle while the voice reads the input), and the grain synth switches to it (§2.4). The voice writer is paused; the copy is one `/b_gen copy` per channel, or two when it wraps; the voice phase bus is set to the copy's end, so the frozen grains continue from where they were with history 0 inside the copy; and the live grain synth gets the voice ring and phase bus with a `set` (`GrainBuf` latches its buffer per grain, so the change is seamless). The input ring's 4 s guard plus 1 s (§2.1) keeps the copied span from being overwritten while the copy runs, even at the largest history. The shared input writer never stops. Unfreezing restores the voice's history on the live ring | the voice writer, switched to read `inputBus`, is replaced by the spectral writer, and the grain synth reads the voice ring |
| buffer | the scan stops: the `Phasor` that scans `bufPos` (`:657`) runs at `bufScan × (1 − freeze)`, so the position holds while spread, pitch and the draws still move | not offered |

- **Unfreeze** reverses each step. The writer resumes from its frozen phase (the grains may cross the seam between old and new audio once). An input voice goes back to the input ring.
- **A source switch unfreezes.** Lua sets `v<i>_freeze` to 0 through a hook in `S.registry.source_change` (§8), so the screen, grid and engine agree. A frozen buffer → synth switch would otherwise freeze a ring holding old or no audio. During a scene recall the scene's freeze is applied after its source, as a discrete key at the end of the transition.
- **Controls:**
  - **on the screen, a `freeze` row in the VOICE page's mix section** (through `voice_rows`). E2 moves to it and E3 toggles it, as on any VOICE field; K3 keeps 3.1's "next section" (Decision 5). With `freeze mode` beside it on high. No 3.1 key changes: ALT+K3 stays lock on MAIN and VOICE. `[F]` shows on MAIN's status row (y 26, after `[L]` and `[T]`; not in the voice list, which has no room);
  - the 256 grid: page 4 rows 9-15 column 12 (each voice's source row; columns 11-16 are free today), and on page 1 a hold of row 16 column 8 turns columns 1-7 from lock into freeze while held;
  - 128h page 4: column 12 of rows 1-7;
  - 128v sources page: row 14, columns 1-7;
  - the 64 has no room (screen and MIDI only);
  - the param can be mapped to a MIDI CC;
  - scenes capture freeze and the freeze mode;
  - randomize and mutations never touch either.
- Freeze is never stored as audio: a recalled frozen scene freezes whatever the voice hears at the end of the transition.

### 4. Per-grain variation and scales

Every draw is a `TRand`/`TIRand` on the grain trigger, an input of the `GrainBuf`, so it is latched with the grain and costs no memory. They live in `StrataVariation.sc` (rate, pan, size) and `StrataScale.sc` (quantize).

| Param (Lua, per voice) | Engine | Range, default | Effect |
|---|---|---|---|
| `v<i>_reverse` | `reverseProb` | 0-100%, 0 | the probability that a grain plays backward |
| `v<i>_pitch_jitter` | `pitchJitter` | 0-12 semitones, 0 | rate × 2^(u × jitter / 12), u uniform in -1..1 |
| `v<i>_pan_jitter` | `panJitter` | 0-1, 0 | adds a per-grain offset to both buffers' pans (clipped at ±1), on top of the slow wander |
| `v<i>_size_jitter` | `sizeJitter` | 0-1, 0 | grain duration × 2^(u × jitter), capped at 0.5 s |
| `v<i>_intervals` | `interval1..8`, `intervalCount` | off, octaves, fifths, chord, custom; off | each grain adds one interval, picked at random from the set |
| `v<i>_interval_prob` | `intervalProb` | 0-100%, 100% | the probability that a grain takes an interval at all ("off-set" grains play at the base pitch) |
| `v<i>_quantize` | `quantize`, `scaleNote` | off/on, off | grain pitch (base × jitter × interval), the voice's MIDI notes and, for a synth voice, its `freq` param snap to the scale |
| `scale`, `root` (global) | `setScale(root, mask)` | musicutil scales or off; C | the scale everything quantizes to |

- **Interval sets.** Lua turns a set into up to eight semitone values, sent as `interval1..8` plus a count. These are separate scalar controls, named like `modBus1..3`, so `setGrainParam` and the stub's name check need nothing new.
  - octaves: -12, 0, 12;
  - fifths: -12, -5, 0, 7, 12;
  - chord: the root, third, fifth and seventh of the scale from `musicutil`;
  - custom: five intervals edited on the VOICE page, as in twine.
- **Quantize, engine side.** `setScale(root, mask)` (new, `"ii"`: root 0-11, mask a 12-bit pitch-class set) fills a 12-frame `scaleBuffer`, where each pitch class holds the offset to the nearest scale tone.
  - A grain's semitone offset `s` becomes `q(scaleNote + s) − scaleNote`, with `q(n) = round(n) + scaleBuffer[round(n) mod 12]`.
  - `scaleNote` is the voice's reference note. Lua sends the synth voice's frequency as a MIDI note, and the root for buffer and input voices (their content's key is unknown, so it is taken as the root).
  - Bend and crossmod are applied after quantizing, so they still bend.
- **Quantize, Lua side.**
  - **MIDI notes** snap in `lib/midi_in.lua`, which 2b owns.
  - **The `freq` param snaps** for each of the seven synth voices (`v<i>_freq`, which every voice SynthDef has). It is the main param (E3, arc ring 2) only on the Resonator (`MAIN_PARAMS`, `strata.lua:3009-3017`); the other six show it on the VOICE page and the 256 fader page.
  - `freq` snaps as it is turned, in steps, through a value filter that 2b registers in `S.registry.param_filters["freq"]` (§8), so 2b edits no shared param code.
  - The other main params (FM index, fold, drift, width, decay, ratio) are not pitches and never snap. A buffer or input voice's `freq` does nothing in the engine, so it quantizes grain pitch only.
- The variation params are new per-voice params. They are scene fields with the defaults above (3.1's sound), crossfade except `intervals` and `quantize` (discrete), are never touched by randomize or mutation, and show in a new VOICE section, `variation`. The global `scale` and `root` are scene globals, registered through `S.registry.scene_fields` (§8).
- **Pan jitter is added to the slow wander, not swapped for it.** The roadmap says it replaces the wander. Keeping the wander at its fixed ±0.5 keeps every old scene's stereo image, which the anti-goal requires.

### 5. Loop regions

- **Params:** `v<i>_loop_start` (0-1, default 0) and `v<i>_loop_length` (0.001-1, default 1), as fractions of the slot's valid region, in grain params `loopStart` and `loopLength`. They apply to buffer voices; Lua clamps the length to `1 − start`.
- **`bufPos`, the scan and the spread are fractions of the loop**, wrapping inside it, in `StrataLoop.sc`'s position function:

  ```
  start = loopStart + ((bufPos + scan + spreadDraw) wrap 0..1) × loopLength
  ```

  A grain starts inside the loop. It may play past the loop's end, but never past the valid region's end. Today's grain-end rule (`:663-680`) keeps holding, so short loops still get full-length grains.
- **Reverse grains in slots** must start at least a grain's frames into the region, so that they end at or after its start. The position function scales reverse starts to `[grainFrames, validFrames − grainEndMargin]` (the probe in Constraints showed a reverse grain crossing frame 0 wraps into the zeroed rest of the slot).
- The params are scene fields with defaults that reproduce 3.1 (0, 1), crossfade, and appear on VOICE in the buffer section. Grid and arc gestures are 3.3.

### 6. Mix and CPU

#### 6.1 Per-voice filter

- Inside every grain synth, after the grains: `this.voiceFilter(sig, ...)` in `StrataMix.sc`. It is the master filter's design, moved into a shared function: `RLPF`/`RHPF`/`BPF` weighted by a lagged type match, so a type change crossfades over 20 ms (`:713-729`). `SVF` would mean sc3-plugins.
- **Params:** `v<i>_filter_type`, `v<i>_filter_freq` (20-20000 Hz, exp, 5000), `v<i>_filter_res` (0-1, 0.5), `v<i>_filter_mix` (0-1, default 0, which bypasses it). They are grain params (`filterType`, `filterFreq`, `filterRes`, `filterMix`) and scene fields.
- `v<i>_filter_freq` is an LFO destination; 3.4's fast modulation lists it too.
- **Both tiers**, unless the CM3 measurement in #6 finds the 21 grain synths' 126 biquads at the worst case too heavy. The standard tier would then keep one type (`RLPF` only), and the type param would be high-only.

#### 6.2 Sends that reproduce 3.0's chain

**3.0's chain** (`:989-1007`):
- the filter: `F`, mix 0 by default;
- the delay: `out = (1 − m_d) · F(x) + m_d · Delay(F(x))` (`:739-743`);
- the reverb: `FreeVerb2` with mix `m_r`, default 0.3 (`strata.lua:1428`), `out = (1 − m_r) · in + m_r · Rev(in)`.

So 3.0's output is:

```
(1 − m_d)(1 − m_r) · F(x)  +  m_d (1 − m_r) · Delay(F(x))  +  m_r · Rev((1 − m_d) · F(x) + m_d · Delay(F(x)))
```

**3.2's routing.** Per voice, `s_d` and `s_r` (`v<i>_delay_send`, `v<i>_reverb_send`, 0-1, default 1). The global mixes `m_d` and `m_r` are broadcast on a control bus (`fxMixBus`, set by `setDelay`/`setReverb`, lagged 0.05 s in every reader as 3.0 lags them inside the effects). Each grain synth writes its filtered output `y` to three buses:

| Bus | Gain |
|---|---|
| dry | `(1 − s_d · m_d)(1 − s_r · m_r)` |
| delay send | `s_d` |
| reverb send | `s_r · (1 − s_d · m_d)` |

Then:
1. **Three master filters**, one on each bus (`\strataFilter` × 3, each with its NaN guard). The filter is linear, so filtering the three parts equals filtering their sum. The master filter stays exactly where 3.0 had it, before the delay and reverb.
2. **`\strataDelay`** reads the filtered delay send and outputs `D` (the delayed signal only).
3. **`\strataReverb`** reads the filtered reverb send plus `m_d · D`, and outputs `R` (wet only: `FreeVerb2` at mix 1, or the FDN).
4. **`\strataMaster`** reads `dry + m_d (1 − m_r) · D + m_r · R`, then drift, limiter and saturator, as now.

**With every send at 1** this is term for term 3.0's expression, including when the mixes move (an LFO or a scene fade): `m_d` and `m_r` multiply the same signals at the same points. **Where it can't match:**
- **After an explicit bypass** (§6.3). A mix at 0 keeps the effect running, exactly as in 3.0, so raising the mix reveals echoes and a tail already built. Only the explicit bypass frees the node. 3.0 had no such state; 3.1's FX K3 set the mix to 0 and back. When a bypass is lifted the effect restarts empty, so for `time` seconds (delay), or while the tail builds (reverb), it differs from 3.1's restore.
- **While the delay mix moves**, the filter sees `(1 − m_d(t)) · x` instead of filtering `x` and then scaling. The difference lasts as long as the filter's impulse response (milliseconds) and is inaudible.
- **With sends other than 1**, which 3.0 never had: the delay feeds the reverb as one source (`m_d · D`) and returns through the global `(1 − m_r)`. So the echoes of a voice with reverb send 0 are still reverberated, and a voice with delay send 0 still hears the other voices' echoes in the reverb. Each voice's own dry and wet balance follows "send × global mix" exactly. A voice whose sends are 0 plays dry at full level. It is never silenced by a high global mix, which is what plain crossfade mixes would do to it.
- `FreeVerb2`'s mix is taken to be the linear crossfade written above. The engine check confirms it by comparing a 3.2 run with all sends at 1 against check-only copies of 3.0's chain SynthDefs, for the defaults and for an LFO-swept mix.

**Engine:** the buses `dryBus`, `delaySendBus` and `reverbSendBus` (stereo, each also filtered: `...PostBus`) and `delayReturnBus`. `this.voiceOutput` in `StrataMix.sc` writes them. The mirror and crossmod are unchanged. `effectKeys` gains the two extra filter instances (`\filterDelay`, `\filterReverb`); `setFilter` sets all three.

#### 6.3 Bypass frees CPU and memory

**Only an explicit bypass frees anything; it is independent of the mix** (Call made in review).
- **A mix of 0 just silences.** An LFO, a scene fade, PARAMS or a MIDI CC taking `delay_mix` or `reverb_mix` to 0 leaves the node running, exactly as in 3.0, so mixes can move through 0 freely and never create or free nodes.
- **The bypass state** is two binary params, `delay_bypass` and `reverb_bypass` (off by default), in the fx group (registered by 2d through the fx-group registry 0c adds, §8).
  - On the FX page, K3 on the delay or reverb row toggles them. This replaces 3.1's "set the mix to 0 and restore the last non-zero mix" for those two rows. The filter row keeps 3.1's mix toggle, because the filter is never freed (below).
  - The mix params keep their values while bypassed, so lifting the bypass returns to the same mix.
- **PSETs store the bypass params; scenes do not.** A bypass is a CPU and setup choice, like the performance setting, not part of a sound to crossfade into. A scene transition can't fade into an effect that has no node, and a recall freeing and creating nodes in the middle of a fade would cost a `/s_new` with the 1 MB `DelayC` allocation at the worst moment. Scenes keep capturing and crossfading the mixes. If a scene's delay mix is above 0 while the delay is bypassed, the FX row shows `byp` and the delay stays silent.
- **Engine:** `engine.setBypass(effect, bypassed)` (new, `"ii"`: effect 0 = delay, 1 = reverb, others ignored; bypassed 0 or 1).
  - On a bypass, the engine first broadcasts that effect's mix as 0 on `fxMixBus`, so the dry gains of §6.2 return to full and nothing jumps. It then waits for the 0.05 s lag plus one block and frees the node. Freeing `\strataDelay` returns its 1 MB `DelayC` to the pool.
  - Lifting the bypass re-creates the node in its place (`\addAfter` the reverb-send filter for the delay, before the master for the reverb) from the stored controls, then broadcasts the stored mix, which fades in through the lag. The new line starts silent: delay UGens output zeros until filled.
  - `setDelay`/`setReverb` while bypassed store their values (`setSynth` ignores the missing node) and keep the broadcast mix at 0.
- **The master filter is not freed.** Its three instances are cheap, they carry the NaN guard, and freeing them would leave their output buses unwritten (silence).
- These nodes still never end on their own: the engine frees and creates them, so messages to them stay plain (`effectKeys`).
- **Fast toggling:** a bypass lifted inside the wait cancels the free, and a free in flight finishes before the re-creation. The engine check toggles the bypass at 20 Hz for 2 s and finds at most one delay node, and none once it settles bypassed. It also sweeps the mix through 0 with an LFO-rate series of `setDelay`s and finds the node never freed.
- Free and re-create was chosen over the roadmap's `/n_run 0` (Decision 3). Should it ever need to change, the change is local to `StrataEffects.sc`.

#### 6.4 High-tier reverb

A core-UGen feedback delay network, `\strataReverbFDN`, in `StrataEffects.sc`:
- four `AllpassN` input diffusers (about 5-30 ms);
- eight `DelayL` lines of prime lengths (about 30-110 ms, scaled by `size`) in a Householder feedback matrix built with `LocalIn`/`LocalOut`;
- per-line damping (`OnePole`, from `damp`), and slow `LFNoise1` modulation of two lines' lengths against metallic ringing;
- the stereo output tapped from alternate lines.

`size` sets the decay (feedback gain) as well as the line lengths, `damp` the damping, and `mix` stays the return level (§6.2). The command is unchanged (`setReverb`, `"fff"`). It is chosen at `alloc` by the tier (standard keeps `FreeVerb2`). RT memory is about 300 KB, against `FreeVerb2`'s roughly 120 KB, measured in the check. The FDN's defaults should land near `FreeVerb2`'s decay at size 0.8: the check measures the RT60 of both and requires them within 30%.

### 7. Longer buffers (high tier)

- **`bufferSeconds`** is set by the performance area (first in `order`) before the buffers are allocated (`:122-123`, then in `StrataBuffers.sc`). `recordBuffer` and `loadBuffer` already cap at it (`:1530`, `:1641`). CLAUDE.md's rows say "at most `bufferSeconds` (16 s standard, up to 300 s high)".
- **Loads.** The decode check is synchronous today (`fileDecodes`, `:1532`): about 9 ms for a 16 s FLAC on a desktop, so seconds for 300 s on a Pi.
  - For files longer than 16 s at the server rate it runs in a routine that yields between chunks.
  - The load takes effect (`slotChanged`, zeroing, read) only after the check. If another load, record or clear of the slot arrived meanwhile, the check is dropped, reporting nothing, as a superseded load already does.
  - `bufferLoads` still counts at the command, so `bufferLoadFailed`'s numbering is unchanged.
- **Saves.** The interleave is a per-frame sclang loop (`:1851-1864`). A 16 s take takes about 0.06 s on a Mac, so expect 1 s on a Mac and several seconds on the Pi 4 for 300 s.
  - It already yields after every 8192-frame chunk (`writeChunkWait.wait`, `:1862`), so nothing stalls and no change is needed there. A long save just takes time.
  - The temporary files are one mono float file per channel: for 300 s, 300 × 48000 × 4 bytes = 57.6 MB each, 115 MB per save, in `Platform.defaultTempDir`.
  - Package 2e measures a 300 s save on the Pi 4. If it takes more than 10 s, it writes the temporaries as `int16` and interleaves them (half the data), or uses `sox -M` when `sox` is on the path, keeping the sclang loop as the fallback. The `.part`, generation and stale-file rules (`:1790-1829`) cover every path.
- **Clears and records** zero up to 115 MB per slot (two 57.6 MB mono buffers; `b_zero` on the server's non-realtime thread, about 50-100 ms on a Pi 4). Fade-before-zeroing already waits for the fade, not the zeroing, so nothing changes.
- **`bufScan`** moves in valid-region lengths per second (`:657`), so a 300 s slot scans 300 s per second at scan 1. Loop regions (§5) are the answer. A seconds-based scan mode is a 3.3 candidate, noted in status.

## Cost if wrong

- **Pitch by rate (accepted).** A user who wants 3.0's smeared shift on a synth voice has no switch back. A `PitchShift` insert as an optional per-voice mode would cost 128 KB per synth again, only when chosen.
- **Rings at 4 s.** If high-pitch, reverse and spread grains need more, the ring grows in one constant (10.8 MB of RAM per 4 s across the voices, no real-time memory).
- **The engine decides the tier.** If a board is misdetected, `standard` or `high` forces it from SETUP at the next start. A board whose model string is new falls to standard.
- **Engine split into extension files.** If norns ever stops compiling `~/dust` recursively, every script with a `lib/` engine breaks, not only Strata. Merging the files back is mechanical.
- **Effects mapping (Decision 1).** If plain sends are wanted later, only `voiceOutput`'s three gains and the master's sum change, plus a scene migration rule for the mixes.
- **Triggered grains shortened at high pitch (Decision 2).** If short grains sound thin, the cap can move from one grain length to two in one constant. The cost is accents up to two grain lengths late.
- **FDN reverb (Decision 4).** If its sound disappoints, JPverb needs sc3-plugins in CI. `FreeVerb2` stays the standard tier's reverb either way.
- **Freeze on VOICE only (Decision 5).** If freezing from MAIN proves too slow in performance, MAIN ALT+K3 can take it once 3.1's hardware check settles K1-as-ALT. Lock would then live on VOICE only.
- **Free-and-recreate bypass.** If re-creation ever finds the pool too fragmented for the delay's 1 MB block, the delay stays off with a console line. Measured headroom (§2.7) makes that unlikely; `/n_run 0` is the fallback. Because only the explicit bypass frees, an LFO or scene can never cause it.
- **Bypass outside scenes.** If performers want scenes to switch effects in and out, the bypass params become discrete scene fields, applied at the end of a transition. The cost is one node creation per recall that changes them.
- **128-grain tables on high.** Density stays at 100 on both tiers. If 3.5's measurements leave room, `maxGrains` is already a tier value in `performance_active.data`, so raising it is one constant plus the Lua density maximum.
- **Input freeze at the read point.** A performer who expected freeze to grab "now" while history is set far back hears the delayed audio held instead. That is the point of the ruling (no jump); setting history to 0 before freezing gives "now".
- **Freeze cleared by a source switch.** If performers want freeze to carry over, the Lua source action stops clearing it, and the engine freezes the new source at once.
- **Per-voice filter on the CM3.** If it is too heavy, the standard tier keeps the lowpass only (§6.1).

## Calls made in this design

**Calls made in review** (the builder check of 2026-11-07, ruled by the coordinator):
- **Memory floors from 3.5's arithmetic** (§2.7):
  - a note stream is about 35 KB with 128-grain tables, about 59 KB with 256 (measured by 1b on SuperCollider 3.14.1: about 50 KB with 128; see the correction in §2.7);
  - streams replace a voice's single grain synth, and today's lifecycle gives up to 3N per voice;
  - the floors are 3 MB free on standard and 4 MB on high at 3.2's worst case, and 1b's `memory` area enforces them;
  - 256-grain tables don't fit with margin, so high keeps `maxGrains` 128 and density 100;
  - six notes on high is left to the 3.5 design to make fit.
- **Bypass is explicit and independent of the mix** (§6.3):
  - only `delay_bypass`/`reverb_bypass` (FX K3, PARAMS, PSETs; not scenes) free and re-create the node, through `setBypass`;
  - a mix at 0, from an LFO, a scene fade or PARAMS, only silences.
- **Input freeze copies the 4 s ending at the voice's current read point**, history included, so freezing never jumps to the present (§3).
- **The engine split adds every hook later packages need** (§0):
  - area registration, from which `controlNameSets`, `effectKeys`, the grain-def table and the grain-param handlers are built;
  - `areaState`;
  - settable tier variables, and classvars for the settings, model and meminfo paths;
  - so no package after Wave 0 edits `lib/Engine_Strata.sc`.
- **Lua's shared spots go through registries 0c owns** (§8): source-change hooks, scene fields, param filters, LFO destinations, fx params and `S.performance`. Every remaining shared Lua file has one owner per wave.
- **No freeze key on MAIN**, because 3.1 gives ALT+K3 to lock on MAIN and VOICE. The freeze key was then decided on 2026-11-08 (Decision 5).
- **Scale quantize snaps grain pitch, MIDI notes and each synth voice's `freq` param.** It is the main param only on the Resonator; non-pitch main params never snap.
- **1b re-checks the wrap, reverse and memory facts on SuperCollider 3.13**, the version norns and CI run.

**Calls made in the first draft:**
- The engine decides the tier at `alloc` from the saved setting, the board model and `/proc/meminfo`, and writes `performance_active.data`, which Lua reads in `init`. The engine runs high only if that write succeeded.
- An explicit `high` is honored on any board, with a warning on a CM3 or Pi 3. `auto` never picks high there.
- The high tier: buffer length 16/60/120/300 s, default 60 s, stepped down to leave 1 GB free; input history 60 s. Its first-draft `maxGrains` 256 and density 200 were withdrawn in review.
- `bufferStateStride` becomes 1000.
- Two grain SynthDefs (`\strataGrainRing`, `\strataGrainBuf`) built by one function; `\strataGrain` removed.
- Ring writers are persistent nodes at the tail of `voiceGroup`, publishing their phase on control buses; freeze pauses them with `/n_run 0`.
- 4 s voice rings; ring rates clipped to ±4; grain duration after size jitter capped at 0.5 s.
- Ring grains start `margin + history + spread + max(r − 1, 0) · dur` back; reverse grains read older audio from `margin + history + spread`. Triggered grains above rate 2 are shortened instead (Decision 2).
- Position spread for ring sources is a backward random offset up to 0.5 s × spread; triggered mode ignores it, as 3.0 did.
- Input history is a new param (`v<i>_history`), not a reuse of `buf_pos`.
- The input source gains `bend` and frequency crossmod, through the grain rate.
- Input freeze copies 4 s into the voice's idle ring; the input ring has 1 s of extra guard for the copy. Spectral freeze lives in the ring writer (synth and input only) and is high-tier only.
- A source switch unfreezes. Grid freeze controls on the 256 (page 4 column 12, and a row 16 column 8 hold on page 1), 128h page 4 column 12 and 128v row 14; none on the 64. A `freeze` row on the VOICE page and `[F]` on MAIN.
- Pan jitter adds to the slow pan wander instead of replacing it, so old scenes keep their stereo image.
- One global scale and root; quantize per voice; grain quantize relative to `scaleNote` (the synth's note, or the root for buffer and input voices); new commands only where no grain param fits: `setScale(root, mask)` and `setBypass(effect, bypassed)`.
- Interval sets as eight scalar controls plus a count and a probability.
- Loop regions apply to grain starts; a grain may play past the loop end but never past the valid region; reverse grains in slots start at least a grain into the region.
- The per-voice filter is after the grains, inside the grain synth, using the master filter's core-UGen design, on both tiers unless the CM3 measurement says otherwise.
- The master filter stays where it was, applied to the dry, delay-send and reverb-send buses (three instances, exact by linearity), and is never freed.
- Randomize and mutations leave every new param alone.
- 3.2's new per-voice params stay off the 256 fader pages (`fader = false`), so today's faders don't move.
- Long loads decode in a routine; long saves are measured before any rewrite.

## Decisions (2026-11-08)

The five questions of the draft were decided as recommended. The body above is written to match.

1. **Effects mixes: keep 3.0's crossfade mixes, with per-voice sends as multipliers** (§6.2). It is exactly 3.0 at all sends 1, even with moving mixes, and a voice with send 0 plays fully dry.
   - Rejected: plain send/return (old scenes' dry about 3 dB louder at the default reverb), and the serial chain with no sends.
2. **Upward pitch on synth and input voices: continuous grains start further back; triggered grains are shortened** (§2.3).
   - In continuous mode a grain at rate r starts `(r − 1) × dur` back, with full-length grains (1.5 s back at pitch 4 with 0.5 s grains).
   - In triggered mode, grains above rate 2 last `dur / (r − 1)`, so the lookback never exceeds one grain length.
   - Rejected: the same rule in both modes, either way.
3. **Bypass frees and re-creates the delay and reverb** (§6.3). Only the explicit bypass param triggers it (Call made in review). CPU and memory come back, and the effect restarts empty.
   - Rejected: `/n_run 0` (CPU only, and a resumed delay replays audio from before the pause).
4. **High-tier reverb: a core-UGen FDN** (§6.4), so CI and every norns stay identical.
   - Rejected for 3.2: JPverb from sc3-plugins. It stays a later option once CI carries sc3-plugins for another reason.
5. **Freeze lives in a `freeze` row on the VOICE page, plus the grid keys of §3 and a MIDI CC mapping** (§3). No 3.1 key changes: ALT+K3 stays lock on MAIN and VOICE, and the control works under 3.1's long-press fallback. MAIN shows `[F]`.
   - Rejected: K3 held on MAIN (it collides with the long-press fallback and delays start/stop), grid and MIDI only (not playable from the norns alone).
   - Deferred: MAIN ALT+K3 as freeze with lock on VOICE only. It can be revisited after 3.1's hardware check.
