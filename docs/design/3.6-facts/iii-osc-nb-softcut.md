## 1. iii

### 1a. Devices and modes
- Grids: "2022 and later grids (includes grids one and zero)" run iii; 2020-2021 grids have a different microcontroller and cannot; grids with an FTDI USB-serial chip cannot do USB-MIDI so cannot run iii. https://monome.org/docs/iii/
- Arc: only the 2025 edition (it has a pushbutton) ships with iii support, and may need a firmware update. https://monome.org/docs/iii/
- The iii page does not list sizes. The editions page lists: 2023 "zero" 16x16 and "one" 8x16, both RP2040; 2022 grid is RP2040, size not stated; it does not say which are iii-capable. https://monome.org/docs/grid/editions/
- iii repo README: "a Lua interface for rp2040-based devices" with a USB-serial REPL, USB-MIDI, and a small onboard flash file system; sub-repos for grid one, grid zero, grid 2022, arc. https://codeberg.org/tehn/iii (readme.md)
- Mode switch: hold a key while powering up (key 1,1 top-left on a grid; the only key on an arc). Start-up light pattern: "particles" = serial/monome mode, "plasma" = iii mode with a blank script. Holding the key through the timer animation while entering iii mode force-clears a locked-up script. https://monome.org/docs/iii/
- A USB host in iii mode sees USB-MIDI and also USB-TTY (CDC serial, for file transfer and live scripting). https://monome.org/docs/iii/ ; `CFG_TUD_MIDI` 1 and `CFG_TUD_CDC` 1, MSC/HID/vendor 0: https://codeberg.org/tehn/iii/raw/branch/main/tusb_config.h
- The USB MIDI device name was not found in any fetched source.
- In iii mode the device is not serialosc/monome-serial (inference from "switch modes"; the pages say only that the two are alternative modes). Old FTDI grids use serialosc; norns grid handling is unchanged by iii.

### 1b. Script API (current docs, https://monome.org/docs/iii/code)
- Grid: `event_grid(x,y,z)` callback; `grid_led(x,y,z,rel)`; `grid_led_get(x,y)`; `grid_led_all(z,rel)`; `grid_intensity(b)`; `grid_refresh()`; `grid_size_x()`; `grid_size_y()`. `rel` true adds z to the current value.
- LED value range for z is NOT stated on the code page. LED changes are queued until `grid_refresh()` (search-result summary of an older copy of the docs, not confirmed on the current page).
- Arc: `event_arc(n,d)` (ring n, delta d); `event_arc_key(n,d)` as printed on the page (the page copies `event_arc`'s description; the porting page and changelog say `event_arc_key(z)`, one argument); `arc_res(n,div)` (default 1; higher = coarser); `arc_led(n,x,z,rel)`; `arc_led_ring(n,z,rel)`; `arc_led_all(z,rel)`; `arc_intensity(b)`; `arc_refresh()`.
- MIDI: callback `event_midi(byte1,byte2,byte3)`; `midi_out(table)` ("data bytes or msg", sent to the USB MIDI port); `midi_note_on(note,vel,ch)`; `midi_note_off(note,vel,ch)`; `midi_cc(cc,val,ch)`; `midi_to_msg(data)` (decode to a table). Source: code page above.
- Raw byte send is `midi_tx(data1,data2,data3)` (3 bytes, each cast to uint8) registered in main_lib. https://codeberg.org/tehn/iii/raw/branch/main/vm.c ; `midi_tx` writes `tud_midi_stream_write(cable 0, packet, 3)`: https://codeberg.org/tehn/iii/raw/branch/main/midi.c
- Defaults in lib.lua: channel 1, note 66, velocity 100, cc 1, value 100. Status byte = base + (ch-1) (0x90 note-on, 0x80 note-off, 0xb0 CC); pitch bend is LSB first. `midi_to_msg` returns note-on with velocity 0 as `note_off`. Source: lua/lib.lua summary via https://codeberg.org/tehn/iii/raw/branch/main/lua/lib.lua
- Receive path: `midi_task` drains `tud_midi_available()` and calls `rx_callback(packet[1], packet[2], packet[3])`; so `event_midi` gets the three message bytes with the status byte first (not ch, status, d1, d2). `vm_handle_midi` calls the global `event_midi` with three integers; nil = ignored. https://codeberg.org/tehn/iii/raw/branch/main/midi.c , vm.c
- Sysex: no documentation on the code page. In lib.lua `midi_to_msg` returns `{type="sysex", raw=data}` for data starting 0xF0, and `midi_out` on a raw byte array sends via `midi_tx_many`, which sends 3 bytes at a time (last call gets nil arguments if the length is not a multiple of 3); the F7 end byte is not checked. Whether a host sysex message arrives intact via `event_midi` (3 bytes per call) and whether sysex sent out is framed correctly by the stream writer is not verified.
- Timing: `m = metro.init(callback,time_sec,count)`; `m:start(time)`; `m:stop()`; `m.time`; `m.free(m.id)`; `m.free_all()`; "limited to 15 total" (docs). lib.lua pool is described as 12 slots in one fetched summary: the two numbers disagree and neither is confirmed. Callback `metro_event(index,count)` in C. `get_time()` returns float seconds, microsecond precision. `slew.new/to/freeze/allfreeze/stop/allstop`. No clock-sync (beat) functions are listed.
- Storage: `pset_init(name)`, `pset_write(index,table)`, `pset_read(index)`, `pset_delete(index)`; files `pset_name_xx.lua`. File functions `fs_read_file`, `fs_run_file`, `fs_write_file`, `fs_remove_file`, `fs_list_files`, `fs_file_size`, `fs_free_space`, `fs_reformat`; helpers `ls`, `cat`, `rm`, `mem`, `gc`, `require`, `first`, `device_id`, `device_version`, `dostring`, `ps`, `pt`, `clamp`, `round`, `linlin(n,slo,shi,dlo,dhi)`, `wrap`. https://monome.org/docs/iii/code ; changelog https://codeberg.org/tehn/iii/raw/branch/main/changelog.md
- Boot: `lib.lua` runs first (rewritten if missing or its first 24 bytes lack `III_VERSION`), then a GC pass, then `init.lua` if present. `first('name.lua')` writes an `init.lua` that runs that script; `first()` clears it. Source: vm.c `vm_init`; code page; changelog.
- Lua: C uses the standard Lua C API with `lua_isinteger` (so 5.3+; probably 5.4, inferred from vm.c, not stated). Memory: custom `realloc` allocator, "out of memory" triggers a watchdog reboot; no size limit coded; heap size not stated; script size and script count limits not stated. https://codeberg.org/tehn/iii/raw/branch/main/vm.c

## 2. OSC on norns

- norns listens on port 10111 by default (`remote_port`, overridable with `-o`); it registers a catch-all handler and advertises `_osc._udp` via DNS-SD as "norns". NORNS/matron/src/args.cc:21, :51; matron/src/osc.cc:34-38.
- Every received message becomes an event; the sender is read with `lo_message_get_source`, and its host and port are passed to Lua as `from` = `{host, port}`. matron/src/osc.cc:64-85; weaver `w_handle_osc_event`, matron/src/weaver.cc:2528 (arg types int32, float, string, blob, int64, double, symbol, char are converted).
- `_norns.osc.event(path, args, from)` first calls the script's `osc.event(path, args, from)` if non-nil, THEN does the built-in handling regardless: `/param*` goes to `param_handler`, `/remote*` goes to `remote_handler`. A script that sets `osc.event` therefore keeps the built-ins. NORNS/lua/core/osc.lua:112-123.
- `/param` handler: path split on `/`; accepted forms are exactly `/param/<id> <value>` (pset id "" = the global `params`, created with `paramset.new()` and no id) and `/param/<pset_id>/<id> <value>`; 2 or 3 parts total, `/param` is parts[1]. Value is `args[1]` (error if nil). It calls `param:set(value)`, i.e. the param's real value (for a control, in its own units such as Hz or dB, not 0-1), and the action runs (silent flag not passed). `lookup_param` raises "invalid paramset index" for an unknown id (inside the event call, reported, not fatal). osc.lua:55-89; paramset.lua:93-102 (`ps.id = id or ""`, `ParamSet.sets[ps.id]`), :485-493; lua/core/startup.lua:31; params/control.lua:68-70 (`set` maps real value; `set_raw` is 0-1).
- A string starting with "/param" also matches paths like "/paramfoo" (`util.string_starts`), and the handler then fails the part count or finds no param. osc.lua:116.
- `/remote/key`, `/remote/enc`, `/remote/brd`: command is `path:sub(1,11)`; with 2+ args, n, val = args[1], args[2]; else n = number after `/remote/key/` (character 13 on) and val = args[1]. `/remote/key` calls `_norns.key(n,val)`; `/remote/enc` calls `_norns.enc(n,val)`; `/remote/brd` calls `keyboard.process(1,n,val)`. osc.lua:92-109.
- Send: `osc.send({host, port}, path, args)` (args optional); `osc.send_crone(path, args)` goes to sclang. A new `lo_address` is created per send; the destination must be known (no broadcast code in osc.cc; a UDP broadcast address as host was not tested/verified). osc.lua:31-48; matron/src/osc.cc:50-62.
- Feedback: norns' built-in param handling sends nothing back (osc.lua has no send in `param_handler`); the script must send feedback to `from` or a configured host.
- Cleanup: `osc.cleanup()` sets `OSC.event = nil`, called at script reset. lua/core/script.lua:74; osc.lua:51-53. NOTE this sets the field to nil; the built-in dispatcher still runs.
- Two-part `/param` handling reads `args[1]` only; Lua booleans/strings pass through to `param:set` unchecked (option params expect an index, not a name; not verified beyond reading osc.lua).

## 3. TouchOSC

- Current TouchOSC `.tosc` is a zlib-compressed XML tree (root `lexml`, version 3 in tosclib docs). Libraries that generate it: py2tosc (Python 3.10+, no dependencies, all control types, OSC, MIDI, Lua scripts; saves `.tosc`, XML or JSON) https://pypi.org/project/py2tosc/ ; tosclib (unaffiliated with Hexler) https://albertov5.github.io/tosclib/docs/build/html/guide/1-tosc-files.html , https://github.com/AlbertoV5/tosclib . So a layout can be generated by script; the schema is unofficial/reverse-engineered, not documented by Hexler (not verified).
- Hexler says the newer editor's document format is not compatible with the TouchOSC Mk1 app (search summary of hexler pages); hexler.net manual says documents "can be freely exchanged between all versions of the application" (https://hexler.net/touchosc/manual/getting-started-file-formats) - the two statements are about different things and were not reconciled.
- Message addressing: an OSC message's address is built from partials (CONSTANT, INDEX, VALUE, PROPERTY) evaluated left to right; each argument partial becomes one argument, typed BOOLEAN, INTEGER, FLOAT or STRING; range scaling `out = min + in * (max - min)`; send triggers ANY / RISE / FALL; no default address (the user configures partials). https://hexler.net/touchosc/manual/editor-messages-osc
- Feedback: a message has receive flags; an incoming message that matches the address updates the control's values; a "feedback" flag (off by default) controls re-sending after a received change, with a warning about loops. Same page. TouchOSC therefore needs the host to send OSC to the device's Receive Port.
- Connections: ten OSC connections, each with its own send destination and receive port; types UDP, TCP Client, TCP Server (OSC 1.0 size prefix or 1.1 SLIP); host + send port needed to send; receive port to listen; Zeroconf advertise/browse. https://hexler.net/touchosc/manual/connections-osc
- Scripting (onReceiveOSC / sendOSC): exists (manual sidebar "Scripting API") but the exact message-object format was not read. Not verified.
- Mk1 `.touchosc`: a zip package holding `index.xml` (root `<layout>` with `<tabpage>`/`<control>` children, version attribute 15 or 17 seen in different examples); editable by renaming to `.zip`. Sources: https://www.matrixsynth.com/2011/07/how-to-edit-mass-parameters-in-touchosc.html , https://hexler.net/touchosc-mk1/manual/configuration-layout (search summaries, not read in full).

## 4. softcut

- `softcut.VOICE_COUNT = 6`; `softcut.BUFFER_SIZE = 16777216 / 48000` (about 349.5 s per buffer); two buffers (`SC.buffer(i,b)`, 1-based). NORNS/lua/core/softcut.lua:17-20, :119. C++: `BufFrames = 16777216`, `NumVoices = 6`, `buf[NumBuffers][BufFrames]`: crone/src/SoftcutClient.h:25-26, :39. Voice i defaults to buffer `(i%2 + 1)`, loop `(i-1)*2` to `(i-1)*2+1` (softcut.lua:417-478).
- Engine into softcut: `audio.level_eng_cut(value)` (linear amplitude) calls `_norns.level_ext_cut(value)`. lua/core/audio.lua:358-360; weaver.cc:467, :3163-3168. System param `cut_input_eng` ("input engine", dB, applies `util.dbamp`) holds the menu value, default 0 dB. audio.lua:882-889; lua/core/state.lua:45. The ADC, tape and cut-to-reverb levels are `audio.level_adc_cut`, `level_tape_cut`, `level_cut_rev` (audio.lua:352-372).
- Softcut level into the output: `audio.level_cut(level)` (`_norns.level_cut_master`), audio.lua:187-189; system param `softcut_level` (dB, up to +6, -inf min), audio.lua:649-656 and state.mix.cut.
- Input routing per voice: `softcut.level_input_cut(ch, voice, amp)`; ch 1-2. softcut.lua:47. Voice output `softcut.level(voice, amp)`, `pan`; `play(voice,1)`, `rec(voice,1)` (`rec_flag`), `enable(voice,1)`, `buffer(voice,b)`, `position(voice,s)`.
- Loop and record calls: `loop_start(voice,pos)`, `loop_end(voice,pos)`, `loop(voice,state)`, `rate(voice,rate)`, `rate_slew_time(voice,t)`, `fade_time(voice,t)`, `rec_level(voice,amp)`, `pre_level(voice,amp)` (the preserve level of old audio; 1 keeps all, lower decays on each pass), `rec_offset`, `level_slew_time`, `recpre_slew_time`, `level_cut_cut(src,dst,amp)`, `voice_sync(dst,src,offset)`. softcut.lua:31-126, :232-249. Defaults: fade_time 0.0005, rec_level 0, pre_level 0, rate 1, rate_slew 0.001, loop 1 (softcut.lua:417-478). Note `pre_level` default 0 means a recording voice erases what it overwrites unless set.
- Filters: `pre_filter_fc/fc_mod/rq/lp/hp/bp/br/dry` and `post_filter_fc/rq/lp/hp/bp/br/dry` per voice; defaults pre fc 16000 lp 1 dry 0; post fc 12000 with all outputs 0 (softcut.lua:131-228, :417-478). `filter_*` are aliases of `pre_filter_*` (softcut.lua:179-186).
- Phase: `softcut.phase_quant(voice, seconds)` (default 1), `phase_offset`, `poll_start_phase()`, `poll_stop_phase()`, callback `softcut.event_phase(function(voice, phase) end)`; `query_position(i)` with `event_position(func)`. softcut.lua:257-268, :372, :391-397.
- Reset on script load/unload: `script.reset()` calls `softcut.reset()` after `poll.clear_all()` and engine clear; `SC.reset()` calls `_norns.cut_reset()` and `event_phase(norns.none)`. NORNS/lua/core/script.lua:85-89; softcut.lua:405-409.
- What the C++ reset does: clears both buffers entirely, resets each voice (buffer pairing, out level 0, pan 0.5, disabled, phase quant 1, offset 0, input/feedback matrices 0, loop points), stops the phase poll. crone/src/crone.cpp:103-111; crone/src/SoftcutClient.cpp:248-275. It does not touch the audio mixer levels (`audio.level_eng_cut`, `level_cut`, etc.) which belong to `audio.lua` and the system params, so a script that sets those directly must restore them itself (system params `cut_input_eng`, `softcut_level` hold the user values; a `params:bang()` of system params was not checked).
- Cleanup consequence: the next script starts with empty softcut buffers and no voices enabled; the phase callback is cleared. A script's own recorded loop is lost on cleanup (clear on reset), so saving needs `softcut.buffer_write_stereo(file,start,dur)` or mono before cleanup. softcut.lua:358-370.
- Audio routing: if a script changed jack ports, `audio.routing_default()` is restored on cleanup (script.lua:92-96); softcut level calls are not routing.

## 5. nb

- Include (README): add as a submodule, `git submodule add https://github.com/sixolet/nb.git lib/nb`, update with `git submodule update --remote`; then in init: `nb:init()`; `nb:add_param("voice_id", "voice")`; `nb:add_player_params()`; get a player with `params:lookup_param("voice_id"):get_player()`. https://raw.githubusercontent.com/sixolet/nb/main/README.md . The exact Lua `include` line (commonly `local nb = include("lib/nb/lib/nb")`) is not in the fetched README text: not verified.
- So nb is vendored in the host's `lib/nb` as a submodule, not found in `dust/code/nb`; its code finds its own directory via `_path.code` (`nb.lua` line 1) and includes `player` from there. https://raw.githubusercontent.com/sixolet/nb/main/lib/nb.lua:1-2
- `nb.lua` functions: `nb:init()` (resets refcounts, adds MIDI players from `midi.vports`, calls `stop_all()`); `nb:add_param(id, name)` (voice-select option plus hidden string param, one-second delayed init); `nb:add_player_params()` (adds each player's params once); `nb:get_players()`; `nb:stop_all()`. `nb.voice_count` (default 1) set before init. Global `note_players` table is where mods register players "before you call nb:add_param". nb.lua (same URL).
- MIDI players are built for every connected MIDI vport at the time the script starts (name `"midi: <abbr> <j>"`): channel param default 1, mod CC default 72, bend range 12; velocity = `floor(127*vel)`; only `pressure` is handled as a note modulation key. nb.lua lines 25-108 (summary).
- No MIDI port or mod: the list contains only "none"; selecting "none" returns `nb.none` (an empty player whose methods are no-ops). So a host works with nb absent from voices as long as the library files exist in `lib/nb`; if the submodule is missing, `include` fails (the host must pcall the include to degrade; not documented by nb).
- Player interface (`lib/player.lua`): `note_on(note, vel, properties)`, `note_off(note)`, `play_note(note, vel, length, properties)` (length in beats via `clock.get_beat_sec()`; default calls note_on then note_off after the delay in a clock), `modulate_note(note, key, value)` (-1..1, key in `note_mod_targets`), `pitch_bend(note, amount)` (semitones), `modulate(val)` (0..1), `modulate_voice(key, val)`, `set_slew(slew)` (seconds), `add_params()`, `stop_all()` (for pset load), `active()` / `delayed_active()` (after 1 s) / `inactive()`, ref-counted via `count_up`/`count_down`. `describe()` returns `name`, `supports_bend`, `supports_slew`, `modulate_description`, `note_mod_targets`, `voice_mod_tarets` (misspelled key in source), `params`. Default for the supports flags is false. https://raw.githubusercontent.com/sixolet/nb/main/lib/player.lua
- A `stop_all` key also exists on `describe()` per the question; the fetched player.lua summary lists it only as a method, not a describe field: not verified as a describe field.
- Cleanup: nb.lua has no cleanup hook; the host should call `nb:stop_all()` (the comment asks callers to call it on pset load); what mods do on script cleanup is not documented in the fetched files (not verified).
- Voice mods (all external repos; install as norns mods, not part of nb): `nb_crow` (pitch/env on crow outputs 1+2 or 3+4, tune param; page does not mention ii devices) https://github.com/sixolet/nb_crow ; `nb_jf` (eight Just Friends voices: six mono, one unison, one poly) https://github.com/sixolet/nb_jf ; `nb_drumcrow` (a player for each of crow's four outputs) https://github.com/entzmingerc/nb_drumcrow ; `nb_ex` (Disting EX) https://github.com/sixolet/nb_ex ; `nbout` (a virtual MIDI device exposing nb voices to MIDI-output scripts) https://github.com/sixolet/nbout ; `nbin` (MIDI input into nb, tested with Linnstrument MPE and Emplaitress) https://github.com/beels/nbin ; `nb_midiconfig` (per-device config of MIDI voices) https://github.com/dstroud/nb_midiconfig . Emplaitress itself, a w/syn mod and an `nb_midi` repo were not found.

## Surprises
- `audio.level_eng_cut` calls `_norns.level_ext_cut` (not `level_eng_cut`); fine, but grep for the C name `level_ext_cut` if tracing.
- A script's `osc.event` does not replace the built-in `/param` and `/remote` handling; both always run. `osc.cleanup()` only nils the script hook.
- Built-in `/param` takes real values (Hz, dB), not 0-1, and sends no feedback; the 3-part form is `/param/<pset_id>/<id>`, with the global set's id being "".
- iii's `event_midi` receives `(status, data1, data2)` in order, not `(ch, status, d1, d2)`; older docs and the `midi_rx` name are obsolete after v1.1.0; the API has had breaking changes as recently as 2026-03 (v1.1.0).
- iii's `midi_out` with raw bytes sends in 3-byte groups; there is no built-in sysex framing.
- nb is vendored as a git submodule in the host's `lib/nb`; nb has no declared license; the nb README names no voice mods; crow/JF/Disting EX voices exist, w/syn and Emplaitress voices were not found.
- softcut reset clears both 349 s buffers, so a loop does not survive a script change.
