# AGENTS.md

This file gives coding agents guidance for working in this repository. It is an index: the rules every change needs, the engine command interface and how to run the checks. Each module's details are in its own notes file (see the module table): read that file before changing the module.

## Project Overview

Strata is an ambient granular soundscape generator for monome norns. It has seven synthesis voices (Resonator, FM, Folder, Sub, Pulse, Karplus, Ring), each with its own granular processor. Any voice's grain stage can read one of eight stereo sample buffers or the live input instead of its synth. A filter, delay and reverb, six global LFOs, MIDI input, scenes, an eight-page screen UI (MAIN, VOICE, SEQ, FX, LFO, BUFFER, SCENES, SETUP), grid and arc complete it. Version 3.0 added the buffers and live input, the filter and delay, grain envelopes and triggered grains, the LFOs, MIDI and the paged screen. Version 3.1 made everything playable from the norns alone: the VOICE, SEQ and SCENES pages, K1 held as ALT, lock, randomize undo, fine adjustment and center detents, arc rings on every page but SETUP, and grid pages per grid, with the script split into `lib/` modules. Version 3.2 added the performance setting (a high tier on the Pi 4, with buffers up to 300 s), one grain path for every source, freeze per voice, grain variation and scale quantize, loop regions, input history, a filter and sends per voice and effect bypass, with the engine split into `lib/engine/` areas. Version 3.3 made the buffers instruments: overdub and loop recordings that play while they record (grains steer around the record head), record sources, threshold and clock-synced takes, random loads, a long file's start point, trim saves, waveforms, playheads, position jumps and bookmarks, arc scrub with friction and a position page on every grid, with one mix stage per voice holding its filter and sends; it also carries the fixes of a whole-project review and two audits (the state invariants checked after every unit test among them), safe data files and the Pulse res turned the right way. The current release is 3.3.2 (see CHANGELOG.md).

## Architecture

The project is written in two languages that must stay in sync:
1. **`strata.lua` and its `lib/*.lua` modules** (the norns script): UI, params, encoders/keys, grid, arc, MIDI and LFOs. They control the engine through `engine.*` commands.
2. **`lib/Engine_Strata.sc` and its `lib/engine/Strata*.sc` class extensions** (the SuperCollider engine): all synthesis and audio processing. It exposes commands with `this.addCommand()`. `lib/Engine_Strata.sc` holds only the class, every variable, `*new` and a generic `alloc` and `free`; all other code is in `lib/engine/` (`StrataUtil`, `StrataVoiceDefs`, `StrataGrainDefs`, `StrataVoices`, `StrataLifecycle`, `StrataBuffers`, `StrataFiles`, `StrataEffects`, `StrataPerformance`, `StrataRings`, `StrataScale`, `StrataVariation`, `StrataLoop`, `StrataFreeze`, `StrataMix`, `StrataRecord`, `StrataWaveform`, `StrataPositions`, `StrataModulation`).
   - The engine is built from **areas**: one `strataArea<Name>` method per area, returning an Event (`order`, `allocState`, `addDefs`, `addCommands`, `start`, `stop`, `free`, `effectKeys`, `grainDefs`, `grainParamHandlers`). `alloc` runs them in ascending `order` and `free` in descending order, every `stop` before any `free`, so every node is freed before any bus or buffer: a node never goes in `free`, a bus or buffer never in `stop`. Orders: performance 10, voices 20, grains 30, buffers 40, files 50, effects 60, rings 70, scale 80, variation 90, loop 100, freeze 110, mix 120, record 130, waveform 140, positions 150, modulation 160. An area keeps new state in `areaState[\<name>]`. Details: `docs/notes/engine/structure.md` (Areas).
   - Engine files are named `Strata*.sc` and extension files add methods only, never variables. Renaming or deleting an engine file needs a norns restart note in the changelog fragment.

```
Voice Synth → Voice Bus → Ring Writer → Voice Ring → strataGrainRing → Synth Path ┐
                                                                                   ├→ strataVoiceMix (voice filter, level on the other path, sends) → Main Bus (dry) + Delay Send + Reverb Send → Filter ×3 → Delay → Reverb → Master (drift/limiter/saturation) → Output
Buffer source:  Buffer pair (L/R) → strataGrainBuf → Other Path ──────────────────┤   (the stage mirrors the other path to the Voice Bus → Mod Synth, and writes the voice tap)
Input source:   SoundIn → strataInput → Input Bus → Ring Writer → Input Ring → strataGrainRing → Other Path ┘

Voice Bus → Mod Synth → Mod Bus → Other Voice Synths (cross-modulation, 3 slots per voice)
```

### Lua modules and `S`

Details, and how to register each kind of record: `docs/notes/lua/state-and-voices.md` (Modules and `S`).
- `strata.lua` holds only the entry points (`S`, one `include` per module, `init`, `redraw`, `enc`, `key`, `cleanup`, and the start steps only the script can own). Everything else is in `lib/`.
- **`S`** (`lib/state.lua`) is built fresh on every load. State more than one module uses is a field of `S` under its plain name; state one module uses stays local to it. `S.constants` is `lib/constants.lua`.
- **Includes**: only `strata.lua` calls `include`, once per module, always as `include("lib/<path>")`, never `"strata/lib/..."` (a test checks).
- **A module** is a constructor, `return function(S) local M = {} ... return M end`, ending with exactly `  return M` and `end`; its table is `S.lib.<name>`, or `S.lib.<dir>_<basename>` in a subfolder. Functions that were global stay global, in their module (`MODULE_HOMES`).
- **Registries** (`S.registry`: `pages`, `params`, `grid_layouts`, `start`, `cleanup`, `voice_params`, `scene_fields`, `source_change`, `param_filters`, `lfo_destinations`, `fx_params`, `grain_restart` (`S.register_grain_restart(fn(voice_idx))`, run by `lib/engine_sync.lua` after every `engine.voiceOn` and every `engine.setGrainSource` that changes a running voice's source, all sent through `S.lib.engine_sync.send_grain_source`), `alt_release` (`S.register_alt_release(fn())`, run when ALT goes from held to not held), `menu_close` (`S.register_menu_close(fn())`, run by the menu watch, `lib/ui/menu_watch.lua`, each time the norns menu closes, after norns' `set_mode(false)` returns, each hook in its own `pcall`), `invariants` (`S.register_invariant(name, fn)`: `fn()` returns nil while the owning module's state invariant holds, else what is broken; the test harness checks every one after each unit test, nothing runs them on the device; `docs/notes/lua/state-and-voices.md`), and 3.4's `scene_blocks` (`S.register_scene_block`), `scene_migrations` (`S.register_scene_migration`), `pset_hooks` (`S.register_pset_hook`, run by the PSET actions `lib/params_setup.lua` installs), `param_touch` (`S.register_param_touch(fn(param_id, source))`, run after an encoder, arc or grid edit sets a param), `lock_change` (`S.register_lock_change(fn(voice_idx, locked))`), `step_outputs` (`S.register_step_output`) and `mod_sources` (`S.register_mod_source`, read through `S.lib.mod_sources`); `S.register_lfo_global_destination(label, param_id)` adds a global entry to `lfo_destinations` and `S.register_scene_field` takes an optional `set`) are read at init, never at include time (the first three of 3.4's close there; the other four are read at each use and stay open). Each register function checks its argument and refuses a duplicate name.
- **`S.performance`** is the tier the engine runs (`lib/performance.lua` reads the engine's `performance_active.data`). Every tier-dependent spec reads it; the setting itself (`performance.data`) is SETUP's, never a param.
- Tests reach script state with `local_value(name)` and `find_upvalue(name)`: a field of `S`, then of `S.constants`, then an upvalue of a global function.

### Lua ↔ SuperCollider Communication

**IMPORTANT**: this table is the engine command interface. The tests require exactly one row per engine `addCommand`, with the same signature and argument count. Keep the row format `` | `engine.<name>(<args>)` | `"<sig>"` | purpose | `` and update the table in the same commit as the engine. No `engine.<name>(` mentioned in this file, README.md, `docs/status.md` or `docs/notes/` may name a command the engine no longer has. Behavior details are in the area notes under docs/notes/engine/.

| Lua Command | SC Signature | Purpose |
|-------------|--------------|---------|
| `engine.voiceOn(voice, freq, amp, pan, grainSize, grainDensity, pitchShift)` | `"iffffff"` | Start a voice (resets `bend` to 1). Never stacks: synths still running or releasing are re-gated |
| `engine.voiceOff(voice)` | `"i"` | Stop a voice (release envelope) |
| `engine.retrigger(voice, velocity)` | `"if"` | Accent a running voice at velocity 0-1 (Karplus re-plucks; one grain in triggered mode). Creates no nodes |
| `engine.setVoiceParam(voice, param, value)` | `"isf"` | Set a synthesis param, or `bend` (MIDI pitchbend ratio) |
| `engine.setGrainParam(voice, param, value)` | `"isf"` | Set a grain param (`envShape` index, `grainMode` 0 continuous / 1 triggered, `bufPos`, `freeze` 0/1 and `freezeMode` 0 hold / 1 spectral, handled by the freeze area, `t_scanReset` a jump's scan restart, not stored, `scrubRate` and `scanHold` transient, ...) |
| `engine.setMasterDrift(amount)` | `"f"` | Global tape drift |
| `engine.setReverb(mix, size, damp)` | `"fff"` | Reverb mix 0-1 (broadcast on `fxMixBus`: 3.0's crossfade at reverb sends of 1), size, damping. `FreeVerb2` on standard, the FDN on high. Kept while bypassed (the mix stays 0 until lifted) |
| `engine.setFilter(freq, res, type, mix)` | `"ffif"` | Master filter, on all three of its instances (dry, delay send, reverb send): 20-20000 Hz, res 0-1, type 0 LP / 1 HP / 2 BP (20 ms crossfade), mix 0 = bypass |
| `engine.setDelay(time, feedback, mix)` | `"fff"` | Master delay: 0.01-2 s, feedback 0-0.95, mix 0-1 (broadcast on `fxMixBus`: 3.0's crossfade at delay sends of 1; 0 = dry, the node keeps running). Kept while bypassed (the mix stays 0 until lifted) |
| `engine.setBypass(effect, bypassed)` | `"ii"` | Effect 0 delay / 1 reverb (others ignored), bypassed 0 or 1: broadcasts the mix as 0, frees the node after the 0.05 s lag plus a block, and re-creates it in its place from the kept controls when lifted (a lift inside the wait cancels the free). Only this frees an effect |
| `engine.setModSource(voice, slot, sourceVoice)` | `"iii"` | Crossmod source for slot 1-3 (-1 = none → `silentBus`, 0-6 = voice). The three crossmod commands ignore any other slot |
| `engine.setModAmpAmt(voice, slot, amount)` | `"iif"` | Crossmod amplitude depth (-2 to 2) |
| `engine.setModFreqAmt(voice, slot, amount)` | `"iif"` | Crossmod frequency depth (-2 to 2) |
| `engine.setModSpeed(voice, speed)` | `"if"` | Mod signal LFO speed (0.1-50), kept per voice for restarted mod synths |
| `engine.setGrainSource(voice, source)` | `"ii"` | 0 = synth, 1-8 = buffer slot, 9 = input. A running voice's grain synth is replaced (never stacked); a stopped voice's choice is recorded. Same source = no-op |
| `engine.loadBuffer(slot, path, start)` | `"isf"` | Read a file into slot 0-7 from `start` seconds into it (at the file's rate; clipped to the file; 0 = the beginning; a start past the file's end loads the slot's length of its last frames): at most `bufferSeconds` (16 s standard, up to 300 s high) at the server rate (a 96 kHz file keeps half as many seconds on a 48 kHz server). Voices reading the slot fade first. A file longer than 16 s at the server rate is checked in a routine that yields between chunks: it takes effect only after the check, and is dropped silently if a record, clear or later load that took effect arrived meanwhile. A missing, unreadable, empty or damaged file (checked by decoding it) leaves the slot unchanged but cancels a recording in it; a server read that fails anyway (the file vanished) leaves it empty. Both are reported by the `bufferLoadFailed` poll. The slot's peaks file is written before its length is reported |
| `engine.recordBuffer(slot, seconds, level, feedback, source, threshold, loop, delay, sent)` | `"ifffififf"` | Record `source` (0 input, 1 pre-master, 2 post-master, 3-9 voice 1-7; others input) × `level` into slot 0-7, from frame 0, for `seconds` (at most `bufferSeconds`). `feedback` 0 with `loop` 0 is a replace take: the slot fades, empties and reads 0 s until it ends; so is a recording into a slot holding audio at another sample rate (its `feedback` and `loop` are dropped). Otherwise the slot keeps playing (grains avoid the head), its length becomes the longer of its own and `seconds` when recording starts, and each frame keeps the old audio × `feedback`; `loop` 1 wraps over the first `seconds` until `stopRecord`. `threshold` > 0 waits for the source's level (linear), with a 10 ms pre-roll. `delay` (s) starts it that long after Lua sent the command (clock sync): `sent` is Lua's wall clock modulo 1000 s at the send (`util.time() % 1000`), from which the engine works out how long the command waited for sclang (wrapped at 1000 s), however busy sclang was (#565); a negative `sent`, or a wait over 10 s (posted), runs the delay from when sclang handles the command, and a synced replace take empties its slot only 0.21 s before its start. States on `recordState`. At its end writes the peaks file and the scratch take `buf<n>.wav` |
| `engine.clearBuffer(slot)` | `"i"` | Zero slot 0-7 (cancels a recording) |
| `engine.stopRecord(slot)` | `"i"` | End a recording now, with its 5 ms fade, and keep what was captured; an armed recording that has not started is canceled (keeps nothing) and leaves its slot as it was, unless the take had already emptied it (a replace take prepares 0.21 s before a synced start, at once otherwise). No-op if the slot is not recording or armed |
| `engine.saveBuffer(slot, path, start, length)` | `"isff"` | Write `[start, start + length)` of the slot's valid region (fractions; 0, 1 = all of it; a region under one frame writes nothing and reports failed) as a stereo 16-bit WAV (creates the directory). Samples beyond ±1 clip symmetrically. How the write ended is reported by the `bufferSaveResult` poll |
| `engine.setScale(root, mask)` | `"ii"` | The scale every quantized grain lands on: root 0-11 (0 = C), mask a 12-bit pitch-class set from the root (bit k = k semitones above it; 4095 = chromatic, the default). A root outside 0-11 or a mask outside 1-4095 is ignored |
| `engine.setFastLfo(lfo, voice, destination, shape, rate, depth, offset)` | `"iiiifff"` | Engine LFO 0-5 on voice 0-6's fast destination 0-4 (pitch, position, size, cutoff, amp), for the whole voice (note slot 0 in 3.4): shape 0-7 (sine, tri, square, up, down, s&h, smooth, drunk), rate 0.003-50 Hz, depth 0-1, offset -2..2 (half ranges). Creates the LFO's node if it has none, else sets it; a new shape replaces the node, a new voice or destination moves it and zeroes the old channel. Never more than one node per LFO |
| `engine.stopFastLfo(lfo)` | `"i"` | Release LFO 0-5's node (20 ms) and zero its channel once it ends. No-op without one |
| `engine.syncFastLfo(lfo, phase)` | `"if"` | Set LFO 0-5's phase (0-1) now. No-op without a node |
| `engine.setScatter(depth, rate, destinations, voices)` | `"ffii"` | Scatter: depth 0-1 (0 releases the node over 0.5 s), rate 0.01-1 Hz, destinations a 5-bit mask (bit d = destination d), voices a 7-bit mask (bit v = voice v). Creates the node when depth rises above 0 |
| `engine.setFastOffset(voice, noteSlot, destination, offset)` | `"iiif"` | Set the Lua-computed offset (-2..2 half ranges, clamped) on voice 0-6's note slot (0 in 3.4; 0..`fastModNoteSlots` - 1) and fast destination 0-4, through the offset node, lagged 50 ms. Out-of-range indices and a non-finite offset are ignored with a console line. Creates no node |

**3.4's five fast-modulation commands** (the last five rows; `docs/notes/engine/modulation.md`): each ignores an out-of-range index or a non-finite continuous argument with one console line, and clips its continuous arguments to the ranges above. `setFastLfo` and `setScatter` make, set, replace and release the area's LFO and scatter nodes in `fastModGroup`; `setFastOffset` sets one value of the offset node, which runs from the area's start to its stop. `test/sync_check.lua` holds them in `PENDING_COMMANDS` until the Wave 1 package that calls each removes its name.

**Poll `bufferState`** (engine → Lua): matron's polls carry one float, so each message carries **one** slot as `slot_index * 1000 + seconds` (`BUFFER_STATE_STRIDE` = 1000, 0-based slot, seconds ≤ `bufferSeconds`, at most 300; the largest value, 7 × 1000 + 300, keeps 0.01 s in a 32-bit float). It sends one slot every 0.25 s, in turn, then the slots' length (`bufferSeconds`) as slot index 8 (`8 * 1000 + seconds`, which caps Lua's `S.performance.buffer_seconds`, #153), so a full cycle takes 2.25 s, and every change is also sent at once. A slot recording a replace take reads 0 s; one recording playably reads its valid length. A slot that holds any frames reads at least 0.01 s (#456: a 128-frame single cycle would round to 0.00); only an empty slot reads 0.

**Poll `bufferLoadFailed`** (engine → Lua, not periodic): one message per failed load (a missing, unreadable, unsupported, empty or damaged file, at once; a server read that fails, after the fade and the read), whether or not the slot held audio, as `(load_number * 2 + emptied) * 8 + slot_index` (`NUM_BUFFERS` = 8, 0-based slot; `load_number` counts that slot's `loadBuffer` commands from 1, in the engine and in `load_buffer` alike; `emptied` = 1 when the failed server read left the slot zeroed). Lua's `buffer_load_failed` undoes exactly that load (its previous name, path and file param come back, or the slot shows empty) and never a later load, clear or recording, in whatever order the reports arrive.

**Poll `bufferSaveResult`** (engine → Lua, not periodic): one message per save whose write ends, written or failed (an empty slot, at once; a folder that cannot be made, a short write or a failed rename, when the write ends), as `(save_number * 2 + failed) * 8 + slot_index` (`NUM_BUFFERS` = 8, 0-based slot; `save_number` counts that slot's `saveBuffer` commands from 1, in the engine and in `save_buffer` alike; `failed` = 1 when nothing was written, so a file already at the path stays). A write abandoned for a newer write to the same path reports nothing. Lua's `buffer_save_result` prints the outcome and flashes `saved buf <n>` or `buf <n> save failed` on BUFFER only for the slot's newest save, so a late report never speaks for a newer one, in whatever order the reports arrive.

**Poll `recordState`** (engine → Lua, not periodic): one message per change of a recording's state, as `((record_number * 4) + state) * 8 + slot_index` (`NUM_BUFFERS` = 8, 0-based slot; state 0 armed, 1 recording, 2 ended and kept, 3 canceled; `record_number` counts the slot's `recordBuffer` commands from 1, in the engine and in `record_buffer` alike). Lua acts only on its newest recording's reports, in whatever order they arrive. A `canceled` sent by a stop, a load or a clear is followed at once by the slot's `bufferState` (audio when the take had not prepared the slot), then, for a failed load, its `bufferLoadFailed`.

**Poll `takeWriteFailed`** (engine → Lua, not periodic, #312): one message per recording that ended and was kept but whose scratch take could not be written (a full card, a folder that cannot be made), sent when the write ends (after `ended`; seconds after it for a long take), as `record_number * 8 + slot_index` (`NUM_BUFFERS` = 8, 0-based slot; `record_number` as in `recordState`). A take that is written reports nothing. Lua acts only on the slot's newest recording, while the slot still holds its take: the take stays in the buffer, its path is forgotten (at once, or when it settles), so `buffers.data` never names the file of an older take, and BUFFER flashes `buf <n> take not saved`.

**Index conversion**: voices are 0-indexed in SC and 1-indexed in Lua, so always pass `voice_idx - 1`. Mod sources go through `engine_mod_source()` (Lua 0 = none / 1-7 → SC -1 / 0-6).

**The `voices` table is the only source of values.** The engine holds no per-voice defaults. A start (`S.lib.engine_sync.start_voice`, from `toggle_voice` or a pattern step) sends `setGrainSource` and every grain value before `engine.voiceOn`, and the synth and crossmod values after it (#325). Param actions reach the engine only while a voice is active. The `v<i>_source` action is the exception: it also reaches stopped voices.

### Invariants that are easy to break

One line each; the detail is in the "Must not break" list of the notes file named.

The engine's (under docs/notes/engine/):
- **Pattern steps and MIDI notes never create nodes**: they call `retrigger`, and velocity only scales the accent envelope's `levelScale` in every voice SynthDef and in `\strataVoiceMix` (Karplus's pluck impulse is the one allowance; the check asserts it). `docs/notes/engine/voices.md`
- **Replace, never stack**: a source switch replaces the grain synth; fading synths are cut with `cutSynth`, never a second `release`; new grain synths are placed with `startPlacedGrainSynth`. `docs/notes/engine/lifecycle.md`
- **`openedGate(gate)`** wraps every ASR gate; never `gate.max(...)`. `docs/notes/engine/lifecycle.md`
- **Silent bus**: unrouted mod slots read `silentBus`, never control bus 0. `docs/notes/engine/voices.md`
- **Limiter before the tanh saturator** in `\strataMaster` (the check asserts the order). `docs/notes/engine/effects.md`
- **One grain path**: every grain synth is a `GrainBuf` pair built by `grainBody`, pitch is the grain rate, it writes only its source kind's path (`voicePathBus`), and no grain SynthDef has a `PitchShift`, `DelayC` or other delay line, nor a filter, send, mirror, accent or amp control. `docs/notes/engine/grains.md`
- **Buffer and input sources have no voice synth**: their grain synth writes the voice's other path; the stage mirrors that path (filtered, after the level) to `granBuses[i]` so crossmod keeps working; the synth path never mirrors, and the synth-source grain synth keeps `pan` and `rateLevel` at 0. `docs/notes/engine/grains.md`, `docs/notes/engine/mix.md`
- **One persistent stage per voice** (`\strataVoiceMix`, `effectKeys`, never re-gated): at the tail of its mix group, which sits just before the voice's mod synth (`startModSynth`); it holds the voice filter, the level (after the filter, on the other path only), the sends, the mirror and the tap; its inputs and filter outputs go through `zeroBadValues`, and a NaN or inf on a bank (never a denormal) replaces it in place. Node order inside `processGroup`: synth-source grain synths (head), then each voice's mix group (buffer and input grain synths at its head, the stage at its tail) before its mod synth. `docs/notes/engine/mix.md`
- **Ring writers** run at the tail of `voiceGroup`, are persistent `effectKeys` and zero bad input; a ring grain reads behind the write head and never past the ring. `docs/notes/engine/rings.md`
- **The ring head is read sample by sample**: every ring grain starts the lookback and one block behind the write head wherever its trigger falls in a block (grains at one rate read one distance back), so `ringGrainReader` never holds the head for a block without adding the sample's offset while it advances; a head that did not advance a block (across a wrap it did) starts that block's grains at one point, never between two rings. `docs/notes/engine/rings.md`
- **`ringReaders`** maps every `\strataGrainRing` to its voice until it frees; a voice ring and the input ring only append (only their writers write them); the one other ring write, an input freeze's copy into the voice's copy ring, fades that ring's readers first and runs only if `ringChanges[voice]` is unchanged. `docs/notes/engine/rings.md`
- **Freeze** changes a synth voice's ring writer only with `run` or `Synth.replace`; an input freeze never touches the voice's ring or its writer: its copy is in the voice's copy ring (`copyRingFor`), which only the voice's input grain synths read, and its spectral writer is a node of its own (`copyWriterKeys`), started and freed by the freeze area (#494, #495); spectral exists on high only; history is 0 inside a frozen input copy; a source switch unfreezes first; an unfreeze's re-point and the grain synth's `freeze` 0 go in one bundle; what a ring grain synth reads at its start, its re-gate and a freeze is `grainReadPairs`' answer, never pairs of their own. `docs/notes/engine/freeze.md`
- **No `LocalBuf` in any engine SynthDef** (it corrupts sclang 3.13's collector; a structure test enforces it). `docs/notes/engine/freeze.md`
- **Every SoundFile `readData` reads into a fresh array** (`freshReadArray`, #131; a structure test enforces it). `docs/notes/engine/files.md`
- **No per-sample sclang loop in engine code**: build sample arrays with C primitives (#131; a structure test enforces it in `StrataFiles.sc`). `docs/notes/engine/files.md`
- **No List that grows without bound while sclang allocates heavily** (an OSC responder, a polling loop, a long routine): make it with room for all it will hold (`List.new(n)`) or bound it (#131). `docs/notes/engine/files.md`
- **Buffer memory**: slots of `bufferSeconds` (16 s standard; high steps its setting down to leave 1 GB, counting the slots, the voice and copy rings and the input ring: `highMemoryBytes`), voice rings and copy rings of 4 s (10.8 MB each set) and the input ring; never allocate longer ones; bufnums never change; the engine runs high only if it wrote `performance_active.data`, or an old one it cannot replace says high (what Lua reads). `docs/notes/engine/memory.md`, `docs/notes/engine/performance.md`
- **Real-time memory**: norns' pool is 8192 KB. Every `GrainBuf` uses `maxGrains` (128), never size a delay line or table from a control, a voice holds at most its live synths, one fading and one cutting set, and the check requires 3 MB free on standard and 3.5 MB on high (3 MB on both with eight recordings), at the mixed worst cases (synth -> buffer -> synth among them: two voice synths per voice for the cut, #502) and the all-buffer one, every grain synth under 88 KB and each mix stage under 42 KB since 3.4 (40 in 3.3: 3.4's cutoff and amp offsets, step gate and mute take a stage to 40.4 KB, and every floor holds with them). 3.4's figures, with six engine LFOs and scatter on every voice and destination running, the memory area alone on 3.13: `\strataGrainRing` 59.0 KB, `\strataGrainBuf` 69.1 KB, the stage 40.4 KB, the high synth -> buffer -> synth worst case 536-556 KB above 3.5 MB. `docs/notes/engine/memory.md`
- **Fast modulation**: every channel of `fastModBus` comes from `fastModChannel`; the buses hold offsets only and Lua owns every base value (no graph folds an offset into a control); the cutoff and voice-level amp offsets belong to the per-voice stage (`voiceMixMod`), and the grain synths read those two channels but feed them to no UGen; at most one node per engine LFO at every moment, a releasing one included (a shape change is a `Synth.replace` only while the node was never released since it started, else it frees the node as its new one starts, in one bundle; a node that ends as it is re-gated starts again), and one scatter node; a channel is zeroed when its last writer ends; messages to LFO and scatter nodes go through `sendToSynth`, and the offset node is an `effectKeys` node at the head of `fastModGroup`, the first node of `xg`. `docs/notes/engine/modulation.md`
- **The step gate and mute are the stage's** (`voiceGate`, on the whole output but the mirror): the mirror is never gated or muted and the tap is; velocity never reaches the gate's envelope; `seqGate`, `gateSeconds`, `gateRelease` and `voiceMute` are kept in `grainControls[voice]`, so a stage replaced in place and a voice stopped, started or switched keep them (Lua sends `gateSeconds` only when it changes and relies on it). `docs/notes/engine/modulation.md`
- **`slotChanges[i]`** guards late replies and the fade wait (a clear or load sent later always wins); load and save reports name their number. `docs/notes/engine/buffers.md`
- **One record synth per slot, only in the tap group** (`areaState[\record][\tapGroup]`, after the master): a new recording, load or clear frees the old one at once, even in its stop fade. A playable recording never shrinks its slot and zeroes it only through `afterSlotFade`; every delayed step of a recording runs only if `slotChanges` is unchanged. `docs/notes/engine/record.md`
- **The head guard** (`slotHeadGuard`) passes a grain's start through when the head bus reads -1, moves a start the head would meet during the grain's life to the zone's edge (never past D), and keeps it in `slotGrainPos`'s valid range. `docs/notes/engine/record.md`
- **Chunk loops in a routine** wait through `yieldToCommands`, never a plain `wait`. `docs/notes/engine/files.md`
- **Fade before zeroing**: never zero a slot directly; go through `afterSlotFade`, and fading `\strataGrainBuf`s only ever get `bufFrames 0`. `docs/notes/engine/buffers.md`
- **Messages to synths that can end on their own** go through `sendToSynth`, never `synth.set`/`release`/`free`/`moveBefore`; the effects chain's `effectKeys` get plain sends. `docs/notes/engine/lifecycle.md`
- **Bypass is explicit**: only `setBypass` frees the delay or reverb and re-creates it in its place; a mix at 0 only silences; the master filters are never freed. `docs/notes/engine/effects.md`
- **Sends reproduce 3.0's chain**: every mix reader lags 0.05 s, the bus and the nodes' mix controls move in one bundle, and a stage gets its send and mix buses through `stageControls` (`docs/notes/engine/mix.md`). `docs/notes/engine/effects.md`
- **NaN guards**: the three `\strataFilter`s and `\strataMod` (input and output) replace bad values with `zeroBadValues`. `docs/notes/engine/effects.md`, `docs/notes/engine/voices.md`
- **File writes** go to a `.part` file renamed into place, never the final path; `deleteStaleParts` deletes only old `.part` and temporary float files. While the waveform area's mover lives, a peaks write, a save or a scratch take renames through it (`renameIntoPlace`), never a forked `unixCmd` or `systemCmd` (#210, #217). `docs/notes/engine/files.md`, `docs/notes/engine/waveform.md`
- **The peaks file is in place before the length is reported**: a load's `bufferChanged` runs as `writeSlotPeaks`' action, after the rename; a failed write still reports the length. `docs/notes/engine/waveform.md`
- **The peak scan allocates nothing per sample** (#131): bin-aligned chunks and `Signal`'s `peak` (a C primitive; `maxItem` and `minItem` run a sclang function per sample; a structure test enforces it). `docs/notes/engine/waveform.md`
- **`\strataFilter`**: never compare a UGen with `==`; use `BinaryOpUGen('==', ...)`. `docs/notes/engine/effects.md`
- **The filter's highpass and cutoff**: `multimodeFilter` runs `RLPF` and `BPF` only, the highpass is the input less both (never an `RHPF`), and a cutoff rises at most `cutoffRiseRate` through `riseLimitedCutoff`, passing bit for bit otherwise. `docs/notes/engine/effects.md`
- **No slot grain reads past the valid region**: forward or reverse, whatever the loop; the loop is cut to the legal starts (the bounds of the trigger's own sample: `max` and `min` at audio rate, never a control-rate `Clip`), never shortens a grain, and the engine never trusts Lua's start and length pairing. `docs/notes/engine/loops.md`
- **Grain draws latch per grain**: every variation draw is a `TRand`/`TIRand` on the grain trigger feeding a `GrainBuf` input; size jitter never makes a grain longer than 0.5 s (the rings' lookback relies on it); quantize comes before bend and crossmod; `scaleBuffer`'s bufnum never changes. `docs/notes/engine/variation.md`
- **Transient scan state**: `scrubRate`, `scanHold` and `t_scanReset` are the one exception to "the `voices` table is the only source of values" (not params, in no scene or PSET; Lua's voice sync clears the first two). `t_scanReset` is never stored (its handler sends it and returns true); `scrubRate` and `scanHold` are plain grain controls: a grain restart ends the glide (`lib/positions.lua`) and every voice sync sends both as 0. Every grain start restarts the scan: a new `\strataGrainBuf` starts at 0 and `gateVoice` sends `t_scanReset` with a releasing one's re-gate. `docs/notes/engine/positions.md`, `docs/notes/lua/positions.md`
- **The engine runs the tier Lua reads**: `parseActivePerformance` stays identical to `S.lib.performance.parse_active_text`, the step-down arithmetic matches what the rings area allocates, and the poll's slot length only ever lowers Lua's `S.performance.buffer_seconds`. `docs/notes/engine/performance.md`, `docs/notes/lua/performance.md`

The Lua side's, across modules:
- **Param → engine** goes through `send_param_to_engine(id, value)` and an `S.engine_senders[id]` entry, never `engine.*` from a control param's action; a command carrying several params builds the others from `engine_param_value(id)`; LFOs never `params:set` their destination. `docs/notes/lua/engine-sync.md`, `docs/notes/lua/lfos.md`
- **Scenes**: a new captured field needs `validate_scene` coverage and a migration default; discrete keys switch at the end of a transition (discrete extras after the source), never crossfade; a recall sends one full sync per running voice whose source changed. `docs/notes/lua/scenes.md`
- **Data files**: `scenes.data` and `buffers.data` are written only through `S.lib.data_files.write` (a checked `.part` renamed into place, nothing written when the bytes are the same) and read only through `S.lib.data_files.read` (a parser: the file is never run), never `tab.save` or `tab.load` (a structure test enforces both); scenes.data is written at every scene save and buffers.data whenever a slot's remembered path or start changes; a backup never replaces an earlier one. `docs/notes/lua/data-files.md`, `docs/notes/lua/scenes.md`, `docs/notes/lua/buffers.md`
- **Source tests**: `voice_uses_synth(i)` / `voice_uses_buffer(i)`, never `not voice_uses_synth` (that includes input). `docs/notes/lua/state-and-voices.md`
- **Grid, arc and MIDI handlers live on the vport only**, never on the raw device passed to `grid.add`. `docs/notes/lua/grid-core.md`, `docs/notes/lua/arc-core.md`, `docs/notes/lua/midi.md`
- **Arc rings** sweep their range in 1024 ticks (a full turn) through `arc_sweep_param` and draw through `arc_ring_fill` from `param_fraction` (`arc_ring_fill_param` picks the bipolar fill), never a bare `segment` or a hardcoded range; whole-step rings carry ticks through `arc_whole_steps`, forgotten on a page change and when what they were turned on changes; Strata follows one arc. `docs/notes/lua/arc-core.md`, `docs/notes/lua/arc-pages.md` (cursor and step rings)
- **Lock** is the user's name (`[L]`, the hints, the grid's lock keys, `toggle_lock`) for the state `S.frozen`; "freeze" is 3.2's audio freeze, never said with the lock in user docs unless contrasting, nor named with it in code; a locked voice is left alone by randomize, drift and mutation and can still be edited. `docs/notes/lua/freeze.md`, `docs/notes/lua/mutation.md`
- **Randomize undo**: every page randomize (ALT+K2) goes through `S.lib.mutation.randomize(spec)` (MAIN's `randomize_voice` too; the 256's pattern keys still call `randomize_pattern` directly, with no undo), and every param a spec draws calls `note_param_edit` from its action (a test checks each page record's `randomize_section` in each layout state); there is one undo, `S.undo`, naming its page, section and voice, and a quick ALT+K2 undoes only there (`undo_for`), randomizing anywhere else; an edit of a held param, a pattern edit of a pattern undo's voice (`note_pattern_edit`), recalls, a new randomize and a mutation of the undo's voice end it, the drift's and the undo's own writes never do; a binary draw goes through `set_binary_param`. `docs/notes/lua/mutation.md`
- **LFOs** (3.4, `lib/lfos.lua`): one 48 Hz clock (`S.lfo_clock`, from its start step to cleanup) steps the six in index order; an LFO on a fast destination (a voice's grain pitch, position, size, `vfilt` or `amp`) runs in the engine (`setFastLfo`, `stopFastLfo`, `syncFastLfo`, never from a control param's action), every other in Lua through the one round robin (`S.lib.lfos.mark_due`, at most `LFO.sends_per_step` 12 sends a step with the matrix's, each inside `deferrable`); a modulation input reads lower-numbered LFOs only; a new destination is a control param whose label, with `~` when fast, fits 49 px. `docs/notes/lua/lfos.md`
- **Selected voice**: after init, `S.selected_voice` changes only through `S.lib.ui_keys.select_voice_by`. `docs/notes/lua/midi.md`
- **Filter restore mix**: `S.fx_last_mix.filter` changes only in `lib/params_setup.lua` (the `filter_mix` action on a rise, `toggle_filter_mix` at the press), never in the FX page; the delay and reverb have none. `docs/notes/lua/pages/fx.md`
- **Registered per-voice params** (freeze, variation, loops, history, voice mix) default to 3.1's sound and never reach MAIN's randomize, mutations or the 256 fader pages (`fader = false`); a page randomize of their own section (their record's `randomize` draws) is the one exception (#557); registered LFO destinations follow every built-in one, so saved indices keep their meaning. `docs/notes/lua/params.md`, `docs/notes/lua/loops.md`, `docs/notes/lua/variation.md`, `docs/notes/lua/voice-mix.md`
- **Mute and solo**: a mute silences in the mix stage (`voiceMute`, sent as `S.lib.voice_mix.silenced(voice)`, never as a stored value) and never stops a voice; scenes store mutes (a discrete key) and never solos. `docs/notes/lua/voice-mix.md`
- **Loop pairs**: scenes set extras in sorted key order, so `loop_length` comes before `loop_start`: the length's filter stands down during a recall or transition (clamped to the old start's room, a recall from (0.5, 0.5) to (0, 1) would end at (0, 0.5)), the start's action, set after it, cuts a length that does not fit, and a loaded pair goes through the record's `normalize_scene`. `docs/notes/lua/loops.md`, `docs/notes/lua/scenes.md`
- **Scale quantize**: there is one `freq` filter, which snaps a per-voice shadow note and never the incoming value; only a turn moves the shadow (`S.turning_param`, set through `S.lib.ui_detent.as_turn` by `delta_with_detent`, the freq param's own `delta` and a mutation step), every other set snaps its own value (#318); `scaleNote` is resent on every change that moves it; a voice's `quantize` loads ahead of its `freq` (`add_first`, #125). `docs/notes/lua/variation.md`
- **Recordings (Lua)**: the record params are PSET-only, never scene fields; only reports of a slot's newest recording act (`recordState`); every path that ends a recording or a long load's check cancels its timer through `S.lib.record.cancel_timer(slot)`; what a slot holds has one answer, `S.lib.buffers.status(slot)`, and a random or fill load takes a slot only when `S.lib.buffers.is_free(slot)` (#247); a playable recording is never sent while a load awaits the engine (#455). `docs/notes/lua/record.md`, `docs/notes/lua/buffers.md`, `docs/notes/lua/files.md`
- **Peaks and playheads**: a peaks file is read only in `lib/waveforms.lua`'s clock loop, never in a draw or a poll callback; pages and grids read the waveform, heads and bookmarks only through `S.lib.waveforms`, `S.lib.playheads` and `S.lib.positions`, and send no engine command for them. `docs/notes/lua/waveforms.md`, `docs/notes/lua/playheads.md`, `docs/notes/lua/pages/buffer.md`
- **The playhead restarts where the engine's scan does**: a `voiceOn` and a running voice's source switch (`S.register_grain_restart`) and a jump reset it; a new place that restarts a voice's scan resets the playhead too, and anything that changes the hold or the glide's rate calls `S.lib.playheads.advance(v)` first. `docs/notes/lua/playheads.md`
- **Jumps and recalls** enter through `S.lib.positions.jump` and `recall_bookmark` (the grid, the arc and BUFFER alike), which send `t_scanReset` only while the voice runs (only buffer voices respond); the scan hold (a set of holders per voice, #238), the glide and the last recalled bookmark are transient (never params, scenes or PSETs), and a held grid position key lives in `S.lib.grid_core.port_state(port).positions` only. `docs/notes/lua/positions.md`
- **Bookmarks, 3.4's interface**: `S.lib.bookmarks.recall(v, n)` and `is_set(v, n)` keep their names and behavior and never create a node (a pattern lock fires them). `docs/notes/lua/bookmarks.md`
- **Macros** (3.4, `lib/macros.lua`): a macro never targets a macro or the morph (`S.lib.macros.target_ids()` is the only list of targets; `set_target` and learn refuse any other id); scenes, a transition and morph set a macro silently (its scene field's `set`, `set_silently`), so its targets keep the scene's own values; every apply's fan-out is deferrable (one `deferrable` per apply, from the one clock `S.macro_clock`, at most 30 applies a second per macro); an LFO on a macro moves its targets' engine values (extra offsets, the matrix's fast extras, each through `S.lib.lfos.mark_due`), never a param, and skips LFO-param and matrix-depth targets. `docs/notes/lua/macros.md`
- **The matrix adds offsets and never sets a destination param** (3.4, `lib/matrix.lua`): each LFO step (`S.lib.lfos.on_step`) a Lua destination's routings sum into one extra offset (`set_extra_offset("matrix", id, sum)`), added to the LFOs' in `with_lfo_offsets` and clamped once per destination, and a fast destination's routings and the macros' fast extras reach the engine only through `engine.setFastOffset` (the sum clamped to −2..2 in Lua), never `setGrainParam`; every send goes through `S.lib.lfos.mark_due` (the LFOs' cap of 12 a step, deferrable), resent when its value moved from what the engine last got and once more when its sum returns to 0; its destinations (`destination_ids()`, the LFO destinations but none and the macros) never include macros, LFO params or matrix depths; `set_routing` (recalls, morph, PSET loads) never applies `edit_routing`'s 25 % rule. `docs/notes/lua/matrix.md`
- **Morph writes params and never recalls**: it never calls `recall_scene` or `recall_scene_instant`, never starts a transition and never clears the undo itself; each continuous value goes through `S.lib.scenes.set_value` (a transition step's setter, no recall flag, so a quantized freq snaps), a voice's loop pair together, start first, and the crossing's discrete entries through `apply_entries(entries, {only = "discrete"})`, inside `S.lib.engine_sync.deferrable`, at most 10 applies a second and 120 values an apply, from the one clock `S.morph_clock`; a recall or fade after a pending move wins (the move is dropped), and a PSET load never applies it. `docs/notes/lua/morph.md`
- **The sequencer plays only through step outputs** (`S.register_step_output`, `voices` first, read at each hit): every hit is one event to every output, each call in a coroutine of its own, so one that raises or yields prints `step output <name>: <error>` and is skipped until the patterns next start; an output's `play` never yields. The `voices` output is the exception: an error in it is Strata's own bug, so it stops the patterns and is raised again (#243, #382). Steps never create nodes, ratchets included: a stopped voice is started with `start_voice` at a step's first hit, a running one gets `retrigger` at every hit. `docs/notes/lua/sequencer.md`
- **Step locks and notes are base overrides** (`S.lib.engine_sync.set_base_override`), never `params:set`: a voice's next played step without them clears them, and every override of a voice ends at once when the patterns stop, its pattern is replaced or cleared (`replace_pattern`: a recall, a chain link) or its length is set below the step that set them, and at its wrap with no set step left; only a hand edit ends one earlier; a synth voice's freq override resends its `scaleNote`, and its end the voice's own. `docs/notes/lua/sequencer.md`
- **Strata follows the transport and never leads it**: an external clock's transport start and stop (`clock.transport`) move the patterns only while `seq_follow_transport` is on (a start: every voice at step 1 at once, never through the quantizer); the play keys start and stop the patterns locally, and nothing calls the clock's own start or stop. Any jump of the clock's beat while they play (a start they do not follow, a new clock source, a reset no handler passes on) keeps one count for every clock, the bars and the ratchets (the clock's beats plus one offset, 0 from every pattern start: rulings 47 and 54); a clock tests the beat its `clock.sync` returned, never the live beat, and never waits for the beat to climb back to an old count. `docs/notes/lua/sequencer.md`

## Working in parallel

Several pull requests are built at once, often by agents: a feature lives in files that only its work edits, apart from one-line registrations. How a session runs packages through agents (the controller, workers and reviewers, scratch folders, the ledger, briefs, reports, merging and cleanup) is in `docs/process/agents.md`. The rules every change follows:
- **Superpowers skills, invoked, not imitated**: each session invokes the skill for its step with the Skill tool, as `docs/process/agents.md` (Skills) lists them: `superpowers:brainstorming` for a new design, `superpowers:writing-plans`, `superpowers:using-git-worktrees`, `superpowers:subagent-driven-development` (the controller, at a plan's start and on every resume), `superpowers:test-driven-development` (every worker changing code or tests), `superpowers:requesting-code-review` (the controller, for a review outside a plan's task loop: a design, a docs change, a release); a plan's package reviews use `superpowers:subagent-driven-development`'s own task-reviewer and re-review templates; and `superpowers:finishing-a-development-branch` (at a plan's end, pull request only). Following a skill from memory does not count. Where a skill differs from `docs/process/agents.md` or this file, those win (parallel packages, rebase-only merges).
- **Rebase, never merge main in**: `git fetch -q origin && git rebase origin/main`, then `git push --force-with-lease`; never `git merge origin/main`, never `gh pr update-branch` without `--rebase`. Pull requests merge with rebase (`gh pr merge --rebase`), so `main` stays linear. A plan's reviewed packages land in batches, one pull request per batch, so a worker rebases only when the controller asks (`docs/process/agents.md`, Landing in batches).
- **One worktree per pull request**, branched from an up-to-date `main`; never share a checkout between two pieces of work. Engine checks in different worktrees run on different `$STRATA_SC_PORT` ports.
- **Own scratch folder and worktree, nothing else**: never write to, rename or delete another worker's folder, worktree, logs or containers. Remove only a worktree you created, with `git worktree remove`; leftovers are the controller's or the maintainer's to clean up. The controller's ledger is `.superpowers/sdd/<plan>/progress.md` in the main checkout, never in a worktree.
- **Edit only the files your package owns** (a release's design lists them; for 3.1, §9 of `docs/design/3.1-design.md`), plus registration lines and the package's own notes file, unit test file and `docs/user/` page. Need a change in a file another package owns? Ask for it, or make it a separate pull request.
- **Registering** is a few lines in the owning module, and the pointers name any other file: a page (`docs/notes/lua/ui/pages-and-dispatch.md`, Registering a page), a param group, per-voice params and the other shared spots (`docs/notes/lua/params.md`, Registering params), a start or cleanup step (`docs/notes/lua/state-and-voices.md`), a grid layout (`docs/notes/lua/grid-core.md`), an engine area (`docs/notes/engine/structure.md`, Areas). `init`, `cleanup()` and `lib/Engine_Strata.sc` are never edited.
- **On a conflict in a registration line** (an include, a `UI_PAGES` entry, a `START_ORDER` or `CLEANUP_ORDER` entry, a `register_params` call, a module table row in this file): keep both lines, in the order the sequence needs, and rerun the checks. Two `START_ORDER` or `CLEANUP_ORDER` entries on the same number: give the later one a free number.
- **Shared files** (CHANGELOG.md, `docs/status.md`, this file, README.md): edit them only where your package needs to. A feature pull request never edits CHANGELOG.md.
- **Changelog**: every pull request adds a changelog fragment `changes/<branch-name>.md`; see `changes/README.md`. The release pull request merges the fragments into CHANGELOG.md.

**Common norns pitfalls:**
- `UI.List` has no `set_items()`: recreate the list. `UI.List.new(x, y, index, items)` needs every argument.
- `clock.sleep()` works only inside `clock.run(...)`. Never call it in `init()`.
- Param IDs must be unique, and norns has built-ins such as `reverb`. Use prefixed ids (`strata_fx`, ...).
- A group's size `n` must equal the number of params that follow it. Groups cannot nest. The stub errors when a group gets fewer than `n` params before the next group or the end of the list, or when the param after its last one is not a separator or a group.

## Code Style Guidelines

**Named constants, never magic numbers.** They live in `lib/constants.lua` (`S.constants`, aliased as locals at the top of each module that uses them): `NUM_VOICES` (7), `NUM_SCENES` (16), `PATTERN_LENGTH` (16), `SCENE_DATA_VERSION` (6), `NUM_MOD_SLOTS` (3), `NUM_UI_PAGES` (8, `#UI_PAGES`), `MAX_STEP_LEVEL` (15), `NUM_BUFFERS` (8), `STANDARD_BUFFER_SECONDS` (16), `STANDARD_PERFORMANCE`, `BUFFER_DATA_VERSION` (2), `PSET_FORMAT` (2, the hidden `strata_pset_format` every PSET holds), `NUM_LFOS` (6, the engine's `numFastLfos`), `NUM_BOOKMARKS` (4), `WAVEFORM_POINTS` (64, the engine's `waveformPoints`), `RECORD_SOURCES`, `RECORD_SYNC`, `FILES`, `WAVEFORMS`, `PLAYHEADS`, `SCRUB` and `NORNS_SAMPLE_RATE` (48000), and 3.4's `NUM_MACROS` (16), `MACRO_BANK_SIZE` (4), `MACRO_TARGETS` (8), `MATRIX_SLOTS` (16), `NUM_GESTURES` (4), `SCENE_BANK_SIZE` (8), `SCENE_NAME_MAX` (12), `GRID_HOLD.step_edit_seconds` (0.3) and `ENGINE_BUDGET` (`messages_per_window` 150, `window_seconds` 0.1: the deferrable sends' budget, `lib/engine_sync.lua`). The engine mirrors them as `numVoices`, `numBuffers`, `standardBufferSeconds` and `numModSlots`. 3.4's fast modulation adds `NUM_FAST_DESTINATIONS` (5) and `FAST_MOD_NOTE_SLOTS` (1), mirrored by the engine's `numFastDestinations` and `fastModNoteSlots` (a docs test compares them). The slot length is a tier value, not a constant: read `S.performance.buffer_seconds`. Never hardcode 7, 8 or 16 in voice, scene, pattern or buffer code (bare numbers in grid code are coordinates and LED levels).

**Lua's 200-local limit applies to each function, checked by a test**: the locals probe measures the free locals at the end of each file's main chunk and of each module's constructor function, and fails when any has fewer than 30 (`strata.lua`'s main chunk uses 5). Group a feature's constants in one table (as `LFO_PAGE`, `GRID_LAYOUT`, `BUFFER_PAGE`, `FX_PAGE`, `BUFFER_SETTLE` do) rather than adding many `local`s, and split a module that runs short.

**Descriptive names**: `selected_voice`, not `sv`; `master_density`, not `md`.

**Bounds-check every index** (voice 1..`NUM_VOICES`, scene, step, slot, grid coordinates) before indexing, so tables never grow by accident. **Clean up** every metro, clock, poll and device handler on exit: the module that owns it registers a step with `S.register_cleanup` at its place in `S.constants.CLEANUP_ORDER` (never code in `cleanup()` itself; the sequence is in `docs/notes/lua/state-and-voices.md`). Cancel an existing clock before starting its replacement.

**No unguarded recursive deletes**, in code or in the shell commands you run. Lua tests delete only through `h.remove_tree` (inside `h.data_root`); the engine check and `test/run_engine_check.sh` delete only folders matching their own templates, and a structure test fails on any other `rm -r`. In your own commands, quote the path, fail on an empty variable and pass it after `--` (`rm -rf -- "${dir:?}"`), spell out an absolute prefix rather than a bare `$var/...`, and remove a worktree with `git worktree remove`, never `rm`.

**Keep docs current in the same change**: the `docs/user/` page for the area (user-facing behavior; README.md only for the overview, quick start and index), the module's notes file (implementation details, and its "Must not break" list), this file (rules, the command table, the module table) and `docs/status.md`.

### CRITICAL: keep Lua and the engine in sync

- A new or changed `addCommand` needs: matching `engine.*` calls (same count and types; SC type codes i/f/s), the table row above, and the engine stub picks it up from the SC source.
- A new SynthDef argument the user controls needs: the `voices` table default, the voice's `param_order`, `add_voice_params()`, `get_param_spec()`, a sender in `S.engine_senders`, and the exact case-sensitive name. Grain params go through `setGrainParam` and `GRAIN_PARAM_IDS`.
- Lua defaults are what the engine plays (`S.lib.engine_sync.start_voice` sends them at every start). SynthDef defaults for the filter and delay must equal the Lua param defaults, because the script never bangs its params.
- New voice-level controls that a buffer or input grain synth also needs belong in `voiceControls` / `grainControls` and `controlNameSets` (see Audio Sources in `docs/notes/engine/grains.md`).

### IMPORTANT: update the UI with every feature (128×64 screen)

Details: the UI core's notes (`docs/notes/lua/ui-core.md`, an index of docs/notes/lua/ui/) and each page's `docs/notes/lua/pages/<page>.md`.
- **Pages**: `UI_PAGES = {"MAIN", "VOICE", "SEQ", "FX", "LFO", "BUFFER", "SCENES", "SETUP"}`. Each page file creates one record at `S.registry.pages[UI_PAGES.index.<PAGE>]` (`name`, `draw()`, `hints(alt_held)`, `enc(n, d)`, `key(n)` and optional fields); only its `lib/arc/<page>.lua` sets the four arc fields (`docs/notes/lua/ui/pages-and-dispatch.md`). Find a page by index (`UI_PAGES.index.<PAGE>`, `S.ui_page`), never by its title string. Change pages only through `S.lib.ui_keys.set_ui_page`, never by setting `S.ui_page`. Change a page's draw or hints function, never `redraw()`, whose one dispatch besides the page's is the modal owner's (`S.lib.ui_modal.push(owner)`: while an owner is pushed, the screen's body and hints, E2, E3, K2, K3 and the arc are its own and E1 does nothing; `docs/notes/lua/ui/pages-and-dispatch.md`, The modal owner).
- **ALT** is K1 held, the only way into ALT. Every ALT+K2/ALT+K3 action goes through `alt_action(page, n)`, never `alt_key` directly (the exceptions act on release, in `alt_key_release`, by how long they were held, and their `alt_key` only notes the press: BUFFER's ALT+K2 and ALT+K3, `docs/notes/lua/pages/buffer.md`, and the ALT+K2 of every page that randomizes, through `S.lib.ui_alt.k2_down` and `k2_up`: a press released within `ALT_HOLD_SECONDS` randomizes or undoes, a longer one runs the record's `alt_hold`, or cancels on a page without one, and the hint says which: `K2:reset` or `K2:cancel`); a key release acts only on the page where the key went down, and a key pressed with ALT releases through `alt_key_release`, never `key_release` (`docs/notes/lua/ui/alt-and-keys.md`).
- **Encoder and ring changes** never call `params:delta`: a page's `enc` calls `enc_param_delta(n, id, d)`, rings call `arc_sweep_param` or `delta_with_detent` (a binary VOICE row is set with `set_binary_param`, which sends the MIDI-map feedback `params:delta` would). Fine adjustment is ALT+E3 only; a range through 0 lands on 0 and holds there for 3 detents or 24 ticks within 1 s (`docs/notes/lua/ui/detents-and-fine.md`).
- **Redraws**: when state the screen or arc shows changes, call `request_redraw()` (a frequent change no arc ring shows, BUFFER's input meter, asks for the screen alone with `S.lib.ui_frame.request_screen_redraw()`, #434); never call `redraw()` or `arc_redraw()` from script code, and a page's `draw()` never calls `request_redraw()`. Grid redraws stay direct (`grid_redraw()`) (`docs/notes/lua/ui/redraws.md`).
- **Header and hints**: every page has the header at y=8 (`draw_header()`, positions in `S.constants.HEADER`) and the hint row at y=62, drawn by `redraw()`; a page never calls `draw_hints`. Transient messages go through `S.lib.ui_flash`, never a page's own flash clock (`docs/notes/lua/ui/header-and-flashes.md`). On MAIN the voice list (x 0-60, `UI.ScrollingList`, 4 visible rows) sits left of the divider at x=62 and the selected voice's details at x 65-127. Status indicators use `[BRACKETS]`; levels are 15 bright, 4 dim, 1-2 subtle.
- **Cursors other modules move** go through their owner: the VOICE cursor through `S.lib.ui_cursors` (`sync`, `place`, `move`; never `clamp_all()` alone or a bare assignment), the SCENES cursor through `S.lib.pages_scenes.move_cursor` (`docs/notes/lua/pages/scenes.md`), row pages through `S.lib.ui_field_list`. A ring never reaches into a page's state (`docs/notes/lua/ui/field-list-and-cursors.md`).
- A new voice type needs a `MAIN_PARAMS` entry (E3, the MAIN display and arc ring 2 follow; `list_name` is its voice-list name, at most 5 characters) and `get_param_spec()` specs.
- The layout tests check every page for overlapping strings, text off-screen, the hint row and the MAIN divider; keep them passing. They miss strings crowding on nearby baselines and text over a rect or line: look at the page renders after a layout change (`docs/notes/lua/ui/layout-and-renders.md`).
- Before finishing, check that new values are visible with units, hints match the keys, all 7 voices fit, and nothing leaves 128×64.

### CRITICAL: keep grid and arc in step with the code

Details: `docs/notes/lua/grid-core.md`, each layout's `docs/notes/lua/grid/layout_<size>.md`, `docs/notes/lua/sequencer.md`, `docs/notes/lua/arc-core.md` and `docs/notes/lua/arc-pages.md`.
- Grid layouts are one file each (`lib/grid/layout_256.lua`, ...), registering `{key, redraw}` in `S.registry.grid_layouts` and picked by the exact `cols`/`rows` in `grid_layout()`. Patterns are `S.patterns[voice][step]` (`lib/sequencer.lua`). Anything the grid shows must call `grid_redraw()` when it changes, wherever it changes (cheap without a grid).
- Grid keys, pages, held keys and other per-grid state are per port (`S.lib.grid_core.page(port)`, `any_page(n)`, `S.grid_held[port]`, `port_state(port)`): no global grid page, and other per-grid state lives in `port_state`, never in a layout local or on `S`. Pattern keys go through `step_key`, scene saves through `scene_save_key`, delayed key actions through `on_hold`, never a clock of their own. Pattern edits from any page, ring or layout stay within bounds and call `grid_redraw()`; a whole-pattern replacement goes through `S.lib.sequencer.replace_pattern`.
- A grid's position page (page 5 on every layout, `POSITION_PAGE` in `lib/playheads.lua`) repaints from the playheads' 15 Hz clock when `S.lib.positions.display_signature()` changes; param actions never redraw it (`docs/notes/lua/playheads.md`).
- New params in `param_order` appear on the fader pages automatically (`fader_param_ids`, following the controlspec warp). Review whether a feature needs grid buttons or LED feedback on every layout.
- Arc: review whether new params belong on a page's rings (set only in `lib/arc/<page>.lua`). Ring feedback uses the param specs' ranges (`param_fraction`).
- Everything must degrade gracefully when no grid, arc or MIDI device is connected. Update `docs/user/grid.md` or the layout's `docs/user/grid/<size>.md`, `docs/user/arc.md` and the matching notes file with new patterns.
